`riscv_iommu_query_leaf(domain,iova,out)` validates domain operations before `container_of`, accepts initialized RV64 single-stage DMA/DMA_FQ/UNMANAGED domains in the current driver mode/positive aperture, and rejects nested/G-stage/identity/blocked/SVA/foreign/uninitialized domains. The public header has CONFIG-unreachable failure stubs; failures clear the non-NULL output, NULL output returns EINVAL.

The original fetch follows nonzero intermediate entries without all validation needed by an evidence API. A new checked walk applies the same indexing to the actual page tables, without modifying the original fetch/map/free. Every table must be page aligned and have a valid CPU address; every PTE is read once. It checks hardware V, unsupported/reserved high bits, W-without-R, intermediate U/A/D, remaining level and next PFN before following a table. Leaves require physical superpage alignment; output contains actual raw PTE, leaf shift/base and physical address including offset. Svnapot/Svpbmt encodings are rejected. Normal 1G leaves can also be reported; the later E4 consumer must demand precisely shift12 or21 for its requested condition.

The caller must keep the domain/mappings alive and exclude changes in the queried range. This is a read of stable software page tables, not an atomic concurrent snapshot or IOTLB query. It performs no map, unmap, invalidation, MMIO or DMA drain. The proposed E4 driver invokes it only while holding its mappings and experiment lock, outside the hardware timing window.

[Final finite host evidence](leaf-host-final02/validation.json): **65 cases,7232 production queries**, non-PIE ASan+UBSan, CONFIG-unreachable stub compile/run. Actual unmodified function bodies are extracted for new public/checked queries and the existing map/unmap/alloc/free/fetch/address conversion; allocation, PTE types and MM validity use explicit host stubs. The tests cover 4K/2M across all512 subpages and final byte at Sv39/Sv48/Sv57 levels, normal1G offset, RO/RW leafs, accepted domain types, foreign minimal heap domain, NULL/type/mode/stage/root/aperture failures, reserved PTE bits54..63, invalid permissions, invalid non-leaf flags/PFN, malformed final non-leaf, and misaligned2M PA. Every query compares full allocated-table digests and alloc/free counts; no query changes them. These are host model results, not kernel-runtime/RTL/cache or board validation.

Same-IOVA4K/2M alternation uses the original production allocator/unmap/free. Its live table counts are `3,3,4,4,5,5` for three cycles (root included); querying each unmapped range returns ENOENT. The original allocator calls free at PAGE_SHIFT when replacing a4K subtree with2M, where free immediately returns. A separate direct empty-table-free case observes delta0 with its existing first-entry-present guard. **No leaf does not mean all page-table memory was freed.** These behaviors are recorded, not repaired. Test-only teardown reclaims all tracked host table allocations after each domain so ASan can distinguish model teardown from production reclamation.

# 每日增量核查方法

维护目录为 `/home/xvhaocheng/work/docs/research-history/`，这是用户授权的独立整理记录。主会话负责每天调度；本次没有安装定时器、修改SSH/系统设置或创建自动实验。

1. 记录实际核查UTC时间及用户要求的日期标签；不把文件mtime当实验日期。先读适用AGENTS，确认现有目录和用户新增内容，禁止盲覆盖。
2. 只读核查根CURRENT_STATUS/HANDOFF/研究计划、平台validation及新阶段报告。对照本目录evidence/source-versions.json的SHA和行段阅读账本，先列新增/修改/撤回记录；不重跑已完成实验。
3. 实际阅读全文新增段、变更段和必要前后文。每项关键实验定位合同、真实运行、验收/分析、原始证据。若只打开回执字段，标为抽读；若只生成列表，标未读（程序清单），绝不自动升级全文阅读。
4. 按正文实验日期、阶段、commit、BIT/kernel/boot/run身份串联事件。源事实、软件/RTL实现、功能测试、行为模型、数学推导、FPGA性能分别记录。历史“计划/blocked/未上板”保留为当时状态，不覆盖后来回执。
5. 相同正文重复只算同一事件；相同文件名不证明同版本。历史before/snapshot/草稿保留，修订和否定不能被去重漏掉。新来源SHA与阅读范围进coverage；既有快照SHA不得被当成最新文件SHA。
6. 更新README的当前概括与timeline新增段，生成或追加daily/YYYY-MM-DD.md，写核查时间、变化、证据、尚未读范围和下一缺口。保留用户已写内容；同日多次更新用时间戳节，先留旧版本再合并。
7. 保存后只校验本整理文件可读、链接及CSV行列完整；不调用科学validator、构建、仿真或板卡操作。报告实际新读数量和实质变化。无变化也记录已核的来源版本，不能宣称重新验证实验。

原项目代码、实验日志/CSV、CURRENT_STATUS/HANDOFF和已有状态文档继续只读。本目录维护授权不代表可以启动新研究方法、发表、发送外部消息、安装软件或修改凭据。出现未知主机指纹/认证、访问限制或用户内容冲突时暂停相应操作并明确报告。

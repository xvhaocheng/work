先读这些边界
============
1. 默认32768元素、64tiles；四个2048B L1槽。core8是bulk DMA publisher，core0-7做FMA；不是四个独立发布者。
2. future地址可由循环索引计算，payload槽复用仍须owner/消费约束。不要由“地址已知”直接推出有足够提前窗口或完整收益。
3. dmcpy返回的是descriptor被实际FIFO接受后的软件job ID，不是完成。FE的completed_id是已退休job数，即最后完成ID+1。
4. 最后写分段的B退休触发完成；在同AXI ID有序返回等条件下形成公开完成前缀。数据成功、cache交接、失效完成、释放不能由这个数替代。
5. mover不检查写失败，错误响应也可能推进完成计数；不能当成功工作验收。
6. runtime把deserialize编码到bit2，而固定FE只保留cfg[1:0]；固定路径serialize=0。保留错配，不据此断言已发生死锁或所有执行错误。
7. RX/RY的host AR/R走外侧IOMMU，本地L1 AW/W/B由集群内路由完成；WY反向。远端R结束不等于本地输入B完成。
8. 外侧AR/AW同SID0/SSID0；一个DMA允许结构上的跨copy流水，但实际双请求同存、仲裁竞争、HOL与净收益仍未证。
9. 同ID跨本地/外侧目的的xbar约束尚需实际实现核查；descriptor已接受不等于其外侧AXI地址已出现。
10. 普通等待最后必需RY的一个ID可能表达A5最后tile动作；它本身是普通强对照，不是新反馈机制。未应用/编译该变体。
11. quiesce/invalidate/cache三个Hero硬件hook仍default deny；源码与工具链资产不能写成native链已通过。
12. 目前仓库下一有限B1证据任务使用mm-large的future B stripe，和本包AXPY不是同一应用；不得相互代用窗口、页数、成本或结果。详见00说明。

1: # A4：固定 native DMA 接受与完成回执
2: 
3: 结论：这个固定 Snitch endpoint 确实有“接受后返回的事务 ID”和“有序累计的完成前缀”。`dmcpy` 返回表示 descriptor 已进入原生请求 FIFO；完成计数的来源是该 job 最后一个写分段的 AXI B 响应退休，二者不能混为一谈。最后 tile 等输入 ID 可以在计数语义上排除后发旧输出；源码没有给出实际发生的提前窗口或净收益。
4: 
5: 另有一个必须保留的源码错配：固定 Carfield runtime 的“cfg0 默认串行”注释与固定 Snitch RTL 不一致。RTL 丢掉 runtime 编码的 bit2，最终 `serialize=0`。这不证明本任务已经死锁，也不抹掉 source/API 对照价值；但不能把注释当成当前硬件的串行、无死锁或完整 native 正确性验收。

15: ## 2. dmcpy 的承诺点：接受，而非 offer 或完成
16: 
17: F:284–299 的原文顺序是：先等 accelerator response spill 可接收，再 assert `twod_req_valid`，等 `twod_req_ready`，才返回 `next_id` 并确认 accelerator request。T:41–60 明确 `ready=!req_fifo_full`、`push=valid&ready`。
18: 
19: 所以返回的数值是这一拍接受 descriptor 前的 `next_id`；同一成功握手使 `next_id` 加一（F:169）。它不等 payload 完成。response spill 和核心响应通路可延迟 CPU 实际看到返回值，因此“接受后返回”不意味着一个固定周期延迟；只拉起 VALID 也不能当成已成功接受。
20: 
21: ## 3. 为什么 completed_id 是有序前缀
22: 
23: 需要核的是实际 FE，不能只找到一个名字类似的计数器就套语义：
24: 
25: 1. FE 的 `twod_req_q` reset 为全零；完整 instruction decode 从未为 `.id` 赋非零值（F:60–79、227–355、361）。这里的软件 transaction ID 是 `next_id`，它没有被写成 descriptor 的 AXI ID。
26: 2. top-level descriptor 按 twod FIFO 顺序输出（T:41–60、72–104），1D descriptor 再进入 backend burst FIFO（K:149–176）。
27: 3. reshaper 只有当前 job 的 `src/dst` 状态；只在当前读写的最后分段可以一起移交时装下一条 FIFO job，AW 的 `.last=w_finish` 只标本 job 的最后写分段，AXI `.id` 从 descriptor 原样带过（R:239–310）。
28: 4. AW 分段进入单个 AW FIFO，按队头 valid/ready 发出；所有 job 的本地 AXI AW ID 都是 0（M:152–169、321–330）。在互连扩大或重映射之前不存在每 job 独立乱序 tag。
29: 5. 每个 AW enqueue 同时把其内部 `.last` 标志入 `last_transaction_queue`。`B_READY` 恒 1，每个 `B_VALID` pop 一项；只有该项 last=1 才产生 `trans_complete`（M:332–369）。**在 AXI 同 ID 写响应按 AW 次序返回的协议条件下**，B 与 last 标志一一对应，完成脉冲就是 job 顺序前缀。这里没有以任意 job done 次数冒充可乱序完成许可。
30: 6. FE 又在每条 1D descriptor 被 backend 接受时排入“它是否 top-level job 最后一条”的 FIFO，在 `oned_trans_complete` 时 pop；只有最后一条完成才累加 `completed_id`（F:140–170）。本 AXPY 为 1D，T:104 直接令该 last 为 1。
31: 
32: 上面给出固定 endpoint 的原生排列与回执合同，并明确依赖正常 AXI 同 ID 返回条件；本轮没有全面证明 downstream 互连/目标的所有协议行为。
33: 
34: FE:169–173 的真实计数是两个 reset0 的 32 位加法器：`next_id` 计已接受 job 数，`completed_id` 计已退休 job 数，因此 completed 是“最后完成 ID 加 1”。busy 精确为 `next_id != completed_id`。selector0/1/2/3 分别给 completed/next/busy/!twod_ready（F:320–324）。原 `dma_wait` 用有符号差 `completed-tid>0`；它需要新鲜 ID 与小于 2^31 的模差窗口，不能把任意古老 ID 永久拿来等（U:429–458）。此有限 AXPY episode 不能被当作回绕/错误执行验证。
35: 
36: `idma_tf_id_gen.sv` 虽在源码清单中，但 FE 没有实例化它。它 reset 为 next2/completed1、且跳过部分回绕数值（I:30–76），不能套到这个实际 FE 的 reset0 加法器上。
37: 
38: ## 4. done 到底保证什么
39: 
40: `trans_complete = is_last_aw & B_VALID`（M:369），且 B_READY=1。它是 **DMA master 端最后写分段的写响应退休**，不是 descriptor 入队、AW 收下或 W 发完。在正常 AXI/data-path 语义下，写出的数据已从 R 接收路径进入数据 FIFO，再被 W 路径取出（D:176–199、282–343），所以它也不是只有读地址承诺。
41: 
42: 但它不证明成功：mover 明确不检查写失败（M:332–335），FE completed 累加不看 B_RESP；data path 的 R_RESP 输入也未参与完成控制。错误响应同样可能推进计数。因此不要用这个回执代替成功/重试合同、host cache handoff、DRAM 持久化、IOMMU 失效完成、quiesce、unmap 或 free；A2 已有硬件 gate 缺口继续成立。
43: 
44: ## 5. 最后 tile 的普通对照可表达什么
45: 
46: 沿 A3 原发布顺序，最后 RX 和 RY 先接受，前一 tile 的 WY 后接受（A:88–98、127–137）。设它们 ID 是 `q, q+1, q+2`。在输入均完成而该旧输出尚未退休的计数状态，`completed=q+2`、`next=q+3`：输入 ID waits 可以通过，busy 仍为 1。该有序累计计数不会仅因为后发输出仍 pending，就把输入 ID waits 强制扩成 wait-all。
47: 
48: 这是一种**允许的回执状态**，不是已观察到的可达时间窗口。若硬件服务/供给恰好使旧输出在最后一次 ID poll 或 barrier 前结束，真实提前窗口就为零；若 poll、barrier 或末尾排空抵消提前，完整净收益也可为零。不能由 buffer 深度或允许 pipeline 直接推出正收益。
49: 
50: 两次 ID wait 在此原生前缀语义下有效；因为 RY 后发，单独等后发输入 ID 已覆盖 RX，原生回执边界只需保留一个32位 ID（4B逻辑状态）。这仅给 root 提供强对照的简化事实，不替 root 裁决完整 owner/consumer、编译寄存器成本或候选接受。四个原2048B L1槽和最后统一排空条件仍按 A3 合同处理。
51: 
52: 实际分级资源是：twod FIFO 3 descriptors（T:41–60）、backend FIFO 3个1D requests（K:149–176）、AR/AW/R/W FIFO 各深3、data BufferDepth=3、last-AW 标志 FIFO 深6、FE last-1D 标志 FIFO 深16（F:90–160、M:121–228、352–368）。它们单位与阶段不同，不能相加冒充一个总接受容量；也没有以源码值冒充同时 occupancy 或延迟测量。
53: 
54: ## 6. cfg0 与 serialize 的固定版本错配
55:

60: ## 7. descriptor 边界和控制位置
61: 
62: core8 在调用 DMCPY 之前仍能选择或延后独立 descriptor，包括 RX/RY 交换、在合法 slot owner 条件下调节输入/输出发布顺序。完成/回收 guard 必须单独满足。接受后 descriptor 已压入 native FIFO；这份 FE 没有 cancel/任意 reorder API，native pipeline也不提供绕过队头的 whole-job 调度。A:77–103、127–149；F:265–355；T:41–104；K:149–225。

1: # A5：固定 HERO AXPY 的翻译地址路径与并行证据边界
2: 
3: 结论：**一个 Snitch DMA 不等于没有内部并行；但一次 AXPY 拷贝也不等于两条同时过 IOMMU 的地址腿。** 集群内 DMA AXI crossbar 先按地址分流：L1 TCDM 地址和其 alias 直接走本地存储，只有外侧地址走 SoCDMAOut。继承 A3 已接受的 FPCluster 外侧连接后，RX/RY 的 host IOVA 读地址 AR、WY 的 host IOVA 写地址 AW 进入同一个 IOMMU；相应 L1 写、读地址留在集群内。AR/AW 各有 FIFO、各自驱动 VALID，且固定 serialize=0 允许跨 descriptor 在旧完成前继续移交，因而不能用“单 DMA”排除跨拷贝并行。**这些原件没有证明默认 AXPY 曾在 IOMMU 内同时保有两个翻译请求，更没有证明实际仲裁竞争、HOL 或时间收益。**
4: 
5: 本席只复用 A3/A4 与五份既有 RTL 原件，未扩源、取网络、编译、仿真、板测、改生产代码或补 hook。以下“过 IOMMU”指接到 `dev_tr_req_i` 的结构路径；实际翻译模式、有效 context/PTE 与成功执行不由这份接线证明。

29: ## 2. 固定 context 标签、接口门槛与未核项
30: 
31: H:469–488 表明所有非 FPCluster 外部 master bypass；FPCluster 的 pre-MMU 请求被接到 `axi_iommu_req`。读写方向都强制 `stream_id=0`、`ss_id_valid=1`、`substream_id=0`。H:514–525 把它接到 `riscv_iommu.dev_tr_req_i`，完成请求接回 FPCluster post-MMU；IOMMU 隐式内存访问另走 IOMMUMstIdx，不是第二个 AXPY publisher。H:492–494 还固定 `.InclPC(0)`、`.InclBC(0)`；本席只记录实参，没有再读 IOMMU 内部去外推其全部语义。

1: # A5：真实AXPY的等待范围与控制位置设计
2: 
3: 2026年10月15日。**推进A的“完成域与等待范围证书”版本；AXPY保留为真实消费者校准任务。普通按ID等待已经能表达本次动作，实际共享翻译竞争和完整时间收益仍需证据。** 本轮不选定跨方向最优，不恢复A默认排名。

5: ## 1. 真实任务与本轮新事实
6: 
7: 固定已有HERO AXPY：32768个FP32元素，64tiles；core8发布，核0–7在四个2048B L1槽上做FMA。原main cold/hot各恢复相同输入，两个kernel共384个job/786432B，映射建立一次、最终撤销一次。源码和A2补丁/编译成果复用，没有运行在当前CVA6四iDMA平台。
8:

10: | --- | --- | --- |
11: | RX/RY：host→L1 | host IOVA的AR/R | L1的AW/W/B |
12: | WY：L1→host | host IOVA的AW/W/B | L1的AR/R |

20: ## 2. 完整任务合同与最小动作
21: 
22: 源地址为`mapped_iova + 0x200000000 + tile*2048`，L1目的/源是原四槽；实际运行IOVA、有效context/PTE和时钟未知。`BYPASS_OFFSET`名称不作为绕过IOMMU的证明。全部源参数、输入公式、地址/context、容量、owner、合法前缀、事件和服务前提已写入[冻结合同](../out/a5-wait-scope-contract-20261015/case-contract.json)。
23: 
24: root保留最小 **O-T1**：倒数第二轮只保存后发RY63的原生返回ID，最后轮只等这个ID后进入原barrier；它的有序前缀已覆盖RX63。逻辑增加一个32位值，实际寄存器/poll/fence开销未知。四槽、最后输出、末wait-all/fence/barrier、DONE、CPU cache交接、独立consumer及全部unmap/失效完成/unpin/free保留。未应用/编译变体。
25: 
26: HERO没有当前平台的NEXT寄存器；这里是DMCPY→FE offer→FIFO接受→返回ID。这个返回是接受回执，完成计数来自写B退休。当前程序先wait-all/起始barrier，预取next与当前FMA并行，结束barrier后才发布WY。最后tile没有未来预取覆盖，旧WY62用bank0、K63用bank1。原生错误计数不代表成功，成功/可见性仍须独立合同。

# Agent执行约定

这里保存稳定的执行细则；当前任务、分支进度和暂停状态只在[当前状态](../CURRENT_STATUS.md)维护。总入口为[研究导航](../研究导航.md)，方法按[ARS-Codex](/home/xvhaocheng/.codex/skills/academic-research-suite/SKILL.md)的对应工作流选择，不默认启动全流程。机器上的技能路径以根AGENTS为准。

## 模型与分工

根[AGENTS](../AGENTS.md)的配置表是项目建议，不是OpenAI针对本项目验证的最优配置。依据为已核对的[模型选择](https://developers.openai.com/api/docs/guides/model-selection)与[部署检查](https://developers.openai.com/api/docs/guides/deployment-checklist)；配置随任务、正确性、返工、耗时和可取得的用量数据调整，不为比较模型重跑已完成工作。

- root和子agent都按当前任务选模型与强度。Sol可以做创新设计；Astra可以直接做开放机制或架构决策，不要求先让Sol反复失败。任务阶段变化时重新判断。
- `ultra`只用于少数特别困难的冲突、依赖推演或严格反例。使用前写明难点、预期解决的问题与接受条件；无代表性对照时标为待验证判断。不把`ultra`、`max`、`pro`视为同义项。
- 区分建议、请求和实际运行配置。工具不能原位切换就如实记录；实际元数据不可得填unknown，不以请求值代证，不改历史记录冒充切换。
- 使用原生上下文和自动压缩默认值，不设旧手动窗口覆盖。给子任务充分而有边界的上下文，完整产物留文件，交接提供原文入口及关键未解项。
- 每个子任务明确独占范围、输入、交付和接受条件；并行处理不同决定问题，不安排重复全文阅读或例行复审。共享IOMMU研究继续Codex-only。

## 建设性研究与新意

- 先发展保留idea核心的最强合理版本。可以贡献机制、接口、组织、实现成本、部署能力或有证据的新认识；有相似构件不等于没有研究空间，组合本身也不证明贡献。
- 优先从已有结果推导：普通方案依赖条件X，目标系统缺少X或需付费；M用何时可得的信息，以代价C在任务Y改变结果Z。给一个决定性预测与相邻失败条件，不用无来源的约束制造差异。
- 提出阶段允许来源绑定、假设冻结的短序列和小模型，不要求完整原生系统或所有关闭路径先实现。诊断与未知清单是输入，不能把反复补条件当作机制进展；精细观测须说明改变了哪个决定。
- 精读决定判断的最近工作，写清其问题、能力、信息、费用与边界，再比较实质。仅标题/摘要相似不足以宣布覆盖；原文未核明确保留。文献及阅读状态进入[根文献库](../references/README.md)。
- 分开发表前作、独立普通构造、同新增付费接口上的等价实现/消融和离线上界。候选换一种写法不自动成为旧方法；同接口策略等价只限制策略增量，接口和架构成本另判。普通对照得到同等信息、付费接口及合法资源复用机会。
- 创新是在明确任务和资源下得到有意义、可解释的改进，不要求所有普通组合都做不到或所有场景都更快。实质重合时，只停止证据覆盖的版本；保留资产，不扩大为整个方向无价值。

## 证据、授权与资源

- 核心结论回到论文原文、源码、原始数据及实际验证；模型一致不是证明。来源事实、条件推导、模型结果、构建、原生运行与板测分开写，缺输入不能靠提高推理强度补齐。
- 授权从驱动、消费者、信任关系和部署合同确定，不凭`dma_unmap`名称推完整安全边界，也不添加隔离需求制造优势。
- 相同有效工作和服务要求下，CPU费用或不可回收内存降低可以是主要贡献。CPU、物理内存、带宽、完成结果分别计；映射不等于额外物理保留，原帧早归还不等于总内存减少。回收/分配改变时分别导出真实再用序列。
- 用户已认可持续研究与CPU/内存价值，不反复询问一般授权或等待保证成立的痛点。只有具体且不能通过条件分析继续的价值取舍才携方案和证据提问。未知成本给盈亏范围，不自动触发系统开发。
- 全局方向、分支局部合同和硬件状态分开；整理、模型或规则更新不恢复暂停goal、旧实验或硬件，不自动升位其他分支。新硬件主张须核实际身份、时钟和时序。

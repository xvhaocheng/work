# The Virtual Block Interface: A Flexible Alternative to the Conventional Virtual Memory Framework

稳定ID：`vbi2020` · 类型：`research_paper` · 主题：`foundations`

作者：Nastaran Hajinazar; Pratyush Patel; Minesh Patel; Konstantinos Kanellopoulos; Saugata Ghose; Rachata Ausavarungnirun; Geraldo F. Oliveira; Jonathan Appavoo; Vivek Seshadri; Onur Mutlu；年份：2020；出处：2020 ACM/IEEE 47th Annual International Symposium on Computer Architecture (ISCA)。

阅读等级：**既有worker全文提取；非root逐篇精读**。本轮是资料归档，不新增人读标记或复现实验结论。

问题：unknown（既有JSON卡没有独立问题字段；已存机制、假设和原文证据保留如下，不能由题名补写）。

机制／已存认识：VBI 用全局 Virtual Block address space；OS 只控制 attach/RWX，memory controller 的 MTL 管 physical allocation 与 VBI-to-physical translation；VBI address 可直接访问 cache，支持 VIVT-like cache、延迟分配和 per-VB flexible translation structure。

支持边界：原记录的全文证据提取；root只抽核部分关键原文，未逐篇重审或复现。

条件：OS 仍保有 access protection 与 CVT；MTL 是可编程低功耗 core，可信；应用用 request_vb/malloc(index)/CVT-relative addressing；VB 不重叠，VBI address 全局唯一，因此无 homonym/synonym；multi-node 是 future work

限制：无硬件原型，仅 Ramulator-VBI 仿真；multi-node 未评估；需要 ISA/OS/应用库改动；安全仅 OS-controlled CVT 权限层面；MTL 复杂策略仍需软硬件分工验证

与研究关系：本条用于对应主题的前作/语义边界；是否当前采用须回到总计划。

相邻资料：[utopia2023](utopia2023.md)：Utopia 把 VBI 视为 intermediate address space/virtual block 相关工作，并称正交可组合。；[sparta2020](sparta2020.md)：两者都强调 memory-side translation，但 VBI 是 controller-centric global VB，SPARTA 是 partition + shared memory-side TLB。

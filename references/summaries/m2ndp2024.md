# Low-overhead General-purpose Near-Data Processing in CXL Memory Expanders

稳定ID：`m2ndp2024` · 类型：`research_paper` · 主题：`accelerators`

作者：Hyungkyu Ham; Jeongmin Hong; Geonwoo Park; Yunseon Shin; Okkyun Woo; Wonhyuk Yang; Jinhoon Bae; Eunhyeok Park; Hyojin Sung; Euicheol Lim; Gwangsun Kim；年份：2024；出处：MICRO 2024。

阅读等级：**既有worker全文提取；非root逐篇精读**。本轮是资料归档，不新增人读标记或复现实验结论。

问题：unknown（既有JSON卡没有独立问题字段；已存机制、假设和原文证据保留如下，不能由题名补写）。

机制／已存认识：用 CXL.mem 可寻址 M2 func 承载 NDP 管理命令，并用 memory-mapped mu-thread 执行通用 NDP；设备侧翻译依赖 ATS/ATC，并用 DRAM-TLB 扩展 TLB reach。

支持边界：原记录的全文证据提取；root只抽核部分关键原文，未逐篇重审或复现。

条件：使用未修改的 CXL.mem 与未修改 host processor；M2 func 需 CXL controller/packet filter 支持；NDP 目标为 memory-bound、低算术强度、大数据集工作负载；使用 HDM-DB 与 back-invalidation 支持 device coherence；M2 func region 按 host process 分配且 uncacheable；packet filter 用 base/bound/ASID 区分进程；设备侧可发 ATS 请求，ATC 缓存翻译，host 负责 invalidation；多 CXL-M2NDP 扩展需要软件做数据放置；自动扩展未实现；kernel 用 assembly 编写，因为 M2NDP 编译器尚未提供

限制：主结果来自 cycle-level 模拟器，不是硬件原型；仅 CPU-NDP OLAP 基线在真实双路 EPYC 上测量；没有评估多设备共享 host IOMMU/IOTLB/ATC 的干扰、队列容量或尾延迟；ATS 被明说可能 µs 级；DRAM-TLB 只补 reach，不解决共享 IOMMU 争用；TLB shootdown 需发给所有 CXL-M2NDP；作者假设 in-memory/no-swapping 使其 rare；多设备 scalability 只按模型并行/数据放置模拟，未做共享 IOMMU 端到端实验；未评估安全隔离或多租户共享 ATC/IOMMU 的攻击面

与研究关系：本条用于对应主题的前作/语义边界；是否当前采用须回到总计划。

相邻资料：[iommu_cost2007](iommu_cost2007.md)：2007 关注软件 map/unmap 成本；M2NDP 关注 CXL 设备侧 ATS/ATC 延迟与 DRAM-TLB reach，二者不是同一瓶颈。；[iotlb_bottleneck2010](iotlb_bottleneck2010.md)：M2NDP 未评估共享 IOTLB 冲突；2010 的 IOTLB 冲突/容量实验不能直接映射到 CXL 多设备共享 IOMMU。

# Designing Virtual Memory System of MCM GPUs

稳定ID：`mgvm2022` · 类型：`research_paper` · 主题：`multigpu`

作者：Pratheek B; Neha Jawalkar; Arkaprava Basu；年份：2022；出处：MICRO 2022 (evidence: L1618 mentions MICRO 2022; cross-file Barre2024 L1919-L1921 cites MICRO 2022, pp. 404-422)。

阅读等级：**局部已核（保留原有核读范围）**。本轮是资料归档，不新增人读标记或复现实验结论。

问题：unknown（既有JSON卡没有独立问题字段；已存机制、假设和原文证据保留如下，不能由题名补写）。

机制／已存认识：提出 MCM-aware GPU virtual memory (MGvm)：dHSL 按 LASP 静态分析为每个 kernel 选择 VA 到 L2 TLB slice 的映射；dHSL-coarse 以 2MB 粒度放置 leaf PTE 到 home chiplet；dHSL-balance 运行时监测 L2 TLB 流量失衡，在失衡且高 hit rate 时切到 4KB 细粒度交织。

支持边界：原记录的全文证据提取；root只抽核部分关键原文，未逐篇重审或复现。

条件：4-chiplet MCM GPU；每 chiplet 有 CUs、L1 TLB、L2 TLB slice、PTW/PWC、HBM；inter-chiplet 约 768 GB/s、32ns 级（L114-L184, L898-L920）。；private vs shared L2 TLB；shared 时 VA 经 HSL 哈希到 home slice，remote L2 TLB hit 更慢（L275-L315）。；LASP 做 CTA 调度与数据放置；PTE 放置跟随数据放置；UVM 适用但需扩展 page fault handler（L306-L314, L1564-L1581）。；基础 4KB 页；64KB/2MB 大页仅扩展讨论；dHSL-coarse 默认 2MB（L690, L896-L897, L1240-L1255）。

限制：仅 MGPUSim 模拟，无硬件原型；大页大规模仿真耗时很长（L1240-L1247）。；static analysis 只针对最大内存分配；被所有 chiplet 并发访问的小于 2MB 热 VA 会在单 L2 TLB slice 排队（L693-L723, L650-L672）。；dHSL-balance 切到 4KB 会牺牲本地 PTE 访问；远程 TLB 条目本地缓存因重复使 MPKI 增 60%（L664-L672, L1551-L1563）。；页表复制需保持多副本一致，复杂度高；MGvm 不做复制（L1551-L1568）。；KM 在 MGvm 下 MPKI 反而更高，因更快 page walk 导致 TLB thrash（L1058-L1060）。；未评估安全/权限隔离与尾延迟。

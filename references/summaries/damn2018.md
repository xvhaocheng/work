# DAMN: Overhead-Free IOMMU Protection for Networking

稳定ID：`damn2018` · 类型：`research_paper` · 主题：`io`

作者：Alex Markuze; Igor Smolyar; Adam Morrison; Dan Tsafrir；年份：2018；出处：ACM ASPLOS 2018。

阅读等级：**局部已核（保留原有核读范围）**。本轮是资料归档，不新增人读标记或复现实验结论。

问题：网络缓冲频繁map/unmap及严格IOMMU保护带来CPU开销，同时需要防恶意DMA设备影响OS读取视图。

机制／已存认识：将IOMMU保护边界从DMA map/unmap上移到用户/内核边界；DAMN分配器永久映射包缓冲，OS首次访问时复制，避免每DMA建立/拆除IOMMU映射。

支持边界：原记录的全文证据提取；root只抽核部分关键原文，未逐篇重审或复现。

条件：OS、设备驱动和IOMMU可信；IOMMU安全且DMA不能伪装；boot前IOMMU保护已建立。；攻击者控制DMA设备但不能重配IOMMU；已授权DMA中的内容篡改不在范围内。；目标场景是POSIX-like内核接口、用户/内核边界本来就有copy的网络路径。；DAMN页只服务包缓冲，且按device和read/write权限独占映射。

限制：不适用end-to-end zero-copy、sendfile、zero-copy IP forwarding、RDMA/DPDK/Arrakis等kernel bypass。；不适用storage media的page cache或O_DIRECT路径，NVMe只能与prior schemes配合。；原型未实现shrinker；内存压力回收只设计上可行。；需要修改网络栈和NIC驱动；v5.1实现后来被F&S质疑不完整。；IOVA元数据编码会降低huge IOVA pages效率，是性能差距来源之一。

与研究关系：映射组织与持久授权近邻：按device/rights/NUMA分池、长期映射、refcount复用、首读复制均已有；本项目B-only回收和完整资源费用须按具体owner/cut比较。

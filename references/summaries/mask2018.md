# MASK: Redesigning the GPU Memory Hierarchy to Support Multi-Application Concurrency

稳定ID：`mask2018` · 类型：`research_paper` · 主题：`gpu`

作者：Rachata Ausavarungnirun; Vance Miller; Joshua Landgraf; Saugata Ghose; Jayneel Gandhi; Adwait Jog; Christopher J. Rossbach; Onur Mutlu；年份：2018；出处：ASPLOS 2018 (23rd ACM International Conference on Architectural Support for Programming Languages and Operating Systems), Williamsburg, VA, USA。

阅读等级：**既有worker全文提取；非root逐篇精读**。本轮是资料归档，不新增人读标记或复现实验结论。

问题：多应用GPU并发时，TLB容量、翻译请求和数据访存争用互相放大，单独优化翻译命中率不足以保证应用进度。

机制／已存认识：多地址空间并发下的 GPU 内存层级重设计：TLB-Fill Tokens + 32 项 TLB bypass cache 抑制共享 L2 TLB 抖动；按页表层做翻译感知 L2 bypass；Address-Space-Aware DRAM 调度器（Golden/Silver/Normal 三队列优先翻译请求）；用 per-core 页表根寄存器 + L2 TLB 9-bit ASID + 定向 flush 提供内存保护。

支持边界：原记录的全文证据提取；root只抽核部分关键原文，未逐篇重审或复现。

条件：4 级页表；per-core 页表根寄存器（类 CR3）与页表根 cache 供 PTW 使用；L2 TLB 条目扩展 9-bit ASID；flush 只针对指定 core 的 L1 TLB 及匹配 ASID 的 L2 TLB 条目；token epoch 100K 周期，miss 率变化 >2% 才调整 token；InitialTokens=80%，threshmax=500；共享 PTW 最多 64 并发 walk；PWC 8KB 16-way；L1 TLB 64 项/core、L2 TLB 512 项；6-bit 并发 walk 计数器，仅支持 ≤64 应用（作者列为未做）；评价用 oracle 静态核分区 + GTO，调度非本文重点

限制：页错误与 TLB shootdown 明确留作 future work（仅引用他人技术）；计数器虚拟化（>64 应用）未做；纯模拟为主；实机测量仅用于时间多路复用开销的动机验证（K40/GTX 1080）；不涉及 MIG/硬实例隔离、动态映射迁移、远端 PTW、尾延迟指标

与研究关系：当前M0首PTE票据的直接强近邻：MASK已联合考虑PTE/data优先、应用配额和存储组织；本项目只能研究具体接口实现能力与完整成本差异。

相邻资料：gpu主题近邻；历史收录不代表当前主线采纳。

[iommu-platform/docs/research-landscape-20261005.md:40](../../iommu-platform/docs/research-landscape-20261005.md)：

共享资源上，静态容量分配能提供部分隔离但可能低利用；动态共享能提升吞吐但可能破坏可预测性。[MASK](https://research.ece.cmu.edu/safari/pubs/MASK-address-space-aware-gpu-memory-hierarchy_asplos18.pdf) 显示多地址空间共享 GPU L2 TLB 和 page walker 时，translation 会成为一阶瓶颈，token/bypass/DRAM 调度有收益；[Walk Stealing](https://www.csa.iisc.ac.in/~arkapravab/papers/hpca21_DWS.pdf) 显示静态划分 walker 会 under-utilization，动态偷取提升多租户吞吐，而 DWS++ 为了改善公平，会牺牲部分总吞吐——这不是无条件定律；[KPart](https://people.csail.mit.edu/sanchez/papers/2018.kpart.hpca.pdf) 在真实 Intel LLC 上显示 per-app way partition 粒度粗、associativity 低，聚类后才改善；其背景先行点也要保留：给后台更多缓存可降低后台内存带宽需求、改善 moses 前台尾延迟，因此现有 P/N 组合现象不自动新。原证据卡见 L2。剩余约束：本次证据未确立跨平台通用隔离结论，不能写成“隔离与利用率不能同时最优”的形式化不可能定理。

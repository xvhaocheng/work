# GRIT: Enhancing Multi-GPU Performance with Fine-Grained Dynamic Page Placement

稳定ID：`grit2024` · 类型：`research_paper` · 主题：`lifecycle`

作者：Yueqi Wang; Bingyao Li; Aamer Jaleel; Jun Yang; Xulong Tang；年份：2024；出处：2024 IEEE International Symposium on High-Performance Computer Architecture (HPCA)。

阅读等级：**局部已核（保留原有核读范围）**。本轮是资料归档，不新增人读标记或复现实验结论。

问题：unknown（既有JSON卡没有独立问题字段；已存机制、假设和原文证据保留如下，不能由题名补写）。

机制／已存认识：多 GPU UVM 下以页错误/保护错误计数触发页放置策略切换，用 PA-Table/PA-Cache 记录 VPN、读/写属性与故障计数，再用 Neighboring-Aware Prediction 将连续页合并为页组并在 PTE 中维护 scheme bits，从而运行时在 on-touch、access-counter 与 duplication 之间动态选择。

支持边界：原记录的全文证据提取；root只抽核部分关键原文，未逐篇重审或复现。

条件：UVM 驱动在 CPU 侧维护集中页表，每个 GPU 有本地页表；本地 PTE 无效产生 local page fault 并由 UVM 驱动处理（L309–L325、L363–L366）。；页的私有/共享与读/读写属性可由本地缺页和保护错误计数推断；私有页只触发一次缺页，不会进入策略变更流程（L957–L990）。；相邻页通常具有相似属性且属性变化同步，因此可以用一个页的属性预测相邻页（L771–L868、L1033–L1071）。；初始页放置方案为 on-touch migration；方案变更需要 UVM 驱动在各 GPU 间失效对应 PTE/TLB（L310–L314、L1232–L1236）。；页组提升规则为：相邻 8 页中超过半数采用同一新方案才合并，之后可递归提升到 64 页（L1132–L1147）。；页组检查在后台执行，不阻塞 GPU，也不伴随额外迁移或 PTE/TLB 失效（L1237–L1247）。；方案决策延迟通常可隐藏在 page table walk 中；作者称评估中很少出现需要推迟 page fault replay 的情况（L977–L984、L1220–L1230）。

限制：纯仿真，使用 MGPUSim，无真实 GPU 硬件原型或商用部署验证（L405）。；Ideal 基线被作者明示为不可实现，仅用于体现优化空间（L51）。；DRAM 容量配置为应用内存 footprint 的 70%，用于模拟 oversubscription 并避免仿真时间过长（L372–L373、L408–L415）。；默认 4KB 页；2MB 大页下平均收益从 60% 降至 23%，作者归因于大页 false sharing 使页属性混合（L1516–L1565）。；C2D 等 producer-consumer 共享页只产生两次缺页，低于 fault threshold，GRIT 维持初始 on-touch（L1319–L1328）。；page duplication 的 write-collapse 与副本管理开销仍存在，GRIT 只是切换策略，不消除这些成本（L640–L670、L1232–L1236）。；未评估远端 PTW、队列占用、失效延迟尾部分布；未涉及 IOMMU/SVA/PASID/设备认证/安全隔离。；没有跨论文可比性：主结果基线是 MGPUSim + 4KB 页 + on-touch，不能与 CoLT 的平均性能数字直接比较。

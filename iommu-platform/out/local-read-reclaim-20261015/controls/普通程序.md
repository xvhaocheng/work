# LR1 独立普通程序

这三个程序给出了完整普通控制流程：整份拷贝完成后归还源页、源读阶段完成后归还源页、具名目标失效与排空后归还源页。后两者在相同、已付费的完整目标证明上可以覆盖 LR1 的动作；不能把普通程序强制改成等待全部 DMA 或目的 W/B 完成。是否覆盖候选的真实执行链，由 root 的真实值、generation 和共同协议集成检查接受。

固定输入为 DMA0/1、depth512、aligned4096B、DEFAULT、1PTW、cache16、原队列。源 PA 对象与目的不重叠，源授权只读。这里没有增加数据 buffer，没有修改生产 RTL、驱动或 ABI，也没有重跑旧实验。平台容量与实际接线由 root 的独占源码任务核验，本席不以这些前提替代 native 证明。

## 执行接口

代码是 [ordinary_policy.py](ordinary_policy.py)。三个函数各自写出动作分支，不互调，不导入候选或 oracle；只共用严格的输入校验。输入是一次原子 frozen snapshot，其 16 个字段见文件 `SNAPSHOT_FIELDS`。所有 bool 必须是字面 True/False，epoch 和 old_obligations 必须是非负 int，bool 不算 int。缺字段、非法类型、inactive request、错 epoch 均返回 wait；额外私有字段不读取。

`all_readers_complete` 的含义必须由共同实现证明：每一个注册的旧 generation reader 对这整页 4096B 都已在 DMA 的真实 R 接收点收齐，身份、offset、长度、错误、最后拍及所有权都正确；helper 完成、cache hit、AR 已发、RVALID 或整个 job 的某个状态位不能冒充。`old_obligations == 0` 另外覆盖 raw、walk、helper、OUT、heldVALID 和已接受事务，以及同一个已授权原始 parent 的 committed-but-unissued interval/remaininglength；交接期间不能丢主。

`all_sources_sealed` 封的是目标 PA 对象/旧 generation 的 accepted-parent/authorization frontier：不再承诺新旧代 parent 或未注册 interval。已授权的 4096B 原 parent 已经拥有两段声明 read interval；若中途 seal，尚未发的第二 burst 仍是旧义务，必须允许它按原计划发出并退休。不能暂停这个 committed remainder，否则会造成 source join 永远等不到的死锁。已出现 heldVALID 的 AR 按协议保持直到真实接收。seal 不表示禁止所有后续旧代 AXI AR，更不是全系统静默。

| 动作 | 共同执行器必须做的工作 | 成功归还条件 |
|---|---|---|
| seal | 核 source/job/context/PA-object/generation/all-readers 注册，封旧代新 parent/未注册 interval；继续退休原 parent committed remainder、heldVALID 与各阶段所有权 | 不归还 |
| wait | 等目标真实 R 或其余旧义务退休，保留原容量与正常 W/B 进展 | 不归还 |
| revoke | 撤掉覆盖源 PA 对象的全部相关 PTE 授权，处理 IOVA/context 别名 | 不归还 |
| sync | 使 PTE 更新按平台缓存和内存排序规则可见；必要的缓存维护不能省略 | 不归还 |
| invalidate | 提交覆盖全部别名的精确失效，并取得真正提交/完成证据 | 不归还 |
| order | 完成目标必要排序及 CQ 命令顺序证明；已有独立目标排序证明时无需新增全局 PR/PW 排空 | 不归还 |
| ack | request epoch 匹配、全部资格与完成证据成立，交给页所有者执行成功归还 | 唯一成功归还点 |
| error | 旧入口已封且 old_obligations 为零后的错误收据 | 页面保留隔离，不生成成功 release |

这些动作是请求，snapshot 的对应完成位只能在共同执行器真正完成后改变。布尔接口不是免费信息；物理 gate、读接收统计、generation/别名注册、旧流水义务和 CQ 完成都要实现并计费。读错误的 seal/wait/error 路径允许先于 whole-copy completion；失败的 copy 可能永远没有该完成位。目的后续 W/B 的正常或错误退休仍走共同协议，不由 error 收据抹掉。

## 三个独立流程

**whole_copy**：普通 driver 等整个 copy/job 完成，再关闭源新 parent 的授权入口，核整页读与所有旧流水已退休，执行源 PTE 撤权、缓存维护、精确失效、排序/命令完成，最后 ACK。该程序按其自身定义先等 `whole_copy_complete`，不是替其他普通程序增加限制。

**phased**：普通 producer/driver 把源读阶段的全部 registered readers 做 join，封旧代新 parent 授权，继续发出并退休已授权原 job 的全部 committed read remainder，对原有 raw/held/accepted 流水做精确退休。join 的真实 R 与 old_obligations 都完成后，调用普通 unmap、缓存同步与精确失效，取得必要命令完成和目标排序，再 ACK。目的数据已经在原 DMA buffer/原队列中，非重叠目的 W/B 可继续。这里没有等待全 job 或其他 DMA。

RISC-V 的 `IOFENCE.C(PR=PW=0)` 只提供前置 CQ 命令完成/提交语义，自己不提供旧 DMA read 排空。若同一收费公共实现已证明所有目标读真实完成、所有旧入口被封且旧义务退休，源只读与无别名/无重叠条件又成立，则可以使用这个轻命令同步。若证明缺一项，phase 等待；不能把当前 native flags0 直接宣称为无条件安全。

**targeted_drain**：普通 driver 明确目标 IOVA/context/domain 与全部 PA 别名，封旧代新 parent 授权并继续履行原 job 已承诺 interval，等完整 DMA reader join 和旧流水退休，撤权并同步，然后发对应目标失效及适用的排空/完成命令，待目标排序证明后 ACK。Intel VT-d 是这种流程的具名前作：domain-selective 与 page-selective-within-domain 对已经过 remapper 的未翻译主存请求分别给 domain 与地址范围排空保证。它不能代替 raw/held 请求封闭或 DMA 整页接收证明；在本 RISC-V FPGA 上此函数是普通协议参考，不表示存在 VT-d 硬件。

phase 和 targeted_drain 在当前冻结接口上的成功序列一致，是两个独立普通流程得到同一目标协议动作；没有通过导入候选、改名或隐藏候选信息得到答案。Intel 的适用硬件/排空范围与 RISC-V 的相同收费目标证明应分别解释，不能从相同字符串序列推出 native 成本相同。

## 相同真实撤权要求下的其他普通做法

| 做法 | 能否满足本次源页归还合同 | 完整成本或限制 |
|---|---|---|
| 持久映射 | 继续保留旧设备授权，不满足源 PA 对象撤权并交还新所有者的要求；若补同一撤权流程，则重新计入 PTE/cache/invalidate/order | 可用于同一合法所有者复用，但不能把这个较弱需求当本次对照 |
| 原 DMA buffer 复用 | 整页真实读接收与全部旧义务完成后，支持 phase 的非重叠目的写继续 | 已有 buffer 不新增；精确 readreceipt、封入口与撤权仍收费 |
| scratch copy | 可在额外位置保存数据后做源撤权；不会自动消除旧 reader/alias/generation 闭合 | 每个物化页至少多 4096B 存储以及 4096B read+4096B write，随后原 copy 从 scratch 读；实际调度、cache、重映射与 CPU 成本未知 |
| CPU 完成分阶段复制 | 可以组织读 join 和正常 unmap | 必须计实际 CPU、缓存维护、driver 与应用成本，当前均 null |

scratch 或 CPU 复制属于不同成本的普通比较项，没有实现到这三个 frozen policies，也不是新增案例实验。

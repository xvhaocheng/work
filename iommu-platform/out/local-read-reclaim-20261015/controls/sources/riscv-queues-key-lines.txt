   979  <p>Software should ensure that all previous read and writes processed by the IOMMU
   980  have been committed to a global ordering point before reclaiming memory that was
   981  previously made accessible to a device. A safe sequence for such memory
   982  reclamation is to first update the page tables to disallow access to the memory
   983  from the device and then use the <code>IOTINVAL.VMA</code> or <code>IOTINVAL.GVMA</code> appropriately
   984  to synchronize the IOMMU with the update to the page table. As part of the
   985  synchronization if the memory reclaimed was previously made read accessible to
   986  the device then request ordering of all previous reads; else if the memory
   987  reclaimed was previously made write accessible to the device then request
   988  ordering of all previous reads and writes. Ordering previous reads may be
   989  required if the reclaimed memory will be used to hold data that must not be made
   990  visible to the device.</p>
   991  </div>
   992  <div class="paragraph">
   993  <p>The <code>IOFENCE.C</code> with <code>PR</code> and/or <code>PW</code> set to 1 only ensures that requests that
   994  have been already processed by the IOMMU are committed to the global ordering
   995  point. Software must perform an interconnect-specific fence action if there
   996  is a need to ensure that all in-flight requests from a device that have not yet
   997  been processed by the IOMMU are observed. For PCIe, for example, a completion
   998  from device in response to a read from the device memory has the property of
   999  ensuring that previous posted writes are observed by the IOMMU as completions
  1000  may not pass previous posted writes.</p>
  1001  </div>

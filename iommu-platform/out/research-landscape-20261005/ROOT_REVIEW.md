# Codex 原始证据审查与地图成稿要求

这是主协调者的关键来源审查/研究判断，不是新的实验结果。四份 DeepSeek 阅读报告保留原文；本文和最终 docs 地图优先于原报告的过度表述。

## 已直接核查的关键边界

- Barr 2010 摘要/§2–4：缓存部分翻译可跳过层级；TLB miss 不应默认等于四次未缓存 DRAM 访问。
- KPart §III-C、§V-H，提取文本 439–468、1478–1505：给后台更多缓存能降低后台内存带宽需求、改善 moses 前台尾延迟。这一反直觉本身早有先行工作；不能直接把我们的 P/N 组合现象写成首发现。
- Page Walk Stealing 2021 文本 316–344：同资源比较是必要的；加 walker 也可能冲击 TLB。论文结果是 GPU 模拟，不是我们 RISC-V IOMMU 的现成因果证明。
- HDPAT §II，文本约 74–95：明确把 GPU-to-GPU 迁移排除在范围外，因此没有评估 TLB shootdown 影响。必须保留这一重要条件。它研究晶圆级拓扑的集中请求和多跳延迟，不能泛化成每个 IOMMU 的所有瓶颈。
- ShareMMU §V-B/V-C，文本 364–455：Permission Tracker 对私有 TLB 包含，驱逐需定向 back-invalidation，权限下降可只清受影响设备权限；仍等待 dirty write-back/flush acknowledgment。没有消灭全部动态更新/排空成本。安全可信假设、性能隔离、数据一致性分开。只作为前沿条件，不据此转安全主线。
- IDYLL §1/§2、文本 124–190：42% 失效开销来自双 A100 实物剖析；零失效上界和提出方案收益来自 MGPUSim。不能说整篇全实物，也不能说整篇没有实物证据。
- ObservUVM §IV-A，文本 350–410：主动把选定 2 MiB 区域的一部分 64 KiB 采样页迁至主存，再借 PCIe 访问计数推断活跃性；并非计数器直接全量监控显存。依赖空间局部性，采样有代价。§VIII 多 GPU 仅讨论，当前实测单 GPU。原文用 HBM 泛称 GPU 显存，实际 RTX 3090 不应被写成采用 HBM 芯片。
- RISC-V IOMMU 官方队列文档 319–355：PR/PW 只覆盖已被 IOMMU 处理的请求；尚未抵达的设备在途请求可能另需互连 fence。标准已支持按上下文/地址失效，也允许简单实现扩大为全局失效；不能把实验 quiet 条件当通用规范要求。
- vAttention：现在已有 ASPLOS 2025 正式版；旧2024版保留历史，不再作为唯一当前题录。需改驱动以支持细粒度；映射可与 LLM 计算重叠；与强 PagedAttention decode 对手可持平，收益看上下文/阶段。不承诺所有动态场景都有瓶颈或都被解决。
- NDS §5.3/§6.1 文本 820–880：作者报告自建 TLC SSD/控制器+NVMeoF 实验平台，不应误改成纯模拟。
- BypassD 文本 367–370、§5：ext4 without data journaling，不应简写成完全无日志；硬件 IOMMU 改动成本以模型评估，有真实软件/SSD实验。
- Tiara Table 1 / §2：应用间接表≠硬件OS页表，PagedAttention已优化批处理基线是2RTT，不拿朴素160RTT当最强对手；指针链不同于可并行散读。2026预印本，不能说已正式会议发表。
- Revelator 2026 v2 现已取得（2026-06-25更新，与2025v1不同）。最终成稿须读 v2 核对，采用当前标题 System-Software-Guided；已有 ISCA2026 DOI 10.1109/ISCA66397.2026.00147。v2 Linux6.10.8原型+Sniper模拟+RTL综合，不能说完整真实处理器加速已实现。支持THP/NUMA并不取消OS分配协同要求，不照搬旧版27%等数字。

## 不采纳的模型推断

L3 中“唯一硬分界”“能隐藏就只是工程”“预取完全无能为力”“只能PIM/NIC”“裸VMM普遍慢100倍”“epoch重复GPS”“没有论文给定量界”等均收窄或删除。L4已给定向修订。L2“隔离/利用率不能同时最优”不能写成形式化不可能定理；“不存在通用结论”只能表示本次证据未确立。2015严格失效不可扩展是当年实现测量，不能泛化为2026所有实现的定律。

## 主地图的范围和结构

用户要先摸清版图、经典与前沿、领域卡点；不再优先此前3个候选，不以现有FPGA适配度筛掉大问题。论文创新仍未成立；旧172功能验收是实验能力和证据资产，不是论文贡献证明。

成稿保存为 docs/research-landscape-20261005.md。应有：

1. 直接结论：主干已有大量有效方法，主要困难在规模、粒度、共享、动态变化和跨层信息条件同时出现时；这是本次跨论文综合判断，不是无条件“不可能三角”。
2. 六条研究线总表：翻译覆盖/延迟；共享干扰与服务顺序；I/O软件管理/映射生命周期；间接访存与布局/搬运接口；GPU动态分配；驻留迁移与观测。每线经典→现在→已解决→受限条件。
3. 全局五到六个卡点，每个写具体因果和至少2个原始来源，保留强解法而非故意弱化对手：粒度不一致；共享利用率与可预测性；动态放置与更新代价；缺信息及测信息有成本；访存位置/依赖/布局与可编程性；静态资源和物理扩展极限。无需给每个卡点发明方案。
4. 代表论文索引（约36篇，按机制族分组，合并vAttention和Revelator版本，不重复计篇）：题名短称、年份/venue、做了什么、条件/评估性质。每行主来源为原始 URL；不要全文摘录、不抄数字大表。完整证据卡链接到 workers 报告，并明确那些是原稿、采用本次更正。
5. 2025/2026前沿窗口：HDPAT、Revelator v2、ShareMMU、DX100、MINISA、ObservUVM、OASIS等已全文；Tiara为预印本。下述4个仅摘要/局部原文，明确不能据此作新颖性裁决。
6. 最容易误当创新的常规组件与强基线。不能因为组件经典就推出所有组合没价值；要有新问题/机制/代价曲线/可泛化证据。
7. 项目位置：是共享翻译线的可修改实物平台；不代表CXL/ATS/GPU/UVM已部署。当前P/N已可验证部分机制，未建立真实应用收益、一般性、创新。下一步是挑少量真实应用条件，逐项对比现有论文假设和最强对手，之后再决定是否/怎样做实验；本轮无源码/测试/构建/上板。
8. 明确剩余范围：CXL完整放置/一致性、编译器布局与稀疏格式、RDMA注册缓存/撤销、更广的实时QoS/形式化界还需专门深读；不把未覆盖说成没有工作。

用简洁中文、有因果、可导航；总长建议4000–6000中文字加表格和链接，不塞所有细节。无需网页、交互界面或外部发布。不写“本文完全摸透全部领域”。引用紧跟观点，来源URL可由manifest取得；相对文档链接以最终docs目录解析。

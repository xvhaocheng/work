阅读原文时需保留四个边界：

- **＋37,854拍不能归为主线PR/PW drain。** 该数来自旧m1/m2/m3、PR=PW=0及两条fence的过程；额外等待主要在CQ FETCH/REGISTER，即命令取数。主线ML-strict另使用PR/PW测试模型，尚未做不同邻居流量强度的因果比较。见[原始诊断](../dead-translation-20261017/diagnosis/results.md)。
- **“100%”是本批差分交互项。** A单跑细粒度减宽失效为0，共跑差为19,512拍，因而该差分交互占比为100%；不能推成所有额外周期都由PR/PW等待或某一种DDR阻塞造成。PTW、COPY和配置段存在抵消。
- **RISC-V默认配置有条件。** 策略choice默认strict，但是否编入DMA-IOMMU仍须区分；最终CONFIG_IOMMU_DMA=n时core默认IDENTITY。本轮没有生成并启动主线RISC-V配置。见[Linux核查](../dead-translation-20261017/sources/linux/findings.md)。
- **FQ容量与测量窗口要写准确。** 默认256槽实际容纳255条，第256次入队先刷新；本轮只入队128条，A/B工作均在10ms期限前结束，随后确有一次timer刷新，最终排空为501,475拍。工作窗口内0%变化不能外推为长时间FQ无干扰。见[实验报告](../dead-translation-20261017/README.md)。

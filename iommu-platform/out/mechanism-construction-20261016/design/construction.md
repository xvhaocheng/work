## 1. 结论与范围

**可继续发展的具体机制是：真实PTW启动时发一个短期“首PTE顺序票据”，在共享选择器第一次承诺独立载荷前，给这个尚未公开的PTE留一次顺序位置；P1取得顺序承诺后立即放行载荷。** 不预测第二、第三层PTE，不预约整个walk，不修改MIG返回排序，不取消任何旧VALID或已接受请求。

它有一个具体的完整任务正例：两路各4096B copy均成功，三层walk、全部读写及4个B保留，V/A完整完成和最终排空都提前6个模型时间单位。A最后源读反而晚3单位，但其原本就被V写owner挡住；这3单位不是被隐藏掉的受害者成本，已记入结果。

**同一主例里，普通“先读128 beat，P1优先，再读128 beat”在零额外费用时还比候选快2单位。** 因此不能宣称早意图具有独占的完整性能收益。存活的具体研究命题是：在黑盒MIG外，保留原burst的短票据能否以较少的额外AR、返回拼接及集成成本，取得这类依赖间隔覆盖；完整成本需与复用现成legalizer的普通分段比较。本文给出费用盈亏区间，没有以未知费用当作停止构思或自动开发硬件的理由。

旧M0的3689周期差额已经被行为DDR的DS返回优先消除；旧10月14日固定CPU-off/两sole4096B DMA自然prefix的负结果仍保留。本例不是那段prefix的新收益，也不是实板约12.7%退化的归因。此前early-intent的思路不是本轮新发现；本轮新增的是一次性P1合同、完整收益因果和暴露其最强低成本替代的具体短序列。

## 2. X：M0普通强对照依赖的接口，实际MIG缺在哪里

M0的普通DS优先可以在C++**已接受读队列**中换服务次序，保留held R及同ID次序。该规则让P/PN的V/A/quiet分别相同，属于已验负结果，不需要重跑。[M0原报告](../../../docs/workflow-g0-m0-results-20261010.md:16)的完整范围在`:19–35,58`。

所核生成MIG的外部接口没有“后来PTE提升到已接受payload前面”的read-vs-read操作。source依据是生成参考的accepted-read保序与held义务，不是把全部AXI实现说成同一服务律。[DDR边界](../../../docs/ddr-service-boundary-20261014.md:7)和[来源合同§1](../source/minimal-source-contract.md:7)给出原源码及manifest。

实际可改的位置是更早的共享selector：当前有效DS头可以先选，但本地PTW已经合法启动、PTE还经过MEM_ACCESS及DS仲裁/spill时，该selector可能只看见另一个合法L。一旦首次输出L的VALID，晚到P便不能撤回它。真正缺的是**已拥有翻译依赖到首次payload承诺之间的及时信息通路**，不是再发明一个优先级公式。[源合同`:40–50`](../source/minimal-source-contract.md:40)明确实际start、聚合端口、目标关联及不能授予未来权限的边界。

选择该X不表示所有普通程序都不可能猜中start。已知固定工作流、普通等待、分段或提前准备都可能规避它；下面逐项给实际机会。

## 3. M：最小信号、状态和动作

### 3.1 一次首PTE，不保留整条walk

1. 在合法S1的实际PTW启动条件上，产生一次`intent(occurrence)`。不能拿`init`电平、当前active或未经接受的输入VALID代替真实start。
2. 关联该次walk的第一笔物理PTE AR。模型用显式marker；真实实现可检查现有PTW fullID加单walker occurrence能否完整复用，但在证明前不能把目标关联当免费。DS还有DDTW/PDTW/CQ等，任意DS出现不能清票据。
3. intent及时到达且没有旧held时，抑制新payload首次offer。其他DS、所有已承诺AR、R/W/B、错误和owner排空照常运行。若L是当前owner生产所需的数据，本例的“独立L”合同不成立，不能靠门控阻断它。
4. **P1真正进入共享selector原output spill后清票据**。以后P2/P3只享受普通current-VALID DS-first/F4。P1的有效顺序承诺不是翻译成功；后续PTE地址和存在性仍由真实返回决定。
5. 最长H单位后解除新抑制；超时不能撤销held P或L。晚intent遇已offer L记录错过窗口并正常排空。一个episode后，给已有non-DS一次接受机会才允许再次关闭；DS-first/F4原公平计数单位仍是selector接受，不是MIG接受或R完成。

H=16是模型参数。它只给新抑制一个有限界，不保证下游READY或内存完成的墙钟上界。错误/取消/reset不能清除真实旧义务；完整错误与reset实现未在本小性能模型验证。模型只接受无错误成功工作量，其他情形留作明确协议义务，不能伪称全协议验证。

### 3.3 参考marker与条件无新增marker版本

参考版本M-tag把“本次首PTE”显式随原DS请求传递，保证目标关联，代价是N_tag及接线。更低成本的M-ID版本可以利用**原有PTW fullID＋一个pending票据**：新start置pending，首个匹配PTW身份的共享AR接受清pending。这样不新加整条DS/spill的user字段，不存PTE地址，不改R路径；root正定向亲核local PTW ID0到共享fullID的实际映射（fullID48是待原文确认的具体候选值）。功能性成本可降为start到selector的一条信息通路、pending/timer/escape控制以及已有fullID的一个匹配条件；marker位是否真正省净、组合路径和Fmax均未测。

这个降成本版本有两项可审核的具体理由，不能靠一句“单walker”省略：第一，normal单PTW的新start前，上一walk所有PTE返回已经被消费，所以不能有旧同身份AR在途待选；第二，本次intent必须在其P1共享选择之前到达，才可将下一匹配AR认作P1。**晚于L首次offer只会失去收益；晚于P1自身选择则可能误把P2当P1，属于关联正确性问题。** 后者须有传播先后保证、显式确认，或保留参考marker，不能假定timeout自动解决。

已有active_o也可作为较晚的持续信号，但实际start首拍active仍0；它与真正start的早一拍能力分开报告。无论选哪条线，传播/注册不能抹掉有效窗口。这里是对同一动作合同删掉冗余状态的建设性实现选择，不是另一个调度机制。冻结事件模型保持精确P1关联，因此无需改合同或重跑模型；真实ID/在途证明及最终接受由root保存，本文不抢先声称已验。

## 4. Y：正常来源形状与完整有限工作

选择已有源码支持的正常两路aligned4096B copy，使用前两DMA原512×8B buffer；AXI burst最长256 beat。V源已合法读回512 beat、目的cold、已持第一笔W owner；A首256源beat已回，第二个256-beat源读L已成功翻译且完整字段稳定，受原4096B fullbuffer证书允许到达selector。A读L不生产V的任何必要数据；A写仍须等V的初始W owner释放。

旧C-readiness证明了normal源先行和**另一job** A提前源读被V W owner延后完成的形状，没证明同job FAST源/冷目的组合，也没证明本次精确相位。[来源`:25–38`](../source/minimal-source-contract.md:25)明确区分这些事实。

为避免删工作，模型计入：

- 公共前缀V源256+256及A源256，共768 R beat；示意前缀时间P0=768。每策略总完成均加P0。
- suffix含A剩余L=256 R beat、冷目的P1/P2/P3各1 R beat、V/A各2×256 W beat、每write burst自己的B。
- 全cold任务payload R=1024 beat、PTE R=3、W=1024；AR=7、AW=4、B=4。两路原copy各4096B，有效写结果8192B。
- 写owner继续次序冻结为普通RR的V0/A0/V1/A1；V0先保留原owner，其余每笔仍有独立AW/W/B。不是把512 beat写成非法一笔burst。
- 同一个串行内存数据资源服务R和W，正在服务的burst不抢占；没有假设R和W免费同时跑。读FIFO及就绪write的选择见JSON，任何就绪write不能为了保胜无故闲置。

这是一个**从有来源形状的检查点出发、把前缀费用加回的条件有限任务**。P0的原始读工作是明确的；从实际reset到该检查点的完整native交错仍未知。普通提前准备可以改动这个前缀，不能因为本比较从检查点开始就把它禁掉。

hot配对状态使用同样4096B有效工作，但目的翻译已缓存，因此无三笔PTE。cold/hot在决策时共享selector公开的AR/W/held/owner历史相同，两者t=0都没有可利用的WVALID；hot W首次ready参数为4。区别只藏在内部PTW是否真实启动。该不可区分性仅是**声明的selector观察合同**，不涉及整个CPU或软件历史，也不是native成对prefix已证明。

## 5. Z：手算正例为什么改善整个任务

冻结参数为：L=256，P1在共享端可见d=2，每PTE服务1；P1返回到P2可见间隔τ1=8，P2到P3间隔τ2=1，P3返回到合法V写ready的尾4；每B在该burst WLAST后2单位返回，可与后续数据服务重叠。d/τ1/τ2/尾4/B2全部是模型参数，不是native时延。源码支持存在状态/DS路径依赖，并不证明这些精确数值。

| 事件 | 普通current-VALID DS-first | 首PTE票据 |
| --- | --- | --- |
| A最后源L | 0–256 | 3–259 |
| P1 | 256–257 | 2–3 |
| P2 | 265–266 | 259–260 |
| P3 | 267–268 | 261–262 |
| V0首次可服务 | 272 | 266 |
| V0 / A0 / V1 / A1的W区间 | 272–528 / 528–784 / 784–1040 / 1040–1296 | 266–522 / 522–778 / 778–1034 / 1034–1290 |
| V完整B完成 | 1042 | 1036 |
| A完整B完成、quiet | 1298 | 1292 |

共同前缀P0=768加回后，V完整完成1810→1804，A/quiet2066→2060。第一PTE早254单位并不是贡献数字；**整个任务只净省6**，其原因是把原先P1后的8单位依赖空隙用L覆盖，付出开头等P1的2单位。

这里A R晚3单位，两个任务的完整完成却都提前6。V最初W owner使A提前读完不能立即写；没有这个来源绑定的完成依赖，不能从PTE更快自动推到净完成更快。

在L足够长覆盖τ1、其他义务和上述服务律保持时：

`candidate_complete_gain = min(L_service, tau1) - d`。

再有候选接口的额外暴露费用h_e时，应减h_e。该h_e只可表示仍及时到达后的实际额外路径费用；intent真正迟到则整次顺序机会丢失，不能继续套“只少一点收益”的公式。

## 6. 强普通方法保留全部合法机会

### 6.1 current-VALID与固定guard

O_CURRENT已给DS-first/F4全部当前头、原held/ready、声明的公开历史；它没有P1可见前的内部start信息。O_GUARD_G在L首次eligible后固定等G，期间DS仍可进；同一G必须同时用于cold和hot，不能事后拼两个赢家。

G=2在cold完全复现候选quiet1292；hot则quiet1284，比候选和O_CURRENT晚2。G=0在hot匹配，却在cold晚6。其余G={1,3,4,8,16}也已冻结供模型实际执行。这个差异说明信息可以减少无walk时的保守等待，**不证明候选击败所有普通程序**。

同early-intent和目标marker上的普通if/else门控应与候选逐事件相同，模型把它记为O_SAME_TICKET。这是“新增付费接口的能力控制”；该相等剥离独立调度公式主张，不说明该接口已发表或实现费用相同。

### 6.2 更强的普通两段读取：必须承认它在零费用下占优

O_SPLIT_128_PACED保留原4096B parent和fullbuffer资格，仅把L=256分为128+128。第一段t=0发；在第一段R完成前不发布第二段；随后给当前已可见的P1一次普通优先，再发第二段。第二段覆盖τ1，不需早意图。

零额外费用时：L第一段0–128；P1 128–129；L第二段129–257；P2 257–258；P3 259–260；写ready264；V/A/quiet分别1034/1290/1290。它比候选的V1036/A1292都快2，hot仍匹配1282，只多一个AR。

这不是现成frontend读128选项。现有reg64把两侧长度上限硬接0，deburst同时缩读写；backend已有可复用独立长度逻辑，但只改src在`decouple_rw=0`仍连带缩W。read128/write256要明确适配或post-TL splitter。[补核`:7–12`](../source/split-control-note.md:7)给出实际连接与调用范围。

完整可执行适配需保留AR属性、物理地址连续性、parent错误语义、R响应顺序；post-TL路径可只抑制第一段的上游RLAST并在第二段真正末拍终结原parent，但必须有合法header/phase及返回关联。若在原legalizer复用已有字段，不能人为禁复用再宣称候选省面积。若对整job固定128，原两个AR变四个；“仅多一个AR”只适用于明确选择最后L的版本，选择和metadata成本同样要记。

若把2048B改为两个1024B子COPY，则parent供给/完成、AW/B和许可路径不同，而且原4096B fullbuffer资格不能无条件保留；不能把这个软件版本和保留parent的读分段混同。[补核`:14–26`](../source/split-control-note.md:14)也明确没有每subCOPY强制CQ/invalidate，故不虚增这些费用。

令a_split为额外分段边界**实际暴露**的费用（额外AR若被隐藏，可以为0），主例：

- 普通两段quiet=`1290+a_split`；候选quiet=`1292+h_e`。
- 候选更快的条件是`a_split > 2+h_e`，相等时完整时间相同；小于时普通更快。
- hot候选不因intent等待，普通两段只付实际a_split；跨状态服务结果与AR、状态、线路和CPU分别比较。

冻结a_split={0,1,2,4}，不把4挑出来当“典型成本”。正例之外的接口成本主张必须依真实实现支撑；如果普通复用legalizer以相当或更低完整成本达到这些结果，这一**成本版本**就被覆盖，不能靠“不是原生寄存器”挽救。

### 6.3 现成deburst、提前准备与spare

现成deburst允许两侧都单拍，保持全部任务：两job payload AR=1024、AW=B=1024，cold再加3 PTE AR；原长burst则payload AR=4、AW=B=4。完整流量和返回必须计，不把现成双侧deburst包装成免费read-only旋钮。

普通分段可选择少在途，或使用已有更多credits/spare；本例的两段pacing是普通自己选择，不是人为规定所有强对照只能一个child。允许合法复用metadata，不能通过固定字段用途制造面积差。零额外代价的细分服务构造可以把全部依赖gap藏在现有payload工作中，full quiet达到2053，早于候选2060；本文不否认这个下界，也不把它直接称为native可测吞吐。

普通提前准备从共同完整起点计费。若已有合法接口能在三个256-beat源前缀之间发P1/P2/P3，可排成`P1,Vsrc0,P2,Vsrc1,P3,Asrc0`，其后A的最后256源读与全部W/B。所有间隔都藏在源读中，full quiet2053；只增加原本就需要的3 PTE beat，未先塞一个任意大的准备惩罚。地址已知、成功许可、lookup结果寿命及真实prepare入口都须成立；如果这些条件在原接口下满足且费用相当，该域无候选性能优势。

若准备要新请求、提交、缓存同步或串行等待，只按具体程序记实付费用。不因未知而假定免费或昂贵；同样不因库里缺一个API名字就宣称创新。两个2053构造只作为明确条件的普通机会，模型执行范围不会为了实现所有假想控制扩成大系统。

## 7. 前作、算法、架构成本与论文贡献分开

MASK §5.4已在内存控制器里用Golden翻译队列、Silver/Normal数据队列和配额处理翻译优先及公平。root复用原文；[旧前作审定`:57–66`](../../../docs/shared-service-mechanism-admission-20261015.md:57)给出该原件入口。本候选不认领“联合调度”“前移优先”“状态感知”这些宽名称，也不把MIG内部没有暴露该能力当作全领域文献gap。

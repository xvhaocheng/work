# 根 Codex 对审核本身的校验（持续补充）

模型间相互同意不构成证据。以下区分事实修正与研究裁决，不修改各席原始回复。

1. **A3 R2 的 F2 不能作为已证协议结论。** 非 ATS 不代表设备未到达 IOMMU 的旧请求会自动消失。若 IOVA 保持 unmapped，迟到访问可以 fault；若同一 IOVA 已映到新对象，迟到请求可能命中新映射，不能保证 fault。RISC-V 队列官方文本 319–355 明确 PR/PW 的覆盖边界，并指出尚未抵达的请求可能需要互连 fence。正确研究前提应是设备语义完成/停止发起、地址命名复用、翻译失效与已翻译请求完成的完整顺序。已有 DMA completion 契约可能已解决它，但必须具体核查，不能由 non-ATS 一词推导。也不能反向据此主张新硬件必不可少。

2. **强基线必须满足相同语义且能共同实现。** 若候选要求严格保护，不可拿忽略保护窗口的 delayed invalidation 直接淘汰；大页只在应用确实允许时启用。LLC、F&S、rIOMMU、DWS、hostCC 属不同平台/层级，不可机械拼成一个不存在且零成本的万能对手。可分开构造最强适用软件/硬件基线，或者明确说明组合实现和成本。

3. **相邻文献不能自动击穿精确命题。** ShadowUpdate 的已核摘要处理迁移映射传播与在途请求门控；它并未在已读材料里证明“任意回收批组下独立容量恢复”已解决。D2 R2 跨审 C3 的重叠提示有用，但“几乎正落在同一描述”不足以作为淘汰证据。必须读全文或把该项标为未决。

4. **低收益例子有适用范围。** DATE2025 的 LLC 结果证明合理页表缓存是必要基线，不证明全部短DMA/多租户/动态映射应用收益必小。反之，当前FPGA的172功能验收和组合退化也不证明普遍应用需求。

5. **A4 R1 的随机占用推断过强。** 平均每页索引数小于1，不等于重复几乎为零。均匀独立模型应按 M×(1-(1-1/M)^K) 估计不同页数，且真实trace未必均匀独立。统计重复只能证明合并机会，不直接证明相同幅度的端到端加速。其“首次让整tile翻译前可见”没有查新支撑，Milk等先行必须比较。

6. **Tiara评估性质修正已直接核原文。** tiara2026.txt 363–378：主延迟为Verilator周期模型；吞吐由延迟与并发槽位推导，主要非Tiara对手为参数化分析模型；BF-2部分图点为实物测量。单MP FPGA构建/布线时序不能把主要性能比较变成实板复现。

7. **非单调与可加性只能是现象入口。** 不相加可由共同瓶颈解释；速度、时延、加速比也不能任意相加。必须展示已有合适模型预测失败的具体实例。反过来，无丢包不排除有限在途设备经服务顺序和缓存状态形成反馈；不得把A1 R2针对包回收机制的反例扩大为“iDMA不可能有任何闭环”。

8. **本 FPGA 不能验证，不等于应用不真实。** 用户明确允许跳出当前线路和框架。D3 R2 把某方案需要 ATS/多GPU 与“不是可修复工程问题、应用真实性不成立”混在一起，应撤回后一推导。必须分别判断现实系统是否存在痛点、手头平台能否测量、取得其他平台/模拟的成本；不能按现有硬件适配度暗中淘汰大胆方向。

9. **已测直接观测开销不是全局收益上界。** A5 R2 用 ObservUVM 特定负载约2%的观测开销直接推定其他时效/决策方案“最多节省约2%”，不足成立。只有目标严格是消除该同一负载上的纯观测成本且不改变决策时才可作近似上界；若候选声称减少错误驱逐，必须另外核查间接代价。另一方面，不能把该可能性当成已存在收益，真实负载与反事实证据仍缺。

10. **DVM 是 A1-P1 必须面对的直接近邻。** 根已打开作者原文 https://research.cs.wisc.edu/multifacet/papers/asplos18_dvm.pdf 并核§3、§4.2：读取可同时进行 PA=VA preload 与映射/权限验证，失败丢弃并重试；写入不可沿用该预读优化。它保留权限检查，不是关掉IOMMU的passthrough。因此“取数与权限验证并行”不能由A1认领新意，IOVA双射的额外必要性与代价仍须独立证明。

11. **必须区分单位、平均关系和硬界。** A3 的“未完成字节×纪元时长”单位不是字节，不能是隔离内存容量。稳态平均退休字节速率×平均等待时间也只在相应条件下给出平均占用关系，不能自动成为突发流的容量上界。类似地，一条全局失效命令不等于全系统完成代价O(1)；不排队不等于没有翻译依赖延迟可隐藏；IOATC配额不自动保证任意PWC前缀驻留。这些修正不自动支持任何新机制。

12. **IDYLL本身已允许保守超集。** 根直接核 `papers/idyll2023.txt:463–477`、§6.2/Fig.8：多个GPU access bits经hash合并，false positives只增加不必要失效而不影响正确性。因此D6-P1将IDYLL描述成必须精确、将保守超集称为新语义，已经被原文直接反证。完整正确性还取决于目录更新顺序，不能把“多发失效安全”扩大为任意并发实现都安全。

13. **A5的两个补救判据仍不成立。** 单游程跨页时覆盖比为`G×触及页数/r`，不总以`G/r`为上界；相邻两token跨64-token页即为反例。Jaccard=1也可能每步选中很多页中的各一个token，粗粒度驻留仍超容量。因此要联合比较实际布局、容量、增量传输、选择/打包成本与精度，不能用Jaccard一个数淘汰。根定向核Quest§3.5与ShadowKV§4/§5.3，它们是粒度与选择/回取的直接强近邻，但不证明所有具体错配已解决。

14. **信息窗口与硬件在途数不可混为同一K。** 在同资源/无附加成本且允许模拟小窗口策略的条件下，更多可见地址不会使最佳可达性能更差。实际退化应归因于规定调度、在途状态、扫描或批次完成依赖。任何独立oracle收益小就提前停止也可能漏掉联合优化，应在同一因果时间线上比较；该反事实只对所给轨迹和模型有效，不自动是真实系统硬上界。

15. **有限容量不自动保证有限排空时间。** A6 R2再次把non-ATS迟到请求必fault、互连槽位有界当成普遍进展保证；前者有第1项的IOVA再用反例，后者还需服务、公平性及停止发起假设。失效传播与请求排空可能重叠，不能无条件求和；用max也只可能给有条件下界，不能替代完整事件依赖。

以上为纸面判断，未执行新实验、仿真、构建或上板。各席原始答复与原台账保持原样；以本笔记、最终R2及根审定的明确修正为准。

# C2 / R1：共享干扰、服务顺序与可组合性能

作者：本次独立 Codex 席 C2。日期：2026-10-05。没有读取其他席或旧讨论提案，没有执行实验、修改 RTL 或上板。结论是**保留一个有严格前置门槛的研究候选，不认可“联合分区与调度”本身是创新**。

## 1. 地图的因果结构，以及必须补的近邻

四篇方向论文共同支持的结构是：软件/应用产生地址流 → 翻译缓存与 walker 改变完成顺序和速率 → 数据请求进入共享内存 → 完成事件又改变下一批地址流。容量、服务顺序与流量并不独立。这个结构已有大量研究，不能把“局部优化影响其他层”作为新发现。

- **KPart** 已利用 cache/IPC/bandwidth 曲线联合分配，§III-C 承认带宽降速估计是简化模型，§V-H 更直接展示给后台更多缓存可以改善前台尾延迟。此前项目组合退化与此类现象相邻，不能仅凭现象发表“首次跨层反作用”。[原文](https://people.csail.mit.edu/sanchez/papers/2018.kpart.hpca.pdf)，本地 `out/research-landscape-20261005/papers/kpart2018.txt`，§III-C、§IV、§V-H。
- **MASK** §4.1 明确讨论一次翻译完成后多个等待 warp 释放数据请求，产生额外排队；§5.4 的 DRAM 策略同时考虑 walk 与被阻塞 warp。因而“按解阻塞收益调度翻译”“区分 PTE 与数据优先级”均已有强近邻。[原文](https://research.ece.cmu.edu/safari/pubs/MASK-address-space-aware-gpu-memory-hierarchy_asplos18.pdf)，本地 `papers/mask2018.txt`，§4.1、§5.2–5.4、§6–7。
- **DWS/DWS++** 不仅安排 walker；§V 与 §VII-B/Fig.9 已说明 walker 份额会改变 TLB 占用，§VII-A 还报告加速 walk 可能增加填充、恶化 thrashing。§VII-D 已比较 MASK+DWS，不能把“联合两者”另起名字。[原文](https://www.csa.iisc.ac.in/~arkapravab/papers/hpca21_DWS.pdf)，本地 `papers/walk_stealing2021.txt`，§IV–VII。
- **IOTLB wall** 已给出有限 DMA 在途窗口的速率模型，且明确描述丢包、回收变慢、buffer shuffling、更多 miss 的正反馈。新研究必须超过“有限在途数 + Little 定律”及“闭环会变差”的层次。[原文](https://dejankostic.com/documents/publications/iotlb-peerj23.pdf)，本地 `papers/iotlb_wall2023.txt`，pp.5–7、11、16、20–23。

地图最需要补充的不是另一个调度启发式，而是以下现成强对手：

## 2. 候选 C2-P1：把地址局部性变成可检查的端到端服务条件

**一句话：研究多 DMA 的“翻译工作量契约”——设备承诺怎样的地址/突发流量，系统才可以在保持共享利用率的同时，对 DMA 完成时间给出足够紧的界。**

优先判断：**有条件保留，先查新与做上界筛选；尚不值得直接实现 RTL。** 创新若成立，应落在可组合的性能抽象与紧度证明，而非新增一个 token 桶。

### 2.1 应用与触发条件

目标首先限定为共享 SoC 内存的异构流水线：持续大块搬运的摄像头/网络/后台 DMA，与频繁短 descriptor 的控制或推理前后处理 DMA 共存。关心的是关键短传输的截止期和后台能否利用空闲资源，不预设“安全”是论文主线。

必须同时出现三个条件才值得推进：

1. 至少两个 DMA 主设备共享翻译及后续内存服务；短 DMA 的翻译等待占可观的关键路径。
2. 设备数据字节率相近时，因不同页边界、IOVA 前缀和映射生命周期，产生的翻译服务需求有显著差异；纯字节带宽限额过于保守或保护不足。
3. 用户需要完成时延的上界或稳定的尾部，而不仅平均吞吐；全部静态分区、最大深度 walk 预算或顺序独占明显浪费可利用资源。

这些是**待验证的应用条件**。Bermuda 在特定 ZCU104/SMMUv2 上说明小传输值得关注，但没有证明上述完整应用组合真实存在。不得用当前四个 iDMA 流自动替代应用需求证据。

### 2.2 可被推翻的研究主张

> 在映射变化和访存突发受约束、内存服务可给出下界的多 DMA 系统中，用少量可检查的地址局部性条件描述翻译流量转换，比“每次访问均按最坏 walk 计费”或普通独立带宽/请求数限额，能显著放宽安全准入范围，同时保持关键 DMA 完成时间界有效。

这里的“显著”必须由任务需求和测量噪声预先确定；不能先挑一个有利百分比。没有证明前，只能称假设。也不宣称跨全部 IOMMU 的通用保证。

### 2.3 具体研究对象，不是口号

一个初始、尚待化简的设备契约可能包含：最大在途 descriptor 数；任意窗口的数据字节和请求突发；新页与页表前缀的出现速率；映射/失效事件预算。系统输出的不是一个“公平分数”，而是给定这些条件下可验证的完成时延界及准入判据。

核心难点有三项：

- **一个输入会生成多个相依操作。** 翻译 miss 生成 PTE 访问，完成后又释放数据操作；它们可能再次访问同一内存服务站。不能把 page walk 与 data 各自的平均延迟相加，也不能把所有 PTE 延迟都算作不可重叠。
- **共享状态会改变生成的工作量。** 同一 IOVA 次序在不同 co-runner、walker 顺序与失效时刻下，可能出现不同数量的 PTE 访问。只有字节率或“不同页数”不足以给出一个紧的局部性收益承诺。
- **局部性条件必须可检查且可维持。** F&S §3 的连续 IOVA 将一个 64-page descriptor 涉及的 PTcache-L3 项缩到至多两个；但原文同时指出 Tx 竞争会增加 miss。因此不能直接把“两个不同项”误写成“至多两次 miss”。必须证明前缀驻留条件，或者在其失效时回退到保守预算。

可研究的实现出口有两种，先用证据决定，不能预先混装：

1. **无需新调度器的分析出口：** 在现有 per-stream QoS 与有限在途机制下，建立地址流 → walk 工作流 → DMA 完成服务的可组合界，并用这一界配置普通控制器。如果普通机制已经够用，论文贡献只能是新抽象/分析与真实效果。
2. **受控的元数据共享出口：** 若前缀驻留是唯一破坏紧界的环节，研究很小的高层 PTE 保障份额与共享余量，使软件连续 IOVA 能对应到可兑现的 walk 预算。分区、借用或预取本身都不是创新；必须证明这种保障为什么比全 IOTLB/PTW 分区更有效、代价多大。

第二种可能最后只是“给 PWC 做分区”，新颖性很容易不成立。若没有额外抽象、证明或应用效果，不应保留它作为独立论文。

### 2.4 与至少两项最近工作的精确差别

| 先行工作 | 已覆盖 | 本候选需要补出的内容 |
|---|---|---|
| DWS/DWS++ §V–VII | 控制 walker 的跨租户交错；完成速率影响 TLB 占用；吞吐/公平参数化 | DWS 的“至多等待一个其他租户 walk”不是这个 walk 的绝对时间界。候选必须把下游 PTE 服务、缓存状态和最后数据操作纳入完成时间承诺。仅再调偷取阈值不构成差别。 |
| MASK §4–5 | 翻译解阻塞后的数据突发、PTE/data 区分、token/bypass/DRAM 三处优化 | 候选要求输入条件可检查，并将其组合成端到端界；不能只重做关键性调度。 |
| F&S §3–4 | 改 IOVA 布局与失效行为，真实系统显著降低每次 miss 成本 | 候选若从连续性获得收益，必须在 F&S 式布局已启用后仍有需求；要证明受并发/失效影响的局部性如何成为承诺，不以平均 PTcache hit 率替代保证。 |
| CBQRI QoS ID §4.1 | PTE与数据已有归属标签、资源控制接口 | 候选不发明标签，而研究同一请求在多个服务阶段重复消耗资源时，何种预算和状态条件能组合出完成服务。实现是否已有须查控制器文献。 |
| ASM §1–3 | 无离线先验的 slowdown 估计与 soft guarantees，已处理 cache/memory 耦合 | 候选针对可检查工作量包络和 DMA 完成界，而非平均 slowdown 估计；若只做估计器，ASM 是直接强对手，不能靠 CPU→IOMMU 改名。 |

这些差别是**研究应达到的目标**，不是已经完成的新颖性证明。仍须补实时分析、re-entrant queue/network calculus、cache-aware service bounds、DMA 调控的论文；地图没覆盖不能当作空白。

### 2.5 最强反例与不可藏的成本

1. **简单办法已经够紧：** request-rate cap + bytes cap + 最坏 walk 深度 + 标准 QoS 就达到全部应用截止期，损失很小。这样额外契约没有价值。
2. **根本没有可用局部性保证：** 共享替换/失效让缓存前缀随时失效；除非做接近完全分区，任何紧界都无效。如果保证代价吞掉共享收益，应停止。
3. **故障/软件延迟不受约束：** PRI/page fault、按需映射、页迁移、软件补给或不可控 DRAM 服务出现长尾。此时不能许诺硬上界；必须明确排除或另给预算，不能偷偷只测驻留页。
4. **硬件优先级不是服务保证：** tagging 本身不能消除 HOL、credit 枯竭或非抢占长事务；如果需要修改全部 NoC/DRAM/桥，必须把成本和必要性公开。
5. **观测与检查开销：** 每窗口 distinct-page/prefix 跟踪可能比 controller 还贵；精确集合状态随 footprint 增长；采样无法直接支撑确定界。
6. **范围过窄：** 只有专门构造的 16B DMA 噪声有效，真实流水线在 F&S/大页或简单批处理后不再受翻译影响，应降级为平台诊断。

### 2.6 强基线和最便宜的“杀死”步骤

必须至少比较：统一共享；静态分区；work-conserving 的 RR/加权轮转；DWS/DWS++；适用的 MASK；两级普通 token 桶（请求数与数据字节）；已有 QoS 标签配合 PTE/data 服务；F&S 式连续 IOVA/PTcache-preserving invalidation；允许的大页。面向网络时还需 hostCC，面向实时保证时需已有 memory reservation/network calculus。相同总资源、相同正确性与服务目标，不把关闭 IOMMU 当唯一可实现强对手。

**第一步不编译 RTL：做一个“该额外信息是否值钱”的离线上界筛选。**

- 选一个有来源的真实多 DMA/网络短事务流，保留地址次序、descriptor 依赖、在途数和释放事件；合成流只作边界，不代替应用。
- 先应用允许的软件布局与大页优化，再以现成仿真/分析工具比较两个理想上界：A 知道精确未来地址/缓存状态的最优准入；B 精确调参的普通请求数+字节双限额/静态保留。A 不应算可交付算法，只判断额外局部性信息的最大价值。
- 让两者使用相同内存总服务、walker数量和正确性约束；分别考查固定预算下可接纳的后台负载，以及关键流完成时延的最坏值/真实尾部。若是有限 trace，“最大观测值”绝不写成形式最坏界。
- **停止条件一：** A 相对 B 的空间小于业务有意义的阈值，或好处仅存在于未优化的乱 IOVA 基线。
- **停止条件二：** 维持 A 所需的 prefix 驻留/观测/共享条件不可低成本兑现。
- **停止条件三：** 用真实动态访问/失效替换固定 trace 后，候选界失效或退化到普通最坏 walk 预算。
- 只有三个条件均未触发，才值得设计契约和证明。证明需先限定假设并找最小反例：两个设备、相同总字节/平均miss率、不同前缀交错和失效顺序。若同一契约允许无界延迟，必须补条件或撤回。

上述均是建议判别步骤，**没有运行、没有结果、没有收益数字**。

### 2.7 成败各能留下什么，平台是否合适

若成功：可写一篇关于“共享翻译中如何用可检查输入条件得到有用的端到端性能承诺”的体系结构/实时系统论文：精确问题、模型/条件、最小机制、真实应用、紧度与资源成本共同构成贡献。不能仅凭“FPGA上比RR快”达标。

若失败：应留下一个清晰的负面结论——在已优化 IOVA、大页及普通 QoS 条件下，额外地址局部性信息的收益很小，或前缀缓存干扰令局部承诺不成立；这有助于选题，但单凭失败不承诺可发表。

当前 FPGA 可以研究可控 walker/缓存/服务次序，建立少量可解释反例和验证机制。它不能直接代表 PCIe credits、200G networking 或实际多 GPU。确认应用需求需要真实工作负载/适合的商用平台；确认更广架构效益需要相应模拟器；硬界还需要模型或形式证明，172/172 功能验收不是替代品。

## 3. 本席主动排除的普通候选

- “联合分区+walker优先级”：MASK、DWS及其联合评估已是直接近邻。
- “少分缓存反而让别人更慢”：KPart已有跨层反例。
- “以工作/字节归一化miss，关注miss成本”：IOTLB wall已有按MiB指标，F&S已直接攻miss成本。
- “translation感知拥塞控制”：Host congestion与hostCC已在研究；除非先证明它们无法处理的具体条件，不另立候选。
- “因果诊断工具加计数器”：若不能改变研究结论或解决不可辨识问题，只是验证资产。

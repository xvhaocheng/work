# C3：动态映射生命周期、迁移回收与并发——R1 独立研究

作者：Codex 独立席 C3。方向 3。完成于 2026-10-06；本轮材料目录沿用 20261005。

## 判断

这个方向仍有值得验证的问题，但目前不能给出一个已经站得住的新硬件机制。我只保留一个**条件性候选 C3-P1**：有限物理容量下，映射撤销的完成组织方式，是否造成现成内存池、按页排空及批量迁移仍消不掉的应用阻塞。应先测量收益上界，再决定是否设计协议。

关键原因是地图缺了一层很直接的先行工作：Griffin（HPCA 2020）已经把迁移批处理与只等待目标页的访问结合；FPT 2021 已在 FPGA SVM 中逐页查询在途读写；LATR 已量化延迟回收的物理容量代价；Nomad 已把并发迁移、影子副本与内存压力放在一起考虑。生产 CUDA 内存池还提供跨 stream 的依赖复用。因此，“局部排空”“按页计数”“异步释放”“内存压力下调整回收”都不能单独当作新贡献。

本席读了指定共同材料与四份方向原文，另外定向阅读上述近邻及 CUDA 官方接口；没有读取其他席或旧讨论候选，没有改代码、运行实验或验证性能。下面区分已读事实、推断与待证假设。

## 1. 因果地图与需要修正的概括

动态映射不能只画成“更新 PTE → 刷 TLB”。至少要区分：应用宣布旧对象结束；停止产生旧身份请求；旧地址翻译失效；已经翻译的请求完成；脏数据满足目标可见性要求；物理页可以交给下一对象。各事件可能重叠，也可能需要不同参与者确认。

性能因此有两条相连的路径：一条是迁移和撤销占用控制面、页表遍历器、缓存及互连；另一条是旧对象尚未安全退休，暂时占住新对象需要的物理容量。前者延迟变小，不能直接推出后者及应用尾延迟变小。反过来，物理容量长期保留也可能只是健康的内存池缓存，并不代表它不能被复用。

当前地图容易过度概括的地方是，把设备排空与软件实验的全局 quiet 混为一谈。RISC-V 规范支持有范围的失效，并明确区分命令完成、已到达 IOMMU 的读写排序和仍在设备/互连中的请求；它并不要求所有无关 DMA 都停下来。[S3] Griffin 和 FPT 2021 进一步说明，缩小排空对象早已有具体实现。[S5][S7]

另一个边界是：**迁移完成、旧地址不能再访问、物理容量可以复用不是同一个指标**。BypassD 说明，即使映射已撤销，已经翻译的存储请求仍可能要求延后块复用；这是生命周期正确性的例子，不能将存储持久化条件直接套用到普通 DRAM。[S4]

这些工作覆盖了很多构件，但构件存在不自动否定组合。真正尚待证明的是：**在使用这些能力后，有没有一种真实、重要且不能靠简单调参消除的跨设备容量恢复问题。** 本轮没有证据证明答案为是。

## 3. C3-P1：有限容量下，映射退休的分组是否制造了可避免的阻塞

### 3.1 应用与触发条件

目标应用是有真实页迁移或映射撤销的 CPU–加速器/多加速器共享虚拟内存任务。例如工作集超过加速器本地容量、不同阶段轮流使用不同页集、多个请求源并发访问，而快层空闲页接近分配水位。迁移和撤销已经实际发生，新页分配需要等待旧页安全释放。IDYLL、Griffin、FPT 和 Nomad 支持这些组成现象值得关注，但**不证明它们在同一应用里形成了下述瓶颈**。

具体待证触发：软件或硬件为降低命令/确认开销，把若干页放进一个完成组；其中少量页仍有合法在途访问，其他页已满足复用条件，却要等共同确认才能回收。在有限容量下，这种等待阻塞下一阶段的分配；如果采用更细粒度完成，又可能增加命令、查询、CPU 和元数据开销。

研究现在有意义的条件不是“设备越来越多”这类泛化，而是实际部署同时满足：真实映射 churn、有限可用容量、不同页退休时间有明显差异、强普通方案后仍存在容量引发的应用阻塞。缺少任一项都应降低优先级。只循环创建对象却由同一固定池立即复用、没有页表变化的负载，不足以验证这个 IOMMU/迁移问题。

### 3.2 一句可被推翻的主张

> 对至少一种有代表性的容量受限异构应用，在相同工作量、最终数据放置、物理容量及正确性条件下，现成的异步内存池、选择性排空与批量迁移仍因退休完成分组造成显著的额外分配等待；将控制命令的批量组织与物理页的可复用确认适当分离，可以获得计入全部开销后的应用收益。

这是**待证假设**，不是发现。若现有实现已经独立回收每个可复用页，或者依靠事件、池划分和合理批大小即可消除等待，主张即失去新机制空间。

### 3.3 可能的新意与精确差别

与 Griffin 的差别不能是“只排空相关页”：Griffin 已做。只能进一步验证迁移批处理的组内完成差异，是否延迟有限容量的恢复，以及在保留批处理摊销效果时，是否值得改变回收确认组织。Griffin 的 §III 不能单独证明它存在此问题；需要其具体实现/模型和新的时序证据。

与 FPT 2021 的差别不能是“按页跟踪在途访问”：它已做。需要证明不是把驱动逐页查询改成批查询即可解决，而是多个请求源、映射状态和完成组的依赖关系产生了普通查询方案不能经济消除的阻塞。

与 LATR 的差别不能是“回收延迟占用内存”：它已有测量。候选若成立，关注的是有多设备访问终止条件、有限快层容量和新工作准入耦合时，哪些等待是语义必需、哪些来自完成组织；任何机制都必须胜过合理的延迟回收与同步回退。

与 CUDA 内存池的差别不能是“跨流事件帮助复用”。只有当真实页映射/迁移和多个参与者的完成条件确实超出已提供的池复用能力，并且调用方不能通过合理的 stream/event 组织达到近似收益，才可能有协议或接口贡献。

因此可能的论文贡献有两个递进层级：先是一个有应用证据、能预测何时容量恢复成为瓶颈的定量模型；然后才是消除已证实额外依赖的实现。单独引入一个名字、计数器或累计字节指标都不构成贡献。

### 3.4 测量对象与因果拆分

对一个物理区域 i，记录字节数 b_i、逻辑释放时刻 t_release,i、满足全部语义条件的最早安全复用时刻 t_safe,i，以及实现真正允许对应用途复用的 t_reuse,i。

可以记录尚未退休的字节曲线：

`R(t) = Σ b_i · 1[t_release,i ≤ t < t_reuse,i]`。

但真正可能优化的是 t_safe,i 到 t_reuse,i 的间隔，不能把最后一个合法访问尚未完成的时间算成协议浪费。还应区分：同一池中的合法复用、跨对象/权限域重新分配、返还 OS、分层迁移腾出快层空间；这些目标的安全条件和物理分配粒度不同。不要把池 reserved−used 直接当作 R(t)。

至少分解四部分：

1. 合法最后访问及必要数据可见性造成的不可消除等待。
2. 失效传播、页表遍历竞争和设备确认等协议服务时间。
3. 共同确认、轮询周期、软件观察延迟或错误依赖放大造成的额外等待。
4. 分配器粒度、碎片、缓存策略及水位造成的容量不可用。

只观察“页没归还”无法区分上述原因。页没有归还若也没有阻塞新工作，则不是本候选要解决的应用瓶颈。需要对容量、退休分组和访问时间差做独立干预，保持传输工作量、语义依赖与最终放置相同；避免同时改掉多项因素后把吞吐提升全部归给分组。

### 3.5 机制草图及不能隐藏的成本

可研究的草图是：控制面继续合并失效/迁移命令，而完成面保留各区域的必要参与者集合与完成状态，让已满足条件的区域先恢复可用容量。是否需要新硬件、软件批次拆分是否足够、能否用已有完成标记实现，都保持开放。

这不是对正确性的捷径。“在途计数现在为零”不能证明设备以后不会发出旧身份请求；撤销点之前已发出但尚未到达 IOMMU 的请求也不能遗漏。必须有可证明的请求源关闭/排序边界，或身份代际机制和相应处理。页表遍历晚到的填充、地址别名、缓存脏数据、写响应与真正可见性的区别也都属于条件。[S2][S3]

代价包括每区域/请求源状态、状态更新带宽、乱序完成队列、驱动确认次数、CPU 开销，以及更细的回收对大页/迁移块聚合和碎片的影响。如果用代际标签，还需核算请求路径支持、存储位数、回绕与旧请求处理。若为了满足这些条件只能重新全局停机，或机制的状态/命令成本大于容量收益，应停止。

### 3.6 最强基线

所有比较固定可用物理容量、访问/迁移字节和正确性目标，并单独报告额外元数据与 CPU 时间。按场景选可实现的基线，不把各论文的数字横向拼接：

- CUDA 支持的异步池、事件依赖、机会复用和内部依赖选项，配合合理的 release threshold；先确认应用真正需要哪些跨设备/跨权限域操作。
- 按生命周期划分内存池、固定池循环复用、双缓冲或多缓冲；若这些普通方法已避免实际映射 churn，应承认它们消除了问题。
- Griffin 类批处理加选择性排空，以及 FPT 类逐页完成监测；扫描合理批大小和查询频率，不能固定一个坏参数。
- LATR 类延迟回收加有界容量/同步回退；适用分层内存时加入 Nomad 类影子副本策略，核算其占用。
- 一个普通的、知道容量压力和依赖关系的软件调度器：先发出有助于腾出容量的操作，避免把通用调度收益冒充 IOMMU 新结构收益。

“增加更多空闲内存”可作为敏感性分析，不能在主比较里偷偷改变容量预算。相反，如果极少的额外容量就能抹去收益，需要把这一成本收益关系作为可能否决理由报告。

### 3.7 最便宜的杀死实验与停止条件

以下是计划，**本轮未执行**。

第一步只做应用轨迹和离线回放，不改 RTL。选一个原本就有实际迁移/撤销的应用与一个不同访问结构的对照，记录分配阻塞、映射事件、最后相关使用、设备完成与实际复用。CPU 调用返回时间不能冒充设备安全完成；若拿不到精确时间，就保留上下界，不填造精确点值。设备/主机时间需校准，采样开销单独确认。

建立一个受语义约束的理想回放：保留相同的请求服务时间、真实最后使用和数据放置，只移除可证明不必要的组间/组内确认等待。理想回放不能提前完成真实 DMA，不能删除脏数据写回，不能增加物理容量。先比较强普通方案与该上界的差距，再考虑机制。

预先采用以下工程筛选门槛，并报告置信区间与应用变化；门槛不是普适论文标准：

- 如果应用几乎没有真实映射变化，或“退休中的容量”没有造成分配/准入阻塞，停止这个应用，不能通过故意缩小到不合理容量来造瓶颈。
- 如果受语义约束的理想回放对应用吞吐和关键尾延迟都只有约 5% 以内的改善空间，停止新协议设计。
- 如果合理的事件/池划分、批大小或软件调度取得约 95% 的理想改善，且开销可接受，停止硬件创新主张；至多留下工程配置经验。
- 如果收益来自取消合法同步、隐藏缓冲容量、忽略确认开销，或仅出现在人为注入的单个无限慢请求，淘汰当前论证。
- 只有应用效应可重复、因果上界足够大、普通方案明显不能达到且成本核算合理，才进入协议原型。第二种实际负载/系统条件用于检验是否有可解释的适用边界，而不是只凑测试数量。

这一步也可能证明有效优化应在应用分配器或运行时中完成，而不在 IOMMU。应接受这种结果。

### 3.8 最致命的反例与论文形态

最可能致命的反例是：所有额外占用都由仍然合法的设备访问决定，而非完成分组；或者成熟内存池和逐页完成本来就允许及时复用。此时新增计数/证书只是在另一层重复已有功能。

若成功，论文应围绕一个经过测量的跨层性能问题：揭示何时翻译/迁移完成组织使有限容量恢复慢于必要条件，给出可预测边界，并以具体系统消除该差距。安全条件是性能机制的约束，不需要转成攻击论文。

若只有一个新指标而没有新的解释力、反直觉结果或可用机制，不足以单独成文。若失败，仍可留下清晰的否定结果：哪些场景由池复用解决，哪些是不可消除的最后使用等待，哪些只是驱动查询或调参问题。这对避免无效 RTL 投入有价值。

当前 Genesys2 平台可在未来授权后构造多个 DMA 源、有限页池、不同请求延迟及映射更新，观察因果关系与验证协议；现有 172 项功能验收不提供上述应用证据，也不证明已有所需时间戳、回收器和监测接口。真实应用收益需要可观察的 GPU/SVM、FPGA SVM 或其他异构系统；商用 GPU 不开放的协议不能凭板端微基准代替验证。先用运行时/驱动可获得的轨迹，确认空间，再决定用模拟器还是扩展 FPGA。

## 4. 没有进入候选清单的想法

- 按页只排空相关请求：与 Griffin ACUD、FPT Request Monitor 直接重叠。
- 给映射加 epoch，等旧请求结束再复用：单独看是已有生命周期管理；还没有解决 DMA 请求关闭边界。
- 在迁移时保留副本，之后并发提交或丢弃：Nomad 等已有明确机制。
- 把异步释放改成容量压力感知：LATR 已关注保留内存，Nomad 和生产池有压力/复用机制；仅加水位或阈值不够。
- 利用跨流事件让缓冲区复用：CUDA 已有生产接口，不能作为新研究机制。

## 5. 导航摘要与进入 R2 的问题

| 编号 | 一句话 | 先行工作重叠风险 | 最需要核查的证据 | 优先判断 |

## 0. 地图的因果结构与我认为的遗漏或过度概括

### 因果结构（压缩版）

[EVIDENCE] 地图的主干是：新条件同时出现时，经典单点优化的代价会转移。新条件包括更多设备共享、更大内存、更频繁的分配与迁移，以及设备行为不可见（iommu-platform/docs/research-landscape-20261005.md:7-9）。

落到方向5相关的两条研究线：
- 线5"动态分配是否成为瓶颈，取决于可预测性、重叠、缓存池、粒度、驱动和阶段"（research-landscape:19）。
- 线6与卡点4"缺信息，且测信息有成本"（research-landscape:20, 43-44）。

### 遗漏一：把"缺信息"默认当成需要新传感器的问题，忽视了应用层往往已经持有该信息

[EVIDENCE] 三篇方向原文中，信息的来源其实各不相同：

| 工作 | 信息从哪里来 | 来源 |
|---|---|---|
| ObservUVM | 驱动对 HBM 驻留访问完全盲视；靠把采样页迁到主存、借 PCIe 访问计数器来补 | observuvm2026.txt:22-27, 376-386 |
| vAttention | 自述 decode 阶段 KV 需求"按迭代可预测"，后台线程据此提前映射 | vattention2025.txt:404-409, 605-641 |
| GMLake | 利用训练迭代的周期性，约四次迭代后只走精确匹配 | gmlake2024.txt:558-564, 954-977 |
| OASIS | 对象身份直接取自分配 API cudaMallocManaged | oasis2025.clean.txt:454-458 |

[INFERENCE] 对 LLM 服务而言，KV 块表、reqId 和序列长度都由运行时自己维护：
- 稠密注意力的下一迭代访问集合，运行时本身就知道。
- 前缀缓存的命中，也由应用层自己的查找结构看到。

因此，"给 LLM 服务加 ObservUVM 式硬件观测"大概率是错位的需求。真正的观测缺口只出现在 GPU 内核按数据驱动访问、而运行时不索引的数据上，例如通用 UVM 应用和图遍历。

[RECOMMENDATION] 这一点应成为本方向的筛选规则：任何候选若声称"观测"有价值，必须先证明该信息不能以近零代价从应用语义得到。

### 遗漏二：线5的结论几乎全部是单租户结论，地图没有标出这一边界

[EVIDENCE] vAttention 的评测是一个模型独占 1–2 块 A100（vattention2025.txt:667-672, 746-750）。
- 它"64KB 页无 TLB 抖动"的结论来自单模型内核测量（vattention2025.txt:84-87, 1058-1061, 1167-1179）。
- 延迟回收被定位为"隐藏自身分配延迟"（vattention2025.txt:643-675）。

[EVIDENCE] GMLake 的评测是单作业训练（gmlake2024.txt:632-647）。

[INFERENCE] 地图第19行"取决于可预测性、重叠…"没有提醒：这些"可隐藏"都是在不存在共租户翻译竞争的条件下成立的。这正是 P2 的出发点。

### 一个细化：ObservUVM 的观测是一次性的，而且本身就是扰动

[EVIDENCE] 采样页被访问一次后即迁回 HBM，该区域"不再可观测"，阈值必须为 1（observuvm2026.txt:376-386, 397-400）。

[INFERENCE] 地图把观测代价写成"采样有代价"（research-landscape:44），这低估了一个性质：观测本身就是迁移操作，会改变被测系统的数据位置。它给出的是"至少被访问一次"的一比特信息，而不是访问频率。ObservUVM 的 LFU 只能对访问次数做粗估。

## A5-P1：选择性/稀疏解码下 KV 分层驻留的"语义-粒度错配"边界

### 1. 真实应用、触发条件、为何现在

[EVIDENCE] vAttention 给出的每 token KV 占用（全部层合计）为：Yi-6B 64KB、Llama-3-8B 128KB、Yi-34B 240KB（vattention2025.txt:413-414）。它讨论的最大上下文是 200K（vattention2025.txt:484-493）。

[INFERENCE，算术] 200K × 240KB ≈ 48GB。也就是说，单个超长请求就接近一块 80GB 卡的容量。长上下文下 KV 必然要向主存分层。

[EVIDENCE] vAttention 把"把 KV 换出到 CPU 内存"明确留作未来工作（vattention2025.txt:591-593）。它还认为 cudaMallocManaged/UVM 不适合 KV：不支持部分释放、不支持别名、默认 2MB 页（vattention2025.txt:1170-1190）。

**触发条件**：同时满足以下两点。
- 解码使用选择性注意力：每步只读一部分 token 的 KV，选择由模型分数决定。
- KV 总量超过 HBM 预算，需要按选择结果决定哪些 KV 驻留 HBM、哪些从主存回取。

[INFERENCE] **为何现在**：vAttention 路线让"KV 在虚拟上连续、物理上按页组映射"变得可行，并已有上游化尝试（vattention2025.txt:1275-1277；PR 题名见 1333-1334, 1348-1349）。一旦与稀疏解码结合，"页组粒度"就从碎片问题变成驻留精度问题。

### 2. 最接近的先行工作与精确差别

**vAttention**（ASPLOS'25，https://apanwariisc.github.io/publications/asplos-2025-vattention/vattention-asplos25.pdf）
- [EVIDENCE] 页组按物理粒度包含的 token 数随模型变化（Table 8，vattention2025.txt:1152-1163）：
  - 64KB 页组含 32–128 token。
  - 2MB 页组含 1024–4096 token。
- [EVIDENCE] 它的优势主要出现在 prefill（计算受限）。decode 与最优 PagedAttention 持平，原因是 decode 受访存限制，可以掩盖分页带来的额外计算（vattention2025.txt:827-830, 896-906）。
- **差别**：它只处理稠密注意力、单层存储。

**PagedAttention / vLLM**（SOSP'23，https://arxiv.org/pdf/2309.06180；本席未读全文，只读到 vAttention 对它的转述）
- [EVIDENCE，经 vAttention 转述] 分页内核多执行 7–13% 指令，且有寄存器溢出（vattention2025.txt:345-347）。
- 块表准备曾占 decode 延迟 30%，修复后仍可达 10%（vattention2025.txt:338-350）。

**ObservUVM**（ISCA'26，https://www.csa.iisc.ac.in/~arkapravab/papers/ISCA26_ObservUVM.pdf）
- 它在信息不可得时用硬件采样补信息。
- **差别**：本候选所处的场景里，信息由模型免费给出；困难在于信息粒度（token 级）与驻留粒度（页组级）不一致。

**InfiniGen、H2O**
- 题名可在 vAttention 参考文献中核到（vattention2025.txt:1401-1404, 1436-1442/1459-1460）。本席未读内容，与本候选的差别**待核**。

**Quest、ShadowKV 等按页/块选择 KV 的工作**
- 仅凭记忆，citation unavailable from the provided context。
- [ASSUMPTION] 我记得其中一部分工作就是在块粒度上做选择。若属实，"粒度错配"已被它们部分吸收（见第4节"致命反例"）。

### 3. 可被推翻的研究主张

> 在选择性解码中，若"理想 token 级选择"的选中 token 游程，显著短于页组所含 token 数（对 64KB 页组即 32–128 token），则：
> - 按页组驻留的 HBM 浪费因子 ≈ 页组 token 数 / 有效游程；
> - vAttention 式虚拟连续布局的内核收益趋于零；
> - 设计重心转向"选择元数据粒度 × 驻留粒度 × 回取 DMA 粒度"的联合取舍，而不是选哪一个页大小。
>
> 若选中 token 天然成簇（游程 ≥ 页组 token 数），该主张被推翻。

### 4. 因果链、代价、关键假设与最可能的致命反例

**因果链** [INFERENCE]
1. 模型分数决定每步需要的 token 集合。
2. 若该集合在序列维度上碎片化，同时驻留以页组为单位，那么为了少量选中 token 就要整页驻留，HBM 有效容量随之下降。
3. 若改用细粒度块（如 PagedAttention 的 16 token），驻留精度上升，但要付出：
   - 内核间接访问开销（EVIDENCE：vattention2025.txt:345-347）；
   - 映射调用开销（EVIDENCE：vMemMap 64KB 约 8µs，vattention2025.txt:467-477）。
4. 若改用复制压缩（把选中 token 重排到连续区域），则要付出 HBM 带宽，并破坏前缀共享。

**回取侧的放大效应** [INFERENCE，算术] 以 Yi-6B 为例，每 token 每层约 64KB/32

### 1. 对原文的更正

**更正一：原文混淆了三个层级。**
- [INFERENCE] 主张中的"粒度错配"实际上涉及三个不同的粒度：
  - (a) 虚拟内存映射粒度，即 vAttention 的页组，归驱动和 VMM 管；
  - (b) 驻留与分层决策粒度，归 serving 运行时管；
  - (c) 注意力内核的访问粒度。
- HBM 浪费只与 (b) 有关。原主张第二条"vAttention 式布局的内核收益趋于零"（A5.md:106）属于 (c)。它既不能从 (b) 推出，而且 vAttention 的收益本来就主要在 prefill（原文自述 A5.md:84）。**此条撤回。**
- 本候选与 IOMMU 或翻译硬件没有直接因果关系，是应用运行时层面的问题，只能挂靠地图卡点 1"粒度不一致"（research-landscape-20261005.md:35）。

**更正二："信息由模型免费给出"（A5.md:93）是把假设当成了事实。**
- [INFERENCE] 运行时免费知道的只是"哪些 token 存在、属于哪个请求"。它并不知道"下一步哪些 token 重要"。
- 精确的 token 级 top-k 需要先对全部 key 打分，这意味着 K 必须常驻或可读，或者改用近似元数据。所以"选择信息"本身是有代价的观测。
- 这同时收窄了 §0 遗漏一（A5.md:36-42）：筛选规则仍然成立，但 LLM 场景并不能自动豁免观测成本。

**更正三：其他措辞收窄。**
- "必然要向主存分层"（A5.md:68）应改为"分层是选项之一"。并列的选项还有多卡切分、KV 量化和丢弃式压缩。
- 浪费因子公式（A5.md:105）只是单游程情形下的上界。真实指标应定义为"触及页数 × 页 token 数 / 选中 token 数"。
- 原文提到的 P2 本轮不提供。遗漏二只保留为观察。

**更正四：ObservUVM 细化需要收窄。**
- [EVIDENCE] 区域在一次通知后确实不再可观测（observuvm2026.txt:384-386）。但策略每次事件都会重新挑选观测候选（observuvm2026.txt:522-528），采样数也会自适应调整（observuvm2026.txt:514-522）。
- [EVIDENCE] 作者实测观测相关开销约 2.4%，通信与执行开销约 1.8%（observuvm2026.txt:744-751）。
- 因此"一次性"应读作"每个观测周期一比特"，而不是"永久失明"。"扰动"在其负载上实测很小。

### 2. 第 4 节续：回取侧的放大效应与代价

- **粒度对比。** [ASSUMPTION] 设 Yi-6B 为 32 层，则每 token 每层 KV 约 64KB/32 ≈ 2KB（若 K、V 分存，则各约 1KB）。[INFERENCE] 这与原文转述的"64KB 页组含 32–128 token"的下端吻合，但该数字未复核。
- **两种回取方式的代价。**
  - 按 token 回取：每步每层发出大量约 2KB 的 DMA。小传输的链路效率较低，这是推断，未测。
  - 按页组回取：为少数选中 token 搬整页，带宽被放大。
- **其他不可隐藏的代价。** 选择元数据（每块的摘要或代表向量）、映射调用、紧缩拷贝所耗的 HBM 带宽，以及精度损失。这些都必须与"HBM 有效容量提升"放在同一账本里比较。
- **跨域旁证。** [EVIDENCE] OASIS 在 2MB 页下会把私有对象挤成共享对象，收益随之下降（oasis2025.clean.txt:897-905）。这说明粗粒度会扭曲语义分类，可作为机制层面的旁证，但不能证明 LLM 场景成立。
- **本候选押注的方向。** [EVIDENCE] ObservUVM 测得超过 90% 的 2MB 区域在被驱逐前所有 64KB 页都被访问过（observuvm2026.txt:367-370）。[INFERENCE] 本候选押注的恰好是相反的情形：页内稀疏。这正是需要验证的地方。

### 3. 最可能致命的反例

1. **块粒度选择已经吸收了错配。** [ASSUMPTION，仅凭记忆] 若按页或块打分的稀疏解码在相同字节预算下精度接近 token 级选择，那么选择粒度可以直接对齐驻留粒度，错配问题不存在。
2. **时间局部性强。** 若相邻解码步的选中集合高度重叠，驻留集就稳定，细粒度的代价可以被摊薄。
3. **多头与 GQA 取并集后变稠密。** 若一个页组存放某 token 所有头的 KV，那么各头选择取并集后会显著变稠密，错配随之减弱。
4. **强互连使分层可以直接远读。** 在 CPU-GPU 强互连平台上直接远读选中的 KV，可能比管理驻留更简单。

### 4. 最强普通方案（须在相同 HBM 预算和相同精度下比较）

- (a) 16-token 分块，加块级选择，加按分数或 LRU 的块换出（vLLM/PagedAttention 路线）。
- (b) 每步把选中 token 收集、紧缩到连续暂存区。
- (c) 不做分层：KV 量化、多卡切分。
- (d) 文献中的块级元数据选择方法（待核）。

### 5. 低成本判别实验与停止条件

**[RECOMMENDATION] 第一步：纯离线 trace 分析，不需要 FPGA，也不改系统。**
- 选一个开源长上下文模型，在全注意力 decode 时记录每步、每层、每 KV 头的 top-k 索引（或累计注意力质量达到阈值的集合）。
- 计算以下指标：
  - (i) 选中游程长度的分布；
  - (ii) 页组大小 G∈{16, 32, 64, 128, 1024} 时的覆盖放大比 R(G)；
  - (iii) 相邻步触及页集合的 Jaccard 相似度；
  - (iv) 头内单独计算与同层头并集两种口径下 R(G) 的差异。
- 同时让协调者完成文献核查：块级与 token 级选择在等预算下的精度对比是否已有报告。

**停止条件。** [ASSUMPTION：阈值为本席设定，需在审核中商定] 满足以下任一条即淘汰本候选：
- 头并集口径下 R(16) ≤ 1.5，且 R(64) ≤ 2.5；
- Jaccard ≥ 0.8；
- 文献已给出等价的定量边界。

**第二步（仅在第一步通过后）。** 在 GPU 上实测上述三种策略的代价曲线。

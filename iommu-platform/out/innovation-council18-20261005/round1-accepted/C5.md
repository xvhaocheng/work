# C5 R1：GPU 内存观测的有效期限与扰动边界

席位：Codex C5；方向 5：动态 GPU 内存、应用语义、可观测性与运行时。独立阅读完成于 2026-10-06。**只保留一个条件候选 C5-P1；尚无通过新颖性和应用收益验收的候选，不建议直接开始实现。** 未读取其他席提案或旧候选，未调用其他模型，未运行实验、修改代码、构建或上板。

## 1. 地图的因果结构与需要补足的边界

本方向的因果链应当拆开：应用决定哪些数据何时需要 → 分配器决定保留、映射和复用什么 → 驱动决定哪些页驻留及何时搬运 → 观测只看到其中一部分行为 → 策略再据此改变驻留。应用本来可预测时，直接表达未来需求通常比先制造缺页再推断需求便宜；应用不可预测时，额外观测又会消耗它试图节省的迁移资源。因此“有更精细的信息”不自动推出更好的端到端结果。

四篇原文不是一组可互相替代的方案：vAttention 利用解码每步增长可预测及后台时间；GMLake 利用迭代分配模式收敛后的映射复用；ObservUVM 用迁出样本页获得原本看不见的驻留页访问；OASIS 在模拟多 GPU 上借对象及阶段规律放大有限信息。其共同边界是**规律在多长时间内有效，以及获得、使用这个规律是否赶得上下一次决策**。

地图的遗漏会影响创新判断。SUV 已结合静态程序语义与选择性动态 UVM 管理；Forest 已把访问感知和可复用模式用于 UVM；MSched 已将内核参数预测与任务调度时间线结合。不能把“加入语义”“按阶段调策略”“联合计算和迁移”本身作为新贡献。另一个容易过度概括的地方是 ObservUVM 的空间相关性：其“区域在驻留期间大部分页最终被访问”不等于“在驱逐决策前剩下的短窗口内，抽到的页会及时提供证据”。但原文已经观察到区域可能在样本被访问前驱逐，所以连这个现象也不能声称首次发现。[O，355–405、899–915；新增来源见 §5]

## 3. C5-P1：观测必须在驱逐前兑现——侵入式 GPU 采样的可用时间边界

### 3.1 真实需求与精确触发条件

首先研究超额订阅 GPU 上的图遍历前沿变化、B+tree 查询批次、数据依赖稀疏访问；要求访问集合无法仅从内核参数准确推出，且可驱逐区域的近期热度确实改变下一步缺页代价。ObservUVM 的 BFS/BTR 是可追踪的起点，但它们尚未证明本候选需要的短窗口效应。[O，704–722]

触发条件必须同时成立：

1. 显存压力使部分区域在较短时间内可能成为驱逐对象；
2. 现成语义提示或参数预测仍留有足够大的工作集不确定性；
3. 样本在整个区域生命周期有代表性，但在当前决策窗口未必有代表性；
4. 仍存在某种可执行操作，能在决定前利用证据或避免无效观测开销。

这四条缺一不可。只存在“很难预测”而没有来得及执行的动作，不能产生本方案收益。只存在固定、密集扫描，直接预取、静态 advice 或调度预测可能已经更好。

LLM 不是默认正例。密集注意力每次访问大片 KV、GMLake 类型规则训练，应作为无需侵入式观测的负对照。稀疏注意力、动态 MoE 和多租户仅列为后续可核应用；当前没有取得能证明上述四条件的实际轨迹。尤其不能把 serving 系统的显式显存管理直接等同于 UVM。

### 3.2 一句可推翻的研究主张

**在确有数据依赖访问及快速显存压力变化的应用中，按“证据能否赶在当前驱逐决定前生效”选择何时启动或放弃侵入式采样，可以在计入全部观测开销后，持续优于已调优的 ObservUVM 及廉价语义/调度方案；若没有这段可用时间与收益空间，系统应停止购买更多观测。**

这是待检验假设，不是已发现性能问题。潜在贡献首先是定量边界，其次才是机制；不把普通自适应控制、增加置信度字段或给信息打时间戳本身包装成贡献。

### 3.4 因果链、一个最小反例与拟议机制

定义 `t_arm` 为迁出样本并可开始观察的时刻，`t_commit` 为本次驱逐决定最后可撤回的时刻，`H=t_commit-t_arm` 为剩余窗口。有效证据至少要求：样本页在此窗口内被访问、相应通知及时可用、策略尚能改变决定，而且改变决定确实减少后续代价。仅仅“最终看见访问”不够。

一个只用于说明漏洞的组合概率：固定未被观测扰动的访问轨迹，2 MiB 区域有 `n=32` 个 64 KiB 页，在 H 内只触及其中 `m(H)` 个；无放回均匀选 k 页时，至少抽到一个被触及页的概率为 `1-C(n-m(H),k)/C(n,k)`。通知传递与执行延迟还会进一步压低及时证据概率。这是普通抽样计算，不是创新定理。即使区域自进入显存以来最终访问过全部 32 页，若采样启动后的决策窗口仅再碰一页，k=1 的空间命中概率也只有 1/32。此例尚不是应用真实性证据。

增加 k 会占用更多计数器并迁出更多数据；额外传输、页表操作、通知处理可能拖慢有用工作，使 H 本身变化。窗口不应被当成外生固定参数；用同一条固定轨迹重放，只能做初筛，不能证明干预后性能。

若初筛保留，最小机制拟为“有期限的探测准入与放弃”，不另造替换策略：

- 先用现有语义、历史和队列状态筛掉已知规律的对象；
- 对剩余候选估计驱逐前可用时间及完成观测的延迟分布，只为预计能改变本次决定的区域分配有限样本；
- 将“未得到证据”保留为未知，区别于已知冷页；过期通知不得继续代表新阶段；
- 时间不足时停止新探测，回退到调优后的既有替换/预取方案。未知不意味着永远保护；容量不足仍须选择牺牲者，也不因此承诺正确性以外的保证。

`预期减少的后续停顿 - 探测成本 - 探测导致的延迟 - 占用有限资源的机会成本` 是离线判据，不假装在线能知道全部项。估计 H 若需要昂贵全量跟踪，或误差与 H 同量级，机制可能根本不成立。现有阶段事件只在可直接获得时使用，不要求每个应用先人工重写。

### 3.5 不可隐藏的代价与致命反例

成本要包含样本迁出、命中后的回迁、映射/失效、计数器竞争、CPU 中断与通知、驱动和用户态通信、元数据、阶段检测和估计开销，还要计入观测改变页驻留后对应用调度与后续驱逐的影响。不能仅用采样页字节数估计全部费用。对于 k 个样本、R 个区域，计数器需求约随 kR 增长，但硬件容量须在目标卡实测。

最可能杀死候选的反例是：真实应用只有两类——容易预测的应用不需要采样，难预测的应用直到最后一刻也没有能提前使用的证据。其他致命情况包括：简单扩大观察区域或更早采样就解决；临近驱逐时估计时间比随机猜测好不了多少；晚到证据虽多但不影响真正昂贵的再访；性能下降只是实现批处理/队列积压，修实现即可；有限样本虽不及时，但避开它节省的成本本来就很小。ObservUVM 在已有基准上额外增加样本收益小，本身就要求本席先证明新的负载条件，而不是重跑一遍期待不同结论。[O，910–915]

### 3.6 强基线与最低成本判别：先杀候选，再实现

所有方案保持相同有效显存预算、可用互连资源、应用结果和工作量；静态参数用独立调参集选定，不能拿默认未调参数当最强基线。至少比较：

1. 作者 ObservUVM 的完整策略，以及采样页数、区域数、提前启动位置和通知批处理的合理调优包络；
2. 不采样的最佳驱动管理，加可得的静态 placement/advice 与阶段预取；
3. 廉价“每阶段重置”“固定提前量”“更大观察窗口”“减少采样频率”四种简单改动；
4. 可适用的 SUV 或同等语义信息配置；使用内核参数和调度信息时必须加入 MSched 思路对应的可运行强基线，不能靠不向对手提供相同信息制造差距；
5. Forest/OASIS 的信息能力作为单独标明硬件代价的参照；未来信息 oracle 只作上界，不充作可实施对手。

**判别 0：文献/代码杀死，暂不写新机制。** 获取 ObservUVM 作者实现，追踪样本选择、计数器事件到用户策略、驱逐承诺及重置路径，确认是否已处理时效与阶段；补读 SUV/Forest/MSched 的完整机制和可运行性。若同样问题和控制已解决，撤销机制新颖性；若无新量化结论，也结束候选。当前这些代码未审阅，不能跳过。

**判别 1：两种真实应用的最小轨迹审计。** 选择原生具有数据依赖的图前沿和查询批次，保留真实输入、算法和依赖，设置确有使用场景依据的显存压力；先单 GPU，再考虑多租户。记录 t_arm、样本通知、驱逐承诺、内核/阶段事件、后续实际再访及其停顿成本，明确区分“没碰到”“没开始执行”“碰到了但通知迟到”。需要独立访问证据，不能把同一延迟通知或缺页流再当真值。密集解码和规则训练作负对照；合成改变页访问顺序只验证机制，不计入真实应用个数。

全量插桩会改变 GPU 时序，不能直接把它的时间当无扰动真值。可先在独立运行收集访问集合及阶段顺序，再与低扰动事件采集和未插桩运行核对；对数据依赖的调度变化必须保留不确定性。若没有可靠、可承受成本的证据方法，也应暂停，不能靠看起来完整的轨迹下结论。

**判别 2：离线收益上界和廉价替代先行。** 在同一轨迹上，分别给 oracle 正确冷热、正确及时性、零开销观测，区分收益到底来自更好替换还是取消无用探测。只有在保持原有工作量、考虑搬运成本后有足够空间才写机制。预先采用以下工程决策门槛：若两类应用中最佳可实现信息上界相对最强普通方案均不足约 10% 的端到端时间，停止机制开发；该 10% 是项目筛选线，不是文献常数。若最大收益全部来自简单更早采样、阶段重置或常规调参，也停止独立机制主张。

**判别 3：保留后才做真实干预。** 报端到端完成时间/有效吞吐、尾延迟、缺页停顿、迁移字节、额外 CPU 消耗、证据及时率与观测引起的延迟，展示压力、阶段长度、带宽改变时的收益和回退边界。最终若不能在至少两种真实访问模式上稳定超过最强普通方案约 5%，或正常负载有不可接受退化，降级为测量结果；5% 同样是预注册的筛选门槛，须结合测量方差与实际意义解释。固定轨迹重放不是通过此关的证据。

本轮没有执行上述任何实验，也没有确认合适 GPU 或驱动可用。

### 3.7 成功与失败分别能留下什么

成功时可写一篇边界清楚的系统测量与机制论文：指出驻留观测的决策窗口截断怎样使空间代表性失效，给出可复现的“及时信息—迁移扰动—压力”关系，再用一个简单机制靠近可行上界。必须有强静态/语义/采样基线和真实运行，不能只有调参曲线或新控制器。

失败若证据充分，仍可得到有用但未必独立成篇的认识：哪些 GPU 应用值得购买驻留访问观测，哪些直接用语义即可，哪些因为时间不足而无法从更精细采样获益。单纯“又一个算法没有提升”不自动成为论文。

现有 FPGA 可以在完全受控条件下研究探测流量与服务期限的相互影响，帮助说明一般因果链；它不能验证 GPU 驱动通知、CTA 调度、显存迁移或实际应用价值。本候选主证据必须来自支持所需 UVM 行为的真实 NVIDIA GPU、可检查的驱动/作者实现及真实应用；硬件观测替代方案另需模拟或硬件支持。不能用当前 172/172 功能验收代替这些证据。

## 4. 不列第二候选的原因

“利用 prefill/decode 差异动态借用激活显存扩大 KV”已有 2026 年预印本直接研究，而且作者在其单一配置报告调小 prefill 分块即可更好地消除空间浪费；VAMP 又已讨论多轮 MoE 的 expert/KV 再分配。因此仅把 vAttention 与动态池拼合不够。[§5] 尚未形成能避开这些先行工作的具体反例与新机制，不列 C5-P2。

同理，GMLake 的不规则分配尾部、OASIS 的对象异质性都是真实假设边界，但“做自适应粒度”本身太普通。没有实测的独特触发条件与强基线之前，不为凑两个候选而扩写。

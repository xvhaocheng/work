## 3. A2-P1：保留的只能是可检验预测增量

**最强重述。** 固定命中率的多站队列模型可能遗漏：服务顺序改变并发访问交错，交错改变共享翻译缓存状态，完成又决定后续发起。因此增加一个内生局部性状态，可能事前预测两个优化组合后的效果，而无需遍历全部配置。

**已证重叠。** S3 §VII-A 已报告少数 HH 负载上较快 walk 增加填充和 thrashing，§VII-D 已做 MASK+DWS。S4 已跨 TLB、cache、DRAM 控制，不是“现有方案都单层”。S2 的联合 cache+memory 分配说明一般耦合与协同配置早已被研究。不过，ASM 对平均 slowdown 的估计不自动等价于 A2 所需的、未观测组合点上的干预预测；不能用相邻题名宣告精确覆盖。

**剩余必要假设。** 模型必须明确输入是固定开放到达流、固定每设备依赖序列，还是 completion 驱动的闭环；允许观测哪些状态；是否需重新标定每种共运行组合；预测平均吞吐、尾延迟还是组合符号。若每次都先测完整组合再求“耦合系数”，就是解释器而非预测器。固定点可能只是求平均稳态的计算方式，不能单凭求解形式声称新理论。

**真实性与成本。** 目前缺一条来自真实设备/应用的多请求者依赖流，不能拿四条合成 iDMA 流直接充当网络/存储应用。真实应用不必在现有 FPGA，但替代平台及采集成本须列出。新状态跟踪、参数辨识、误差和相位变化都计入代价；可精确窥视未来的模型只能作收益空间上界。

**强适用基线。** 同一数据、同一训练/观测预算下比较：固定命中率的闭环队列模型；能重估 miss/MLP 的既有 cache+queue 模型；适用的 ASM 式聚合 slowdown 模型；普通瓶颈分析；同预算的直接搜索。ASM 原始 CPU 策略若不能直接运行，说明改配方法及代价，不能假装原版已经预测 DMA 尾部。

**首个判别与停止。** 先从一个明确的两设备地址/依赖例子写出两种模型，留出组合配置，不让拟合读取组合结果，检查是否真有预测分歧及其原因；然后才需要真实 trace 验证效用。这是便宜的资格筛选，合成例子不构成应用证据。若普通内生命中率队列模型已经解释并预测目标效果，或新模型不能改善实际配置决策，停止。只复现“MASK+DWS≈DWS”无法判别新模型：共同瓶颈已经足以解释这种结果，不应为此先移植大型模拟器。

## 4. A2-P2：已有网络反馈之外，跨设备持久性仍待证

**最强重述。** 设备 B 的短时竞争，把运行在固定负载下的 A 推到另一种缓存/缓冲池状态；B 撤除后 A 仍长期较慢，若恢复必须采取额外动作，这会影响隔离和恢复策略。

**已证与未证。** IOTLB wall 的丢包、回收滞后、buffer shuffling、miss 增加是实证近邻，F&S 也处理相关路径。尚未证明：第二设备确实共享导致翻译干扰的资源；B 撤除后有自维持状态；在连续 IOVA、合理页表缓存与普通流控后仍成立。多网卡/NVMe 共机并不能证明共用同一翻译缓存或 walker，DRAM、PCIe、CPU 竞争均是替代原因。

**不能采用的捷径。** 一条恢复很慢的曲线不等于多稳态；“恢复时间大于突发时长 T”也不是有物理根据的判据。必须比较同一后续负载、不同初始状态，记录队列排空、缓存回暖、缓冲池周转和网络恢复时间尺度，区分普通长暂态、滞后和持续反馈。严格按序完成也不自动排除所有软件重排；但若没有网络丢包/重传/回收路径，就不能把该具体环直接搬给 iDMA。

**普通方案与最低判别。** 首先纸面画出目标系统的共享位置和状态更新链，给出实际工作负载来源；缺任一环就不进入板上实验。若可获得目标平台，再用最小状态日志区分上述替代解释。对适用网络栈，F&S 式布局、允许的大页、已有缓冲池恢复/host 拥塞响应分别是强对手；必须保证同一正确性与可实现性，不能把它们无成本拼接。若优化布局后仅剩已有 IOTLB wall 机制，或所有慢恢复都由普通队列/软件周期解释，淘汰新主张。若没有资源取得相应系统，则是当前研究取证成本过高，不是应用不真实。

## 5. D2-P1/P2：现象不能升级成定律

### D2-P1：原单系数判据不充分

**公平重述。** 用便宜可测的局部耦合量，预判跨层优化何时值得组合，减少配置搜索。这一工程目标合理；现有判据不成立。

原文从“上游改变下游需求”推出所有增益不可加，并用系数符号进行三分类，缺少目标函数、尺度和高阶作用。例如无量纲目标 `F±(x,y)=1+x+y±kxy`：在原点，两种系统的单独干预曲线和一阶导数相同，联合交互项却符号相反。这只是证明一阶信息不充分的数学反例，不冒充 DMA 性能模型。即使补上“超可加”第四类，也没有解决预测依据缺失的问题；吞吐差、时延差、加速比的交互项还会不同。

S2 已有 cache+memory 协调配置；S3 已有 walker 份额改变 TLB 占用。D2 必须证明某个更精确、低开销且可迁移的量能预测，否则只是给既有现象命名。“独立分区无定义”应撤回：资源份额当然可以定义，只是对性能的联合映射未必可分离。S3 某些吞吐比较中静态分区较差，也不能证明它在截止期、最坏干扰、实现复杂度等所有目标上被支配。

**最低否证已经是纸面的。** 原判据对上述同一阶信息、相反交互项没有区分能力，故淘汰原定律，无需新硬件。剩余测量只有满足 A2-P1 的预测要求才值得继续；不要仅把 `c≈max(a,b)` 定义为支持、把 `c≈a+b` 定义为反例。

### D2-P2：拆开容量、速率、稳定性

**公平重述。** 在有限在途和共享缓存下，加快一处服务可能改变访问交错，产生更多无效翻译工作；希望找到能指导限流的边界。作为有条件的 walker 调度假设可以研究，原文覆盖三个干预的普遍 r* 不成立。

- 对**相同全局引用序列、相同映射/失效事件、真正具有栈性质的 LRU 容量扩展**，增加容量不会增加 miss。这足以给原普遍容量句找反例。它不涵盖任意“类 LRU”、改变集合映射的缓存，也不涵盖容量改变后重新交错的闭环输入。
- 请求率、在途数、walker 数和覆盖页数不是同一变量。不同瓶颈可能产生多个拐点；没有依据将其压成一个 r*。容量原假设固定、干预又扩大容量，也须重新定义模型。
- S3 §VII-A 的原文是少数 HH 工作负载中 DWS 无益，伴随填充率和 thrashing 增加，2048 项 TLB 改善它们。不能据此推出所有负载更坏、确定阈值、坏吸引子或滞后。
- 非单调曲线、正反馈、局部不稳定、多稳态、路径依赖是不同命题，证据门槛依次不同。有限 trace 上找到拐点只是经验值。

**首个判别。** 先写明唯一干预变量、状态更新、缓存策略、流的依赖关系与评价量，构造是否改变全局序列的对照；若剩下的只是已知 thrashing/共同瓶颈，则停止。无丢包不能否定一切闭环：有限在途设备的完成会释放额度，服务顺序可改变跨设备交错，交错可改变缓存状态。不过这仅说明逻辑上可能，不证明本平台实际形成了有论文价值的反馈。不能用原来“iDMA 等效网络 buffer shuffling”的假设跳过这一步。

## 6. A3-P1：跨方向协议检查

**最强重述。** 把资源退役和回收分开，异步等待已接纳事务结束，期间隔离旧资源，以缩短请求撤销的同步临界路径。目标并非荒谬；完成追踪、延迟复用已有强近邻，必须给出新的语义或成本优势。

**三项当前错误。**

1. **复用安全不等于访问权限撤销。** 延迟把旧页交给新所有者，可以保护新所有者；但撤销返回后旧设备仍写旧页，未必满足权限下降、CPU 接管、CoW 或迁移一致性。迁移还须保证复制与旧写之间的顺序，单纯隔离源物理页不够。原文把非协作强制撤销与合作设备完成纪元混在一起，必须二选一并写清返回的含义。
2. **非 ATS 不是完成证明。** S6 明确 PR/PW 只覆盖已被 IOMMU 处理的请求；未抵达的在途请求可能需要互连 fence。IOVA 保持 unmapped 时迟到请求可能 fault；若 IOVA 已重新映到新对象，则可能按新映射访问。须分别处理设备停止发起/语义完成、上游在途、旧翻译失效、已翻译请求的可见性、物理和 IOVA 复用。设备一个 completion 位究竟保证哪几项，要查具体契约，不能预设等同于全路径提交。
3. **内存界量纲与活性。** “未完成字节数 × 纪元时长”的单位是字节·时间，不是内存容量。若有退役突发 `σ` 字节、持续退役率 `ρ` 字节/秒和有效宽限期上界 `Tg` 秒，可讨论 `Q≤σ+ρTg` 这类容量界；它的前提是完整的到达包络和宽限期保证。有限事务数单独不保证 `Tg`、退役速率或隔离内存有界。恶意/失效设备不完成时，需背压、故障隔离或明确失败语义。

**最近工作边界。** S7 BypassD 已明确已翻译 SSD 访问无法由失效取消，并延迟块复用到完成同步点；“区分失效与访问结束”不是新发现。ShareMMU 则明确把 dirty writeback 和 in-flight drain 放进权限更新完成条件，因此移除等待须替代其一致性义务，不能只删除锁。两者不直接证明 A3 的每一种异步细粒度协议已覆盖；LATR/EcoTLB 与设备 epoch 回收的精确关系仍待核。ShadowUpdate 摘要只证明相邻的传播/门控机制，不能当作完整覆盖证据。

**强基线与首个判别。** 先为一个合作设备、一个具体 API 写五事件时序：停止/结束旧操作 → 失效及顺序保证 → 必要的全路径完成 → 复用名称/资源 → 开始新操作；并尝试插入“旧请求迟到、IOVA 已复用”的反例。与现有 completion+严格 unmap+异步 retire list 在同一语义下比较。返回“已提交撤销、尚未完成”可以是合法新接口，但不等同原严格 unmap 返回；若效果只是把等待转交调用者，不能宣称去掉依赖。传统 delayed invalidation 只有满足同一保护目标时才是对手。

**停止条件。** 无法给出完整完成保证则停止当前协议；现有完成事件/延迟回收已经以同成本满足目标，则无独立创新；没有真实应用因该等待受限，则降级。删除“非 ATS 下 IOFENCE 必然消灭问题”和武断的 5%/每秒千次门槛，以真实应用收益要求与噪声确定阈值。时间段可能并行，收益按依赖图的关键路径算，不能把失效、fence、排空的墙钟时长直接相加。

## 7. 对本席 R1 的修改，以及回应 A2/D2

**接受并收窄。** C2-P1 只保留“可检查工作量条件能否显著改善准入/完成界”这一分析问题。撤销“很小的 PTE 保留机制”作为独立候选的资格；若后续分析确需它，作为实现条件核算，不预设有新颖性。必须补 cache-aware 响应时间、可重入服务网络、DMA/内存保留原文；没有完成这一步不能宣称新抽象。补强 ASM 的精确已证重叠：S2 §7 不止估计，还实现联合 cache+memory 分配。

**不同意的四种过度否定。**

- A2 R2 从 F&S 的“每页至少一次 miss”推出“严格模式 IOTLB 没有局部性可契约”，过强。S1 309–318 明确区分第一次 PCIe 事务与之后事务；同一映射生命期仍可重用/命中，跨请求能否重用取决于合法生命周期。C2 必须声明生命周期，不能反向许诺跨严格 unmap 的命中；也不能据此断言只剩 PWC 一个对象。
- “IOATC 预留 2×N_inflight 项”不是已交付的任意 PWC 保证。S1 的两个**不同前缀**不等于两次 miss；S8 的容量控制不自动证明缓存层级、集合相联冲突、失效或前缀驻留。若某实际控制器确实提供所需保证，它是强普通基线，不能故意避开；若没有，先计实现代价，不能免费假定。
- “类 LRU 即否定所有容量反馈”“无 PWC 则无契约对象”“必须加 LLC 才能保留任何 FPGA 现象”均过强。分别要看全局序列与策略、其他可检查翻译工作、目标芯片预算。DATE2025 证明页表缓存很重要，不证明所有目标都需同样配置；其中 4 项 IOTLB 也不是本工程配置的证据。
- D2 R2 将所有方向共同绑定一个停止条件不妥。平均性能的闭环模型是否有增量，和端到端确定界是否足够紧，是不同问题；一个被普通 MVA 解释，不自动消灭另一个。也不得将 F&S、LLC、DWS、hostCC、CBQRI 当成零成本同时存在的万能基线。

**本席修订后的基线规则。** 网络/Linux 用该设备可实现的布局、失效与流控；SoC 用可实现的页表缓存、普通请求数/字节限额、内存服务保留；GPU 用相同预算的 MASK/DWS 类方案。大页以实际分配、保护和迁移语义允许为前提；硬件保留与 LLC 的面积/延迟计入预算。若跨层组合确实可以做，应实现或建模它的真实成本；若不能，分别列最强适用软件和硬件基线，不造万能对手。

**本席首个可执行判别也收缩。** 先取得一个有来源的应用、一个可说明的 DMA 完成契约和下游服务条件，再写保守双限额界与局部性加强界，寻找二者是否有真正的准入差距。R1 的“未来信息 oracle 对精调基线”是后续收益空间筛选，不保证现有工具能廉价完成，也不能用某篇服务器平均延迟拟合系数直接算成最坏界余量。若应用不需要更紧保证、普通方案已满足要求，或所需服务条件无法兑现，停止本候选；不先增加计数器、改 RTL 或重跑 172 项。

## 8. 根需要特别核查的最终清单

1. 只保留两个互不替代的纸面问题：A2-P1 的**预测增量**、C2-P1 的**服务界与准入增量**；都未通过应用/先行研究门槛。A2-P2 需要另一个真实系统证据包，不随它们自动通过。
2. DWS HH 原文是限定范围的“无益 + thrashing 增加”；勿扩成普遍性能下降定理。MASK 的原始 walker 配置与 DWS 对 MASK 的描述有口径差异，未经代码核对不要把“无限 walker”作本轮决定性事实。
3. A3 的关键错误是语义与顺序条件不全，而非“非 ATS 已全面解决”或“必需新硬件”。尤其要分开物理复用、IOVA 复用、复制/权限更新和设备 completion 的保证。
4. F&S 是必须面对的强近邻，但不是对所有映射生命周期和设备的全域消除证明；CBQRI 标签也不是现成 PWC 驻留证明。不要借审核纠错把新颖性风险反转为已经有创新。

结论依据是上述原文边界和反例，没有新增性能数字、应用验收或协议证明。下一步应由根选择有条件、有证据获取路径的纸面判别，不能按模型票数筛选。

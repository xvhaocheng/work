## 1. 致命问题

**C2-P1**

- **重述最强版**：设备承诺在途描述符数、突发量、新前缀率和失效预算；系统据此给出比“每次按最坏 walk 计费”更紧、且可组合的 DMA 完成界，同时保持共享利用率。
- 【证据】严格模式下，每页 DMA 至少一次 IOTLB miss（C2-fands2024.txt:299-311、:471-476）。
- 【证据】F&S 已保证每个描述符至多 2 个 PTcache-L3 项（:550-551、:812-823），但承认竞争会增加 miss（:555-557、:825-828）。
- 【推断】因此“地址局部性契约”在严格模式下只剩一个对象：PWC 前缀在竞争下能否驻留。这正是 C2 自己担心的出口 2，即“给 PWC 做分区”（C2.md:64-66）。
- 【证据】CBQRI 已允许 IOATC 容量控制（C2.md:22）。若出口 2 仅为“IOATC 小份额保留 + F&S”，就是现成组件组合。
- **结论**：机制新颖性在当前证据下不成立，只保留“竞争下紧界分析”这一出口。

**D2-P1**

- **重述最强版**：一个可测的上游→下游耦合系数，可以在施加组合干预之前预测两项优化是可加、冗余还是冲突。
- 【证据】F&S 的消融显示，A（保留 PTcache）或 B（连续 IOVA + 批量失效）单独都不够，三者合用才达到高吞吐（C2-fands2024.txt:944-957、:984-987）。这是超可加，不在 D2 的三分类之内。
- 【证据】ASM 已协调 cache 分区与带宽分区（C2-asm2015.txt:1251-1260），并能直接估计不同 way 分配下的减速（:1072-1079）。
- 【推断】这里的“系数”本质上就是析因设计的交互项。“c≠a+b 即支持”的判据几乎无法被推翻，因为只要接近瓶颈，任何系统都不可加。所以它不构成新规律。

**D2-P2**

- **重述最强版**：请求率超过 r* 后，“让翻译更快或更全”反而降低 goodput。
- 【推断】对固定访问序列，LRU 具有包含（栈）性质，加大容量不会增加 miss。容量子句只能经由“时序改变访问交错”成立；在非栈替换策略下也可能成立，但那是替换策略问题，不是共享规律。
- 【证据】丢包 → ACK 增多 → IOTLB 竞争加剧的环，F&S 已记录（:339-347）。F&S 降低每次 miss 的成本后丢包减少、ACK 减少、miss 下降（:829-841）。
- 【推断】最强普通方案已经切断这个环。FPGA 上的 iDMA 没有丢包或重传，“描述符回收延迟等价物”是【假设】。
- **待核**：我 R1 引 walk_stealing:582-587 写 DWS 在 HH 负载“无益”，D2 引 :887-890 写“有害”，两者需对照原文。

**共性（时间与成本）**

- 【证据】C2 已指出 PTE 访问与数据访问不能把平均延迟相加（C2.md:57）。
- 【推断】D3-P1 把“回收就绪”拆成失效完成 + 排空 + 回写 + fence 并比较占比（D3.md:36），但这几段在时间区间上重叠，占比不可加、定义不良。必须改用关键路径归因：逐段移除，或加入因果延迟注入。

## 2. 值得做的改进

- 【建议】**C2-P1** 先做一个解析上限，再决定是否值得做契约。
  - 用 F&S 的模型 T=p/(l0+M·lm)（C2-fands2024.txt:271-282；拟合值 65 与 197 的单位在提取文本中乱码，可能是 ns，待核）粗算：最坏每页 4 次读约 853，F&S 式 M≈1.03 约 268，差约 3 倍。
  - 【推断】这说明在 Intel 服务器参数下，契约界确有余量。但余量几乎全部来自 F&S 布局加前缀驻留，而不是来自新机制。
  - 竞争下的界必须与“IOATC 保留 2×N_inflight 个前缀项”的普通方案比较。还须补实时分析中 cache-aware 响应时间与网络演算的文献，引文在所给材料中不可得。
- 【建议】**D2-P1** 改为四类（可加 / 冗余 / 冲突 / 超可加）的特征刻画，并以 ASM 式聚合估计器作为基线，不能只用 MVA。
  - 可以争取的具体新结构是：ASM 依赖“性能∝访问率”的稳态假设（C2-asm2015.txt:253-263），且高核数时残余排队难以解释（:974-986）。
  - 闭环 DMA 在 wall 附近是否恰好破坏这一假设，才是 PRIMARY_CHECKS:24 所要求的“传统模型失效的具体结构”。
- 【建议】**低端 FPGA 上暴露的问题**，一律在“开 LLC / 暖页表”的配置下复测（PRIMARY_CHECKS:17-18）。只在无 LLC、4 项 IOTLB 条件下出现的交互项不计入证据。
- 【建议】任何有限 trace 上的最大值、扫描得到的 r*，都只能写成经验值，不能写成硬上界或阈值定理。C2 已遵守这一点（C2.md:97），D2 尚未遵守。

## 3. 最小判别（不执行，仅建议）

**首个判别：零成本平台参数核对。**

- 【建议】由协调者读平台 RTL 或配置，确认以下五项：
  1. IOTLB 项数与替换策略；
  2. 有无 PWC 及其级数；
  3. 有无共享 LLC，页表行能否被缓存；
  4. iDMA 在途上限，以及是否乱序完成；
  5. 能否按请求者计数。
- 各项结果直接决定候选去留：
  - 若替换策略为 LRU 或类 LRU，D2-P2 容量子句直接判死。
  - 若无 PWC，C2-P1 在本平台上没有契约对象，只能依赖其他平台。
  - 若无 LLC，所有平台现象需在加 LLC 后重测才可作证据。

**各候选第二步：**

- **C2-P1**：在核对得到的参数上做上述解析比较，对照三种方案：最坏计费、F&S 加前缀保留、精确调参的双限额。若差距小于业务阈值，按 C2.md:98 的停止条件一停止。
- **D2-P1**：零硬件。只用 F&S 图 12 与 walk_stealing §VII-D 的单项干预数据，事前预测组合后的效果符号。若无法预测出 F&S 的超可加，判死。
- **D2-P2（walker 子句）**：固定小 IOTLB、开 LLC，walker 并发取 2 档、请求率取 3 档。只有在开 LLC 的条件下仍出现符号反转，才保留。

## 4. 对 D3 的查漏

- **D3-P1**：PRIMARY_CHECKS:10 所载 ShadowUpdate 已用迁移在途跟踪器暂存翻译、复制完成后再释放；F&S 已有严格模式同步失效与描述符级批量失效（:645-653、:681-691）。“有界在途记账 + 安全早复用”需先与这两项以及 Linux 的延迟 flush queue（凭记忆，待核）对照。本平台没有 ATS，在途排空近似于 DMA 完成，因此 quiet 条件下的测量不能代表一般情形。
- **D3-P2**：IOFENCE.C 前缀语义与 ATS 超时引起的队头阻塞，本平台无法真实触发。另外，所引 VT-d Invalidation Wait 是否已按作用域区分完成，是生死点，待核。

## 5. 审核停止条件

满足以下任一情形，本方向的审核即可停止，不再增加轮数：

- 平台参数核对完成，且 C2-P1 的解析余量低于阈值；
- 或三个候选都无法给出与 ASM、F&S、CBQRI 可区分的预测或界。

此时方向 2 只保留“共享翻译特征刻画 + 平台诊断”，不再作为论文主线。

## 6. 我 R1 应撤回或修改之处

1. **A2-P1 主张（A2.md:100）须修改。**
   - 基线必须加入 ASM 式聚合减速估计器，因为 ASM 已覆盖 cache 与内存的耦合及分配后预测。
   - 符号分类须加入“超可加”。
   - “真实 RTL 上的因子化”不得暗示首创：DATE 2025 已在 FPGA 上评估 CVA6 SVA，且加入共享 LLC 后翻译开销大幅减小（PRIMARY_CHECKS:15-18）；因子实验必须包含 LLC 维度。
2. **A2-P2 须大幅收窄，可能直接淘汰。**
   - 丢包驱动的环 F&S 已记录并已消除。F&S 连续 IOVA 使每描述符的 L3 项数与回收顺序无关，打乱机制在 F&S 下可能不再成立。
   - “最强普通方案”须加入 F&S（A2.md:255-258 漏列）。
3. **A2.md:267 的停止条件须改写。**
   - 同设备 Rx/Tx 经共享 IOVA 空间产生干扰，F&S 已有记录（:348-371）。“降为同设备问题”不是退路，而是已有先行工作。
4. **R1 表中“ASM 待核”须更新**：其摘要、§1–§4、§7 已在本轮提供，相关结论按本文第 1、2 节处理。

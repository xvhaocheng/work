## 1. 先纠正会改变裁决的事实

### 1.1 non-ATS 不推出迟到请求必然 fault

直接复核的 RISC-V 队列原文区分：IOTINVAL 同步翻译状态；IOFENCE.C 确认先前命令完成；PR/PW 排序已被 IOMMU 处理的访问；尚未抵达的设备请求可能还需互连动作。[S1]

**由此推导的反例**：旧请求携带 IOVA x，在设备或互连中尚未抵达；软件撤销 x→P，完成相应失效，再把 x 映到新对象 Q；旧请求随后到达，可能合法翻译到 Q。它没有携带足以区分两个对象的代际信息，“没有 ATS”并不能让它自动报错。若 x 始终保持 unmapped，迟到访问可被拒绝；这与复用同一 x 是不同前提。

因此需要把三个状态分开：旧物理页是否仍可访问；旧 IOVA 名称是否可重用；旧设备任务是否已完成/停止继续发请求。A3 R2 的 F2 和 D3 R2 据此作出的“只剩 ATS/仿真”应撤回。但这也**不证明**必须增加硬件：正确的设备完成契约、驱动停止发起及地址隔离可能已经闭合该窗口。

Linux DMA API 的普通用法恰好要求设备 DMA 已完成后再 unmap；官方文档对 single、page、scatterlist 都明确给出这一前提。[S2] 因而不能用违反既有契约的并发 unmap 微基准，证明正常驱动存在待解决的性能缺口。强制迁移/撤销应审其专门接口与设备协议，不能只看 IOMMU unmap 函数。

### 1.2 ShadowUpdate 暂存并放行的是请求，摘要没有证明容量独立回收

本次直接读了机构原始摘要。它说明新映射搭载失效广播传播，并在复制完成前暂存翻译请求，随后放行。[S3] “放行翻译请求”不是“旧物理页已按任意批组独立归还分配器”。因此 A3/D3 审核中用该摘要直接宣布 A3/C3/D3 的通用回收机制被覆盖，证据不足。

它是重要近邻，足以否定“迁移时主动推送映射、复制期间门控请求”的宽泛首次性；精确回收粒度与依赖组织仍需全文。当前未取得并完整读取全文，不用这一未知点替任何候选背书。

### 1.3 现有平台不能验证，不等于现实问题不存在

缺 ATS/多 GPU 只说明 Genesys2 的验证边界。用户明确允许跳出当前框架。现实应用存在性、获得其他平台的成本、当前 FPGA 能测的内容必须分别判断。另外，未到达 IOMMU 的请求并非只有 ATS/PRI/SVA 才有；D3 R1 的这项平台描述应修改。

### 1.4 区间可重叠，测量并不要求把它们强拆成互斥段

接受 A3/D3 对直接相加的警告，但不接受“必须先证明各区间可分离，否则不能研究”的更强要求。正确方法可以是带重叠事件的依赖图、联合时间线与明确反事实。我的 R1 中 `R(t)` 按区域是否可复用计一次，不会因为失效、写回和排空重叠而自动重复计算；错误会发生在把各子阶段时长相加解释 `R(t)` 或收益时。是否改变资源竞争的回放，也会影响其可解释范围。

## 2. A3-P1：等待可以转移，撤销承诺不能偷偷改变

**公平重述。** 最强版本不应被理解成凭空取消物理等待。它可以是在允许异步完成的资源释放路径中，及时阻止新访问，隔离旧资源，返回一个尚未完成的退休状态，让调用方先做不依赖回收的工作。可信完成事件最终解除隔离。

**致命问题一：R1 混用了不同契约。** “撤销返回后新所有者不受旧请求影响”与“权限降级返回后旧设备不能再写原对象”不是同一承诺。隔离旧物理页对前者可能有用，对后者并不足够。CoW、迁移拷贝的一致性、权限降级都不能仅靠“暂不把原页交给别人”完成。A3 在 R2 删除权限降级/CoW 是正确收窄；但剩余操作仍要逐项写出调用方何时可依赖结果。

**致命问题二：已经接近旧抽象。** LATR §3–4 已把虚拟页、物理页留在回收列表，等待相应翻译失效；§8 明确限制权限/所有权变化等操作。[S4] BypassD §3.6 已延后块复用，Griffin §III-D/FPT §III-B 已按相关访问判断排空。[S5][S6][S7] 从调度 tick 换成设备完成事件，仍需证明一种旧方案不能表达、或成本明显不同的约束。ShadowUpdate 不是这里的决定性淘汰证据。

**成本与修正。** 必须计入隔离物理容量、IOVA 名称空间、完成状态、错误处理、回绕及调用方的新等待点。R1 的“未完成字节数×纪元时长”量纲是 byte·time，不是内存容量上界。若退休字节到达有 burst/rate 约束、每个对象退休延迟有硬上限 L，才可在相应假设下给容量界；有限 trace 最大值、平均服务时间或有限在途数量本身不提供这个保证。

**强基线须同契约。** 对可信 DMA 的普通释放，应先比设备已完成后的正常 unmap、合理池复用与异步回收；对迁移，应比适用的选择性排空与复制重叠；对严格撤销，不可拿允许继续访问的惰性失效充当等价对手。LATR、EcoTLB、DAMN、BypassD 也不能机械拼成一个能在同平台零成本共存的实现；本席只直接核了其中 LATR/BypassD。

**最便宜判别。** 先选一个确实需要操作的应用和接口，画“停止旧请求→翻译同步→设备/互连完成→物理/IOVA 再用”的事件关系，标出返回承诺。若所谓去掉的等待仍是下一步必需数据依赖，候选不能取得所称收益；若调用方本来能异步做其他事，则先尝试既有完成事件/池接口。找不到额外差别时停止新机制主张。不要将“每秒上千次”作为无依据的普适门槛：频率、每次代价及关键路径暴露共同决定价值。

**裁决：** 当前通用机制淘汰，特定应用下的同步暴露量可测；不能用 non-ATS 或平台不适配作为淘汰理由。

## 3. D3-P1：安全复用接口有实际前例，剩余问题需要应用证据

**公平重述。** 它希望把安全复用完成信息交给分配器，减少保守等待；并非声称在最后一个合法写未完成时可以直接覆盖旧页。

直接近邻比 R1 所选 IDYLL 更强：FPT 2021 §III-B 在中央 Request Monitor 中追踪每个请求至完成，驱动可查询指定页的活跃访问，回迁等待目标页请求结束；§IV-D 还讨论逐页检查成本与批量检查优化。[S7] Griffin §III-D 对相关页选择性排空。[S5] 因此“按页在途记账 + safe-to-reuse 查询”已经不能独立作为新机制。它们不自动覆盖所有设备、别名、隔离域与故障条件，候选需要指出这些差异中哪一个确实造成新的、可测的代价。

**主张过强的地方。** “主要来自回收就绪而非失效处理”将包含关系和关键路径混在一起：回收就绪本身可能包含失效处理，且排空、写回、fence 可重叠。更有用的命题是：在选定应用中，最早语义安全点到实际可复用点之间有多大可避免的差距。只给出百纳秒/微秒的跨平台量级不能判谁是一阶成本；BypassD 的不同层次测量不能直接作为本平台 barrier 的阈值。

**应用与强基线。** NIC 按包缓冲、用户态存储、GPU UVM、CPU 分层内存不是同一实验平台，也不是同一回收契约。先选一种：NIC 要核原本是否池化及何时完成；GPU 要核真实迁移/驱逐和容量压力；CPU 分层内存要面对 Nomad 一类并发复制方案。缓存/LLC 对页表流量是必要敏感性因素，但不能由 DATE2025 的 gemm 数字断言所有排空或容量问题消失。相同保护强度、相同容量及可以共同实现的基线才有淘汰力。

**最低成本判别。** 在合法调用顺序下取一条真实轨迹，记录逻辑释放、最后相关访问、所需协议确认、实际复用、分配阻塞；无法精确观察的设备时刻用上下界。先用适用的池/按页确认/合理批处理，判断额外等待是否存在及能否落在应用关键路径。若额外等待可消除后仍不能显著改善应用，或者普通方案达到近似效果，停止。合成 churn 可检查机制，不能替代这一步。

**裁决：** 降级为可与 C3-P1 合并的现象核查；不接受 R1 的高优先级接口/硬件立项，也不接受 R2 用 ShadowUpdate 摘要直接证明其全部被覆盖。

## 4. D3-P2：前缀耦合是真的，性能必要性与新颖性仍未知

**公平重述。** 最强版本针对正常命令混合中不同上下文的完成条件，不以设备超时作为唯一负载。一个上下文的长失效/确认，可能让另一个已经完成实质工作的上下文仍拿不到软件可以依赖的完成通知。

### 4.1 规范可确定的部分

RISC-V IOFENCE.C 要覆盖它之前的 CQ 命令。固定队列顺序为“较慢的 A 命令、B 的定向失效、B 的 fence”时，B 的 fence 仍包含 A；B 的失效指定了 GSCID/PSCID 不会缩小该 fence 的完成范围。[S1] 因而 D3 R2 的“定向失效+就近 fence 可能已消掉大部分效应”只能作为待测软件优化，不能作为已成立的规范反例。软件在入队前优先安排 B 可以改变顺序，但不能从已提交的前缀中删掉 A。

D3 R1 因果链里“该命令之前的所有命令完成判定被推迟”方向写反：典型受影响的是包含该慢命令的**后续**完成条件。乱序执行也不等于允许软件忽略既定 fence 的完成保证。

### 4.2 必须加入的更直接基线：VT-d wait 语义

本次从 Intel 官方 Rev.5.0 规范 §6.5.2.9/§6.5.2.12 定向取得原文段落。其 wait 至少要求前一个 wait 之后、本 wait 之前的描述符完成；FN=0 允许后续描述符在该 wait 完成前执行，FN=1 才要求它们等待。另有描述符类型之间的排序要求与超时规则。[S8]

**推断边界：** 这比“所有系统只有同一种全前缀 fence”更细，是已有完成分组/非屏障执行能力的直接近邻；不能宣称把完成范围缩小首次出现。但“至少”、实现选择和其他类型依赖也意味着，不能仅凭该段保证某款 Intel IOMMU 一定实现跨组乱序完成，更不能推导它提供任意 context/region 的完成接口。正式对比应选择具体平台和驱动；AMD COMPL_WAIT 本席未核，不作已知结论。

### 4.3 何时有研究意义，何时只是错误处理或普通调度

如果只有 ATS 超时才产生明显等待，当前性能主张不足；可以另立故障隔离议题，但不能偷偷拿它替代正常运行收益。若正常 ATS 响应、批量失效或命令突发也带来显著异质服务时间，需要应用轨迹证明其频率和影响。不能由“内部命令”推导 non-ATS 必然没有长尾，也不能由可注入长尾证明真实部署有长尾。

公平基线包括：现有定向失效、合理合批、软件提交优先级/限流、就近完成标记，以及目标架构实际提供的队列/分组完成选项。它们应分场景评估。RISC-V 标准 IOFENCE 的原保证不能被偷偷削弱；若增加范围化完成接口，需另给契约。共享物理页、别名和跨上下文依赖要做必要集合的合并；PR/PW 的访问排序还可能引入超出命令执行的依赖。成本包括跟踪条目、作用域查找、乱序完成存储、命令带宽、驱动开销、背压和公平性。

**最便宜判别与停止条件。** 第一阶段是少量纸面事件序列和目标实现阅读：比较 RISC-V 原前缀、适用 VT-d 非屏障 wait、软件入队调度，明确究竟是哪一条保证阻止 B 完成。第二阶段才采集一个正常应用的命令轨迹，把排队时间、真正必要工作与额外完成依赖分开；只移除额外依赖的回放用于判断收益空间。若软件提交策略/已有 wait 分组已经达到近似收益，停止新机制；若只能靠故意超时证明，停止当前性能立项；若目标始终必须全局排序，作用域化没有空间。

**裁决：** 可保留独立问题线索，优先做规范和正常负载判别；现有材料既不足以淘汰问题，也不足以证明新机制。当前 FPGA 可研究其已实现命令路径，不能模拟成“实测真实 ATS”；若主现象依赖 ATS，应选择对应平台或明确的模型。

## 5. 跨方向 A4-P1：先把地址重排与映射生命周期分开

**公平重述。** 对已经可见的索引 tile，在地址翻译前聚合同页访问，改善小页条件下翻译局部性，再继续物理行重排。它没有把真串行链列作可排序对象，这个适用边界合理。

直接核对 DX100 §3.2/§3.6：其地址解码先翻译再生成 DRAM 坐标，采用大页与一次性装载所需 PTE 的假设。[S9] 因此拿掉大页假设值得比较；但“首次让整个 tile 在翻译前可见”没有查新支撑。Neighborhood-aware Translation §IV 已扫描待处理请求并利用同一 PTE cache line 处理同邻域 walk，也避免启动可被正在进行的 walk 合并的请求。[S10] 这未必覆盖“软件可见整个 tile 的更大窗口”，但基线不能只有没有合并能力的 LRU-256。Milk/Propagation Blocking 的直接实现仍需核，不能仅列名字就宣布已被软件全部吸收。

**具体修正：**

- 均匀独立取样时，不同页期望是 `M·[1−(1−1/M)^K]`。M=32768、K=16384 时约 12893 个不同页，约 21% 的请求重复已有页；平均每页不到一次不代表重复几乎为零。这只是取样模型下的机会，不等于 miss 或时间减少 21%。
- 排序不改变不同页或不同叶 PTE 线的数量，改变的是时间局部性和合并机会。叶线数接近页数也不能单独淘汰同页重复的收益；相反有重复也不说明现有 coalescer 没利用它。
- 4 KiB 页不等于频繁 remap。可以先在稳定小页映射中研究；若引入动态映射，需要独立证明它是应用的实际要求，不必为了接上本方向而强造生命周期冲突。
- 在上游只重排 IOVA、仍逐次通过原翻译路径，与保存并复用 PA，是不同机制。后者才需要审查被缓存翻译如何失效；片上集成设计也不当然要求 PCIe ATS。不能把所有排序器一概说成必须响应 ATS.INVAL。
- 若 tile 内确实允许撤销/迁移，不能混用跨代次翻译；需要完成、取消、重试或稳定映射的契约。仅加 epoch 字段不足以证明正确性，但现有运行时阶段边界可能已经足够，并非必然需要新协议。

**成本、判别与停止。** 按真实索引流比较原顺序+同页合并+邻域 walk 合并+合理 TLB/PTW/PTE cache/LLC，与软件页排序及候选大窗口；大页只在应用允许时启用。计入索引预处理、缓存污染、SRAM/CAM、额外首批延迟、结果回排和必要生命周期处理。离线发现的合并机会可作为入口；若合理基线已利用机会，或软件排序的总成本更好，停止硬件主张。A4 的 15%/50% 阈值可以是工程筛选参数，但 Genesys2 的差距不是目标 DX100 的性能上界。

**裁决：** 保留离线轨迹判别，尚不认可机制新颖性；当前只读了 DX100/Neighborhood 的相关段落，没有进行完整软件重排文献查新。

## 6. 对自身 C3 R1 的修订和对审核的回应

1. **接受应用缺口。** 本席仍没有一条证明额外退休分组阻塞的真实应用轨迹。不因三席围绕同类问题讨论就提高可信度；不启动 RTL。
2. **补强 Griffin 边界。** 其 §III-D 明确整组相关 CU 排空后才执行相应 shootdown，评价也指出选中页多且有在途访问时仍会排空较久。[S5] 这支持一个测量入口，不证明有限容量下存在可避免的回收阻塞，也不证明其实现不能及时释放已经迁移的页。
3. **收窄“上界”。** R1 的理想回放仅针对给定轨迹、固定服务时间和依赖模型提供条件性差距估计；调度会改变资源竞争时，甚至不能无条件当完整新系统的性能上界。5%/95% 是事先约定的筛选门槛，不是硬实时界或跨负载定理。未执行回放，不能写成已有否定性测量结论。
4. **保留重叠事件的正确建模。** 不把失效、排空、写回、fence 无条件相加；无需把真实重叠强改成互斥阶段。`R(t)`、关键路径和应用等待各自回答不同问题。
5. **拒绝两个过强淘汰推论。** D3 R2 的“unmap 是按范围，因此通常不存在组完成才回收”缺少具体实现依据：请求粒度、命令完成粒度和分配器回收粒度不是一回事。ShadowUpdate 摘要也不能直接判定 C3 已被完全覆盖。这些都是待核，不能反向算作创新证据。
6. **基线改成可实现的方案族。** CUDA pool、LATR、大页、Nomad 和 Griffin 属不同条件；R1 的清单应按目标场景挑出可共同实现的组合，核相同容量、保护和完成语义。若普通方案足够，接受淘汰。

## 7. 下一步顺序：先用最少工作排除伪问题

| 顺序 | 实际交付物 | 它决定什么 | 停止条件 |
|---|---|---|---|
| 1 | 为一个目标应用写清设备完成、映射撤销、PA/IOVA 再用的事件契约；另为 D3-P2 对照具体队列完成语义 | 窗口是真实必要条件、额外软件等待，还是错误用法 | 候选依赖违反 API 或偷换返回语义即停止该版本 |
| 2 | 阅读该目标的有限调用链/实现，确认自然回收粒度与现成池、wait、调度能力 | 是否已被普通方案直接覆盖 | 明确同契约实现已覆盖且无剩余假说，不造新协议 |
| 3 | 获取已有或低开销的正常应用轨迹，给出关键时刻上下界和反事实差距 | 应用价值是否有可观空间 | 无真实 churn/压力/干扰，或差距太小则停止机制投入 |
| 4 | 只有前三项保留明确差异，再选模拟器或硬件进行成本完整的机制对比 | 是否值得论文与工程投入 | 可实现强基线达到近似收益，或成本抵消收益则终止 |

本轮完成的是纸面审核与决定性来源核查，以上步骤未执行。D3-P2 的规范事实可作为独立入口；A3/D3-P1/C3 的资源回收问题应避免重复立三个实质相同的项目。

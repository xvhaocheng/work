## 1. 致命问题

### D5-P1
- **最强版本：** 稠密注意力超订时，"活跃请求 + 长度 + 进度"足以决定驱逐，采样观测净收益 ≤0（D5:83）。
- **问题一：对手方案没有部署形态。** [EVIDENCE] vLLM 用块表显式管理 KV，并自带 swap（D5:109）。我 R1 转述过 vAttention 认为 UVM 不适合 KV（A5:70，引 vattention 1170-1190，未复核）。[INFERENCE] 没有人用 ObservUVM 式 UVM 采样管理 KV，所以"免费信号胜过采样"是在跟稻草人比较。
- **问题二：结论先验，不是新规律。** [INFERENCE] 稠密解码每步都读活跃请求的全部 KV 页，页级冷热退化为请求级调度，结论在动手前已经确定。C5 也把稠密解码列为负对照（C5:39），两席判断一致，这只能说明结论是常识。
- **问题三：稀疏分支并不新。** [INFERENCE] 唯一非平凡的稀疏分支，其选择元数据仍由模型显式产生，属于 Quest/ShadowKV 一类，与 UVM 采样无关（这两项为 citation unavailable from the provided context）。
- **次要问题：**
  - D5:68 写"每区域抽 1 页"，与采样数自适应不符（A5:152 引 observuvm 514-522）。
  - 开销行号两席不一致：D5:94 为 753–763，A5:153 为 744–751，待协调者核对。

### D5-P2 时间预算分支
- **最强版本：** 只在相位边界做短时观测，即可拿到大部分收益（D5:160）。
- **先行工作已覆盖。** [EVIDENCE] Forest 已有"识别出模式后停止监测"（C5:53；C5-source-audit:7）。ObservUVM 每次事件重选候选、自适应调整采样数（A5:152）。OASIS 有相位重置（D5:151）。
- **收益空间几乎为零。** [INFERENCE，算术] D5 自己引用的观测加通信开销约 2.4%+1.8%（D5:171）。即使砍掉一半扰动，端到端最多省约 2%，可能低于噪声。D5:186 的"保留 80% 收益、扰动降 50%"判据，即使通过也没有实际意义。

### D6-P1
- **最强版本：** 失效只发给租约持有者，非持有者回退到页表遍历，订阅表可以是保守超集。
- **"保守超集安全"不是新点。** [INFERENCE] IDYLL 式目录同样是假阳性只损失性能、假阴性破坏正确性。D6:53 要求"无授予则不缓存"，持有者集合因此恒等于授予集合，这与目录维护的不变量相同。"回退到遍历"就是普通的 TLB miss。D6:43 说 IDYLL 必须"精确"，是把对手写弱了。
- **证据挪用。** [INFERENCE] GPS 的订阅者分布统计的是数据副本，不是翻译副本（D6:32），不能直接迁移过来。
- **还有更直接的先行工作。** [EVIDENCE] ShadowUpdate 已把映射更新搭载在失效广播上，并用在途跟踪器暂存请求（PC:10-11）。

### D6-P2
- **最强版本：** 安全回收需要"失效确认 + 在途排空"，且无法靠加缓存降低（D6:116）。
- **"地图遗漏"不成立。** [EVIDENCE] 地图:41 与 :132 已写明 PR/PW 只覆盖已被 IOMMU 处理的请求，在途请求另需互连 fence。D6:11 所说的"地图把它压缩掉了"不符合原文。
- **相加下界不成立。** [INFERENCE] 停止设备发起请求和发出 IOTINVAL 可以并行，两者的关系由协议约定的先后顺序决定，下界应取关键路径，而不是两段之和。"与利用率无关""随设备数线性增长"也都没有推导。"不能靠加缓存降低"在逻辑上是平凡的。
- **低端 FPGA 不代表目标场景。** [INFERENCE] Genesys2 上 4 个 iDMA 的排空时间多半被 CVA6 软件队列延迟淹没，不能代表 CXL 的 RTT。多次运行的最大值也不是硬上界；硬上界只能来自"在途上限 × 最大延迟"的规范约束，而不守规范的设备本身就是无界的（D6:128）。
- **已有工程约定。** [ASSUMPTION，待核] PCIe ATS 失效完成语义、Linux DMA API 的"设备完成后再 unmap"约定、RDMA MR invalidate 语义，可能已把这一层工程化。

## 2. 值得做的改进

- **C5-P1。**
  - 主张应降为测量：每次驱逐承诺前，把"无证据"拆成未触及、未执行、通知迟到三类。C5:51 已有此拆分，这是它唯一可能的新增内容。"有期限的准入与放弃"机制先删掉，它很可能只是 ObservUVM 加一条超时判断（C5:56）。
  - C5:73 的代价式把探测延迟和停顿直接相减，但探测延迟可能与计算重叠。只应计入关键路径上的部分，否则会重复计算。
  - [EVIDENCE] 作者自报在现有基准上增加样本收益很小（C5:79）。新负载的必要性要先成立，不能重跑原基准期待不同结论。
  - [EVIDENCE] 结果来自 RTX 3090（GDDR），不能写成 HBM 的结论（C5:21）。
- **D5-P2 外溢分支。** 若要保留，必须先拿出 UVM 超订多租户的真实部署证据。还要比较 UCP 式按效用分配（地图:77）和普通的 PCIe 带宽争用解释，排除"只是带宽争用"的可能。
- **D6。** 只保留两项测量：实验 A 的持有者数量分布（先核 IDYLL 是否已报告），以及 t_ack 与 t_drain 的重叠程度。不再声称存在"下界定理"。

|---|---|---|

[RECOMMENDATION] **首个判别：** 先做零成本的 C5 判别 0，加上 Quest/ShadowKV/Forest 的全文核查。不需要 GPU，就能一次决定 C5-P1 与 A5-P1 是否还有剩余空间。

## 4. 停止条件

满足以下任一条，本方向审核即可终止，不再追加轮次：
- 判别 0 显示时效处理已被实现，且块级选择在等预算下已有精度报告；
- 剩余候选的 oracle 上界相对最强普通方案低于 10%。

不得因票数或"组合未被收录"而继续推进。

## 本席 R1 需要撤回或修改的主张

1. **A5:36-42 "LLM 运行时已持有访问信息"不是洞见。** 看到 D5-P1 后应承认它是常识，只能作为筛选规则或负对照，不能作为贡献来源。
2. **A5:52 "可隐藏只在无共租户竞争下成立"撤回。** 我没有证据支持；D5-P2 也显示多租户观测外溢缺少部署前提。
3. **A5:191-193 停止阈值需要修正。** 单模型、单轨迹得到的 R(G) 和 Jaccard 只是有限样本统计，不是边界，必须跨模型、跨长度重复。A5-P1 优先级维持"低到中"，并明确它与 UVM 或 IOMMU 均无因果联系。
4. **D5-P1 的稀疏分支与 A5-P1 是同一问题。** 应合并，不重复计为两个候选。

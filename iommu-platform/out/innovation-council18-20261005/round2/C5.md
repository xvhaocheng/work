## 1. A5-P1：保留具体未覆盖问题，修正数学和最低成本判据

### 公平重述与直接先行工作

A5 补充版已撤回“重要 token 信息免费”“驻留放大导致 vAttention 内核优势趋零”，这是必要修正。剩下最强版本是：选择、GPU 驻留、CPU 回取的粒度不同，可能在相同质量下浪费容量或传输，值得测清边界。[A5 R1，133–148、173–196]

本轮定向核原文得到两项决定性证据：

- **Quest** 已用页内 Key 的最小/最大值估计页重要性，选择页做注意力；§3.5 已显式核算元数据与选中页的数据量，§4.3 比较相关算子成本。它保留完整 KV，不应被误称为已经解决 CPU 分层驻留。[Quest 原文，§2.2、§3.4–3.5、§4.3](https://arxiv.org/html/2406.10774v1)
- **ShadowKV** 更直接：低秩 Key、CPU 上的 Value、chunk 选择与回取、时间局部性缓存已经联合设计；§5.3 给出 chunk 大小对精度、批量和命中率的消融。因此“粒度×选择×回取的代价曲面”作为宽泛贡献已不足，不能再只把它列为记忆中的待查名字。[ShadowKV 原文，§4、§5.3、附录 A.1](https://arxiv.org/html/2410.21465v1)

但这些证据**没有**证明所有模型、布局和硬件预算下的粒度错配都已解决。合格的后续命题必须指出：哪种真实布局/质量约束使现有系统的哪个预测或选项失效，而不只是重新画 chunk 曲线。

### 数学及层次修正

1. **G/游程长不是一般放大比，也不总是单游程上界。** 设连续选中 r 个 token，从偏移 a 开始，页有 G 个 token，则触及页数为 `P=floor((a+r-1)/G)-floor(a/G)+1`，放大比为 `GP/r`。G=64、r=2、a=63 时跨两页，实际放大为64，而G/r=32。因此 A5 补充版148行的“单游程上界”仍须撤回。对于任意非空集合 S，`G×|pages_G(S)|/|S|` 才是该固定布局下的覆盖比；它尚不等于增量驻留开销或端到端时间。

2. **高 Jaccard 不能一票否决。** 例：每步都选相同100个 token，每个来自不同64-token块，J=1；理想选中集合只占100单位，按块保留需6400单位。如果显存只容200单位，粗粒度仍无法全驻留。普通压紧拷贝可能解决这个例子，但它恰说明必须比较容量与拷贝成本，不能由J≥0.8直接淘汰。A5 R2 仅把阈值改为多模型重复，仍未修复这个逻辑问题；D5 R2 将它称“一票否决”也不成立。[A5 R1，191–194；A5 R2末尾第3项；D5 R2第二节、收尾]

3. **头并集取决于真实布局和执行范围。** 共享同一 KV head 的 query heads 可能需要并集；不能无条件把全部 KV heads/全部层做并集。需要记录 head 分组、K/V 是否分开、TP、token 字节数和每次实际传输范围。vAttention Table 8 的64 KiB项确为32–128 token，但 Yi-6B TP-1 为64，TP-2 为128；A5 以“每层K+V约2 KiB”推向32 token忽略了两张张量分存。[V，153–158、1152–1163]

4. **16-token逻辑块不等于一次64 KiB VMM映射。** 常见的预分配池可以在物理页内装多个逻辑块；小块回取可以打包、批量复制或经暂存区合并。因此不能直接用 vMemMap 延迟给每个逻辑块收费。紧缩也不必摧毁原来的只读前缀共享，它可能只增加一份临时副本。应测对应实现的实际成本。[V，149–165；A5 R1，114–121、175–176]

5. **全注意力索引轨迹是 oracle，不是免费选择器或质量证明。** top-k/注意力质量阈值不自动保持多步自由生成质量；记录轨迹本身也可能要运行模型、增加显存与插桩成本。“离线”只是分析阶段不在线执行，不等于无需 GPU、已有 trace 或零成本。

### 强基线、不可隐藏成本与首个否证

先分开可运行基线：保留全 KV 的 Quest 类选择；实际分层的 ShadowKV/InfiniGen 类系统；普通池内细块加批量 gather；允许时再比较直接远读。InfiniGen 已有下一层重要 KV 的推测与预取，进一步否定“重要性信息免费”的前提。[InfiniGen 原文，§4.1–4.3](https://arxiv.org/html/2406.19707v1) 这些不同系统不能零成本拼成一个万能对手。量化或多卡是质量/资源预算允许时的备选，不是同单卡预算下自动公平的对手。

账本至少含：选择元数据、低秩表示/恢复或评分、驻留缓存、额外缓冲、CPU内存、传输描述符和打包、实际搬运字节、可重叠部分、长依赖任务精度。先按相同质量与字节预算画现有方案可达边界；只有具体应用点位于其外，才收集所需轨迹并问剩余差距。

**首个停止条件：** 若无法指出 ShadowKV/Quest 已有分析以外的具体差异，停止“泛化粒度研究”命题。若有差异，再看实际缓存容量下的新增回取与完整成本，不能沿用R/J单指标停止。原文已覆盖与负载收益不足是两种不同淘汰理由，不应混在一起。

## 2. D5-P1：当前独立主张淘汰，但不是“先验已经证明净收益≤0”

### 最强版本及必须撤回的跳步

最强版本是：稠密注意力、KV页归单请求时，已有请求调度状态是否让驻留采样变得无用？这是合理负对照，但 D5 将“显式 swap 到CPU”推成“UVM驱逐成为一阶变量”，不成立。显式管理可以完全绕过 UVM 的缺页选择器；vAttention 原文明确把 CPU swapping 留作未来工作。D5 没有给出统一分配、映射、迁移和策略接口，三个系统“同时可用”也不证明它们可以直接组合。[D5 R1，§2.1；V，583–593、1167–1217]

“活跃请求的KV都要读”只给集合信息，未必给异步执行中的页访问次序和资源竞争；活跃集合本身超过容量时，问题常先变成 batch/调度/预取。只有当已知状态足够决定所需次序、策略利用充分且获知成本相同，才可推导额外观测没有信息增益。这是附条件的信息支配关系，不是现有三项调度信号自动满足的事实。因此不接受 A5 R2 “没人部署、结论动手前已确定”两项过强论断；也不接受 D5 R2 仍将本命例单列“收窄保留”。缺少部署证据不能证明不存在，缺少实际接口却足以阻止当前实验设计。

R1查新的SUV/Forest/MSched已经压缩“用语义替代观测”宽泛新意；MSched尤其给出了内核参数与调度时间线的主动迁移近邻。[MSched 原文，§4–6；只定向阅读](https://arxiv.org/html/2512.24637v2) 此处无需再人为把生产KV接上采样器来证明一个负对照。

### 必须修正的证据和判据

- vAttention 中映射新页组的毫秒级例子，不能充当 UVM 迁出样本的时间；API、页表状态与同步路径不同。
- 错误驱逐次数≤对手1.1倍，不足以支持净收益≤0。缺页有不同字节数、局部性、关键路径位置及预取作用；页面错误计数不是tokens/s的同义词。
- 普通同服务语义基线应包括可运行的显式KV调度/回取；若研究UVM路线，则说明其必要性并计入接口改造。prefix索引已知不自动等于访问不可知；稀疏重要性选择也不等于驻留热度采样。不能把所有稀疏支线自动并入A5并假称同一个问题。

**首个否证/停止：** 对一个具体框架、版本、分配API和迁移策略画真实调用链，确认有没有 UVM 做驻留牺牲者选择的节点。若没有，停止D5-P1当前命例，不为制造对比额外改造成UVM。若未来找到必要且合理的UVM部署，再以相同服务语义比较，不以此轮“淘汰”预先否定它。现阶段仅把密集规则访问作为 C5 的负对照，不能承诺正反结果都自然足够发表。

## 3. D5-P2：阶段触发降为基线，外溢保留证据不足

### 时间分支

最强主张是少数事件附近的观测足以保留大部分决策收益。这可以测，却还不是新机制。ObservUVM 已在事件后重选候选及自适应采样，OASIS 已按阶段重置；Forest 已在模式选定后停止追踪。[O，495–528；A，624–690；Forest，§4.5–4.7，R1定向阅读记录] 不过这些片段只能证明宽泛组件重叠，不能像 A5 R2 那样声称精确的“短时观测预算”已被三篇完全解决。

原判据“保留80%收益、降低50%扰动”还可能得到净亏损。应先定义同一无观测基线上的端到端收益，直接比较实际完成时间/尾延迟；少做观测本身不是目标。相位边界识别、kernel事件率、共享页fault信号的可用性都要收费，OASIS模拟器中的相位机制不是可直接调用的CUDA接口。

### 外溢分支

最强问题是：观测不仅改变本进程信息，还抢占别人能用的计数器、搬运或控制资源。这个问题不因普通带宽干扰已知而自动无价值，但必须证明有普通配额无法解释或解决的特殊耦合。当前R1的“多租户共享同一256计数器池”标为事实过强：约256来自特定测量，不是所有GPU/上下文/虚拟化模式的契约；2–4租户每户100区域是200–400，不能一概说“不紧张”，还取决于每区域样本数和计数器分配方式。

MIG与普通共享/MPS必须分开。官方MIG说明为GPU instance划分L2、内存控制器等路径，因此不能由“同一物理卡”推出共享同一个显存争用模型。这个事实也不证明所有PCIe或观测资源都被完全隔离，具体范围仍待核。[NVIDIA MIG官方说明，Introduction](https://docs.nvidia.com/datacenter/tesla/mig-user-guide/introduction.html)

同样，**没有检索到生产部署不构成淘汰条件**，否则任何新系统都无法研究。需要的是可信应用需求、实际支持的共置配置、真实工作量与可复现路径。可先选同一非MIG GPU上的两个真实UVM应用核支持，再决定是否有资格做LLM服务类外推；目前这一步尚未完成。

### 开销上界纠正、强对手与否证

直接复核 O 的744–753行：作者报告采样迁移约2.4%、通信和策略执行约1.8%，公布结果已含这些开销。另739–741行约2%指Tournament选择策略开销，不能混为同一数字。它们是该负载配置的平均量，不是新负载开销上界。

A5 R2 的“砍一半最多省约2%”只有在**同一负载、决策完全不变、只消除同一成本项**时才有近似意义；若减少错误驱逐或影响邻居关键路径，不能据此封顶收益。反向也不能用ObservUVM平均34%提升作新策略收益上界：分母、对手和因果都不同。D5 R2把已测比例一律改成“上下界待测”也过头，应保留原文实测事实，仅撤销跨场景外推。

可实施强对手是：完整ObservUVM及调参；固定每进程样本额度/频率；简单权重/轮转；已支持的资源分区。后者有容量碎片和并发度成本，不能与共享方式当成免费同配置。效用分配理念可作普通策略，但不能把CPU UCP模块直接当GPU可运行实现。

**首个判别：** 查清卡/驱动的计数器及迁移事件归属、作者代码是否允许两个上下文同时受控、目标共置需求。若不具备，只停止该配置。具备后设计未来因果实验：关闭观测、固定额度、观测策略，以及尽可能匹配字节/时序/搬运引擎的普通传输干扰对照；同时记录邻居工作量、驱逐决定及关键路径。相同字节不保证同效应，也不能将各组p99简单相减当可加机制。

**停止条件：** 若所谓观测外溢完全由普通搬运带宽解释，且固定额度/普通带宽限额在同语义同资源下抹平全部差距，则撤销独立机制主张；若没有可测影响，收束为该配置的负结果，不推出全GPU不存在。若存在无法由简单对手消除的证据质量与资源分配耦合，再提出机制，当前不提前命名新控制器。

## 4. 跨方向 A6-P1：问题可保留，上界和对照必须先重写

最强版本是：另一设备的失效/命令流能否影响静态映射设备，影响来自误伤缓存还是共享命令服务，隔离成本是什么。这个问题可以在现实SoC成立；本FPGA不支持某环节，只能限制本平台验证，不能否定应用。

### 原始规范核查与数学反例

1. RISC-V规范明确允许扩大IOTINVAL范围。[Q，280–282] 因而A6补充版191行的C2“只对A不用的地址发失效，所以不会清A”与它自己的核心前提相冲突。只有已经验证精确失效实现后，这个对照才可能隔离纯命令路径；否则须读出/计数实际失效范围，或用可控的精确/扩大实现做配对消融，计入硬件差异。

2. IOFENCE.C保证该CQ中所有先前命令完成提交，并不是按租户只等“发起方自己的命令”。PR/PW还规定已处理读写的全局有序点，规范允许简单实现作更广排序。[Q，302–326、344–355] 这不等于其必然暂停第三方查找；阻塞必须由具体实现证明。A6补充版164行应改写。

3. `W×单次walk` 至多是**限定条件下一个隔离失效事件的粗估**。若同一DMA期间连续N次扩大失效，即使W=1也可反复丢失刚补回的项；若工作集本来不适配TLB，或服务受排队/背压影响，单次walk延迟也非固定上限。反之，并发walk会重叠，求和又可高估实际关键路径。没有失效到达包络、服务保证和进展条件，就不能据此给p99或截止期硬上界，不能先用它淘汰问题。[A6 R1，168–182]

4. `p99(B最坏R)-p99(B空闲)` 是选定负载条件的分位数差，不是数学最大值/安全上界；扫到的最大R与有限trace不能覆盖未来突发。小于“截止期余量10%”也只是工程筛选阈值，不证明无应用价值。命令路径比容量争用弱同样不等于不重要，二者可能对应不同的失约约束。[A6 R1，195–202]

### 同语义对手与最低成本修复

passthrough/identity、lazy失效和独立IOMMU不能不加条件地作为同语义强对手：保护、地址重定位、资源成本可能不同。可先比较符合原保护要求的精确失效、合理页表缓存/LLC、适用大页及普通批处理；分别给出实现面积/端口/队列成本，不能零成本叠加。DATE2025提醒必须有合理缓存基线，但其单例结果不证明全部控制面干扰很小。

把首个步骤改成**K1先行**：核软件发出的范围、CQ/fence作用域、实际匹配粒度、共享端口与命令服务规则，以及真实应用操作率/突发。随后才能写条件化模型；B的PTE写入、命令访问、CPU软件提交和数据流量需要匹配对照，且“只改PTE不失效”不能在仍被设备使用的地址上随意当安全等价负载。

若实际精确失效及合理缓存消除误伤，剩余命令路径又无相关共享阻塞，则停止**该实现上的候选**。若普通精确失效以可接受代价已解决应用需求，则不再包装机制创新。Bermuda全文、CPU shootdown及相关实时干扰先行仍需补核；我本轮未审平台RTL/Linux路径，故不声称a/b已存在或已被排除。

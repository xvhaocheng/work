## 1. C3-P1：公平重述与检验

**最强版本**：它不主张"页没归还就是浪费"。C3 已明确区分 `t_release`、`t_safe`、`t_reuse`，把可优化量锁在 **t_safe→t_reuse（组完成差异造成的额外等待）**，并要求真实 churn + 有限容量 + 退休时间差异 + 强基线后仍有阻塞。这一版已经比 R1 里多数"生命周期痛点"稳妥，值得认真对待。

**逐项检验**：
- **应用真实性**：C3 自认"本轮没有证据证明答案为是"。这是全篇最大空洞——触发条件（快层接近分配水位、组内页退休时间显著不同）在其材料里没有任何实测或公开 trace 支撑。
- **精确先行差异**：与 Griffin 的差别不是"只排空相关页"（Griffin ACUD 已做），而是"同一迁移批内页退休时间不同，能否让已就绪页先复用"。这个差别**逻辑上存在**，但只是可能，且 PRIMARY_CHECKS 的 ShadowUpdate 把"迁移在途跟踪 + 复制完成后再释放"列为已做，进一步压缩剩余空间。
- **必要假设/成本**：①容量压力真实；②组内退休时间差显著；③细粒度完成的状态/查询/驱动确认成本 < 收益。三条都未证，第三条尤易被反噬。
- **最强普通组合**：CUDA 事件依赖 + 合理 release threshold + 生命周期分池/双缓冲 + LATR 类延迟回收 + 大页。C3 列了，但**没有给出为何该组合仍不够**。这是它的关键缺口。
- **区间能否相加**：C3 的 `R(t)` 与"四部分分解"若在真实系统里时间区间重叠（失效处理、排空、脏行回写、fence 常常并行），收益上界会被高估。C3 已声明要做独立干预，方向对，但必须把"能否分离出互不重叠的区间"本身当作前置判据。
- **有限 trace 最大值非硬上界**：C3 的"语义约束理想回放"只是给定 trace 的最大值，不能外推为新协议的可达上界。
- **低端 FPGA 暴露问题**：DATE 2025 已示在共享 LLC + 暖页表下，所测 gemm 翻译开销大幅减小。RISC-V IOMMU 驱动的 unmap 本就是按范围/IOTINVAL，通常**不存在"组完成才回收"**——C3-P1 的组阻塞在标准路径上可能只来自软件合批。

**致命 vs 可修复**：机制空间被强普通组合覆盖属较难修复；应用证据缺失可修复。**裁决：收窄后保留为测量候选，不进入机制/RTL 立项。** 与 C3 自评"仅保留为小成本现象与收益上界核查"一致，但我对它能否跨过 5% 门槛更悲观。

**最低成本否证**：先读 Griffin 的 CPMS/ACUD 实现或模型，确认它是否已按页/按区域独立回收；再核对 RISC-V 驱动 unmap 粒度。若二者本就逐页独立，则 C3-P1 的"完成分组阻塞"在标准路径上不存在。

## 2. A3-P1：公平重述与检验

**最强版本**：它抓住一个真实且被地图低代表述的结构——**"翻译撤销完成"≠"访问撤销完成"**，并主张用可信设备完成事件作为纪元隔离复用，从而把同步排空/ACK 移出撤销关键路径，同时保持"撤销返回后不存在对已复用物理资源的访问"。

**逐项检验**：
- **应用真实性（最致命）**：A3 自己列为第一致命反例——若非 ATS 下 IOFENCE 已基本关闭 TIW，窗口只存在于 ATS/预翻译场景；而地图第 137/184 行明确本项目平台未实现 ATS/PRI/SVA。这意味着**该候选在现有 FPGA 上无法验证**，只能仿真。这不是可修复的工程问题，是应用真实性缺口。
- **精确先行差异**：与 LATR 的差别（LATR 等所有核清 TLB + 固定两 tick；A3-P1 等设备完成事件）真实但极窄，A3 自认"若只剩把 CPU 纪元换成设备完成事件就停"。PRIMARY_CHECKS 的 ShadowUpdate（在途跟踪器 + 复制完成后再释放）更直接：A3-P1 的核心（在途跟踪 + 完成后释放）已被覆盖，剩余差别只在"纪元来源是否为设备完成事件"及"是否作用于通用页"。
- **必要假设/成本**：设备完成语义可信、隔离内存有界、纪元回绕与旧请求处理。这些都要计，A3 已列。
- **最强普通方案**：LATR（延迟物理复用）+ EcoTLB + DAMN + BypassD sync point + 严格 pin。这是很强的组合，A3 列为待核是对的。
- **规范层判别**：RISC-V 队列 319–355 说 PR/PW 只覆盖已被 IOMMU 处理的请求，未抵达 IOMMU 的在途请求可能另需互连 fence。若必须用互连 fence 关闭该窗口，则 A3-P1 的"纪元复用"不是**消除等待**，而是**给既有 fence 加完成记账**——退化为命名学。这是它最可能的自伤。
- **证据内部矛盾**：A3 自报 ShareMMU PCPKI 0.31 与 Fig.5 纵轴上限约 0.05 疑似不一致。用它论证"撤销频繁"前必须先核；这条自我批判正确。

**致命 vs 可修复**：非 ATS 下 TIW 可能存在属较严重（应用真实性），但可被一次纸面判别快速定论。**裁决：降级为"仅 ATS/仿真"，先纸面判别；非 ATS 分支倾向淘汰。**

**最低成本否证**：精读 RISC-V 队列文档 319–355 与 Linux RISC-V IOMMU 驱动严格 unmap 路径，确认"撤销返回后是否仍可能有旧翻译访问"。这是纯纸面工作，成本极低，应在本项目任何 RTL 设想前完成。

## 3. C4 跨方向查漏（从生命周期/并发视角）

从生命周期线看，C4-P1 有一个它自己未处理的耦合：它假设"合法读阶段内映射稳定、阶段间允许换映射"。但搬运窗口的**消费组边界**与**映射代次边界**不重合时，同一个消费组的输入可能跨两个映射代次；此时"组就绪"通知就必须跨映射失效，C4 的窗口划分退化成生命周期问题。这是 C4 未列出的潜在致命点，也是它相对 D3/C3/A3 的**唯一可能新组合**——但 C4 当前并未证明它，只证明了"两个维度各自存在"。

其余检验：C4 的"组就绪"信号若能被现有完成事件/在途跟踪器（ShadowUpdate 式）表达，则它并非新接口；Tiara 已在 NIC 侧做可验证 ISA + 异步传输，C4 若要求新接口需说明 Tiara 类机制为何不能覆盖。C4 的最强反例 2（页排序仍保留行局部性）与 DATE 2025 的"LLC + 暖页表消掉翻译开销"是同一类打击：若映射长期稳定为大页，C4 的"翻译工作集受限"前提消失。**裁决：维持 C4 自评（证据不足、先低成本否定、不立 RTL）；新增必查"映射代次 vs 消费组边界"。**

## 4. 对用户特别检查点的统一回应

1. **"不相加/非单调"是否证明新规律**：不证明。C3 的"三个时刻不是同一指标"、A3 的"翻译撤销≠访问撤销"都是**常识性分离**，其价值取决于是否给出可测的分离量与代价曲线；仅指出"X 不是 Y"不构成新规律。我自己 D3-P1 的同类表述也应同样收窄。
2. **区间能否重叠**：不能无条件把失效处理、排空、脏行回写、fence 相加。C3 的 `R(t)`、我的三段分解都可能因此虚高收益上界；必须先证区间可分离。
3. **目录/版本/局部排空/批处理是否只是旧方案**：是——IDYLL directory、LATR 版本/延迟、Griffin ACUD/FPT per-page drain、rIOMMU/CPMS batching 都已有。C3/A3 的"新"必须建立在这些之上，否则只是改名。
4. **低端 FPGA 暴露问题是否被 LLC/暖页表/布局消掉**：DATE 2025 直接示是。CVA6 仅四个 IOTLB 项并无 LLC 时测得的 barrier/翻译开销**不能**当普遍痛点；D3-P1、C3-P1、A3-P1 都受此约束。
5. **有限 trace 最大值不是硬上界**：C3 的理想回放、C4 的"翻译零成本反事实"都只是给定 trace 的最大值，禁止外推。

## 5. 我 R1 需撤回/修改的主张

- **D3-P1 撤回强断言**："回收就绪是一阶成本且当前靠全局停顿/保守延迟支付"改为"在特定条件下可能暴露，需先证未被 LLC/暖页表/池化消掉且区间可分离"。
- **D3-P1 撤回"普遍性"**：ShadowUpdate 已做"在途跟踪器 + 复制完成后释放"，与我的"按页有界在途记账 + 安全早复用"高度重合；应承认剩余空间只在"是否以设备完成事件为纪元、是否作用于通用页"。
- **D3-P2 收窄**：跨上下文完成谓词耦合需先证"慢命令/超时概率不低到可忽略"，并补上我未充分比较的强基线——**按上下文定向 IOTINVAL + 就近 IOFENCE**（规范已支持 GSCID/PSCID）；这条可能已消掉大部分队头效应。
- **方法学修正**：撤回把 barrier、失效处理、回写**直接相加比较**的隐含假设，改为先测可分离区间。
- **待核不变**：Intel VT-d Completion Wait / AMD COMPL_WAIT 作用域仍未核（PRIMARY_CHECKS 未提供），仍是 D3-P2 新颖性的关键判别。

## 6. 真实可行的首个判别（不执行，仅列步骤）

**对三候选统一的第一步（纯纸面，半天量级）**：核对 RISC-V IOMMU 队列文档 319–355 与 Linux RISC-V IOMMU 驱动严格 unmap 路径，判定"撤销返回后旧翻译是否仍可能访问"，并同时记录 unmap 的自然粒度（per-page / per-range / per-batch）。此一步可同时否证 A3-P1 的非 ATS 分支、压缩 C3-P1 的"完成分组"空间、并给 D3-P1 定范围。

**第二步（仍不实验，读文档）**：核对 Griffin 实现/模型中 CPMS/ACUD 是否已按页独立回收；再核 CUDA pool 事件依赖能否表达 C3-P1 所需效果。若二者都能，C3-P1 机制空间即可淘汰，只留测量。

**第三步（前提满足才考虑）**：只有前两步留下明确剩余空间时，才谈 FPGA 上带竞争的 map/unmap/reclaim 微基准；且必须带 LLC/暖页表条件，不得用冷启动暴露值当结论。

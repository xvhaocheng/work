## 0. 地图的因果结构与一处可能遗漏/过度概括

**地图的主干因果是"瓶颈转移"叙事**：经典方法（缓存、大页、分区、调度）在给定假设下有效 → 新条件（多设备共享、更大内存/物理距离、更频繁分配与迁移、软件不可观测）使原假设吃紧 → 瓶颈转移到互连、peer cache、一致性、功耗、失效（`docs/research-landscape-20261005.md:24-28, 50`）。六张卡（粒度、共享利用率与可预测性、动态放置代价、缺信息、访存依赖、静态资源极限）是并列的"卡点清单"。

**可能遗漏**：地图反复说"瓶颈会转移"，但没有给出跨卡的结构化因果——即**一个上游资源的分配如何内生地决定另一个下游资源的需求**。四篇原文里这类耦合其实是硬事实：Walk Stealing 明确"DWS 改变 walker 份额，同时成比例改变 L2 TLB 份额"（`papers/walk_stealing2021.txt:857-876`）；KPart 的 moses 案例显示"给 batch 更多 cache 降低其带宽需求，反而改善带宽敏感型 LC 尾延迟"（`papers/kpart2018.txt:1508-1516`）。地图把它们当作各自的"收益来源/case study"，未提炼为可检验的耦合/可组合性命题。

**可能过度概括**：卡 2 把"静态分区"框定为"隔离 vs 利用率"的权衡（地图 `:38`）。但 Walk Stealing 的对照实验显示，**相等的静态 walker 分区在该条件下严格劣于 baseline**（"static partitioning degrades performance over baseline"，§VII-D）。也就是说，至少在 walker 这一层，静态并非"更可预测的次优解"，而是被支配——把静态分区一律写成可用权衡会掩盖这种情形。

## 候选 D2-P1：共享翻译资源的需求内生性——一个可组合性抽象

**一句话**：把"上游资源分配→下游资源需求"的耦合显式建模为可测系数，用它可以预测两个翻译层优化是**冗余、冲突还是可加**，并据此判定"独立逐层分区"何时根本无定义。

### 1. 真实应用、触发条件与时机

- **真实条件**：多请求者共享同一翻译基础设施（共享 IOTLB/PTW）。2026 的现实形态包括 RISC-V IOMMU 多上下文、Arm SMMU 多域、GPU MPS/MIG（`papers/walk_stealing2021.txt:20-24, 210-217`），以及 200 Gbps NIC 的多个 RX 队列各带独立 buffer pool（`papers/iotlb_wall2023.txt:237-238`）。
- **本平台可复现的触发**：CVA6+4 iDMA+共享 IOMMU 上，一个通道做**大块高局部性流**（每字节翻译少），另一个做**大量小散访问**（每字节翻译多）。真实对应：网络小包 RX + 存储 bulk、控制面描述符 churn + 数据面 bulk。
- **为什么现在**：各篇都在单层优化（MASK 管 TLB 与 DRAM 调度、DWS 管 walker、KPart 管 cache、HPA 管 buffer 局部性），但学术界缺少"组合后是否还成立"的原理。Walk Stealing 已给出一个关键数据点：**MASK+DWS 不显著优于单独运行**（§VII-D），但没有解释为什么，也没有给出可推广判据。

### 2. 最接近的先行工作与精确差别

| 先行工作 | 它做了什么 | 与 D2-P1 的精确差别 |
|---|---|---|
| **Walk Stealing**（HPCA 2021）`papers/walk_stealing2021.txt:857-876`，§VII-D | 发现 DWS 控制 walker 份额时**成比例控制 TLB 份额**；报告 MASK+DWS 不叠加 | 它把这写成"subtle consequence/附带好处"，不做抽象；本席把"上游配额隐含下游配额"推广为**可组合性条件**（冗余/冲突/可加），并要给出可测系数与判据 |
| **KPart**（HPCA 2018）`papers/kpart2018.txt:1508-1516` | HC+KPartBatch 下，给 batch 更多 cache→降低其带宽需求→改善带宽敏感型 LC 的尾延迟 | 它把它当"Case/收益来源"；本席把它当**跨层需求传播定律**的实例（cache 配额→带宽需求） |
| **MASK**（ASPLOS 2018）`papers/mask2018.txt:661-675, 891-935` | 类型优先（Golden/Silver/Normal）+ PTE bypass，改变 L2/DRAM 行为 | MASK 改的是单层服务顺序；本席关心"改一层如何改下一层的需求曲线"，与 MASK 正交 |
| **IOTLB wall**（PeerJ CS 2023）`papers/iotlb_wall2023.txt:226-238, 314-325` | buffer 回收局部性→IOTLB miss；hugepage 映射恢复吞吐 | 它证明"分配器→IOTLB"耦合存在，但只做单向测量；本席要把它放进统一的可组合性框架 |
| （待核）UCP Qureshi MICRO 2006；Walk Scheduling Shin ISCA 2018 | 前者按收益分区、后者按进度关键性调度 | 仅通过地图/被引条目，未读全文，不作新颖性裁决 |

### 3. 可被推翻的研究主张

> 在共享翻译/I-O 路径中，对任一上游资源（cache 配额、walker 配额、buffer 局部性）的划分会**内生地决定**至少一个下游资源（带宽需求、TLB/IOTLB 有效容量）的可用量；因此两个分别针对上游与下游的优化，其增益**不是可加的**。判定可组合性只需一个从上游分配映射到下游需求的耦合系数：系数≈0（独立）→可加；同号且作用同一约束（共线）→冗余；反号→冲突。

### 4. 因果链、代价、关键假设、最可能致命的反例

- **因果链（两条已知支链）**：
  - walker 份额↑ → walk 完成率↑ → TLB 填充率↑ → 有限 TLB 被更多不同页占用 → 有效覆盖↓（Walk Stealing §VII-B；MASK `:846-869` 用 epoch 反馈调 token）；
  - cache 份额↑ → LLC miss↓ → 内存带宽需求↓ → 其他请求者可用带宽↑（KPart `:1508-1516` 的 moses）。
- **代价**：耦合建模需在线测量下游需求（计数器/采样），本身有开销；判定依赖稳态假设。
- **关键假设**：下游需求对上游分配是**可测且稳定**的单调函数。
- **最可能致命的反例**：当工作集远小于 TLB/IOTLB 容量、或局部性极好时，耦合系数≈0，两个优化天然可加——此时 D2-P1 的判据退化为平凡，论点无用。第二个致命点：若耦合系数随负载相位剧烈变化（非稳态），静态判据会误判。

### 5. 最强普通方案 + 低成本杀死实验

- **最强普通方案**（不可弱化）：分别独立施加 MASK、DWS、HPA/hugepage 映射；"统一大共享（全共享）"；以及"对每层各自静态等分"。Walk Stealing 的 §VII-D 已把 static 与 MASK 作为对照，须同预算、同正确性比较。
- **判别实验（当前 FPGA 可做）**：构造三条干预——(a) 仅 walker/PTW 侧（调度或合并）；(b) 仅 IOTLB 覆盖侧（大页或 buffer 局部性）；(c) (a)+(b)。测量各自与组合的端到端收益。
  - 支持 D2-P1：收益(c) ≈ max((a),(b))（冗余）或 (c) < (a)（冲突）；
  - 杀死 D2-P1：收益(c) ≈ (a)+(b)（可加）。
- **应用真实性 / 收益空间**：用真实"小散 DMA 干扰 + 大块 DMA 流"，而不是纯合成计数；收益空间来自多请求者共享翻译这一真实条件。
- **停止条件**：当任一层单独干预后翻译已非一阶瓶颈（收益落入噪声），实验无信息，应停。

### 6. 成功/失败产物与平台依赖

- **成功**：可写一篇"共享翻译资源不可独立分区：需求生成抽象与可组合性判据"的论文，在 RISC-V IOMMU 多上下文 + 4 iDMA 上验证，并（有条件地）外推到 SMMU/GPU。
- **失败**：留下"哪些上游-下游耦合在真实翻译路径中不显著"的负面结果，修正地图"瓶颈转移"叙事的普适性。
- **现有 FPGA 能做**：IOTLB/PTW 容量覆盖、walk 依赖时延、合并/调度、软件 IOVA 控制面、小 DMA 干扰、失效/同步语义分离（地图 `:184`）。
- **必须依赖其他平台**：可编程 walker 的真实 SMMU/Intel VT-d（对照）、GPU/MIG 多租户与真实 200 Gbps NIC 的 buffer shuffling（外推）。这些在本轮不能覆盖，须写成局限。

## 候选 D2-P2：共享翻译系统的正反馈与非单调性——一个因果模型

**一句话**：在共享 IOTLB/PTW 中存在一个可测的**请求多重度阈值**；超过它后，"让单次翻译更快/更全"的局部优化会**提高**稳态 miss 率并**降低** goodput，即端到端性能对"翻译服务质量"非单调。

### 1. 真实应用、触发条件与时机

- **真实触发**：高速 DMA/网络下，buffer shuffling 造成 IOTLB miss↑→丢包↑→更多 shuffling（`papers/iotlb_wall2023.txt:226-238, 519-527, 704-712`：丢 3% 包可使 miss/MiB 增至约 2.5×）。GPU 侧：降低 walk 延迟→TLB 填充率↑→thrashing↑（`papers/walk_stealing2021.txt:887-890`，HH 负载下 DWS 反而有害）。
- **为什么现在**：多请求者 + 高速率让系统可能**停在坏吸引子**；现有工作把"性能"当单调量，缺乏阈值/稳定性判据。

### 2. 最接近的先行工作与精确差别

| 先行工作 | 它做了什么 | 与 D2-P2 的精确差别 |
|---|---|---|
| **IOTLB wall**（PeerJ CS 2023）`papers/iotlb_wall2023.txt:226-238, 908-912, 958-993` | 描述 buffer shuffling 正反馈、thrashing 恢复（fresh hugepages） | 现象描述 + 工程启发式；本席要给出**稳态模型与阈值判据**，并断言非单调 |
| **Walk Stealing**（HPCA 2021）`papers/walk_stealing2021.txt:887-890`，§VII-C | 观察 DWS 对 HH 反而有害、加剧 TLB thrashing | 归因为"资源受限"；本席把它当**反馈发散的可测证据**，并预测"加速"何时变"恶化" |
| **MASK**（ASPLOS 2018）`papers/mask2018.txt:846-869` | TLB-Fill Tokens 用 epoch 反馈调 token（负反馈控制） | MASK 隐含承认反馈存在，但未分析正反馈/多稳态与边界 |
| （待核）经典 cache thrashing / 工作集理论 | 反馈与相变在缓存领域早已研究 | 未读全文，须核验是否已给出翻译路径的等价阈值；不作新颖性裁决 |

### 3. 可被推翻的研究主张

> 在共享翻译路径中存在请求多重度阈值 r*：当请求率 r > r* 时，增加 walker 数量 / 降低单次 walk 延迟 / 增大 IOTLB 覆盖会提高稳态 miss 率并降低 goodput；即 goodput 对"翻译服务质量"在 r* 处改变单调方向。

### 4. 因果链、代价、关键假设、最可能致命的反例

- **因果链**：更多 walker/更快 walk → 填充率↑ → 有限 TLB/IOTLB 被更多不同页占用 → 有效覆盖↓ → miss↑ → walk 需求↑（正反馈）。
- **代价**：面积/功耗（多 walker、大 TLB，Victima/HDPAT 类代价，地图 `:49-50`）、尾延迟、能耗；"稳定"可能以牺牲峰值吞吐为代价。
- **关键假设**：TLB/IOTLB 容量固定且工作集超过容量。
- **最可能致命的反例**：工作集在容量内则填充率↑单调有益，无反馈；请求流局部性好则 shuffling 不发生（IOTLB wall 的 "No Pool" 案例 `:975-979` 正是反例形态）。

### 5. 最强普通方案 + 低成本杀死实验

- **最强普通方案**：单纯增大/替换 IOTLB、大页映射、LRO/TSO、主动 buffer 回收、加更多 walker。Walk Stealing 已证明"只加资源不解干扰"（`:316-338`："even with a large TLB and many PTWs ... interference is a key performance limiter"）；IOTLB wall 证明大页有效（`:958-993`）。
- **判别实验（当前 FPGA 可做）**：固定 IOTLB/PTW 容量，扫描小 DMA 请求率；对每个率比较"快 walk 干预"开/关的 goodput。
  - 支持 D2-P2：存在一段率区间，开干预后 goodput **下降**（非单调）；
  - 杀死 D2-P2：goodput 随干预单调增。
- **应用真实性 / 收益空间**：真实"小散 DMA + 丢包/重传等价物（描述符回收延迟）"；收益空间来自"知道何时应稳定而非加速"。
- **停止条件**：请求率低于 miss/MiB 突变的拐点（IOTLB wall `:519-527` 的"wall"）时无信息，应停。

### 6. 成功/失败产物与平台依赖

- **成功**：给出反馈模型 + 阈值判据 + 稳定化建议（"在何条件下优先稳定而非加速"），可在 RISC-V IOMMU + iDMA 上验证定性曲线。
- **失败**：负面结果——真实翻译路径中正反馈不显著/易被吸收，界定 IOTLB wall 的普适边界。
- **现有 FPGA 能做**：控制 IOTLB 覆盖、PTW 数量/调度、小 DMA 率，观测 miss 率与 goodput。
- **必须依赖其他平台**：真实 200 Gbps NIC 的 buffer shuffling、GPU TLB 行为（外推）。

## 事实 / 推断 / 假设的区分

- **事实（有原文行号）**：DWS 改变 walker 份额即成比例改变 TLB 份额（`walk_stealing2021.txt:857-876`）；MASK 用"并发 walk 数 × 每 miss 阻塞 warp 数"作 DRAM 调度门限（`mask2018.txt:891-935`）；KPart 中 moses 因 batch 少占带宽而尾延迟改善（`kpart2018.txt:1508-1516`）；IOTLB miss 随丢包骤增（`iotlb_wall2023.txt:704-712`）；加大 TLB/PTW 不能消除干扰（`walk_stealing2021.txt:316-338`）。
- **推断（本席综合）**：上述耦合可统一为"需求内生性"并用于预测可组合性（D2-P1）；翻译路径存在非单调阈值（D2-P2）。均未被原论文直接证明。
- **假设**：耦合系数在稳态下稳定可测；当前平台的小散 DMA 可等效替代高速网络 buffer shuffling 的正反馈（应用真实性待验证）。

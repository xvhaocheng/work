## 候选 D6-P1：翻译作为「可撤销订阅 + 有界回退」

### 1. 真实应用与触发条件

**事实**：地图 44 行（源自 IDYLL）指出 UVM 驱动不知道哪些 GPU 持有有效翻译副本，基线向所有 GPU 广播失效；地图 122 行记 IDYLL 用 PTE directory 做过滤。

**具体触发条件**（两条，均可观察）：
1. **热区解映射（unmap invalidate hot range）**：一个被多设备访问的地址范围被 unmap，同时该范围仍有 demand walk 在进行。IDYLL 的真机剖析显示这类失效可占执行时间约 42%（地图 41 行）。
2. **池/迁移重分配**：CXL/NVLink 场景下物理页从设备 A 转给设备 B，A 侧所有翻译副本（CPU TLB、IOMMU IOTLB、设备 TLB、ATS 缓存）都必须先失效。

**为什么现在值得研究**：
- **推断**：设备数在升（CXL 多主机、chiplet、每 SoC 多加速器），广播失效成本 O(N_devices)，而**实际共享者通常很少**。GPS 在 GPU 侧测到这一点：多数页只有一个远程订阅者，只有 ALS 这类全对全应用才接近全订阅（gps2021.txt 823–825、1042–1049、1145–1155 行）。地图没有把"订阅集通常很小"这个可测事实引入 IOMMU 失效设计。
- **事实**：ShareMMU 的 Permission Tracker 仍需要定向 back-invalidation 与 dirty write-back/flush 确认（ROOT_REVIEW 11 行），说明"谁持有副本"在安全场景已经必须被跟踪；本候选问的是**能否把它做成不需要精确的**。

### 2. 最接近的先行工作与精确差别

**(a) GPS（已读全文，gps2021.txt）** MICRO'21。
- 相同点：页粒度订阅跟踪、只向订阅者推送、退订机制。
- **精确差别**：GPS 的回退语义是"未订阅的 load 走**远程读到某个订阅者的副本**"（336–363 行）。这要求系统知道**哪个订阅者持有数据**。本候选的回退是"未持租约的访问直接降级为**普通页表遍历**"——不需要知道任何副本持有人，也不需要每设备副本状态。这不是同一件事。

**(b) IDYLL（仅地图/ROOT_REVIEW，全文待核）** MICRO 2023，地图 122 行、ROOT_REVIEW 12 行。
- 相同点：定向失效、过滤不必要失效。
- **精确差别**：IDYLL 的 PTE directory 必须**足够精确**：漏报 = 正确性错误。本候选的核心是**订阅表允许是保守超集（近似）**，因为回退路径永远正确——失败模式从"欠失效=正确性 bug"变成"欠订阅=性能损失"。这是语义上的新点，而非把目录换个名字。

**(c) 次级对照（全文待核）**：rIOMMU 一 ring 一 IOTLB entry、burst 末失效、依赖 ring 顺序（地图 88 行）；Utilizing the IOMMU Scalably 的 per-core deferred invalidation，延迟失效存在保护窗口（地图 89 行）；RISC-V IOMMU 允许简单实现扩大为全局失效（地图 132 行）。

### 3. 一句话可被推翻的研究主张

> 在存在有限但无界在途请求的互连上，若失效被实现为「只发给租约持有者，且未持有者对同一地址的访问自动降级为普通页表遍历」，则失效流量为 O(实际订阅者数)、订阅表允许为保守超集而不引入正确性错误，且可观察语义与广播失效等价。

### 4. 因果链、代价、关键假设与最可能致命反例

**因果链**：缓存一份翻译 = 获得一份**可撤销授予（租约）**，而不是一次**被观测到的事实** → 授予状态放在 IOMMU 边缘（每 device×PASID×range），而不是放一个中心目录 → 设备 TLB 条目携带 grant id；walk 找不到有效授予则不缓存 → 失效只按授予集合发送 → 未授予设备的访问走普通 walk。

**代价**：授予状态 O(devices × ranges)，可能远大于目录的 O(pages)；失效 O(subscribers)；回退会引入额外的 PTW 流量。

**关键假设**：
- (A1) 【假设】互连能保证"失效确认之后，任何使用旧授予的在途请求都不会完成"。**这是最可能致命的点**：ROOT_REVIEW 14 行明确说 PR/PW 不覆盖在途请求，可能另需互连 fence。若在途不可界定，则"定向失效"的前提退化成"先 fence 再失效"，收益被压缩到一次 fence RTT。**这个反例本身就是一个研究问题，而不是本候选的补丁。**
- (A2) 【假设】回退（页表遍历）在目标场景下不比省下的失效更贵。对 200 Gbps 网卡（地图 90 行，IOTLB wall）walk 风暴可能反噬。

**最可能致命的反例**：全对全工作量——几乎每个设备访问几乎每个页。此时订阅 ≈ 全体，无收益且多了授予管理开销。GPS 自己测到 ALS/CT 就是全对全（gps2021.txt 1042–1049 行）。因此主张必须带**可测条件**（订阅集大小分布），不能写成普适结论。

### 5. 最强普通方案与低成本判别实验

**必须比较的最强普通方案**：
- 延迟/批量失效 + 大页（Utilizing the IOMMU Scalably、IOTLB wall；地图 89、90 行）。
- 目录/按上下文定向失效（IDYLL、ShareMMU；地图 122、93 行）。
- 直接全局失效 + 宽 fence（RISC-V 规范允许；地图 132 行）——这不是弱基线，可能是工程上最优点。

**杀死候选的判别实验（低成本，先做，不需要新硬件）**：
- **实验 A（纯 trace，离线，零硬件）**：取真实 unmap/invalidate 轨迹（Linux IOMMU unmap trace，或 GPU UVM 失效轨迹），统计每个失效地址范围在当前时刻的**持有者数量分布**。
  - 应用真实性：轨迹来自真实驱动/负载，不是合成。
  - 收益空间：设可消除的失效字节比例上限 = 1 − E[subscribers]/N_devices。
  - **停止条件**：若在代表性负载下可消除比例 < 20%，直接淘汰候选。
- **实验 B（现有 FPGA 上可做，需另一轮启动）**：用 CVA6+4 iDMA+RISC-V IOMMU 测量"失效确认时间"与"在途请求耗尽时间"这两个分量各自的量级与随 outstanding DMA 数的变化。
  - **停止条件**：若在途耗尽时间 ≥ 你想消除的失效成本，本候选应被重新定义为"fence 优化"，而非"定向失效"。

> 本席未执行上述任何实验；这是提案，不是结果。

### 6. 成功/失败的产出与平台依赖

- **成功**：论文可写「Translation as a Revocable Subscription: Bounded Invalidation With Correctness-Preserving Fallback」，含语义、正确性论证、订阅集分布测量、与目录/延迟失效的同预算对比。工程产出是 RISC-V IOMMU 特性 + Linux 驱动改动。
- **失败**：留下一个负结果——**哪一类订阅分布下定向失效无法胜过广播**，以及**在途耗尽时间的实测分量**，后者是任何未来失效方案都必须尊重的下界。
- **现有 FPGA 能做什么**：可承载控制面状态、可测定向 vs 广播的失效代价、可测 A/B 两分量（用 4 个 iDMA 制造 outstanding）。
- **必须依赖什么**：真实 ATS/PRI/SVA 设备（如支持 SVA 的网卡或 GPU UVM 驱动）来产生真实设备 TLB 行为；以及互连级在途语义（PCIe/CXL 模型或真实 fabric）。地图 184 行明确当前平台不能直接支持 ATS 加速器/GPU 多租户结论。

## 候选 D6-P2：池页安全回收窗口的「双层」上界（失效确认 ≠ 在途耗尽）

### 1. 真实应用与触发条件

**事实**：地图 162 行（边界索引，仅摘要已核）记 Pond 研究 CXL 内存池容量浪费与延迟权衡，生产 trace + 仿真/延迟模拟，**不是 2023 已实物部署 CXL 全栈**；ROOT_REVIEW 47 行同。地图 186 行把 CXL 完整放置/一致性、RDMA 注册缓存/撤销列为**尚未深读**的范围。

**具体触发条件**：
1. **CXL 池页重分配**：池中物理页从主机 A 转给主机 B。A 侧所有翻译副本与在途 DMA 必须排空。【事实】地图 132 行指出规范只覆盖已被 IOMMU 处理的请求，在途可能另需互连 fence。
2. **RDMA MR 注销/注册缓存驱逐**：注销后网卡可能仍有使用旧映射的在途读。地图 186 行记为待深读，**本席未读全文，标待核**。
3. **内存压力下的高频回收**：回收频率高时，任何"固定延迟"策略会直接体现为池容量损失。

**为什么现在值得研究**：【推断】池化/可撤销映射把"安全复用"变成一阶问题，而当前语境下的默认做法（固定保守延迟、或 flush+ack）一个是浪费容量、一个是 O(devices) 状态。实时/混合关键性主机（Bermuda，地图 92 行；ROOT_REVIEW 38 行列实时 QoS 为未覆盖范围）需要的是**有界**而非平均意义的回收。

### 2. 最接近的先行工作与精确差别

**(a) Pond（ASPLOS 2023，仅摘要/§1/§9 由根读过；本席未读全文，待核）** 地图 162 行、ROOT_REVIEW 47 行。
- 相同点：CXL 池化的容量/延迟权衡。
- **精确差别**：Pond 的权衡是**容量 vs 访问延迟**；本候选问的是**重分配时的安全性契约**——一个页在什么时刻才能安全交给另一个主机。这依赖的不是池容量模型，而是失效确认 + 在途耗尽的分层界。

**(b) IDYLL / ShareMMU（地图 122、93 行；ROOT_REVIEW 11–12 行）**。
- 相同点：都是"翻译更新必须完成"。
- **精确差别**：两者研究的是**失效成本**（42% 时间、back-invalidation）。本候选主张的是**失效完成不足以构成安全复用**；真正下界由最慢的失效确认 **加上** 互连在途耗尽共同决定。**这两层不能被合成一层。**

**(c) WIC（已读全文，wic2025.txt）作为反例证据**：WIC 报告 UVM 一次只能处理 **256 个 fault**，超出的 fault 必须排队，成为扩展瓶颈（887–898 行）；且用配套页 P/P′ 的失效信号轮换来"保证有效且精确的失效"（673–689 行）。这说明**故障/握手路径的深度是硬性上限**，不能靠缓存消除。

### 3. 一句话可被推翻的研究主张

> 对池化或可撤销映射，安全回收延迟的下界等于「最慢失效确认完成时间 + 互连在途耗尽完成时间」，且该下界与池利用率无关；因此任何按固定定时器/固定延迟回收的策略，要么不安全，要么其容量损失随设备数与 RTT 线性增长，且**不能通过增加翻译缓存或预取来降低**。

### 4. 因果链、代价、关键假设与最可能致命反例

**因果链**：回收 = 撤销授予 → 层 1：失效必须被硬件**确认**（可测）→ 层 2：使用旧授予的**在途请求必须全部终止**（通常需要 fabric 级排序点或请求时间戳/epoch）→ 只有两层都完成，页才可交给 B。

**代价**：若 fabric 无 epoch 原语，必须用保守延迟 = max over devices (ack + in-flight RTT)，容量损失 ≈ 回收速率 × 延迟；若有 epoch 寄存器，则增加每请求者状态。

**关键假设**：
- (A1) 【假设】存在 fabric 级 fence/epoch 能给在途集合一个有界。**若不存在**，安全回收只能在"停住设备"下完成——这既是本候选最强反例，也是最强论文（对一类部署的不可能性结论）。
- (A2) 【假设】池控制器能区分"设备空闲"与"设备无在途"。多数实现不能。

**最可能致命的反例**：一个**不守规矩或无法界定的设备**持续向已 unmap 的池地址发起读。若在途不可界定，则不存在有限安全延迟，只能靠 fabric 强制——这直接**否定"更大的翻译缓存/预取能解决问题"这条惯性路线**：你无法用缓存摆脱无界的在途集合。

### 5. 最强普通方案与低成本判别实验

**必须比较的最强普通方案**：
- 定时器回收 + 保守延迟（工业默认，必须核实 Pond 全文是否已做，待核）。
- Flush + 每请求者 ack 后复用（代价 O(devices)/次）。
- IOMMU 全局失效 + 宽 fence（RISC-V 允许扩大为全局，地图 132 行）。
- RDMA MR 注销 + fence（verb 语义待核）。

**杀死候选的判别实验（可在现有平台做，这是本候选的最大优势）**：
- **实验 C（现有 FPGA，第二轮才能执行）**：在 CVA6 + 4 iDMA + RISC-V IOMMU 上测两个分量：
  - t_ack：IOTLB 失效完成时间；
  - t_drain：从"设备停止发起"到"IOMMU 不再收到新请求"的时间。
  扫描 outstanding DMA 数与并发设备数。
  - 应用真实性：iDMA 的队列深度可编程，能制造真实 outstanding。
  - 收益空间：t_drain / (t_ack + t_drain) 决定"翻译缓存路线"最多能占多少份额。
  - **停止条件**：若 t_drain/t_ack ≈ 1 且不随队列深度增长，则在本平台上"在途耗尽"不是一阶项 → 淘汰 P2 的本平台版本，只保留理论层。
- **实验 D（需外部材料）**：检索并核对 CXL 3.0 fabric 是否提供全局 epoch/fence 原语、PCIe PRI 的 Page Request queue 深度规范值。**这是"待核来源"，本席无浏览能力。**

### 6. 成功/失败的产出与平台依赖

- **成功**：论文可写「Two-Layer Safe Reclamation for Pooled Memory: Separating Invalidation Acknowledgment from In-Flight Exhaustion」，含语义契约、下界证明、以及现有 FPGA 上的两分量实测分解。
- **失败**：留下**现有平台上两分量的定量分解**，以及"对池化内存，翻译缓存不是约束项"的负结果——这本身就收窄了地图第 41 行的因果权重。
- **现有 FPGA 能做什么**：**能**做实验 C 的两层分解，这是当前平台少见的可直接支撑的跨域问题。**不能**做真实 CXL 全栈、真实多主机 fabric（地图 184 行明确）。
- **必须依赖什么**：CXL/PCIe 规范文本与实验数据（待核）；若要验证多主机语义，需要 fabric 仿真器或真实 CXL 硬件。

## 事实 / 推断 / 假设 分层

**事实（有提供文件行号支撑）**：IDYLL 真机 42% invalidation（地图 41 行、ROOT_REVIEW 12 行）；RISC-V IOMMU PR/PW 不覆盖在途请求、允许扩大为全局失效（地图 132 行、ROOT_REVIEW 14 行）；ShareMMU 仍需 flush 确认（ROOT_REVIEW 11 行）；GPS 订阅是 hint、未订阅走远程（gps2021.txt 336–363 行）；GPS 订阅集通常很小、ALS/CT 例外（823–825、1042–1049 行）；WIC 的 UVM 256 fault 上限（wic2025.txt 887–898 行）；NDS 翻译层额外 17–41 µs、占存储 0.1%（nds2021.txt 1383–1398 行）；MINISA 控制流可放大到 96.9% stall、抽象粒度压缩 2×10⁴ 倍（minisa2026.txt 40–45、861–877 行）；Pond 为 trace+仿真而非实物 CXL 部署（地图 162 行）。

**推断**：地图第 41 行把四类"定向/批量/目录/按范围"并列到同一成本轴是过度概括；"在途耗尽"应被视为独立一层；订阅集通常小这一事实可迁移到 IOMMU 失效设计。

**假设（未被任何提供材料证实）**：D6-P1 的(A1)互连可界定在途；(A2)回退不比省下的失效更贵；D6-P2 的(A1)存在 fabric epoch；(A2)池控制器能区分空闲与无在途。三者若被证伪，候选应相应淘汰或收窄。

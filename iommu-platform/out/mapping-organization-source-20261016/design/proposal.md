# 候选 1 的有界正向发展：路由揭晓后的整页转交

2026-10-16。此文只回答本次设计子任务，不改变研究排序、暂停状态、生产代码或实验授权。请求配置为 `gpt-6-astra / xhigh`；独立运行元数据不可取得，实际模型与强度记为 `unknown`。共享 IOMMU 研究 Codex-only，未使用 DeepSeek、Claude 或子席。

## 1. 结论

**保留一个具体正向版本：接收页在路由揭晓后停止接收，把不去 B 的对象搬出，保留去 B 的多数数据原地，再把整个物理范围转为 B 可访问的范围。** 它改变了付复制费的一方；对于“绝大多数转发、少量本地处理”的混合页，存在少搬数据的条件空间。

**但“搬走另一保护域的数据，再形成大映射”本身已有明确前作描述，不能作为新策略。** Mosaic §4.2 正文直接写出：为把 Application 1 的小页合成大页，先迁走 Application 2 的小页，再按需要整理 Application 1 的连续性（[原文 411–417 行](../../shared-translation-literature-20261006/papers/mosaic2017.txt#L411)）。同信息普通程序也能执行下文全部动作。因此，本轮得到的是**可推翻的系统问题与协议候选**，没有得到独立策略创新或收益证明。

最有希望保留的准确问题是：**当分类晚于 RX 放置、而独立子页回收早于整页授权退役时，能否用有界的备用内存和局部暂停，把一个接收页安全转交给另一设备，并使整条路径的费用优于精确映射或影子复制？** 若现有 page flipping／fbuf 等机制已经支持相同合同和转换过程，就应停止该版接口新意主张；仍可核查是否存在可复用的新成本认识，但不能仅把改用 XDP 当贡献。

这里提出一个强版本，候选 2 仅在第 8 节划定独立发展边界，不拼成大系统。

## 3. 两条合同轴必须分别冻结

**空间授权：** A 的专用接收池可以长期授给 A，不意味着 B 可以访问其中 CPU 路径对象。若 G 中仍存在仅供 CPU 的活对象，整页授 B 不合法。把该对象复制走之后，还必须合法结束旧对象对原地址的占有，把空洞重新分配成可授 B 的空间；清零只有数据清理作用，不会自动产生授权。原页中的旧 packet、headroom、尾部、驱动元数据和未用槽也必须逐项处理。

**时间撤销：** 至少分开以下三种语义。

1. `POOL`：合同允许指定设备的专用物理池持续映射；对象 return 不要求立刻取消该设备的全部物理访问。仍然禁止向 B 暴露 CPU 路径数据。
2. `STRICT-PHYSICAL`：每个对象要求的 unmap 返回／撤销边界之后，该设备对原物理字节的访问必须结束。此时整页映射不能跨过某个子对象的撤销边界，只因其他对象仍在使用就继续保留它。
3. `LOGICAL-ORIGINAL`：保护的是原始对象，允许复制到设备自己的影子池后，影子物理内容按另一合同保留。它与 `STRICT-PHYSICAL` 不同，不能用影子池的历史数据可读性偷换原始对象保护。

本版本的主要正向条件使用 `POOL`，或明确允许整个批次保持所有权到共同退役点的合同。`STRICT-PHYSICAL` 下，除非原应用允许把相关撤销调用本身延后并支付其等待后果，否则必须及时拆映射／细粒度撤销或回退；不能把完成时间修改成有利条件。

用户尚未选择这些合同，本文不代选。完成时间、CPU 费用和不可回收内存也分别作为结果，不用一个维度代替另一个。

## 4. 唯一正向版本：C1-EVAC-CONVERT

### 4.1 输入何时知道

| 时刻 | 已知且可用 | 不允许免费知道 |
| --- | --- | --- |
| 初次 RX 分配 | 接收设备 A、当前保护域／用途、物理回收单位、槽状态、队列、内存预算 | 下一 packet 的 B／CPU 路由、最终引用持续时间、未来空闲窗口 |
| RX 完成并实际执行分类 | 当前 packet 的动作、目标 B、所需权限；已有已完成 RX 的真实路由 | 同页仍在设备手里的描述符将收到何种数据，尚未到来的 packet 的动作 |
| 页封闭成功 | G 内每个已发布 RX 的实际完成；哪些槽仍空闲；不再有写入 G 的合法新 RX；每个存活对象的已揭晓目标 | B 最终 TX 完成时刻、CPU consumer 将来多久释放 |
| 对象发布／回收 | 实际取得的外部引用、TX 完成和 return 事件 | 将软件 flush、提交队列或某个局部完成当作全部 DMA／引用结束 |

root 提供的本轮源事实是：本地选定 mlx5e XDP 路径为 order-0、一页一包，PASS 与 REDIRECT 是分支。因此“混装”是拟议 PMD 组织把多个现有小页放入同一更大范围后才出现的结构，不能倒写成当前驱动已在 4 KiB 页中混装多个路径。本席不重复调用链核查；root 应将其已核精确行号接入最终报告。

### 4.2 具体动作及提交边界

令 G 为可大映射的对齐物理连续范围，F 为其中转交 B 的有效数据字节数，E 为其余需保留对象的有效字节数。所有分类信息来自实际已完成接收。

1. **先尝试局部封闭 G。** 停止从 G 给 RX ring、refill cache、page-pool cache 或其他 CPU 分配新槽。不能只设置一个 pool 标志而保留旧描述符继续接收。已有 RX 必须实际完成、合法取消或使此次转换回退；没有流量时不能无限等待一个未填满的接收页。给封闭尝试设实际可接受的等待预算，超时走普通路径。
2. **在发布前冻结对象身份。** 只有尚未交给不可控 CPU consumer／外部引用的对象能直接搬走。将不去 B 的对象复制到保持其原授权的存储，使用真正的对象构造／引用转移接口；等价性要求 payload、顺序、校验、元数据及释放语义保持。已发布的 skb 或其他不能迁移的引用不符合此快捷路径，应回退或另计合法迁移协议。
3. **结束旧对象并重新分配所有字节。** 原 E 区域失去旧对象身份后，才能转为属于 B 页租借的空间。清除必须隐藏的残留；仍需 CPU 使用的驱动元数据应移至 B 不可访问的控制存储或明确纳入授权。填充／空槽不能仅凭“当前为零”被授予 B。若合同不允许这些地址重新授权，整页方案不成立。
4. **处理 A 权限和所有别名，再发布 B。** 若合同允许 A 对专用池持久访问，只能依据该合同保留 A 映射，且软件不能再写入该批次；若 A 权限也必须结束，就撤 A 并等待真正的同步／在途义务完成。核对其他映射别名、可缓存设备翻译和 CPU 同步。然后建立 B 所需的映射及权限，完成所需发布屏障，才向 B 提交原地保留的 F 对象。这里没有“coalescing 所以无需失效”的特权。
5. **独立对象完成，只归还记账。** 某个 B 对象 TX 完成可以解除其真实引用，但在 B 仍有 G 的整页映射时，该对象对应子页不得返回 A 的正常接收复用路径。所有 return callback 必须进入该页的退役状态，并防止重复返回或绕过该状态的缓存复用。若合同要求该子对象当时立即撤销 B 权限，执行拆分／细粒度撤销或拒绝本次整页转换。
6. **整个 G 的义务结束后再交回 RX。** 等实际最终引用和 DMA 结束，撤销 B 的整个授权并完成必要同步，按下一次所有者所需清理内容、处理 A 映射与页池身份，最后让 G 重新接收未知路由数据。**绝不能跨过此边界保留 B 的大映射来摊薄未来未知 packet 的费用。**

消费者引用归零并不自动表示 G 已空闲：page_pool 仍可能缓存小页并保留 A 映射。封闭必须控制或取回这些缓存、已发布 RX 描述符及每个 return 回调；底层 PMD 是否 idle 不能只靠 consumer refcount 判断。root 已确认这是本轮接口核查的决定点。

步骤 1–3 可失败回退，但已进行的复制、整理和等待仍计费。步骤 4 之后只能依照已发布描述符的完成／撤销协议退役，不能通过“取消候选”消除在途义务。

这是协议语义草案，没有新增生产 ABI，也没有声称已有实现能无损挂入 page_pool。所需的最小接口问题是：是否能获得并最终释放**整个 G 的接收与回收控制权**，同时不停止不相关页的接收。仅得到“当前小页 refcount 为某值”不够。

root 还指出两个待判别接口：分类返回后的现有 redirect 会立即发布，候选须在此前保存每帧目标引用、有效性和状态，不能保留短命的每 CPU 临时信息或免费重跑有副作用的分类程序；如果已提交 RX 只能整队停机回收，局部封闭就不能声称不影响其他页供给。这两项均未在本席实现。

### 4.3 为什么这个动作值得测，而不是预设未来路由

普通方向是把去 B 的 F 字节复制到 B 永驻池；本版本选择移动不去 B 的 E 字节，使原物理连续范围成为 B 的合法存储。它不提前预测当前页的目标，也不要求所有 packet 路由相同；已观察的分支组成决定本次是否尝试转换。

但是，当前页路由信息只支持当前转换；它不能为未来 RX 分配提供已知正确的目标。历史偏好可以作为普通启发式，但必须允许变化并计错选、回退和页等待费用，不能变成免费 oracle。

## 5. 同信息、同合同的具名普通对照

| 对照 | 具体可执行动作 | 不能人为拿走的能力 |
| --- | --- | --- |
| O-EXACT | 保持 A 接收池，B 只映射将转发的实际小页／合法 scatter-gather 范围；按真实 TX 完成和合同撤销 | 允许合法 batching、已有 page_pool、合并失效、页表缓存、普通预热；它不必每包做全域失效。若同页其他字节也不授权 B，还须先做到最小映射粒度隔离。 |
| O-SHADOW | 根据已揭晓路由把 F 复制到 B 专用、方向／权限正确的影子池；源对象按自身合同释放 | 持久映射、NUMA 本地池、并发分池及同信息复制阈值。原 buffer 与影子物理池的撤销合同分开比较。 |
| O-POOL-SELECT | 在分配时用当时已知队列／目的类别分池，未知类别落普通 RX 池；路由揭晓后在精确映射与复制之间选 | 可用真实硬件／软件提前分类接口，但不能免费赋予其未核能力；新增分类延迟、配置与复制仍计成本。 |
| **O-SEAL-EVAC** | 用现有可获得的页／对象所有权、引用计数、复制、清理及 map/unmap，把第 4.2 节的整套动作逐项写成普通控制流程 | 与候选得到同样的路由、完成、预算和任何新增付费接口。它可以选择搬 E 而不是 F，也可以对已知当前状态采用同样阈值。 |

**裁决：O-SEAL-EVAC 是候选策略的完全同动作复现。** 本轮不能声称候选控制策略相对它有性能增量。若实际现有接口足以低成本执行该复现，就不应再为同样动作添加一个新接口或复杂控制器。若确实缺少廉价、可组合的整页控制权，研究对象可以是该能力及实现；普通程序在该新增付费接口上复现策略，不证明接口已发表，但接口缺失本身也不证明新意。

这里的“复现”指同信息、同接口下已逐步列明的普通控制构造；没有编写、编译或运行该实现，也没有因此证明当前驱动已提供全部所需接口。

精确映射与 O-SHADOW 哪个更强由输入、合同和成本决定。离线已知所有未来路由／释放时刻的分组只可作为上界，不能充当部署对照。

## 6. 完整成本、必要条件和正反预测

### 6.1 成本表：不把不同单位相加成“最优”

默认报告资源向量：CPU 工作、逻辑复制／清理字节、实际内存流量、峰值及保留内存、页表与映射操作、失效服务、翻译请求／miss、有效任务完成时间和吞吐。只有用户或应用合同给定权重、服务约束后才形成标量目标。逻辑字节不等于 DRAM 流量；更少页表项不等于更少总延迟。

候选必须支付：

- 获取／维持物理连续页、初始映射、准备与清零；若基础接收池本来已支付，所有对照共享该共同费用。
- G 的状态、generation／所有权检查、路由汇总、每对象引用与 return 接入、并发锁／原子操作和控制元数据。
- 不能继续给 G 补包时的 RX 替换存储、ring/refill 补充工作、额外等待、对有效吞吐的影响；固定总内存预算，不能靠无限备用页隐藏等待。
- E 的搬迁、对象重建、原位置／padding／敏感元数据清理，以及失败尝试已花掉的工作。
- A 或其他别名需要的撤销；B 建映射、发布、最终失效和同步；设备缓存翻译／CPU 缓存同步按实际平台收费。
- 每个对象已经完成但 G 尚不能退役时的保留内存；B 长尾使 G 不可复用的后果。
- G 回 RX 前重建 A 映射、下一轮内容清理、翻译重新加热，以及对其他设备共享资源的影响。

O-SHADOW 的目的池也有内存和初始化费；其永久 B 映射可重复使用，不能让候选独享摊销，也不能把候选每次 A→B→A 的转换当永久映射。O-EXACT 可以节省上述整页锁定和 CPU 搬迁，但有自己的精确映射与翻译费用。

### 6.2 必要条件与可推翻的条件正例

设 t 为尝试授予 B 大映射的时刻。若 G 中还有未搬离、未合法释放且不许 B 访问的对象，则 G 不满足大映射空间授权条件。若合同要求独立子对象即时撤销，且没有细粒度过滤，则其第一次撤销边界就结束该大映射的合法持续区间。这是直接的合同推导，不认领新定理。

在“保留原地 F、不等待 E 自然释放、E 没有可直接采用的其他完整副本、只允许普通复制来保持 E 内容”的限定下，至少要搬运 E 字节的有效内容；实际还要清理 Z 字节及处理元数据。只计逻辑 payload 读写时，候选约为 `2E + Z`，影子复制约为 `2F`，另加各自完整清理／分配等费用。**这个表达只表示指定操作的字节账，不是性能模型、最小性定理或已测 DRAM 流量。**

一个可接受的条件正例必须同时满足：

1. 已核路径能在不可迁移的外部引用发布前取得完整路由，且 G 内已发布 RX 都能在等待预算内结束，或确有合法取消接口。
2. 同一 G 中 F 显著大于 E，Z 与元数据整理也足够小，使完整搬运费低于 O-SHADOW；这不能仅由转发包数占多数推出，仍需 payload、headroom、旧内容及对象构造信息。
3. 相对于允许全部合法 batching 的 O-EXACT，大映射减少的实际翻译／映射工作足以支付封闭、整页往返权限变更、CPU 搬迁、状态和保留内存费用。
4. 总内存和服务约束允许为封闭 G 补充 RX 供给；所有方案完成同一批有效工作。各设备的实际 domain／IOMMU 关系须核实；两张 netdev 本身不是两个独立授权域或共享 IOMMU 资源的证明。

满足 1–4 可支持“该整页转换在这一来源投影下有可行成本范围”；仍不支持它胜过 O-SEAL-EVAC，因为后者复现同一动作。若要声称完成时间改善，必须补服务和重叠关系，不能从字节不等式直接推出。

**相邻失败，保持同一任务而只改变一个关键输入：** 当前页中出现一个已经发布给不可迁移 CPU consumer 的对象，且其释放晚于允许转交时刻；则不能完成少数搬离，必须等待、精确映射或复制 F。另一个失败是其余条件不变但第一次 B 子对象的 strict 撤销早于整页结束；整页持续映射就失去合法性。还有可直接计费的失败：E／Z 增大、接收空洞使封闭等待过长、B 长尾使备用页不足，或者 O-EXACT 的批量同步已经很便宜。

### 6.3 本轮接受标准及下一份最小证据

本轮接受“具体问题和可推翻机制卡”，**不接受新颖性、性能、原生可达性或最优性结论**。下一份最小证据应是一页／一个有限 batch 的源绑定账：

- 明确合同与可重新授权的字节集合；明确谁能看到 shadow／历史内容。

## 7. 可核查的新意表述

> Mosaic 已经通过域内连续分配、原地合并和压缩降低大页管理代价，并明确描述迁走异域页以获得可合并范围；Ingens 已经把连续性、利用率、访问频率和后台搬迁纳入协调管理（上述节号与原文行号可复核）。所以本候选不把分池、利用率阈值或搬少数保多数作为新方法。要发展的问题是：接收位置先于下一消费者确定时，如何将路由揭晓后的对象授权转换为整个物理页的可执行所有权转交，并闭合独立子页归还与整页设备授权的时间差。若能在真实控制点实现一种现有近邻不能以相同能力／费用提供的局部转换，并在固定内存、授权和有效服务合同下给出完整成本优势，这可以构成系统贡献；若 O-SEAL-EVAC 或最接近已发表工作以相同接口和费用复现，就不能把该版本的策略或接口称为独立创新。当前只证实前作边界和条件问题，没有证实上述新增能力与收益。

这一论证保留用户思想，明确了需要兑现的差异，也允许版本被否决；不是“没有找到接口，所以新”。

## 8. 候选 2 的独立边界：释放依赖与局部退役

候选 2 先固定合法授权，研究物理回收粒度，不依赖候选 1 成立。

- 若分配时已知道准确的最终释放批次，普通 arena／region 加引用计数就可把同批对象放在一起并在最后一次释放时退役；仅增加标签、水位线或关闭某页补入，不能作为独立机制。
- 可能值得保留的是：最后释放责任在分类／fan-out 后才改变或出现多个真实持有者，而现有按设备／队列分池不能据此形成可退役单位。须先证明两个不同的真实最终释放依赖会进入同一物理回收单位；不能把 RX 完成、TX 提交或 page_pool return 混为同一边界。
- 若在后继揭晓后才分组，就要支付搬迁、引用更新或等待；不能把晚知道的信息回填给最初分配器。若依赖前置已知，必须给普通 arena 同样信息。
- 只关闭新分配不会迫使老引用结束。没有消费者完成界、失效界及后续释放界，就没有有限退役期限。保留内存至少受非空物理回收单位约束，但该直接粒度推导不是新定理。
- Ingens 已覆盖利用率驱动升降级与后台压缩；Mosaic 已覆盖拆分、同域迁移和空闲大页恢复。因此增量须在具体 DMA／引用条件下的可执行退役能力或完整成本差异，不能只说“把生命周期加进去”。

候选 2 的推进条件是：已有 cap／shrinker／MRU、队列分池、普通 arena 以及实际可用的小页拆分／迁移都计费后，仍有一个明确残余。当前没有该来源切片，本席不把它升级为第二个主方案。

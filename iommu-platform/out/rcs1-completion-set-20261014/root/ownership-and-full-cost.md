# RCS1: legality, ownership and full costs

This round changes fill/victim/bypass choice after one complete normal walk. It keeps the original TC/native source identity, held VALID, same-ID request order, successful-result checks, current hit bypass and W-owner/read-admission guards. A registered intention never gives a PA or permission. A completed-set score never releases a payload buffer, publishes a successful dependency or suppresses a walk/fault/invalidation.

## Necessary new production interfaces (not implemented)

1. Trusted four-task finite scatter registration: exact formal key/current context/epoch, real producer publication/consumer receipts, source/function-job/slot association, all remaining R/W lookup uses. Native source0/1 HOLD accepts strictly aligned64B DEFAULT/no batch/idle only. The multi-copy software task requires its own paid registration and pre-NEXT_ID supply; there is no enlarged free native gate.
2. Exact last-use receipts: private current translation alone cannot delete later same-page lookup uses. Last native physical AR/AW acceptance, precise phase/slot/source/epoch mapping and no-replay proof must close each remaining-use bit. TC trans_resp_ready is always1 while waiting, and subsequently COMPLETE waits actual physical packet acceptance into the native path. That endpoint is not external DDR service or task/B/consumer completion. Pending callbacks prevent slot reuse; invalidation/epoch change disables hints and drains owned requests normally.
3. A normal full-walk direct-result path: current TL PT exits on iotlb_lu_hit. PTW update supplies a full checked result but zero replacement mask merely suppresses cache writing. A full-result content latch / mux must reuse the normal permission and address formation logic, retain native request association until one stable response is accepted, suppress repeat PTW init while owned completion is pending, and implement error/epoch priority. It forwards only to that accepted request owner; other tasks still need native lookups and permission checks. Permission faults must not become successful fill/response. Superpage/global/S2/MSI/ATS stay conservative normal fallback in the finite S1/4KiB/non-global candidate scope.
4. Live resident/formal-key/permission/epoch snapshot and arbitrary selected allocation mask. Although the cache's policy_mask_i can express an arbitrary mask/zero, the current TL wrapper only wires the fixed0x0003/0xfffc partition masks when enabled. New online mask routing and snapshot read ports are required. The research snapshot lacks a complete permission/epoch contract, is not a free high-bandwidth control port, and source presence does not show a loaded FPGA bitstream.
5. Selector pipeline with snapshot generation checks. Current hit bypass and R/W/B progress remain enabled; if a concurrent last-use or invalidation changes the scored snapshot, the conditional program discards the hint and uses current ordinary PLRU while delivering the owned result. Hints must never queue/block a real retirement simply to keep scoring stable.
6. Complete error and data/consumer receipts. The current production wrapper uses NO_ERROR_HANDLING; backend reports neutral error and B-based normal done. Native done alone cannot certify response-success, downstream consumer/cache handoff, no later access or final buffer release. The finite model has all OKAY responses and checks normal-success closure; injected error/drain production safety remains unvalidated.

## Full costs, with unknown quantities preserved

All comparison rules receive the same paid information and normal full-result route. Native tags, request fields or a legally consumed field may be reused; do not force duplicate state to give RCS1 an advantage. The18-key materialized record example is `(29 VPN +20 PSCID +16 GSCID +2 stage +1 valid +4 R users +4 W users + E epoch)*18 = 1368+18E` bits. Four2-bit registration ages add8. This is a component subtotal, not a complete added FF count or minimum representation. Registry/task range/segment descriptors, all owners/slots/generations/ABA control, errors/receipt tracking and software costs remain additional.

Current package iotlb_stage_content_t is52 bits (44 PPN, two page-size flags, six permission/status bits); full iotlb_content_t is104 bits. A straightforward new shared full-content result latch is therefore104 bits plus valid/association/epoch/mux/control, unless some existing owned storage is proven reusable. Neither this104 nor the1368 subtotal is a complete design cost. Original15-bit PLRU history is reused; no duplicate PLRU or extra translation pool/walker is needed.

Root adopts the exact E_q filtered-reference implementation. In this four-task scope, E_q is a4-bit combinational mask if not stored. It requires detection of per-task missing keys other than incoming q, current per-way user bitmap filtering, popcount/comparison, insertion-versus-bypass and score-tied mask formation. Counts fit3 bits for0..4 tasks and5 bits for0..18 keys if materialized. A 17-virtual-cache state array or 17-cycle scan is not mandatory. Choice fanout, key-to-way matching/read ports, update/fill/invalidation synchronization, timing and optional generation/snapshot registers still cost resources. B5 blind min-ref uses the same per-key users and cheaper popcounts but omits E_q filtering; B3/fraction also pay their own exact missing/fraction logic.

The conditional model charges one choice tick and one ordinary result/permission tick, with identical accepted-request/response semantics across rules. One model clock meeting all logic timing is explicitly conditional; actual selection latency/Fmax/area/CDC and absolute state are unknown. PTE and data share the one service abstraction, and all actual prefix payload work is inside the measured episode; nothing is prefilled.

For a concrete software supply realization, current idma_submit_config writes64-bit src,dst,length,conf, followed by NEXT_ID read.51 copies therefore imply204 configuration writes plus51 trigger reads (255 MMIO operations, nominal2040 transferred register bytes) **before** polling, registration, page/ownership management, consumer receipts or cache maintenance. These are sourced operation counts for this possible software realization, not measured CPU time or actual MMIO bus bytes. Required polling adds at least one valid completion observation per copy if this sequential software route is used; actual polling count/cycles are unknown. The conditional engine abstracts that supply contract and reports measured-model service timing separately; it does not claim full CPU-inclusive speedup.

Full physical area, Fmax, actual CPU/software/registration/cache-maintenance cycles, application/GPU benefit, FPGA timing and production fault/invalidation drain tests remain null. Publishing all categories with null values closes the cost *accounting*, not their physical measurement. An unmeasured shared cost is not zero, and a model improvement alone cannot prove complete hardware net benefit.

## Finite data obligations

Four logical tasks are fixed by one producer completion and three real downstream task receipts, not divided per64B copy for cache scoring. Payload copies use disjoint64B blocks inside shared formal4KiB pages. The publication copy's B plus stage receipt controls data dependency; all remaining copies run under the original one-copy-per-source ordering. Last shared lookup may precede that copy's W/B, producer-stage receipt and task retirement. Final quiet requires no pending translation/walk/result/service/R/W/B, real consumer receipts and owner releases. Full source-ID association and same-source order remain observable in the new event record; no result permission broadcast or early data release is allowed.

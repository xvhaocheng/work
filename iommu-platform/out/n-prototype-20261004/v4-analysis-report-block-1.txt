# 交付 2：用户可见简明结论（plain 中文）

1. 两版 BIT 已由 actual Codex 构建，exit 0、时序通过；S/N 各自 15 个 case 全部 complete、exit 0、`problems=[]`、`taint=0`、`unexpected_warnings=[]`；原版 15 项为复用、未重跑。（`serial-v4-build-acceptance.json:4-8`、`hit-v4-build-acceptance.json:4-8`、`serial/summary.json:469-482`、`hit/summary.json:469-483`）
2. 长组条件中位 V 吞吐：Solo ≈ 282.8 / 283.2 / 283.0 MiB/s；A1 ≈ 149.3 / 143.4 / 143.2；A8 ≈ 108.9 / 104.3 / 104.3；A16 ≈ 100.7 / 96.7 / 96.7（original / serial / hit）。同窗口 A 吞吐在 A1/A8/A16 与 V 相等（窗口被 V 工作量占满），**不是独立的总线吞吐**。
3. `S/原版` 差异约 +0.1% ~ -4.2%，其中 A1/A8/A16 的 -4% 左右主要来自"结构 + buffer 差异"，**不能当纯布局因果**（original 是 3 拍 buffer，S/N 是 512 拍）。`N/S` 差异约 -0.0% ~ -0.1%，本轮 **fast 全 0，不构成绕过收益或代价的证据**。
4. 诊断 bit2 `candidate_in_window` 在全部 45 case 从未出现；probe / dc_eval / leaf_eval / leaf_miss / fast_accept 全为 0；banked-hit 的 bit15 `runtime_enable` 在 15/15 均出现；A8 偶见 bit1 `full_fast_window`，A16 只到 bit0。**结论是本轮未观测到合格窗口候选，不能推出"没有 IOTLB 命中""没有上游 V 排队""路径坏了"或"MSI 被拒"。**
5. 读守卫（`w_unfilled_q>0` 且 owner 非 V 时挡住 V 的新 AR）在 RTL 方程上**可以是**结构排除原因，但本轮没有上游排空/阻塞/候选计数，**运行时 cause 未获证明**；也**不能**把旧 MSI mode0-only 静态排除称为本轮实际唯一原因（从未进入 probe）。
6. N 是前人已知 hit-under-miss 基线，**本报告不宣称 novelty**；旧 HPM / miss / PTW 字段在 banked 结构下无效，本报告一律不用。
7. 保留：冻结旧数据全部保留，本轮不重跑，不更新 Linux/SD。

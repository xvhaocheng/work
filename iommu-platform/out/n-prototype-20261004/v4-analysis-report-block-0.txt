### 6.2 candidate=0 的严格含义

**本报告确认：** 在本轮 frozen 工作量（short = 262144 B、long = 16777216 B = transfers × 4096）下，**未观测到任何"窗口内合格候选"（bit2 = 0）**；因此 probe 从未启动，DC/LEAF 未评估，无显式 MSI reject，无 fast accept。

**本报告不确认（禁止外推）：**
- 不能说明"没有 IOTLB 命中"：RESULTS.md `:348`。
- 不能说明"没有排队的上游 V"：RESULTS.md `:348`。
- 不能说明"路径已坏"或"机制已被科学否定"。
- fast 全 0 是科学上未行使，**不是技术失败**：RESULTS.md `:326`、`:513`。
- DC good = 0 且无显式 MSI reject 时，**不能唯一归因 MSI**：RESULTS.md `:349`。
- 诊断采样跨窗口时 start/eval/leaf 计数之间**无需守恒**：RESULTS.md `:351`。
- **旧 HPM / miss / PTW 字段在 banked 结构下不是有效 metric，绝不作为机制证据**：RESULTS.md `:352`、`:701`；`raw_observation` 长度 35 仅是旧 HPM 数组，本报告不使用：RESULTS.md `:651`、`:701`。

### 6.3 helper window 与诊断 bank 的定位（避免混淆）

- **helper window 本身有效**：`helper_window` 与 P4M cycles 一致、A 字段来源已交叉核对（RESULTS.md `:95-105`、`:573-612`；`hit-v4-01/cases/long-r1-a8/helper.json` 的 `cycles=7673237` 与 RESULTS.md `:169` 一致）。
- **诊断 bank 是第二个 16-word bank**：观察器局部索引 16..31，研究逻辑索引 **D10..D1F**，前端 raw **F10..F1F**：spec `:166`。即 **"前端 raw F10" = "第 16 字偏移（word offset 16）" = "逻辑 D10"** 是同一 bank 的三种命名；本报告统一称"诊断 bank"，其后紧跟 D11..D1F（offset 17..31）。
- 诊断计数器位于 diag bank offset 7..15（绝对 word 23..31），只计 event bits 3..11：spec `:167`。
- `diag fast` 必须等于 core fast sum：spec `:167`（validator `test_fast_accept_must_equal_core_fast_sum`）。

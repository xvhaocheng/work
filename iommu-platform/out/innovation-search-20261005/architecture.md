## 0. 先锁定可用的“事实地基”

我提的问题都尽量锚定在已有事实上，而不是凭命名想象：

- 【已知事实】平台：CVA6 + 四 iDMA + RISC-V IOMMU + Linux，Genesys2，50MHz，16 条 IOTLB，四模式 S/N/P/PN（`SPEC.md:4` `SPEC.md:5`）。
- 【已知事实】原始问题是“多 DMA 共享地址翻译时的干扰和性能”，且**不要求**局限于两路或 16 条目（`BRIEF.md:7`）。
- 【已知事实】172/172 功能验收成功，但只来自单次启动内重复，不能当统计充分性（`BRIEF.md:7` `E3.md:78`）。
- 【已知事实】E3 的机制结论：A 侧被延长的 S1 PTW 响应传导到已在等待的 V read，A 等自己的 PTW 完成时占住共享控制状态，V 的命中在其后等待（`E3.md:35`）。
- 【已知事实】该共享控制器细节：AR FIFO 头只在 `ar_ready` 前进；只有 IDLE 才 select；AWAIT_RESP 保持当前请求；COMPLETE 要等输出地址被接收（`E3.md:43`）。
- 【已知事实】观测语义：`e41/e73` 记的是**翻译响应**，`e43/e75` 才是数据返回（`E3.md:44`）；观测到 `e70−e41=9`、`e42−e41=2`、`e73−e71=4` 的规律（`E3.md:52-54`）。
- 【已知事实】接口现状：配置/失效必须在全 quiet 下原子完成，软件 mutex 串行，`clear_o` 为同周期组合脉冲（`SPEC.md:41`）；扩展 ABI 走独立 ioctl 0x11 与 128×u64 bank（`SPEC.md:6-7,42-44`）。
- 【已知事实】当前设计**明确不改**缓存 tag/命中/权限/规范失效，也**不是**新安全隔离（`SPEC.md:4`）。
- 【已知事实/文献线索】MASK(ASPLOS2018) 已联合翻译缓存分配、页表流量与调度；HPCA2017 加速器地址翻译已有 hit-under-miss；UCP、KPart 已有“容量/背景带宽/前台延迟反转”；rIOMMU(ASPLOS2015) 已用 I/O ring/buffer 信息；BypassD(ASPLOS2024)、ShareMMU(NVIDIA,2026-09)、Bermuda Triangle(arXiv2508.19670) 已分别覆盖校验式转换、跨加速器预翻译地址共享、SMMUv2 多方干扰测量（`BRIEF.md:9` `BRIEF.md:11`）。因此**描述符预翻译、跨设备翻译共享、首次发现 IOMMU 干扰都不能算新**。

这五条问题分别沿 **单位 / 时间 / 位置 / 所有权 / 接口边界** 五个正交决策变量展开，保证机制上互不相同。

## 1. 五个机制上不同的研究问题

### 问题 1（单位）：把翻译对象从“页/描述符”改成“设备声明的搬运单元契约”

- **真实需求**：共享翻译的干扰强度，取决于“翻译请求量”与“被搬运数据量”的比值。逐描述符翻译把工作集大小绑在描述符数量上，而不是绑在设备真正要搬的字节上。16 条 IOTLB 面对 4 路逐描述符访问时（`SPEC.md:4` `BRIEF.md:7`），这个比值完全由访存模式决定，与“搬多少”无关。
- **被打破的旧假设**：【假设】翻译单位必须等于地址保护粒度（页或描述符）。当前整个缓存/份额/统计体系都建立在“一条目 = 一页/一次 lookup”上（`SPEC.md:4,5,40`）。
- **最小不同点**：请求携带“本单元覆盖的 IOVA 区间意图”，IOMMU 以**搬运单元**为单位建立一次覆盖契约；命中/份额/驱逐以契约为粒度，而不是以页为粒度。区别不在于“预翻译更多”，而在于**命中与统计的记账单位改变**。
- **最强普通对手**：更大的页（2MB/1GB）或描述符预翻译（`BRIEF.md:11` 已把描述符预翻译列为已知）。若契约覆盖在连续性上和 2MB 页等价，则机制没有增量，只多了一层元数据。
- **反例 / 杀死条件**：若工作集在每个搬运单元内是稀疏/随机的，契约覆盖率会退化到逐页水平，而元数据开销反而上升。**快速否定观察**：单元内覆盖率相对 2MB 页覆盖率的增量是否趋近 0。

### 问题 2（时间）：为翻译引入“有用性窗口 / 过期语义”，由设备进度决定是否值得启动

- **真实需求**：E3 已把“翻译响应时刻”和“数据返回时刻”分开测量（`E3.md:44`），并且出现稳定的 9/2/4 周期结构（`E3.md:52-54`）。这说明“翻译什么时候完成”和“数据什么时候用得上”是两个时间轴；翻译结果存在“完成时已经无意义”的可能。
- **被打破的旧假设**：【假设】每个到达的翻译请求都应当被服务，服务语义与到达顺序绑定。当前共享控制器正是按到达顺序保持请求（`E3.md:43`）。
- **最小不同点**：翻译请求携带设备进度令牌（描述符序号 / 缓冲水位 / credit），IOMMU 据此判定“结果到达时是否还有用”，对**注定过期**的翻译不启动、中途中止或降级。机制的核心不是限速，而是**定义并利用“过期翻译”这一语义**。
- **最强普通对手**：固定优先级 / 自适应限流（`BRIEF.md:9` 明确不算新）。区分点：限流改的是发起速率，过期语义改的是“即使完成也无用”的判定，能丢弃对下游完全无贡献的工作；普通优先级无法表达“永远不该做”。
- **反例 / 杀死条件**：若翻译延迟始终远小于设备容忍窗口，则不存在过期翻译，机制空转。**快速否定观察**：翻译完成时间相对设备容忍窗口中位数的分布，以及“完成即被使用”的比例是否接近 1。
- **重叠澄清**：Q2 与 Q1/Q4 都用到设备侧信息，但 Q2 决定的是 **admission/abort（做不做、续不续）**，Q1 决定的是 **coverage（覆盖多大）**，Q4 决定的是 **retention（留哪条）**，三者是不同决策。

### 问题 3（位置）：把翻译请求的仲裁点从数据事务控制器里搬出来，形成独立“翻译请求面”

- **真实需求**：E3 把干扰至少部分定位到**共置的共享控制状态**：同一个 trans_ctl 的 AR FIFO 头、IDLE/AWAIT/COMPLETE 状态机把翻译与数据事务串在一起（`E3.md:35` `E3.md:43`）。位置问题就是：这种共置是必然的吗？`E3.md:46` 也明确承认不能证明下游各级自始至终 ready——即“共置控制状态”和“下游内存/页表取数”是两种竞争解释。
- **被打破的旧假设**：【假设】翻译请求必须与数据事务共用同一条事务控制路径与仲裁状态。当前实现正是如此（`E3.md:43`）。
- **最小不同点**：翻译-only 请求走独立的 FIFO/仲裁与独立状态机，只在“地址就绪”处与数据事务汇合；**位置本身成为自变量**，用于判定干扰来源。与 hit-under-miss 的区分：hit-under-miss（`BRIEF.md:9` 引 HPCA2017）是“命中可越过未完成 miss 前进”，是策略；Q3 问的是“命中路径与 miss 路径在**物理排队位置**上是否必须共用控制状态”，是结构。
- **最强普通对手**：在**同等缓冲预算**下直接加深/复制现有 AR 队列。
- **反例 / 杀死条件**：若加深缓冲与搬移位置得到同样的干扰规律，则位置不是变量；若搬移位置后干扰完全不变，则干扰来自下游内存/页表取数而非控制状态共置。**快速否定观察**：同负载下 `e73−e71`（V 自身翻译服务，`E3.md:54`）与拥塞排队是否随位置改变。

### 问题 4（所有权）：把“保留/驱逐的权威”部分下放给知道未来的那一方

- **真实需求**：当前保留/驱逐完全由 IOMMU 侧决定（mask 约束 tree-PLRU，`SPEC.md:5`），而“哪些翻译会被再用”的先行信息在设备/驱动侧的描述符环顺序里；PN 在某些工作集比 N 慢（`BRIEF.md:7`）提示保留决策与实际复用并不一致。
- **被打破的旧假设**：【假设】只有 IOMMU 有权决定保留哪条翻译；设备侧信息只能被动当请求。
- **最小不同点**：翻译条目携带设备给出的软寿命/复用提示，驱逐在既有约束（如 mask，`SPEC.md:5`）内优先满足提示；权威归属从“中央替换策略”变为“知情者建议 + 中央执行”。注意：这不是换一个 PLRU 参数，而是**更换保留决策的信息来源与权属**。
- **最强普通对手**：更大的缓存或更精细的替换策略（采样/LRU 增强）。
- **反例 / 杀死条件**：若提示与 recency 高度相关（设备访问近似顺序），则没有独立信息，机制退化。**快速否定观察**：提示相对 recency 的信息增益，以及“被驱逐条目随后被复用”的代价是否显著。
- **新颖性风险**：设备/应用导向的替换提示在 CPU 缓存文献中可能有先例，**新颖性未知**。

### 问题 5（接口边界）：把“逐事务请求/响应”改成“可中止的翻译承诺 / 纪元”

- **真实需求**：当前接口把配置与失效绑定在**全局静默点**上（`SPEC.md:41`），代价是必须等整个系统 quiet 且靠 mutex 串行（`SPEC.md:41`）。这限制了并发，也把“失效”变成低频但昂贵的全局事件。
- **被打破的旧假设**：【假设】翻译是一次性、不可撤回的；撤销只能在静默点发生（`SPEC.md:41`）。
- **最小不同点**：IOMMU 发出带纪元的翻译承诺（覆盖范围 + 撤销接口），设备在收到撤销时在**可界定的边界**停止并报告已完成的原子单位；接口形态从“请求-响应”变为“承诺-撤销”，失效不再需要全局 quiet。
- **最强普通对手**：在现有协议上加更多/更细的静默点。
- **反例 / 杀死条件**：若设备（iDMA/外设）无法暴露可界定的部分完成边界，撤销只能退化为 quiet，机制无差。**快速否定观察**：现有设备在撤销时可界定的最小原子单位与回滚代价，以及 quiet 窗口在总时间中的占比。
- **重叠澄清**：Q5 与 Q4 都涉及“谁承担失效代价”，但 Q4 是**保留决策权属**，Q5 是**协议形态与撤销语义**，机制不同。

## 2. 五问的机制正交性对照

| 问题 | 改变的轴 | 决策变量 | 与已有方案的最强对手 |
|---|---|---|---|
| Q1 | 单位 | 覆盖多大（coverage） | 大页 / 描述符预翻译 |
| Q2 | 时间 | 做不做、续不续（admission/abort） | 限流 / 优先级 |
| Q3 | 位置 | 在哪里排队/仲裁（placement） | 加深/复制 AR 队列 |
| Q4 | 所有权 | 留哪条（retention authority） | 更大缓存 / 更好替换 |
| Q5 | 接口边界 | 协议形态与撤销语义（protocol） | 更多静默点 |

## 3. 建议主 Codex 深入的 2 个

我选 **Q3（位置）** 与 **Q2（时间）**，理由：Q3 直接建立在手头最强的机制证据上（`E3.md:35` `E3.md:43`），且改动可局限在 RTL 内部、不必先改 ABI；Q2 沿最正交的时间轴，能带来一个**定义性贡献**（“过期/有用翻译”），普通限流与优先级无法占位。二者一个空间、一个时间，互不覆盖。

### 3.1 Q3 最小区分实验（提议，未执行）

- **三配置同预算对照**：(a) 现状共置 trans_ctl；(b) 同总缓冲预算但翻译-only 请求走独立 FIFO/仲裁；(c) 单纯加深/复制共置 AR 队列（对手）。
- **负载**：沿用 E3 可复现的 A-miss 触发 V-hit 结构（`E3.md:76` 给出了 A/V 的身份与触发条件），以及 `SPEC.md:47-48` 的 short/探索矩阵作为背景负载。
- **测量**：`e73−e71`（V 自身翻译服务，`E3.md:54`）、A 剩余服务、以及是否重现 9/2/4 结构（`E3.md:52-54`）；同时用 `e41/e43` 分离翻译响应与数据返回（`E3.md:44`）。
- **判定**：若 (c) ≈ (b) 且明显优于 (a)，则位置不是变量；若 (b) ≈ (a)，则干扰来自下游内存而非控制状态共置。
- **文献检索关键词（线索，未核查）**：IOMMU transaction controller arbitration；address translation queue separation；hit-under-miss IOMMU；shared transaction controller head-of-line；SMMU translation buffering；IOMMU interference isolation；decoupled address translation plane。**新颖性未知**；须与 `BRIEF.md:9` 的 HPCA2017 hit-under-miss 明确划界（策略 vs 排队位置）。

### 3.2 Q2 最小区分实验（提议，未执行）

- **两段式**：第一步只测量——以 `e41/e43` 的翻译响应/数据返回分离（`E3.md:44`）为基准，统计“翻译完成时间相对设备容忍窗口”的分布，以及“完成即被使用”的比例；这一步不引入新机制。
- **第二步**：在多 DMA 竞争负载下，对比 (a) 到达顺序服务、(b) 固定优先级、(c) 用过期满丢弃注定无用的翻译。要求 (b) 与 (c) 使用同一信息量上限，避免把“信息更多”误当成机制。
- **判定**：若第一步就显示几乎无过期翻译，机制空转，直接否决；若 (c) 相对 (b) 无独立增益，则退化为已知的调度/限流。
- **文献检索关键词（线索，未核查）**：deadline-aware address translation；translation staleness；useful translation；stale prefetch translation；demand translation deadline；DMA latency tolerance window。**新颖性未知**，且需与“投机预翻译/时限预取”的先有概念划界（见第 4 节）。

### 3.3 备选与被暂缓的

- Q5 是最具“重定义接口”潜力的方向，但依赖设备侧可界定中止语义，风险最高，建议先做“quiet 窗口占比”的可观测性测量再决定。
- Q1 的最强对手（大页/描述符预翻译）很可能直接杀死它；Q4 的设备提示信息增益需要先验证。

## 4. 看似新、实则旧的诱惑方向

**“用 DMA 描述符环 / 驱动提示做投机或预翻译来隐藏翻译延迟。”**

这看起来像是一个新的调度洞见，但：rIOMMU(ASPLOS2015) 已经利用 I/O ring/buffer 信息（`BRIEF.md:11`）；MASK(ASPLOS2018) 已联合翻译缓存分配、页表流量与调度（`BRIEF.md:9`）；HPCA2017 的加速器地址翻译已有 hit-under-miss（`BRIEF.md:9`）。把它包装成“借描述符环预测翻译”不会产生新机制，只会复现已有工作的组合。**不应作为主线。** 若仍想在“单位/时间”上创新，必须落在 Q1/Q2 那种**改记账单位或改过期语义**的层面，而不是“加预翻译”。

## 5. 标准兼容 vs 重新定义接口的取舍（供主 Codex 权衡）

- **【已知事实】当前平台本身就把“扩展接口”当研究载体**：独立 ioctl 0x11、128×u64 bank、静默点配置协议（`SPEC.md:6-7,42-44`）。这说明在不破坏旧 ABI 的前提下做接口扩展是被现有工程接受的。
- **Q3 可做成纯微架构改动**：不触及 ABI、不改缓存 tag/命中/权限（`SPEC.md:4`），与 RISC-V IOMMU 架构可见接口无冲突，标准兼容风险最低。
- **Q2 需要设备→IOMMU 的旁带进度信息**：RISC-V IOMMU 标准接口不直接表达“设备进度令牌”，属于新增语义；可由驱动/设备侧显式传递，但会引入非标准接口。
- **Q5 直接重定义接口形态**：撤销/纪元的语义在标准里不存在，把失效从“全局 quiet”改为“可界定边界”（`SPEC.md:41`）会改动失效模型，标准兼容风险最高，但也最可能带来真正不同的机制。
- **通用权衡**：标准兼容保留可比较性与 Linux 兼容，但把机制限制在当前请求/响应 + 静默点框架内；重定义接口解锁新机制，却失去与 COTS 设备/现成驱动栈的可比性。鉴于 `BRIEF.md:5` 明确允许改变软件接口、DMA 工作单位、翻译粒度、时间、位置、跨设备协议与应用假设，任务本身**不要求**固定在现有 RTL/板卡上；建议按“风险从低到高 = Q3 < Q2 < Q5”推进，先做可证伪的观察，再决定是否改接口。

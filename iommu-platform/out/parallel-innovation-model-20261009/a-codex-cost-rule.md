# §80 A 成本方向：共享记录延续到实际 W 消费

作者：Codex，2026-10-09。仅关键源码阅读、原文核对与纸面推导；没有执行模型、修改 RTL、编译或上板。本任务不调用 DeepSeek。

**结论：最强组织是让一份源数据同时承担有限历史与尚未退休的写数据义务，晚许可者只在完整旧前缀仍驻留时加入。这个组织有明确可实现的合法行为，但同合同的普通共享环／多读者前沿控制能匹配其状态和动作。因此本轮不能把单份存储、按前沿回收、无逐拍掩码或一次加入作为独立算法贡献。剩下的窄问题是：在真实 iDMA/IOMMU 接口下，独立许可与不可撤回写事务的集成，是否出现普通控制没有的能力，或有实质且完整收费的实现成本差异。当前没有闭合这一差异，停止 A 新夹具与 RTL 推进。**

## 1. 实际边界，不能借用不存在的接口

直接核对 `out/shared-read-inflight-join-20261009/shared_pretl_read.sv`：

- 106–113 行的 `repair_pair_authorized` 核双方各自成功的源 READ、完整目标 WRITE 前沿、相同源 PA 与事务属性。相同 CACHE/PROT 等属性**不证明源不会被其他主体写入**；本文另要求应用在整个任务期间保证源不可变。
- 124–125、208–248、588–600 行是**一个全局 skid、一个逻辑上游 R 通道**。共享记录按 V、A 串行交付；任一接收者未交付完都会阻止下一物理 R 捕获。不能从零新增 payload 推出 V 零延迟。
- 133–135、227–228 行使用现有实际 W／承诺 W 前沿，借用最多两个原生私有 FIFO 位置；这些可依法重放的 payload 都属于历史容量 H。
- 357–359 行的 `held_r_q` 保护逻辑 `s_r_o`，不是物理 `m_r_i` 的稳定性证明。物理源在 VALID 且 READY=0 时的保持义务必须独立检查。
- 当前是一对对齐 2 KiB 任务／复位，不能据此声称连续任务、跨 epoch 或任意暂停／退出已实现。

本文提出替换存储组织的纸面方案，**不是**说上述源代码已共享两条原生 DMA 的数据 FIFO。

「credit multicast」普通控制在本文具体定义为：发包前取得每个已登记接收者的容量 credit，发送期间保存固定接收集合，收到各自接受／消费反馈后归还 credit。若用共享池，credit 可以由读前沿与空闲量推得，不必逐记录计数。未授权 A 不可先接收数据；把 A 的预留槽、授权状态及返还路径排除在成本外不合法。上表没有把任一论文未读到的字段冒充其已有实现。

## 3. 最强规则：有限前缀驻留时才加入，数据活到 W 债退休

使用同一共享环存源 payload。记录先用于逻辑 R 交付，之后仍作为已承诺目标 W 的数据来源；不会在 R 接受时复制到两个私有 payload FIFO。

**合同只有一种加入，不任意改变成员：**

1. 一对固定身份的 V/A，源地址、长度和字节布局相同；一个静止任务 epoch；正常不可变源，初版排除读错误、映射撤销和取消。各方目标可不同。已成功源 READ 与目标 WRITE 许可分别独立取得，加入时覆盖完整任务。
2. 在 A 许可前，只登记 V。**不因潜在 A 而额外保留已退休数据，不让 A 的未授权状态占 reader/credit。** 原物理 AR 一经提供／接受，地址、长度、ID、真实 RLAST 保持原合同。
3. A 尚未发起物理源 child AR、逻辑 R 或目标 AW/W；已准备的原始 logical parent 可以存在。当它的全部许可成功，且从任务第 0 拍到已捕获末端的完整前缀仍在共享池内，才一次登记 A。源匹配和不可变性另外成立。若前缀有任何空洞／已丢失，拒绝本合同的加入，采用独立任务／普通 patch；不重新定义 H。
4. A 从池中第 0 拍按序得到自己的逻辑 R；之后读同一物理源流的记录。各逻辑 ID/LAST 分别按原 parent 重建。物理 RLAST 只退休原物理事务，不能冒充两条逻辑任务完成。
5. 已提供且被背压的逻辑 R 或目标 W，所有字段、所指 payload 及 owner 不变。加入只改变尚未承诺的未来交付；不改已承诺 AW 的端点／归属，也不越过原 W 服务顺序。
6. 记录在所有已登记成员的对应 **实际 W 握手**之后才释放；逻辑 R 接受或 WRITE 翻译成功都不释放记录。W 完成后 B 错误／完成义务继续保存，但在本排除重试的合同下无需为等待 B 再保存 W payload。
7. 成员仅在完整任务及其 B 义务退休后离开，期间无取消／任意退出／再加入；新 epoch 在全部旧物理与逻辑义务静止后建立。该限制是协议合同，不是当前 DUT 已实现连续运行的证据。

这条规则把晚加入窗口绑定到**本来就必须留存的 V 写数据**；不另造可无限等待的历史。但窗口可能很早消失，A 可能根本无法加入，不能承诺任意晚加入。

## 4. 完整可实现的普通控制，以及状态比较

定义普通控制 **O-ring**：用 published MRB 的一 producer／多 reader 环，记录按源偏移递增写入；每个 flow 的「最后使用 reader」在实际 W 接受时前进。逻辑 R 前沿仅决定该 flow 是否已被提供过数据；它不会提早释放 payload。A 在完整旧前缀驻留且全部许可完成时激活，随后按相同顺序读；parent 与已接 AW/B 单独保持。该控制是本文完整给出的可实现简单对照，**不是**声称 MRB 论文已经实现这一 IOMMU 协议，也不是要求击败所有可想象的增强算法。

记 `P` 为物理已捕获拍数，`R_f` 为逻辑 R 已接受拍数，`W_f` 为实际 W 已接受拍数，`E_f` 为已承诺 W 端点。全部是本 epoch 的单调绝对索引；只在任务静止后复用，环槽为 `index mod H`。

不变式：`0 ≤ W_f ≤ R_f ≤ P ≤ N`。活动成员集为 `M`，尚存连续区间为 `[L,P)`，`L=min(W_f:f∈M)`；要求 `P-L≤H`。提供 AW 前，其数据范围必须已由本 flow 逻辑取得且真实驻留，已承诺端点与 owner 不随成员变化。新物理 R 只有在有真空槽时捕获；可用单端口串行服务降低端口成本，也可真实增加端口，但两种控制按同一条件收费。

加入谓词为：`A未激活 && R_A=W_A=E_A=0 && A无已提供/已接物理child AR或目标AW && L=0 && P≤H && 独立完整READ/WRITE许可 && 同源/同epoch/不可变`。加入当天先禁止新的物理捕获，用一个固定成员事件激活 A；这样不需假定不同顺序的同时更新免费。之后 `L=min(W_V,W_A)`，所有条件与上述规则相同。对已 held 的逻辑 R 保持原 owner；held 记录因 `W≤R` 无法被回收；物理 held-R 与本池输出各自遵守其稳定性合同。

| 状态／动作 | 提议组织 | 完整 O-ring |
|---|---|---|
| 真实 payload | H 份；R 与 W 共用 | H 份；R 与 W 共用 |
| 物理捕获索引 | P | P |
| 逻辑交付与实际 W 索引 | R_V、R_A、W_V、W_A | 完全相同 |
| 逐记录 R/W 角色掩码 | 单调单 cohort 下不需要 | 同样不需要；MRB 前沿已足够 |
| 晚加入前的 A 保留／credit | 无 | 无 |
| 一次激活／退出状态 | 至少加入／活动标志与静止检查 | 相同 |
| 独立许可、源/epoch、parents、AW/W/B 债 | 必须全部计入 | 相同 |
| held R/W 输出 pin、选择器、存储端口 | 必须按实现计入 | 相同 |
| 加入时逐记录扫描 | 不需要 | 同样不需要 |

`N=256` 时 P 与四个单调前沿各至少 9 位（包括结束值 256）。已有 R/W 前沿可复用的条件是语义、时钟边界与更新事件完全相符；端口、扇出及比较器仍计成本。L 可组合求最小值，不必另加寄存器。连续任务需要真实 epoch 或足够的序号宽度，不可把本静止合同的隐含 epoch 当免费通用能力。

不能把普通控制写成每记录 4 位角色掩码，再宣称省掉 `4H` 位就是创新；O-ring 已明确不给它该开销。也不能用 Intel 任意线程／任意目的地址所需的通用 tag FIFO，强迫同一固定任务、线性目标地址的对照保存等价冗余 tag。

## 5. 手算能力见证与不能成立的收益

取 `N=4,H=3`。源拍 0、1 已捕获，V 已逻辑收到它们；V 的目标 AW `[0,2)` 已接受，但 W 尚未接受：`P=2,R_V=2,W_V=0,E_V=2`。A 还没有任何物理 child AR 或目标 AW/W，但自己的原始 parent 可已准备。原源 AR 是长度 4 的不可撤回事务，仍可能持有第 2 拍 physical VALID。所有 source payload 0、1 因 V 写债仍驻留。

此时 A 独立源 READ／目标 WRITE 全部成功。同源不可变，加入谓词成立。将 A 激活为 `R_A=W_A=0`，保持 V 的 `[0,2)` AW 义务原样。若物理第 2 拍已 VALID，在加入边界把 READY 保持 0，不修改上游该拍；这是合法背压，并非撤销物理事务。

- A 逻辑接受第 0 拍后 `R_A=1`，但 `W_A=0`，第 0 拍仍不能释放。
- V 实际接受第 0 拍 W 后 `W_V=1`；因为 `W_A=0`，第 0 拍仍不能释放。
- A 针对自己已接受的 payload 提供合法目标 AW，并实际接受第 0 拍 W 后 `W_A=1`；只有这时 L 才变为 1，第 0 槽可以重用。
- 第 2、3 拍继续来自原物理 AR；所有背压最终解除时，两任务可完成，各自正确 LAST/B；总物理源读可以为 4，无新历史 payload。这个存在性见证不保证完成时间，也不保证始终满速。

此例区分了「pending-read scoreboard 返回即不再允许登记、私有 W 数据又不能跨 DMA 读取」的控制：后者必须重新抓取 A 的旧前缀。但 **O-ring 在每一步完全匹配**，因此不能把此例作为击败最强普通共享池的证据。

局部 payload 点：现有两条 B3 私有 FIFO 的名义 payload 是 `2×3×8=48 B`，全局 R skid 再有 `8 B`。一份 H=3 池名义 payload 是 `24 B`，但这不是同能力下的总面积结果：

- 若保留原生 FIFO、再加 token/pool，只增加成本；需要实际移除／旁路真实重复存储。
- 单个连续环受 `P-min(W)≤H` 限制；两条私有 FIFO 对不重合或有间隔的存活区间可能容忍不同的游标偏斜。不能删掉这项能力再称同合同节省。
- H 必须包含输出寄存器、私有 W staging、依法可重放的 cache 等全部 payload；存储端口、RRESP/错误与稳定输出字段、父事务和债状态另外收费。
- 一个读端口可串行 R 与 W，可能增加等待；两个端口／多个逻辑 R 返回口的成本不可省略。现单 skid 实现的 V→A 串行仍可能延迟 V。

## 6. 独立创新的明确条件与下一门

因为 Intel 的共享数据／tag 保留和 MRB 的单份 FIFO／reader 前沿已覆盖基本组织，而且上面的完整 O-ring 与本规则的状态、加入和回收动作相同，**本轮不能把共享存储、R/W 游标、有限前缀加入或零额外 payload 单独作为独立创新**。这不是根据「可能有人再加同样模块」否决，而是给出了同合同、同收费、动作逐项一致的具体控制。

如果真实原生 iDMA/IOMMU 的接口约束使 O-ring 必须新增一项实质成本，而一种独立设计能在不减少权限、稳定性、不可撤 AW/W/B 义务、容量或端口能力的条件下消除它；或者新合同允许一项 O-ring 上述明确规则不能合法完成的行为并给出廉价安全实现，**那项具体差异可以成为实现／机制贡献**。当前既无该差异，也无完整面积／时序证据；不能以模块名字或不同领域包装替代它。

仅保留一个待证点：原生 DMA 是否允许通过 payload handle 把逻辑 R 确认与 W-data 来源解耦，且共享记录的访问／债更新成本低于完整的普通 pool 控制。必须先指出明确接口限制和最少新增状态／端口；如果普通控制也能用同接口、同状态，A 独立贡献结束，不进入 RTL。本轮不继续制造 late-job、continuous-job 或新对齐窗口。

附：§79 的 R0 保留 skid 极窄情况（`R_V=1,R_A=0`、skid 空、单 epoch、无 A 旧 child）可从实际 route/游标证明剩值为源第 0 拍。但公平缩到同一 J=1 合同后，普通控制也可把历史索引常量化；不能拿通用 9 位索引当它必需成本。它至多证明现有存储的局部可用性，不能替代上述成本差异。

## 1. 导航摘要（约 320 字）

最值得进一步对照的只有两条：**(A) 用「另一 bank 主 PTW 的叶读即将发出」这一可见进度，做成从 IOMMU 到 iDMA 的有界持有触发线，由**请求方**在发出下一个完成读之前自持若干拍**；它与四类现成办法都不同：不是 MASK 式在共享服务内排队页表优先（决策点在请求方而非被争用队列）、不是短 burst（不改 burst 长度）、不是 R→AW coupler（不涉及写地址与首拍 R）、不新增缓冲/信用/owner 队列。**(B) iDMA 自观测「本次任务首次翻译返回时延」，只对该次任务条件化分块**：与短 burst 差在触发源是本地可观测的翻译留痕，而不是固定长度或全局限速。两条都能在一份小模型对照里做有限次判别。

不值得大改的：重写 `banked_ctl` 的 owner/guard 语义、加全局翻译暂停、改 DDR/NoC 仲裁、动 Linux 与生产 RTL。§11 的四类、C2 的成对预翻译/信用/重放/源先发都已经有前史，任何一张卡如果落地后只剩这些语义，就应如实归入普通基线。

## 2. 候选卡

### 卡 1：跨 bank 负反馈——把「对侧主 PTW 叶读未发」当作完成读的有界自持触发

- **a. 新增决策（例子）**：V（bank0）这一笔 256 拍数据读准备进入完成端口时，若发现 bank1 的主 PTW 正处于 `PT` 状态且它的下一条叶读 AR 还没发，就让 V 的**下一个完成读 offer** 自持最多 `K_defer`（如 32 拍）。PTW 叶读在这 32 拍内发出即双赢；否则照原样放行。例子：V 的 `0x80000000/256拍` 与 A 的 `0x70010/1拍` 竞争时，V 先让 32 拍给 A 的叶读。
- **b. 作用等待链 / 场景**：共享 DDR 的 R 返回与 xbar 主口排队；针对 §8 里「PN V 数据读先于 A 叶 PTE 入 DDR，A 叶 PTE 返回 334 拍 vs P 的 45 拍」这条链（`out/pn-data-path-20261007/trace-evidence.json`，事件时间 2758/2763/2766/3100/3156）。
- **c. 源码 hook**：完成侧多路复用出口 `cva6/corev_apu/riscv-iommu/rtl/transaction_controller/rv_iommu_banked_ctl.sv:418-449`（`axi_mux`，master 侧 ID 高位即 bank 位，见 `:201`、`:511`）。触发信号现成但未引出到该层：`rv_iommu_tl_wrap.sv:771`（`active_o(e3_ptw_active)`）与 `rv_iommu_tl_wrap.sv:114`（`ptw_axi_req_o`）；bank 关系已有等价判据可参考 `rv_iommu_tl_wrap.sv:303-306` 的 `n_window`。
- **d. 最少信号/状态与资源**：每 bank 2 bit（PTW active、PTW AR pending）+ 一个 6 bit 有界延期计数 + 一个 1 bit 公平轮转位。估计（非综合，仅量级）：~40 FF + 少量组合；不新增 buffer、不新增 ID。
- **e. AXI/Wowner/读缓冲安全与可达失败例**：只能延迟「未握手的 offer」，不能撤销已 Valid 的 AR；完成端口当下无 gating，需保证 master 侧 VALID 稳定。可达失败例一：两个 bank 同时命中触发，互相持有到计数耗尽——必须有公平位且上限有限；失败例二：**持有的是 xbar 侧尚未入队的事务**，而 §8 的争用发生在 xbar 已入队之后（模型里 DS 读与完成读走不同 slv、同 mst0，见 `nonblock_actual_dma_system_top.sv:346-360, 384-385, 416`），因此**本卡的延迟必须在 offer 进入 xbar 之前生效**，否则无效。此点需 Codex 核 `axi_xbar` 的入队边界。
- **f. 最近邻 / 最强基线**：MASK（ASPLOS 2018）§5.4 的页表优先；以及现有模型干预 `nonblock_actual_dma_test.cpp:519-525` 的 `ds_priority` 轮转（只改 C++ DDR 返回顺序，不改 RTL）。**注意**：`ds_priority` 已经把结果打成 P=79847 / PN=79484（`out/pn-data-path-20261007/comparison.json`），本卡只是把等效效果搬到 RTL 可实现位置，**不能算独立创新**。
- **g. 潜在增量 / 缺何证据**：潜在增量只有「在请求方**off**er 边界做有界持有，且用**对侧** PTW 状态做触发」，与 MASK 在共享服务内排队不是同一层。当前缺：①`axi_xbar` 的 offer 入队点是否在 `banked_ctl` master 之后；②触发线从 TL 到 banked_ctl 是否存在可用路径；③是否有比 `K=32` 更小的作用窗口（模型里 P 的叶 PTE 只等 45 拍）。
- **h. 小模型判别 / 停止条件**：在同一 `tests/nonblock_actual_dma_test.cpp` 入口，用**模型侧**延迟代替 RTL gating（只动 C++/SV，不动生产），跑 P/PN 各一次，比较 `W_cycles` 与 `DS read latency sum`。停止条件：若 P 的 `W` 也同等下降（PN−P 不缩小），或 A 的 `a_completed` 下降，判为本卡仅等价于已有 DDR 优先，丢弃。

### 卡 2：IOMMU→iDMA 跨 bank 进度线，由请求方自持「下一个完成读」

- **a. 新增决策（例子）**：把卡 1 的触发做成一条**显式跨模块控制线**（"对侧 bank 主 PTW 叶读待发"），iDMA 收到后只延迟自己**下一个**完成的 AR offer 若干拍，而不是由 IOMMU 侧统一持有。
- **b. 作用等待链 / 场景**：同上（§8 共享 R 返回 + xbar 主口排队），但把决策推到**产生 256 拍长突发的请求方**，这正好对应 §9「PN 的退化对 V 供给节奏敏感」这一观察。
- **c. 源码 hook**：请求方入口 `cva6/corev_apu/iDMA/src/idma_backend.sv:612-625`（AR fall-through register，`ar_ready_dp` 是可在不撤销 Valid 的前提下延迟的点）与 `idma_backend.sv:632-659`（W-last 队列，说明「下一个 offer」可独立计数）；IOMMU 侧引出 `rv_iommu_tl_wrap.sv:726/732`（`ptw_r_fire` / `ptw_active`）与 `:375`（`ptw_init`）；顶层接线位置参考 `ariane_peripherals_xilinx.sv:1446-1467`。
- **d. 最少信号/状态**：跨线 1-2 bit + iDMA 侧 5 bit 延期计数 + 1 bit「本次任务已在延期」标记。估计：~15 FF，跨模块 1-2 根线，无新 ID、无新缓冲。
- **e. AXI/Wowner/读缓冲安全与可达失败例**：AR 通道延迟合法（`idma_backend.sv:614-625` 的 fall-through register 本身就有 ready 背压）。可达失败例一：两个 DMA 都被同一条线触发，谁都不发第一拍 → 必须由 IOMMU 侧保证触发在有限时间内撤销（PTW 进 `COMPLETE` 或超时）；失败例二：**该线只覆盖完成读，不覆盖 PTW 自身**，若 A 的 PTW 叶读因别的依赖延迟，线会一直拉住 V，需有界超时。否则会把 §8 的「数据阻塞页表」反转成「页表阻塞数据」。
- **f. 最近邻 / 最强基线**：MASK §5.4（优先级语义相同，位置不同）；`HotNets 2022 Understanding Host Interconnect Congestion`（已记录 IOTLB miss 拉长 DMA 延迟并占信用，主题邻接）；RTCSA 2025 Bermuda Triangle §III/§VI-C（同平台类 IOMMU 干扰实测但未评缓解）。
- **g. 潜在增量 / 缺何证据**：增量候选是「**可见进度线 + 请求方自持**」这一协调接口，而不是新的优先级算法；相对 MASK 的差异是**被保护的是对侧页表读、被约束的是数据读，且约束施加在数据读的源头**。当前缺：①该触发线在任何已综合配置里都不存在（需 Codex 核 top 与 DV 是否有合法路径）；②若只在 DV harness 加线，则**是模型证据，不是可上板机制**；③缺少「用该线后，PN 的 `fast` 计数是否保持 >0」的对照。
- **h. 小模型判别 / 停止条件**：在 system harness 里只加线 + iDMA 侧有界延迟（不动 IOMMU 仲裁），跑 P/PN 各一次。停止条件：若 PN−P 的 `W` 差额不变，或 `fast` 被压到 0（即等价于关 N），判为失败并丢弃，不得改写成「机制有效」。

### 卡 3：翻译留痕触发的条件化分块（provenance-gated burst slicing）

- **a. 新增决策（例子）**：iDMA 自观测「本次任务首个翻译的 AR→首拍 R 时延」；若低于阈值（说明这次翻译被短路径服务过），对该**次任务**后续读分块（例如 2 KiB×2），否则维持整页突发。
- **b. 作用等待链 / 场景**：把长连续读的共享 R/W 占用窗口从 256 拍降到 128 拍；针对 §9 里「gap0 时 PN 比 P 慢 12.85% 且 A 速度低 11.39%」这条退化链。
- **c. 源码 hook**：`cva6/corev_apu/iDMA/src/idma_legalizer.sv:143-145`（`r_page_addr_width`）、`:170-177`（`w_page_addr_width`）、`:201-214`（`c_num_bytes_to_pb` 与 `decouple_rw` 门控）、`:452-469`（flow control）；需要新信号的配置位在 `frontends/register_64bit/idma_reg64_frontend.sv:366-373`（现仅暴露 `deburst` 完全解突，`src/dst_max_llen = '0`）。
- **d. 最少信号/状态**：per-job 12 bit 时延观测 + 1 bit「已判为短路径」+ 1 bit 运行开关；分块本身复用 legalizer 现有页宽逻辑。估计：~20 FF；不改缓冲字节总数；请求总数会按分块因子成比例上升。
- **e. AXI/Wowner/读缓冲安全与可达失败例**：只增 AR 数量、不改总字节、不改 W 路由（`idma_backend.sv:632-649` 的 last 队列仍按 burst 粒度递减）。可达失败例一：分块把 V 的读变成多笔，**增加 TR 端口翻译请求数**，在 §8 已观察到 `tl_accept=514` 同为常数的情况下会直接改变 TL 负载，可能把收益抵消；失败例二：若 A 也因同样的短路径判据被分块，页表读反而被切碎，形成新的优先级反转。
- **f. 最近邻 / 最强基线**：§11 第 2 类「缩短数据 burst」；`idma_reg64_frontend.sv:368-373` 明确「当前前端仅支持完全 de-burst」。**若落地后只剩固定分块，本卡即普通基线**。
- **g. 潜在增量 / 缺何证据**：增量候选只在触发源——用**本地可观测的翻译留痕**代替固定长度或全局限速，使分块与「本次是否真的被短路径服务」挂钩。缺：①留痕阈值是否与 N 是否触发可靠相关（需 P/N/PN 三模式同条件对照，当前 N 同条件仿真缺失，见 §9/§11）；②分块后 V 的完成时间是否改善而非仅改变顺序。
- **h. 小模型判别 / 停止条件**：在 `nonblock_actual_dma_test` 里用现有 `+deburst`/页宽做固定分块对照，另加一个「时延阈值」分支。停止条件：若固定分块与条件分块的 `W` 无差异（说明触发源无信息量），或 P 与 PN 同时变慢，判为本卡退化为短 burst 基线，丢弃。

### 卡 4：固定预算缓冲布局——整页 512 拍缓冲改为两段 + 段间依赖检查点

- **a. 新增决策（例子）**：V/A 各保留 512 拍总容量不变，但只允许在 2 KiB 边界跨段：第一段读返回并开始写目的之后，才准入第二段读，避免「整页读一次性占满返回路径」。
- **b. 作用等待链 / 场景**：共享 DDR 的 R 返回队列与被占用的在途 credit；对应 §8 的「V 数据读 256 拍先入 DDR」。
- **c. 源码 hook**：`cva6/corev_apu/fpga/src/ariane_peripherals_xilinx.sv:1263-1272`（`BUFFER_DEPTH = NonblockMode!=0 && i<2 ? 512 : 3`、`NUM_AX_IN_FLIGHT=8`、`RAW_COUPLING_AVAIL=0`）；分块实现点 `idma_legalizer.sv:143-177`。
- **d. 最少信号/状态**：每通道 1 bit 段号 + 1 个「首段开始写」标记。估计：~6 FF；**总 buffer 字节不变**，但「在途未返回字节」上限减半，需在合法资源台账里写明（`innovation-deeper-20261006.md:63-72` 的 B/K/W/C 口径）。
- **e. AXI/Wowner/读缓冲安全与可达失败例**：AXI4 不要求整个系统只有一笔在途写，但**合并写事务后必须保持地址顺序**（§11 引 Arm 规范）；两段读→写在 `idma_backend.sv:632-649` 的 last 队列下按 burst 逐条登记，天然保序。可达失败例：段间检查点若写成「等第一段 W 的 B」，在 `NO_ERROR_HANDLING` 下 `w_dp_rsp_valid & w_last_burst` 语义不同（`idma_backend.sv:519-534`），可能在错误路径上卡死；必须只用「已被下游接受」而非「已完成」。
- **f. 最近邻 / 最强基线**：§11 第 2 类（短 burst）+ 第 4 类（缓冲/信用）。**若只展示「分批变小突发」，就是普通基线**。
- **g. 潜在增量 / 缺何证据**：增量候选仅是「**在总字节不变的约束下，用段间依赖切换而非减少总容量**」；这与「加缓冲」和「砍 burst」都不同，但仍属已知资源的重新切分，**增量弱**。缺：段间检查点会不会把 V 的完成时间拉长（§9 已显示 gap 变大时相对差距缩小但绝对 W 变长）。
- **h. 小模型判别 / 停止条件**：在 system harness 里对 V/A 分别试「第一段完成即放第二段」与「整页放行」，比较 `W_cycles` 与 `ddr_r_stall`（`comparison.json` 里 P=295/PN=60）。停止条件：若 `W` 不降或 V 绝对时间上升，判为回退，不进入最小 RTL。

### 卡 5（更远替代，只作对照/判别，非机制创新）：数据布局与映射路线

- **a. 新增决策（例子）**：把 A 环的页表与数据挪到不与被 V 长突发共享同一返回路径的地址区间；或让 A 用大页映射减少叶读次数。
- **b. 作用等待链 / 场景**：直接绕开共享 R 返回队形，而不是减轻它；用于回答「§8 的因果假设是否成立」。
- **c. 源码 hook**：本平台**无 RTL hook**；实现在 Linux 页布局与 DT/驱动侧（`nonblock_actual_dma_test.cpp:407-415` 的 A 页表布局是模型侧可改点）。**注意**：`rv_iommu_nonblock_hit.sv:94-99` 明确拒绝 1G/2M 叶，用大页会让 **A 走不到 N 快路径**，因此会同时改变 P/PN 的语义。
- **d. 最少信号/状态**：无；仅模型地址与页表内容。
- **e. 安全/可达失败例**：大页会改变 `leaf_ok` 判定，使 P/PN 失去可比性；这是**混杂**，不能作为机制收益证据。
- **f. 最近邻**：普通页布局/大页优化，无本平台前史需要，也不应包装为机制。
- **g. 潜在增量 / 缺何证据**：**本身不构成创新**。价值仅在于：若布局一改 PN−P 差额消失，则证明第三项瓶颈确实是共享返回路径竞争；若不变，则动摇 §8 因果假设。
- **h. 小模型判别 / 停止条件**：一次即可（A 环换地址区间）。停止条件：结果只作因果判别，无论正负都不进入 RTL 路线。

## 3. 优先级表

| 卡 | 工程跨度 | 预期作用范围 | 建议 |
|---|---|---|---|
| 卡 1（完成侧有界持有） | 中（要引出 TL→banked 触发线 + 完成口 gating） | 仅共享返回路径争用链；不解决 AW owner | **先做模型判别**（可与 `ds_priority` 同口径对照），不先改 RTL |
| 卡 2（跨模块进度线 + 请求方自持） | 中高（跨模块新接口 + 有界超时） | 同上，但把约束推到源头；可覆盖 AW/W 依赖更少 | **先做模型判别**；若只在 DV harness 可行，则明确标注为模型证据 |
| 卡 3（留痕条件分块） | 中（legalizer + frontend 配置 + iDMA 侧观测） | TR 端口请求数、共享 R 占用 | 先做**固定分块 vs 条件分块**对照；若触发源无信息量即丢弃 |
| 卡 4（固定预算两段缓冲） | 低中（仅改配置/段标记） | 在途未返回字节上限 | **普通基线**；不建议单独立题，可作卡 1/2/3 的对照 |
| 卡 5（布局/大页） | 低（软件/模型） | 绕开问题 | 只用于**因果判别**，不作为机制 |

不建议：改 `banked_ctl` owner/guard 语义、加全局翻译暂停/失效锁、改 DDR/xbar 仲裁、动 Linux 与生产 RTL。

## 4. 同工作量/同资源下的最低验收

**必须同时给出，缺一即不接受该卡的“有效”结论：**

1. **数据正确性与进度**：V/A 各 64 完成，`v_completed == 64`、`a_completed == 64`，V miss = 0，全部字节逐字通过（`nonblock_actual_dma_test.cpp:1769-1785`），`check_quiet` 通过（`:1120-1156`）。
2. **V 时间**：以现有窗口定义报 `W_cycles`（50 MHz，`(open,close]`，`:793-798`），并同时报 `win_open_cycle`/`win_close_cycle`。**不得**用「W 减去 gap」充当独立服务延迟（§9）。
3. **A 速度**：报 `a_completed × 50e6 / W_cycles`；对 A8 同页数对照。
4. **N 确实仍触发**：报 `fast` 与 `fast_bank*`（`comparison.json` 中 P 为 0、PN 为 62/14）。**若机制的作用是让 `fast→0`，必须如实写成“关闭 N”，不能写成“修复退化”。** 建议同时报 `tl_accept`、`iotlb_lookup`、`iotlb_hit`。
5. **避免“只关 N 消退退化”**：
   - 优先做**配对对照**（同次运行、同 BIT/启动、同工作量、同资源），而非跨 BIT/跨启动比对（§3 已说明 n=3 与混杂）。
   - 必须给出 **P 的 V 时间与 A 速度**；只有当 `PN−P` 的相对差在 `W` 和 A 速度上同时收窄，才允许申报“本卡有效”；仅 PN 改善而 P 也同等改善，判为普通基线。
   - 不给 N 同条件仿真时，**不得写“PN 已与 N 持平”**。

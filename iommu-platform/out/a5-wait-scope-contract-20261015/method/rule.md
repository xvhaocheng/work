# A5：按消费者与完成域判定等待范围

本轮root实质设计。只处理固定映射、串行publisher、有序累计完成ID、有限buffer且访问范围可知的端点；不是通用最优调度器。具体任务/两案输入见[冻结合同](../case-contract.json)。原方法W/L/S/N与A4 O-T1/O-G继承，不重新运行旧验证。

## 1. 一项明确、可检验的贡献候选

**从真实地址路径、端点完成语义和owner，提取能检查的等待范围证书，事前判断某个消费者放行动作使用现有普通控制是否足够。** 该证书应列明必需的完成域、待完成但可暂不等待的义务、下一次复用guard与最终排空；只知道远端读完时不得跨过尚未完成的本地写。

若在未见端点/任务上能复用摘要并准确给出有用部署判断，可以支持接口抽取/部署方法贡献。若每例仍需手工填写全部边，且标准同信息建模同样容易完成，就不能把本版当独立分析贡献。当前只是有原件支持的一个手工实例，没有接受自动抽取、新求解器或论文主贡献。

## 2. 输入、规则与输出

输入为：源码中的任务和数据访问、映射/context、地址路由、接口承诺与完成摘要、四槽owner、实际或明确条件化的已接受前缀、当前可见信息、计划后续动作、最终consumer/释放目标。服务范围与开销另输入；没有就保留UNKNOWN。

使用相对接受rank，避免直接对可能回绕的原始32位ID取max。设已接受job为0..a−1；完成计数f表示0..f−1按序退休。由consumer读写数据的生产者与barrier依赖得到必需集合D，h=max(D)。公开wait-ID只证明该前缀完成，错误成功与可见性须独立成立。

```text
判断一次consumer放行：
  缺稳定映射、成功/可见性或完成语义摘要：返回 UNKNOWN(具体缺项)
  把任务访问映射到端点各地址腿及其真正完成事件
  D = 当前consumer需要的生产者完成rank + 既有barrier前提
  h = 必需前缀的最后rank
  f <= h：返回 WAIT(尚缺输入完成事件)
  E = 已接受且未退休、但不属于必需前缀的job
  检查当前访问及下一guard之前的所有访问：
    与E存在RAW/WAR/WAW冲突且未被合法guard支配：返回 NEED_GUARD(job,slot,事件)
  若owner仍保留到E完成，后续发布/全部末尾排空与host全生命周期保留：
    返回 PUBLIC_PREFIX_SUFFICIENT(仅限这一放行动作)
  否则返回 UNKNOWN(缺失的owner或尾部证明)
```

barrier不是一个免费的ID：源码barrier与编译器/硬件顺序必须核实，费用另计。保守公开输出B可以作Y槽回收guard；不能把内部“已读完旧Y”反馈免费给程序。对一般循环O-G，当前计算放行后可以先发下一RX，但下一RY覆写旧Y前仍要wait旧输出ID。最后tile没有这次覆写，O-T1只需一个RY ID。

条件证明：f>h加有序成功/可见前提覆盖所有必需数据生产者；E与当前/下一guard前动作无未保护冲突，故不改变仍活跃数据；之后访问由guard和末尾排空保护，所有映射/owner保留至安全释放。它是**动作的源级安全证书**，不是该动作更快、硬件已正常工作或全部晚策略不能达标的证明。

## 3. 应用到具体AXPY

每kernel 64tiles，RX0/RY0后逐轮预取下一RX/RY，计算barrier后发当前WY。最后输入RX63/RY63的相对rank为188/189，旧WY62为190。K63访问L1 X/Y bank1；WY62还读取bank0并写不相交的host y[62]。原四槽保留，K63后仅剩WY63与全排空，无下一预取。

因此D={188,189}、h=189。f=190时普通wait(RY63)足以通过输入门槛，即便WY62未退休；f=189时即使RY63远端R已结束，也不够，程序必须等其本地写完成。两案都不允许在旧输出/最后输出、host消费及撤销完成前释放资源。

这里有一个范围明确的不可替代性命题：**在本源/API摘要允许的执行集合内，仅有远端R_done事实，不能推出本地B_retired及K63就绪。** N给出该依赖模型中的反模型。因此，若某个“输入可用”通知仅以远端R或更早的翻译返回为依据，要对该摘要内所有执行安全，就必须增加足以证明本地完成的信息/服务保证，或继续等待现有本地完成回执。本例已有公开ID前缀提供后者，不需要新通知接口。这个量词只覆盖该摘要与这个放行动作；它不是实际全部RTL状态的不可区分证明，也不是任何入口优先策略都无法改善完整时间的结论。错误的R-only通知是用于检验信息缺失的普通构造，不是MASK/DWS或AXI前作主张的机制。

## 4. 控制位置不等于沿路径越早越好

| 动作 | 当前可用控制 | 不能由该位置免费做到的事 |
| --- | --- | --- |
| 确认L1输入可读、放行计算 | 源固件的原生完成前缀＋barrier；O-T1即可表达 | IOMMU外侧读返回单独不能证明本地写B；更早翻译完成也不能替代该事件 |
| 改变RX/RY与输出的发布顺序 | 源端在调用/首次offer前排序或节流；当前WY须先有计算结果 | 已接受descriptor不能撤回；已拉起的队头VALID不能换成另一请求 |
| 对真实同存的翻译/载荷head优先 | 普通入口/适用DS-first；有可部署资源时可比较MASK/DWS式能力 | 不可选择隐藏job，不免费增walker/缓冲，不任意R/B重排 |
| 达到完整消费者期限 | 具名完整策略＋真实服务与全部费用给出上界 | 本例没有期限或服务界，不能宣布入口优先足够或必须前移 |

入口若有足够合法选择、真实服务和完整目标证书，可以足够；本例未取得这些证据。源端排序动作在接受后无效，但**consumer放行动作仍可能有效**。若要证明一处“已经太晚”，量词必须覆盖那个位置全部允许策略和同一完整目标；仅比较O0/O-T1不能给出这种结论。

## 5. 完整完成怎样继续推导

各job拆开源调用、FE offer、FIFO接受/返回ID、各地址腿AR/R/AW/W/B及consumer边。按真实服务器和容量给服务节点界，保留已经承诺的请求与合法流水。源级DAG只给先后，不给周期。

最后计算到达时间由必需输入/合法guard/barrier决定；新WY的首次offer还依赖计算结束。旧/新输出B、末wait-all/fence/barrier决定DEVICE_DONE；随后CPU cache acquire、独立consume决定结果可消费，再由实际撤销/失效完成/unpin/free决定资源归还。两次cold/hot均要完成，映射setup一次、最终cleanup一次，恢复/供给/cache/consume各两次。

完整时间区间由所有上述节点组合；候选完整上界U1与普通方案下界L0有 `U1<L0` 才能事前保证该对照的严格改善。若声称某位置的全策略必要性，还需相应策略集合下界。当前真实服务、CPU/cache/CQ/锁槽费用和并发重叠损失未知，时间、收益及期限判断全部UNKNOWN。serialize=0和同ID有序B不允许把新job全部服务强制串行到旧B之后。

## 6. 本轮检查的精确边界

冻结合同后，新写的最小依赖检查只实例化两次真实程序结构共384个job及必要host释放边，核两切面是该手工DAG的下闭集、检查输入门槛与访问冲突。同信息标准DAG得到同样决定。R_all/W_all/B是整job的聚合事实，不是一个AXI burst；没有周期、任意返回重排、容量求解、payload执行或真实DMA。

没有重新运行A1四案八次或A3八项。两切面不等于已经取得一正一反两时间留出，也不证明默认AXPY自然出现这些切面。精确RTL/跨目的同ID路由、实际外侧同存、错误/可见性与时间仍未验。不能声称两切面全部IOMMU可见信号相同或全部晚控制无法判断。

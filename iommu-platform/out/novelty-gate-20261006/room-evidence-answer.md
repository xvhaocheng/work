## 0. 简短可导航结论

1. **有空间，但很窄，且不在"新机制"上。** 现有 172 条里有一个**尚未写进任何文档、可纯 CSV 复算**的量：P×N 的 2×2 交互项 `I = W_PN − W_P − W_N + W_S`。它在 (A8, V gap=0) 上约 **+15%**，而单独 P 几乎为零、单独 N 为 −3.9%；A 只有 1 页（无翻译未命中）时该交互项塌到 **+0.1%~0.3%**（自带零对照）。同 block 三重复一致到 0.1%~0.5%。
2. **但已知量必须去重。** platform-feasibility 报的 (A8, gap=0)"W +16% / r_A −14%"**不是两项独立证据**：该条件下四模式 `a_completed_jobs_window` 恒为 4096 = `transfers`（60/60 个 gap=0 且 a_pages≥1 的行都如此），r_A 的 −14% 只是 W 的 +16% 的代数倒数。
3. **计数相等 ≠ 时序相等。** 可排除的只有**事件计数层面**的替代解释（V 自身未命中变多 / IOTLB 失效变多 / 快速路径是额外工作）；"容量 / 服务 / 供给"三条腿在现有计数器上**不可分离**。
4. **现象类别已被前作覆盖。** DWS 明示 walker 份额按比例决定 TLB 条目份额、静态划分反而更差、MASK+DWS 合跑无显著额外收益；MASK 用未命中率驱动填充令牌＋旁路缓存；Bermuda 给出"干扰≈对小负载最重的固定税"；SP-IMPact 明确"两种缓解叠加会产生复合或冲突效应、穷举扫描不现实"。**本交互本身不构成新机制。**
5. **下一项最低成本判别只有一件：读源码判定 `v_window_cycles` / `a_completed_jobs_window` 的语义**（尤其后者是否被 `transfers` 截断或由 V 侧派生）。这是所有 A 侧结论的前提，且 60/72 的精确分裂是强提示。其次是**一个独立 boot** 复测 6 个 cell——旧 172 条无法提供独立性。
6. **结论：保留 B1 为候选与下一判别对象，不认定创新成立，不进入控制器/RTL。**

**(a) "两项证据"实为一项。** gap=0 且 `a_pages≥1` 的全部 60 行（`metrics.csv:3-5,7-9,11-13,15-17` short；`:18-29` noise；`:34-45,82-93,130-141` explore）中 `a_completed_jobs_window` **恰等于** `transfers`（16 或 4096）；而 `v_gap_cycles>0` 且 `a_pages≥1` 的 72 行**无一等于** `transfers`（如 `:39` 4096 vs `:54` 4840、`:86` 4096 vs `:104` 8191、`:73` 4096 vs `:118` 18368）。60/72 的精确分裂说明 `a_completed_jobs_window` 很可能不是自由运行的 A 吞吐计数（可能是批次上限、被 V 侧结构派生，或窗口边界与 A 环长对齐）。**未识别。**

**(b) 模式之间的计数恒等式未被任何文档写出。** 全部 explore 行满足 `raw_v_lookup + raw_v_fast == 4 × transfers == 16384`（`:39` 8484+7900；`:41` 10240+6144；`:55` 16384+0；`:61` 15189+1195；`:123` 15964+420）。即**快速路径是同一批 16384 次 V 翻译事件的改道，不是额外工作**。同时 `raw_v_fill == raw_v_miss`、`raw_a_fill ∈ {raw_a_miss−1, raw_a_miss}` —— 两列冗余，不能当第二个信号。

**(c) 失效不是因子。** 全部 172 行 `raw_inval_cycles == 0`；`raw_v_miss ≤ 2`（多数为 0）。

**(d) 因果不可识别清单。** ①"PN 让 V 变慢"是通过 A 的翻译未命中（容量）、A 的数据/到达节奏（供给）、还是 V 命中路径时延（服务）——四模式同时改动这三者；②(a8,g4000) 中 A 作业数 18368→12287 的归因（是 A 被拖慢还是窗口变短）；③P 单独在 (A8,gap0) 上"零效应"（+0.04%）是真零还是欠功率；④三 block 非独立，无法给区间；⑤`raw_replace_pscid`（`:41` 值 2、`:125` 值 4，仅 mode N 出现）语义未见文档。

## 2. 对 Bermuda / DWS / MASK / SP-IMPact 全文：最强已知解释与真正未知

**最强已知解释（我给出的、四篇合起来能支撑的解释）**：这是一个**共享翻译容量 ↔ 逐流服务份额 ↔ 各流到达/供给**的联合闭环。改动填充/准入（保护容量）会改变哪一类请求被快速服务，进而改变各流的占用与未命中/填充率，再改变各流彼此施加的干扰；某个流的端到端时间是其"自身服务率变化 + 对方份额变化 + 两者交错方式"的合成，所以**两个各自不太差的机制叠加可以比基线更差，且符号随另一流的空闲结构而变**。

| 属于**已有闭环知识**（不能再主张为缺口） | 原文证据 |
|---|---|
| 控制一方的服务份额会按比例改变其翻译缓存条目份额（walker 份额 ⇒ TLB 条目份额）；静态划分 walker 反而低于基线；MASK+DWS 合跑可能无显著额外收益 | `out/shared-translation-literature-20261006/papers/walk_stealing2021.txt:390-405`、`:857-876`（Fig.9 与 §VII-D） |
| 用未命中率驱动填充令牌（±2% 死区、按 epoch），被拒绝填充者进旁路缓存保局部性；PTE 层命中率低于数据命中率则绕 L2；DRAM 三分队列＋按应用配额 | `.../mask2018.txt:828-870`、`:874-886`、`:894-915` |
| 干扰是对每笔 DMA 的近似固定税（~100ns），小负载受害最大、大负载稀释；缓解方向（per-stream QoS、页着色、预取）由作者列出但**明确未评估** | `.../bermuda2025.txt:570-589`、`:624-627`、`:642-655`、`:663-676` |
| 两种缓解叠加会产生复合或冲突效应；穷举扫描组合配置不现实；现有静态分析工具"漏掉 IOMMU 与中断控制器"；自适应管理留作未来 | `.../spimpact2025.txt:35-36`、`:102-105`、`:1471-1485`、`:1525-1536` |
| 项目内：旧框架 p1..p6 已是"用反馈调节准入"，A gap / 页数入口已在硬件中 | `docs/novelty-gate-20261006.md:13-25`、`docs/platform-feasibility-20261006.md:19,30,33` |

**真正还未知（且这四篇都没给）**：
1. **不扫描就能预测**：给定两个机制与一条请求流的时间结构，改动前能否预测交互项的符号与量级。四篇都是"运行中自适应"（MASK/DWS）或"离线穷举扫描"（SP-IMPact）。
2. **符号翻转的具体条件**：SP-IMPact 只说"可能复合或冲突"，没给判定条件；DWS 说的是"合跑不一定多赚"，没说"合用会更差，且差在什么条件下"。
3. Bermuda 明确把实时/WCET 分析与缓解评估留给未来（`:654-676`）。

**因此**：B1 若要有增量，只能是"**特定条件下符号翻转的可证伪判据+一个预测器**"，而不是"发现组合不叠加"。后者已被覆盖。

## 3. 现有计数器能排除的替代解释（精确 case / 列 / 对比 / 算式，供 Codex 执行）

以下均为**只读**、只需 CSV（`out/paper-council-20261005/metrics.csv`）与源码列定义。

**E1（可排除一支）**——"PN 使 V 自身的翻译事件或未命中变多，所以 V 变慢"：
- 断言：对所有 `phase==explore` 行（`:30-77,78-125,126-173`）`raw_v_lookup + raw_v_fast == 4 × transfers`。
- 断言：对所有 172 行 `raw_v_hit + raw_v_miss == raw_v_lookup`、`raw_v_miss ≤ 2`、`raw_v_fill == raw_v_miss`。
- 断言：对所有 172 行 `raw_inval_cycles == 0`。
- 结论：V 的翻译事件**总量恒定、未命中≈0、失效为 0**；(A8,gap0) 的 +16% W 差异不可能由 V 自身"未命中变多 / 失效变多"解释。**但该排除只在事件计数层面**：没有逐事件时延，所以"V 的命中路径服务变慢"未被排除（用户告诫成立）。
- 同时排除：把 `raw_*_fast` 当作额外工作量（它是恒等式中的改道项）。

**E2（可查的矛盾）**——`a_completed_jobs_window` 的语义：
- 断言：`v_gap_cycles == 0 且 a_pages ≥ 1` 的 60 行中 `a_completed_jobs_window == transfers`；
- 断言：`v_gap_cycles > 0 且 a_pages ≥ 1` 的 72 行中 `a_completed_jobs_window != transfers`；
- 观察（手工，待复算）：a_pages=1 时 `a_completed_jobs_window` 在**同一 gap 下跨四模式、跨三 block 完全相同**（gap0=4096，gap1000=8191，gap4000=24571，各 12/12），且 4096=1×4095+1、8191=2×4095+1、24571=6×4095+1（4095=`transfers−1`）。
- 结论：这不像自由运行的 A 吞吐计数；须由源码判定是"批次上限 / 由 V 窗口结构派生 / 真计数"。**在判定前，(A8,gap0) 的 r_A 结论不可作为独立证据。**

**E3（可排除"单 block 偶然"，但不能排除"单 boot 偶然"）**——同 block 内三重复：对 `explore-b{1,2,3}-g0-a8-mpn`（`:39,86,137`）与 `-a8-mp`（`:38,89,136`）等，`raw_a_hit/raw_a_miss` 在 N/P/PN 三模式跨三 block **逐位相同**（13308/3072、11267/5117、9802/6582），而 W 仍有 0.1%~0.6% 波动 → W 波动至少有一部分不来自翻译事件。

# A3：真实消费者的等待范围、所有权及控制位置证书

2026年10月15日。root本轮设计。问题沿用用户确认的A：现有控制能否满足真实消费者目标；不能时，缺的是哪个位置的什么能力以及全部费用。这里给出具体可检查规则，不把通用图、状态搜索、下界逻辑或按ID等待本身当新算法。

## 1. 输入、输出和判断层级

复用A1的K合同，新增必须显式携带的两项：

- **允许的任务实现族M**：同一外部目标可用的CPU、原buffer、普通IOVA/shadow、合法保留/节流/分段及候选实现。设备执行可以是一个具名实现的事实，不能自动变成算子只能由设备完成。若某条“必经DMA”边被一个允许的CPU实现绕过，就不是整个问题的必经边。
- **完成API的范围**：wait-all覆盖哪些已发布任务，wait-ID是否只支持累计完成前缀，何种事件才允许slot复用；分开source调用、接收、DMA完成、cache获取、设备/host consumer及资源释放。

其余输入仍包含真实source/profile、生成依赖、有限owner和容量、每位置观察/动作、共同合法前缀、服务范围与全成本、完整完成向量。所有字段分别标source事实、接受的API语义、拟议适配或未知。

输出不只四个标签，还标**证明层级**：

1. 源/API层：可否取消一个不必要等待、是否有合法并行机会、是否破坏owner。
2. 协议层：上述动作是否受现有offer/accept及完成顺序允许，需什么收据。
3. 完整时间层：`T=(T_A,T_B,T_device_consumer,T_host_consumer,T_release,T_quiet)`，有限服务/费用缺失则null。

“普通控制足够”必须同时写目标。能合法放行最后tile的compute，不等于能保证某个完整deadline；后者需要完整时间证书。

## 2. 从API摘要派生依赖，不能反填获胜轨迹

支持的初始模板有限且具名，不声称解析任意C或任意DMA：

| 模板 | 抽取规则 | 必须核的来源 |
| --- | --- | --- |
| `start(src,dst,len)->id` | 产生有owner的异步搬运义务；仅有调用语句不能推硬件已接受 | library、指令/接口握手、实际配置 |
| `wait_all(engine)` | 返回依赖该调用范围内所有未退休job；若还有其他发布者，范围与发布屏障须另核 | busy定义、publisher集合及调用顺序 |
| `wait(id)` | 依公共API展开其完成闭包；若是累计completed-ID，包含所有更早ID，不能随机选择独立完成 | API、ID顺序/回绕、完成RTL |
| `barrier(cores)` | 只连接参加的核；除非源码另给DMA保证，不产生DMA排空边 | barrier实现及接线 |
| `compute(slot)` | 等所有真实输入已可见，取得读/写owner；结束后只释放实际不再被用的访问 | 实际load/store/compute代码 |
| `reuse(slot)` | 新写必须晚于旧读者或设备义务的可观察安全释放；缺read-done收据时用现有完整job完成 | slot别名、最后访问、公开收据 |
| `host_consume/free` | DMA结束后还要cache/上下文/应用consumer与释放；不能从DEVICE_DONE自动删去 | runtime/driver/consumer/lifecycle |

此轮source绑定由人工定向核原件，摘要可重复应用；**尚未做可复用自动抽取器，也未证明节省了手工建模工作。** 这是当前论文证据缺口，不用新JSON字段掩盖。

## 3. 规则W：按消费者缩小等待范围，先检查owner回边

给定某控制点的已发布未完成集合O、下一真实consumer C和其输入生产者集合R(C)，先用公开完成API求闭包`Q=CompleteClosure(R(C))`。只有Q全部完成且cache/owner条件满足时，C才可释放。

对`E=O\Q`中的每个job检查：

1. 它访问的slot不与C访问冲突；只读共享按真实规则判断。
2. 在其公开安全完成前，后继publisher不会重写它仍持有的slot。需检查consumer之后产生的prefetch，不能只看C自己的输入。
3. 最终host consumer、排空和free仍等待该job，并保留原有ID/owner。
4. API/编译器/硬件可见性成立；原生ID反馈不是免费内部翻译反馈。

四项均有依据时，可把C前的wait-all换成Q完成等待，得到**一个现有软件接口上的合法放行方案**；元数据、额外poll/fence/供给及并发竞争全部付费。若Q真小于O，只证明出现结构机会；实际窗口和完整净收益仍需时间/服务证据。若任一项失败，补具体reuse guard或返回UNKNOWN，不能径直宣称新硬件必要。

这是本轮对真实AXPY最有用的规则：最后tile没有后继prefetch，旧Y-bank仍被上一输出读取，下一compute使用另一bank，因而能提出有界普通方案；中间tile则还有回写旧bank的后继prefetch，单改wait不安全。

## 4. 规则L：对晚位置的所有允许策略给出有效下界

限定同一完整目标G、实现族M、真实服务环境E和位置c的可实现策略族Π。时间必要性不能来自两个策略的赛跑。

对每个实现m，构造**所有允许策略都必须满足**的约束：

- 由真实消费者目标产生的必需工作与生成边；可被另一允许实现删去的工作不当成全局必需。
- 各owner已承诺且该位置不能撤回/绕行的先后义务。
- 消费者等待、buffer复用和完整释放必须保留的边。
- 有来源的服务下界及共同ready之前后的完整前缀费用。

给定这些差分约束，可用标准最长路/LP得到乐观下界ℓ(m,c)。只对所有策略共同成立的资源串行边计入下界；可调度的次序不任意固定。允许在该下界松弛中删除未承诺竞争、给予完美信息或无限非必需资源，因为它只会让完成更快；这些放宽**不能用于可部署方案或收益估计**。未知费用可以不强化下界，但仍使真实时间/可行方案上界为UNKNOWN，不能说实际费用为0。

若`∀π∀e:T(m,c,π,e)≥ℓ(m,c)`，则对所列全部实现取`L_c=min_m ℓ(m,c)`，得到`L_c≤inf_(m,π) sup_e T`。若只检查了M的一部分，只能给已检查实现的结论，不能对完整M用该min。

一项已计费更早方案的完整最坏上界U及固定期限D满足：

`U_earlier ≤ D < L_c`

且其他任务/公平性/资源/释放目标全部通过，才足以称**该合同下晚位置不能保证、较早方案可以**。这是标准上下界证明逻辑，候选领域增量在于可复用的must边抽取和不同部署决定，不在这条不等式。

### 前缀和量词的两个陷阱

- 若下界从某次执行中选的prefix开始，只能证明**到达该prefix之后**晚控制过迟。要说从共同任务就绪起所有晚策略都失败，还需证明这个prefix对它们不可避免，或者覆盖所有可能prefix。不能把失败基线的旧债务强加给其他合法节流策略。
- 上述是所有环境下的点态下界，通常较弱。若改用对抗环境加强，必须证明`∀π∃e`，不能给每个隐藏状态选一个事后动作再拼成在线策略。更早策略仍遵守同观察历史同动作。

## 5. 规则S：普通足够需要完整见证，不需要击败一切程序

给一个具名、在线可实现、相同信息及资源的普通程序π，其所有允许环境下完成向量不超过事前目标，资源/错误/释放合同也满足，就可推荐普通方案。只需有这一个可行见证；不必证明它全局最优。

若本轮只建立了合法owner/等待见证，就输出`SOURCE_CAPABILITY_SUFFICIENT`及时间null；不输出`DEADLINE_SUFFICIENT`。原buffer writev是三包文件功能的完整见证，不能拿来当AXPY算子结果的见证；后者仍允许CPU计算再交付的实现，需计实际费用。

## 6. 规则N：局部提前为何可能对完整目标无益

分两种强度：

- **局部屏蔽**：C还要等另一个未改变的必需完成Q，所以只提前一个PTE/输入不立即改变C的ready。只对这个cut成立，不推广到整个后续任务。
- **完整无影响证书**：在所有允许环境下，改动离开该cut时的完整相关状态等价，且cut完成时刻不变；后继源PC、数据、owner/credit、缓存/TLB、在途R/W/B和服务状态均包含在等价关系中，后继策略/环境同样耦合。由此才能推出完整完成向量相同。

只有应用DAG相同或wait-all最终都结束，不足以证明完整等价；先来的翻译可能改变TLB替换，提前载荷可能改变另一owner的服务。不能免费删去这些资源冲突边。没有完整等价或实际服务证据时，保留UNKNOWN。

## 7. 真实AXPY上的具体普通版本

精确代码使用四个L1槽X[2]/Y[2]，每槽2048B。core8发DMA；compute核读取当轮X、读取并原地更新当轮Y。公开start返回transaction ID，runtime有`dma_wait(id)`和`dma_wait_all()`；当前AXPY丢弃前者返回值、使用wait-all。

只在最后tile使用以下拟议版本，早先迭代完全维持原排空规则：

```text
penultimate iteration:
    id_x_last := start(X_last, host_X_last)
    id_y_last := start(Y_last, host_Y_last)
    ...原compute/barrier及output_penultimate发布...
last iteration entry on core8:
    dma_wait(id_x_last)
    dma_wait(id_y_last)
    ...所需compiler/hardware ordering，费用保留...
    barrier(all cores)
    ...原compute_last；没有后继prefetch...
    barrier(all cores)
    start(host_Y_last, Y_last)
end:
    ...原末dma_wait_all、fence、barrier、host可见性及释放，全部保留...
```

原四槽不增，保存两个原生返回ID（两个32位量，实际寄存器/栈代价待编译），没有新增反馈接口。ID回绕、累计完成顺序、错误和fence语义要按实际实现验证。实际输入规模32768/64tiles，不把两tile符号窗口冒充新的native工作负载或原生收益样本。

这是**未应用/未编译/未执行**的普通候选。它能在源/API合同上去掉“最后compute必须等上一Y回写”的人为全engine等待；实际ID-ready与Y回写同时pending窗口没有观测，TCDM bank竞争可能延长compute，DDR/cache/供给/host释放全成本未知。该任务仍只有一个DMA publisher，不填补多端点共享竞争的缺口。

## 8. 同信息标准分析比较与研究接受条件

让标准依赖/资源图得到同样的transfer、wait范围、owner、ID完成闭包与目标，标准可达性/差分约束分析应得到相同合法结论及L值。本轮小规模参考只核等待/owner的合法结论，刻意给标准直接建模相同信息并得到相同结果；没有服务参数，不计算或声称验证任何数值L或WCET，也不把一致性包装成A击败标准分析。

剩余可能成立的贡献是：受限API模板可重复抽取这些边并拒绝不合法比较，使工程师事前选出更低成本的有效位置，且对未见任务有可量化适用性/工作量/准确性价值。**当前只有人工source绑定及规则实例，尚未达到这项论文证据要求。** TC2023粗参数不同于该完整输入，但差异只证明新增信息有用；RTAS2026已给FIFO外调度/合法分块/完整任务分析，不能宣称这些构件为新。[已核近邻入口](../../research-novelty-assessment-20261015/analysis-priors.md)

下一关口是：确认最后tile普通版本的原生ID/owner及窗口，或绑定另一个真实多端点任务；有可量化目标/有限服务后再使用规则L/S/N作完整时间判断。不得借当前缺口把普通方案排除、搭任意时延模型或凑四个时间案例。

局限：单一AXPY实例、人工摘要、无native窗口和服务、无多端点原任务、无自动抽取/未见实例效果。方法为Codex root推导，source席提供有界原件核查；未调用外部模型，不构成独立同行评审或论文新意验收。

# IOTLB 失效造成的跨设备干扰

术语：walk＝页表遍历；PSCID＝一阶段地址空间编号；GSCID＝客体二阶段编号；AV/PSCV/GV＝地址/PSCID/GSCID 有效位；CQ＝硬件命令队列；FQ＝延迟刷新队列。

**真实部署。**2026-10-17 06:41:50 UTC 查询固定版本；表内位序为 AV/PSCV/GV。

| Linux 来源 | 普通 host 失效 | 延迟刷新 |
| --- | --- | --- |
| A 主线 `58161ead29e5` | 按地址 `1/1/0`；退回整域仍为 `0/1/0` | generic_pt 支持 FQ，是否启用受 strict 配置等约束 |
| B 开发分支 `d371fb0f95d5` | `0/0/0`，跨所有 host 地址空间 | DMA_FQ 回退 DMA |
| C 本地 `f215540ad19d`；iommu.c SHA256 `62c137d53cfa…`，工作树干净 | 同 B；map 和 unmap 都刷新 | 同 B |

默认每个设备组一个域：独立平台设备通常异域，同组可同域。规范 v1.0.1 §4.1.1 表11规定 GV=0 忽略 GSCID，故异域也挡不住 B/C 的宽失效。A 的逐地址路径超过512条可退回整域，S/NL 等例外及文件行号见[Linux 核查](sources/linux/findings.md)、[规范核查](sources/spec-rtl/findings.md)；不能把本地行为泛化为最新主线。

**干扰大小。**Verilator 仿真采用原版16项 PLRU IOTLB＋[既有必要修复](sources/baseline/manifest.json)，无分区/旁路；真实 CQ/MMIO、两路真实 DMA。A 做64次4KiB COPY，B 做256次，足迹含读写两侧；预热后 B 单独运行零 walk。A 用递减的新 IOVA，Linux rcache 实际可能复用地址。两级设备目录固定 DID10/11；DDR 队首等待16拍、随后每拍8B。28配置各一次，CPU/Linux 本身未运行。

M0 的实际 walk 为0/65（4/8页），均非失效造成；M1 为322/326，均通过驻留条目清除及随后首次 miss 归因。M2 异域、M3 为0/8，失效归因均为0。M2 用 `0/1/0`，M3 用 `1/1/0`。M1 令 B 慢17.6%/14.8%；[归一化图](analysis/B_completion_normalized.png)按足迹分组。

**开销。**每轮刷新为一条 IOTINVAL＋两条 IOFENCE。下列 A 完成时间包含最后 unmap/fence；范围覆盖4/8页。

| --- | ---: | ---: | ---: |
| M0 | 0 / 0 | 0 | 81739–86639 |
| M1、M2同域 | 256 / 512 | 99110 | 194749 |
| M2异域、M3 | 256 / 512 | 136858–136964 | 213675–214261 |
| M4 N=16 | 136 / 272 | 53289 | 145718 |
| M4 N=64 | 130 / 260 | 49221 | 140756 |

细粒度保护 B 时，A 比 M1 慢9.7%–10.0%，自身 walk 仍为128。M4 仅合批 unmap（N按解除映射的4KiB页计），map 仍宽失效；尚未完成 fence 的页不复用。仅 unmap 刷新对照的 B 为193/197 walk，周期218700/219020，说明不能省略 map 侧开销。逐次命令时延、队列占用、双方完整时间及合计、页表字节见[完整 CSV](analysis/results.csv)和[原始数据](runs/)；[复现说明](runner/README.md)保留 IOFENCE 实现边界与首次预检失败，[核对记录](analysis/validation.json)检查全部28组。

**结论：本工作负载中宽失效主导 B 的翻译干扰，容量/替换仍有残余；按域/地址收窄能消除失效造成的 miss，但保护 B 存在 A 的完成时间代价。**

# C2 · 性能讨论 R5：最终决定与发表边界

2026-10-05。已读六席 R4 与 `ROUND5-DECISION-NOTES.md`。本轮只收束审查，未新增来源查询、实现、仿真、构建或板测；以下检查均尚未执行。

**继续性能主线。最终问题是：有限在途、完成驱动的多 DMA 工作中，翻译命中绕过与缓存保护怎样改变实际翻译工作和共享服务等待，进而改变双方进度；怎样据此选择有用的配置？** 当前有值得诊断的反例，没有已经验证的论文创新。现有 E2/E3 局部机制证据、172 条功能验收和 PN/N 条件性性能结果继续成立；它们不能替代新因果链、应用价值或新颖性证据。

## 1. 首选、备选与不做

- **首选执行：H1 首次分歧的真实 IOTLB 小检查。** 它检验“分配隔离后，另一分区的有效 touch 是否改变 victim 和下一逻辑页的 hit/miss”，预测明确、入口现成、成本有限。H1 是最低成本诊断入口，不是预定论文机制。
- **条件性后续/备选：H2 实际等待链。** 按局部结果与信息缺口，检查合法接受、译后地址等待、PTE/数据服务与双方完成之间的具体依赖。H1 不足以解释进度时，H2 仍可保留；不能把“剩余量”直接命名为相位成本或非翻译成本。
- **不做：** 先救 PN、先造 PTW 优先级/释放感知控制器、再写问题卡、大 gap 扫描、重新寻找已知缺失的旧 trace、默认建完整 DDR/iDMA 仿真、转向安全题目。D2 的服务机会保护须有真实 V-miss 需求与实际排队点；D3 的独立相位方法须有相应控制与独立价值，当前均不投入。

当前两页 V 几乎不 miss，保留为保护可能多余的负例；关闭 P 的 N 是必须认真对待的对手。四页 ping-pong 搬运/计算只是 R3 的结构化合成模板，尚无实际应用证据，不能靠增大 V 工作集制造保护需求。

## 2. 下一项交付已经确定：小补丁、实际结果、首处分歧记录

复用 [composition 测试入口](/home/xvhaocheng/work/iommu-platform/tests/test_composition_iotlb.py)、其小顶层和 C++ 驱动。具体以 [C1 R4 验收规格](/home/xvhaocheng/work/iommu-platform/out/performance-council-20261005/round4/C1.md)为准，不再另写一版设计。

测试层启用 `TouchEnable=1`、暴露有效 touch，并增加分区更新 shadow；当前生产 IOTLB 是实际被测对象，shadow 是规则对照，不是已实现的候选 RTL。用正常 fill 接口构造共同槽内容、核验全左初态，不内部 force 状态。四例必须分别给出断言与逐边沿证据：

| 用例 | 固定前提下的验收结果 |
|---|---|
| V0 touch，隔拍后 A fill | 实际共享树 victim 8、对照 victim 2；后继原槽 8 页为 miss/hit。 |
| 同 lookup，但 touch=0 | 本次两边 victim 都为 2；显式门控负例。 |
| touch 与 fill 同拍 | 本次两边均按旧态选 2；不能把边沿后状态倒算进本次选择。 |
| 正例状态的独立反向后继 | 原槽 2 页为 hit/miss；隔离历史并非对所有序列单调有益。 |

结果保存初始槽表、页/归属、touch/fill/mask、树前后态、实际及对照 victim、后继翻译内容与断言。实际 RTL、手算预期和原规则模型应一致。若同一精确前提下后继页两边均 miss，这是规格、测试或实现不一致，不能降格称“弱成功”。首次分歧后不得继续强迫两边使用原执行的槽命中/fill，伪造整轮反事实。

**全过也只证明组件输入下的局部依赖。** 单槽 priming 是合成初始化，`touch_i=1` 是上游已确认事件的接口输入；它没有证明真实 fast 接受生成该前缀、当前 batch 实际出现或板上性能收益。这些边界应写入结果文件，而非只留在讨论中。

## 3. 通过以后怎样增加投入

**下一证据按成本与决策价值选择。** 真实 bank/TL coupled 入口可检查接受与 touch/fill 的关系及等待阶段，但缺真实 iDMA、XBAR/DS 仲裁和 DDR，且默认深度 3、512 需显式选择。不能把其人工有序返回队列当实际内存纪律。若关键未知已是实际出现频度和共享等待，可评估一次最小实物观察，不要求先新建完整自由演化平台仿真。需要新 RTL 观察且最小记录范围明确时才评估观测 BIT；本讨论不自动启动构建或上板。

**升级为方法原型的门槛：** 有可信工作流及明确进度目标，定位一条对该目标有影响的依赖，并发现适当简单基线仍未处理的有界区域。诊断可用于发现基线为何有效，不要求开始诊断前已经证明所有基线失败。实际应用证据至少要交代逻辑搬运/计算依赖、页复用、队列深度与有效工作量；没有 deadline 就不要宣称硬实时保障。

强基线按定位结果选择，而不是无差别实现全表：

- H1：同总容量、同配额的普通分区内替换；不把分区更新门控本身预定为创新。
- 配置/服务：N、合理静态 quota/gap、有限在途、简单 RR/pacing；若已定位 PTW 排队，再比较合适的优先级/aging 与相应已有方法。
- 作业粒度：应用允许的 chunk 调整，保持总字节、映射和合法顺序，按原始任务或有效字节归并计量。
- 所有对手采用相同信息与资源口径；更大 IOTLB、额外 walker/端口单列预算变化，不能称免费对手。

性能主坐标为 `(W_V, r_A=A_c/W_V)`，同时保留完成总量与边界在途。不要求每个点都双赢，但要预先明确目标区域及允许取舍。**V 窗口不变、A 有效完成率改善仍可能有价值；只有相关目标都不改善，才能停止相应性能收益主张。**

## 4. 论文升级与停止对象

[UCP](https://www.eecs.northwestern.edu/~rjoseph/eecs453/papers/quereshi-micro2006.pdf) 已有按应用归属约束替换；[KPart](https://people.csail.mit.edu/sanchez/papers/2018.kpart.hpca.pdf) 已直接覆盖缓存分配、竞争方后端压力与敏感任务延迟交互。MASK、hit-under-miss 和开闭环评价原理的已核边界也继续有效，详见 [R1 文献记录](/home/xvhaocheng/work/iommu-platform/out/performance-council-20261005/round1/C2-literature.md)及 [R2 文献记录](/home/xvhaocheng/work/iommu-platform/out/performance-council-20261005/round2/C2-literature.md)。本次不是穷尽查新；共享 masked PLRU 精确近邻、Page Walk Stealing 全文和实际应用轨迹仍有缺口。

可能贡献只保留两类：① 有迁移能力的表征/预测，能在后来新增条件中提前判断配置排序或有效区域，或以明显更少的观察得到同等有用的设计判断；② 对真实目标有必要、在适当强基线之后仍有成本可解释收益的方法。**普通模型能编码该行为不自动否定论文；只重述规则、换成 IOMMU 对象或拟合已见数据则不够。** 当前 172 条已看过，只能作回溯分析，不能改称未触碰验证集；不以三 block 极差充当普遍效果阈值。

停止必须针对主张：

- 四例不符合精确预测：修正具体初态/规则/实现理解；若该例不成立，停止该局部反例，不能用聚合相关性补证。
- 局部成立却未在有关合法工作中出现，或不影响所声明的进度目标：停止用它归因相应退化，保留已成立的局部事实。
- 普通修正或 N 覆盖了事先界定的有意义条件：停止复杂方法；可以交付工程结论，不自动转成“表征论文”。单点匹配不否定所有条件，也不许反复换目标保票。
- H2 合成单槽模型与真实服务不符：停止它的定量归因；是否还有另一条实际等待链由证据决定。
- 效应只在窗口尾段/在途：先限定效应与适用任务口径。真实边界行为仍是系统行为；只有具体测量、定义或不当外推错误才叫伪差，不据此自动否定时间机制。

## 5. 最终分歧校正

撤回本席 R4“与 A1 首选执行顺序有分歧”的过时表述：**A1 R4 已同意 H1 先做，问题重要性偏向 H2 与先做廉价 H1 并不矛盾。** 仍不接受其“先有真实 batch 自由演化仿真窗口效果，才可观测 BIT”的硬顺序；现有环境不具备完整平台，必要实物观察可能更便宜。第一项组件检查也不能提前写成覆盖了实际 fast 接受路径。

对 D1 的“同总翻译工作量”和 D2/D3 的“同容量干净对照”保留异议：P/PN 固定容量与配额，未固定接受、触碰、服务和完成；相同 miss 总数也未固定页/层次/每次成本。对 D2/D3 的“尾段即伪差”和“V 窗口不变即无性能价值”明确不采纳。A1 已撤回整窗 1:1 锁步推断，最终判断不继续沿用这个标签。

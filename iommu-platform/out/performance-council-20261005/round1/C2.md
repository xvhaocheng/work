# C2 · 第二次讨论 R1：性能问题的独立论文审查

作者：Codex C2。2026-10-05。只读本轮 BRIEF、既有证据边界和定向原始文献；未读其他席本轮 R1，未执行分析程序、实现、构建或板测。

**判断：继续性能主线有依据。首选研究“容量保护与非阻塞服务何时产生负交互，以及怎样预测和缓解”，备选研究“完成驱动的 DMA 供给怎样改变架构策略的比较结论”。现有结果足以提出问题，尚不足以确认原因或论文贡献。** 后者先服务于前者的因果识别，不建议立刻拆成第二篇论文。

## 1. 三个现象分别允许说到哪里

| 已有事实，来源为本轮 BRIEF | 支持的问题 | 目前不支持的结论 |
|---|---|---|
| A8/g0 中 N 比 S 的 V 窗口短约 3.5%–4.1%，PN 比 N 长约 16%；A 同窗完成量均为 4096 | 有了 N 后，固定容量保护是否改变了竞争者的服务需求，抵消甚至超过保护收益？ | 已定位 walker 饱和、互连拥塞，或已经证明 P 与 N 普遍不兼容 |
| PN 可有更多 accepted fast 却更慢 | fast 是已接受的有用服务事件，但它的机会数和净收益是否由其他慢路径共同决定？ | fast 是假命中；更多 fast 必然拖慢；窗内 fast 可反推窗内特定来源 miss |
| PN/A8 增加 gap 后，V 窗口变短，A 同窗完成量和完成率均增加 | 有限供给反馈可能影响服务交织，值得区分负荷、请求历史和相位 | 已证明锁相；扣除 gap 即得服务时间；系统最大开环吞吐已提高 |

共同窗口的 A 完成率是有效结果，不能因为窗口由 V 决定就否定它。论文仍应交代窗口边界在途量、工作序列和另一方目标；whole-round A 的可变尾段不能替代该指标。已有 172 项全部见过，后续重组只作回溯分析，不能称真正未见数据验证。

## 2. 候选 C2-P：容量保护的收益能否穿过共享翻译服务链？

### 问题与贡献候选

有限 IOTLB 中，给一个小热集保留条目，可能把更多翻译工作转移到另一租户及共享服务链。命中绕过能够处理被保护请求，并不保证它的完整 DMA 作业更快。**研究对象是“保护收益—新增共享工作—返回/数据推进”之间的组合边界，而非再证明分区和 hit-under-miss 有用。**

可以保留两种贡献形态，但须靠证据选择：

1. **可迁移的表征或预测方法。** 给出少量、可独立测定的结构参数，预测何时 PN 比 N 好、相近或差，以及退化来自哪一环；不能给每个模式/工作集自由拟合一个成本，也不能拿结果产生的 fast/miss 数当作事先已知输入。
2. **针对该边界的低成本机制。** 若证实容量保护将压力转移到一个具体的共享资源，让保护配置与该资源的工作预算共同选择；或只在该资源出现可识别的阻塞条件时抑制旁路/竞争请求。这里“工作预算”必须落实为可观察事件和可执行规则，不能以新名词包装普通限流。目前不承诺需要自适应控制，更不预选控制算法。

### 竞争解释与可区分预测

| 解释，均未证实 | 能与其他解释区分的预测 | 最小必要证据 |
|---|---|---|
| H1：容量限制增加竞争者真实 walk 工作 | 同一逻辑工作量下，增加的 walk 及等待可解释退化；在诊断模型中固定请求的翻译结果序列后，该部分差异应明显消失 | 分请求/身份的首次翻译结果、walk 开始/完成；边界已有 walk 单列。不能以 4 次 burst 翻译代替 4 次 miss |
| H2：旁路与慢路径在某个返回、发射或数据推进资源上互相拖延 | 固定需求历史的诊断模型中，仅改变争用资源的授权规则，就改变慢路径完成与 V 作业时间；变化不是仅由多/少 miss 解释 | C1 确认实际共享点；一小段能把 fast 接收、walk 完成、翻译响应和对应 DMA 完成关联起来的事件链 |
| H3：观察到的差异主要由闭环释放反馈放大 | 保留逻辑地址与作业依赖、交换“固定释放”和“完成后释放”后，排序或效应幅度显著改变 | 释放、接收、完成的区别，以及 gap 作用点；参见候选 C2-F |

H1 与 H2 可同时成立。钳制翻译结果或固定到达仅是模型中的因果干预，不能伪装成现实硬件可获得的 oracle，亦不能成为部署方案的公平性能基线。新增 event trace 的范围须由 C1 的依赖链决定，不建议先收集所有信号。

### 最贴近的已知重叠

- [MASK，ASPLOS 2018](https://research.ece.cmu.edu/safari/pubs/MASK-address-space-aware-gpu-memory-hierarchy_asplos18.pdf) 已联合处理共享 TLB 与翻译/数据在存储层次的干扰。不能声称首次跨层处理翻译干扰。
- [Page Walk Stealing，HPCA 2021](https://www.csa.iisc.ac.in/~arkapravab/papers/hpca21_DWS.pdf) 的作者原文索引摘要/引言明确把共享 walker 当成多租户瓶颈，并提出软分区与动态借用。**本轮未成功读到其完整设计/消融**，不能断言它已覆盖或遗漏当前 PN 交互。
- [加速器地址翻译，HPCA 2017](https://vast.cs.ucla.edu/sites/default/files/publications/hpca17.pdf) 已有 hit-under-miss。因此当前 N 可作为研究基础与适当基线，不能把 N 本身当新颖性。

这些近邻使“分区 + 非阻塞 + 按身份调度”这个组件清单很弱，却没有单凭组件存在就解决本平台的完整交互问题。当前未确认的差异是：在少量在途 DMA、有限 buffer、完成驱动供给下，是否存在已有机制没有有效预测或处理的组合边界。**对象换成 RISC-V IOMMU 本身不构成差异。** 文献读取范围见本目录 C2-literature.md。

### 必须面对的强而适当的基线

1. **N，加可调静态容量分配。** 包括不保留、当前 2/14 及与目标有关的少量配置。若当前 V 目标本来就由 N 满足，不得人为要求必须保留 P，才能制造新方法价值。
2. **N，加简单供给/在途控制。** 在相同信息与资源下调静态 gap 或 outstanding 上限；需要服务公平时，再加入简单工作守恒 RR/配额。按相同 V 作业目标与 A 完成率比较，而非逐一挑最佳单指标。
3. 若最终方法依赖 miss 压力或多 walker 分配，再引入与 MASK / Page Walk Stealing 思想对应、适配实际资源结构的基线。单 walker 不能机械照搬“给每租户一组 walker”，但也不能因此省略简单公平服务对照。

不要求一种新方法在所有负载上击败所有基线；要求它在声称的条件下，对明确目标有收益，并报告失效区域和代价。**最能击败本候选的简单对手，是经合理调参的 N + 静态 gap / 有限在途：若它在有关配置上实现同等双方进度，复杂联合控制应停止。**

### 最小决定性证据与停止条件

先完成一个具体 PN/N 反例的机制闭合：同工作身份 → 哪条服务需求改变 → 哪个共享资源延长等待 → 哪次作业完成受影响，并有一个只改关键边的干预支持。普通排队解释能完成这一步也有价值，诊断无需先创新。

要继续争取论文，还需至少一个机制预先给出的正/负预测，在以后新增的不同工作集或供给深度条件中成立；并展示容量保护确实有必要的区域，避免只研究“应关闭一个无益 P”。未来证据可用事件模型加有限硬件确认，范围由具体问题决定，不把多平台大矩阵设为开始诊断的门票。

若只是实现特有气泡、已知容量取舍或固定 gap 能充分处理：机制提案降级为工程修复；仍可整理诊断结果，不能自动宣布有表征论文。若模型只是把已测时间重新相加、不能给新条件预测，则预测贡献停止。首阶段成本应为现有证据和依赖链上的问题卡，尚不值得先重编硬件。

## 3. 候选 C2-F：完成驱动供给下，怎样公平比较翻译架构？

### 问题与可能差异

当下一次 DMA 取决于上一次完成，改变翻译结构也改变下一次请求的释放、全局交织和潜在缓存历史。**值得研究的是硬件策略与负载反馈之间的可分辨影响，及这种影响何时足以改变设计选择。** 不能把闭环称为错误负载：真实流水线若这样运行，闭环效果就是系统行为。

[Open Versus Closed: A Cautionary Tale，NSDI 2006](https://static.usenix.org/events/nsdi06/tech/full_papers/schroeder/schroeder_html/index.html) 已证明负载生成方式会显著改变调度评价。因此“开环与闭环不同”“加入 think time 会改变负荷”“设计一个双模式发生器”都不足以发表。

尚可争取的额外内容，是面向翻译/数据耦合的**依赖保留比较方法或可预测的排序变化条件**：用少量描述 DMA 作业依赖、在途深度和页重用的信息，预测哪些结论能跨供给模式迁移、哪些不能。它应优于普通队列模型或忠实的离散事件回放；不能只比一个人为过弱的全 hit 常数模型。

### 最小决定性设计

- 同一逻辑作业序列保留源/目标页、读写与完成依赖。比较实际闭环释放与诊断用预定释放时刻。预定释放先进入独立源队列，记录“计划释放—实际接收”，不把 ready/valid 回压伪装成固定到达。
- 回放时不能把违反作业依赖的并发当性能收益；不现实的放宽只能标为机制实验。若容量/接收限制导致积压，队列长度、等待和丢弃策略必须显式报告。
- 先检验现有 gap 改善是否由平均供给量即可解释。只有相同有效供给下的交织仍有实质差异，才深入相位或依赖链；均值相同不意味着过程等价。
- 具体通过例应为：一种冻结的低参数模型预告某个策略比较在某类依赖/深度下改变，并在未来数据中被证实；同时解释为何普通模型失败。仅重新展示排序随 gap 变化不够。

### 基线、否决与优先级

强简单对手是**保留真实完成依赖、容量与回压的离散事件模型**，加常见开/闭环工作负载生成；成本模型须按可解释请求类别校准。不能假设通用模型天然不会处理缓存反馈，然后以补入该反馈自称新框架。

若普通模型和现有 NSDI 原理已准确解释效果，保留其为 C2-P 的必要评价方法，不单独立项。只有发现具有现实重要性、可推广、简单对手未处理好的预测或诊断缺口，才升为备选论文方向。此方向比 C2-P 更容易退化成方法常识的复述，当前优先级较低。

## 4. 本轮主张

首选 C2-P，先把“为什么 PN 更差”变成能被反驳的机制问题，再按结果选择表征贡献或缓解机制；C2-F 先承担供给反馈的对照设计。保留已有性能成果，不为创造性而跳去安全领域。也不把六席的一致意见、有限原始来源核查或当前反常现象，当作新颖性和可发表性的证明。

## Codex 审定与未采用内容

- 采用 A 的小范围提交控制与 B 的配置测量候选；C 作为工程诊断，不把四个 PLRU 用例重新设成全部选题前置条件。独立“事件账本论文”未采用，日志/字段是工具，需有额外方法与用途才立题。
- 两组草案中有“固定总 miss”“同 miss 条件图”的过强设定。改为固定逻辑工作、输入与公平资源；miss 是结果。相同 miss 总数也不固定事件时序。
- prior 提议“敏感延迟除以后台完成字节”不作为主指标。采用敏感任务耗时—后台有效吞吐的权衡曲线，另记任务释放/提交/积压和测量边界；固定完成量不能代替同吞吐条件。
- 不预设能够测尾延迟：现有窗口计数不提供逐作业分布。新增时戳与足够样本之前，只报告实际可测窗口。
- 大页/缓冲区复用/ring 调整是适用的强对照，不能因为原有固定 ABI 不支持就从科学问题中排除，也不能声称无需实现即可直接跑。
- 原始草案沿用规格旧标题“未上板”或“单 boot 未上板”的措辞不代表当前状态；已有后续172/172功能验收。当前gap是闭环节奏，512拍缓冲不等于descriptor深度。只有给定接口支持的参数才可称直接可用。
- rIOMMU 的 N≥L 和每ring缓存项是容量/正确运行约束，不是一个已经实现的通用可调在途限速器；有效IOVA的使用可乱序。
- “主张失败就转测量论文”不自动成立。测量线仍需相对前作的新解释、有用的设计判断及未见条件验证；日志完整、阴性结果或换平台本身不够。
- 停用 IOMMU 或放宽失效语义可以帮助隔离成本，但不能作为相同保护语义的部署优化；未采用草案里将它们直接混入同条件性能基线的表述。
- 对选题规模的调整不等于承诺普通期刊一定接受。未给发表概率、虚构性能目标或固定截稿期限；两周仅为建议的立题工作安排。

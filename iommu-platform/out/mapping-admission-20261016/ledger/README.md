# 有限条件事件与费用账

这是root冻结合同的可运行算术账。CPU数值单位是**纯说明单位，不是cycle、测量值或可预测耗时**。没有运行Linux、驱动、设备、真实流量或性能模型，没有验证IOMMU/所有权协议。账本只完成同样10次B转发、2次本地UDP消费及最终排空。

运行：`python3 fee_ledger.py`（任意工作目录均可）。只用Python标准库；输入`events.json`，覆盖本目录`result.json`。执行记录保存在结果中。请求模型Sol/medium；实际独立运行模型和强度元数据unknown，不能用请求值冒充实际值。

## 冻结输入与限制

三对齐PMD源区g0/g1/g2，假设三RQ各持一个源区并在每区依次复用同一RX slot；同区下一RX在前一源对象归还之后。g0/g1分别一次B转发、一次PASS本地UDP消费，g2依次八次B转发。三个region_retire最后发生。此布局、分配与路由序列是条件输入，不是Linux v6.12普通order0已经满足PMD布局或真实RSS/FIB轨迹的证据。

READ-key表示“满足规定权限的O2类普通构造”，不是原RFC08/22已支持按方向收窄leaf。原RFC实际为整PMD CACHE|READ|WRITE；直接使用它需要T_RW明确授权B全PMD RW。若T只准READ，需普通read-only适配，并将实现/维护/转换全部成本计入；这里未实现该接口。整H的头尾空间、元数据与空洞也必须处于T授权范围内。PASS本身不会A unmap，也不会更换源区物理generation。region_retire时A源池撤销由源合同决定，处于本B费用账范围之外，事件字段为null；这里不宣称源池最终退役也无A撤销。

所有目标TX均被接受是本条件fixture的结果假设，不是在线决策时免费知道SQ将接受。部分接受或失败路径不在本账内。

每次forward共同CPU项d=2，copy x=3，短map s=4，R=min(x,s)-d=1，持久建立及最终撤销F=3。F在建立时整笔收费，retire中标记已预付的最终B撤销，不再重复收费；这是费用分摊，不能读成撤销已在建立时执行。PASS成本共同保留为2U，不虚构数值。

O0每次短map；O1每次copy；O2每key首次建立；O3只用当前事件、历史a及共同冻结F/R参数，在a+R>=F时建立，否则付便宜临时方案并累计a。用户给出的是一般组织思想，尚未定义一个不同的controller。这里具体的累计超额版本按定义就是普通O3，结果标记`candidate_example_is_O3_alias=true`；没有另跑同一分支并宣称独立候选验证，也不据此判整个候选族被覆盖。只有明确标记的离线下界读取最终r，用min(rR,F)选择。

所有行另保留源大页取得/保留/集成的残余CPU成本G、关联表/IOVA/PTE/同步/内存管理/回调适配的残余CPU成本L和共同UDP成本2U。这些符号只表示未被d/x/s/F/K/h覆盖的CPU工作：F已收B map/revoke费用，L不能再收同一工作。物理内存字节数、保留时间、带宽与完成约束单列为未知，不能和CPU费用混加。K/h/G/L/U为非负未知成本；两个策略的G/L差可正可负。数值小计不是完整净费用，不把未知项设0。

在2R<F<=3R且当前copy为较便宜临时方案时：O3归一化为10d+F+4R，O2为10d+3F，O1为10d+10R。要胜O2，须K+10h+ΔG+ΔL<2F−4R=2；要胜O1，须10h+ΔG+ΔL+ΔK<6R−F=3。只有实际共用相同目标池生命周期，O1/O3的K才可抵消。原生O0如果不需要三RQ、预填大页及其保留成本，就不能把这些源池成本从双方抵消。最终收益、可行性与新意均不由这个账本证明。

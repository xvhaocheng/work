N2 - Hardware-assisted virtualization relies on two-dimensional (2D) nested address translation, trading the costly software traps of Shadow Page Tables for high access-time latency. This overhead is heavily concentrated at the leaf of the page walk: the final host page-table traversal required to resolve the data page. To eliminate this bottleneck, we introduce SagePTE, a hardware-software co-design that bridges the gap between nested and shadow paging by shadowing only the leaf PTEs, directly in-place within the guest page table. We formally verify SagePTE’s isolation guarantees using Alloy and evaluate it on ARM, demonstrating average end-to-end speedups over nested translation of 1.30× with 4 KB pages and 1.22× with Transparent Huge Pages (THP).

4.2 TLB Types
The Memory Management Unit (MMU) in the I8500 core consists of four address Translation Lookaside 
Buffers (TLB). These include ITLB, DTLB, VTLB, and FTLB as described below: 
4.2.1 ITLB and DTLB Overview
The Instruction TLB (ITLB) and Data TLB (DTLB) are both fully associative micro-TLBs. The Instruction 
Fetch Unit (IFU) and Load Store Unit (LSU) use the ITLB and DTLB to perform high-speed Virtual Address 
(VA) to Physical Address (PA) translation for instruction fetch and data accesses, respectively. The MMU 
manages both micro-TLBs in hardware.
The ITLB and DTLB entries support an arbitrary mix of 4KB and 64KB page sizes. The MMU automatically 
segments larger pages into 64KB entries when refilling the ITLB and DTLB. Both micro-TLBs are shared 
among all harts.
Each TLB entry is two-sectored, holding both an even page and its successive odd page, so 8 DTLB 
entries can map 16 x 4K = 64K if they all hold 4K mappings.

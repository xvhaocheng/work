## 3. 首个有限源：保留哪些真实语义

为缩小首个模型，拟选择**一个 namespace、一个 worker、顺序纯 read、无 metadata、count 模式**；这是从源码能力选定的研究子集，不是声称已有该配置的运行记录。count-only语义投影没有wall-clock终止；对真实perf运行，若时间、signal或其他退出先于N，须标为incomplete，不能声称完成同一N任务。每个 owner 有独立的有效任务，先以两个这样的源实例研究共享硬件；它们是拟议模型中的两个独立 owner，不宣称已取得双 SPDK 实机共跑。暂不引入 iperf3，以免同时增加网络协议、socket/receiver 与 NIC 源映射的不确定性。

用符号 `N_i ≥ Q_i ≥ 1` 定义第 i 个 owner 的成功提交预算和初始 task/QD。`N_i ≥ Q_i` 避免在初始化尚未发满时已经设 draining、随后又调用要求非 draining 的 `submit_single_io`。`N_i`、`Q_i` 不设拍脑袋数字；buffer 大小、映射粒度和队列额度也是公开配置。若真实运行能力限制 QD、PRP/SG 或页大小，进入 N 时按实际约束收紧。

保留如下状态和事件：

1. `task=(owner,slot)`；每次成功提交产生新 `generation`。同 slot 的 buffer 在该 task 生命周期内保持身份；generation 防止把旧 CQ/旧 DMA 退休算给新命令。buffer 的实际 IOVA 仍待另席绑定，模型映射记为明示 `mapping_id`。
2. 分配/准备→offer→成功提交→设备/host DMA 阶段→成功或错误 CQ 可见→poll/callback→补发或释放。拒绝提交没有提交额度、在途额度或成功字节；错误 CQ 是终止/失败事实，不能凭 `io_completed` 统计掩盖。
3. 成功提交时增加在途数和总提交数；对应 CQ 的 callback 退休该在途命令，只有成功 CQ 计成功工作。错误路径单列，下述首版直接判失败。未 draining 则同 task/buffer 重提交；达到 `N_i` 后 draining，后续 callback 只释放，不新增工作。
4. 命令顺序由该 worker 的普通生成规则产生。先用顺序 read，避免把随机 LBA 种子或模式隐藏；后续若加入随机/Zipf，所有已经决定的命令、种子/生成规则及可见历史同给 O0。不同动作改变回调顺序时，要按真实规则重新决定命令和 task 的绑定。
5. 源可同时有 QD 个在途 task，不强制整个 owner 单活跃。拟议 adapter 的真实 tag/事务额度不足会形成可计费 backpressure，不能静默减少 QD 又把吞吐损失归咎策略。
6. 模型的 NVMe read payload 是**设备向 host buffer 写入**，并保留命令/CQ阶段和完成依赖。不能把 iDMA 从 host source 读再写 host destination 的 COPY 自动认成同一流量。

首版错误处理可收紧为“提交失败或 CQ 错误则本次任务失败，不进入性能集合”，并保存错误事件。它是明确的 error-free 研究子集，不是复刻所有 `continue_on_error` 行为；将来研究重试时须按原实现的 queued_tasks、重提交和代际补全，不能用成功 completion 假造重试。

有限终点至少满足：两方各提交恰好 `N_i`、各成功完成恰好 `N_i`、无错误/丢失/重复、无在途/held offer、所有 payload/协议事务退休、CQ已被消费、task/buffer 已按 draining 生命周期释放、研究共享通路 quiet。map/pool/setup/free/队列销毁的计费范围必须列明；源码的 `spdk_dma_free` 不证明每次完成都执行 IOMMU unmap，本文不作此假设。

## 4. 模型需要什么新接口

| 接口 | 最小语义 | 必须支付或约束的成本 |
|---|---|---|
| 源 offer / accept | `(owner,task,generation,command,buffer/mapping,len,direction)`；accept 才占有资源；未接受的 offer 内容稳定 | 命令准备、队列/descriptor、host poll/提交处理，有限 QD、tag 与 buffer pool |
| 完成 | generation 对应的一次状态/成功字节；CQ可见在相关 payload 完成之后；CPU callback 有独立可见时刻 | CQ/descriptor 服务、poll 轮询、回调和释放；不能在 TL hit/AXI AR 接受时完成任务 |
| 研究动作 `P_M/PN_M` | 在同研究架构与同预算下，仅改变经安全检查的快 hit 路径许可；普通 TL、资源、隔离配置相同 | probe/cache端口/响应槽、模式配置、quiet等待、clear和warm；`P_M` 获得实现 PN 所增资源可合法利用的公平对照 |
| 候选付费摘要 `Z` | 例如上一完整窗口里“已就绪 DS 请求与 payload 占服务同时存在”的有界累计，以及有效窗口/饱和/过期标志 | 确定观测点、信号可得性、寄存器/计数器位宽、采样读出、计算、存储和控制动作；当前无真实延迟/面积测量 |
| 边界 | source停止新增→全任务 drain→共享 quiet→配置/clear/warm→下一次有限 invocation | 边界期间所有时间/资源；源 task 在 draining 中释放，下一 invocation 的重新分配/映射身份公开 |

`P_M/PN_M` 是待实现的模型动作，只有实际复用现 RTL 时才可核实等于平台 P/PN。若模型另造动态门控、调度或更宽 fast 条件，必须另命名，不能复用旧 P/PN 结果。维持权限、真实 cached leaf、same-ID、held VALID、写归属和容量证书约束；不借模型把原 guard 删掉。拟议 `Z` 不是已完成实现；若其信号在实际边界取不到，或与已有可见信息可互相推导，则对应观测方案失败。

源状态机每次在**该动作自己的**完成和 poll 后计算后继。可复用的是共同命令生成规则、外生服务工作/状态转移规则及初始世界；不可复用另一动作的绝对 submit/CQ 时间。环境服务若受排队和命令时刻影响，也随当前动作演化；不能给两个动作硬塞同一张完成日历。

| M-E：先做事件语义，再按需要加服务 | clockless 源状态机、task generation、QD/pool、提交/成功CQ/callback/补发/drain；以后才连接有限服务器与拟议翻译/存储接口 | 首个工件只需状态和事件检查；服务阶段另需 command/payload/CQ及CPU资源、TL/PTW/cache、P/PN许可、协议容量、持久态和观测费用。全部符号/假设可查，不需要先实现 Linux/NVMe/DDR 控制器 | 首版仅证明投影语义一致和闭环合法；服务模型以后才回答明确架构下的条件效果，不支持真实 SSD 或 RTL周期/面积/频率 |

## 6. 条件状态对：如何让机制可推翻而不手调相位

这部分是未来服务模型的**假设合同**；`state_plus/state_minus/Δ` 当前均为 `null`。本席没有发现或证明真实自然状态对，也没有把“PN有收益”放进服务规则。

定义 `U` 为有限源/设备服务状态机在共同历史后的内部状态；它影响设备服务进度与后续 completion→resubmit。它可以在所有 host DMA 已 drain 后保留，但必须是模型明示的设备内部状态，不能冒充仍未排空的 host 队列。`U` 的真实设备存在性、参数和持续概率均未知。原理模型可声明一个合法服务类研究其后果；真实设备版本必须取得实际材料。

最小 provider 合同是：每条已接受命令进入有界服务队列，按明示资源和调度规则取得有限服务工作；服务阶段完成后才产生后续 payload/CQ需求；其状态按自己的工作/外生事件推进。服务需求可为 `s(command,U)`、状态转移为 `F(U,command,work,event)`，均先冻结规则与允许参数域，再比较动作。若没有参数依据，保持符号域并作条件结论。不能让 provider 查询当前“希望哪个模式获胜”，不能直接指定候选到达应落在PTW哪一拍，也不能在看结果后挑 seed/offset。

拟比较下面一对**可达性条件**：两者来自同一 provider 类、同一程序/映射/QD/pool/预算/已知命令与同一边界规则，O0 的可见历史相同；`U` 由模型历史/明示外生过程生成，不能手工插入目标相位。

- `u+`：源反馈自然产生合格 cached-hit 与另一 owner walk 的重叠；PN 的真实许可和下游推进早于普通路径；该推进落在双方完整完成的关键路径。早 payload 对后续 PTE/其他 owner/尾部的额外延迟小于关键进展，且候选观测/切换/预热费用可由剩余收益覆盖。
- `u−`：同样的普通配置与O0下，源反馈自然使提前 payload 插到关键 PTE/后台关键阶段之前，或未来有用需求在普通路径恢复后才就绪；完整关键路径没有相应提前，新增阻塞/probe/配置/观测代价使 PN 不利。

局部诊断可令 `e = t_P(normal_release) − t_PN(usable_payload_progress)`，令 `d` 为新增早 payload/probe导致的竞争及尾部关键延迟。`e>0` 只表明局部机会；必须在整条有限闭环上验证收益未被 `d`、其他 owner 尾部、配置和观测抵消。`e/d` 是事后解释量，不得作为在线免费输入。若服务资源有并行性或不同关键路径，不能机械用 `e−d` 取代整图完成时间。

首选完整目标是预先固定的双任务 makespan，附两方完成时间与quiet/free时间；若 root 选择前台约束目标，须事前固定后台期限/工作量，不能看结果换评价。设完整损失为 `J(a,U)`，从共同开始到双方相同有效工作成功且释放的共同终点。正负预测分别是 `J(PN_M,u+) < J(P_M,u+)` 和 `J(PN_M,u−) > J(P_M,u−)`；不先填数值。这是待测预测，不能因未得到反号便事后修改 provider、guard、phase或终点。

反号仍不等于 D。下一任务决策只看决策时可见 `O0` 和已付费的 `Z`：

1. **源/语义可达性关**：provider 自身生成该交错；所有 generation、buffer所有权、QD、协议与finite end有效。否则该正反例作废。
2. **O0充分性关**：给全历史/结构的普通可执行规则先尝试识别。如果已足够区分或选出同一最优动作，则不主张新Z的选择增量。不得把合法命令/映射/QD差异藏起来凑相同O0。
3. **跨边界预测关**：上一invocation的Z经过drain/config/clear/warm之后仍预测目标invocation的相关U；否则下一任务反馈版失败。IOTLB驻留被clear后不能当持续量；设备内部状态持续必须单独声明/验证。若模型内置reset将所有相关U清成给定O0下同一个状态，或独立刷新使未来损失在给定O0后与旧Z独立，则旧Z的条件期望选择增量为零，付正成本更不利。这是该模型排除了问题所需状态，不是实机状态无效或整族D失败的证据。当前clockless语义原型根本不含U、服务计时或Z，不能据其reset/枚举结果评价持续性和新意。若独立刷新U后仍声称旧Z有效，直接推翻实现或统计方法。
4. **全费用关**：`min E[J|O0] − E[min E[J|O0,Z]]`只是在指定信息与分布下的决策价值表达，必须再计Z取得、计算、控制、clear/warm和试选额外成本；这些成本若已在J中计入，不重复扣。没有实测分布时仅能给参数条件，不能报平均真实收益。
5. **反事实关**：每个动作重算完整完成→补发及环境排队；固定输入重放只能作为明示的开放输入实验，不得称应用反事实。

如果同一服务类无法生成满足这些条件的状态对，结束该合同的观测选策主张，保留有限源/可达性结果；不是整族D的无价值证明。若只找到不同已知QD/页大小的反号，优先输出普通结构决策边界。

## 7. 给普通控制完整公平机会

O0 不是一个 miss 数。按首次可见时刻包含：源/命令生成规则、已经选择的LBA、task/generation/buffer/mapping、已提交/成功/错误、当前QD与待补发队列、pool/pinning、所有公开页大小/映射/拓扑、已知owner/程序依赖、完整合法的已有host完成历史和计数。软件可取得的时间/计数不能只给候选；读取及存储有成本时双方按同样条件获得。

至少比较以下**具名可实现**控制：

- 固定P与固定PN；依据公开结构/历史的普通源感知规则；相同信息下的普通选策程序。若候选只是从同信息计算同动作，它没有额外信息贡献。
- 合法的 QD 调整、常驻 buffer/pool、预先准备、复用、任务发布与pacing。吞吐/资源/停机/映射/锁页费用全计；不能人为卡成single-active制造新门控价值。
- 真实支持且语义安全的大页/连续池等映射替代；它们改变输入布局时需在同有效任务/总资源预算上比较。现N仅支持4KiB leaf，不得据此禁止普通基线的大页方案，也不假设页可免费合并或原设备已支持某页型。
- 付费试选：允许普通程序用合法pilot或前一完整有限任务试P/PN、估计并选择。pilot的全部完成/资源/清理/状态扰动和目标任务延后都计入；不能把未来目标任务跑两遍取较优结果，或免费复制真实设备隐状态。离线oracle单独只作上界。

候选Z也可交给同信息普通策略比较，以区分传感接口价值与某一决策规则价值。普通程序在同一付费新接口上复现动作，只排除该策略增量，不证明接口已发表或整个架构无价值。现阶段不新增论文新意接受结论。

## 8. 下一最小工件的独立建议

root提出的两个更小工件属于 M-E 的前置工作，不是增加第三种模型路径：

| 工件 | 直接去除什么不确定性 | 当前限制 | 建议 |
|---|---|---|---|
| 离线真实事件准入检查器 | 核源记录的schema、请求代际、提交/错误/CQ phase/重试与实际可证明的drain；标出buffer/IOVA/设备绑定缺项 | 它不会替缺失字段造证据；只用submit/CQ也不能证明每笔payload服务或真实共享IOMMU；本席没有可用真实事件文件输入 | 若另一席已取得可用真实事件段，先对该段做检查更直接；输出事实与缺项，禁止D性能输出 |
| 无计时的有限源语义原型 | 显式执行 `N≥QD`、task generation、accept、成功/错误、callback补发、draining/free和全部尾部；通过不同合法completion次序核closed-loop反馈 | 它只证明语义合同可实现；completion次序是测试输入，不证明自然设备发生、P/PN反号或Z收益 | **按本席现有输入，优先此工件**。不需要等待硬件接口存在，也不需要先造完整service仿真 |

选择理由是信息增量：当前源码已经提供语义，但“投影怎样运行”尚无一个可审查的执行对象；小原型能暴露非法复用、generation别名、QD缩水、停止条件和固定到达反事实等错误。没有实际事件数据时，checker只能再次报告缺材料；若另席取得的数据足以改变这一前提，先checker是合理的输入更新，不是另一方向的默认优先。

建议原型的接受条件：`accepted = succeeded = N_i`、无错误时所有task释放、在途永不超QD、同buffer在旧generation完成前不复用、draining后不新提交；故障输入必须显式失败；同一公开命令规则下不同合法完成次序要重新产生后继，不照抄时间表。只输出事件偏序/状态/守恒检查，**不输出周期、吞吐、P/PN胜负、隐藏状态已存在或论文新意**。测试次序不当作自然样本，成本未知字段留unknown。

本席没有启动实现。root已通知语义原型合同冻结并交独立Sol/medium席实施；其实际代码/验证结果不在本席证据范围，本文不将未收到的结果写成通过。root保留关键语义、接口和证据接受，不需例行加席重审。

## 9. 进/不进的边界与诚实增量

- **进：** 有源支持的、clockless有限完成驱动语义原型；它可验证新研究硬件承载这种源的合法性，为以后的反事实服务模型提供可复用接口。它是研究基础工件，不冒充性能贡献。
- **条件性能模型当前不进：** 待root另行固定service/方向/action/全部成本/O0/候选信号/强基线与留出规格后，再裁决小服务模型。没有真实jointtrace仍可做条件可达性、因果机制和信息充分性分析；必须用“在这些假设下”描述，给参数边界/失败域。若只重述已有决策价值公式或人为定义两个winner态，没有论文增量。
- **暂不进：** 新RTL事务源及一般QD闭环仿真、原生P/PN部署或性能宣称。理由是当前待解信息不需要这些新增实现，且完成/协议/边界接口债务明确；不是因为新硬件尚未原生存在。
- **仍需真实测量：** 所选设备服务态/持续性、O0下真实不可区分性、Z可获得性与全部代价、实际共享结构、状态分布/到达/波动、完整原生效果，以及新硬件的时序/面积/功耗。模型结论不能补写这些值。

有意义的后续贡献可能是：给出源保真的完整闭环条件边界，证明某类现有汇总不足或证明其已充分，并找到代价可控的最小信息接口。是否构成独立新意必须与已核最近工作实质比较，再由root根据原始证据裁决；本设计没有接受新的novelty主张，也没有改D/I/A的全局安排。

## 0. 边界与总判断

BRIEF 明确要求：扩大边界、加深讨论，拒绝“参数/工程包装论文”；IOMMU 不必是主角，性能仍是首要价值来源，安全/正确性为约束；不能把现有 RTL、16 条 TLB、合成两路流量或 Genesys2 容量当选题边界，也不能由此推导真实 GPU/PCIe/CXL 或多节点性能（`BRIEF.md:5`、`BRIEF.md:7`）。已知近邻包括 MASK2018、HPCA2017、UCP/KPart、rIOMMU、BypassD、ShareMMU、SPARTA、ISCA2018 查表调度、MICRO2018 地址翻译合并，以及 vAttention、PagedAttention、strided/gather DMA、编译器融合、N-Dimensional Storage 2021（`BRIEF.md:9`、`BRIEF.md:13`）。因此，任何“新命题”必须说明：它挑战了什么旧假设、旧强基线为何不能直接替代、需要什么不可免费获得的信息、在什么观察下价值被击穿。

我提出三个可被反驳的命题：

| 编号 | 命题 | 挑战假设 | 是否超出 IOMMU | 优先级 |
|---|---|---|---|---|
| P1 | 价值条件化数据搬运：请求在发出前不应默认“值得执行”，应允许延迟承诺与可物化表示 | “请求都值得执行” | IOMMU 边缘，跨 DMA/运行时 | 高 |
| P2 | 地址生成即计算：地址不是先验输入，而是可下推的程序/状态 | “地址已知” | 超出 IOMMU，加速器/编译器 | 中低 |
| P3 | 关键路径有效工作：局部吞吐不是任务进度，I/O/翻译资源应按端到端关键路径分配 | “局部吞吐代表任务进度” | 超出 IOMMU，系统/运行时 | 高 |

下面深入 P1 与 P3；P2 给出较简但完整的构造、下界和强基线。

## 1. 深入命题 P1：价值条件化数据搬运

### 1.1 命题陈述

**命题 P1**：在异构卸载系统中，许多数据搬运请求的消费价值依赖于尚未可知的下游决策；传统“请求一旦发出/接收就执行”的假设不是最优。可行方向不是在事务已接收后丢弃它，而是在总线事务之前延迟承诺，并传输“可物化表示”而非最终数据。核心研究问题是：价值确认信息最早何时可得？不可预知信息如何影响竞争比？在什么条件下该机制被全量搬运、压缩、预取、PagedAttention/vAttention 等强基线击穿？

**来源事实**：BRIEF 已纠正“丢掉已接收总线事务可能破坏协议”（`BRIEF.md:15`）。因此本命题不能以“取消已接收事务”为创新点，必须把价值判断放在事务之前。

**合理推断**：很多加速器负载是“候选—验证”或“预取—消费”结构：候选数据可能被后续过滤、采样、验证或控制流淘汰。传统 DMA/IOMMU 只看到地址和长度，执行所有已提交搬运。

**机制假设**：设备侧保留候选数据，只向消费者传输低维接受位图/物化描述符；消费者确认后再按需物化。IOMMU 只参与物化请求的地址翻译，不承担价值判断。

### 1.2 构造例：候选验证流水线

设设备产生 `k` 个候选块，每块 `B` 字节；带宽 `W`；每候选验证接受概率为 `p`，接受位图在最终内存写事务之前可得。

- **传统全量搬运**：  
  `C_full = k * (B/W + L_t)`  
  其中 `L_t` 是翻译/描述符/发起开销。

- **价值条件化延迟物化**：  
  `C_lazy = k * s + p * k * (B/W + L_t + L_mat) + C_buf`  
  其中 `s` 是位图/描述符写成本，`L_mat` 是物化发起延迟，`C_buf` 是设备缓冲机会成本。

- **收益条件**：  
  `C_lazy < C_full`  
  近似要求：  
  `p < [B/W + L_t - s - C_buf/k] / [B/W + L_t + L_mat]`

因此，当接受率 `p` 很高、物化延迟 `L_mat` 大、设备缓冲稀缺时，延迟物化反而更差。若 `p=1`，额外描述符和缓冲只会增加成本。

**离线下界**：若预先知道接受位图，最优成本至少是 `p*k*(B/W + L_t)`。任何在线机制不可能低于该离线下界。接受位图的信息量约为 `k * H(p)` 比特。这不免费；预测器必须用历史、模型或额外计算来估计，且预测错误会导致多传或重算。

### 1.3 观察信息何时可得

关键窗口是：**验证结果已产生，但最终数据搬运总线事务尚未发出**。  
例如：设备本地完成候选生成和轻量验证；接受位图可通过现有 doorbell/completion 事件传给消费者；消费者再发起按需物化。若验证必须把全部候选搬到主机内存后才能进行，则窗口消失，本机制退化为普通取消/浪费。

### 1.4 不可预知信息不能免费

接受位图、后续控制流、消费者是否真正读取，这些都是未来信息。  
- 若用预测：收益取决于预测精度与 `p` 的分布。  
- 若用重算：省了带宽，但花算力/延迟。  
- 若用缓冲：省了事务，但占设备内存/占用生命周期。  
因此论文必须给出信息论或竞争比下界，而不是只展示一个 `p` 低的甜点。

### 1.5 最小机制

不发明 IOMMU 新硬件。最小机制可以是：

1. 设备侧候选缓冲。
2. 位图/物化描述符通过现有完成事件或 doorbell 传递。
3. 消费者按接受位图发起物化请求。
4. IOMMU 只翻译物化请求地址。

若使用共享虚拟地址，设备缓冲可映射到消费者地址空间，但这不是必须的新硬件；强基线 ShareMMU/ATS/PASID 已覆盖部分能力。

### 1.6 同资源/同语义强基线

必须打掉：

- 全量 DMA，不做价值判断。
- 普通预取/零拷贝。
- 压缩/量化候选后再全量搬运。
- late cancel/epoch/取消 token——若协议允许取消，则本命题需证明“事务前窗口”仍有独立收益。
- PagedAttention/vAttention：按需物化 KV 的软件分页/虚拟连续视图。
- draft model 本地执行或 CPU 端验证。
- 共享虚拟地址 + ATS/PASID + 设备端 MMU。

若这些基线在同资源、同语义、同正确性下已达到收益，P1 不成立。

### 1.7 击穿观察

- 接受率 `p` 超过阈值，延迟物化无收益。
- 物化延迟 `L_mat` 或缓冲机会成本 `C_buf` 过大。
- 验证必须发生在主机可见内存中，无法在总线事务前完成。
- 消费者必须读取全部候选，不能按需物化。
- 协议/一致性要求强制立即发出事务，不能延迟承诺。
- 共享虚拟地址 + 设备端 MMU 已让全量搬运足够便宜。

### 1.8 看似新实则普通的风险

“取消 token”“epoch”“推测执行”“惰性物化”“按需分页”“零拷贝”本身都不新。  
P1 只有满足以下之一才可能新：

- 明确刻画“事务前价值确认窗口”，并证明现有取消/预取无法利用该窗口。
- 给出在线价值条件化搬运的竞争比或信息论下界。
- 证明在何种协议/一致性约束下，延迟承诺不违反已接收事务语义。

否则就是旧机制换名。

### 1.9 跨实现证据如何成立

不能由当前 FPGA 平台推导真实 GPU/PCIe/CXL 性能。跨实现证据应通过主 Codex 查阅原始文献，比较 GPU copy engine、DPU/SmartNIC、CXL 内存池、NVLink/PCIe 上的候选验证/取消/惰性物化机制。可用关键词：speculative execution、lazy materialization、demand paging、DMA cancellation、transaction ordering、ATS/PASID、PagedAttention、vAttention。

## 2. 深入命题 P3：局部吞吐不是任务进度

### 2.1 命题陈述

**命题 P3**：局部吞吐、完成请求数、字节带宽、IOPS 等指标不必然是端到端任务进度的代理。在共享 I/O、翻译、内存队列的系统中，最大化局部吞吐可能延长关键路径完成时间。应定义“关键路径有效工作”指标，并证明在何种可观测信息下，关键路径调度优于吞吐/公平/SRPT 基线；在不可观测时给出竞争比下界。

该命题超出 IOMMU，属于系统/运行时/调度理论。  
来源事实：BRIEF 允许扩大到运行时、系统接口（`BRIEF.md:7`）；同时警告不能把当前串行路径受阻当领域普遍缺陷（`BRIEF.md:5`、`BRIEF.md:15`）。因此下面的构造例是理论反例，不依赖当前平台 bug。

### 2.2 构造例：短请求洪泛与关键长请求

设一个 DMA/翻译资源，服务率归一化为 1。

- 流 A：`n` 个短请求，每个服务时间 `1`，局部吞吐贡献高。
- 流 B：`1` 个长请求，服务时间 `L > 1`，但 B 完成才能解锁下游关键任务。
- 目标：最小化 B 的完成时间，或最小化包含 B 的关键路径 makespan。

调度策略：

- **吞吐优先/SRPT/小请求优先**：先执行 A 的 `n` 个短请求，再执行 B。  
  B 完成时间约为 `n + L`。
- **关键优先**：先执行 B，再执行 A。  
  B 完成时间约为 `L`，关键路径缩短约 `n`。

在 `[0, n]` 区间，吞吐优先的完成请求数/吞吐率更高；但任务进度更差。若只看局部吞吐，会选中错误策略。

更一般地，若 A 的短请求可以持续到达，吞吐优先甚至可能让 B 饥饿。公平调度会给 B 份额，但不一定最小化关键路径。SRPT 在单机平均完成时间上最优，但对关键路径 makespan 不一定最优。

**符号下界**：在未知未来到达、未知服务时间、未知关键性的在线设置下，最小化 makespan 的在线调度没有常数竞争比；若任务 DAG 和关键性静态已知，则静态关键路径优先级已足够，本命题失去新意。因此 P3 的论文价值必须落在“动态可观测性不足”和“局部吞吐指标误导”的形式化上。

### 2.3 观察信息何时可得

- 任务 DAG、依赖、fence、completion 事件可在运行时暴露部分关键路径。
- 现有 IOMMU/DMA 完成事件可标记“某流已完成”，但不直接说明“该流是否在端到端关键路径上”。
- 未来请求到达和服务时间通常不可知。

因此最小机制不是新硬件，而是利用现有 fence/completion/dependency 信息做关键性估计。若系统没有暴露任何依赖信息，则无法免费判断关键性。

### 2.4 不可预知信息不能免费

关键性、未来到达、服务时间都是信息。  
- 若应用运行时能声明依赖图，则关键路径可计算，但需要编程模型/编译器配合。  
- 若只能观察完成事件，则只能事后估计，可能已错过窗口。  
- 若用历史预测，则需给出预测错误下的性能退化上界。

### 2.5 最小机制

不发明硬件：

1. 运行时维护轻量任务/流依赖图。
2. 利用现有 completion/fence 事件更新关键路径。
3. 在 DMA/IOMMU 队列或软件调度器上做“关键性加权”选择。
4. 若关键性不可知，退化为公平/吞吐基线。

### 2.6 同资源/同语义强基线

必须打掉：

- FIFO、公平轮询。
- SRPT、LAS、最大完成数。
- QoS/带宽分区/缓存分区。
- 静态关键路径优先级。
- 预取、work stealing、GPU copy engine 默认调度。
- 单纯给调度器加标签或加队列。

若关键路径静态已知，静态优先级是强基线，P3 不新。新意必须在动态、部分可观测、I/O/翻译资源耦合的设定中。

### 2.7 击穿观察

- 任务 DAG 简单且关键路径静态可知。
- 所有请求价值相同，局部吞吐与端到端进度正相关。
- 优先关键路径导致总吞吐崩溃，且 makespan 无改善。
- 应用无法提供依赖信息，完成事件粒度太粗。
- 关键路径在运行中频繁变化，估计开销超过收益。

### 2.8 看似新实则普通的风险

关键路径调度、DAG 调度、QoS、尾延迟优化都是成熟领域。  
P3 只有做到以下之一才可能新：

- 形式化证明某类局部吞吐指标在 I/O/翻译资源上不是任务进度的单调代理。
- 给出不可观测关键性下的在线竞争比下界。
- 提出新的可观测表征，使关键性可在现有完成/fence 事件上低成本估计，并证明优于 SRPT/公平/QoS。

否则只是把 CPU 调度搬到 IOMMU 队列。

### 2.9 跨实现证据如何成立

理论命题可跨实现成立：只要存在共享 I/O 队列、短请求洪泛和关键长请求，局部吞吐指标就可能误导。跨实现验证需主 Codex 查文献：GPU copy engine、NVMe completion、CXL.mem QoS、RDMA、DPU 队列。不能由当前 Genesys2 平台推导真实 GPU/CXL 性能。

## 3. 命题 P2：地址生成即计算

### 3.1 命题陈述

**命题 P2**：传统 DMA/IOMMU 假设访问地址在发出前已知，或由 CPU 预先准备。对于数据依赖访存、稀疏访存、图遍历、嵌入查找等，地址是计算状态的一部分，可能在设备端才产生。新方向是把地址生成下推为“地址流程序”，由近存或 DMA 引擎执行，而不是搬运完整地址列表。

**来源事实**：BRIEF 已将 strided/gather DMA、编译器融合、N-Dimensional Storage 2021、vAttention/PagedAttention 列为强近邻（`BRIEF.md:13`）。因此 P2 必须打这些基线。

### 3.2 构造例与下界

设 `N` 个地址，每个地址 `b` 字节，地址空间大小 `M`。地址列表成本 `N*b`。若地址生成程序大小 `S`、执行成本 `e`，则省描述符带宽的条件是：

`S + e < N*b`

但若地址近似随机，地址序列熵为 `N*log2(M)`，不可压缩。此时任何“程序化地址”都不比列表省。若地址有结构（步长、哈希、范围、重复），程序化可能省。收益条件窄。

### 3.3 信息时机与不可预知

地址生成在设备端计算中可得；但数据依赖地址（pointer chasing）直到读取数据后才知，无法提前免费获得。编译器可导出部分地址表达式，但动态依赖部分不可预知。

### 3.4 最小机制与强基线

最小机制：编译器/运行时把地址生成表达式下推到 DMA/近存引擎；IOMMU 只翻译最终地址。  
强基线：设备端完整 MMU、ATS/PASID、gather DMA、TMA、编译器融合、N-Dimensional Storage、共享虚拟地址。  
若设备端 MMU + gather 已解决，P2 不新。

### 3.5 击穿观察

地址可预计算；带宽非瓶颈；地址随机熵高；程序开销 `S+e` 超过列表成本；设备端 MMU 已支持数据依赖翻译。

**优先级**：中低。强近邻太多，收益条件窄，容易被视为 gather/TMA/设备 MMU 的重新命名。

## 4. 哪些看似新实则普通

以下不能单独作为创新：

- 软件分页换成硬件分页；零拷贝；普通预取。
- 加 epoch、取消 token、取消队列。
- 给调度器更多标签、更多队列、更多优先级。
- 页表缓存固定分区、Cache 分区、带宽限流。
- gather DMA、strided DMA、TMA、N-Dimensional Storage。
- vAttention/PagedAttention 的简单硬件化。
- 普通关键路径调度、SRPT、QoS、尾延迟优化。
- 普通压缩/量化/KV eviction 换名。
- 仅利用“当前平台某条串行路径命中受阻”推导领域普遍缺陷。

真正可能新的点必须落在：**旧假设失效的条件、信息时机、不可免费信息的下界、强基线无法替代的机制边界**。

## 5. 优先级与需查文献关键词

### 优先级

1. **P1 价值条件化数据搬运：高**。直接挑战“请求都值得执行”，构造例清晰，信息时机可定义，强基线可打。风险是退化为取消 token/惰性物化，需用事务前窗口和下界区分。
2. **P3 关键路径有效工作：高**。可做纯理论发现，跨实现潜力大。风险是关键路径调度近邻多，需新指标或竞争比下界。
3. **P2 地址生成即计算：中低**。强近邻多，收益条件窄。

### 需查文献关键词

- P1：value-conditional I/O, speculative execution, lazy materialization, demand paging, DMA cancellation, transaction ordering, escrow transactions, PagedAttention, vAttention, ATS/PASID, IOFENCE, PCIe no-snoop, completion semantics.
- P3：critical path scheduling, makespan, SRPT, LAS, QoS, progress sharing, tail latency, DAG scheduling, online scheduling competitive ratio, GPU copy engine, NVMe completion, CXL.mem QoS, RDMA scheduling.
- P2：address generation unit, gather DMA, TMA, N-dimensional storage, sparse embedding, pointer chasing, device MMU, shared virtual memory, compiler fusion, near-memory computing, SmartNIC, CXL address translation.
- 理论工具：online scheduling lower bounds, competitive ratio, entropy lower bounds, rate-distortion, information-theoretic lower bounds.

## 6. 给主 Codex 的验证与验收检查

1. **查原始文献**：确认 P1 是否已有“事务前价值条件化搬运”的等同工作；确认 P3 是否已有“局部吞吐不是任务进度”在 I/O 调度上的形式化；确认 P2 是否被 TMA/gather/设备 MMU/ND storage 覆盖。

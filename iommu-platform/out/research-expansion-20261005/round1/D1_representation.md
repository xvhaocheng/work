## 2. Q1：派生携带的数据（Derivation-Carrying Data）——非物化视图的身份、失效与完成语义

### 2.1 这不是什么（先排除被禁的表述）

- **不是"零拷贝"**：零拷贝/页别名（DMA-BUF、CUDA VMM、`mmap` 同一文件、`zeMemGetIpcHandle`【知】）都只能表达**恒等映射的多次暴露**。转置、量化、色域转换**不是**某个物理页的子集，**页粒度别名在原理上表达不了**。这是本问题与"零拷贝"的分界线，而且是可证明的分界线。
- **不是"布局视图"**：一般意义上的"layout view"是**消费者侧的纯本地变换**（读的时候自己重排）。本问题的核心恰恰是：**当视图必须由"另一侧"（mover / cache / 迁移器 / 失效器）理解时，正确性会发生什么变化**。
- **不是"融合"**：融合是编译期把消费者改成读生产者布局，零运行时成本，MLIR/One-Shot Bufferize、XLA、JAX `donate_argnums` 都在做【知】。**融合是本问题的强便宜对手之一**，不是同义词。
- **不是 strideDMA**：不要求引擎支持更多 stride 模式；要求的是**"变换可以在读路径上被表达且其依赖可被失效"**。

### 2.2 真实工作负载

1. **LLM 推理的 KV 与激活多视图**：KV 做 PagedAttention 式分页（BRIEF:13）后，同一份 KV 被多个消费者以不同视角读：attention kernel 读分块 KV、投机解码读同一块的另一版本、前缀缓存读同一块的去重副本、监控/统计读整层的激活直方图。vAttention（BRIEF:13）用 CUDA 虚拟内存 API 保 KV 虚拟连续、物理动态分配【知】——它解决"虚拟连续"，**不解决"同一物理字节的多视图身份与失效"**。
2. **成像/ISP 流水线**：Bayer → RGB → YUV → 多个下游（编码器要 YUV420、检测网络要 RGB、AE/AF 统计要 Bayer 的稀疏格点）。今天要么每一级物化一次，要么把变换写死在某个消费者的数据通路上。
3. **DNN 推理的混合精度副本**：同一权重同时以 fp16（算）和 int8（另一个算子）存在；同一激活同时以 fp32（校验）和 bf16（下发）存在。

**为什么这些负载有"多视图"而非"两次拷贝"**：消费者集合不固定（A/B 路由、早退、推测解码、多任务头），**在编译期不知道要哪几种物化**，运行时再生成第二份/第三份副本的成本是 "2N 搬运 × 副本数"。

### 2.3 当前的不利假设（要被推翻的那个）

**【设/要推翻】现行系统隐含假设：**
> 「任何被消费的字节，必须先在某个地址上以消费者所需的布局存在。因此"布局变化"只有三种处置：在生产者侧物化、在消费者侧本地变换、或让消费者改成读生产者的布局。不存在第四种：**把布局变化登记为一种可被 mover/cache/失效器理解的、带版本的派生关系**。」

具体表现：
- mover 只看到 (src_addr, dst_addr, len)；
- cache 只看到物理行；
- 失效器只看到地址/上下文（RISC-V：按地址/上下文失效、IOFENCE【源 BRIEF:15】）；
- 生命周期只看到 refcount/fence。

**这四者中没有一个能表达"这块字节是那块字节的转置/量化"**。

### 2.4 已知工作边界（不虚构出处）

| 工作 | 与本问题的关系 | 边界 |
|---|---|---|
| **N-Dimensional Storage (2021)**【源 BRIEF:13】 | 把多维文件描述符引入存储，最接近"派生视图由系统理解" | 我的判断：NDS 处理**布局/访问**，但我不认为它把"派生关系的失效与完成语义"当作一等正确性问题——**此项必须由主 Codex 核对原文后再判定，我不做断言** |
| **vAttention (ASPLOS'24)**【源 BRIEF:13】【知】 | 用 CUDA VMM 保持虚拟连续、物理动态 | 只解决虚拟连续性；多视图身份/失效不在其范围 |
| **PagedAttention (SOSP'23)**【源 BRIEF:13】【知】 | 软件分页 KV | 软件分页；多视图一致性不在其范围 |
| **ShareMMU (MICRO 2026)**【源 BRIEF:9】 | 跨不可信加速器共享预翻译地址、权限跟踪、定向反向失效 | **"定向反向失效"与本问题的"派生失效"最近**——但 ShareMMU 反的是**地址/权限**，不是**派生关系**。判定差异需要核对原文 |
| **rIOMMU / BypassD / SPARTA / MASK / PTW 调度 / Neighborhood-Aware AT** | 都在翻译元数据、缓存、调度层面 | 全部假设"被翻译的对象是数据的地址"，不假设"数据是另一份数据的函数" |
| **MLIR bufferization / XLA / JAX donate** | 编译期别名与拷贝消除 | 只在编译期静态、单一地址空间内；本问题的难点是**跨地址空间 + 运行时消费者集合** |
| **DBMS 物化视图 / 增量视图维护** | 语义上最接近 | 我判断其重点是"何时维护/维护什么"，**不是"不物化时读写可见性如何定义"**——需核对 |

### 2.5 强便宜对手（必须在提案首页承认）

1. **一次物化 + 所有消费者读同一份**。D=1 或访问次数少时，必胜。
2. **页粒度别名**（DMA-BUF / CUDA VMM / 多 mmap）。对"页对齐的子集选择"（crop、取偶数行、取某些页）**已经完全够用**——这是一个精确的否定反例，见 §2.9。
3. **编译期融合/重排**。零运行时成本；凡消费者代码可控处，融合都赢。
4. **纯缓存**：给派生视图一块普通 cache，按需填充。**不需要任何新硬件**，且在多消费者重复访问时可能打平甚至更好。
5. **拷贝时变换**（strided copy / 转置拷贝）。转置本来就是标准做法。
6. **全精度 + 少动**：在 DNN 场景，A100/H100 的 Compute Data Compression、AMD DCC【知】已经在用无损/近无损压缩省带宽；**"用精度换带宽"已被工业界占据**。

→ **Q1 的存活条件必须非常窄**：多消费者 × 消费者集合运行时可变 × 变换是逐元素或重排 × 数据大（不能全物化）× 需要部分可见性。若条件不成立，便宜对手直接杀死它。

### 2.6 机制真正改变的信息 / 能力

**【设】新能力：内存系统第一次拥有"派生关系"这一信息维度，并据此在"读路径上生成"而不是"写路径上物化"。**

派生描述符（提案形状，非结论）：
```
derived_id      : 单调 ID
base            : { PA range | base_view_id }        // 允许链式
op              : 封闭集合 { permute(axes) | broadcast(dim) | pad | crop
                            | dtype_convert(src,dst,rounding) | quantize(scale,zp)
                            | channel_permute | tile }
version         : base 的版本 / epoch
coverage        : 本视图覆盖的 base 子范围（用于部分物化与并发）
validity        : dirty bitmap 指针（分块）
cost_hint       : A_est（预估访问放大，见 §2.7）
```

**关键设计约束（这是本问题真正的技术核心）**：
- `op` 必须是**封闭集合**，否则失效推理不可判定。
- `op` 必须**逐元素可判定**：对 base 的任一元素，要能 O(1) 算出它在派生视图中的位置集合（转置 ✓，broadcast 是 1→多，量化是 1→1）。
- `coverage` 必须存在，否则任一 base 写都要失效整个视图 → 失效成本 O(N)。

### 2.7 成本模型与 break-even（核心）

符号（平台值均为【设】，必须实测）：

| 符号 | 含义 | 平台假设值 |
|---|---|---|
| N | 基数据字节数 | 例：4 MiB |
| BW | 有效搬运带宽 | 0.5 GB/s（**必须实测，不可引用**） |
| L | line / 事务粒度 | 64 B |
| e | 元素大小 | 4 B (fp32) |
| D | 消费者数（视图数） | 2–4 |
| k_i | 消费者 i 的访问次数 | ≥1 |
| s_i | 消费者 i 消费的视图比例 | ≤1 |
| A_i | **访问放大因子** = L / (每 line 被有用消费的字节数) | 见下 |
| C_sync | 一次失效 + 同步成本 | 2 µs（**假设，需实测**） |
| C_copy(N) | 一次物化搬运 | 2N/BW |

**A_i 的关键二分（这是本问题最有用的结论）**：

| op 类型 | 例子 | A_i | 说明 |
|---|---|---|---|
| **逐元素** | 量化、dtype 转换、色域、缩放 | **1**（若消费者顺序访问） | 不重排地址 → line 里所有字节都有用 → 视图几乎免费 |
| **重排** | 转置、axes permute、channel permute | **L/e = 16**（若消费者逐列流式）；**1**（若消费者 tile 访问） | **A_i 由消费者代码决定，不由机制决定** |

**Break-even 命题 Q1-a（可被反驳）**：
```
视图方案优于物化方案  ⇔  Σ_i k_i·s_i·(A_i − 1)  <  2·Σ_i s_i·(1 + M_c)
其中 M_c = 元数据 + 失效的相对成本占比
```
- 代入 D=4，每个消费者各访问一次全覆盖（s=1, k=1），**全部是逐元素变换**（A=1）：
  - 视图：4N（每个消费者读 N 一次）
  - 物化：生成 4 份 = 8N（读 N + 写 N）× 4，再消费 4N → **12N**
  - **视图胜 3×** ✓
- 代入 D=4，全部是**转置**且消费者逐列流式（A=16）：
  - 视图：4 × 16N = 64N
  - 物化：12N
  - **视图输 5.3×** ✗ → **这就是否定反例的核心形态**

**Break-even 命题 Q1-b（关于同步，与 Q1-a 独立）**：
```
视图优（仅从同步看）  ⇔  C_sync(N) < C_copy(N) = 2N/BW
代入 C_sync = 2 µs、BW = 0.5 GB/s  →  N* = 1 KB
```
**结论（反直觉但重要）**：只要 N > ~1 KB，**"每个消费者一次失效"就比"一次拷贝"便宜**。所以 **Q1 的障碍不在同步成本，而在 A_view**。这一条把研究重心从"失效机制"推向"访问模式可控性"，而后者在很多负载里**不可控**（消费者的数据通路是固定的）。

**由此得到 Q1 的诚实收窄**：
> Q1 的真实价值可能主要落在 **"消费者是我们自己生成的代码"** 的场景（编译器可见、可保证 tile 访问的 DNN 算子 / GPU kernel / ISP 硬件通路），而不是"任意第三方消费者"。若不能收窄到这个范围，Q1 大概率被"融合 + 一次物化"杀死。

### 2.8 具体小例（含地址 / 布局 / 别名）

**布局定义**
```
基张量 A : shape [1024][1024], fp32, row-major
base_pa   = 0x8000_0000            // 4 MiB，正好 1024 个 4 KiB 页
row_stride = 4096 B
elem(i,j)  = 0x8000_0000 + i*4096 + j*4
D1 = permute(1,0)  (转置视图)
D2 = quantize(scale=0.0039, zp=-128)  → int8, 1 MiB
D3 = select_cols(j ∈ {0,64,128,...})  → 页对齐子集
```

**别名检查：为什么 D3 不能用 Q1 论证，而 D1 必须用**
- **D3 是页对齐子集**：取 j=0,64,128,192,... 若按 4 KiB 行选，等价于"选第 i 行里第 0..1023 列的子集"，每行的子集在内存中不连续，但如果按"取偶数列的整页"这类模式（例如 j 取每行的连续 16 个元素 × 对齐），**可以用把同一物理页映射两次 + 偏移来表达**。
  → **D3 被页别名方案完整覆盖 → Q1 无新增价值。这是第一个精确反例。**
- **D1 不行**：转置后 `elem_D1(j,i)` 的地址是 `j*4096 + i*4`，它在 base 里**不是任何页的子集**（a 页 = A 的连续 1024 个行内元素 = 一行的 1024 列，而 D1 的一个页 = 若干列的 1024 个行内元素各 4 B）。**页粒度别名在原理上表达不了跨行步进的等距列采样。**
- **D2 是逐元素**：`elem_D2(i,j)` 与 `elem_A(i,j)` 同地址序，只差元素宽度。
  → **D2 是 Q1 最有利的情形（A=1）；D1 是最不利的情形（A=16）。**

**失效放大（这是 Q1 原创性最强的量化点）**
- 基侧写一个 64 B line → 覆盖 A[i][j0..j0+15] 共 16 个元素。
- 对应 D1 的元素是 D1[j][i]，j ∈ [j0, j0+15]。它们在 D1 中的地址是 `j*4096 + i*4`：j 相差 1 → 地址相差 4096 B。
  → **基侧 64 B 的写，需要失效派生侧 16 个彼此不相邻的 line。失效放大 = L/e = 16。**
- 若失效粒度是 **line 位图**：16 个 line = 16 bit。若失效粒度是 **元素位图**：需要覆盖 D1 的整列 i（1024 行），即 1024 bit = 128 B。
  - **line 位图**：省流量，但派生侧每次读要多做一次掩码测试（成本从带宽移到执行）。
  - **元素位图**：4 MiB base 全位图 = 512 KB = **12.5% 的数据量**——太大，必须分层/分块（例如 4 KiB 页粒度 + 页内 line 位图）。
  - **这是一个可量化的真实 design tradeoff**：位图粒度 × 位图大小 × 读路径额外开销。
- 注意：**若失效命令是"按地址失效"（RISC-V 已有【源 BRIEF:15】），那么 16 条地址失效命令本身 = 16 × (命令字节数 + 处理开销)**，可能远大于一次 in-place 转置的 64 B 写的成本。**这是 Q1 的一个真实风险，必须计入 M_c。**

**撕裂视图（torn view）——Q1 的核心正确性风险**
- C2 读 D1 的整列 i（逻辑上 1024 个元素）；同时 C1 写 A 的行 i0。
- 结果：D1[\*][i] 的读会得到"i0 之前旧、i0 之后新"的混合。**这违背"矩阵快照"语义。**
- **对比物化方案**：物化方案下，一次拷贝与写并发也会撕裂，但可以用 **一次 fence 把 writer 与 copy 分开**（成本 O(1)）。
- **视图方案下，每个读者都可能与写并发 → 同步成本从 O(1) 变成 O(D)。**

**【设】命题 Q1-c（可被反驳）**：
> 派生视图把"一次 fence + D 次拷贝"换成"D 次失效/同步 + 0 次拷贝"。  
> 净收益要求 `C_sync < C_copy`（见 Q1-b，N>1 KB 时成立），  
> **但代价是"一致快照"语义的丢失**：视图只能提供**逐元素顺序一致（element-wise coherence）**，不能提供**快照一致（snapshot consistency）**。需要快照的消费者必须退回双缓冲（成本回到 2N）。

这条命题如果成立，它本身就是一个可发表级的负结果 + 一个明确的设计空间划分。

### 2.9 正确性要求

1. **派生描述符本身必须可信**：若 op/coverage 可被不可信组件伪造 → 越界读或错误别名。必须由可信侧（内核/编译期/受信 IPA）构造。
2. **逐元素一致性（最低要求）**：对任一元素 x ∈ base，若 x 的写 W 在 fence F 之前完成，则 F 之后发起的派生读必须返回 W 之后的 x 的值，或**可检测地**返回旧值。
3. **不可撕裂的元素**：单个元素（≤ e 字节）的派生读不得看到半新半旧。
4. **失效的传递性**：链式派生（D1 派生自 D2 派生自 A）必须保证 A 的写传播到所有下游，且**不得无限增长失效风暴**；需定义最大派生深度或强制在该深度物化。
5. **失效的原子性边界必须显式声明**：跨多个 base 行的派生读，**不能**承诺快照一致（见 §2.8 撕裂视图）。
6. **变换的幂等与精度**：`quantize` 必须是确定性、无状态、无浮点环境依赖的；若涉及浮点舍入，必须固定舍入模式（否则同一份数据在不同加载路径上得到不同字节 → 破坏"派生等价"的可检验性）。
7. **别名一致性**：若同一物理页同时以 base 和 derived 两种身份被暴露，必须保证二者的内存属性（cacheable/attribute）**不冲突**。RISC-V 对"同一物理地址不同内存属性"的行为我不做断言——**【未】需核对规范**。

### 2.10 足以否定 Q1 的反例（列全）

- **R1**：变换是"页对齐子集选择"（D3 型）→ 页别名方案已完整覆盖，Q1 无新增价值。
- **R2**：单消费者 + 单次访问 + 大尺寸 + 转置访问且消费者不可改（硬件通路逐列流式）→ A=16，视图输 5–16×，物化拷贝必胜。
- **R3**：消费者需要**快照一致**（例如做一次全局归约）→ 必须双缓冲，成本回到 2N，Q1 的收益归零。
- **R4**：基侧写是细粒度、高频的（例如 32 B 粒度的原子更新）→ 失效放大 = 16/次，失效流量超过数据流量，视图净输。
- **R5**：编译期融合可行（消费者代码可控、布局可静态确定）→ 融合零运行时成本，视图方案多付元数据与失效。
- **R6**：变换很便宜但数据很小（N < 1 KB）→ 视图与物化都在噪声里，没有工程意义。

### 2.11 平台可验证性（严格限定）

**可做**（不推真实 GPU/PCIe/CXL 性能）：
- 基数据放 DDR，用 4×iDMA 模拟 D 个消费者；用 iDMA 的二维描述符表达"tiled 访问"与"逐列访问"两种模式，测**有效带宽**（有用字节/时间）与总线上实际事务数 → 直接验证 A_view 二分。
- 用 IOMMU 的按地址失效路径测**一次失效 + 同步**的实际延迟 → 验证 C_sync，进而验证 N\* ≈ 1 KB。
- **必须写清楚**：这是**用 2D DMA 模拟视图语义**，不是实现了派生视图硬件。任何把它写成"实验通过"的说法都是错的。

**不可做**：任何声称能代表真实 GPU/PCIe/CXL/多节点性能的结论（BRIEF:5 明确禁止）。

### 2.12 新颖性状态

**【未】**：我不能断言 Q1 是空白。必须核对：(a) NDS 原文是否已处理失效语义；(b) ShareMMU 的"定向反向失效"对象是地址还是派生关系；(c) DBMS 物化视图一致性理论中有没有"非物化读的可见性定义"；(d) 是否有工作定义过"view-consistent memory model"。**在核对之前，Q1 只是一个"有明确可反驳命题 + 有可执行判定实验"的方向。**

## 3. Q2：元数据的按需生成与「元数据放大预算」

### 3.1 这不是什么

**不是 strideDMA**：不要求引擎支持更多 stride 模式；问的是**描述本身是否可以被推导出来，以及推导失败时怎么办**。

### 3.2 真实工作负载 / 不利假设 / 边界 / 便宜对手（紧凑）

- **负载**：gather map、KV block table、多级页表、稀疏矩阵 indices、AF_XDP UMEM 帧表。
- **不利假设**：**"描述符必须先物化为内存中的数组，然后被引擎读取。"**
- **已知边界**：【源 BRIEF:9】MASK2018（联合翻译缓存/流量/调度）、SPARTA2020（内存侧翻译、按虚拟地址定位内存分区）、ISCA2018 PTW 调度、MICRO2018 Neighborhood-Aware AT、rIOMMU（ring-aware 平坦页表 + 隐式失效）、DX100 §3.6（stream/indirect 区域假定大页、256 项 TLB 一次载入）。【知】iDMA 支持多维描述符；NVIDIA TMA 支持 tiled/im2col；2:4 结构化稀疏把索引成本降到常数。
- **强便宜对手（致命）**：① 大页/连续化（2 MiB 页把 PTE 数降 512×）；② 引擎的多维描述符（元数据从 O(#blocks) 降到 O(#dims)）；③ 元数据缓存 / descriptor prefetch；④ 结构化稀疏格式。

### 3.3 为什么我把它降级：一个朴素的数量级估算

- **case A（gather）**：1024 个 64 B 块的 gather map = 1024 × 8 B = **8 KB 元数据**，对应数据 **64 KB** → M/N = **12.5%**。但**多维描述符可以把 1024 项压成 1 项** → Q2 无空间。
- **case B（LLM KV block table）**：1024 个 16 KB block，block table 用 32 位 id = **4 KB 元数据**，数据 **16 MB** → M/N = **0.025%** → **微不足道**，Q2 无空间。
- **case C（地址翻译，真正的深间接）**：一次 4 字节的数据访问触发 4 级页表走 → 4 次内存访问 ≈ **256 B 元数据** vs **4 B 数据** → **M/N = 64×**。**这才是唯一元数据真正比数据贵的场景**。

**【推】结论**：Q2 在数量级上会自动收敛回**地址翻译**，而那里已经站着 BRIEF:9 一整排工作。**这是我对 Q2 新颖性的主要负面判断。**

### 3.4 唯一可能残余的切面：【投机生成 + 可恢复失败】

若描述符由消费者按需生成，则**生成可能失败**（越界、非法地址、模式不匹配）。需要的不是"生成"能力（很多已能做），而是：
- **失败必须可恢复**（不能丢总线事务——BRIEF:15 已警告：丢掉已接收的总线事务可能破坏协议）；
- 需要一个"投机生成 → 验证 → 回退到物化列表"的三态路径；
- 与 IOMMU 的 page fault / PRI / ATS 与 Intel DSA 的 block-on-fault【知】有耦合——**需核对是否已被覆盖**。

**Break-even**：`C_gen × r + p × C_fail < M × r`，其中 p 是失败概率。**只要 p 大或 C_fail 大（例如一次回退要重建 8 KB 列表），Q2 立刻净输。** 这是一个非常容易否定的命题——这也是我把它排在最后的理由。

### 3.5 可执行的最小判定实验

测一次 TLB miss + 完整 4 级页表走的**实际元数据字节数**（可用性能计数器或读取 PTE 的次数）与请求的数据字节数的比值。**判定**：若在常规负载下 < 1%，Q2 仅剩"极小访问 + 深间接"这一角，且必须与 BRIEF:9 的那一排工作逐一对撞。

## 4. Q3：用便宜证据替换保守性——搬运路径上的「证明代替引用计数 / 证明代替保守失效」

### 4.1 这不是什么

- **不是"加标签"**（BRIEF:13 明确禁止单独当创新）。区别在于：**标签必须来自编译期证明、且必须能跨用户态/内核态/设备边界而不退化成运行时检查**。难点恰恰是"如何不退化成检查"，而不是"加什么字段"。
- **不是"消除全局 quiet"**（BRIEF:15 已纠正：我们的配置切换要求全 quiet ≠ 规范要求全局静默）。
- **不是"翻译完成 vs 数据完成"**（BRIEF:15 已纠正）。

### 4.2 真实工作负载

- 在线推理/媒体流水线的**小粒度多次搬运**：每次 2–64 KB 的 KV block / 宏块行 / 量化权重块。
- 网络路径：AF_XDP UMEM frame 的搬运与归还。
- Linux 上 `io_uring` 的小 I/O + 零拷贝发送 + 注册缓冲区。

### 4.3 当前不利假设

**【设/要推翻】**
> 「任何一次 DMA 的生命周期与失效都必须保守处理：在无法证明没有其他读者/写者时，必须 pin、必须 refcount、必须发失效并等待在途事务、必须在完成后做 cache 维护。」

**【推】根源不是硬件不变，而是搬运路径上缺少关于别名与生命周期的静态信息。** 今天的信息在两处被浪费：
- 编译器/语言有所有权信息（Rust borrow checker、MLIR alias analysis、region 生命周期）【知】，但止步于 ISA，不下沉到引擎；
- 内核有生命周期信息（`dma_resv` fences、refcount）【知】，但只有运行时的、保守的。

### 4.4 机制真正改变的能力

**让每一次搬运请求携带一个可机器检查的、局部的、单调的"所有权/生命周期断言"**，使引擎在不询问任何中心权威的情况下决定四件事：
1. 是否需要 pin；
2. 是否需要失效；
3. 完成时是否需要 cache 维护；
4. 是否可以把 dst 的所有权直接移交给消费者而不销毁重建映射。

**新能力 = 把"是否必须保守"从运行时猜，变成请求里可验证的位。**

请求形状（提案，非结论）：
```
transfer(src_handle, dst_handle, len, proof: ProofToken)
ProofToken ::=
  | Exclusive { buffer_id, epoch }        // 编译期证明：本 epoch 内无别名读者
  | Immutable                             // 编译期证明：no-write 区间（如只读权重、常量表）
  | Shared    { reader_epoch }            // 未证明 → 走保守慢路径
  | Persistent{ iova, pinned_until }      // 持久映射
```

元数据：每个缓冲区一个"所有权槽"：`{ owner, epoch, immutable_flag, pinned }`，放在内核或设备可读表中。
执行：引擎按枚举选快路径。
完成：**完成记录回写 epoch/owner —— 这仍然是一次小的原子写，不能免费 → 必须计入成本模型。**

### 4.5 具体小例（含地址 / 别名）

场景：CPU 写缓冲 A（PA `0x8000_0000..+64 KiB`），iDMA 通道 0 搬 A → B（PA `0xC000_0000`）。

**今天的路径**：
1. `dma_map_single(dev, A, 64 KiB, TO_DEVICE)` → IOMMU 在 domain D 建立 IOVA `0x2000_0000`。**若用 4 KiB 页：16 个 PTE 写**；**若用 2 MiB 页：1 个 PTE 写**。
2. 提交描述符 → doorbell。
3. 等完成中断。
4. `dma_unmap_single` → 清除 PTE + IOTLB 失效（按地址，但**可能仍需等待在途事务**——注意 BRIEF:15 的纠正：这不等于"规范要求全局静默"，但**实现上可能仍有一个等待窗口**，必须实测）。

**别名风险（真实存在，必须处理）**：
- A 同时被 CPU 通过 VA `0x7f00_0000`（可缓存）访问。
- 若 CPU 在 DMA 期间写 A → cache 与 DMA 读可能撕裂。
- 若 IOMMU 的 domain 与 CPU 的 PTE 指向同一 PA 但属性不同（cacheable vs non-cacheable），**同一物理地址两种内存属性的行为我不做断言【未：需核对规范】**。

**Q3 的主张**：若编译器能证明"这段区域在 epoch E 内只被 P 写、之后由 D 独占读"，则：
- dst 的直接映射可以保留（不用每轮重建）；
- map/unmap 可以合并为一次；
- 完成后除必要的 cache 维护外无需额外动作。
**代价**：epoch 切换时一次原子写 + 证明有效性。

**违反证明的反例（真实且危险）**：
- 同进程 `fork()` 后子进程持有同一映射（COW 前）；`mremap` 遗留的旧映射；另一个 `io_uring` ring；设备自身的 ATS/PRI 让它自行取页表并缓存旧 IOTLB 项 → **"独占"不成立 → 静默数据损坏。**
- **这就是为什么必须用编译期证明 + 有类型句柄，而不是运行时 `assert`。**

**一个诚实的降级陈述**：
> **Q3 不能免除失效，只能把失效从"每次搬运"变成"每次所有权转移"。** 因为 ATS/设备侧 TLB 的存在，所有权改变时仍需失效。

### 4.6 成本模型与 break-even

| 项 | 含义 | 平台假设（**必须实测**） |
|---|---|---|
| BW | 有效搬运带宽 | 0.5 GB/s |
| N | 单次搬运字节数 | 变量 |
| t_x | 传输时间 = N/BW | — |
| F_fast | 快路径固定开销（描述符 + doorbell + 完成中断） | 1–3 µs |
| F_map | 映射开销 | 4 KiB 页：N/4096 次 PTE 写；2 MiB 页：N/2MiB 次 |
| F_inval | 失效 + 等待 | 1–10 µs |
| F_ref | refcount/epoch 原子写 | 50–200 ns |
| F_cache | cache 维护 | 每 line 一次操作 |

**核心公式**：
```
慢路径单位成本 ≈ F_fast + F_map + F_inval + F_ref + F_cache + N/BW
快路径单位成本 ≈ F_fast + F_epoch_write + N/BW          // F_epoch_write 不能省
批量化后单次成本 ≈ (F_fast + F_slow) / b                // b = 合并的搬运数
```

**临界搬运粒度**：
```
N* = (F_fast + F_slow) × BW
取 F_fast + F_slow = 8 µs，BW = 0.5 GB/s  →  N* = 4 KB
若 Q3 把 F 从 8 µs 降到 2 µs          →  N* = 1 KB
```

**【设】可测的具体主张**：
> Q3 能把临界搬运粒度从 ~4 KB 降到 ~1 KB（即 4×），代价是所有权槽的一次原子写。

**必须承认的致命对手（写进首页）**：
1. **批量化**（doorbell batching、描述符链、`io_uring` batch）：把 F 摊成 F/b，**几乎免费**。Q3 只在 **b 无法增大** 时有价值（延迟敏感 / 依赖链 / 无法合并到同一连续区）。
2. **持久映射 + 长期 pin**（持久 IOVA、identity domain）：把 F_map + F_inval 从热路径彻底移除。
3. **refcount 本身很便宜**（一条 cacheline 的原子 RMW，~ 几十 ns）→ F_ref 单独不构成动机。

### 4.7 正确性要求

1. 断言必须**可检查或来自可信来源**（编译期 / 内核构造），不可被不可信设备或用户态伪造。
2. 断言粒度必须与硬件可见性粒度匹配（页 / line），否则证明无法下降到引擎。
3. **必须定义违反断言时的行为**：是 UB 还是可检测？**若只能是 UB，则 Q3 只能用于内核/驱动/受信 IPA 范围**，不能覆盖不可信加速器。
4. **完成序**：epoch 更新的可见性必须先于后续搬运的读 → 需要一条 release/acquire 序（RISC-V 上 `fence` 或 `amo`）。
5. **所有权移交给消费者后，生产者不得再触碰该区域**——这个约束必须能被静态检查，或必须由内核在边界处重新验证。

### 4.8 足以否定 Q3 的反例

- **R1**：所有搬运已用 2 MiB 大页 + 持久映射 + 批量 doorbell → F_slow 可忽略 → Q3 无空间。
- **R2**：工作负载搬运粒度天然 ≥ 64 KB（流式训练 / 大块拷贝）→ N\* ≪ 实际粒度 → Q3 无空间。
- **R3**：消费者必须对每个块同步（依赖链）→ 批量化不可行，**Q3 有空间**——但此时瓶颈是**延迟**而非带宽，而 Q3 省的是 µs 级固定开销，**可能被中断/调度噪声淹没**。→ 必须先用性能计数器证明 F_slow 是尾延迟的主要成分，否则命题不成立。
- **R4**：设备/驱动使用 ATS/PRI 自主取页表并缓存 → "独占"断言失效，必须回到失效 → Q3 退化为"把每搬一次失效改成每转移一次失效"，收益缩水。

### 4.9 平台可验证性

**可做**：iDMA 搬运 N ∈ {1KB, 4KB, 16KB, 64KB, 256KB, 1MB, 4MB}，分别测 (a) 预映射无 map/unmap、(b) 每次 map/unmap 4 KiB 页、(c) 每次 map/unmap 2 MiB 大页。拟合 F 与 k，求出 N\*。
**不可做**：任何外推到真实 PCIe/CXL 设备的结论（BRIEF:5）。

### 4.10 新颖性状态

**【未】**：需核对（且我不声称检索过）：
- 内核侧类型安全 DMA / 有类型缓冲区句柄的已有程度（Rust-for-Linux 的 DMA 抽象、`io_uring` 注册缓冲区、`dma-buf` 的 attachment/direction）——**它们是否已把"所有权证据"下沉到引擎？我的判断是"没有"，但需核对。**
- seL4 / verified kernel 中的 DMA 所有权与能力传递。
- Intel DSA 的 descriptor 与 completion record 是否已表达"占位/独占"语义。
- "证明代替 fence"在系统文献中的既有程度。

## 5. 三者关系与冲突

| | Q1 | Q2 | Q3 |
|---|---|---|---|
| 改变的对象 | 数据身份 | 元数据生成时机 | 搬运路径可得信息 |
| 主要成本项 | A_view（访问放大）+ 失效放大 | M/N（元数据放大）+ p·C_fail | F_slow（映射/失效/refcount）+ F_epoch_write |
| 致命对手 | 一次物化 + 融合 | 大页 + 多维描述符 | 批量化 + 持久映射 |
| 共享的难点 | **失效的粒度与完成语义** | 描述符的可信性 | 断言的可信性 |
| 是否互相依赖 | Q1 的失效机制可用 Q3 的证明降低触发频率 | Q2 若做，其失败恢复需要 Q1 的版本语义 | Q3 的 epoch 与 Q1 的 version 是同一种东西 |

**【推】三者的共同内核是同一个东西：用一个"单调版本/epoch + 区域"的抽象，同时表达"数据是谁的函数"（Q1）、"描述符是否还有效"（Q2）、"所有权是否已转移"（Q3）。**  
如果主 Codex 要做取舍，这个共同内核可能是比三个独立问题更好的单一选题——但**这也是新颖性风险最高的一步**，因为它可能已经被 ShareMMU 的"权限跟踪 + 定向反向失效"覆盖（BRIEF:9）。**必须先核对 ShareMMU。**

## 6. 建议主 Codex 执行的最小判定实验（都可被一次实验证否）

| # | 实验 | 判定条件 | 若成立则 |
|---|---|---|---|
| **E1** | 用 4×iDMA 在同一 4 MiB DDR 区域上做「tiled 行访问」与「逐列访问」两种模式，测**有效带宽**（有用字节/时间）与总线事务数 | 逐列访问的有效带宽 < tiled 的 1/8 | **A_view 主导的论断成立** → Q1 的胜负判据被钉死，必须收窄到"消费者代码可控" |
| **E2** | 测一次 IOMMU 按地址失效 + 等待的实际延迟；对比一次 4 MiB 搬运的时间 | 失效延迟 × D < 一次拷贝时间 且 N\* ≈ 1 KB | **Q1-b 成立** → 障碍不在同步，在 A_view |
| **E3** | iDMA 搬运 N ∈ {1KB…4MB} × {预映射, 4 KiB 页 map/unmap, 2 MiB 页 map/unmap}，拟合 N\* | (b) 与 (a) 的差在 N ≥ 16 KB 时 < 5% | **Q3 被限制在小粒度**，生存空间收窄 |
| **E4** | 测一次 TLB miss + 4 级页表走的实际元数据字节 / 请求数据字节 | 常规负载下 < 1% | **Q2 仅剩"极小访问 + 深间接"**，不宜作主攻 |
| **E5** | （非实验）核对 ShareMMU / NDS / vAttention / MLIR bufferization 原文，回答"谁已经处理了派生失效与完成语义" | — | **决定 Q1 是否还有题目** |

**E5 必须先做**，因为它是唯一可能直接杀死 Q1 的一步，且成本最低。

## 8. 未决问题与风险（我明确不知道的）

1. **Q1 的新颖性未知**：我无法判断"派生视图下的内存模型"是否已有对应工作。**不做空白断言。**
2. **Q1 的 A_view 是否可在真实负载中被控制**：这是它能否成立的生命线，而它取决于消费者代码，我在报告中已把这个风险放在最显眼处。
3. **Q2 大概率应被放弃**：我用最朴素的估算就把它逼回地址翻译，而 BRIEF:9 已列出该领域的密集近邻。
4. **Q3 的生存空间窄**：批量化 + 持久映射 + 大页是三个几乎免费的对手，Q3 只在"小粒度 + 延迟敏感 + 不能预映射 + 不能合并"四条同时成立时才有意义。
5. **平台值的全部为假设**：BW = 0.5 GB/s、C_sync = 2 µs、F 各项数值都是【设】，**没有任何一项是实测**。本报告中所有 break-even 数值必须由主 Codex 用 E1–E4 替换后才能作为论证依据。
6. **共享内核的吸引力与风险**：三者可能收敛到同一个"版本/epoch + 区域"抽象（§5），这可能更好，但**新颖性风险最高**。
7. **我不迎合上一轮的三个候选**（稀疏访存加速 / 跨设备布局视图 / 取消后资源回收）——本报告没有把它们作为出发点；如果它们与本报告重合，那是独立收敛，不是继承。

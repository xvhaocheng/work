## 2. 候选 S1：SPDK NVMe perf 的完成驱动补发，加独立 iperf3 网络任务

**真实来源有了，原生联合需求、共同翻译实例和 D 状态对没有。** 这是两个真实官方程序的拟议研究组合；不能改称已有实际双设备共跑轨迹。

### 源链与自然变化

固定 SPDK v24.09 / `19524ad45373e35d5fdc06f4e081444d87ceed80`：

1. `nvme_setup_payload` 为 task 分配 DMA buffer，读命令把 `task->iovs[0].iov_base` 与存储 `lba` 分开传入（原件 `SPDK_PERF:804–840,847–904`）。
2. `io_complete → task_complete → submit_single_io`：完成后减少当前队深；未 draining 时复用同一 task/buffer 补发，达到 number-ios/时间停止条件后不补发并最终排空（`1471–1629,1737–1859`）。**下一笔何时提交确由真实完成驱动，不需人为指定到达相位。** 但源码没有提供所选 SSD 的逐请求服务轨迹或其稳定状态。
3. 顺序/随机模式改变的是 namespace LBA。`randread` 本身没有重新分配 host buffer，因此不能把 LBA 随机当成 IOVA 页环随机（`1480–1495,1566–1573`）。
4. 固定 iperf3 3.17.1 / `2acfcfe94e928e74542c9f107e02aa6dd4748a79` 可按有限字节/块数结束；不加 `-F` 时可生成/丢弃数据，从而允许与本地存储任务数据独立。网络接收时序仍需所选端点的真实记录，手册不提供逐包时序（`IPERF:59–91,125–132,321–328`）。

这些自然完成/网络到达**可能改变**翻译请求与 payload 的相遇，但本次未取得这种相遇的实际时序，更没有它令 PN 净效应反号的证据。不能将“服务有波动”直接升级为“付费联合观测可预测下一任务”。

### 保留的最强合理版本：同映射下的完成时序来源

**不改 IOVA 不会否定它的时序用途。** 可发展的具体链是：`实际 LBA/设备服务状态 → NVMe command completion → io_complete → 同 task/buffer 重提交 → 此后 payload 与另一 owner 页表服务相遇`。其中 callback 后半链已由源码直接建立；前半链需要具体设备及原始请求/完成记录，不能由程序名推断。已知 LBA、命令顺序、队列和已有历史全部给 O0；若 LBA 改变本就足以预测，普通源感知基线即可利用。

有意义的待证版本是：**同一完整任务、同映射池和全部已知配置下，存在尚未被普通已知历史解释的设备服务状态；它在自然运行中影响完成/补发的形状，并跨 quiet 决策边界保留足够预测性，使一个付费联合摘要对下一完整任务的 P/PN 选择有增量。** 这段是来源绑定的条件研究设计，不是已经确认某种内部状态或 phase。即便自然 jitter 被记录出来，若它不持续、不能预测下一任务，或只是随机噪声，就不支持当前的跨任务反馈版本。

最少补证应先取得一个所选设备/任务的**原始实际事件段**：同实例的 host buffer/IOVA、已知 LBA/命令序列、提交、payload 服务和成功 completion，以及下一任务决策的准确边界。然后核哪些部分在边界时已由普通程序知道，什么未公开状态/有效历史关联仍待观测。先有这份事实才能冻结正反状态；不预选“快/慢设备态”、不把 LBA 随机种子当等价状态、不手调两个任务偏移去对齐 PTW。

### O0 能知道什么

queue depth、task/buffer 身份、host 映射池、读写模式、已经选出的 LBA、已完成/待补发状态、draining、网络方向/字节预算/pacing 配置，都有普通程序来源，应按可得时机与费用给强基线。不能隐藏常驻 buffer 复用，或只给一个 miss 数。未来 SSD completion/网络到达不因事后 trace 可见而成为当次事前 O0；反过来，未来未知也不自动证明现有 O0 缺一个可预测的持久状态。

**未取得：** 同一真实运行中双方 translated mode、Requester/domain、实际共用 IOTLB/PTW/服务路径；quiet 后仍保留且影响下一任务的服务状态；该状态与可及时取得信号的联系。VFIO 的 IOMMU group 是权限/隔离粒度，不能替代共享物理翻译结构证明（`SPDK_CONFIG:5–17,49–59`）。

### 正侧与相邻反侧

- 正侧所需的源条件：在同一任务预算/已知映射与配置下，真实自然就绪/服务状态使 PN 的等待节省大于完整后台和收尾代价，而且强 O0 无法事前区分；须有实际记录，再冻结预测。目前没有这种来源绑定状态，正侧为 null。
- 相邻反侧条件：若合法常驻池/准备、普通按完成补发与 pacing 已把有效翻译需求及关键路径解释清楚，或完整效果始终 P 不劣，则源感知普通控制已足够；不需要新联合观测。该条件没有在本次被性能验证，不填效果数字。
- 原源 `io_completed` 还包含错误回调路径，不能直接作成功字节；完整目标须保留 receiver 成功完成、NVMe 成功完成和各自尾排空（`SPDK_PERF:1539–1544,1577–1601,1835–1859`）。

### 固定 M0 能否表达

**不能忠实表达本来源。** M0 没有 NVMe 媒介/命令与 CQ callback、网络端点和 CPU poll 供给；gap0 的固定 64×4KiB 完成补发不等于上述两项完整任务。将 LBA 直接改成 A1/A8 又既非来源语义，也已被 O0 区分。选择一段真实 trace 投影需另订供给/服务/成本合同，不能称仍在首批固定 M0 内；PC/NIC/SSD 上也没有本平台 P/PN 动作已可部署的证明。

## 3. 候选 S2：官方 SDI→DDR / YAVTA 采集，加独立有限后台

**前台生产者和 buffer 生命周期明确；独立后台仍未识别，不能组成双共享状态对。** 官方入口是 SDI Rx→VDMA S2MM 或 Framebuffer Write→Memory，示例 `yavta -n 3 -c10 -f YUYV -s 1920x1080 --skip 7 -F /dev/video0`（`SDI_SNAPSHOT:95–105`）。它不是全帧 DDR→DDR COPY 的来源。

### 源链与自然变化

固定 YAVTA `42573311466dbeab630d084bc2d5afe88154690b` 的正常链为 `DQBUF → verify/log → optional save → QBUF`，最终 STREAMOFF/free（`YAVTA:2300–2407`）。源帧到达和消费释放是真实自然事件；buffer 数、bytesused、stride、实际周期与索引顺序必须用返回值/记录，不能用命令名义参数填齐。

**已核的具体相邻边界：** 若实际返回三槽、正常十帧、默认不 requeue-last，`skip7` 只在 `i=7,8,9` 保存，而同段 `i>=nframes-dev->nbufs` 在 `i>=7` 已跳过重新 QBUF（`2349–2368`）。因此这条示例不能支持“开始保存→后续重入队变慢→新的 DMA 到达相位”的因果链。保存仍可能影响完整消费者/文件尾部成本，不能记成免费，也不能据此推得所需 P/PN 反号。

### O0 与缺口

输入格式/布局、已分配 ring、skip/迭代号、所有权、已返回 buffer index/sequence、已经消费或重新 QBUF 的状态，是源程序可知道的普通信息。已知保存阶段或帧率配置变化不能藏成相同 O0。物理源未来 jitter 或消费系统的未观测状态可能存在，但当前无匹配轨迹、持续性或可预测性证据；文档的支持模式列表不是此次实际到达周期。

保存采集帧是前台消费者，不是独立后台。旧来源卡没有识别独立有限文件/任务、到达、完整字节及自然结束；没有匹配 final DTB/overlay/StreamID 证明 capture 和另一 master 都实际翻译并共享结构。旧 base DTS 的 SMMU disabled（`DTS:1047–1071`）只说明那个基础配置，不能断言所有 SDI 部署绕过 IOMMU。

### 正侧与相邻反侧

- 正侧所需源条件：一个已识别的独立有限后台与真实采集共同服务；自然 slot-release/源到达使 P 与 PN 有可预测的完整收益交换；强 O0 后仍留信息缺口。当前后台、时序和正侧状态均未取得，正侧为 null。
- 相邻反侧条件：静态 ring 合法准备、可用大页/驻留、按真实 buffer/完成事件的普通发布策略已经满足双方完整目标；或保存只影响前台尾部而不形成待选的共享翻译窗口。上述官方 skip7/尾三帧是后一点的**来源反证边界**，不是实测 PN 性能反例。
- 两张卡均没有一正一负的完整时间，也没有“观测选择获益”的数据。

### 固定 M0 能否表达

**不能。** stream→memory 的生产者、返回布局、消费/requeue 和独立后台不是 CPUoff、静态映射、固定两路 COPY/gap0 的同一任务；把整帧先放 DDR 再按选定周期 copy 会改动 source-ready 与端点语义。添加这条来源必须另立合同，不能将本卡视为现合同的两组新参数。

## 4. 已有首选工作流为何没有填上这对状态

这部分是指定来源的定向排除记录，**不新增第三张候选卡，不重开旧分支。**

- **HERO `mm-large`：** 直接核原官方 `double_buf_mm`，线程0/1/2的 A/B 输入与 C 输出由固定条带、buffer 和完成依赖发布（`HERO_MM:93–208,238–276`）；计算循环对每个元素执行相同循环结构，不因 B=2I 的零值跳过乘加（`214–228,320–325`）。因此换稠密数值不能当自然强度/相位变化来源。尺寸/条带、映射、复用及计算资源是已知配置，基线同获；没有证据证明固定输入会带来所需隐藏服务态。既有六槽/16KiB/288搬运合同与首批64×4KiB也不同；追加8MiB后台始终不是源应用的独立任务。
- **HERO AXPY：** 核本次 A5 实际复用的 A2 修正源码，RX/RY→wait-all/barrier→预取 next 与固定 FMA→barrier→WY，尾部真实 wait-all（`AXPY_KERNEL:77–156`）；main 的 cold/hot 标签、两次恢复相同输入、共同映射及最后 consumer/unmap 明确（`AXPY_MAIN:79–137`）。cold/hot 是可见 episode，不能把标签隐藏成 O0 不可分；实际硬件 cache/服务状态和同配置运行未知，也不能仅据标签填周期差。它是单 native DMA、同 SID0/SSID0 的原工作流，双 buffer 不证明两 DMA/双 context 或真实共享 PTW 竞争。A5 已有源级安全正反切面不是 D 的完整效果反号对。
- **DASH 行预取：** 现已核合同给规则释放/640B 行、普通 P 满足原登记期限；不能把规则行号或手改释放相位作自然隐藏状态，更不能拼出 PN 正侧。旧结果按原范围保留。

## 5. 最小可检验的重设计建议，未执行

**保留现 M0 合同就不放宽 guard、继续扫参数或加观测器；本轮来源门到此停止。** 指定来源没有提供一个在完整 quiet/warm 后仍有因果作用、强 O0 未知的持久服务状态。是否 M0 自身还有此自由度由独占机制席判断，不能由本席的来源缺证代替机制证明。

若 root 决定发展 H-D，最小下一交付应先是**一份“同实例源—动作—服务”联合合同及实际事件段**，而非 collector/性能矩阵：

1. 只选一个实际可运行实例，先确认两项独立有用任务确实共用所研究翻译结构，且 P/PN 或另行命名的动作在该实例上真实可用；来源/投影/部署分别写明。
2. 从该实例记录完整有限任务的 ready、接受、成功 completion、consumer 和释放；natural-ready 从程序/真实输入来，不能在看到 P/PN 结果后选偏移。保留完整尾部和相同有效工作。现候选若不能给该证据，就保持未通过，不再补调 phase。
3. 预先给强 O0 全部已知配置、程序阶段、映射/pool、同成本的实际完成/队深/就绪信息，说明每项首次可见时刻；若这些已区分状态，改用普通源感知策略，不强求新联合观测。
4. 只有实际源证实了会跨决策边界保留的服务状态，并且可取得的历史信号对下一任务有稳定预测联系，才冻结两个来源绑定状态和相邻反侧。未来 trace 只作标签/验证，不能免费交给当次选择；若不保留/不预测，就撤销该版本的信息价值主张。
5. 忠实表达自然事件如果必须改变 gap0、固定 64×4KiB、CPUoff、固定 warm 或服务端点，**先明确提出一个新合同**；当前来源卡没有授权放宽或执行。新模型/原生端到端证据也不能用旧 M0、E3、PN 窗口拼接代替。

接受条件是“具名真实来源 + 同实例可执行动作 + 事前 O0 + 未见完整正反预测 + 全费用”，并不预设一定有反号。若新增源仍无 PN 获益侧或普通源感知策略已覆盖，就停止该 H-D 版本的新增观测/选择收益主张，保留来源与诊断资产。

# 论文工作区：新任务入口

## 按任务选择模型与推理强度（2026-10-15 用户最新要求）

本节适用于本项目的root、子agent及更深层执行席，取代本项目此前“全树固定Sol/ultra”“不得调整推理强度”及其他冲突的模型分工条款。**这是用户指定的项目任务分配策略，不是OpenAI针对本项目给出的配置，也未验证为最优组合。** 当前共享IOMMU任务继续Codex-only；本次规则更新不改变研究方向、实验授权、暂停状态或其他项目的分工。

官方依据（2026-10-15已核对）：[Model selection](https://developers.openai.com/api/docs/guides/model-selection)强调按任务、质量、时延与成本选择模型，并以代表性结果检验；[API deployment checklist](https://developers.openai.com/api/docs/guides/deployment-checklist)说明推理强度的取舍及实际评估。下表是据此制定的**项目建议**，执行前仍须核对工具支持与实际运行记录。

### 一、任务分配

| 任务 | 建议配置 |
| --- | --- |
| 单纯字段提取、格式转换、按明确规则分类 | `gpt-6.1-sol` / `low`或`medium` |
| 普通实现、脚本、文档整理、归档与引用修复 | `gpt-6.1-sol` / `medium` |
| 核心论文精读、源码调用链、日志与证据核查 | `gpt-6.1-sol` / `high` |
| 已明确问题下的新机制设计、复杂反例、严格验证与决定性实验设计 | `gpt-6.1-sol` / `xhigh`；必要时启用本机`ultra` |
| 高度开放的研究问题、论文主线重构、重大架构取舍、困难机制冲突与复杂根因 | `gpt-6-astra` / `xhigh`；必要时启用本机`ultra` |

- Astra可以直接承担正向创新设计或担任root，不要求先让Sol反复失败。Sol同样可以承担创新设计，不能仅因任务称为“创新”就自动切换Astra。
- root与子agent都按当前任务选模型和强度，不按身份固定。任务从证据整理进入机制设计，或从研究决策进入普通实施时，重新判断配置。
- 执行前核对模型与推理强度的实际工具支持和运行元数据。若建议配置不可用，记录限制及实际选择的可用替代配置，不静默替换或声称已调用。

### 二、ultra的使用条件

- `ultra`仅用于少数推理要求特别高的问题，例如多个机制解释相互冲突、长协议依赖链、严格反例构造或决定研究方向的复杂推演；不设为所有席位的常驻档位。
- 使用前说明具体难点、期望解决的问题和接受条件。已有代表性任务结果支持更高强度时优先采用；没有对照证据时，将选择标为待验证的判断。
- 官方API文档列出`low`、`medium`、`high`、`xhigh`、`max`，具体支持取决于模型；本机Codex可能另提供`ultra`。以实际工具支持和运行元数据为准，未验证映射前，不把`ultra`、`max`或`pro`当作同义项。官方的`reasoning.mode: "pro"`与推理强度是独立设置，不能由档位名称推断已启用。
- 缺论文原文、真实轨迹、参数或测量时先补证据；提高推理强度不能代替这些输入。
- 根据正确性、证据完整性、返工、耗时及可取得的用量数据调整配置。不为比较模型而重复已完成实验，不未经测量宣称节省或质量提升。

### 三、执行与交接

- 每个子任务明确独占范围、输入、交付物、接受条件、建议模型和强度；派发时记录请求配置，交付时核对实际配置。并行席位处理不同决定问题，不重复阅读全文或安排例行复审。
- 核心结论必须回到论文原文、源码、原始数据及实际验证；模型之间达成一致不算证明。
- 保留正在进行的工作和历史结果，不为换模型重跑已完成任务，不改写历史模型记录。
- 核对实际运行记录，区分“建议配置”“请求配置”和“实际运行配置”；无法取得的字段标为未知，不用请求参数冒充实际运行证明。不能原位切换时如实说明，在工具支持的后续任务中应用；不能把修改本文件说成已经切换模型。
- 使用原生上下文与自动压缩默认值，提供完成任务所需的充分上下文，不设置`model_context_window`、`model_auto_compact_token_limit`或`model_catalog_json`等旧手动窗口覆盖。不默认复制全部历史，也不为省上下文遗漏关键原文；完整产物留文件，交接给出可导航入口、关键证据、未解问题和下一步。

## 研究方向不默认沿用A（2026-10-15 用户最新纠正）

- 用户指出：若此前沿用已有A，就不需要默认按A推进。后续方向判断取消A的默认优先级；A保留为候选，不能凭旧计划、已投入工作或文档成熟度认定它最有希望。
- 区分“在A前提下做了实质分析”与“平等比较不同方向后独立选择A”。2026-10-15创新点报告属于前者，其前作核查和条件论证保留，但撤回跨方向的最优排名；新的独立方向比较已完成，见[六族独立比较](iommu-platform/docs/independent-research-directions-20261015.md)，后续安排按当前总计划执行。
- 之后按真实问题、最接近工作留下的空间、可提出的新机制/认识及关键验证可行性比较不同候选，允许选出A、其他方向或暂不选定。复用已有证据，不为摆脱锚定而丢弃成果，也不强行制造替代方案。
- 本纠正不自动恢复暂停goal、旧席或实验，不把A归档为失败；原硬件与原生验收合同仅作为相应候选获选后的条件。

## idea发展与新意判断（2026-10-15 用户最新要求）

- **默认优先保留并发展用户idea。** 先寻找保留核心思想的最强合理版本，考虑如何深化方法、补足已有不足，或以新的问题组织形成可检验的认识；不因存在相似工作就过度防御性地否定方向。判断标准是明确且有意义的新增贡献和探索空间，不要求绝对原创、完全没有先例或所有构件都首次出现。
- **先系统调研最接近的一批论文，再判断重合。** 按相关性组织检索，深入阅读决定判断的核心方法、问题设定、假设、算法／协议、技术细节、评估和贡献边界；必要时核查实现。复用已核阅读，不凑数量或重复调研。标题、摘要、关键词或表面相似不足以支持覆盖结论；未取得或未读完的关键内容明确标为未核，不凭猜测补齐。
- **比较实质，而非只比名称。** 逐篇写明已有工作解决什么、依赖什么信息与执行能力、保证到哪里、有哪些成本和局限，以及本idea具体新增或推进了什么。差异可以落在机制、接口／协议、架构组织、实现成本、适用条件或有证据支持的新问题视角；组合、换场景或故事更完整本身不自动构成贡献，须说明它带来的新能力、解释或结果。
- **给出一段可核查的novelty论证。** 清楚说明“最接近的工作已做到什么；还留下什么不足或新问题；我们具体增加或推进什么；为什么有意义；哪些证据支持、哪些仍待验证”，附准确论文及章节／页码等原文位置。避免无依据的“首次”或“从未有人做过”，不把拟议收益写成已证事实。
- **前作、普通构造、候选等价实现和离线上界分开。** 普通程序在同一新增付费接口上复现策略动作，只能按其证明范围排除该策略增量，不能单独证明接口已发表、架构无价值或整体idea应关闭；也不能因现有接口缺项就认定创新。不要求击败所有想象程序；实际对照仍须具名、可执行并计入完整成本。
- **实质撞车时停止该版新意主张，不强造novelty。** 精读后若核心问题、关键方法和主要贡献高度重合，且合理发展仍无法形成实质区别，明确指出撞车论文、对应原文、具体重合和剩余差异为何不足。停止范围限于证据覆盖的主张或版本，保留成果；不能把单个负结果或未完成核查扩大成整个思想族无价值。
- 以上是解释旧“覆盖／淘汰／停止”措辞的最新判断规则。规范更新本身不恢复暂停goal、旧席、关闭分支或实验，也不改写既有结果；具体重审或执行仍按当前任务授权和事实推进。方法细节及模板见[研究方法.md](研究方法.md)。

## 贡献筛选与记录流程（2026-10-09 审查后执行）

- 先固定候选卡：真实问题、新增动作、准确前作、完整可执行强对照、全部资源与完成成本、一个决定性正例及相邻反例。把安全能力、性能收益和前作覆盖分别裁决；最大安全长度不等于最快长度。
- 模型前先核决定可达性的实际配置和接口：读写分段标志、生产实例、真实返回容量、首次VALID承诺、成功许可握手和结果所有权；同预算对照包含单目的提前准备、已有共享槽和可用在途额度，不把未握手的VALID当授权。强对照允许合法回收已消费阶段的字段；不能用人为单child限制或固定字段用途制造收益。增加prepare/raw-adopt接口前，先比较正常翻译后的物理缓存等更简单集成位置。只定向核关键调用链，不先全面扫描或修大夹具。
- 并行席位各解决一个独立决定问题，产物先汇入root接受结果再写文档；一个具体普通控制已完整复现时，停止该性能试验，保留边界或明确重设计问题，不为维持席数继续测试。
- 一轮先形成稳定的 `root-result-acceptance.json`，普通文档在轮末一次提交；修订以具体错误或新事实为输入，不重复生成未变正文。DeepSeek思考/输出预算和root关键源码、权限及协议审查保持；不新增例行审计或网络探测调用。
- `CURRENT_STATUS.md` 仅保留当前结论、实际执行、下一判别题和证据入口；旧版本原样归档，阶段记录进入 `HANDOFF.md` 与验证文档，不在当前页不断前缀叠加历史。
- 只在输入改变、验证失败或关键结论仍缺证据时补测；已通过且未变的模型、RTL及构建不重复运行。保存实际调用和执行账本；用实测数据评价流程成本，不宣称未经测量的节省。

# Codex 审查：独立设计、前作核查与补充提案

2026-10-07。作者与最终判断：Codex。设计规格先写入 `codex-proposal.md`，之后才读取 `prior-answer.md`、`rules-answer.md`。用户明确要求 Codex 亲自参与创新设计与分析，不能只将其交给 DeepSeek 后做摘要。

## 1. 审定结果

没有确认新颖性或性能。本轮形成两条具体候选、核实接口代价，并剔除返回材料里的若干错误。没有新增仿真或生产改动。

**最终优先级调整：先核 C（目的准备状态指导源数据提前量）；D（按可执行等待者改变下一段长度）降为配套机制／普通对照。** 独立稿末尾原先优先 D，是审查之前的候选排序，保留原稿不抹去推演过程。

理由：D 的 X/Y 区分若已体现在“物理 AW 是否进入下游等待队列”，普通下游压力自适应也能区分；不能故意用只看输入 AW 的弱基线。即使 D 在当前项目第一次实现，也不因此成为领域创新。C 至少提出一个仍需核的不同决策：目的翻译未完成时，在专属接收空间内允许有限早读；目的可执行后扩张窗口；目的因另一 job 的所有权阻塞时不再扩张。但它也可能等价于两端准备加普通在途额度。

**不能拿“有完成依赖信息”本身立题。** 先明确强普通方法看不到、或用更高资源成本才能使用的具体信息，再核候选是否作出不同合法决定。

## 2. Codex 独立方案需要修正／补证的地方

1. **可达性还缺。** 当前每 bank 一个 TC，AW 在 COMPLETE 未获物理握手时会占住 TC；不能默认此时同 bank 的源端已经另行翻译完成。AW-first 若本来就让目的先完成，C 所需“源热目的冷”状态可能很少。必须从实际生成/接受顺序核查，或明确新增独立准备槽所创造的状态及其全部成本，不能称已有板上现象。
2. **准备接口有实质代价。** C/D 中 translation-only 请求不能伪装为普通 AW；输入 demux 会保留 W owner。当前 TL 对主 PTW 与 FAST 以 bank 路由，一个 bank 同时两角色还需事务标签或严格串行准备状态，不能仅加两个 valid bit。N window 当前只容许另一 bank。
3. **段长改变可能产生更多翻译请求。** 固定逻辑字节与页面集合不等于固定请求数／miss数。短段的额外 AR/AW、IOTLB 查询、页表遍历必须记账；不能为制造优势强行匹配实际已经改变的 miss 数，也不能只报告命中率。
4. **不能提前宣布有界等待。** 专属读空间预留可限制溢出风险；不保证 DDR 延迟、不保证所有权一定释放、不实现公平。既有 guard 与排空路径保留；新循环等待要单独推演。
5. **FIFO 512 深度不是通用 free-beat 输入。** 实际逐 byte lane 带对齐/strobe；长度与占用按真实 lane 保守算。当前 4KiB certificate 是可容纳且单 job 的证书，不是数据已齐或物理 W 已排空。
6. **异常与映射更新未闭环。** 第一判别限定静态映射、正常 copy。TC 在途记账、fault 的已收事务终结、IOFENCE PR/PW、prepared PA 有效性需要完整契约；清掉记录或 TTL 到期不是正确的取消／失效协议。

## 3. 对 DeepSeek 五条接口提案的具体审查

DeepSeek 的本轮提案不是被验证的 RTL 算法。下述问题阻止直接采用，原答复保留供定位。

| 提案 | Codex 关键检查 | 裁定 |
|---|---|---|
| C1 completion frontier | 伪代码维护的是事件顺序，未建立 job 依赖图；旧请求不一定关键。5 类却估 2-bit class；W owner 释放不能用 B 代替 WLAST。另把“普通 PTE 优先返回”写成“拒发所有新数据直到返回”，两者不等价。 | 保留释放依赖问题；不采用规则或成本数。 |
| C2 pending queue + ticket | 若新 entry 的 ticket 只能由该 entry 自己的 response 放行，就有“未发请求等自身返回”的循环；若等待另一旧事务，应显式记录前驱关系。分 bank/ID 队列与跳过不可执行队头已有强前史；测试代理的单 entry HOL 不能当原生产系统新瓶颈。 | 分队列作普通对照；不是当前论文主方法。 |
| C3 src/dst rendezvous | DID/PID/AXI ID 本身不是 job/字节段标识，单 active job 限定也需角色和偏移。原文“另一 ticket 在途”不等于另一端已准备好；其伪代码条件与文字不一致。 | 配对准备可作支撑；不采用原门控/TTL。 |
| C4 adaptive P/N | `n_window` 要求 PT 状态、主 PTW active；“主因 DATA 阻塞而启用 N”不能从一次 PTE 返回推导。保护 DID 正是 V，直接拒绝它可能仅关闭主要 N 收益。共享 PLRU 影响已做隔离，不能当当前未修复原因。 | 不采用现稿分类及反例。 |
| C5 debt classes | 当前代理 debt 收费对象是 completion data，不是 PTE。PTE 返回抵 data debt 不守恒；用 debt 大小定义 older 也不是年龄。不同返回类别需真实 ID/拍数匹配账本。 | 不采用；不能宣称老类 reserve 保证进展。 |

通用问题：故障、失效或 IOFENCE 不能无条件清掉已接受虚拟请求／已承诺返回的数据与债务。保持外部 VALID 只是必要条件，不是完整协议正确性。静态位数估算未包含地址/属性、前驱、slot、同 ID 队列与路由，不是面积结果。

对 `prior-answer.md` 的两状态说明也收窄：H1 将输入 W owner、物理 W、B 混用，不是真实可达时间线；H2 若 q2 本来就是页表请求，页表优先可能同样选择 q2。只能作抽象待核条件，不能报道“强前作失效已证明”。

## 4. 本轮直接核原文后的边界

原源导航与定位见 `source-audit.md`。Codex 定向核了以下内容：

- Criticality 2013：处理器侧关键性及其与既有 CAS/RAS 调度的组合。通用“先处理能解阻塞的请求”已经很成熟。
- SMS 2012：逐 source FIFO、批调度、SJF/RR、公平与轻载 bypass。两个准备队列不是新增调度思想。
- DASH：按完成内存请求进度／期限和应用强度安排服务。改用 job 完成率或进度反馈，不能单独声称新规则。
- MMU-aware DMA 2018：已有 burst retirement buffer，记录 DMA transfer ID、read/write 角色、地址和响应；按 ID 顺序重试。job tag 与保留物理地址不是独立新意。
- AXI-REALM 2025：可配置碎片长度、完整写 payload 缓冲再发 AW/W、周期预算、阶段追踪。C/D 需超过这些普通组合。
- Arm DMA-350 Issue 04 §5.8.1：完整读返回空间与完整写 burst 数据是普通仲裁资格条件，必须纳入强基线。
- ABW 2015：机构摘要明确自适应 DRAM 写批次长度。这里的 write batch 不是一个 AXI AWLEN；限制宽泛“自适应缩短”主张，但不能据摘要称覆盖 C/D 精确规则。未核正文。
- NB-Walker MICRO 2026：只核正式题录/artifact，全文仍缺。没有穷尽最新前作。

## 5. 下一步规格，不扩实验矩阵

先定向验证 C 的状态可达性与等价性：

1. 复用真实 DMA 链路的 job/读写/TC/PTW 事件，确认源已准备、目的未准备的窗口发生在哪个合法入口；每条状态须绑定真实 job 与字节段。
2. 比较强普通方法：两端先准备、逐读空间预留＋在途额度、页表优先、固定短段／普通压力自适应，保持相同总字节、请求端配置与资源上限。
3. 写出候选 C 与至少一个最强对照的不同决定及可重复预测。只有普通窗口控制能同选同成本，就结束 C 主贡献主张，继续找别的具体切口。
4. 有独立差异后才做一次测试侧小判别；记录 V 耗时、A 完成字节/有效吞吐、额外事务/翻译和空间开销。现成工具能够支持时不另造大框架。不根据本次讨论自动启动 BIT。

本轮没完成上述新实验，不能把这份设计当实验结论。创新、架构和关键分析继续由 Codex 亲自做；DeepSeek 补充证据和独立质疑，不能代替这一步。

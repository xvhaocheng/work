stage111 / Oct7 f9：CPU cycle、TIME 连续性与阶段换算审查

结论
1. 可以在明确条件下按 Dell 校准区间换算两个 ordinary 阶段；目前没有实际 CAPS/RUN 证据，不能填写实际 Hz 或阶段秒数。
2. 冻结源码支持固定率结构：CPU cycle 在正常模式每个主时钟加一；TIME 实际由 OpenSBI 模拟读取 CLINT mtime，mtime 每两个主时钟加一。两者共用主时钟，不是两个独立振荡器。
3. CPU cycle 在 debug_mode 时停止计数，而且冻结新 Linux/OpenSBI 的 PMU 路径可以重新赋值 mcycle。TIME 不受 debug_mode 门控，但 mtime 可由总线写入，复位也会归零。三次 CAPS 正增量和共同率区间不自动证明随后 RUN 没有这些事件。
4. 主时钟的运行时改频、输出停钟没有可用的软件控制入口：实际生成的 MMCM 将 DRP、动态相移及 PWRDWN 系零，输出为普通 BUFG；这支持“固定分频设计”，不能证明板上振荡器无漂移或量化一个漂移界。

TIME / CLINT
19. 冻结 CSR 硬件只有 TIME 枚举（riscv_pkg.sv:556），csr_regfile.sv 没有 TIME/TIMEH 读分支，未知读 :501 抛异常；OpenSBI delegate_traps 不下放 illegal instruction（sbi_hart.c:109-137）。sbi_trap.c:243-247 -> sbi_illegal_insn.c:35-80 -> sbi_emulate_csr.c:69-78 将本 host S-mode 的 TIME 读模拟为 sbi_timer_value()。
20. sbi_hart.c:505-508 检查真实 TIME 支持；sbi_timer.c:144-174 在无硬件 TIME 时使用平台 timer_value；platform/fpga/ariane/platform.c:51-62,162-172 选择单 hart CLINT、64位 MMIO 并以 reference=NULL 冷初始化；aclint_mtimer.c:24-31,54-60,173-203,232-233 实际用64位 load读取 mtime。fw ELF 中 mtimer_time_rd64 的实际指令为 ld a0,0(a0)，没有软件缩放。
21. F 顶层 :733-739 每clk将 rtc 翻转；clint.sv:198-207,239-269 的同步正沿检测每两个clk产一脉冲；:89-94 的 mtime 在脉冲加一。因此稳定运行时 f_TIME=f_clk/2，固定同步管线延迟改变相位，不改变稳态率。这个结构关系可用于理解/一致性核查，不能当独立物理频率校准。
22. clint.sv:89-125,210-218：mtime 增量没有 debug/WFI/CPU privilege/软件 mcountinhibit 门控；MMIO MTIME 写入优先于增量，ndmreset_n 使它归零。CPU暂停而主时钟继续时 mtime继续走。
23. OpenSBI timer_event_start/stop 只写 mtimecmp（aclint_mtimer.c:63-81），不会为了每次中断改写 mtime。sync() 的确存在 mtime 修正写入（:91-110），但该平台传 reference=NULL，:98-99 会返回；普通启动路径没有这个校正。未据此宣称任何 M-mode/调试总线写都不可能；硬件本身仍允许写 mtime。
24. 这些 TIME 数据的实际采样点是 trap 内的 CLINT MMIO 返回，而非 rdtime 指令的首次执行时刻；trap、总线与返回开销没有已测定的固定上界。校准仍适用，因为该实际读点被 Dell 整个 CAPS 调用区间包围。

两段 ordinary 与其他计数器
25. P/source/linux/drivers/misc/idma_finite.h:34-41 先读 CPU cycle，再读 TIME，再读 ktime；这三项不是一个原子 stamp。:678-697 的 stage3 是 swapout phase，stage6 是 restore phase；各自 source now() 的 begin/end 只适合本 counter 的两个真实读点，不保证 CPU/TIME表示同一对时刻。
26. phase :423-459 包含 observer prepare/arm、HPM前后读、batch循环、软件轮询及capture；batch :326-368,404 包含配置、NEXT trigger、DONE/globalquiet轮询和每1024 spins的 cond_resched。CPU/TIME换算结果应称“已插桩 ordinary 阶段经过时间”，不能写成纯 DMA 传输或单纯翻译硬件延迟。全字节检查在 stage4/7，层 ready 在 verify() 中，不能混成 stage3/6 的边界。
27. 本 ordinary 路径只读 CSR_CYCLE/TIME，不写二者；observer prepare()（idma.c:1022-1026）清的是 DMA MMIO observer。finite_hpm() :247-256 的 raw[0] 是 IOMMU IOHPMCYCLES；iommu-hpm.c:38-67,196-218 的 inhibit/save/restore/read 操作 IOMMU MMIO。它们不等于 CPU MCYCLE 或 CLINT MTIME，不会因 observer/HPM 窗口重置而让 CPU/TIME自动归零。该源码结论不替代 RUN 原始记录。

允许的计时措辞与接受条件
28. 至少三条同一新boot/同hart的真实 CAPS，以 Dell begin/end包围；host/calibrate_finite_timer.py:111-173 给全部pair的共同恒定率兼容区间。单独的 sampled-average bounds不要求恒定；用该共同区间转阶段秒数则仍要求运行期间同 counter连续，且瞬时有效计数率保持在所采用界内。
29. 在无reset/写入/停钟、无未涵盖频率漂移的条件下，TIME delta D 的界为 [max(0,D-1)/f_TIME_high,(D+1)/f_TIME_low]；CPU还要求无debug停止和无PMU改写，同式分别计算。公式对应本 counter 的实际读点，不能把TIME与CPU相互替换或硬套2:1解决采样错位。
30. 建议实际结果写为：“冻结 f9 的固定分频实现下，同 boot/hart、无计数器改写/复位/停钟且校准至运行频率保持的条件下，stage3/stage6 的 TIME 原始差额按 Dell CLOCK_MONOTONIC 参考率区间换算为 [a,b] 秒；CPU区间另列并附无debug/无PMU改写条件。”
31. 同时保留 raw cycle/time ticks、nominal kernel ns、校准pair原始输入、独立 Dell 命令包围墙钟和BIT/boot identity。无独立 Dell参考速率误差界时，这只是相对 Dell操作参考秒，不能称有严格 SI Hz或纳秒物理误差保证。
32. 静态结构审查接受：固定分频、TIME来源、WFI/debug差异、reset/CSR写入边界。仍未验实：当前实际新boot/BIT执行身份、真实CAPS频率界、RUN全过程无debug/PMU/reset/停钟/mtime写、短期模拟漂移界。不能把“MMCM控制系零”升级为全部物理稳定性已经板验。

# C：按缺页集合形成消费者完成闭包

日期：2026-10-09。作者：Codex C 关键设计席。范围：机制、纸面构造、关键原文边界与平台可达性；未写/编译 RTL、Linux、BIT，未做板卡或仿真实验。DeepSeek 的日常证据整理见同目录 `c-deepseek-answer.md`，其工作没有替代下述设计。

限定修订：根指出原稿在 B4 已满、consumer ACK 尚未到来时提前发射下一 copy，违反整片容量预留合同。原稿保存在 `c-codex-design-v01.md`；本稿改为下面明确的 dispatch/ACK 时间线。这是纸面时间合同纠正，未运行小模型或 DUT，不是 DUT 失败。

## 结论

建议保留一个正向候选：**把缺少相同翻译页集合、但需要不同数据的多个消费者，组成能真正完成并归还数据缓冲的闭包；按闭包而非单个短任务、热门页或固定 tile 选择下一批。** 候选的关键动作是“哪几个组一起完成”，不是再改 IOTLB replacement/refcount。

纸面上它能作出不同于短组优先加同页预取的决定；下面同 3 次翻译、7 个数据片段、4 片段缓冲的构造给出精确差异。然而 JPDC2025 DARTS 已有“以较少传输解锁多个任务”的非常强近邻。**如果其既有代价与聚合规则已经计算不同 payload 共享的 PTW setup，以及 WRITE 完成与消费者 ACK 的不同释放时间，那么本候选的这部分被覆盖，不能把闭包/密度重新命名为创新。** 本轮进入小模型与前作决定门，暂不送 RTL。

## 1. 要解决的合同

可见窗口最多 W 条已登记 copy 描述符，归属最多 G 个消费者组。一个组只有在其所有必需输入 copy 完成，且达到 CPU/设备可见的完成条件后，才能启动。消费者完成后明确 ACK，归还暂存空间。输入集合必须 sealed；尚未产生的地址、未来组和事后 trace 不可用于调度。

每条描述符仍是普通源 READ、目的 WRITE，数据各读一次，不增加 multicast、不共享不同组的 payload。不同片段可以在同一源页，因而共用一次合法翻译的 setup；其数据字节及目标写入均分别付费。源翻译、目标翻译和暂存数据不是同一种驻留物。

必须分开三个事件：

1. 翻译成功：只能证明相应 context/epoch/访问权限的有效映射。
2. copy 完成：不是原始 source R 退休；必须包括目的写完成及适用的可见性条件。
3. consumer ACK：输入缓冲才可归还；ready 通知本身不释放数据。

对照也拿到同样 descriptor、group、sealed、完成与 ACK 信息；同样 IOTLB/PTW/暂存总预算。软件排序、扫描、通知、微任务提交及缓存维护都收费。

## 2. 一个具体可执行规则

先实现一个有限规则，不求通用 DAG 最优解。参数可取 W=16、G=8；初版只处理每组当前缺页数不超过 2 的窗口，其他组通过下面的公平逃生路径处理。

**状态。** 每组保存完整依赖声明、已完成描述符位/计数、当前仍缺的翻译 key 集合、输入持有字节、ready/ACK 和年龄。翻译 key 含页、实际翻译 context、访问类别及有效 epoch；不能只用 VPN 或物理页。目标 WRITE 若未命中也进入缺页集合，不能免费忽略。

**形成候选。** 将当前缺少相同一页/两页集合的 sealed 组放入一个桶。每个桶按年龄取有限前缀，分别考虑两种页顺序。一个候选的动作计划是：按页服务这些组各自的描述符，同页优先完成已有输入最多的组；完成一组就通知消费者，在空间不足时等其 ACK，再推进下一条。不顺手搬入不属于该候选、又不能在这批完成的组头。

**可准入条件。** 整条计划按真实 WRITE 完成与消费者 ACK 计算的峰值持有量，加不可撤销在途 copy 的已保留空间，必须不超过 B。计划不依赖未来新输入或其他未启动组来释放空间。缺页必须可通过现有正确的权限翻译完成；当前没有 fault recovery 合同的实现只接受正常成功映射。

**选择。** 对每个可准入的桶前缀计算：

`闭包密度 = 本计划可使输入 ready 的组数 / 生产计划持续时间`。

这里的生产计划持续时间从当前仲裁边界算到本计划最后一条输入 copy ready，包括新增翻译 setup、全部 READ/WRITE 片段服务、排队/通知，以及容量不足导致的 consumer ACK 等待。尾部 consumer 服务若可与下一计划重叠，不重复算入这项生产时间；但其仍持有的数据空间必须继续计入下一计划，最终性能仍按实际 consumer ACK 报告。不能只把 setup 与 copy 服务相加漏掉容量停顿。

选择最高者；等分按最老组。固定闭包之后按数量/时间排序是经典批调度思想，**这个分式不是首创声明**。待检验的动作增量是用翻译 key 而非 payload 相同来形成跨组闭包，并把实际消费归还纳入其准入，而不是仅按某个页的剩余引用数或某个任务的剩余长度排序。

**公平。** 每次成功完成其他闭包增加未服务组年龄；超过有限服务次数阈值，选择最老 sealed 组，停止为新组开缓冲，按其自身依赖完成。最大组必须能在 B 中执行，且内存、翻译、消费者最终提供服务。这提供成功服务次数意义上的避免饥饿；外部可以无限阻塞时不声称固定 cycle 上界。不是所有大组都能在 B 内执行，应在提交时拒绝或由明确的拆组语义处理。

**不可撤请求。** 初版规则在软件/descriptor 发射前仲裁，既有 AXI VALID/已接受 AR/AW 不改。改原生前端后仍只能选择新描述符；已发出的 WRITE 数据债和 B 返回持有资源独立计账。

## 3. 精确纸面判别：不同数据共享翻译 setup

构造只有 4 个消费者，全部已知，映射静态且正常。它不是应用 trace，也不是 RTL cycle 结果。

| 组 | 所需数据 | 源页 | 数据之间是否相同 |
|---|---|---|---|
| X | x | X | 独有 |
| G1 | y1、z1 | Y、Z | 独有 |
| G2 | y2、z2 | Y、Z | 独有 |
| G3 | y3、z3 | Y、Z | 独有 |

每页内的不同片段不假设同 cache line，不合并 payload。一个翻译 setup 耗时 L=10；一个片段的完整 copy 服务耗时 d=1，**包括本模型的源数据和目的写入/B 完成**。源 IOTLB 只容纳一个上述源页，源 setup 串行；此纸面模型还规定上一页数据批服务完毕后才开始下一页 setup，未开启 translation/data lookahead overlap。目标暂存位于一个合法常驻热页，不另产生目标 walk。所有策略都使用这项配置。若允许 setup/data 重叠、目标不热或已 materialize 的映射能在 IOTLB 淘汰后继续用，必须把相应资源与时序加入模型，不能沿用表中数值。

消费者可在 ready 后启动，服务 1 单位时间，ACK 归还其两个/一个片段；单消费者执行资源。暂存池共 4 片段单位，**每条 copy 在 dispatch 时预留整片容量，完成后保持占用，直到其 consumer ACK**。边界 t 先记入已完成的 copy/ACK，再为从 t 开始的新 copy 仲裁；从 t dispatch 的 copy 到 t+1 才 ready。t+1 的 ACK 不能给 t 的 dispatch 提供空间。setup 不产生 payload，但下一 copy 仍受真实空位门控。L/d 是抽象服务单位，不是 FPGA 周期。

候选 Y 三个输入至 t13 占3；Z1 在 t23 dispatch，占满4，t24 ready；G1 在 [24,25) 消费，到 t25 ACK 才释放两个位置。因此 Z2 只能在 t25 dispatch→t26 ready。t26 时仍有1个空位，允许 Z3 同边界 dispatch→t27 ready。G2 ACK t27、G3 ACK t28。峰值不超过4，也没有借用未来 ACK。

### 强简单对照：短组优先 + 同页机会搬运

它选 X（只缺一页），完成 X 后允许把 Y 的 3 个不同输入一起搬入，然后服务 Z。对照获得同样已知地址、完成信息与同页批处理能力，因此不是逐元素最弱对手。

`X: 10+1=11`；`Y: 11+10+3=24`；Z setup 至 t34；Z1 dispatch34→ready35；等 G1 ACK36 后 Z2 dispatch36→ready37；t37 还剩1空位，Z3 dispatch37→ready38。

各组 ready：X=11，G1=35，G2=37，G3=38，平均 **30.25**。

计消费者服务后：X=12，G1=36，G2=38，G3=39，平均 **31.25**，整个阶段到 39 完成。

### 候选

X 闭包密度为 `1/(10+1)=1/11`；Y/Z 三组闭包为 `3/(2×10+6+1)=3/27`，分母额外的1是 pool 已满后等待第一个 ACK 的实际停顿。候选先选 Y/Z。

`Y: 10+3=13`；Z setup 至 t23；Z1 dispatch23→ready24；Z2 等 ACK25 后 dispatch25→ready26；Z3 dispatch26→ready27；X setup27→37，copy dispatch37→ready38。

各组 ready：G1=24，G2=26，G3=27，X=38，平均 **28.75**。

计消费者服务后：G1=25，G2=27，G3=28，X=39，平均 **29.75**，整个阶段仍到 39 完成。

**能说明的差异：** 同为 3 次 source setup、7 个不同片段、相同有限数据池，候选改变哪几个消费者先完成；消费者平均完成 31.25→29.75，降低 **4.8%**，X 自己变晚，阶段 makespan 没有变快。这是平均完成/QoS 的 tradeoff，不是宣称全体端到端速度领先。

对这两个固定闭包，生产计划次序比较改为 `3×11 > 1×27`，差6。等价的 setup 敏感性条件为 `3(L+1)>2L+7`，即 **L>4**。按上述实际 ACK 时间线，先 X 的四组 ACK 总和为 `10L+25`，先 Y/Z 为 `9L+29`，差同为 `L−4`；L=10 时相差6，平均相差1.5。如果强映射/暖缓存让有效 L≤4，或扫描通知开销使该不等式反转，这个例子的选择与收益就消失。这是此合同的可否证条件，不是普遍性能定律。

**不能说明的事：** 不能由这个构造证明首创；不能把目标热页或串行 setup 当所有真实系统的事实；不能用平均 ready 改善冒充 makespan 改善。消费者服务很长、后续存在全批 barrier 或单一关键消费者 X 时，先 Y/Z 可能更差，必须按真实目标重新评价。

**根补的便宜强对照确实追平这一项：** 按尚未准备的页出现次数选择，Y/Z 各出现 3 次、X 只出现 1 次；固定同分 Y 先，其普通 hot-page 次序就是 Y→Z→X，按同样容量合同逐项得到同样 ready24/26/27/38、ACK25/27/28/39。这个四组例只能区分 group-first，不能区分这个 hot-page 对照，不能据它直接选择 RTL。

### 和热门页、固定小 tile 的决定也不同

若再加入 4 组 Hi，各需 W 页上的不同 wi 和各自 Ui 上的独有 ui，热门页 W 有 4 次用途，但先只搬 W 不能完成任何组。闭包规则不会将“4 次引用”自动换成“4 个消费者收益”：两页 {W,Ui} 只完成 1 组，密度为 1/22，无容量 ACK 停顿；它仍先选 {Y,Z} 的 3/27。这是 8 组、15 条描述符，仍在 W16/G8 的声明预算内，数据池仍为 4 片段。

给 hot-page 对照一个明确安全实施规则，避免拿死锁弱策略作对手：页按未准备引用次数选，页内按组年龄搬；对暂时不能完成的输入保留一个 incoming 槽，遇到容量限制停止开新组头；可以服务任何能使已有组完成的页。同分固定 U1 先于其他 singleton 页。它仍在 t0 选 W（4>3），W 的 setup10+三个输入3，t13 时 H1/H2/H3 各占1，共3；第四个 W 不发。此时新 Y/Z 头不能破坏 incoming 槽，U1 则可补齐 H1，因此 U1 setup10+输入1，H1 在 t24 ready、t25 ACK。

之后任何第二个消费者至少还需一个此前未准备的 source 页；当前 IOTLB 是 U1，U1 已无剩余输入。即便把这个 hot-page 对照后续动作交给最佳选择，第二个消费者也不能早于 t35 ready/t36 ACK。候选 G1/G2/G3 在 t24/26/27 ready、t25/27/28 ACK。**截至 t28，候选完成3个消费者，安全 hot-page 最多完成1个。** 此构造因此能区分这个具体同预算 hot-page 对照，而不是仅在名字上区分。

这一扩大构造的结论是早期完成曲线，不是所有8组的全局平均/makespan最优；候选后续 Hi 的有限2页闭包可能重复 W 翻译，必须在小模型里完整执行后再报告整体指标。单靠已有三个提前消费者不能外推整体收益。

固定 tile、page sort 可以在某些原序/大小下恰好组成 Y/Z 三组并复制上述结果。**应扫其合法 tile 与页顺序，不能靠一种不利固定切法判创新。** 若它们在真实同预算窗口内已稳定形成同样闭包和同样完成曲线，就不能把这个条件下的收益归于新规则；不是因为“可以想象给普通策略加同模块”而否决，而是需要实际对照决策/成本证据。

## 5. 实现成本与平台最小可达性

W16/G8 的一个保守侧 metadata 估计：

| 侧状态 | 字段 | 位数 |
|---|---|---:|
| 16 条 descriptor | group ID3、page-class ID4、完成位1 | 128 |
| 8 个组 | 两 page ID8、集合大小2、pending count5、sealed/ready/ACK3、age8 | 208 |
| 16 个 page class | 既有 descriptor 代表指针4、valid1 | 80 |
| 当前计划 | group mask8、page ID8、集合大小2、phase2、descriptor游标4、B=32字节额度计数6、强制公平位1 | 31 |
| 合计 | 不含既有完整描述符、context/epoch、权限成功证书与公共接口 | **447 bits** |

这是软件/逻辑侧状态手算，不是 FF 计数、综合面积或最小位数。代表指针必须从既有描述符取得完整 key 并正确比较；不能省略完整 context/epoch 后还声称安全。若既有描述符未含这些值，新增存储需另计。桶枚举、两种页计划、峰值计算、队列通知逻辑和扫描延迟也收费。4片段数据池若片段为8B则32B；真实应用片段大小不同，不能自动套32B。

初版更适合 **软件决定 batch、现有普通 iDMA 执行**，先测决策与提交代价；不新造 gather RTL，也不向现有共享读原型硬塞新合同。最新共享读 source 只接受一个对齐源 2KiB job（`out/shared-read-inflight-join-20261009/shared_pretl_read.sv:366`），其 job_fire 不重新初始化全套 cursor/done。自然 driver 每组 reset 后完全配置两个线性任务（`multi_test.cpp:1284`、`:1387`以后）。它不是现成 continuous scatter/gather/consumer engine。

因此，平台“可修改 RTL/Linux”足以做最终研究实现，但**现版 §78 fixture 不能直接验证此候选**。最小可达路径是现有 DMA 基础路径/提交脚本产生若干普通 copy，小型暂存池由真实消费函数读取全部输入后 ACK；两个策略相同提交方式、相同缓存维护/WRITE 完成合同。先取得应用或程序级 trace及便宜事件模型，再决定是否需要原生 descriptor 前端。尚未确认/运行热 IOTLB 连续软件任务，不把架构可行性写成实验通过。

## 6. 只推进两个决定门

1. **前作与信息门。** 定向核 DARTS2025/2023 的费用与聚合实现：不同 source payload 同 source page 时，能否只计一次翻译 setup，并按这个共享 setup 组成消费者闭包；输入在 WRITE/B 完成后 ready，但只能在 consumer ACK 后归还时，它的计划如何改。给具体原文/代码与一条真实不同决定，不再全面收集关键词论文。小模型必须给所有策略同等 translation/data overlap、普通有限 prepare window/已 materialize 映射与目标翻译能力；当前串行 setup 纸面例不是这些强能力的反例。
2. **真实应用与收益门。** 找一段 sealed gather 的真实阶段，证实：(a) 多个消费者可以独立提前完成；(b) 暖缓存、实际大页/池化/合理翻译覆盖后仍有显著 setup；(c) 地址已知且允许上述跨组顺序；(d) 同页不同数据形成有价值的闭包，普通 tile/pipeline 尚未稳定取得同效。AMR/粒子应用仅是旧地图线索，本轮没有核到四条件同时。

如果这两个门给出真实不同动作、实际净完成收益，以及可承担的侧状态/提交成本，就可以把“翻译类与消费完成的双粒度闭包调度”论证为机制/算法贡献。若 DARTS 同合同已覆盖，不能称 density 或 many-task unlock 创新；若强映射让 setup 近零，不能靠人为缩 IOTLB 支撑真实性能主张；若只有 paper model 有差异，保留分析而不编 RTL。

本轮产出是一个新提出的具体候选、一个可反算的正向构造和两道可执行筛选门。没有首创结论、论文录用/分区承诺或新的 DUT PASS。

# E3：一笔 A 页表响应是否拖住已排队的 V

2026-09-16：本轮实现及定向本机验证完成，软件和 FPGA 完整构建均退出0、清单passed，BIT/MCS非空；尚未上板。配套文件见[交付入口](README.md)，新内核为 `6.5.0-rc2-00084-g94a519eebf07`。沿用 DS50/50、V=DMA0/DID10、A=DMA1/DID11、4KiB 硬件批量和 CPU 整批轮询。

## 实验在问什么

v3 发现 A8 下 V 的 IOMMU 内部等待增加。本轮把同一笔请求拆成：TR 接收→共享控制器选中→翻译请求握手→翻译响应握手→COMP 首次有效。另锁存第一次 IOTLB 查询结果，不把页表遍历完成后的命中误当首次命中。

当 V 读请求已经排队，A 的正常一级翻译第一次查询缺失时，只选择一笔 A PTW 返回数据。D0 和 D128 都经过同一个响应寄存器：从接收到首次可供 PTW 使用分别为 1、129 周期。每窗口最多一次，128 周期在 50MHz 下为 2.56μs。只改变这笔响应，原全局 DS 延迟不变。禁用/异常退出不会丢弃已缓存响应。

观察 A 服务被延长后，同一笔 V 的排队是否跟着增加；同时看 V 自身翻译和出口段是否变化。整个批次耗时不是主要判据。V 首次查询命中发生在最终获得服务时，仍不能单独证明它在最初排队时就能命中。

## 两轮为什么放进一个调用

新程序 `idma_e3_pair` 使用 ioctl 0x09，在一次映射/分配生命周期内运行 D0、D128 两轮，可反向。每轮都预热、测量、排空、核验，轮间重新填充源/目标缓冲并清理软件状态；两轮结束才解除映射。固定物理地址不等于两轮缓存/到达次序完全相同，因此仍须核对记录，不能只相减平均时间。

首轮失败就不运行第二轮；无法确认排空时沿用 quarantine 和保留映射。没有触发也保留结果，不自动重跑。程序返回 success 仅表示正确性及观测检查通过，不表示因果假设成立。旧 `idma_experiment --batch` 接口保留。

## 上板步骤

必须同时使用本轮 BIT 与 SD payload。程序位于新 rootfs 的 `/usr/bin/idma_e3_pair`。保持收集完整串口和 dmesg，每轮仍输出同 seq 的 3 条 batch +16 条 path；配对程序在两轮结束后向 stdout 输出一条 `idma.e3_pair.v1` JSON，包含两轮原始 E3 数据。失败 JSON 也保存。

先做三项配对短验收（每项含两轮）：

```sh
idma_e3_pair --aggressor none --transfers 8 --warmup 0 --first-delay 0
idma_e3_pair --aggressor 1 --aggressor-pages 1 --transfers 64 --warmup 32 --first-delay 0
idma_e3_pair --aggressor 1 --aggressor-pages 8 --transfers 64 --warmup 0 --first-delay 128
```

Solo 应无触发，预热 A1 用作阴性控制；A8 短测允许 V 首查缺失、允许没有触发，但不据此判断因果关系。核查每轮数据错误/quarantine=0、观测无错误、256 字段完整、同 seq 日志齐全。发生真实错误立即停止；没有触发不是错误，也不补采。

短验收通过后，仅固定角色做 10 对 A8、2 对 A1，V=1页、4096项、warmup256，首轮 D 交替。按第1～5对 A8→第1对 A1→第6～10对 A8→第2对 A1顺序，避免把控制全放在末尾；A1 两对各用一次 D0先/D128先。

```sh
idma_e3_pair --aggressor 1 --aggressor-pages 8 --transfers 4096 --warmup 256 --first-delay 0
idma_e3_pair --aggressor 1 --aggressor-pages 8 --transfers 4096 --warmup 256 --first-delay 128
# A1控制：同样参数，仅 --aggressor-pages 1；共两对。
```

不扩页数、不换角色、不因无触发/首次缺失/顺序不同而替换样本。A1控制预期无正常热态 PTW触发，实际不符也原样保留。

## 读数约定

observer magic v4=`0x49444d414f425304`。MMIO 0x70 选择索引，0x78 读值。旧0～34/64～191字段不变，E3 位于192～447。JSON `e3_words[k]` 对应索引192+k。所有时间是 50MHz 周期；E3时间戳从 ARM 后计数，旧硬件窗口是首项 issue 到末项 done。不能将并行累计时间相加。

| E3相对索引 | 含义 |
|---|---|
| 0～3 | E3格式magic `0x49444d4145330001`、错误位、触发数、配置D |
| 4～9 | 响应接收/首次可用/实际消费时间、实加周期、S1层级编码、PTE物理地址 |
| 10～16 | V/A请求序号、触发至V选中间插入的其它选择数、可用/消费标记、控制器状态、排队V数量、ARM至冻结周期 |
| 17～20、21～24 | Vr/Vw/Ar/Aw 首次命中数、首次缺失数；仅窗口内查询 |
| 32～63、64～95 | 触发A记录、目标V读记录 |
| 96～223 | 4 lane ×4内部阶段 ×8字段 |
| 224～239、240～255 | V/A COMP写事务汇总 |

一条请求记录的0～13：每lane请求序号、AXI ID、DID、IOVA、事件位图、TR/选中/翻译请求/首次查询/翻译响应/COMP首次有效/返回时间、首次命中结果、是否写。14～31保留0；位图0～6表示七个时间戳是否存在。首次查询结果0=缺失、1=命中、2=未观测。A返回可能在窗口外，缺位不填造时间；V记录必须完整。序号从ARM起按lane独立计数。

内部阶段每8字段沿用 v3：进入、全在窗口内完成、跨入窗口后完成、完整样本时间和、最大值、窗口开始在途、结束在途、在途数量积分。V全量每lane预计2×transfers笔（单项4KiB拆成两笔AXI），A首尾在途单列。

写汇总每16字段：窗口AW数、B数、完整三点样本数、跨入样本数、WLAST早于AW数、非负AW→WLAST和/最大、WLAST→B和/最大、AW→B和/最大、结束未完成AW数、结束已WLAST但未AW数（全局，仅V行有值）、开始未完成AW数、两个保留0。W无ID，依AW/W各自全局顺序及B每ID顺序配对；不拿不同接口的时钟点拼接。窗口内V AW→B和必须等于v3写stage3，早到W单列，不能机械拼两段均值。

软件验证magic/状态/守恒/窗口/延迟精度/轨迹完整性；触发样本须为A首次缺失且V已排队。比较时额外核对两轮A/V身份/序号/IOVA、PTE地址及层级、插入次序、V首次命中结果。无触发、V首次缺失、顺序改变分别分类，完整保留。

主读数同时报告 `V选中−PTE响应接收`（触发后的剩余等待）、`V选中−V的TR接收`（完整排队）、`V翻译响应−V翻译请求`（自身服务）、`A翻译响应−PTE响应接收`（A剩余服务）。先比较触发前V已经等待的时间、A此前服务时间和队列状态，再比较两轮差值。即使请求序号一致，触发前历史也未必一致；不能把前史差异算作128周期的作用。有其它请求插入时，当前记录只保存数量，不保存它们完整身份，不能仅凭数量相同声称中间顺序相同。

## 范围和证据

选择条件限定正常未翻译R/W、DID11、仅一级翻译、排除隐式上下文和MSI路径。观察器仅接受DMA0/1的私有ID0（共享侧ID0/4），每lane队列深4，COMP写全局槽8、每ID槽4；溢出/身份不符使结果无效。32位时间戳溢出使结果无效；CLI限制每轮60秒、最多4096项。

本机测试包括真实延迟/观测RTL、旧observer与frontend联测、抽取真实驱动的双轮/异常退出模型、CLI及rootfs检查。日志位于 `out/e3-service-20260916/`。模型不等于完整IOMMU压力仿真或实板验收。时钟/CDC/IO原审查边界保留；按用户要求不读取成功构建日志或时序报告。

# §44 后的单一判别：保存容量、重复工作与持续进度

状态：规格已审定；未执行模型、DUT、构建或实板。本文件不是已成立的新机制或定理。

## 先固定一个可以证伪的合同

先选两个设备、共享一个可切换执行的 PTW、每设备一个已接受普通译址请求，S-stage Sv39 / G-stage Sv39x4；静态 mapping、无 A/D 写，PTE 事务均正常且有限服务。终态的 fault/result 必须完成或用双方同计的存储保存；不人为压低接收端 ready。有限请求与持续供给的结论必须分别写。

在 `C` 中只能保留双方同样需要的原请求、context、根和身份，不能把新进度塞入 C 后不计费。计 active 与 suspended state、全部共享 PWC/结果/归属/allocator 的实际容量；用参数化合法物理地址范围，不能把支持 PAddr56 自动当 FPGA 真有全部56bit可用内存。

“让路”是下一次新 PTE first offer 被切换，当前不可撤请求仍需退休；不是最终 DMA/job 完成。工作量先计 PTE 请求与重复请求，不将它们直接换成 DDR 周期或带宽。若讨论固定时间，还须加入可证的服务界。

## 比较已知具体点，而不是弱基线

1. 整 walk 完成后换设备。
2. Rocket-style 每 PTE continuation：公开父/leaf复用、current table PPN、原请求索引/等级恢复；本特定成功路径普通帧上界82bit，C/token/terminal另计。
3. Whole restart：保留原请求，在安全边界丢全部进度。
4. Partial G restart：保存 S-semantic target/leaf，本特定普通帧上界36bit；每次最多额外3笔G读。若要求持续进度，必须显式给G+S最多4笔的连续运行机会、有限暂停次数，或其他可核查规则。
5. 同总容量的 PWC/partial translation，允许合法共享、缓存优化和复核；不得假定它永久命中，也不得无理由禁止它保存候选相同的进度因子。

82/36是手工上界，不是最小编码或综合资源数字。完整IOTLB逐bit相同不是自动的架构要求；双方都允许合法 skip-fill / 提前形成权限 verdict / cache 优化，仍须同最终权限、错误优先和失效合同。

## 最小分析动作

建立同一个15-PTE正常路径/可达phase图，逐条标注：哪些量可由C与已保存前缀恢复，哪些必须重读；各暂停/恢复边的存储与重复工作。先用两个常驻请求检查反复让路时，是否每请求都有单调完成进展，或依赖连续运行窗口。然后才问这个状态图的最优点是否只是在上述普通构造之间选择。

必须保留两类反证：

- 地址/权限不同而保存状态相同、以后输出或合法fault须不同的不可区分见证；注明缓存合同和合法地址范围。
- 两次/重复正常G-root服务仍没有S推进的 restart 见证；不能用“memory公平”代替“请求完成”。

这一动作尚未执行，不自动授权推导已经新颖。不先改Linux/生产RTL/全量BIT，不先阈值扫描。

## 接受与停止

如果得到了前作未建立的、条件完整且紧的容量—重读—持续让路界，或达到该界并超出上述具体同预算对照的规则，就可以继续作为独立分析/机制贡献；仍需核最强primary和最小模型。

如果结果只是普通帧字段精简、选择已知checkpoint/restart、一般restart livelock或不同保障条件之间的数值比较，就不能称独立创新，停止此分析枝。源文件没写出某个位数、模型三席赞同、或弱对照性能差，都不是通过条件。

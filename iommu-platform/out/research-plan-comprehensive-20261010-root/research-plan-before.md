# 多 DMA 共享 IOMMU 研究计划

日期：2026-10-10

**入口说明。** 本文件是当前计划总入口。旧 [research-convergence-plan-20261010.md](iommu-platform/docs/research-convergence-plan-20261010.md) 是详细场景参考；[workflow-framing-20261010-root.md](iommu-platform/docs/workflow-framing-20261010-root.md) 是 Sobel 补充候选。本文不推翻既有路线裁决，只整合可执行顺序。

## 1. 核心目的与主干

核心目的：沿“原 Remote PTW 对单 DMA 的代价 → 多 DMA 共享同一 IOMMU 时翻译代价如何传播为跨设备共享干扰 → 在合法可观察信息或动作下改善 V 真实完成并保留 A 有效进度，并解释原因和完整成本”的主干，形成有独立增量的方法论文。

- 原起点：远端页表遍历给单个 DMA 带来的代价。
- 当前问题：这些共享服务代价怎样传播到其他 DMA。
- 机制问题：容量保护何时足够，何时还存在普通服务或准入未覆盖的完成进度损失。
- 方法目标：可观察的信息或合法动作能否改善同资源下双方完成与成本关系。

## 3. 地图收敛

- **主问题**：共享干扰与服务顺序。重点看跨 DMA 的翻译干扰、合法服务点、完成进度和准入决策是否留下普通控制未覆盖的差异。
- **支撑**：翻译覆盖和软件映射。用于强简单对照、公平基线和成本边界，不并列为另一条主实现线。
- **不并列扩张**：迁移、间接访存、GPU 分配等不因地图存在就自动展开。本轮关闭扩展不自动恢复：宽泛软件布局、固定 A8 p5 重试、共享载荷或在途加入、晚选目的、裸 walker continuation。
- 采用旧收敛计划已选五篇核心表，列出它们回答的对照问题。

| 核心前作 | 它回答的对照问题 |
|---|---|
| MASK，ASPLOS 2018 | 合法控制点、翻译与数据竞争、翻译优先、应用公平；不能把 GPU warp token 当 DMA 提交额度。 |
| Scheduling Page Table Walks，ISCA 2018 | 完成后才有用的分组不是新规则；若只是源或目的成组或完成优先，须比较同样有组信息的完整普通策略；GPU SIMD 组不等同跨设备依赖。 |
| ICCD 2018 TLB prefetch 与 MMU-aware DMA | 缺失请求留在源端、预取、缺失重试已有直接前史；若准备、暂停或重试，须比较合同与成本；不能任意撤回已公开 AXI VALID。 |
| KPart，HPCA 2018 | 动态容量管理和容量保护不等于性能保护不能单独作创新；不是可直接移植的 IOMMU 算法。 |
| Bermuda，RTCSA 2025 | 支持问题实际意义，不能再宣称首次发现 IOMMU 干扰；其缓解评价空缺只代表该文范围，不能证明无人做过。 |

## 4. 固定首轮工作流与真正约束

首轮使用参数化固定目的微基准，不是已部署应用。以下为计划，不写已测。

- V：DID10，固定一对页循环完成 64 次 4 KiB COPY，完成后下一次就绪。
- A：DID11，源与目的各按既有 A8 页环轮转，独立完成 64 次 4 KiB COPY，完成后下一次就绪；这些是拟定输入，地址和接口可用性在运行前登记。
- 释放：两路首任务在共同逻辑起点就绪，后续由同一完成依赖程序产生；gate 等待计入时间，不能固定为旧运行的完成时间回放。
- 任务目标：以全部固定工作量实际完成时间和双方取舍作为目标；不捏造硬 deadline。若主张周期期限，必须接入有来源的单独 deadline 工作流。
- 约束：固定地址、数据、权限、映射寿命；初例 S1 静态、S2 关闭；正常读写与 B 完成、已承诺 VALID 保持稳定、同 ID 次序、实际资源预算；warmup 与初始状态在执行前登记。
- 公平：允许双方同等合法提前准备、大页、缓存保护、已有缓冲；大页和额外缓冲算真实存储与权限成本，不为维持缺口禁止它们。
- 首轮不假设四个 walker 或四个可调度翻译槽。
- Sobel 补充：不能成为并列实现主线；其 2 个叶映射是有条件几何事实，即物理分配和权限允许、S2 关闭、静态映射且条目保留条件下，V 可能只需两个 S1 叶翻译条目；当前驱动按 PAGE_SIZE 映射，未实现或验证，实际性能缺口未测，不能记成 12.85%，也不能断言为零。

## 6. 公平基线与实际执行边界

- 复用 S、P、N、PN 结构及独立简单控制；对照规则、信息、初态、阈值、资源、选择办法在运行前登记。
- 旧 p1 至 p5 用 V 完成反馈调预算，p6 反馈调 gap；不能写成全静态。gap 是完成后等待，额度是未完成请求上限，二者分开。
- 当前 composition `PolicyEnable` 默认 0；源码存在不等于该 profile 已接入，未接入要计适配。
- 普通 PTE 服务选择只在合法可改动的服务点；行为 DDR 重排不冒充实板 MIG。
- 可用额度只枚举接口核实后合法的 1、2、4、8 上限；这些是条件选项，不是已建立的原生能力。
- 切换模式需 `quiet` 且合法配置会产生 `clear`；若切 S、P、N、PN，必须计排空、配置、冷缓存及重热成本。
- 从逻辑就绪到可消费数据完成计时，包含准入等成本；保持已承诺 VALID 稳定、权限合法、真实读写/B 完成和同 ID 顺序是协议条件，VALID 不是一个可累计完成阶段。
- 同时报告两路任务进度和完整成本；服务上限必须让 A 最终完成，不以饿死 A 换 V 改善。
- 已有基线不可用时先报告缺口及最小适配，不悄悄换成弱版；候选完整规则的等价实现作消融，不作独立前作；逐场景事后最优只作解释上界。

## 7. 条件式贡献假设与 H0/H1

**待证条件贡献假设**：如果在合法可达状态，普通调度、反馈与提前准备之后，仍留下与 copy 关联的翻译/数据完成状态相关的可达损失，那么在合法准入点观察与 copy 关联的翻译/数据完成状态，并暂停或恢复新的后台 copy，可能在计入观察与控制成本后改善匹配强对照下的 V/A 完成与成本关系。这只是待检验的筛选假设：这版候选未实现，剩余损失与收益待测；机制新颖性另需精确的最近前作比较。

- H0：普通 P 或不分区、服务优先、额度或已有反馈足以覆盖目标；PN 变慢仅为普通竞争或实现选择。
- H1：在合法可达状态，常规控制缺少的具体翻译或数据完成状态改变最佳准入决策，并在完整成本后带来实际双方收益；目前只是待检验假设。

**相邻反例**：若卡片所指的共享服务冲突消失，或普通准备、保护或调度已经消除该冲突，该候选的预期优势应当消失；全热翻译本身不能证明数据或服务竞争已经消失。

成功判据：在同等有来源的 V 要求下 A 有效工作更多，或在同等 A 进度要求下 V 更快，或在相同任务服务下实现成本更低；没有应用阈值时比较 V/A 完成时间取舍与成本，不要求双方严格同时改善。性能增量与准确前作比较下的机制新颖性分别裁决，不凭性能差就认定创新。

成功与失败如何改计划：

- H1 获得可重复支持，且有符合预测的反例与完整成本，进入 G2 或 G3，再决定最小原型。
- H0 成立或普通控制覆盖目标，停止对应性能主张，保留平台、基线和负结果。
- G0 失败，即只能写 PN 慢或换术语，停止主线 A，不启动新诊断工程，不扩夹具。
- 技术错误先有界修正，不能当科学阴性；新证据否定后最多两次有明确修正对象的调整，无新增证据停止。
- 备选 B 只在同一合法工作流有阶段变化且能指出现有反馈实际作错的决定时激活，不能自动接续。

## 9. 已有结果复用与范围

- 复用 P、N、PN 板测、P4M、E2、E3、method88、在途加入、round05 等已有结果，但按原始 record、BIT、boot、配置、页大小、窗口、工作量和采集段分别登记。
- 不把 PN 差额当新空间；PN 比 P 慢是可继续解释的反例，不是候选收益本身。
- 不重跑 method88 找优势。method88 只否定固定 A8、target170、该版 p5 对匹配强基线的额外收益主张，不能推广为所有翻译感知控制无用；需要时只引用已有范围。
- 已有基线不可用时报告缺口及最小适配；不把已有旧结果直接当新候选对照。
- 不同组别的数据不可混用。

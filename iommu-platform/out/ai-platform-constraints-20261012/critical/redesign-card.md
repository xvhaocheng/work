# R107：KV 恢复依赖下的共享翻译控制（条件保留）

裁决：保留需求与可控制位置，不注册 G0，不选择 G1 规则。它是对旧共同就绪冷准备前提的具体重设计；不是已成立的新方法。

## 真实问题与工作边界

固定 vLLM v0.1.0 的多序列 group 进入换出分支后，恢复必须保留全部唯一共享 KV 槽，并在每层覆盖／消费前完成该层搬运。K/V 整池常驻，槽编号与引用计数动态变化；释放槽编号不撤销整池映射。源码的同 stream 次序、每层事件、refcount 已承担现有安全动作。

因此研究对象可以是一个有限恢复阶段里，两个实际 iDMA 搬运不同 head 分片时的层数据就绪与整组完成。GPU tensor-parallel 来源只支持分片含不同有用数据；在当前 FPGA 上由 DID10/11 回放恢复，是另需验收的适配，不能写成原生 GPU 运行或已经证实的共同主机 IOMMU。

若使用两分片同一层的最大完成时间，它只表示该层搬运数据都已就绪；没有实际计算／通信时序，不能把它称为 attention 开始或 token 完成。一个分片早完成也不自动等于全组收益。

## 已增加的认识与尚待选择的动作

旧合同只有共同 ready0 的连续冷权重包。本卡增加有来源的槽存活、共享去重、恢复义务与每层 use 屏障；这些信息在源级当前 copy issue 前可达。它们能约束准备和发出次序，但尚未证明普通方法会因此失败。

若后续证明有残余损失，待设计的问题是：在实际首个 issue 前，用本次恢复集合与真实消费依赖安排共享翻译／copy 的服务，同时保留另一分片完整进度。具体控制位置和规则必须由损失位置决定；本卡不预设 ADMIT、预翻译或新的 walker 接口。仅在下一 copy 才到达的信号不能改善已经发出的 copy。

## 可证伪的正例条件

以下是必须提供的实例事实，不是允许人为加入的限制：

1. 一个有限恢复实例给出真实唯一槽集合、两端地址／字节、不同分片、所有者、依赖与自然结束。选择换出分支的理由须明确；若主张容量迫使交换，应比较真实 live 占用与合法 residency/admission，不能拿保守预留启发式当物理不可避免性。
2. 当前 FPGA 的两个真实 requester、共享翻译路径和资源模式被核实。任何研究回放及其产生数据／消费代理均显式标注；不猜计算周期、到达或 deadline。
3. 稳定池预备、合法大页、批量、整任务合并等对照全部保留。它们的资源、映射、缓存交接、完整恢复和排空成本计入后，仍存在影响有效完成的翻译相关等待。
4. 待用信息在当前首个 issue 前可见，并存在能改变该等待的合法控制位置。若只是当前 copy 内部被阻塞，而现有控制只能延迟下一笔，则该控制位置失效。

四项闭合后才能登记一次最小 G0。G0支持具体缺口后，才设计最多两条不同规则；本卡不自动安排新矩阵。

## 相邻反例与关闭条件

- 单序列采用源码默认重算，没有本卡的恢复 copy；或者合法驻留／admission 已满足目标。
- 稳定池映射可提前准备、合法大页覆盖且没有剩余翻译等待。逻辑块不同或回收频繁不能改变此反例。
- 普通按层 copy 与 event 已解决 release/use；仅把它们复制成新控制没有新增能力。
- 合法单 DMA 合并完成目标，所谓独立所有权限制没有来源，或收益只来自禁止它。
- 只有人造计算 delay、任意增压、先限定 4KiB 或删除后台完整工作量才得到正例。
- 改善上界小于准备、切换或控制最低成本，或信号晚于可执行控制时点。

这些条件关闭本卡对应主张，不否定共享翻译问题，也不自动把方法论文改成表征论文。

## 全部工作量与成本

设真实字典去重后槽数为 N，本 worker 层数 L、heads H、head size D、tokens/block B、dtype 字节 e。一方向物理搬运为 `2×L×N×B×H×D×e` 字节，原实现有 `2×L×N` 次 memcpy；恢复加换出至少两倍字节。尾槽未填满部分计搬运成本，语义 useful KV 按实际存活 token 另计；共享槽不按 beam 数重复计。不能套用旧六张量或 64＋64 参数。

成本覆盖整池／模型／activation、分配／pin／map／页表与同步、合法大页失败回退、初始化、额外 staging、descriptor、COW、CPU供给、缓存所有权、事件、双方完整恢复、drain、unmap/free，以及新增控制资源／延迟。数值未知处保持未测，见 [cost-and-control-inventory.json](cost-and-control-inventory.json)。

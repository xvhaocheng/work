# §42 Codex runtime pause/drain contract

Purpose: one controlled real two-DMA RTL comparison on the §39 ordinary prepared physical source bypass. Fixed normal mappings, CONF1 decoupled read/write, ParentDepth4, private payload24B/DMA, same bank, existing TC resources unchanged. Test-only out copies; no production, Linux, BIT, board, SD or old DUT rerun.

Controls: `pause_a_i` closes NEW A AW before the shared mux and NEW A private raw parents outside committed destination prefix. `pause_reads_a_i` additionally closes only NEW A source-child admission, leaving previously offered/accepted children intact. Mode1 is finite diagnostic pause with both controls asserted; mode2 ordinary strong control closes AW and lets committed writes receive necessary source data. Both controls resume after the same finite window; the standard complete-copy/guard/owner/quiet checks remain.

AW safety: preserve gate-output AW seen VALID without READY in the previous cycle, including arbiter lock before mux w_fifo_push. Gate both VALID and backward READY. Already visible AW may push after request and extends the final debt frontier. Keep all W/B/R and downstream AW live; observe full AW stability. Stop only new background prepare candidates outside the debt prefix; do not invalidate parent/cache validity, abort prep_offer/slow responses, or assert whole-parent retirement.

Trigger: first real pre-edge state with A internal virtual offers>=4, offers>physical WLAST, and A committed end>source returned bytes; after both real jobs have issued. C++ sets pause inputs at that cycle's next evaluation/edge and snapshots the same counters before the edge. No forcing registers or synthetic token order.

Observe actual internal w_fifo_push (not CSV vaw handshake), both W owner prefixes, gate-held AW, offered/busy source child, accepted A source parent count, new source child count/bytes, R bytes delivered to iDMA, physical W bytes/WLAST and physical pending B. Track A background prep_offer/slow too. Quiet means no committed A AW awaiting physical WLAST, no pending B, held AW, source offer/response, or A background prepare. Private parent/cache suffix may remain; full job need not retire. This is successful shared-write release in this static configured prototype, not generic cancellation, fault/invalidation or bounded DDR response proof.

Runtime inputs: `pause_a_i`, `pause_reads_a_i` (bool). Debug outputs: `dbg_pause_a_offers`, `dbg_pause_a_wlast`, `dbg_pause_a_bpending`, `dbg_pause_a_children`, `dbg_pause_a_parents` (32bit); `dbg_pause_a_end`, `dbg_pause_a_rbytes`, `dbg_pause_a_wbytes`, `dbg_pause_a_childbytes`, `dbg_pause_v_rbytes`, `dbg_pause_v_wbytes` (64bit); `dbg_pause_a_held`, `dbg_pause_a_read_busy`, `dbg_pause_a_prepare_busy`, `dbg_pause_a_quiet` (bool).

C++ options: `+pause-mode=1|2` required in this matrix, `+pause-offers=4`, `+pause-window=10000`; active only for natural full-copy runs. Four runs: mode1/mode2 × first V/A. Log one JSON snapshot each at request, sealed debt after gate-held drops, first A quiet if reached, pause end, terminal full acceptance. Include original g_cycle and existing TL/PTW counters. Preserve the natural byte/guard/geometry/R-identity/held/drain scoreboards. Mode1 may fail to quiet DURING pause but must pass complete copy after resume; mode2 must quiet during the window while A original job remains unfinished. Record all diagnostics rather than silently treating missing events as success.

Functional control state is at least 65 bits: one AW held bit plus the 64-bit A frontier register used by raw/prep eligibility. Saved observation header/counters are additional diagnostic state; no synthesized area claim.

Analysis gate: minimal future source return bytes for this sequential successful write prefix is max(0,sealed_end-R_returned_at_request); separately report already offered read bytes and NEW child work after request. Equality measures a work bound for this snapshot, not an independent mechanism or a cycle bound. Ordinary drain is the strong control; if it meets the same guarantee/cost, this cannot establish independent mechanism innovation. Next research needs a tighter/general bound or a real same-resource tradeoff beyond the ordinary control and prior art.

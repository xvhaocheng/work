# 独立批评：E2/E3 并行计划、因果链与创新门槛

> 边界声明：本轮只读你给的 4 个文档 + 4 个 RTL 文件，不做代码、构建、仿真或上板，不联网，不新增文献细节。所有文献定位只沿用 `paper-logic.md:113-115`、`:167-170` 已写出的内容，我不判断也不保证新颖性。凡标【假设待核】的，说明我在给定文件里找不到依据。

## 0. 导航摘要

本轮只审计划，无新实验。核心判断：E3 的有限机制结论可保留，但“64B 人工延迟→4KiB 业务损失”缺三步定量桥；同时 A/V 速率近似互换、合并吞吐 217–228 MiB/s 近守恒（`RESULTS.md:41`/`:44`），数据路径/内存共享是尚未排除的强对手。E2 的容量阶梯在“V 暂停→空闲条目被替换”语义下近乎同义反复，阳性弱、阴性强，且动机来自单样本 b15-g0（整轮 miss=2、相位未知）；IOTLB 命中会改写 PLRU（`rv_iommu_iotlb.sv:337`），“只读快照并非无扰动”。N 不是加槽：单 FSM＋队头＋等下游 accept（`trans_ctl:616`/`:711`、`tl_wrap:871`/`:149`）意味着重构；且必须冻结“保持 FIFO 交付”还是“跨 ID 乱序交付”，否则 V 的等待会从翻译搬到交付。创新候选 R 目前是瓶颈分析＋调参，缺负向对照与超额预留对照。仅 3 项为前置门槛，其余可并行。

## 1. 八条可能推翻计划的质疑（按严重性）

### Q1 「翻译干扰」定位可能被“数据路径/内存共享”整体推翻【只影响定位，但决定是否继续】

- **来源**：`RESULTS.md:41`（V 速率中位 108.813／150.603／171.389）、`:44`（A 速率 108.813／75.301／57.088）。两者之和为 **217.6／225.9／228.5 MiB/s，离散度 5.0%**；且 gap0 的 V 与 A 中位数完全相同（108.813）。
- **最强反例**：两路只是公平共享一个约 218–228 MiB/s 的数据路径/内存上限，`gap` 是“需求重分配旋钮”。此时 V 变快只因为 A 主动少要，不需要翻译机制参与；N/P 都不解决任何东西。
- **能回答的证据**：`experiment-plan.md:96` 的 BARE 对照（未构建）；或更便宜的一个点：A 走 BARE/不做翻译、V 正常，看 V 是否仍随 A 的供给变化。次便宜：把 A 的每作业时间与“仅软件 gap”预测对比（gap1000 = 20 µs 空档，而 A 实际每作业 51.9 µs，多出的 ~32 µs 才是争用成本，`RESULTS.md:40`/`:44`、`:42`）。
- **失败后改路线**：把论文问题改成“共享数据路径＋有限翻译资源下的进度分配”，翻译从“主因”降为“其中一条通道”；N/P 不立项。
- **备注**：这是中位数之和不是检验，A 的“字节”不是 AXI 字节（`RESULTS.md:419`）。所以它不是结论，是**红旗**，但不查它就去写 N 是赌博。

### Q2 E3→E1 的定量桥缺三步，现有证据只到“存在性”【可并行，决定 E3 在论文里的角色】

- **来源**：`e3-controlled-results-review.md:59-68`（4 对 cold 互补，ΔV 剩余等待 {127,129,129,130} 与注入量 128 周期同阶）；`RESULTS.md:39`（V 窗口周期中位 7352029.5／5311994／4667742 ÷ 4096 → 每搬运 **1795／1297／1140 周期**，gap0 与 gap2000 差 **655 周期/搬运**）。
- **最强反例**：E3 用的是 **单次 128 周期人工延迟、64 B 诊断、N=4 对、单次启动**（`review:78`），而 P4M 的每搬运差是 655 周期。若自然 PTW 服务时间与碰撞次数按实测代入后差一个量级，E3 就不能作为“收益量”的动机来源。
- **能回答的证据**：至少两项，且都不要求大矩阵——
  1. **A 侧 S1-PTW “活跃周期数”**（不是事件数）。RTL 里 `rv_iommu_ptw.active_o` 已存在（`tl_wrap:639` 已接成 `e3_ptw_active`），只差把它变成可读计数。有了它就能算 walker 占用率，直接给出期望碰撞次数上限。
  2. 一次粗略核算：A 整轮 `s1_ptw` 约等于 A 整轮完成数（`RESULTS.md:54-57`），说明 **A 几乎每次翻译都 miss**；若单次 walk 约千周期量级，busy fraction 可达 ~70%，那么“V 每次搬运 2 次翻译 × 碰撞概率 × 单次代价 ≈ 655 周期”在数量级上**可能**闭合。这是可检验的数值预言，不是证明。
- **失败后改路线**：把 E3 明确降为“机制存在性”证据，方法动机改为直接测 V 的**额外等待**（逐阶段 stall 桶），不再从 128 周期外推。
- **注意**：`paper-logic.md:186` 拒绝为 E3 增加延迟强度（只有 D0/D128），我同意不做全新矩阵；但要接受其代价——这条桥就只能保持定性。把 `rv_iommu_e3_delay` 的 128 改为参数、加 32/64 两个点，是“把存在性变成比例律”的最便宜手段，列为可选项，不列前置。

### Q3 N 的**顺序策略**未冻结，可能使“非阻塞收益”根本不存在【前置门槛】

- **来源**：`rv_iommu_trans_ctl_wrap.sv:616`（只有 IDLE 才 select）、`:637`（AR 在 AW 之后）、`:683-693`（AWAIT_RESP 持当前请求）、`:706-717`（COMPLETE 用 **AR/AW FIFO 队头** `ar_data`/`aw_data` 配 **单份** `trans_resp_data_q.spaddr`，且要等 `axi_comp_resp.*_ready` 才弹队头）、`:323-347`、`:101-102`；`rv_iommu_tl_wrap.sv:871`（`unique case (state_q)` 单请求 FSM）、`:149-151`（下一请求准入绑在响应被取走）。故**交付严格按 FIFO 顺序，翻译只对队头发生**。
- **最强反例**：若 N 只做“**管线化翻译、保持 FIFO 交付**”，V 的 miss/hit 在 A 之后，V 的翻译可以早完成，但**交付仍要等 A 交付完**。此时 E3 会测到“V 不再等翻译、但仍在等交付”，计划自己的判据 `paper-logic.md:178`（“把等待搬到结果出口不算解决”）就命中，而你会误得结论“N 不足 → 需要 P”——真实限制是**排序策略**，不是容量。
- **能回答的证据**：设计卡必须先写清：**保持全局 FIFO 交付**，还是**仅对同一 AXI ID 保序、跨 ID 允许乱序交付**。若选后者，还要处理：单队列里混着所有 ID（`aw_data.id`/`ar_data.id`）、per-ID 顺序的判定、以及 `paper-logic.md:161` 已指出“DID≠order-domain”的安全条件。然后必须在 E3 受控场景测**两个桶**：`t_request_presented → t_resp_fire`（翻译等待）与 `t_resp_fire → t_comp_accept`（交付等待）。
- **失败后改路线**：若设计卡只能选“FIFO 交付”，那么必须老实承认：对“V 排在 A 之后”这一相位，N 不改善 V；P（预留容量）同样不改善；此相位应从方法宣称里剔除，或另立“跨 ID 乱序＋顺序安全”的子问题。
- **类型**：前置门槛，且零硬件成本即可定死。

### Q4 E2 的容量阶梯在“V 暂停”语义下近乎同义反复，阳性弱、阴性强【只影响宣称范围，但决定 90 次预算】

- **来源**：`experiment-plan.md:63`（V 预热→暂停 V→A→排空→probe V）、`:122`（W=0/1/4/7/8/16，合计 2/4/10/16/18/34 条目）、`:71`（PLRU 拐点不可由标称容量推导）。IOTLB 是**全相联**：lookup 遍历所有条目（`rv_iommu_iotlb.sv:92-127`），PLRU 是**单棵全局树**（`:326-364`）。
- **最强反例 / 免疫结论**：V 在 A 相位完全不被触碰，其条目必然是全局最冷。只要有**任意一次 fill**（`:305-319`，`update_i.update && replace_en[i]`），PLRU 选中 V 的概率就不可忽略。因此“W=8 安全、W=16 危险”的阶梯式拐点推理不成立；“V 条目被替换”几乎是“A 曾经 fill 过”的必然结果，而不是“干扰”的发现。反过来，**阴性结果（W=16 甚至 34 都不动 V）是很强的反驳证据**。
- **剂量语义也混了**：矩阵写“各组均完成 112 次搬运”，但对**替换/容量**机制，剂量是**独立页数（最多 2W 次 fill）**与 PLRU 最近使用序，不是 112 次访问。W=1 时有 2 次 fill 加 112 次命中（`:337-344`，命中也在改 PLRU）。所以“等量扰动”靠 112 并没有实现，x 轴应改述为“A 触及的独立页数 2W”。
- **能回答的证据**：per-entry 前后快照 + 替换索引 + 新标签 + 与被保护条目同上下文（`vpn/pscid/gscid/en_1S/en_2S`，`iotlb:95-121`）+ **W=0 对照**；以及一个 fill-free 对照（把 A 的 2W 页在 V 预热前先填好，使 A 相位只有命中没有 fill，运行时可切换，不占固定 10 次）。
- **失败后改路线**：若主矩阵显示 V 条目从不变动，E2 立即降为“排除项”，机制分析转向服务阻塞/出口；90 次不必做完。
- **补充（对用户问题的直接回答）**：我**不建议**用“样本数多”否决 E2。参数运行时可调、不需重烧（`experiment-plan.md:120`），边际成本是时间与日志；真正的一次性成本是**观测 RTL + 快照端口 + runner + 记录格式**。所以把关点应是“观测是否成熟、判据是否可执行”，不是 90 这个数。计划里现有的三处克制应予保留：`paper-logic.md:277`（三态结果、不称复现 b15-g0）、`:297`（不据单样本推断因果）、`experiment-plan.md:124`（不把 64 B 诊断耗时换算吞吐）。

### Q5 “只读快照”并不无扰动：IOTLB 命中会改写替换状态【前置门槛，零成本可定死】

- **来源**：`rv_iommu_iotlb.sv:337-344`（`lu_hit[i]` 直接写 `plru_tree_n`）、`:90-129`（只有 `lookup_i` 为真才产生 `lu_hit`）、`:367-371`（PLRU 只在复位清零）。对照 `experiment-plan.md:130` 声称“快照纯被动，不改变替换与仲裁”。
- **最强反例**：若把快照实现成一次真实 lookup（驱动 `lookup_i`），它会同时改变 PLRU，从而改变后续 probe 与 A 的牺牲者——观测者变成自变量。
- **能回答的证据**：RTL 审查即可；只需在设计里写明快照是否驱动 `lookup_i`。
- **失败后改路线**：二选一：(a) 实现不驱动 `lookup_i` 的旁路读出（直读 `tags_q`/`content_q`/`plru_tree_q`，`iotlb:57`/`:60`/`:326`）；(b) 放弃精确 tag 快照，只记 probe 的命中/未命中与替换计数，并把宣称从“哪个条目被谁替换”收窄为“是否丧失命中”。
- **同类风险**：`experiment-plan.md:126` 已承认“flush 不重置 PLRU，故不虚称各条件起态完全相等”——这是对的，建议进一步把 `plru_tree_q` + 全 tags 快照作为**协变量**逐 trial 记录，而不是当噪声。

### Q6 创新候选 R（保护位置/容量规则）目前是瓶颈分析＋调参【只影响宣称范围】

- **来源**：`paper-logic.md:204`（“根据请求生命周期和阻塞传播关系决定必要保护位置与容量”）、`:261-263`。
- **最强反例**：(a) 若“**每类资源都超额预留**”在同成本下达到同一条 V-A 曲线，则“必要位置”退化为“多给资源”；(b) 若把预留放**不在阻塞路径**的 stage 上（错位预留）也有效，规则没有区分力。
- **能回答的证据**：需要三组对照：错位预留（预期无效，**阴性对照**）、1 槽是否足够（`paper-logic.md:224` 自己标了“仅为假设”）、全类超额预留（**强对照**）。再加一条可执行规则的形式化：输入（阻塞传播图的节点：入口数/是否可抢占/hold 时间由谁决定）、判定、输出（位置集合＋每类最小容量＋预测的 V-A 曲线点）、限制（离线静态、不处理动态借用、不承诺同面积）。
- **失败后改路线**：放弃“规则即贡献”，改走候选 2（机制判别式）或只报实验事实。见第 5 节。

### Q7 对照公平性与成本口径：同容量≠同成本，且计时口径会藏成本【只影响宣称范围】

- **来源（该保留的克制）**：`paper-logic.md:226`（同总容量不等于成本相同）、`:208`（hit 不占 miss 槽、V 自身 4 周期不是固定延迟、各类槽不混加）、`:255`（须计 accept 前等待）。
- **最强反例**：P 胜出只是因为仲裁/mux/流水更短或频率更好；或 N 被实现成“先 accept 后计时”来隐藏轮询/准入成本；或胜负来自下游全球反压（`review:46` 明确不能证明所有下游各级始终 ready），而预留对此无能为力。
- **能回答的证据**：LUT/FF/BRAM/Fmax + **同构负载等价性测试**（只有 A、满载时 N 与 P 的延迟分布应一致；这是把“不偷加优先级”变成可执行判据的最简方式）+ 逐请求 accept 前等待记录。
- **失败后改路线**：改为成本-性能帕累托报告，删除“同成本下更优”的措辞。

### Q8 两条“并行”支线其实版本耦合：E2 的归因依赖“单在途请求”【可并行，但接口必须先定】

- **来源**：`paper-logic.md:300`（“共用记录格式…一条就绪不等待另一条”）对照 `experiment-plan.md:130`（要记录“A 造成的目标覆盖与**请求归属**”）。IOTLB 的 update 口不带 DID（`iotlb:34` 的 `update_i`，`:305-319` 写入），归属只能靠“当前 PT 状态是谁”（`tl_wrap:577-591` `req_data.did`、`e3_a_s1_miss`）——单请求下无歧义，N 一落地多请求就不成立。
- **最强反例**：E3 的 N 先落地且记录格式没带请求跟踪 ID → E2 的“这次覆盖是 A 造成的”永久失效，E2/E3 的横向比较也失效。
- **能回答的证据**：记录格式里加入**显式请求跟踪 ID**（并让 N 贯通该 ID）；或明确 E2 先落在当前 S 版本上。
- **失败后改路线**：改为顺序执行 E2→E3，并接受“E2 记录语义随版本变化”的代价。
- **附**：另一处并行硬件的现实约束是 `paper-logic.md:285`/`:300` 已承认“不保证两个硬件版本可合并一次烧录”。这我同意，不该被后续改写成一次上板。

## 3. E2 专项：判据、语义与可执行性

**先答“90 是不是已冻结”**：不是。计划自己写明正式采样前冻结参数（`experiment-plan.md:124`、`:128`；`paper-logic.md:277`），且短验收通过后**自动固定矩阵**。所以现在它是“参数化的单次部署设计”，不是冻结矩阵。建议在写 RTL 前用三行表定死：变量（W、A 次数、T、前缀 1/8/16、每条件次数）／取值／**冻结时点**／失败处置。这是文档级动作，零成本。

**逐项回答用户点名的问题：**

1. **是否被 b15-g0 单样本牵引**：部分牵引。1/60、计数值 2、**相位未知**（`RESULTS.md:407`：整轮计数不能定位相位）。W 阶梯可独立成立（容量问题与 b15 无关）；**前缀 1/8/16 与额外 30 次是被 b15 直接推动的**，建议降级为“运行时可切换能力”，只有主矩阵出现条目变动才实际跑满。
2. **缺什么判据**：
   - 阳性判据（操作性）：V 至少一个目标条目的 `valid` 变 0 或被换出，且**新标签属于 A 相位被填的页**，且该变化在 W>0 的 ≥k/10 次出现、在 W=0 的 10 次**不**出现，且上下文（`pscid/gscid/en_1S/en_2S/vpn`）与 probe 一致（`iotlb:95-121`）。
   - 阴性判据：W=16 与 34（若跑）在 10/10 次都不动 V 条目 → 容量说在本配置下被否。
   - 不足：W=0 无 A 但仍有 V 条目变动（说明准备阶段/观测本身在改状态）→ 记为准备失败，不作科学阴性（`experiment-plan.md:126` 已这样规定，保留）。

3. **为什么“软件整体窗口 2 miss”可能是别的事件**：整轮 HPM 是软件窗计数（`RESULTS.md:417`），可包含准备/启动阶段；`S1_PTW` 与 `IOTLB_MISS` 同位置上报（`tl_wrap:1154-1157`）；V 的 2 次也可能来自隐式 2S 路径（`tl_wrap:962-968`、`:1099-1106`），虽然 `e3_a_s1_miss` 的判据把 S2/DDT/PDT/MSI 都排除了（`:589-591`），但那只约束 E3 触发条件，不约束整轮 HPM。**整轮计数不能定位相位，因此不能定位机制**（`RESULTS.md:407` 已这样写，保留）。
4. **64B↔4KiB 的桥**：**状态层可推广**（一个 4KiB VPN 对应一个 tag），**代价层不可换算**（`experiment-plan.md:124` 已声明不换算吞吐，保留）。建议在论文里各写一句，别让 64B 的 miss 代价替 4KiB 说话。

7. **只读观测的时序扰动**：见 Q5；“快照发生在哪个边界”必须定义在“A 排空判定之后、probe 之前”，而“A 完全排空”目前**没有可观测**——`trans_ctl:124`/`:149`/`:222` 的 `usage_o` 全部悬空，FIFO 占用不可见。建议要么接 `usage_o`，要么用可读计数拼出排空判据（`state_q==IDLE` ＋ AR/AW FIFO 空 ＋ PTW 非 active ＋ 无未完成结果）。这是具体缺口，不是抽象顾虑。
8. **等时 T**：校准规则要先定义（用哪个 W、测什么、超时/未达怎么处置），`experiment-plan.md:128` 已把“超 T 记为失败、不得悄悄延长”写死，保留。

## 4. E3 专项：真实代码边界、N 是否值得先做

**先答“是否应在创新假设冻结前花大量工作实现普通非阻塞”**：N 属于**强基线与必要可行性**，不是主创新（`paper-logic.md:198-202`、`:281` 自己也是这个定位）。但我反对“先做完整 N”。理由在 Q3 与下面 5 条代码边界：

1. **单请求 FSM**：`tl_wrap:871` 一个 `unique case`，`:241` IOTLB lookup 只在 PT/MSI 状态进行；`:149-151` 下一请求准入绑在响应消费上。→ 要并发，必须把“请求状态”和“walker/查表状态”拆开。
2. **单份结果寄存器**：`trans_ctl:102` `trans_resp_data_q`，`:324`/`:338` 完成侧地址就取它。→ 多请求必须有**每请求结果条目**。
3. **元数据其实已在 FIFO 里**：`:323-334`/`:337-347` 的 AW/AR 字段取自 `aw_data`/`ar_data`（FIFO 头），`:101` 的 `trans_req_data_q` 只存 iova/did/pid/ttype/priv。→ **不需要新建“完整 AXI 头存储”**，FIFO 项本身就是完整头；缺的是“把哪一条 FIFO 项与哪一次翻译结果配对”。这是**降低 N 成本**的重要观察，请 Codex 确认，因为它会改变工程量估计。
4. **交付顺序与队头弹出**：`:711-716` 只有 `axi_comp_resp.*_ready` 才弹队头。→ 下游反压会单独造成队头阻塞，这与 PTW 无关（`review:43` 已写到）。所以“翻译解耦”若不解决交付顺序，就只是把等待移位。
5. **正确性要求（不自动新意）**：保留完整 AW/AR 元数据、AW/W 排空（`:110-158`、`:168-246`）、MRIF 分支（`:696-702`）、错误路由（`:393`/`:521`）、fault/inval 交互、结果寿命与释放——这些是正确性，不是贡献（同意 `paper-logic.md:242`/`:265`）。

**“合理 N 会不会已经足够”——可证伪预测**：E3 受控场景是**1 个 A miss + 1 个 V hit、无容量压力**（`review:76`）。因此：

- 若最小 N（2 在途 ＋ 每请求结果 ＋ 冻结的顺序策略）把 ΔV 压到 ≈0 → **P 无必要**，候选 R 直接砍。
- 若 ΔV 仍 ≈127–130 周期 → 阻塞不在“入口/槽”，而在交付顺序或下游；此时立 P 是错的（P 也动不了它）。
- 这就是**最小下一步能否证潜在方法**的地方：一个场景、一个判据，不需要全矩阵。

**什么场景才允许立 P**：只有在**同一 N 结构、同每类总容量、同 lookup 口**、并且 V 的等待被证明由**某类资源满**引起时（`paper-logic.md:219`/`:257` 的条件），P 才有意义；而且 P（同容量静态预留）本身**不是新意**（`paper-logic.md:262` 已写，保留）。

## 5. 创新：不超过 2 个值得保留的方向与淘汰判据

**我不判断新颖性**（不能联网，不引用未给出的论文细节）。以下只是“值得筛选的方向”。

### 候选 1（保留）：离线**保护位置—容量规则**
- **输入**：阻塞传播图（每个 stage 的入口数、是否可抢占、hold 时间由谁决定）；被保护流的到达率与并发度上界；各 stage 服务时间分布。
- **可执行判定**：对每个 stage，若 (i) 在被保护流必经路径，(ii) 入口不可抢占，(iii) hold 上界由流外事件决定或不可界 → 需要 ≥1 个专用位置；若 hold 无界（例如等下游 accept，`:711-716`），预留**无效**，必须限制流外 hold 或解耦。
- **输出**：位置集合 ＋ 每类最小容量（含“1 是否够”）＋ 预测的 V-A 曲线点。
- **限制**：仅离线静态；不处理动态借用；不承诺同面积同频率；不覆盖 hold 无界的 stage。
- **可证伪预测**：P1 在 hold 无界 stage 预留**不改善** V（阴性对照）；P2 被保护流并发度 ≤1 时 1 槽与 2 槽等效；P3 在非路径 stage 预留无效果。
- **消融**：N ／ P1（1 槽）／ P2（2 槽）／ 错位 P ／ **全类超额预留** ／ 旧 S＋实测 gap。
- **淘汰**：超额预留同成本同效果，或错位预留同样有效 → 规则不成立，退为常规基线。

### 候选 2（保留）：**机制判别式**（同一可观测状态、不同阻塞位置 → 不同措施有效）
- **输入**：三类可观测（IOTLB 状态快照、V 请求在各边界的 stall 桶、A 侧 PTW/出口占用）。
- **输出**：决策表 ＋ 每条分支的预测（哪种措施有效、哪种无效、何时无效）。
- **可证伪**：在“V 命中且出口 ready”条件下若服务解耦无效 → 分支错；在“出口不 ready”条件下若预留容量有效 → 分支错。
- **淘汰**：若三类分支无法被任何可实现的控制分开（尤其**出口反压目前无独立控制**：`paper-logic.md:74` 明确 DS delayer 汇合多类请求），或某一分支能解释近乎全部损失 → 判别式无信息量。
- **这一条比候选 1 更贴近现有证据**：E3 已有一个受限的“服务依赖”结论（`review:35`），而 E2/E4-出口两条还没有；三条都能被独立观测之前，不要写“首次”或新名词。

## 7. 结论：保留 / 修改 / 停止

### 保留（不要动）
1. E3 的措辞与范围（`review:35`、`:82`）与“不称规范强制、不称普适 HOL”。
2. S 与实测 gap 只作历史参考；P 是朴素静态对照，不称创新（`paper-logic.md:198-202`、`:261-263`）。
3. `paper-logic.md:208`/`:226`/`:277`/`:297`、`RESULTS.md:420`/`:424`、`experiment-plan.md:124`/`:126`/`:132` 的克制条目。
4. 两条支线不共用烧录、不把本轮分析自检当未来上板通过（`paper-logic.md:285`/`:300`/`:291`）。

### 修改（改写或补设计）
1. E2 阳性/阴性判据改为 **per-entry ＋ 上下文一致 ＋ W=0 对照 ＋ 源/目两次分开记**。
2. E2 快照的**扰动性二选一**写死在设计卡里（真旁路 / 放弃精确 tag 快照）。
3. 记录格式加**请求跟踪 ID**，使归属跨版本有效。
4. E3 设计卡写明**顺序策略**（FIFO 交付 vs 跨 ID 乱序），并把“翻译等待”和“交付等待”分成两个测量桶。
5. 给出 **A 排空**与 **等时 T** 的可观测定义（含是否接 `usage_o`）。
6. 90 次改为“待冻结参数 ＋ 中点复核/停止规则”；前缀支线降为运行时可切换能力。
7. 3 个 gap 的表述改为“一种固定间隔配额协议上的 3 个点”。

### 停止（明确不做）
1. 顺序策略与公平等价判据未定前，**不要开始大 N**。
2. 不要用 3 个 gap 点宣称“所有限速基线不足”。
3. 不要为 P 立“新算法”之名；若超额预留同样有效，停止候选 R。
4. 当前证据下不做任何延迟上界承诺。

### 门槛分类
- **实验开始前必须解决（3 项，全为文档/配置级，零硬件）**：① N 的顺序策略＋最小功能判据＋退出条件；② E2 快照扰动性二选一；③ `NumIotlbEntries` 与 W 阶梯的边界解释【假设待核：我在给定文件里找不到该配置值，只从 W=7/8 成对出现推测容量为 16，2＋2W 在 W=7 时正好为 16】。
- **可并行（4 项）**：S1‑PTW 活跃周期计数与量级核算；E2 记录格式与 runner；E3 逐阶段等待桶定义；同构负载等价性测试设计。
- **只影响宣称范围（4 项）**：4KiB-only 的状态结论；无 solo/BARE 时不报 slowdown；不报延迟上界；候选 R 的“必要性”措辞。

### 最小下一步（避免无限证据链无方法）
一句话：**先做“能否证”，再做“能否用”。**

1. **一个便宜核算**：加 S1‑PTW 活跃周期计数（RTL 已有 `active_o`，`tl_wrap:639`），算 walker 占用率，代入 E3 的单次代价，预测每搬运额外等待，与 655 周期比。对不上 → 因果链断，改论文定位；对得上 → E3 可升格为量级证据。（不要求新上板，属可并行。）
2. **一个判决实验**：把现有 E3 受控场景（1 A miss + 1 V hit，无容量压力）跑在**最小 N**上，前提是第 ① 门槛（顺序策略）已定死，并同时记两个等待桶。
   - ΔV≈0 → N 足够，P 死，方法必须另找位置（或承认是常规优化）。
   - ΔV 仍≈127–130 → 阻塞在交付顺序/下游，立 P 是错的。
3. **一个有界观测包**：E2 只做 W=0/1/16 三点 ＋ 真旁路快照，作为“容量说”的**否决实验**；阴性即停，不需要 90 次。

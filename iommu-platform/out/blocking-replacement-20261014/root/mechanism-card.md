RCS1 preserved more complete future lookup sets but lost to one fixed SJF in its four conditions. Equal PTE work did not imply equal completion: an early producer rewalk delayed active data progress. BR1 therefore evaluates a different object: the change to current owned obligations' next actual release caused by evicting one resident key.

After one normal successful complete walk for q, choose one of the original legal16 victims and insert q. Keep the native post-fill hit, permissions, original response association, held VALID, same-ID order, hit bypass and R/W guards. No new bypass/direct-result path, additional cache entry, walker, request capacity or data buffer is part of this initial rule. Predict only until these owners' next real release points and the relevant immediate uses. A missing association/history, unsupported class or changed snapshot uses ordinary PLRU. Every actual request still executes a full normal walk/permission check when needed.

## Program to be adjudicated

For each legal victim v, form a virtual residency state (R minus v plus q). Feed the same bounded owned-obligation snapshot to a deterministic service/dependency projection. Recompute service-arrival and resource-order consequences of that hit/miss change; do not merely attach a numerical cost to v. One PTW, dependent PTE stages, shared PTE/data service and native lookup/response and ownership constraints remain in the projection. Service/depth estimates must derive only from completed public feedback, with their observation endpoints, state and error explicitly documented before accepting an estimator.

Let F_o(v) be the projected next real release time of each documented current owner. Choose lexicographically the minimum (max F_o(v), sum F_o(v), additional projected PTE service count), with original masked tree-PLRU for tied victims. No payload is paused to preserve a scoring snapshot. A concurrent retirement/invalidation invalidates a hint rather than blocking the real event.

This is a candidate program specification, not an assertion that an inexpensive production projection or a reachable performance witness exists. Root must resolve both before model entry. A full16-world simulator is an offline explanation, not mandatory/free hardware. Permit algebraic reduction, legal field reuse, or charged serial evaluation; whichever implementation is proposed must preserve the program and charge its actual decision delay.

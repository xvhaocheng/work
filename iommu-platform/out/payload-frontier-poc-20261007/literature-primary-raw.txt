L32: # Physically-Aware Preemptive Virtual Channels for Deadlock-Free AXI Networks-on-Chip
L33: 
L34: Lorenzo Leone^{1}, Luca Colagrande^{1}, Luca Benini^{1,2} Affiliation: ^{1}ETH Zürich, Zürich, Switzerland, ^{2}Università di Bologna, Bologna, Italy Affiliation:  {lleone, colluca, lbenini}@iis.ee.ethz.ch
L35: ###### Abstract
L36: As many-core Systems-on-Chip (SoCs) continue to scale, Networks-on-Chip (NoCs) must sustain increasingly high memory bandwidth while preserving deadlock freedom. In AXI4 systems, protocol-level dependencies between read and write traffic can create circular waits at the network endpoints, even when the routing algorithm itself is deadlock-free.
L37: Decoupling these traffic classes avoids such dependencies, but exposes a key implementation trade-off: multiplane NoCs duplicate wide physical links and increase routing pressure, whereas conventional Virtual Channel (VC) routers add substantial control complexity, area, and timing overhead. This work revisits this trade-off for modern wide-link NoCs. We evaluate four deadlock-free AXI4 traffic-class separation schemes: a multiplane baseline and three lightweight VC-based designs.
L38: Among these designs, we propose Preemptive VCs, a physically-aware architecture that can save up to 76% of link resources with comparable frequency and only 3% router area overhead relative to the multiplane design.

L42: ## I Introduction
L43: 
L44: As many-core SoCs continue to scale [cite19†1 ], the memory traffic generated by large numbers of processing elements increases sharply, making high-bandwidth and scalable NoCs essential for sustaining performance. At the same time, providing industry-standard AXI4 [cite20†2 ] interfaces at the network boundaries remains critical for seamless integration of existing IPs, usually designed with AXI4 initiator and/or target interfaces [cite21†3 , cite22†4 , cite23†5 ].
L45: Deadlock freedom remains a central requirement in NoCs, both at the routing and protocol levels [cite24†6 , cite25†7 , cite26†8 ]. Endpoint behavior in AXI4-based systems creates protocol dependencies that are invisible to the routing algorithm itself. Thus, even when deterministic XY routing is employed, protocol-level deadlocks may still arise if AXI4-capable endpoints internally couple read and write transactions [cite25†7 ].
L46: cite27†Fig. 1 illustrates a representative case in which a DMA engine (AXI4 initiator) issues a read burst request to a remote memory . As the read data returns, each AXI4 beat is immediately forwarded into a write burst directed to a local L1 Scratch-Pad Memory (SPM) (AXI4 target) through the AXI4 crossbar . If, before the DMA completes, an external initiator issues a write burst to the same L1 SPM , its request may occupy the local NoC link .
L47: The DMA can then no longer make forward progress on the read-response path , and a protocol-level circular wait arises at the network endpoint, stalling the entire system. More generally, the challenge of protocol- or message-dependent deadlocks caused by the interaction between NoCs and endpoint protocols has long been recognized in the literature [cite25†7 , cite26†8 , cite28†9 ].
L48: To eliminate protocol-level deadlocks without constraining endpoint behavior, AXI4 read and write channels must also be decoupled so that they cannot block one another on the same NoC link.
L49: Fig. 1: a) Deadlock scenario: all links are blocked (red arrowheads) or starved (red tails); b) Router design space.
L50: One solution is to use VCs [cite29†10 , cite30†11 ]. As shown in cite31†Fig. 2 , VCs provide separate buffers for different data streams while preserving a shared physical link. In our case, AXI4 read and write transactions can be assigned to distinct buffers, so that returning read data and incoming write data no longer compete for the same downstream path in the local interconnect.
L51: A flit may occupy the shared link only if the corresponding downstream buffer has free space, ensuring that the link is released in the next cycle. A second solution is the multiplane approach [cite32†12 , cite33†13 ], which assigns different traffic classes to separate physical links, thereby avoiding inter-class blocking on shared links.
L52: Prior work has established the conventional view that VCs are more complex than multiplane designs [cite33†13 , cite34†14 , cite35†15 ], largely because earlier studies considered classical VC routers targeted at improving link utilization, which incur significant control overhead. Under this assumption, paying for additional link resources has often been seen as preferable to the area and timing cost of full VC support.
L53: However, the design space of modern NoCs is shifting, fundamentally changing the trade-off between router complexity and link resources (cite27†Fig. 1 ). As accelerator-centric systems continue to scale, integrating hundreds of thousands of AI cores, on-chip networks must sustain aggregate bandwidth demands reaching tens of $\mathrm{PByte/s}$ [cite36†16 , cite37†17 , cite38†18 , cite39†19 ].
L54: To sustain this bandwidth, NoC link widths have therefore increased, both in proprietary, closed-source solutions [cite40†20 , cite41†21 , cite42†22 , cite43†23 ] and in open-source designs such as FlooNoC [cite44†24 ]. The latter stands out as the first open-source AXI4-compliant NoC, supporting high-throughput transfers with links up to 1024 bits [cite45†25 ]. At such link widths, the routing-resource cost of physical-plane duplication becomes critical.
L55: Moreover, as these fabrics scale toward wafer-scale integration, reliability also becomes increasingly important. Achieving reliability often relies on redundancy, with examples of triple-redundant interconnects incurring up to a 3$\times$ increase in link width, further exacerbating wiring demand and routing pressure [cite46†26 , cite47†27 , cite48†28 , cite49†29 , cite50†30 ].
L56: Under these stringent constraints, VC implementations re-emerge as a promising option to preserve protocol-level deadlock freedom while saving valuable routing resources. To this end, we propose Preemptive VCs, a novel lightweight VC router design for deadlock-free AXI4 traffic separation which preserves the resource parsimony of VCs while approaching the area and timing characteristics of multiplane router designs.

L68: ## II Related Work
L69: Originally introduced to break cyclic channel dependencies and guarantee deadlock-free routing [cite29†10 ], VCs were soon adopted to improve link utilization by allowing multiple logical flows to share the same physical link [cite30†11 ]. This evolution led to the conventional four-stage router microarchitecture (cite31†Fig. 2 ), designed to dynamically map incoming packets to the available VCs.
L70: In this architecture, routing computation (RC) and switch allocation (SA) must be complemented by substantial VC control and arbitration logic to support dynamic allocation (VA). Consequently, interest in reduced-complexity VC designs has resurfaced to mitigate this overhead. Xu et al. [cite53†31 ] simplify VC and switch arbitration through partially constrained allocation schemes, but still retain a dynamic allocator to adapt VCs to traffic fluctuations.
L71: Shim et al. [cite54†32 ] statically bind VCs to source–destination traffic paths encoded in routing tables, targeting routing optimization rather than traffic-class separation.
L72: In contrast, our work targets protocol-driven AXI4 traffic-class decoupling: by statically associating each logical channel with one VC, much of the allocation, control, and arbitration complexity present in conventional and prior reduced-complexity VC routers can be removed, enabling lightweight VCs for deadlock-free traffic-class separation..
L73: Fig. 2: a) Conventional four-stage VC-based router; b) baseline multiplane FlooNoC single-cycle router.
L74: Multiple physical networks, or multiplanes, have long been used as an alternative to VCs to separate interdependent traffic classes and avoid protocol-level deadlock. Hansson et al. [cite25†7 ] note that many NoCs eliminate request–response dependencies by introducing separate physical networks. The trade-off between VCs and multiplanes was previously studied by Yoon et al.
L75: [cite33†13 ], who showed that multiplanes can achieve simpler routers and higher frequency than classical VC routers, at the cost of fabric duplication. However, while their study targets conventional dynamically allocated VC routers, our work revisits this trade-off under different design constraints, where FlooNoC’s lightweight single-cycle router (cite31†Fig. 2 ) and the static use of VCs for AXI4 traffic-class separation fundamentally change the cost–performance balance.
L76: Following the multiplane approach, other works have adopted multiple physical networks for traffic-class separation. In the General Purpose Graphics Processing Unit (GPGPU) domain, designs such as RAPID [cite55†33 ] and DA2 [cite56†34 ] use two separate 128-bit networks to exploit the request–reply traffic asymmetry of GPGPU memory systems.
L77: Similarly, tiled manycore systems such as OpenPiton [cite57†35 ] and ESP [cite58†36 , cite59†37 ] rely on multiple physical networks, using, respectively, three and six 64-bit physical planes to provide bandwidth and avoid deadlock. While multiplanes have been adopted successfully for message-class separation, they have mostly been demonstrated on relatively narrow links, which are not suited for modern large-scale, data-intensive AI-oriented SoCs.
L78: In such systems, wide links up to 1024 bits are common to sustain high-bandwidth data movement [cite40†20 , cite41†21 , cite42†22 , cite43†23 ].
L79: FlooNoC [cite44†24 ] stands out as the first open-source AXI4-compliant NoC targeting AI accelerators with very wide links. As shown in cite31†Fig. 2 , it implements two logical networks, one wide (up to 1024 bits) and one narrow (typically 64 bits), on top of three shared physical planes: one narrow channel for AXI4 requests (narrow and wide AW and AR, and narrow W), one narrow channel for AXI4 responses (narrow and wide B, and narrow R), and one wide channel for AXI4 data (wide W and R).
L80: This organization makes FlooNoC’s original multiplane choice inexpensive: only narrow traffic is physically separated, while the costly wide data plane remains shared between AXI4 read and write data streams. In the deadlock scenario of cite6†Sec. I , however, the wide AXI4 read and write data streams must also be separated. A pure multiplane solution would therefore duplicate the wide tile-to-tile link, sharply increasing routing pressure.
L81: ## III Architecture
L82: The deadlock scenario in cite27†Fig. 1 stems from the interaction between wormhole-routed AXI4 transactions and IP blocks, such as DMAs, that internally couple read and write streams. This coupling can create circular dependencies and lead to protocol-level deadlocks, which can be avoided by breaking at least one of Coffman’s conditions [cite24†6 ]. We study the design space through a physically-aware lens, since the router-complexity vs.
L83: link-resource trade-off discussed in cite6†Sec. I is critical to system-level feasibility. We evaluate four architectural solutions (cite60†Fig. 3 ), each targeting a different deadlock condition. We focus on wide data routers and the respective tile-to-tile links, which represent the main bottleneck for decoupling AXI4 read and write data streams in large accelerator-centric systems.
L84: Fig. 3: Wide tile-to-tile connection for the various designs.
L85: #### III-1 Multiplane
L86: The baseline solution extends the multiplane approach adopted in FlooNoC. While FlooNoC already separates narrow AXI4 request and response traffic, it uses a single shared wide plane for both read and write channels. To decouple these traffic classes, we instantiate two independent wide planes, one for read and one for write data, each with its own tile-to-tile physical link and router datapath.
L87: As a result, read and write data streams no longer contend for the same wide physical channel, breaking Coffman’s mutual exclusion condition. The main cost is the duplication of the wide tile-to-tile link, which doubles the number of wide pins and routed tracks crossing tile boundaries. Since the wide link accounts for the majority (78%) of the tile-to-tile link resources [cite44†24 ], the multiplane solution substantially increases routing pressure.
L88: #### III-2 Naive
L89: To reduce routing overhead, an alternative approach is to use VCs. We first evaluate a Naive valid/ready implementation [cite61†38 ], where a single physical data link is shared across VCs , while the valid and ready handshake signals are replicated per VC ^{3}^{3} 3 As in the multiplane design, our implementation also replicates the switches. This could be further optimized by sharing one switch between VCs, as shown in cite31†Fig. 2 ..
L90: This allows the sender to select the active stream and the receiver to apply independent backpressure for each traffic class. To break Coffman’s hold and wait condition, data is injected onto the shared physical link only when the corresponding downstream receiver is ready, by masking the upstream valid with the downstream ready.
L91: However, this introduces a ready-to-valid combinational dependency, creating a logic path from the receiving router, through the transmitting router, and back to the receiving router . In tile-based architectures, this path spans twice the tile width (d), making physical delay a critical timing contributor and significantly limiting the achievable frequency.

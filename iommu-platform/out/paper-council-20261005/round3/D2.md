## 3. 主候选 D2-R3-1：服务机会的产权账本（wait-slot ownership ledger）

**这是我的 C7 的重构，不是换名——我把问题从「缓存/优先级怎么分」改定义为「他人 miss 产生的服务机会由谁取用、收益/代价记在谁头上」。**

### 3.1 问题定义（真正越出 P/N/PN）
共享非抢占前端里，一次 miss 会占出一段 **PTW 占用窗口**；fast 路径在该窗口内服务命中（触发条件＝另一 bank 主 PTW 活动，C1 R2-F3 转引 `rv_iommu_tl_wrap.sv:303`）。该资源有两点结构特殊性：
1. **不可存储**：slot 只在 miss 窗口内存在，过期即消失；
2. **非自产**：slot 是**他租户 miss 的副产物**。
当前实现把该窗口当公共机会**免费取用**（`dma_composition_control.sv:352`），于是存在一个未记账的**跨租户外部性**：slot 创建者承担等待，slot 消费者获得服务。

### 3.2 强简单对手（必须击败，不许配软基线）
- **per-DID fast 配额**：给每个 DID 一个**对称**的 fast 消费上限，与谁创建 slot 无关。
- 以及 **N 本身**（work-conserving，免费取用）。
- 更强的还有 C1-QC2-1 的「每租户 RR＋有限在途＋常驻小身份表」与 C2 自设的「静态服务预留＋在途上限」。这些必须在**同身份状态量、同资源、同下游假设**下配平。

### 3.3 标准 RR/配额解决不了、而本候选能解决的明确轨迹
设两租户：**P（producer）**长 PTW、自己几乎不发 fast；**C（consumer）**短翻译、大量消费 fast。
- **per-DID 配额**：C 的 fast 上限＝其固定配额，与 P 产生多少 slot 无关。P 高 miss 期产生的**富余 slot 被浪费**（返回 normal 路径），P 白白等待而无人得利。
- **账本**：fast 消费向 slot 创建者**单向转付信用**；C 在 P 高 miss 期可透支，P 需要时归还。因 P **自身不发 fast**，其服务上界不受影响，而 C 获得更多有效服务 → 在**同 V tail 下提高联合进度**。
- 分界：当「产出＝消费」两租户对称时，账本与配额等价；差异**只在产出≠消费时出现**。这给出一个清晰、可证伪的边界，而不是「静态不适应变化」的常识口号。

### 3.4 最小决定性实例（未来实验，不做大矩阵）
两租户，A＝长 PTW（A8），V＝hit 为主；三臂对照：
1. N（不收费，work-conserving）；
2. 固定 per-DID fast 配额；
3. 产权账本（fast 事件记 creator/consumer，守恒）。

指标：V p99、V 窗口、A 窗口 goodput、**ledger 守恒**。
- **判据**：在 A-miss 率高且 A 自身 fast 需求低的窗口，账本 vs 配额应出现可分辨的 A goodput 差；在 A-miss 率低时三者应回落相等（此时应退回 N）。
- **Kill**：per-DID 配额在同 V tail 下达同 A goodput → 撤回。

### 3.5 依赖 / 待证 / 新颖性风险（不隐藏）
- **当前 172 无此数据**：需要每 fast 事件记录 creator/consumer 的**新计数器**（不存在），所以本候选**只能先仿真/spec 对照**，无板测权限下**标待证**。
- **换名风险**：信用流控是 NoC/互连常识。若 C2 判为「信用流控搬用」→ **降为工程应用，不保选题**。我主动标注，不靠改名保住。
- 与专利 `US20230409197A1`（C2 R2-L1）区别：该专利是**按 PASID/域配额**（对称、身份侧），未触及**跨租户 slot 外部性**；与 HPCA2017 hit-under-miss 区别：后者是**同租户**在自己 miss 期间服务自己命中，不是跨租户外部性。

## 4. 备选候选 D2-R3-2：撤销契约的可判定部分序 oracle

**与 C2 R2-Q4 融合，我的增量是锚到一个具体未验证 gap，并把 pre-IOMMU 在途当一等建模元素。**

### 4.1 问题定义
RISC-V 规范定义 IOFENCE.C 的**完成语义**并允许部分重排（C2 R1/L4，`iommu_in_memory_queues.html` §Page-Table cache invalidation L63–94、§Command-queue Fence L99–113）。标准参考模型（官方 ref model，C2 R2-L6）给**全序**，因此：
- 对**合法重排**会报假阳；
- 不建模 **pre-IOMMU 在途平台流量**（C2 R1/L4：需平台 fencing）→ 漏报「post-fence 旧映射仍可访问」的假阴。

**具体锚**：C1 R2-F5 / C2 R2-S1 转引 `rv_iommu_cq_handler.sv:348/:362` 的 IOFENCE 分支明写 `TODO: Add IOFENCE support with PR and PW using R/W counters`——即**当前分支不能作为已验证 PR/PW 排空的证据**，且 172 未覆盖撤销→复用（`raw_inval_cycles` 全 0，`metrics.csv:2–173` 末列；D1-Q-C2-1）。

### 4.2 标准参考模型解决不了、而本候选能解决的明确轨迹
把 spec 允许的重排抽成**部分序**，构造 oracle：
- 接受**所有合法交错**（消假阳）；
- 用规范必要的序关系（命令提交/PTE 可见/IOFENCE 完成/平台 fencing 边界）**拒绝非法交错**（消假阴），并自动搜最小非法 trace。
- 标准 ref model 无法表达「允许集合」，也无法表达「在途 pre-fence 平台流量」，二者是本候选的直接差异。

### 4.3 最小决定性实例
一条 trace：①pre-fence 设备写被接受 → ②该映射 IOFFENCE.C → ③fence 完成 → ④该 pre-fence 写的 PR/PW **仍在途**。
- 标准 ref model：接受（不建模在途）；
- 部分序 oracle：标记非法；
- 若真 RTL 也允许 post-fence 复用 → **确认 gap**；若不允许 → 说明已有隐性排空，撤回该实例。

### 4.4 依赖 / 风险
- 无完整 IOMMU 定向 Verilator 环境（`research-literature-review-20261004.md:75`）；172 对撤销 0 证据。→ **仿真/形式优先，标待证。**
- 风险：泛 IOMMU 验证已有（Petrykin 2019、官方 ref model）；若 oracle 只是 ref model 弱化，**不保选题**。且 C1 已警告「不能把补全 IOFENCE 当论文主创新」——所以**贡献必须是部分序 oracle 本身，不是补 IOFENCE**。

## 5. 一个非传统备选 D2-R3-3（不换名的越出）：把共享翻译前端当「自时钟拥塞控制」问题

**越出点**：RR/配额/EDF 都是 **IOMMU 侧开环**调度器；本备选把控制权**移到租户自己的释放相位**，IOMMU 故意保持被动。

- **问题**：C1 R2-F4 转引 `idma_reg64_frontend.sv:544/:560/:580`——每路**完成后**才开始 gap、再发下一任务，即**释放是自身完成的闭环**。C1-QA1/A1-X2 已指出「负荷与相位不可分」。于是问题不是「谁优先级高」，而是：**当负载本身是策略的函数时，能否用租户侧闭环打破同步、从而稳定联合吞吐？**
- **轨迹（vs RR/配额）**：开环调度器无法控制 release times，不能打破 A1-X2 的整数锁相；租户侧闭环（信号＝自测完成时延 RTT，控制＝自身下一任务的相位微调）原则上可去同步。判据：实测租户是否随时间**去同步**、联合吞吐是否优于固定 RR/配额。
- **风险（大到必须标待证）**：高度推测；需 driver/agent 改动（D3 归 L2+）；若不测去同步而只测单点，就只是 A1/C1 方向的**换名**。**不保选题。**

# R3 / C2：撤回未成立的新调度，把撤销问题收缩到可判定的边界

日期：2026-10-05。已读 R2 六席完整意见；本轮只做论文判断与有界原始来源核查，没有执行模型、实验、构建或实现，没有派生席位。新增证据见 [C2-literature.md](C2-literature.md)。下文例子是手工推导的候选验证实例，不是测得轨迹。

## 1. 本轮改变与明确去留

**撤回 C2-L 作为当前“新联合调度机制”的主张，C2-T 从候选主线中移出。** 同信息、同资源的普通调度与在途上限已能解释我目前给出的全部小例子；尚未找到必须引入新机制的差异。双时限只是一个可能有应用价值的目标，不凭目标组合获得新颖性。

**保留一个更窄的 C2-O 问题：对异步 DMA/失效/fence 的有限观测，哪些安全性结论能够判定，缺少哪些跨接口事件就必然无法判定？** 允许结果集合、关系模型、litmus 自动生成都已有强先例，不能拿这些词本身当新意。当前仅将 C2-O 保留为模型和方法问题，未升级为论文主线，更不要求补 PR/PW RTL。它的最强简单对手是现有官方参考模型加逐请求/映射版本 scoreboard。

创造性应放在值得回答的边界，而非扩大状态机：若最终能给出最小观测契约、证明在该契约下正确归因的条件，并展示多个真实实现/集成接口漏掉同一种保证，可能形成验证或体系结构接口论文。若只是把标准同步规则编码成几个 assertion，则按工程工具收尾。

### 一个确实击败当前 C2-L 提法的普通对手

仅为手工模型：单一不可抢占资源，一笔已处理写尚需 2 个时间单位才能到达全局排序点；V 还需 1 单位，截止时刻 3；撤销的其他工作已完成，最后的维护完成动作需 1 单位，截止时刻 4。时间从 0 起，写在 `[0,2]`，V 在 `[2,3]`，维护在 `[3,4]`。普通有界在途加适当固定优先级/非抢占 EDF 就满足两期限。

若维护优先导致 V 超时，仅说明该优先级不合适；不是“局部保证不可能组合”的证据。两方工作总量超过可用服务的例子也不能成为我的反例。只有在相同到达知识、相同服务上界、相同安全顺序下，普通方案无法满足真实需求而新规则可以，才重新讨论 C2-L。当前没有这条证据。

## 3. 新来源使 C2-O 的新颖性门槛提高，而非降低

1. **TransForm 已有翻译相关关系模型与测试合成。** [原文](https://arxiv.org/pdf/2008.03578) §III/IV 将页表写、隐式 walk、TLB 失效纳入关系，并合成带最小性条件的 litmus；§VI 给出失效后旧映射的禁止结果。故“用偏序＋自动最小反例测试地址翻译”不是本提案新意。
2. **Arm 的允许结果语义已有完整研究路线。** [Relaxed virtual memory in Armv8-A，ESOP 2022](https://www.cl.cam.ac.uk/~pes20/RelaxedVM-Arm/RelaxedVM-Arm-esop2022.pdf) 定义允许行为包络，包含多阶段翻译、失效与同步，使用 Isla 计算允许结果。不能仅换成 RISC-V 或换成 IOMMU 就声称方法创新。
3. **官方参考模型已经暴露排空边界。** [README](https://raw.githubusercontent.com/riscv-non-isa/riscv-iommu/main/iommu_ref_model/README.md) 定义 `iommu_to_hb_do_global_observability_sync(PR,PW)`，由 testbench 完成全局可见性动作；还有 ATS 完成和超时入口。我又直接核对 [命令源码](https://raw.githubusercontent.com/riscv-non-isa/riscv-iommu/main/iommu_ref_model/libiommu/src/iommu_command_queue.c) `do_iofence_c`，确实有 ATS 等待、PR/PW 同步回调和后续完成处理。**“参考模型只算地址，完全没考虑排空”是错误前提。**

这些来源尚未建立与 C2-O 完全一致的跨接口最小观测结果，也没有被我穷尽检索；但已足够要求：先与它们可直接扩展的普通 harness 比较。不能把参考模型的一种合法实现选择直接当完整规范，也不能刻意不接现成回调使基线漏报。

## 4. C2-O 的小范围问题定义

**问题句：** 在不强迫合法实现产生同样内部时间线的条件下，如何判定“软件看到 fence 完成”是否足以支撑某个 DMA 安全结论；若现有 trace 不能判定，最少还需观测或建立哪条跨接口顺序？

首个模型限于单级普通 4KiB 映射、完整 PTE 原子更新、正确发布顺序、有限请求 ID、普通主存；A/D 预置，关闭 ATS、PRI、nested 和设备缓存。一个域先足够区分规范事件；第二域仅用于核对 fence 全局范围，不能假设 IOFENCE 具有不存在的 per-DID 限定。涉及缺失排序点的实例明确标为“集成接口无法判定”，不把它记成 RTL 错误。

不为制造新颖性一口气加入 ATS、嵌套、别名、混合页大小、恶意设备和 deadline。若最小问题被简单对手解决，先降级，不能靠增加功能数量挽救论文。

### 4.1 原始规范边界

固定来源为 [RISC-V IOMMU v20260222，In-memory queue interface](https://docs.riscv.org/reference/iommu/v20260222/iommu_in_memory_queues.html)，§Page-Table cache invalidation 与 §Command-queue Fence；精确定位与少量原句见文献文件。

| 规则 | 对检查器的约束 |
|---|---|
| S1：无覆盖性失效时，旧/新合法翻译都可能被使用 | 不得强制与某个模型的单次缓存选择相同 |
| S2：普通 `cqh` 前进不等于命令完成；越过 IOFENCE 才有相应完成保证 | 不能把取命令事件当失效结束 |
| S3：PR/PW 约束已经被 IOMMU 处理的先前读/写到达全局排序点 | 翻译响应、设备提交和 DRAM/总线响应不能未经平台论证互相替代 |
| S4：尚未被处理的在途流量需要相应互连 fencing 才能纳入保证 | 缺这个前提时，不能声称整个设备已静默 |
| S5：实现可扩大失效范围 | 多 flush、多 walk 或不同 hit 数本身不是规范违例 |

### 4.2 五个具体实例与一个观测不可能性例子

符号：`P(x)=p0` 是叶映射；`U` 是已正确发布的 PTE 更新；`I` 是覆盖 x 的失效；`F00/F11` 分别表示 PR/PW 都为 0/都为 1 的 IOFENCE；`Fdone` 指无错误的规范完成。`G(W)` 指写达到已明确的全局排序点。以下不同判定均依赖列出的前提，不是笼统地说“fence 后旧数据皆非法”。

| ID | 手工事件序列/前提 | 必须给出的判定 | 检验价值 |
|---|---|---|---|
| O1：合法分歧 | 原先 x→p0 被缓存；`U: x→p1`；没有 I；随后新读 x | 选择 p0 或 p1 均可；只允许这次有效更新涉及的合法结果 | 反驳严格单结果对拍。普通版本集合 scoreboard 已能处理，**不是新贡献** |
| O2：取出不等于完成 | `U: x无效`；提交 I；`cqh` 只越过 I，尚无 Fdone；一条读用 p0 | 若 I 尚未执行，旧译结果可以合法；只凭 head 无法宣告违例 | 检查错误完成点。不能把所有这类结果都判合法，执行历史仍重要 |
| O3：新请求与旧写分开 | `U: x无效`；I；F00done；此后才向 IOMMU 发起一笔新的 untranslated 读 | 这笔新请求不得再获 p0 的访问授权；应出现相应访问失败 | 排除失效后 stale refill。早先已译好的写后来到达 G，则不能仅凭 F00done 判错 |
| O4：真正的排空反例 | 已证明 W 在 fence 之前完成翻译处理；随后 F11done；最后才 `G(W)`；前后无错误/超时 | 禁止；若换成 F00，则仅凭这个顺序不足以判错 | 只差 PR/PW 的合法/非法对。全局可见性 monitor 必须真实，不能把 AXI B 响应擅自等同 G |
| O5：晚到 walk 的精确错误位置 | walk 已取得旧 PTE；发生 U、I、Fdone；旧 walk 晚到并污染缓存；Fdone 后才发起的新请求使用 p0 | 最后的新请求成功使用旧映射是禁止结果；“旧 walk 响应晚到”这一内部现象本身不够判错 | 检查是否阻断旧状态对新 epoch 的授权。逐请求 epoch checker 可能直接覆盖 |
| O6：无法从外部 trace 判定 | 映射保持有效。仅观察到：软件提交 W → F11done → G(W)。隐藏历史 H早：W 在 F 前已被处理；H晚：W 到 F 后才被 IOMMU 处理 | H早违反 S3；H晚不因该顺序违反 S3。相同投影不能区分 | 必须观测/强制建立“已处理”边界，或回答无法判定。增加统计样本不能补回这个信息 |

O6 的两个历史均不更改映射，避免把“未处理的请求后来为何仍可写旧物理页”混入例子。它证明的只是特定观测不足，是一个很简单的信息边界；**不是我声称发现了新的 IOMMU 漏洞或新颖的不可能性定理。** 一条可验证的互连 barrier 若能把 W 纳入已处理集合，就能解除歧义，但需要把 barrier 前提同样给所有检查器。

检查结果必须分成：已证违反、该轨迹在明确前提下满足被检查性质、信息不足。存在一个合法解释只说明“尚不能证明违规”，不能证明真实隐藏历史正确。规范本身有未决解释或 testbench 未提供 G 的定义时，也不能由模型投票补成事实。

## 5. 同信息同资源的强简单对手：B-score

以官方功能参考模型为基础，外加最普通的 scoreboard：

- 按请求 ID 记录读/写类型、是否已处理、是否已到达 G；记录 fence 覆盖的已知请求集合。不得把普通 device-submit 自动写成 processed。
- 按 `(上下文, 页/范围)` 记录可用映射版本与已完成的失效，保留必要旧版本；允许规范容许的缓存丢弃和扩大失效。
- 在 fence 完成时检查其先前命令与 PR/PW 覆盖的请求；利用已有全局可见性 callback/ATS 接口，而非重新发明这些事件。
- 观察不充分时保留不确定，必要时枚举该小界限内的事件顺序。随机刺激只负责找轨迹，不负责决定规范真假。

候选 C2-O 与 B-score 得到完全相同的请求/命令/内存可见性事件、PTE 版本和环境约束，使用相同请求上限、trace 长度、运行时间与内存预算。不能让候选看内部信号、对手只看软件日志；不能用忽略回调的裸参考模型当唯一对手。

**当前判断：B-score 能表达 O1–O6；本轮没有给出候选独有的可检测错误。** 关系 oracle 可能只是 scoreboard 的另一种写法，generic bounded model checking 也可能直接完成全部任务。因此 C2-O 的新算法主张现在不成立。

可能值得继续审的剩余差异只有两种，均需新证据：

1. **接口知识贡献：** 给出一组现实接口的最小观测/同步条件，证明某些接口组合在信息上不足，并由两个独立实现中的集成错误或可复现错误类别说明这个缺口被常规流程忽视。不能只把 O6 的显然结论重复包装。
2. **验证方法贡献：** 在相同输入与预算下，证明某种分解减少所需状态/事件却保留目标错误类别的判定能力；对比 B-score 与现成关系模型的直接编码。若只是成熟 partial-order reduction 的普通应用，应明确降级。

“发现若干 bug”既不是充分条件，也不是必要的新算法证明。若只发现当前明确 TODO 所对应的缺失能力，属于已知实现边界，不用它当新漏洞数量。

## 6. 最小决定性证据和真正的否决条件

本轮不执行；若根协调在后续选择继续，此候选第一阶段只需一份有明确界限的模型说明，不改完整平台。

**最小审查包：**

1. 冻结 O1–O6 的事件定义和规范条款，尤其是 processed、G 与 Fdone；写清不能从哪些现有信号推出它们。
2. 手工的正确/错误实现草图各一个，差异仅为错误完成时机或旧 epoch 污染；不是以 RTL TODO 自动充当错误实现。之后才考虑用工具枚举有限事件顺序。
3. B-score 先行。候选若只做允许集合，就在同输入下比较；明确哪个具体结果是 B-score 检不出、误报或需要显著更多状态的，不能只报覆盖率百分比。
4. 在上板前给出一个不依赖本平台的真实接口失配来源；找不到就将它定位成本地验证资产。

**立即降级/停止主线的条件：**B-score 或现有模型的直接接口扩展覆盖同一错误集合且成本相当；没有真实 processed/G 观测而只靠假设宣布通过；所有例子都是标准明说的规则且没有新接口后果；需要先补全 ATS/nested/互连才找到区别；只凭“六席都觉得有潜力”立项。当前已触发“尚无同信息差异”，所以只保留问题，不给主线通过票。

## 7. 对其他方向的 R3 简短更新

- **前置归属 C1-A：** C1 已接受小身份表＋RR＋限额。我的最新来源没有替它证明缺口，也不给它更低的新颖性标准。若 C1 拿不出合法、现实且同资源的差异，按其自设门禁降级。C2-O 不应与它合并成没有边界的大“责任账本”。
- **A1 的自我降级有道理，但算术拟合不是物理归因。** A1-X2 针对不同格反推出不同 `s_A`，目前支持“普通模型足以解释的可能性”，尚未验证一个固定参数的预测模型，也没有证明谁是串行服务者。无需因此强迫所有新路线先定位约 680 周期的唯一模块。
- **R2 的硬事实应覆盖陈旧质疑。** C1 已查明私有 buffer、AXI 两读两写、fast accept 必须 hit、自主硬件闭环供给；D1/D2/D3 不再将这些列为待新板测的未知。错给 A8 两条而要求 miss 下降的 E1a 仍应删除。
- **D2 的“等待槽产权”不能凭命名获得新问题。** miss owner 等待下游，不等于它为其他域创造了可收费资源；若 fast 不延长其占用，支付信用的成本依据尚缺。先与不收费的工作保持复用、普通 quota 比较；身份明确只让账本能记账，不证明账本有外部价值。

我的 R3 投票：**C2-L 新调度：撤回；C2-T 独立接口：撤回；C2-O：允许一个有界模型/新颖性判别阶段，当前仍低于主线成立门槛。** 这轮新增的是可审查实例、强简单对手和更清楚的规范边界，不是已证论文创新。

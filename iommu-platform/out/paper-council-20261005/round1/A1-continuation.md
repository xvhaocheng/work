### （F3 续）替代解释

上接“替代解”：至少还有四条与相位假说竞争的解释，按威胁程度排序。

- **Alt-1：共享数据缓冲仲裁直接造成锁相，与翻译无关。** 威胁最大。
  - [EVIDENCE] DMA0 与 DMA1 共用同一块 512 拍缓冲（composition-v1-spec-20261004.md:4）。V 固定在 V0，A 只能是 none 或 1（composition-v1-spec-20261004.md:44）。
  - [EVIDENCE] 所有 g0 格中，A 完成数都恰好是 4096，四种模式无差别（A1-partial.md:47，待核实）。A 全命中的 A1 格中，V 窗口也几乎翻倍（A1-partial.md:37）。
  - [INFERENCE] 如果 A 的发射不受约束，它在 V 窗口内的完成数理应随模式变化。四种模式都精确 1:1，更像缓冲轮转授权：每个 V 传输对应 k 个 A 授权。若如此，F2 的锁相是数据路径仲裁的产物，F3 中“miss 落在 gap 里被吸收”的机制也就不必要。
- **Alt-2：harness 或驱动在软件层把 A 与 V 耦合。**
  - [ASSUMPTION] 我没读驱动，不知道 A 的提交循环是否以 V 的完成为节拍。若是，锁相就是实验构造出来的。
- **Alt-3：工作点不同，而非相位不同。**
  - [EVIDENCE] S 与 P 下 A 的完成数不同（14041 对 12294，A1-partial.md:69–70）。
  - [INFERENCE] 因此“每个 A miss 的 V 代价”混入了 A 的吞吐差异。分母选错，就可能人为造出约 4 倍的差距。这一条正是 C1 要检验的内容。
- **Alt-4：替换器状态有确定性周期。**
  - [INFERENCE] 带 mask 的 tree-PLRU（composition-v1-spec-20261004.md:5）会改变 A 被驱逐页的序列，从而形成确定性的 miss 时序模式。这是缓存状态的周期，不是时间上的相位。

**零成本的区分手段。** [RECOMMENDATION] 在既有的 raw128 中逐格查看以下字段，不需要上板：
- GAP 实际占用：offset 24/25；
- 填充：26–28；
- fast accepts：21–23（composition-v1-spec-20261004.md:25–27）。

同时由 C1 或 C2 的作者读 DMA 缓冲仲裁 RTL 和驱动提交循环，判定 Alt-1 和 Alt-2。只要 Alt-1 或 Alt-2 成立，F3 的“翻译相位”表述就必须撤回。

## 2. 候选论证

### A1-C2（首选，有条件）：串行共享 IOMMU/DMA 的锁相阶梯与“相位脆弱”的评测

- **非平凡贡献**，共三层，可以只成立前两层：
  1. [INFERENCE] 刻画：V 的干扰随 gap 呈离散阶梯，且不单调；同一策略相对 S 的符号会随 gap 翻转（证据见 A1-partial.md:74–77）。
  2. 一个可证伪的离散模型。参数只有三类：V 周期、A 单次服务时间、仲裁粒度。它预测阶梯台阶的位置和 k 值。
  3. 方法学结论：只在单一 gap 下评测 IOTLB 分区或 QoS 策略，可能得出符号相反的结论；用 gap 抖动或随机化做评测才稳健。
  
  第 3 点突破了 P/N/PN 框架。它的论文对象是评测方法本身，不是某个策略的胜负。
- **最强已有替代：** 评审会说“周期系统的混叠和相位效应是常识”。实时领域的相位/偏移分析、测量式时序分析里的相位敏感性都指向这一点（具体文献：citation unavailable from the provided context，待 C2 核对）。此外 Alt-1 和 Alt-2 可能把现象降格为实验构造。
  - [INFERENCE] 能抵挡这种攻击的只有两样：在 IOMMU 或 DMA 场景下给出定量的符号翻转实例，以及样本外预测成功。
- **最小决定性实验：**
  - 第 0 步，零成本：读仲裁 RTL 和驱动，判定 Alt-1、Alt-2。
  - 第 1 步：在 A8 下，对 S 与 P 做 gap 细扫，约 40–60 个点，覆盖 0–8000。用一半的点拟合模型，另一半预测台阶位置。
  - 第 2 步：加入 gap 抖动组。
  - 对照基线：随 gap 平滑单调的连续模型。
  - [EVIDENCE] 当前 ABI 只允许 gapV 取 0、1000、4000 三个值（composition-v1-spec-20261004.md:44），因此必须放开驱动校验。[INFERENCE] 不需要改 RTL。
- **资源代价：** 低到中。驱动需要一处小改动。运行约 2 模式 × 50 点 × 至少 2 boot，共数百次。单次耗时未知，待从 records 核实。按 BRIEF.md:6，现在只做计划，不改源码。
- **Go：** 以下条件全部满足。
  - 在至少 2 个 boot 中都出现 3 个以上平台。
  - 样本外台阶位置的误差不超过预先登记的容差（建议不超过扫描步长）。
  - P 相对 S 的符号翻转可复现。
  - 抖动后翻转消失，或可被模型预测。
- **Stop：** 出现以下任一情况即停。
  - A 完成数随 gap 平滑变化。
  - 台阶位置无法预测。
  - 跨 boot 不复现。
  - 第 0 步证实锁相由 harness 构造（Alt-2）。若是 Alt-1，则转入下文的 C2′，不直接停。
- **C2′ 变体：** 若 Alt-1 成立，主线改为“下游数据缓冲仲裁塑形并掩盖翻译干扰，IOMMU QoS 评测因此会归因错误”。
  - [INFERENCE] 这仍是方法学贡献，但它会把论文从 IOMMU 拉向 DMA 与互连，需要 C2 席位评估其新颖性。
  - 决定性实验：若硬件可行，把 A 放到不共享缓冲的 DMA2/3（需改 ABI，可行性待核实）。锁相若随之消失，Alt-1 即被确认。

### A1-C1（C2 的第一刀，留在 PN 框架内）：分区即隐式限流

- **非平凡贡献：** [INFERENCE] 单独成文偏弱。它的价值在于一个纠偏结论：如果 P 的收益可以完全由“降低 A 速率”复现，那么容量分区在串行 IOMMU 上就没有独立价值。这个阴性结论也可以作为 C2 论文中的一节。
- **最强已有替代：** 带宽限流类方法，即 MemGuard/MemPol/MemCoRe 一路（research-literature-review-20261004.md:20,25）。只要限流就能保护 V，这是常识。
- **最小决定性实验：**
  - 在 S 下扫 Agap，画出 V 开销对 A 进度的限流前沿；把 P、N、PN 点叠在图上。
  - 基线是同一 A 进度下的 S 加限流，而不是 S 单列。
  - [EVIDENCE] 当前 ABI 只允许 Agap0（composition-v1-spec-20261004.md:44），需要放开。
- **资源代价：** 低。约 4 个 gap 值 × 3 个 V gap × 至少 2 boot。
- **Go：** P 点严格优于 S 限流前沿，幅度超过噪声（参考 V 窗口约 0.9% 的波动，A1-partial.md:59，待核实），且在至少 2 个 V gap、2 个 boot 上成立。
- **Stop：** P 落在前沿上或前沿以内。此时记作“P 即限流”，不再投入 P 的方法主张。这与 composition-v1-spec-20261004.md:49 的规则一致：只有缓存常识，就不包装成方法论文。

### A1-C3（高上限备选，突破框架）：翻译层时序信道，容量分区关不掉

- **非平凡贡献：**
  - [INFERENCE] 在共享 IOMMU 上，即使按 QoSID 式分区隔离 IOTLB，DMA 域之间仍存在一条信道，经由串行控制、PTW 占用和缓冲传递。
  - 需要量化其容量（bit/s），并评估一种时间分区缓解措施的代价。
  - [EVIDENCE] 依据有三：A 零 miss 时 V 窗口仍然翻倍（A1-partial.md:37）；规范的 QoSID 只做身份关联、不保证调度（research-literature-review-20261004.md:23）；本实现明确“不是新安全隔离”（composition-v1-spec-20261004.md:4）。
- **最强已有替代：** “共享资源存在争用信道，分区不能消除时间争用”是已知原理。内存控制器上已有时间分区防护工作，例如 Wang, Ferraiuolo, Suh 在 HPCA 2014 的 “Timing Channel Protection for a Shared Memory Controller”，[ASSUMPTION] 我相信该文存在，但细节待 C2 核对。IOMMU 上是否已有 IOTLB/PTW 信道论文：citation unavailable from the provided context。Bermuda 只做了性能干扰表征（research-literature-review-20261004.md:17）。
- **最小决定性实验：**
  - 发送方 A 在每个比特窗口内调制自身行为（none/A1 或 Apages1/16）；接收方 V 测量逐传输延迟。
  - S 与 P 各测一次容量；基线是 Solo 的随机噪声。
  - [EVIDENCE] 现有窗口只有聚合周期数（composition-v1-spec-20261004.md:18），缺逐 job 时间戳，需新增观测。
  - [INFERENCE] 若用聚合窗口作 1 bit/窗口的粗信道，只能证明信道存在，算不上论文级结果。
- **资源代价：** 中到高。需要逐请求时间戳（RTL 或驱动），需要 Vpages>1；还要威胁模型论证，说明多租户 DMA 设备共享 IOMMU 是现实场景。
- **Go：** P 下的信道容量与 S 处于同一量级（例如不低于 S 的 50%，预先登记）。同时某种时间分区缓解能把容量压到噪声水平，且代价可以量化。
- **Stop：** P 已经把容量压到噪声水平；或逐请求时间戳在本平台不可实现；或 C2 席位找到 IOMMU 争用信道的直接先例。

### A1-C4（正交后备，完全脱离性能主线）：开源 RISC-V IOMMU RTL 的规范一致性差分测试

- **非平凡贡献：**
  - [INFERENCE] 把 RTL 与参考模型做 trace 差分，再加规范导出的定向和随机用例，系统发现一致性缺陷。
  - [EVIDENCE] 一个已有信号：本平台修复过 DS/PTW 缺陷后才通过验收（BRIEF.md:7）。该 IP 与 DATE2025 使用的是同一开源 IOMMU（research-literature-review-20261004.md:22）。
  - [ASSUMPTION] 该缺陷是否存在于 upstream，未知。
  - [ASSUMPTION] 参考模型可能用 QEMU 的 riscv-iommu 设备模型，是否已在 upstream 待核实。
- **最强已有替代：** 该 IP 自带的测试平台；通用硬件模糊测试，即处理器 RTL fuzzing 一类（具体文献 citation unavailable，待核对）。评审可能视为工程贡献。
- **最小决定性实验：** 先比对 DS/PTW 缺陷的根因与 upstream 当前代码。若 upstream 仍有该缺陷，就以它为种子，搭建最小差分框架，跑定向用例。
- **资源代价：** 第一步极低。之后中等：[EVIDENCE] 目前没有完整的 IOMMU Verilator 环境（research-literature-review-20261004.md:75）。不需要板卡。
- **Go：** 在预先给定的计算预算内，发现至少若干个新的、可复现、经规范条文确认的违例，最好有 upstream 维护者确认。
- **Stop：** upstream 已修复且预算内零新缺陷；或参考模型本身不可信，差分无法判定对错。

## 3. 首选 / 备选 / 不做

[RECOMMENDATION] 执行顺序如下。

1. **第 0 步，零成本，阻断性：** 读 DMA 缓冲仲裁 RTL 与驱动提交循环，判定 Alt-1、Alt-2；查 raw128 的 offset 21–28。
2. **首选 C2，以 C1 作为第一刀：**
   - 第 0 步排除 Alt-2 后，先做 C1 的 Agap 前沿，因为最便宜，且能直接裁定 P。
   - 再做 C2 的 gap 细扫与样本外预测。
   - 若 Alt-1 成立，改走 C2′。
3. **备选：**
   - C4 不依赖任何性能结果，可以与 1、2 并行，成本最低。
   - C3 只在 C2 的机制定位到串行控制或 PTW 占用之后才启动；它与 C2 共享逐请求时间戳这项投入。
4. **不做：**
   - 在固定 gap 下继续比较 P/N/PN 的胜负。理由：F3 显示符号依赖 gap，单点结论不可信。
   - 只用“每个 A miss 的 V 代价”立论。理由：Alt-3 中分母混杂。

## 4. 自我反驳

- [INFERENCE] 对 C2 最强的反驳来自我自己的 F1：A1 时 A 零 miss，V 仍然翻倍（A1-partial.md:37）。这说明干扰主体可能根本不在翻译层。F3 的“A miss 落入 gap”机制因此是可疑的，C2 可能退化为 C2′，即 DMA/互连论文，离 IOMMU 主线更远。
- [INFERENCE] g0 下四种模式 A 都恰好 4096，太整齐了，更像构造出来的数，不像物理现象。我在 R1 前半部分把它当作发现，可能高估了它。
- [INFERENCE] 阶梯模型即使预测成功，也可能被评审视为“确定性仲裁的显然推论”。论文必须靠方法学后果来立住，即评测符号翻转的普遍性；而这需要在第二个平台或仿真上复现，目前不具备。
- [EVIDENCE] 全部证据来自单 boot（BRIEF.md:7–8），三个 block 不是独立样本。F2、F3 的“复现”只是同 boot 内的重复。

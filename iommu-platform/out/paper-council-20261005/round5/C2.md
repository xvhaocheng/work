# R5 / C2：最终可发表性判断与有序计划

日期：2026-10-05。已读 R4 六席位完整意见和 `R5-plan-boundaries.md`。本轮只收束判断，未扩检索、未运行新探针/模型/实验，未构建、上板或修改生产代码。

## 1. 最终判断

**目前没有一条正式论文主线通过证据门槛。** 旧 P/N/PN 组合没有足够独立新意；新机制或被同信息的简单方法覆盖，或尚未给出正确且有应用意义的区别。172 项功能验收仍有效，但不支持新候选的撤销安全、性能收益或创新结论。

这不是“共享 IOMMU 领域无论文可发”。五轮讨论淘汰的是当前提法，也整理出可复用的源码事实、测量口径和规范实例。六席一致不增加创新证据；不为凑一个主线而复活已撤回机制。

## 2. 首选：排空完成的跨接口依据是否充分

**优先问题，不是已批准的论文题目：** 对一个真实 host-bridge/IOMMU/主存组合，现有接口能否为“先前已处理读写达到全局排序点”提供可证明的依据；若不能，缺的究竟是实现接线、文档前提，还是需要新的观测/同步契约？

优先它，是因为已经掌握规范边界和强基线，下一份材料能直接裁决剩余不确定性。不是因为 oracle 获得最多票，也不是因为当前 RTL 有 TODO。

### 第一步：只读，交付一份窄接口合同

- **范围：** 本平台 IOMMU↔桥接器↔普通主存的关键接口与必要协议说明；单级普通页，无 ATS/nested/设备缓存。读与写分别审，不用写响应替代读完成。只读这些边界，不默认全仓扫描。
- **交付物：** 一张 `device submit / processed / translation response / G / Fdone / software observation` 的映射表；每项列可用信号、成立前提、直接来源、缺失事实。另列官方 PR/PW hook 的环境责任怎样由现有接口兑现。
- **本步不重做：** accepted fast 必 hit、私有 buffer、四 burst、PR/PW TODO、官方回调存在；O1–O6 已被手工覆盖，也不重新测试并称作发现。
- **判定：** 若正确连接既有 callback 与普通 request/epoch scoreboard 足够，结论是工程接线/验证资产，关闭“新 oracle”主张。若仅缺文档或观察不到 G，结论是未解决前提，不能据此宣布漏洞或创新。

当前 PR/PW 能力缺口不会被这份合同自动补齐；这一步审研究可行性，不修改生产 RTL，也不认证整个平台安全。

### 第二步：只有出现具体差异，才做小模型

准入条件不是“存在未知”，而是至少出现一项可审查的实质差异：普通接口接法会造成现实误判；一种额外顺序关系是必要的；或可证明以更少状态/事件维持同一检查能力。先写出确切性质、最小事件序列和环境前提，再决定模型范围。

强对手固定为 **官方 ref＋实际 PR/PW hook＋普通逐请求/映射版本 scoreboard**。输入、可见内部事件、状态与运行预算对等。B 响应不能未经证明等同 G；标准全局 fence 的义务不能按撤销对象缩小；局部复用证书若另设接口，须完整计入协议成本。

**结束条件：** 最后仍只是重述 PR/PW 规则、O6 的同投影不可区分，或给已有 scoreboard 加常规字段，即结束这个创新方向，留下接口合同。不能靠加入 ATS、nested、别名和新硬件持续扩大任务来挽救它。

## 3. 备选：已有共同窗口现象的回溯诊断

若首选没有研究差异，且仍希望从现有数据寻找可迁移问题，再做这一项；两条不必同时启动。

**问题：** 已有 PN/A8 的 gap 变化及 N/PN 排序，哪些部分与普通闭环供给、服务成本和仲裁相容；哪些竞争解释给出不同的未来预测？

**成本与交付：** 现有数据离线分析；输出一份明确适用范围的竞争模型说明、参数来源、共同窗口完成率与残差/不确定性表，最后最多提出一个能区分解释的未来观测设计。

必须守住四点：

1. 全部 172 条都已被看过，只能称回溯诊断；此后冻结规则不变成真正未见数据的预注册。
2. 全 hit 的单一服务时间不能无依据外推到不同工作集/模式，也不能逐格自由拟合。缺独立成本依据就缩小模型范围或明确不可识别。
3. `A_window/T_window` 是有效的共同窗口完成率；whole-round 可变尾部另记。0.9% 极差不是统一误差阈值。
4. 拟合好不证明物理根因，残差大不证明 IOMMU 特有机制，更不自动授权逐请求仪器或新板测。只有竞争模型对尚未观察条件给出不同预测，才设计针对性确认；确认条件、指标与误差判据先写清。

**结束条件：** 普通模型覆盖所需描述而无新评测后果，或现有数据无法区分且没有现实应用需要区分，就以表征/诊断资产收尾。不要用弱模型必然失败来制造下一阶段理由。

## 4. 新颖性证据关卡与可能贡献

| 可能贡献类型 | 需要的实质结果 | 目前状态 |
|---|---|---|
| 设备语义/接口知识 | 非显然且必要的完成/观察合同；来源可追溯；对独立接口或实现产生可复现后果 | 未有；首选只读任务判断是否存在入口 |
| 验证方法 | 同性质、同信息下更少状态/观测/求解成本，或明确的可靠性改进；与强 scoreboard/关系模型比较 | 未有；普通允许集合不算新方法 |
| 评测方法/表征 | 可迁移的误判边界、可区分预测与确认；超出已知周期同步和负荷反馈的普通实例 | 现有描述性现象，不足以成文 |
| 新架构/调度 | 真实需求、同安全语义和同信息下强简单对手失败、候选成功，且成本透明 | 当前全部未过 |

[TransForm](https://arxiv.org/pdf/2008.03578) 和 [Arm relaxed virtual memory](https://www.cl.cam.ac.uk/~pes20/RelaxedVM-Arm/RelaxedVM-Arm-esop2022.pdf) 已覆盖关系模型、允许行为与 litmus 路线；[官方参考模型](https://raw.githubusercontent.com/riscv-non-isa/riscv-iommu/main/iommu_ref_model/README.md) 已有排空回调。不能靠更换研究对象获取方法新意。ShareMMU 等最近邻的核查边界见 [R3 来源](../round3/C2-literature.md)；未发现精确相同目标不证明空白。

**保留细微边界：** 能被 scoreboard 编码，不自动排除语义或接口知识贡献；任何有限检查都能被程序表达。应比较明确的强实现及其成本，并证明新知识为何必要。反过来，规则写得更清楚也不自动足够发表。当前缺实质差异与独立后果，不作投稿 venue 或发表概率承诺。

## 5. 不做与重启条件

- 不再以 P/N/PN 组合、四次翻译软件消除、普通 hit-under-miss、slack 公式、VC/response 槽、等待槽产权、普通差分测试作为独立创新；对应旧提案维持撤回。
- C1-A/B、C2-L/T 只有获得真实需求与同信息强对手不能满足的具体保证，才重启。补齐 PR/PW 本身是基础正确性工作，不能顶替贡献。
- 不缩小同一 IOFENCE 的全局义务；不以 `t_B > t_AV` 裁决非法；不以 `k×burst` 字节量推时间上界。
- 不扩 gap 大矩阵、不设任意百分数/boot 数门槛、不把新仿真/RTL/板测列为现在的默认下一步。

若首选与备选均未产生上述研究差异，就结束围绕这些候选的创新论证，保留平台与验证资产；下一次选题应从具体应用的未满足约束重新出发，允许离开当前板卡和 P/N/PN。换名字或增加模型轮数不是重启证据。

## 6. 最终优先级与分歧

我推荐 **窄接口合同只读审查 → 有条件小模型**；备选为 **已有数据回溯诊断 → 有条件的新确认设计**。两者都不等于正式主线立项。与 R4 多席提出的“再用 B-score 测 O1–O6”不同，我认为其覆盖已清楚，无需为跑一个探针重复证明。

D1 对评测反馈的研究潜力更积极，我把它列备选；A1 已撤回其 oracle 和兼容选择性排空主张，应在最终汇总中保留撤回。D2 已撤回机会账本，不再当待投票路线。共同承认“尚未过门”不意味着共同证明“没有创新”。

本席位五轮结束。Codex C2 完成关键原始来源审核与论文判断；没有执行讨论中新提议的探针、实验或实现。最终交付是带停止条件的研究可行性计划。

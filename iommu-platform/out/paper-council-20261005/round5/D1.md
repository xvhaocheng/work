# R5 · D1 最终证据席：最终建议与可操作计划

## 0. 用于最终计划的现状摘要

现有最强事实仍只是：修复 DS/PTW 后 172/172 功能验收通过、单 boot、无性能或创新结论（`iommu-platform/out/composition-ptwfix-20261005/board-acceptance.json:2-31`，其中 `performance_or_innovation_claim=false` 在第 30 行）。同一批数据里存在**描述性共同窗口现象**：A8/g0→g1000 时 V 窗口下降、共同窗口 A 完成数上升，N 与 PN 在同一窗口中方向不同；三 block 同 boot，whole-round A 与共同窗口 A 还会反向，因此现象有效但因果未定（`D1-analysis.txt:2-14,61,63,133,135`；`metrics.csv:38-41,54-57`）。已核定事实包括：accepted fast 必为合格 hit；`raw_v_miss=0` 不覆盖被拒 probe；DMA0/1 各有私有 512 拍缓冲；4 KiB copy 是 2 读 burst+2 写 burst 的四次地址翻译服务，不是 4 页或 4 次 PTW miss；A 是每路自身反馈的闭环供给；当前 RTL 的 IOFENCE PR/PW 仍是 TODO，172 不覆盖撤销/复用（`R4-review-boundaries.md:7,18,19`；`round2/C1.md:9-29,33-47,105-109`）。**当前没有正式论文主线获准。** 若继续，我建议先做 L0 的反馈/共同窗口回溯诊断，再条件性做 L1 的接口语义/B-score 缺口探索；所有探针本轮均未执行，R5 之后也不自动实现、不构建、不上板。

### 1.3 已撤回 / 最终正确口径

1. **“V 总 miss（含 fast）未测”** → 错误。accepted fast 必为 hit；`raw_v_miss=0` 只覆盖 normal first lookup 与被接受 fast，不覆盖被拒 probe 历史（`R4-review-boundaries.md:7`；`round2/C1.md:33-39`）。
2. **`raw_v_fast>0 ⇒ raw_a_miss>0` 是必要条件** → 错误。开窗前开始的 A walk 可延续进窗；它至多是当前样本相关，不是无条件律、判死门或机制必然性（`R4-review-boundaries.md:18`）。
3. **“窗口 A 不是 goodput”** → 过度通判。共同窗口完成率有效；A 裸计数不是速率；whole-round 尾段另报（`R4-review-boundaries.md:19`；`round4/D3.md:6-11`）。
4. **“A8 是 8 条翻译/有 index-set 冲突”** → 错误。A8 是源 8+目标 8=16 页潜在足迹；本实现全相联（`round2/C1.md:49-53`）。
5. **“DMA0/1 共享同一 512 拍缓冲”** → 撤回。各 DMA 私有缓冲（`round2/C1.md:9-15`）。
6. **“128 周期是自然单次阻塞上界/可乘作业数”** → 错误。128 是人为单次剂量，不是自然分布、信道容量或时间上界（`e3-controlled-results-review.md:41,57`；`round2/C1.md:81-83`）。
7. **“A 是固定外部到达流/改 gap 只改相位”** → 错误。A 是闭环供给，gap 同时改负荷与释放相位（`round2/C1.md:41-47`）。
8. **“A miss 不降就证明 P 失败”** → 错误。P 生效时 A 工作集被压到 2 条，miss 增加或不降可以是设计结果；P 正确性看 mask/分配位置/请求归属，效用要选符合容量关系的负载（`round3/C1.md:69`；`round4/D3.md:21-22`）。
9. **“AXI B 响应晚于 AV 即非法写落地”** → 错误。B 响应不是规范全局排序点 G；必须定义抽象 G 或证明平台映射（`R4-review-boundaries.md:15`；`round4/A1.md:15-34`）。
10. **“选择性排空可缩小同一 IOFENCE 对其他已处理访问的义务”** → 不成立。同一 IOFENCE 义务不能因撤销只涉及 A 而缩小；新证书接口须完整计成本（`R4-review-boundaries.md:16`；`round4/C2.md:29-43`）。
11. **“官方 ref 完全不知排空/只与逐条相等 oracle 比”** → 错误。强对手至少是官方 ref + PR/PW 回调 + 逐请求/epoch scoreboard（`round3/C2-literature.md:20-24`；`R4-review-boundaries.md:17`）。
12. **“等待槽产权/跨租户外部性已被观测”** → 未观测。当前只有聚合 fast/fill/replace/inval 计数，无 per-event creator/consumer、credit 前后与 slot 起止（`round4/D1.md:119-124`；`round4/D2.md:5-17`）。
13. **“三 block 或旧 172 可作真正预注册确认”** → 不能。三 block 同 boot；旧 172 已被各席看过，后续只能称回溯诊断，不能称未见 holdout 或预注册确认（`BRIEF.md:8`；`R5-plan-boundaries.md:9`）。
14. **全 hit 单一服务时间硬外推 A8/A16/N/PN** → 不允许。服务成本变化需独立依据或明确限定适用范围；拟合好只说明相容，残差大不自动说明 IOMMU 根因（`R5-plan-boundaries.md:10`；`round4/C2.md:59`）。
15. **noise 极差当误差阈值、`k×burst` 当时间上界** → 不允许。阈值须来自待判断目标与误差模型；在途数×字节数不是时间，只有每段服务/背压界明确后才能换算（`R5-plan-boundaries.md:8,11`）。

### 1.4 未知 / 不可识别

- 共同窗口现象的真实因果：是普通非抢占交替服务、闭环释放相位、窗口删失，还是共享翻译持有/释放边界；当前无 per-request owner trace（`round4/D1.md:142`）。
- 自然 A miss/阻塞分布、被拒 fast probe 的 miss 历史。
- 官方 ref + PR/PW 回调 + 请求/epoch scoreboard 之外，是否存在现实接口上的非平凡语义缺口或状态/事件成本优势（`round4/C2.md:65-81`）。
- 反馈/闭环模型能否预测未来独立数据，而不是解释已看过的 172（`R5-plan-boundaries.md:9`）。
- 任何新机制是否独立胜过免费 N、per-DID quota/token bucket、WFQ、RR+在途上限、静态预留+固定优先级。
- 第二平台、跨 boot、跨实现外部有效性。

## 2. 独立优先级意见：反馈评测 vs 接口语义探索

**我的独立意见：先做反馈评测的回溯诊断，把它当作“决策门”，不是主线；接口语义探索放第二，作为高上限但高风险的备选。**

理由：

- 反馈评测可用现有数据，成本最低，直接决定旧 N/PN/P 共同窗口现象是否只是普通排队/闭环相位；若解释掉，旧线可干净关闭，避免继续包装 P/N/PN。它是证据卫生问题，不是新机制问题。
- 接口语义探索的新颖性上限更高：可能形成验证/接口知识贡献，而不是只做限流。但当前每个候选都被强 scoreboard 压迫，只有出现非平凡差异、现实接口后果、成本/状态优势或泛化证据，才可能立项；不能只打弱单值 oracle，也不能只重述规范。
- 两者不应合并：反馈评测失败不能救接口语义；接口语义可行也不能证明旧 N/PN/P 有性能收益。

## 3. 最终建议：首选 / 备选 / 不做清单

### 首选 P0：RQ-F — 共同窗口与闭环反馈回溯诊断

**研究问题：** 在闭环 DMA 与共同窗口观察下，N/P/PN 的差异是否可由普通非抢占交替服务/闭环释放相位解释？若不能，残差是否集中在可指认的共享翻译持有/释放边界？

**定位：** L0 离线回溯诊断；不是确认性预注册，不自动升级为论文主线。

**最小数据/字段：** 只用现有 `metrics.csv`、`D1-analysis.txt`、`board-acceptance.json` 的 boot_id。字段：case id、mode、a_pages、v_gap、v_window_cycles、a_completed_jobs_window、raw_v_lookup、raw_v_fast、raw_v_miss、raw_a_lookup、raw_a_miss、raw_v_gap、raw_inval_cycles、block、source。**不新增矩阵，不扫 gap，不扩 boot。**

**交付物：**
1. `RQ-F-common-window-audit.md`：共同窗口 A 完成率、V 窗口、whole-round A 尾段；只报现有数据。
2. `RQ-F-S0-residual.md`：固定参数 S0 回溯残差。S0=普通非抢占交替服务/确定性仲裁；参数只能来自事先声明的子集，禁止逐格自由拟合；报告 block 方向与残差位置。
3. `RQ-F-decision.md`：明确 stop / 条件进入 L2。

**成本层级：** L0 + L1 纸面模型。

**证据门槛与停止：**
- 若 S0 以固定参数预测共同窗口下 N/PN 方向与量级，残差未集中在同一 owner 边界 → 关闭 N/PN/P 机制主张，保留为普通排队/仲裁或评测限制。
- 若残差大且同向集中于“某请求 owner 持有/释放”边界 → 才允许设计 L2 最小释放规则对照。
- 若残差大但无法指认边界、或必须靠事后调参才有解释 → 不进入 L2，降为表征/负结果。
- 不许用噪声极差当阈值；阈值须按计数分辨率和同条件重复展开，且诚实标注有限数据局限。

**若进入 L2 的最小设计：** 只做 N vs PN、A8/g1000、闭环完成触发 vs 开环固定间隔、两个初相位；每 job 记录 release/issue/complete、DID、R/W、burst、translation event、fast accept、wait start/end、owner bank。不得扩成八模式大矩阵。

### 备选 P1：RQ-S — 接口语义/B-score 缺口探索

**研究问题：** 在官方 ref + 真实 PR/PW 回调 + 逐请求/epoch scoreboard 之外，是否存在现实接口上的非平凡语义知识缺口，或显著状态/事件成本优势？

**定位：** L1 纸面/模型；不做 RTL，不重测已能手工覆盖的 O1–O6 当新发现。

**最小数据/字段：** 固定官方 ref commit；抽象事件 `submitted / translated / processed / G / Fdone / AV`；请求 ID、DID、R/W、页/范围、PTE 版本、失效 epoch、PR/PW、错误/超时。只允许一个真实接口、一个合法/非法对、一个状态成本主张。

**交付物：**
1. `RQ-S-bscore-contract.md`：官方 ref + PR/PW 回调 + 请求/epoch scoreboard 的伪代码与抽象事件表。
2. `RQ-S-gap-table.md`：至多两个候选缺口；B-score 行为；状态成本；现实接口后果。
3. `RQ-S-decision.md`：stop 或申请独立实现核对。

**成本层级：** L1 只读/纸面；只有过门后才谈 L2 小仿真。

**证据门槛与停止：**
- B-score 用同输入、同观测、同状态/时间预算覆盖同一错误集合 → 停止新 oracle/语义算法主张，只留验证资产。
- 只有打败弱 O-eq、只重述 O1–O6、只缺回调/TODO、必须靠缩小 IOFENCE 义务、必须加 ATS/nested/设备缓存才找差异 → 停止。
- 可继续的唯一条件：B-score 同预算下漏报/误报，或需显著更多状态；缺口对应真实接口；并在第二个独立接口/实现出现同类后果。
- 若通过，也只是验证/接口知识候选，不自动成主线；仍需独立数据与公平比较。

### 不做清单

- 不把 P/N/PN 组合本身当主创新；不救 hit-under-miss、预留/分区、token bucket、纳秒级、FPGA 快节流等已有概念。
- 不做等待槽产权账本作为已观测机制；不做租户自时钟拥塞控制；不把选择性排空包装成同一 IOFENCE 的缩小义务。
- 不把弱单值 oracle 当强对手；不把官方 ref 说成不知排空。
- 不用新增功能数量逃避新颖性门槛；不扩 ATS/nested/设备缓存来制造差异。
- 不重证 fast hit、私有缓冲、四 burst、PR/PW TODO、官方 ref 回调等已核定事实。
- 不做旧 172 的“预注册确认”；不得称未见 holdout。
- 不用全 hit A1 单一服务时间硬外推 A8/A16/N/PN；不用噪声极差当误差阈值；不做无服务/背压界的 `k×burst` 时间上界；不用 128 周期造自然上界/信道容量。
- 不在过门之前实现、构建、上板、写 SD；不把模型共识当证据。

## 4. 顺序与成本层级

1. **L0 P0 反馈回溯诊断**：只读现有数据，产出共同窗口审计 + S0 残差 + stop/go。
2. **若 P0 停止**：关闭旧 N/PN/P 机制主张；保留描述性现象、负结果、工具边界。
3. **若 P0 残差大且集中**：进入 L2 最小释放规则对照，只补 per-request owner 字段，不扩大矩阵。
4. **L1 P1 接口语义/B-score 缺口**：可在 L0 之后并行或紧随；必须先写 B-score 合同，再找非平凡差异。
5. **若 P1 停止**：只留验证/assertion 资产。
6. **若 P1 过门**：申请独立接口/实现核对；仍不自动进入 RTL 或板测。
7. **L3/L4 只在 L2 与 P1 明确过门后讨论**；R5 之后不自动执行。

| 层级 | 含义 | 本轮计划允许 |
|---|---|---|
| L0 | 只读/现有数据离线分析 | P0 主入口 |
| L1 | 纸面/小模型 | P0 模型、P1 B-score 合同 |
| L2 | 小仿真/软件重建 | 仅 P0 残差过门后最小释放对照 |
| L3 | RTL/FPGA 构建 | 不在本轮计划自动启动 |
| L4 | 板测/多 boot/第二平台 | 不在本轮计划自动启动 |

## 5. 争议关闭与保留

**可关闭：**
- 等待槽产权账本作为独立机制：D2 已自撤回，免费 N/per-DID quota/WFQ 未被击败（`round4/D2.md:5-17`；`round4/C1.md:9-23`）。
- A1 的 `t_B>t_AV` 非法实例：规范错误，撤回（`round4/A1.md:15-34`）。
- D3 TSSC/HOL-D：已撤机制立项，强简单对手未败（`round4/D3.md:201-207`）。
- D1 早期“必须 whole-round 才能谈 goodput”过度撤回：共同窗口率有效（`round4/D1.md:27-38`）。

**保留：**
- 共同窗口现象有效但因果未定，P0 是它的最低成本关闭门。
- C2-O/接口语义是否还有非平凡接口知识贡献未关闭，但必须过 B-score 门。
- D3/C2 联合撤销是否可能在 L1 找到最小反例未关闭；当前强简单规则未被击败。
- 反馈评测是否有方法/负结果发表价值未关闭；但当前不足以支撑机制主线。
- 真实分歧继续保留；六席一致不是证据。

## 6. 结论

**R5 最终建议：当前无正式论文主线获准；允许全部旧机制候选关闭。** 下一步不是继续为 P/N/PN 找理由，也不是加功能凑新颖性，而是按优先级执行一个 L0 反馈回溯诊断，条件性执行一个 L1 接口语义/B-score 缺口探针。首选 P0 负责关闭或保留共同窗口争议；备选 P1 负责判断语义/接口知识论文是否还有非平凡空间。所有探针均未执行；R5 之后不自动实现、不构建、不上板。

# R2 · C1：先纠正拓扑与可观测量，再保留可证伪的新方向

**结论：A1、D1、D2各有一处关键前提需要纠正；这些纠正不会自动证明任何候选。当前最有价值的变化，是将“相位/阶梯”保留为待解释现象，将C1-A前置归因与C2-L联合撤销契约保留为两个尚未成立的新问题，暂不批准大矩阵或新硬件。**

这是R2恢复后的完整整理，不是新一轮。已读其他五席R1及C2文献材料，直接只读核查下列代码，查看根Codex已执行的 `D1-analysis.txt`；本席未执行分析脚本、测试、构建、板测或修改生产代码。R1不变的论证不重写。路径均相对 `iommu-platform/`，文中代码行号是本轮直接读取的现行源码。

## 1. 核查结论与证据边界

### R2-F1：DMA0/1是各有512拍私有缓冲，A1误读了“同512拍”

**事实：** `cva6/corev_apu/fpga/src/ariane_peripherals_xilinx.sv:1264` 在按DMA索引的generate循环内各自实例化 `dma_core_wrap_intf`；`:1278` 对 `i<2` 分别传入 `BUFFER_DEPTH=512`；各实例接自己的 `idma_axi_master[i]`（`:1317`）。`cva6/corev_apu/iDMA/src/systems/cva6_reg/dma_core_wrap.sv:306` 各实例再建立独立backend并传入本实例的 `BufferDepth`（`:312`）。

因此A1 R1 Alt-1中“共用同一块512拍缓冲”是错误的硬件事实，应撤回。64位数据宽度下每个缓冲为4096字节；两路不是争抢一块总4096字节存储。

**仍未排除：** 私有缓冲前后仍有共享AXI mux、翻译控制和返回通道。它们可能形成周期耦合，但不能从“共享”二字直接确定锁相根因。纠正缓冲拓扑不等于排除数据路径影响。

### R2-F2：4KiB copy的四次翻译有直接协议拆分解释

**事实链：**

1. `cva6/corev_apu/fpga/src/ariane_xilinx.sv:159` 设置 `AxiDataWidth=64`，经per-DMA实例参数传给backend。
2. `cva6/corev_apu/iDMA/src/idma_pkg.sv:107` 的最大burst函数对AXI返回256；`idma_legalizer.sv:75`、`:78`、`:82` 用 `min(4096, MaxBeatsPerBurst×字节宽度)` 得到分段边界。这里256×8=2048字节。
3. `idma_legalizer.sv:235` 和`:254` 分别拆读、写；`:289` 与`:295` 为源和目标建立各自剩余长度。`dma_core_wrap.sv:316` 已启用硬件legalizer。
4. `idma_reg64_frontend.sv:153` 的batch配置要求4096字节、正常copy、源和目标4KiB对齐；`:325` 将该长度与源/目标地址送入backend。
5. `rv_iommu_trans_ctl_wrap.sv:628`、`:646` 分别从AW/AR头构建翻译请求，`:678` 发起翻译。

**推断，且与聚合计数相容：** 当前对齐4KiB copy需要两个最大长度读burst＋两个写burst，即四次地址翻译服务。这不是“四个不同页面”，也不是“四次PTW miss”。在既定64位AXI接口上，大页或连续IOVA不能把一个burst变成512拍，故D2-C5提出“靠大页/连续IOVA将4降到1—2”的软件路线缺乏成立条件。

跨burst复用一次已授权翻译、设备侧翻译或更宽接口可以改变这个关系，但它们各自改变微架构、失效/权限边界或总带宽，需要新的等成本比较，不能叫作免费消除驱动冗余。也不能凭四次hit就称翻译“过度供给”：hit处理和输出带宽仍可能稀缺。

**额外直接约束：** `idma_reg64_frontend.sv:155` 在硬件batch中校验4096；D2把512B/64KiB sweep称为只放开ABI且无需BIT不成立。普通非batch接口是否适合比较另论，不能偷换供给路径。

### R2-F3：已接受的fast路径一定是合格命中；probe miss另当别论

**事实：** `rv_iommu_nonblock_hit.sv:84` 的 `dc_ok` 要求DDTC命中、上下文有效及受支持配置；`:94` 的 `leaf_ok` 明确要求IOTLB命中、有效用户4KiB叶项和相应读写权限；`:100` 的 `accept_o` 还要求请求身份稳定、无失效、DDTP/DC一致。失败探测不握手，`:169` 进入REJECT并由正常路径以后处理。`:158` 接受后产生响应，`:171` 等响应接收。

`dma_composition_control.sv:352` 仅在 `fast_i && accept_i` 时累加fast；上层连线见 `ariane_peripherals_xilinx.sv:1053`。因此D1-Q1中“fast请求的hit/miss未知，所以normal miss=0不能说明已服务请求全命中”需要修订：**对本实现、当前受支持正常S1请求分类，已accept的fast必为hit。** 若正常首次miss为0且观察范围完整，则正常服务与fast服务均没有记录到服务路径上的miss。

**重要保留：** 聚合计数不包含被拒fast probe的完整历史；一个探测曾miss后落回正常路径，不应被描述成从未发生任何lookup miss。fast accept也不等于译后地址已经接收、数据已经完成或净性能收益。可用 `normal_lookup+fast_accept` 作为窗口中两类服务事件总数；跨窗口在途边界仍须对账。

### R2-F4：A由独立硬件batch供给，窗口结束后软件停止；尚无锁相因果结论

`linux/drivers/misc/idma.c:2539` 把V设为请求传输数，`:2541` 把A设为 `IDMA_EXPERIMENT_MAX_TRANSFERS`。`:881` 的 `idma_batch_window` 启动batch后只轮询V是否完成，窗口循环内没有按每个V完成逐次补A。`:2593` 明确在V观察结束、硬件窗口已冻结后停止自主A。故A不是“软件每完成一个V就只允许一个A”的供给机制。

`idma_reg64_frontend.sv:544` 等本路 `trans_complete_i` 后进入下一任务或GAP；`:560` 在本路完成后开始gap；`:580` 倒计时结束再发下一任务。这是每路自身反馈的闭环供给，**不是固定绝对时刻的外部到达流**。改变gap既改变平均负荷，也改变相位和下一次释放时间；不能将gap干预等同于纯相位干预。

共享bank guard确实存在：`rv_iommu_banked_ctl.sv:259` 至`:268` 根据未填完写及AW所有者限制新读选择。但 `rv_iommu_trans_ctl_wrap.sv:646` 明确允许合格fullbuffer job旁路该限制；`idma_fullbuffer_certificate.sv:16` 对容量至少4096、正常copy、长度4096和源/目标对齐建立资格。当前batch正以这类job为设计对象。**所以guard存在不证明本次1:1计数由guard造成；它甚至有设计上的旁路条件。** 是否实际在每个相关周期旁路，需事件证据，不在本轮臆断。

### R2-F5：A8不是8条翻译；全相联实现没有固定index-set冲突解释

`linux/drivers/misc/idma.c:367` 设置每片缓冲大小为pages×4KiB，`:369`、`:373` 分别分配源和目标；`:388`、`:393` 分别映射这两片范围。A8应按源8页＋目标8页理解，Vpages1是源1页＋目标1页。两路潜在活跃足迹因此是18条4KiB翻译，而非9条。这是容量压力线索，不是全部条目同时驻留或某次miss根因的证明。

`rv_iommu_iotlb.sv:100` 遍历全部条目做标签比较，`:126` 比较地址空间/stage/VPN，`:339` 的mask约束分配位置。因此D2关于“连续A8页映到同一index set导致冲突miss”的具体解释不符合这里的全相联查找结构。PLRU、分区容量与时间局部性仍可能造成替换；仅增加A2/A4并观察跳变不能区分容量和所谓index冲突。

## 2. 点名质疑：A1的相位/阶梯主线

### C1-QA1：三个gap与近整数完成比，尚不建立阶梯

你观察到的计数结构值得保留，但目前只有0/1000/4000三个gap及有限模式，不能确认存在若干稳定平台及转折位置。1:1、2:1、6:1的窗口总数同样能来自闭环服务同步、AXI公平仲裁和开关窗边界，并不唯一指向IOMMU的PTW相位。R2-F1撤回共用缓冲解释；R2-F4撤回逐job软件补给解释；**剩余机制仍多于一个**。

每miss的V额外周期比值不是单个miss的因果代价。分子、分母、A实际到达序列与停止窗口都受同一调度影响。你的Alt-3是实质问题，不能仅作为附注后继续使用四倍比值作相位证据。

**修订建议：** 将主张收窄为“闭环DMA基准中，工作量与到达过程共同受策略影响，可能使局部机制比较随释放规则翻转”。这比仅声明周期系统有相位更值得检验，也不要求坚持IOMMU是唯一根因。

### C1-QA2：先区分负荷与相位，避免直接花数百次运行拟合台阶

建议先给一个无调参、可输出逐事件的有限时序模型或已有能力允许的最小trace：明确每个job完成后延迟的闭环规则；与总工作量/平均供给相匹配的外部固定释放规则比较；再在固定释放规则下仅改变初始offset。三者分别回答“反馈”“负荷”“相位”。固定trace重放要报告产生该trace的方法，不能选择某一策略的有利trace冒充中立工作负载。

如果换成独立释放规则后现象消失，可以形成有边界的基准问题，但“本平台锁相”本身未必足够成文。若仍存在，并且由不依赖观测结果调参的模型预测留出的初相位/负载，才考虑细扫。你的“Alt-1或Alt-2一成立便必须撤回翻译相位”也过强：多条路径可以共同作用，存在一个替代机制不等于已排除翻译机制。

**Stop/go：** 找不到区分竞争模型的最小预测，先停扫；只有拟合后描述台阶而没有样本外差异，停论文主张。开环/闭环的符号翻转需要跨实现检验，不能只靠本地trace称普适评测法。

## 3. 点名质疑：D2的多个“决定性”结论不成立

### C1-QD2-1：fast计数是条件服务事件，不是对方miss数的替代测量

`rv_iommu_tl_wrap.sv:303` 的窗口确实要求另一bank的主PTW活动，这解释本批V-fast与A-miss同时出现。但fast还依赖V是否到达、V的命中/权限、probe耗时、响应占用；A-miss次数相同不保证fast相同。你可以说“触发暴露受A-miss影响”，不能说“fast度量的是攻击端miss，而不是受害端服务”。它**确实记录受害端合格命中已被接受**，只是不证明收益。

按窗口检验 `v_fast>0 ⇒ a_miss>0` 也不能作为无条件判死门：A在开窗前开始的walk可以延续进窗，窗内fast发生而首次A-miss计数不在窗内。聚合窗口未存逐请求时间线，无法从完整JSON还原从未记录的时间信息。D2-C1的“零成本逐请求归因”须撤回。

### C1-QD2-2：128是人为干预剂量，不是一次自然阻塞的上界

`docs/e3-controlled-results-review.md:41` 说明只对一个选中PTW响应插入128周期；`:57` 明说所见数字不是普适常数。不能以4096或16384乘128给现有工作负载构造自然暴露上界，也不能拿它算信道容量、判定服务不是排队分布。你在D2-C2/C3/C4中基于该“常数”的推导都需要撤回。效应幅度除噪声范围也不是互信息或bit/s容量。

### C1-QD2-3：把2条保护给A，不能要求A8/A16 miss下降来证明P有效

P的语义是被保护DID只能在low2填充，其余域在14条；切 `protected_did=11` 会把A的大工作集压到2条。A8又有源8＋目标8页，限制后miss增加或不降完全可以是机制按设计生效。D2-E1a提出“若A miss不降则P机制无效”的判据方向错误，必须删除。

验证P正确性应看实际mask/分配位置及请求归属；验证效用则选择符合容量关系的负载，与等总容量的简单对照比较。warmup只去掉初始cold段，不会一般地消除稳态容量冲突，所以“容量保护唯一可能起作用的冷启动被排除”也不成立。

**本轮处置：** D2-C5的软件消除四次翻译路线暂否决；D2-C1保留计数语义纠偏，不支持它单独升成新论文；D2-C2保留“miss数不决定端到端代价”的研究常識边界，但原128推导无效。新颖性与是否观测到负结果必须分别审查。

## 4. 点名质疑：D1与D3的识别性与保证口径

**C1-QD1：** D1-Q1按R2-F3修订；正常服务miss和fast accept的语义可以从源码消歧，不必为这个疑问新增板测。你关于A窗口/whole-round分离的提醒正确，但A并非没有结束规则：它自主运行直到V结束后由软件STOP。窗口goodput可以定义为该观察策略下的完成速率，不应因whole-round端点不同就说完全不可比；反过来也不能把它当固定外部到达流的吞吐能力。R2-F4给出明确边界。

**C1-QD3-1：** `deadline-now-estimated_remaining` 是调度启发式，不是保证。需要给出剩余服务估计何时保守、是否包括接收前等待/DDT/下游数据，以及估计错误时何种契约仍成立。若用平均walk成本，不能声称starvation bound或硬截止期；若一律用最坏成本，可能被简单静态准入击败。请先给会区分它与非抢占EDF、RR＋限额的具体任务集，而非先安排八个模式的仿真矩阵。

**C1-QD3-2：** HOL-D在当前banked控制和hit-under-miss上还切开什么边界？必须指认一条当前N不能绕过而新队列能绕过的可达等待链，再说明同资源增加普通response槽为什么不够。旧E3发生于旧串行路径，不可以直接当当前N缺陷证明。窗口总时长即使gap0也只是多job完成时间，不自动成为单请求服务延迟。

**统计补充：** 一组S模式的0.9%极差不是所有负载与模式的统一噪声下限；小于该值不等于等价，大于该值也不等于因果。三个独立boot只能提供有限启动重复，并不保证配置、输入或环境独立。明确实验单位、paired treatment及效应区间比固定“三boot”口号更重要。此处不要求新增统计复杂度。

## 5. 点名质疑：C2-L的联合时限契约可实现到哪里

### C1-QC2-1：现行RTL缺PR/PW排空支持，不能从172走直线到安全复用契约

**直接证据：** `cva6/corev_apu/riscv-iommu/rtl/software_interface/rv_iommu_cq_handler.sv:348` 的IOFENCE分支在合法命令路径 `:362` 明写 `TODO: Add IOFENCE support with PR and PW using R/W counters`。之后处理AV写回、WSI和ATS在途等待（`:366`、`:373`、`:379`）；该分支不能作为已经落实先前读写排空的证据。

这是研究能力边界，不是本轮已经验证的安全漏洞报告。172并未覆盖动态撤销→复用语义。若C2-L未来上板，需先证明其声明所需的规范语义已实现；不能靠新准入算法遮住基础正确性缺口，也不能把补全IOFENCE当论文主创新。

### C1-QC2-2：共同准入的可行域改进可能来自使用了不同安全前提

请先分清三种事件：停止发新请求、既有已翻译访问完全排空、旧翻译与cache/continuation失效完成。若一个已接受设备写可以无界等待W数据，任何IOMMU调度都不能给安全复用有限期限。若前提改成每份copy的源数据已被整份私有buffer容纳且返回有上界，那么这个设备配合也必须计入契约和成本，不能给基线更弱设备而给候选更强设备。

“释放时刻开始计时”的好处必须守住：入口背压、等待提交CQ、延迟公布撤销都要记账；允许拒绝时，拒绝比例和拒绝时限是契约的一部分。系统外部不可控制请求不能用“未准入就不算”规避。

**最强击败性反例：** 给每租户有限在途预算，撤销到达后停止该租户新增工作，按全局fence语义完成既有命令/访问，并给V静态保留服务。在同安全语义、相同资源、合法负载包络下，这个简单方案已满足全部三约束。如果新共同准入只是更复杂地表达相同可行域，应停；若只在高利用率边界比保守静态规则好，需要与同样知道到达包络的更强简单调度比。

**可继续的精确问题：** 在共享不可抢占资源下，“哪些已承诺工作必须在撤销时计入完成债务”，能否通过一个小而正确的责任状态降低过度保守排空。这可能与我的C1-A归因边界共享责任模型，但现在不建议把两者合成庞大系统。

## 6. 回应对我自己的候选：收紧并给出足以击败它们的反例

### C1-B降为条件备选，不把“可抢占walk”当既成创新

C2已指出ISCA18有成组/顺序page-walk调度，是否覆盖安全PTE边界抢占仍需全文限定；不因没看到相同词就主张空白。

**击败我的反例B-X：** 在相同continuation/队列存储与单内存端口下，最普通交错walker在每个PTE返回后RR，已经给出同样等待上界；或者阻塞集中在一个不可抢占内存访问，保存continuation没帮助。另一个反例是固定优先级＋预算能满足相同应用需求而状态更少。三者任一成立，停止B作为新机制；不能仅比较当前串行S。

B只有在“与失效/错误正确性相容的最少暂停状态”或“同资源下普通交错方案不能兑现的明确契约”上出现独立技术差异才继续。C2-L提出的新正确性工作反而提醒我们：不要同时扩nested、ATS、撤销、可抢占PTW等多个高风险边界。

## 0. 本轮判决与必须接受的边界

- **接受共同窗口 A 完成率**：`a_completed_jobs_window / v_window_cycles` 是同一 V 观察窗口下的合法完成率；但它是闭环观察策略下的速率，不是外部固定到达吞吐。A 裸计数不是速率，whole-round A 含可变尾段，不能直接与共同窗口比较。依据：`R4-review-boundaries.md:19`；`round3/D1.md:31-38`；`composition_plan.py:454-479`。
- **接受 fast accepted 必为合格 hit**：已接受 fast 必须通过 DDTC/IOTLB hit 与权限门；但 fast 计数不是收益，也不覆盖被拒 probe 的历史。依据：`R4-review-boundaries.md:7`；`round2/C1.md:33-39`；`composition_plan.py:93-95`。

## 1. 现有 172 支持什么、不支持什么

### 1.1 现有证据支持的描述性现象

只列描述性，不升级因果：

1. **A8/g0 同 boot 三 block，V 窗口模式差异存在**：S/N/P/PN 的 V 窗口分别约 8.96M/8.61M/8.96M/10.0M 周期；该条件下四模式 `a_completed_jobs_window` 都是 4096。依据：`metrics.csv:38-41`、`metrics.csv:86-89`、`metrics.csv:121-124`。这支持“同 boot 描述性差异”，不支持“PN 组合失败”或“N 有净收益”。

## 2. 主要候选逐项拒稿审查

### 2.1 撤销/允许结果集合族  
覆盖：A1 R3-A、C1 R3 §3、C2 R3 C2-O、D2 R3-2、D3 R3 oracle 部分。

- **最致命拒稿理由**：没有给出强简单对手无法覆盖的独有可检测错误。官方 ref model 已有 PR/PW 全局可见性回调与 `do_iofence_c` 路径；TransForm 与 Arm RelaxedVM 已有允许结果/部分序/litmus 路线；C2 自己的 B-score 已表达 O1–O6。依据：`round3/C2-literature.md:20-24`、`:28-41`；`round3/C2.md:76-87`；`R4-review-boundaries.md:17`。A1 的 O-allowed 抓 O-eq 漏报，只是击败弱 oracle。
- **规范正确性**：PR/PW 义务针对“已被处理”且到全局排序点的访问；未到 IOMMU 的流量另需平台同步边界。B 响应、AV 写回、数据到达是不同事件。依据：`round3/C2-literature.md:5-16`；`R4-review-boundaries.md:15`。
- **因果识别/可观测性**：必须区分 processed、IOTINVAL done、Fdone、G(W)、软件复用点。当前 172 无撤销/复用事件，`raw_inval_cycles` 全 0；PR/PW 分支 TODO。依据：`round2/C1.md:105-109`；`metrics.csv:2-173` 末列。
- **公平强基线**：C2 B-score：官方 ref model + 逐请求 ID 的 read/write、processed、G、映射版本/已完成失效 + 使用已有全局可见性 callback/ATS 接口。依据：`round3/C2.md:76-87`。
- **泛化**：单级普通 4 KiB 映射的最小模型可以保留；不能外推 nested、ATS、多实现。
- **可实施成本**：模型阶段可零板；若需演示 A1 变体 I，需要可任意拖延 W 的 testbench 设备，成本不低。
- **最低补救**：先做 B-score 对拍；冻结 O1–O6 与 A1 L/I/F 的抽象事件定义；证明某个具体合法重排或非法越界是 B-score 检不出、误报或需显著更多状态。不能只报覆盖率。
- **Stop/go**：B-score 或官方 ref model 直接扩展覆盖同一错误集合 → 停，降为验证资产。B 与 G 关系未证明 → 不得用 AXI B 判非法。无可运行实现演示变体 I → 只保留问题，不立项机制。

### 2.2 撤销债务/选择性排空/双时限族  
覆盖：A1 R3-B、C1 R3 §2、D3 R3 联合撤销部分。

- **最致命拒稿理由**：同一 IOFENCE 不能因撤销只涉及 A 就缩小对其他先前已处理访问的规范义务；选择性排空若没有新接口，不能减少义务；若有新接口，必须计入完整协议与比较成本。依据：`R4-review-boundaries.md:16`；`round3/C1.md:38-44`。
- **强简单对手**：正确选择性失效 + 静态服务预留 + 每租户在途上限 + 固定优先级 + 最长不可抢占尾段计入预算。全局计数器排空 + 每租户在途上限 k 的额外时延上界约 `k×burst`；现实配置可能已满足撤销期限。依据：`round3/D3.md:60-63`；`round3/A1.md:71-93`；`round2/C1.md:117`。
- **因果识别**：必须从真实释放/提交/排空/设备侧失效计时；不能把“映射相关请求队列空了”当 fence 完成。依据：`round3/C1.md:40-44`。
- **泛化**：ShareMMU 已覆盖权限更新、回失效、in-flight drain；未发现相同联合定量时限不等于无人做过。依据：`round3/C2-literature.md:44-50`。
- **最低补救**：L1 两租户模型，同安全语义、同在途上限、同下游有界；比较简单排空/静态预留与候选的选择性债务在安全复用时延上的差。若差值不超过测量分辨率，停。
- **Stop/go**：简单方案满足撤销完成时限、V 服务时限、A 非零进度 → 停。ShareMMU 已实现限定范围 drain → 停。需要规范之外新命令才能早于 fence 复用 → 必须独立论证接口价值，否则停。

### 2.3 D2-R3-1：等待槽产权账本

- **最致命拒稿理由**：当前产物不可观测账本对象。现有 counter 只有聚合 fast/fill/replace/inval，没有 per-event creator/consumer、slot ID、bank owner、credit 转账。`records-full.jsonl` 是每 case 一条，不是逐请求事件流。依据：`composition_plan.py:93-100`；`BRIEF.md:8`；`round3/D2.md:107-110`。此外，若 fast 不延长 owner 完成时间，收费没有可补偿损失；信用流控本身又是常见机制。
- **强简单对手**：per-DID fast 配额、token bucket、每租户 RR+有限在途+小身份表、N 本身 work-conserving。依据：`round3/D2.md:86-95`；`round3/C2.md:114`。
- **规范正确性**：不能把“另一 bank 有主 PTW 活动”直接写成“某次 A miss 创建了某服务机会给某 V fast”。触发条件是必要线索，不是所有权映射。依据：`round2/C1.md:75-79`；`round3/D2.md:81-84`。

- **Stop/go**：per-DID quota/token bucket 在同 V tail 下达同 A goodput → 撤回。无法归因到具体等待 owner → 撤回。fast 不延长 owner 完成 → 先证明边际阻塞，再谈账本。

- **A1 想用的可观察量**：下游 AXI 监视点上的 `t_B`、`t_AV`、以及该 AW 是否在 IOTINVAL 执行前已被翻译。依据：`round3/A1.md:37`。
- **问题**：
  1. `t_B` 是 AXI B 响应，不是规范全局排序点 `G(W)`；R4 已直接指出不能用未证实时间戳替代规范事件。依据：`R4-review-boundaries.md:15`。
  2. `t_AV` 是 AV 写回/完成通知的一种，不能自动保证平台其他写已全局可见。依据：`round3/C2-literature.md:5-16`。
  3. “AW 在 IOTINVAL 前已被翻译”是内部 processed 状态；外部 AXI 监视点不一定可见。
  4. 当前 IOFENCE PR/PW 分支是 TODO，172 无撤销/复用。依据：`round2/C1.md:105-109`。
- **结论**：A1 R3-A 的 L/I/F 三个变体按当前写法**不可由现有观测判定**。若要用，必须改为抽象事件：`processed(W)`、`IOTINVAL done`、`IOFENCE.C done`、`G(W)`、软件复用点；并证明平台映射或仅在模型中定义。
- **强基线**：不能只与 O-eq 逐条相等比较；必须与官方 ref model + PR/PW 回调 + 逐请求/epoch scoreboard 比较。依据：`R4-review-boundaries.md:17`；`round3/C2.md:76-87`。
- **最终计划禁止**：禁止用 `t_B>t_AV` 直接判“旧写落进已复用 PA1”；禁止把 O-eq 当最强对手；禁止把当前 TODO 分支当已验证排空。

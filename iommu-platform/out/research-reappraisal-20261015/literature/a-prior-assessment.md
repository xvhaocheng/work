# 候选A前作覆盖与发展判断

2026-10-15，Codex直接原文核读。独占范围为Bermuda、MASK、DWS、Orchestrated四篇；根汇总的另外三篇不在本席审读范围。本文件不恢复暂停goal、不实施RTL、不运行旧/新实验。

**结论：保留并发展A的分析方法版本。** 这四篇已经覆盖共享IOMMU干扰、翻译与data联合调度、PTW软分区/非抢占借用的局部界、调度与分区及sharing的组合，也已经指出局部命中率改善可能没有整体执行时间收益。因此，A的贡献必须落实为：在MC不可修改、AXI首次VALID不可撤回、有限buffer的控制权限下，能证明哪种重排合法，明确共同已承诺工作和可改变的新工作，并对未用于构造的案例预测完整任务结果及最小部署位置。不能以“优先翻译”“联合考虑内存”“局部不等于整体”或一张事后依赖图作为该版主要新意。[逐篇证据卡](a-cards.md)／[结构化卡及哈希](a-cards.json)

这里“本批未见整套”仅表示已核论文的覆盖范围；即使根汇总七篇都未见，也**不等于已证明整套新颖**。max-plus/DAG最长路、非抢占残余阻塞、carry-in及有限队列组合分析本身都是需要尊重的已有方法。A应证明新增的问题组织、合法性判别和部署决策给出原方法缺少的有用结论，不能借换术语排除它们。

## 2. A最强合理版本的接口

根当前提出的是“控制权约束的反事实事件图”，不是新的优先级名字。建议把交付合同固定如下，先做可核的分析结果，再决定是否需要新硬件。

1. **任务与完成定义。** 明确谁搬什么数据、哪些结果被谁消费、两边有限任务何时完整完成。图中至少区分首次offer、accept、返回buffer占有/释放、消费者能取得/完成数据的事件。必须包含read、write、先决依赖与有限容量，不能把translation返回当任务完成。
2. **控制点和信息。** 每个候选控制位置标注它何时能看见哪种需求，何时首次对该owner输出VALID，以及之后不能更改什么。first-offer发生在accept之前时，held VALID即使尚未握手也必须作为不可撤回承诺，不能通过后续门控消掉。
3. **合法反事实。** 先证明替换顺序在原协议、所有权和资源约束下可执行；保留相同干预前缀及全部已承诺义务。不能一边保留原队列形成的好处，一边把造成等待的旧请求删掉。
4. **具名服务假设。** 说明服务由什么资源提供、上界或观测值来自哪里、共享竞争和顺序改变会不会改变它。条件FIFO、固定服务时长或固定PTW latency只能产生该模型内的条件结论，不能标成MIG真实周期。
5. **任务级预测。** 在合法图上做max-plus/路径计算，输出某控制点能够改变、无法改变或目前因原始条件未知而不能裁定的任务结果；同时报告牺牲的普通流和观测/控制费用。不是只重画现有PN结果。
6. **最小部署。** 如果已有选择器加固定DS-first/F4、普通门控或有界非抢占优先级就能获得同样结果，记录为该策略的普通实现。若新意在有用信息更早出现/接口部署位置，则单列这个接口为何必要、净能力和全部费用，再与付费后普通等价策略分开比较。

这份接口是建议的接受合同，不表示合法独立载荷、正MIG债务、有用完整任务损失或新接口净值已经成立。当前状态中缺失的事实仍是未知。

## 3. 方法内容与普通数学的分界

可以用事件图编码依赖、资源串行边与有限buffer令牌边，以max-plus递推得到条件完成时间。这是计算手段，单独不支撑novelty。更可能有意义的新增来自以下三件事共同成立：

- **合法性产生可检查的判别。** 同一局部优先级在某控制点仍可改变新增承诺，在另一个控制点因first-offer已发生而无效；方法能从实际接口和合法前缀判出差别，而非预先手工把答案标进去。
- **共同债务保留产生可检查的预测。** 先前已经承诺的请求/返回/消费义务都保留；新增承诺造成的差异被单独计算。两条路径共同包含的债务不能因为名字叫“翻译优先”而被扣掉，且旧债务的状态/身份及其对cache/DRAM的影响也不能只用一个计数草率替代。
- **完整任务目标改变部署决定。** 方法能提前预测局部翻译加速被buffer/写完成/consumer延迟抵消，或者指出只需现有某个位置即可净受益。与具名基线相比，预测应有可检验的精度、适用范围和成本收益，而非只更完整地讲故事。

如果替换顺序会改变DRAM row状态、cache命中、背压或请求到达次序，不能冻结旧运行里的服务时长当作干预后的真实时长。应重建这些资源边/状态，或者给出保守服务区间，并标明模型无法覆盖的条件。若形成等待环，还需先判断可行性/死锁；不能默认所有有限buffer事件图天然是DAG。

## 4. 哪些证据会接受A，哪些会拒绝这一版

|关口|有意义的接受证据|拒绝或重设计的具体原因|
|---|---|---|
|实际问题|一个具名有限工作流，在普通完整成本对照下存在可避免的完整任务损失；保留输入、合法前缀、硬件完成证据|只有可疑局部wait、busy盲窗或正债务一条记录，没有有用任务后果；只意味着证据未闭合，不能否定思想族|
|权限正确|源代码/协议证明信息早于本owner first-offer，独立备选头真实可选，所有spill/CDC/held工作与返回容量已计入|把accept前任意时刻都当可撤回；删除共同旧债务；把DS聚合流一律当PTE；这会使该反事实不合法|
|方法新增|至少给出可由接口证据机械核对的控制位置判别，以及未用于构造案例的任务级预测|只对已知PN轨迹手工加图/标签；只复述MASK联合调度、DWS残余walk、Orchestrated局部≠整体|
|模型有效|服务假设具名、可校验；跨模型/实物边界明确；预测区间、误差或排序能被新案例推翻|把FIFO假设当MIG真实服务，或者重排后仍不加说明地复用旧服务时间|
|部署最小|比较已有fixed DS-first/F4、普通门控/公平控制；同任务、相同在途/返回/观测预算，计频率/面积/延迟与普通流牺牲|人为删掉基线已有可用buffer/提前准备/合法字段回收；用付费接口上的普通等价直接否定接口，或凭接口缺项直接主张新颖|
|边界清楚|同一方法同时预测正例、邻近无收益例、信息太晚例、共同债务主导例，并知道何时必须输出未知|只挑translation敏感case；无符号化限制，输出任何负载下全局保证|

此表只判断A这版贡献合同。若普通程序在同一付费接口上复现策略，最先应停止相应策略增量主张；如果方法仍能提前判合法性/选择部署并有必要证据，不能据此关闭整个分析/接口架构方向。

## 5. 能形成决定信息的一小组新案例

本席不启动这些案例；它们供根形成后继验证合同。输入先由实际可达性和服务假设确定，不能为正例虚构MC状态。

- **早信息、可选择、存在可避免新义务。** 保护触发早于first-offer；两路合法头同时可选；方法预测改变次序后完整任务净收益，且普通流完成及新增控制费用均纳入。
- **同样工作、信息晚一拍。** 唯一变化是信息出现在first-offer之后、accept之前；方法应判现有held工作必须保留，收益限缩或消失。用于检验是否把VALID误当无承诺。
- **共同旧债务主导。** 两边开局都要完成相同已经承诺工作；只改变更后的新增义务。方法不能把共同前缀的全部等待算成可省。
- **局部快、任务不快。** 翻译更早，但返回buffer/consumer/写完成使完整任务不变或变差；这是Orchestrated已有认识的更具体可预测化，须事先给出结果，不能事后解释。
- **服务条件未知。** 观测不足以确定MC服务序列/上界；方法应输出未知或条件区间，不能把未测债务记零。

接受A的关键不是案例数量，而是至少有一组真正未用于构造规则、能区分竞争解释的案例。若这些案例只证明普通max-plus图可计算，需继续收窄为方法部署边界，不能夸成调度发明。

## 6. 尚需最少补的最近前作

在根汇总七篇后，优先补**一个有界的理论/分析缺口**：实时系统中非抢占资源的carry-in阻塞与组合响应时间，以及有限队列/握手协议的AXI或互连时序分析。目的不是再堆翻译论文，而是查清“共同旧义务+有限buffer+控制点选择→完整完成”的方法主张有多少已是标准构造。

建议按以下顺序查，取得原文后再决定是否扩大，不在本卡把未读材料当已核前作：

1. max-plus/timed-event-graph与确定性网络演算的现有定理：确认A使用的数学、有限buffer建模、服务曲线与预测保证哪些是普通工具。
2. 最接近的AXI interconnect/SoC可组合最坏时延分析：重点查持有的未accept VALID、队列不可抢占承诺、backpressure和responsebuffer是否已有同样控制位置判别。
3. 若前两类已经给出完整方法，再针对“观测何时足以改变可控事件”的实际接口/信息边界检索。只要A仍产生此前方法不直接给出的部署结论，就按证据发展；若核心问题、关键方法和主要产出高度重合且剩余只是换成IOMMU，停止这版novelty主张。

本席没有深入阅读上述理论/协议分析原文，因此不写“没有人做过”。既有的七篇翻译/IOMMU论文不足以替代这项最近前作检查。

## 7. 可核查的条件novelty论证

MASK已在可修改GPU memory hierarchy的前提下联合管理TLB、PTE/data cache和DRAM三队列（PDF7–8 §§5.2–5.4，M03–M04）；DWS已通过walker软分区与非抢占steal限制跨租户交错，给出局部至多一个外租户walk的性质（PDF5／印刷630 §V，D03）；Orchestrated已经组合TB调度、分区、sharing，并给出命中率改善未改善完整执行时间的实例（PDF4–5 §§IV–V，O05–O07）。对于MC不可修改、AXI首次offer不可撤回且返回/消费buffer有限的共享IOMMU部署，A拟增加一套控制权约束的反事实分析：先由接口和合法前缀判定哪些新增义务还能改变，保留共同已承诺义务，再在具名服务假设下预测完整任务并选择最小部署。若它能对未用案例给出可核的可改/不可改/未知判别，且相对具名普通基线带来新的必要部署判断或真实任务净价值，这可构成有意义的方法推进；当前四篇只支持该差异未在本批被覆盖，实际任务证据、预测有效性、接口费用和理论/AXI最近前作仍待接受。Bermuda的实测干扰为问题可能性提供背景（PDF6–9 §IV，B06–B09），不能代替这些验收。

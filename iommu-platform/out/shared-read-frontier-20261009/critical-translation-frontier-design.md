# C1：共享源读与独立权限／故障进度的边界

日期：2026-10-09。作者：Codex C1，独立架构分析。这里只提出设计并核关键源码；没有写测试、运行仿真、综合、上板或修改生产代码。

## 结论与选择

**当前能成立的具体问题，是一个成员的目标 WRITE 没有成功，阻止另一个成员已经合法的源 READ 开始。解决这个问题不需要新的广播算法。** 按成员独立准入、为失败 WRITE 保留本地错误排空路径，就能修正目前的全成功屏障。

我保留一个更窄的正向候选：**目标已经确定失败、软件选择终止该作业之后，允许 DMA 和共享读控制器一起退休尚未对外发出的读写尾部，而不逐拍制造内部错误响应。** 它需要新的取消确认接口，不能靠 `useful` 位或现有 `ABORT` 直接实现。它的潜在独有收益是减少内部响应、信用退休和故障完成时间；不能把“无需补读 DDR”作为独有收益，因为普通错误响应适配器也可以做到。

优先级：先把“独立成员准入＋准确故障归属”作为正确且完整的普通对照规格；成对退休只保留为有条件的小型接口研究。**不建议把当前共享长读或故障后的免补读直接立为论文新算法。** 根协调者报告 §51 中普通 quantum=256 已与长读模式的四对 CSV 完全相同；这是根执行的结果，我没有重新运行或独立验收这些 CSV。

以下“源码事实”“可达推演”“设计建议”分别标注。可达推演不是已经执行的事件日志；新接口的能力也不是当前平台已有能力。

## 1. 已有接口确实在哪里缺了一步

这里不重新讨论根和义务审核席已经处理的 quantum、先 VALID 后暂停及恢复条件。任何候选都必须保留它们得到的既有总线义务。

## 2. 最小实际平台边界：一个目标拒写就足够

**可达推演 W0；没有执行。** 保持当前原型的两个 2 KiB、页对齐、普通内存作业，不需要多页、动态失效、设备内存或特殊 AXI 属性。源内容不可变。

1. V/A 的源 READ 分别经过自己的 DID/PID 权限检查，均成功，并得到相同物理源范围。V 的目标 WRITE 成功。
2. A 的目标页存在，但不允许 WRITE；其 WRITE 翻译返回失败。源 READ 权限仍合法。
3. 两个原始源 AR 已被共享读控制器接收；A 的失败目标可能已经进入 TC 的本地错误路径，等待对应 W 数据排空。
4. 在当前共享读控制器中，`cache_valid[A][WRITE]` 不成立，131–133 行的条件保持为假。没有源 READ 故障，110 行的检查也不会把这个情况变成正常错误完成。未触发人为 detach 时，V 的共享源读不能开始。

这是合法 DMA 描述符及页表权限组合；被违反的是原型额外的“所有 recipe 成功”假设。**不声称当前错误关闭的 DMA 能正确处理其结局，也不声称已经观察到了运行超时。** 代码已经足够证明启动门槛的问题，不需要先制造一个性能数字。

普通对照可以解决：先让 V 读；A 若仍要按原 AXI 协议完成，则其已授权的源数据可送到对应的本地失败 WRITE 消费路径，最终返回该 WRITE 的错误。若 A 尚无可消费位置，就让它暂时脱离公共返回路径，使用有限缓存或随后补齐。源权限失败的成员则不能接收真实源数据。独立的目标错误不应被广播为 V 的错误。

**精确修正规则 M1（普通对照，不报创新）：** 每个成员的目标进度至少区分“未知”“可正常写”“已分配错误消费路径”。第三种状态不是 `cache_failed` 的别名：必须确认错误响应属于这个原始父事务，而且本地路径已取得实际 W 消费／顺序位置。选择可进展成员时，还要保留已对外 VALID 的 AW/W、共享 W owner 队列和已承诺的 R。单独改第 133 行仍不够。

M1 需要补全父事务的故障归属与一次完成规则。失败预取翻译是否已写 fault queue、后续原事务是否又报一次，必须明确；不能把负缓存或重复 fault 当免费功能。这个控制是预翻译、广播和错误 sink 的合理组合，不因出现在 IOMMU 前就成为独立算法。

## 3. 真正的代价边界：不要把“丢数据”说成“取消义务”

假设 A 的原始逻辑 AR 已被接收。V 已促使公共物理读前进到 `h`，A 只收到 `c` 字节，系统还完整保留了 A 未收到范围中的 `K` 字节。那些已经读过、A 尚未收到且没有保留的字节，若仍要求向 A 返回正常准确数据，就只能补读，或事先多存／限制 V 前进。这里的 `K` 必须包含所有真实保存的有效副本，而非只数共享 skid。

这只是数据保存与已接收响应义务的约束，**不是新的 quantum 定理，也不是 multicast 的新发现**。目标后来失败，不会自动撤销之前接受的 AR。

更关键的是存在一个容易漏掉的便宜对照：

**B-error：目标故障已经确定，作业被明确终止后，保存原始 WRITE 故障；对放弃的内部 READ 尾部返回完整数量的错误响应，在内部消费未发出的 WRITE 尾部。** 所有 RID、拍数、RLAST、已保持 VALID 和原始作业故障归属仍要正确。已经发出的物理 AR 继续排空，已经承诺的物理 WRITE 仍正常结清。它不需要为纯粹被放弃的数据去 DDR 补读。

这不是现有 RTL 的功能：当前库的 READ 错误优先级会覆盖 WRITE 错误，故 B-error 也需要明确的原始故障票据和终止策略。公平比较时，候选与 B-error 得到同一份票据、同一个终止决定，二者都启用正确的作业错误处理。**不能限制 B-error 只能返回源数据，却允许候选放弃读义务，再把免补读算作独有收益。** 如果坚持未改 AXI 接口且不允许错误代替正常完成，才存在前述补读／缓存／等待三选一；应明写这个较强合同。

当前没有找到或证明“B-error 的这个完整组合已经是某篇论文的实现”。它是这里给出的可构造对照，不是用假想前作否决创新；是否已经有相同 DMA 取消接口，还需定向原始文献调查。

## 4. 正向候选 M2：终止作业的读写尾部成对退休

**设计建议，未实现。** M2 的新操作不是“该成员不再有用”，而是 DMA backend 与共享控制器共同确认：这段逻辑 READ 不再需要产生逐拍响应，且与之配对的 WRITE 尾部也不再等待这些字节。只取消内部、尚未产生对外不可撤销义务的部分。

可用的最小接口如下；字段宽度以实际父事务容量确定，不预设免费的全局表。

```text
fault_ticket_valid/ready
  {flow, job_generation, write_parent, failing_range,
   original_cause, original_fault_address, terminal_abort}

retire_prepare_valid/ready
  {flow, job_generation, read_parent, write_parent,
   first_byte_to_abandon, end_byte, fault_ticket_id}

retire_ack_valid/ready
  {same_tags, final_cut, read_credit_retired,
   write_credit_retired, original_fault_preserved}

physical_debt[flow/job]       // 与 logical_job_retired 分开
```

`fault_ticket` 必须来自已经确定属于原作业的权限失败／终止决定，不能用预测失败。`prepare/ack` 不是在 AXI AR/AW 上增加一个可以随时撤回的暗号，而是 DMA 和局部控制器新增的内部协议。

安全步骤：

1. 终止决定冻结该作业新的外部提交。所有已经对外保持 VALID 的 AW/W、已接收 AW 所需的 W、对应 B，以及已保持 VALID 的逻辑 R，先按其原合同结清。不得撤掉 VALID；不得因另一页失败而回滚已经成功写入的前缀。
2. 选择精确的未外发尾部边界。若 A 的 AW 已经进入共享 mux 并占有 W owner，不能只清 backend 的计数器；必须先正常排空它，或者给所有相关队列增加经过验证的取消接口。**首版建议前者**，把取消边界限制在局部未外发尾部。
3. backend 确认不再等待该 READ 尾部，同时退休对应 WRITE、buffer、legalizer 和父事务信用。只退休 READ 会留下 WRITE 等数据；只退休 WRITE 会留下 AR 等响应。job generation 防止旧确认误杀下一项作业。
4. 共享读端在确认后去掉 A 的后续交付义务；服务 V 的公共物理 R 继续，不能伪造物理 RLAST 或把未完成物理请求清零。
5. 对外报告原始 WRITE 错误和明确的“终止后保留已完成前缀”语义。纯暂停、权限尚未查回、稍后打算恢复的作业都不能使用 M2。

**最小差异轨迹 W1：** 从 W0 的普通修复版本出发，先启动 V；A 的源 AR 和原始 WRITE 父事务已被局部模块接收。A 的一个目标 WRITE 子事务拒绝并在本地结清后，A 进入终止状态，仍有一个大于零的局部读写尾部没有对外承诺。若余量为 `n` 个逻辑 R 拍，B-error 必须在原 AXI 返回接口完成这 `n` 拍，M2 则可按父事务／区间退休，不必制造这 `n` 个正常接口握手。

这组描述符、翻译失败、原始长 AR、拆分 WRITE 和局部尾部都来自实际平台接口；**“独立开始、故障票据、终止和成对退休”是建议新增的控制，不能冒充当前原型已经可执行 W1。** 当前 `NO_ERROR_HANDLING` 配置也必须对两个比较者共同更改。

`n` 个握手减少，并不直接等于 V 提速 `n` 周期。只有这些握手占用 V 所需的共享返回服务、占据有用队列，或延长可观察故障完成，才有性能价值。若 backend 能在独立本地路径廉价吞掉错误尾部，M2 的正常作业性能收益可能为零。其差异是内部响应工作量，而非物理 DDR 字节，也不是只靠一位 drop 标记取得的收益。

## 5. 同信息、同资源比较与必须记的新增成本

| 比较项 | 普通对照和 M2 都必须拥有／允许 | M2 独有的新增项 |
|---|---|---|
| 权限与身份 | 两个上下文独立的 READ/WRITE 结果、成功 PA、属性；同一个真实故障票据和终止决定。 | 没有额外页表预言器。 |
| 物理调度 | 相同源 AR 长度选择、payload 容量、下游 READY/延迟、已承诺 W 的排空规则；包含根的 quantum=256 普通对照。 | 不以更短或更弱普通 burst 制造胜利。 |
| 失败语义 | 启用相同作业错误处理；保存相同主故障；允许普通本地错误响应、错误 W sink 和对已弃数据免补读。 | DMA 明确认可“不逐拍完成内部 AXI 尾部”的取消合同。 |
| 状态 | 已有父事务头、成功 recipe、序号和正常顺序状态，以及双方共同所需的 fault 记录。 | 每个同时取消项的父事务标签、区间两端、状态/确认、引用的故障票据；backend 与中间队列的取消或退休逻辑。 |
| 尚未完成的请求 | 仍然计算真实物理 AR/AW/W/B/R 义务。 | 逻辑作业终止与物理排空分开记账；不能把改名当已完成。 |

对最大 256 拍、单一连续尾部的受限版本，区间端点至少需要能表达 0…256 的范围；还要乘上实际并发父事务数，补充 generation/标签与状态位。故障地址、原始 cause 不能只以一个 failed bit 代替。可以复用现有 83 位 response 存储，但只有确认该存储不会仍被成功结果或另一父事务占用后才能扣除面积；接口、FIFO、组合确认路径和 backend 改动仍是新增成本。现有“56 B payload”不涵盖这些控制状态。

**反例／等价边界：** 如果普通广播获得相同的成对退休接口，它可以使用完全相同的去成员与取消动作；这排除了 M2 作为独有广播策略的说法。若普通 B-error 在不新增同等取消协议的情况下，已经在相同内部带宽与状态成本下取得相同故障完成／V 干扰，M2 在这个平台的性能立项就失败。不能在失败后改称“接口优雅”来保住原性能结论。

## 6. 权限失效与已发生写入：首版不能顺手扩大承诺

源 PA 相同只支持共享一次实际取数；每个接收者仍须有自己的源 READ 授权，每个目标仍有独立 WRITE 授权与顺序。只有源授权的成员才能得到真实数据。M2 也不能提供两个作业一起原子成功／一起回滚的语义。

RISC-V IOMMU 的 `IOFENCE.C` PR/PW 涉及先前已经被 IOMMU 处理的访问达到全局排序点；尚未处理的请求另需系统相应的排序办法。不能因 A 的逻辑作业退休，就声称仍服务 V 的公共物理读已经排空，或以一次 B 握手代替所有平台的全局可见性。参见 [RISC-V IOMMU v20260222：内存队列与 IOFENCE.C](https://docs.riscv.org/reference/iommu/v20260222/iommu_in_memory_queues.html)。

首版建议继续限制静态映射、普通不可变源、无 ATS、无设备副作用和无运行中失效。以后若加入失效，必须给权限结果／取消确认加适当 generation，并保留已经发生物理访问的排空责任。不能因为 cache recipe 被清除，就释放此前事务的物理债务。

## 7. 相关工作究竟覆盖什么

- [DMA-Latte](https://arxiv.org/html/2511.06605v3) 的 §IV-B 与 §VI-A 已描述相同源广播及由批次源信息识别共享机会。因此“一个源只读一次、给多个目标”不能在此作为独立贡献。这些已核段落不足以判断它是否已有本文 M2 的成对退休接口；没有搜到术语不等于不存在。
- [Multicast AXI XBAR](https://arxiv.org/html/2502.19215v1) 描述多目的 B 汇合、错误响应归并，以及 W 次序／有限缓存下的协调。因而错误归并和多目的顺序控制本身也不能报新。本文要求的是不同作业保持独立故障归属，并比较是否值得新增局部取消能力；不能用对方的合并 B 合同替代这个比较。
- [§49 跨领域边界复核](../innovation-rescue-20261009/codex-cross-field-boundary.md) 已把端点分发、有限缓存、成员退出、修复等作为需要面对的通用机制。本设计没有把“失败成员不再补发”单独升级为创新。

以上是覆盖范围核查，不是完整新颖性检索。**只有出现具体不同的接口能力、可观测代价和未被准确前作覆盖的实现，才可把 M2 的相应部分称为独立机制贡献；其是否足够成为论文主贡献，还取决于实际工作负载价值。**

## 8. 下一步只做哪个决定性产物

建议先交付一张可审核的接口事件表，固定 W0/W1，逐项列出：原始 AR/AW 接收、各成员 READ/WRITE 结果、故障的原事务归属、最后一个已承诺 W、最后一个必须正常返回的 R、普通错误尾部的拍数、成对退休确认，以及逻辑完成／物理完成两个时刻。对照必须包含 B-error，不能只比“故障后仍补读所有数据”的弱版本。

这是下一项规格交付，不是本次已经写好或运行的测试。先利用现有两 DMA 顶层与私有尾部边界；不需要扩成多页或完整动态撤权平台，也不需要先综合。

**Go 条件：** 能准确找到当前接口上必须逐拍排空的尾部；M2 在保留已发 W/R 和原始故障的同时，确实消除该内部工作；这项工作在目标场景中消耗共享资源或主导可观察完成时间；新增退休状态和 backend 改动有可接受成本。随后才值得做小范围实现与定向前作复核。

**Stop 条件：** 正确的 B-error 已同样消除主要干扰；取消需要清理跨越多个不可撤销队列的大量状态，成本超过收益；或用户关注的正常成功作业几乎不遇到这种终止场景。此时停止的是 M2 性能候选，不是否定整个多 DMA／翻译与数据流研究方向。当前共享长读与普通量子基线的等价结果，也不能被一个尚未实现的故障扩展抹掉。

本次最确定的正面产出是：明确找到了全成功门槛的失败边界，给出了可实现的普通修正，并把剩余创新问题压到了一个实际的新接口能力及其完整强对照上。没有将它宣称为已验证算法或已经成立的论文主线。

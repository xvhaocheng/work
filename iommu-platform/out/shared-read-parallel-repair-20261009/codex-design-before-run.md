# §68 Codex proposal: overlap old donor tail and authenticated repair prefix

## Concrete boundary
§67 sequential handover has one physical source transaction route and cannot start A repair before old V physical RLAST. Waiting J=E improves V progress but delays A; dropping old [J,E) speeds A but waits for true RLAST and duplicates V delivery. Ordinary B pipeline retains small minimal-J gain, so test a new capability: both old V tail and new A prefix may be physically in flight after data-debt closure J, without additional payload buffer.

## New rule and metadata
1. Keep original late-join full independent READ grants/equal immutable PA+normalattrs and separate full WRITE success. Select original minimalJ>=existing promisedV. No invalidation/fault/revocation/stall-authority claim.
2. Phase1 close actual V returned=rawW=J and promise<=J. Old firstVALID AW/W survives; pending B debt remains; no new A write lacking payload.
3. Transfer old physical V transaction to a single old_v_busy bit and existing old_end E. Old ID is stored original V parent ID, next physical index is returnedV because there is one shared response skid and no outstanding undelivered V physical beat when accepting a new beat. Existing main child metadata now captures A prefix [rA,E), not [rA,N). Old V physical tail still returns only V; prefix A returns only A. Both must already have READ/WRITE success.
4. During concurrent phase2, every NEW W child must be payload-resident at firstVALID and clipped to E. This prevents a filled private FIFO waiting behind an older W head whose missing payload requires the other held physical R. Existing missing V W debt was already closed at J. B completion must remain independent of future data.
5. A prefix physical RLAST at E cannot enter unready shared suffix and occupy common R channel while old V R still needs service. Wait until true old V RLAST, A prefix RLAST, both logical cursors E, and skid empty. Then issue A shared suffix [E,N), keeping original logical RLAST256. Phase3 uses existing peer actual-W admission and terminal parking; both own prefixes are already available, original native page B obligations persist.

## State, cost, critical tests
Added one functional old_v_busy bit; existing E and original parent IDs/cursors already stored. No payload added; actual one skid and private B3 FIFOs unchanged. AR count is one extra A prefix/suffix split compared to serial repair; total physical source R remains E+(N−FA), hereFA0. State estimate local declarations only until source reviewed; no synthesis/area or board claim. MaxB1/2 ordinarypipeline same forcontrols. ParallelPrefixRepair=0 must exactly regress §67; Parallel1 must produce actual A AR before oldV physicalRLAST, full two destinations bytes, correct actual R/E cardinality, held AR/R/AW/W stable, no fake logicalLAST. E256 has no shared suffix: the same two-route prefix path becomes ordinary concurrent independent reads, R512. It must be reported separately as a strong control and cannot support a shared-tail gain claim. No extra suffix AR is generated; both original logical RLAST256 retire normally.

## Novelty conditions
Concurrent catch-up/multicast/credits/resident AW are existing ideas. Potential contribution is the concrete one-bit two-route reconstruction + data-debt closure + split-E repair obligation that permits cross-domain independently authenticated late join with irreversible AXI W ordering and unchanged tiny payload capacity. If a primary prior implements this contract with equal information/payload/route metadata, it cannot be called independently new. If implemented benefit or a safety/cost boundary survives the concrete strongest ordinary sequential/independent/resident-concurrent baselines, and priors do not cover this combination's required rule, it can be developed as an independent mechanism; merely changing names or beating serial fixture is insufficient.

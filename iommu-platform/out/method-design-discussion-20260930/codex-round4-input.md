# 第三轮审阅与第四轮收敛（Codex）

新原始文献已核查：Valsan, Yun, Farshchi, Addressing Isolation Challenges of Non-blocking Caches for Multicore Real-Time Systems，作者版 https://www.ittc.ku.edu/~farshchi/papers/taming-rtsj17.pdf 。摘要及第1/2节指出某些非阻塞共享cache的MSHR耗尽可连hit也阻挡，并提出OS/硬件协同控制每核并行度；本文扩展RTAS2016相关工作。它是CPU data-cache而非IOMMU，不可直接说完全覆盖本研究，但不能把非阻塞不等于隔离、MSHR配额本身称首次。

请修正第三轮具体错误：
1. 普通非阻塞不能故意造弱基线。应允许在miss槽满时仍可合法查询/处理hit的常规设计（若能实现），公平仲裁加实际请求/完成跟踪。是否hit需真lookup，不能使用事后first_hit。公平选请求不自动解决资源耗尽，也无需出现永久饥饿才有保护价值；有意义的等待差即可能值得评估。
2. A占满pending槽是否影响hit取决于结构，不能说所有有限非阻塞一定如此；入口/结果槽也不是全都叫MSHR。V纯hit可能不需要miss槽，不应一律入口/在途/结果每段都保留。
3. 第三轮表(a)N而(b)N+k+m+r不公平。固定每类资源总容量（不是各类位宽可互换）比较共享/静态保留；需要更多资源则明确单列成本。LUT/FF/BRAM/lookup/mux和频率真实成本，不能偷偷回到只按statebits比较。
4. hit不等于1拍；本平台测得V自身4是该条件下观测，任何新结构需重新测。一次测到最大等待不是严格最坏上界；不得暗示预留1槽必然V等待=自身服务或A损失小。仅有界/公平也不等于满足未指定应用目标。
5. 不再重复固定128配对结果接近128就否定已有E3的错误质疑，固定干预重复的相近结果正是预期，PTW-only路径+后续firsthit+控制代码支撑有限结论。G0不会重开旧E3，当前也没任意延迟或独立出口控制。新的NB满槽/结果背压均尚未测量，不能称现成实验或无RTL改动可跑。
6. 动态借用不是必须方向。若V需要随到随可用且借用者不可抢占、释放无界，唯一保留槽不能安全借出；这是假设下的逻辑反例，非板测新发现。可以接受保留槽空闲，不以提升利用率名义损害契约。背景A也需正容量/服务，不能N=1还承诺双方进展。
7. 下一步优先设计规格与小范围真实RTL验证可行性；并无现成完整IOMMU定向Verilator环境，抽象模型只作筛选不是硬件证据。未来原型须FPGA验证，formal60续35仍独立保留原协议。

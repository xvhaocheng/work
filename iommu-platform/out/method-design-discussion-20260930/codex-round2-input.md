# Codex 第二轮意见与已核查先行工作（2026-09-30）

用户要决定最重要改善与创新方向，目前只讨论，不授权本轮实现/构建。

## 联网核查到的原始论文

1. Costa, Martins, Pinto, Beyond the Bermuda Triangle of Contention: IOMMU Interference in Mixed Criticality Systems (2025), https://arxiv.org/html/2508.19670v1 。摘要/第V-C节：已研究Arm SMMU DMA干扰，讨论按stream调节/优先级等缓解，但未完整实验评估这些缓解。不能以换成RISC-V、共跑变慢、普通限速为独立新颖性。其关于通用规范支持QoS的说法本轮未独立核对，不转述为规范事实。
2. Cong et al., Supporting Address Translation for Accelerator-Centric Architectures, HPCA2017, https://vast.cs.ucla.edu/sites/default/files/publications/hpca17.pdf 。第IV-A/IV-B，PDF第6页575行及第7页639行，明确既有私有和共享TLB设计提供non-blocking hit-under-miss。无需再猜这种思想是否新，已有直接先例。
3. MASK, ASPLOS2018, https://ghose.web.illinois.edu/papers/18asplos_mask.pdf ，第5.2节是TLB-fill tokens，不是完整DMA启动令牌；第5.4节翻译感知DRAM调度。不能混同它和我们的控制层级，但反馈/令牌/翻译调度宽泛宣称不足。
4. DWS, Improving GPU Multi-tenancy with Page Walk Stealing, HPCA2021, https://www.csa.iisc.ac.in/~arkapravab/papers/hpca21_DWS.pdf ，分配和借用共享walkers，含MASK+DWS对比，多walker GPU场景不同于本机，但共享翻译服务控制已有先例。
以上是定向核查而非全面新颖性检索，不声称没有其他类似设计。

## Codex 对第一轮的反对与判断

- 同意固定gap为基线，优先评估硬件解除在途miss造成的等待；反对把最小解耦/条件化/完整正确性本身当创新，都是必要但不充分条件。
- 把核心问题收窄为：在有限翻译资源下，能否用可量化的小成本，让已驻留的关键DMA请求避免另一DMA长查表的无谓等待，并保留背景DMA进度？E2与所有出口矩阵不应重新成为大而全前置任务。
- 候选边界：保持普通页表遍历器数量与IOTLB容量不变，尝试有限的pending请求上下文、可独立运行的hit处理路径与返回结果/顺序跟踪；针对实际阻塞持有的状态释放，而非仅改IDLE优先级。受保护流可配置，不硬编码DID10；保留A前向进展。仅初步架构候选，不断言小改动或已实现。
- 现已直接复核TL：IOTLB lookup绑定当前req_data、pscid/gscid和单PT/MSI状态；TL请求只有相应响应消费后释放；trans_ctl仅IDLE选择，COMPLETE等下游。这意味着trans_ctl+TL+返回顺序需端到端考虑。不能用已有first_hit事后标签给在线调度当oracle。
- 真正可能贡献：资源有限且正确性约束下，提出区别于合理通用非阻塞设计的具体资源管理/进度保护规则，在同硬件预算下改善V/A取舍；或者在同保护效果下实测明显更低硬件成本。尚未找到具体差别就不能承诺方法创新。
- 公平比较不必把所有基线都完整实现：候选为绕过则通用有限非阻塞设计是必需关键对照；候选为准入则充分调参固定gap与朴素优先/反馈是关键；按研究问题选必要基线，避免工作无限扩大。比原串行基线好不足以证明创新。
- formal60继续原冻结协议，不中途扩gap或重选样本。未来为新方法公平匹配A/V指标确需补控制强度，另开独立小基线试验；现3点不能证明全部限速策略都失败。用户无V目标/A最低速率，用取舍曲线，不编造阈值。
- 新方法机制验收：在正确性许可且V出口可接受条件下，延迟A的PTW后，V相应入口等待不再近乎同比增加；若阻塞仅从入口移到返回出口，任务总时间没改善，不算有效。单次64B因果诊断与自然延迟连续4KiB收益必须分开，不用人工128放大当论文性能收益。
- 连续测量的相位变化不能直接视为额外混淆消除不了：方法会改变到达序列，这是总效果的一部分，但要同发起规则与工作量并报告机制轨迹；不能每种方法筛选有利相位。
- 若通用非阻塞已达到同等成本效果，不发明名字宣称新颖，应承认是常规实现，寻找真实设计缺口或调整论文定位。固定gap满足实际应用不自动说明研究已成功；工程足够和方法创新是两回事。

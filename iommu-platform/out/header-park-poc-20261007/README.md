# 请求头暂存与直接通路：小型 RTL 判别结果

本轮把此前规格实现为测试专用 RTL。两槽暂存加直接通路解除既有停滞，但普通共享三槽队列也通过；正常 P/PN 没有新增收益。当前实现作为工程对照保留，独立机制创新没有成立。

## 场景与方法

两路真实 iDMA、真实 TC/TL、行为 DDR 与合成 CPU。每路同时至多一个活动 job，任务连续执行；每个普通对齐 4KiB job 有两个 2048B 源读 burst，原始读 ID 为 0/4。不是仅执行一次拷贝。未覆盖真实四 DMA、MIG、板端、权限错误或失效/取消。

同 bank 使用两 DMA 到一个 bank 的测试映射，A 每个 job 的首 AR 在首次 VALID 前有限延迟 64 cycles；S、warmup2、V64、A 连续运行。默认分 bank 的 P/PN 对照取消夹具，warmup256，窗口 V/A 各64。

- HeaderParkMode=1：共享可选择请求头，深度由 HeaderParkDepth 指定；HeaderDirectEnable 控制直接通路。
- HeaderParkMode=2：普通每源固定 FIFO 区域，每源深度2，共4个新增头槽/活动 bank，无直接通路。
- 默认 mode0 保留原代码路径；本轮没有另跑默认路径等价测试。

## 实际结果

| 同 bank S 配置 | 结果 | 窗口 cycles | 终止/停滞状态 |
|---|---|---:|---|
| 共享1槽＋直接通路 | 预期 watchdog | 未开始 | 停存1头，派发0，V1挡住A0 |
| 共享2槽、无直接通路（Mode1） | 预期 watchdog | 未开始 | 停存2头，派发0，A0可见但无空槽 |
| 共享2槽＋直接通路 | PASS | 127092 | 262暂存＋2直通＝264派发；满槽直通2次；排空 |
| 普通每DMA2槽，共4槽 | PASS | 127147 | 264暂存/派发，峰值3，排空 |
| 普通共享3槽、无直接通路 | PASS | 127147 | 264暂存/派发，峰值3，排空 |

三个通过例的窗口 V64/A63；终止累计包括预热及窗口外排空。55 cycles 不作为性能收益结论。

| 分 bank 正常工作流 | P cycles | PN cycles | PN 快速翻译/快速数据读 |
|---|---:|---:|---:|
| 共享2槽＋直接通路 | 92109 | 92374 | 62/62 |
| 普通每DMA2槽 | 92109 | 92374 | 62/62 |

以上四项窗口 V/A 均64，耗时与之前无池 Mode7 相同。PN仍比P慢265 cycles。保留已有提前翻译机会不等于增加收益。

**7次SV构建成功；9次运行，7 PASS＋2预期watchdog失败。** 两个失败用于判别容量/直接通路，不计PASS，失败前没有 READ-TAG-TERMINAL。七个成功例的标签 fault/queued均0，字节、排空和守恒检查通过。

## 实现与安全边界

完整已翻译 AR 头暂存，按原始源 ID 选择最早未发头；已排队的同 ID 请求不能被直接通路越过。放行复用已有准确 W 前缀谓词；下游首次 VALID 后锁住选择直到握手。新增同 ID 序号、VALID载荷稳定、终止暂存排空与捕获/派发守恒检查。

跨 DMA 派发后，测试侧 FAST 标签改为按源 FIFO 保持对应关系；原 bank 身份仍用于原预算/豁免。Codex直接核 TC 的 AWAIT_RESP→COMPLETE 与 AR FIFO：在成功 TL 响应握手时，原读头尚未弹出，能够采样源 ID。DeepSeek初稿关于 TL 与完成必须同周期的附加条件没有采用。

## 创新判断与下一主线

最强已跑容量对照是普通共享3槽，而不是只比较普通4槽。候选在本例少一个头槽；没有综合 LUT/FF、时序或总存储成本结果。48B仅是两路活动 DMA 的小数据 FIFO，排除公共TC存储、元数据和控制状态；候选的序号/选择寄存器也应计成本。

该实现本身可由普通共享选择队列加同样的旁路表达，不能将这套组合称为新的调度规则。H1/H2失败只证明当前确定性反例的必要环节，未证明通用最小容量、无死锁或 (K−1)L。

下一主线先明确真实四 DMA/两 bank 下的活动任务数、同 ID 顺序、虚拟/物理 W 顺序与错误路径约束，寻找同信息/同资源下普通规则遗漏的进度边界。需要非平凡的新保证或成本结论才能形成论文贡献；单纯推广这个普通组件，不作为独立创新。

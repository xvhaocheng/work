## Assumptions

1. `+a-dst-offset=4088` is accepted only with `+natural=1 +shared-source=1 +natural-bytes=2048` (the existing shared-source gate at 4443‑4448 already forces 2048). I did not relax that.
2. `+a-next-pte-delay` stays `0..100000` and now requires either `3072` **or** `4088`; it is still applied at most once, to the single walker read whose byte range covers `0x70048`.
3. The 4088 copy is contiguous across two *already mapped* A destination pages (leaf 8 and leaf 9), so `setup_memory_natural()` needs no change: `NAT_DST_PAGES = 9` already covers it.
4. Physical/observed DDR-side counts are unchanged in kind: 256 A destination W beats total, 256 source read beats per detach rule, `n_nat_vaw` becomes 3 (V, A-1beat, A-255beat) and `n_nat_vwlast == n_nat_vaw`.
5. `first_a_page_beats` is defined for the shared 2048-byte fixture per the requested formula; on the ordinary (non-shared) path it reports the literal `256` even though that path uses `NAT_DST_OFF=3072` with 2048/32768 bytes. That field therefore is **not** a claim about the ordinary 32 KiB geometry (flagged below).
6. All these flags are parsed/executed only in an `ACTUAL_DMA_SYSTEM` build (parse block 4146‑4348; `tb.run_natural()` call 4567‑4584). A non-system build ignores them.
7. No RTL, budget, PTE table, payload, expected-data or existing CHECK was weakened. `scenario_budget`/`total_budget()` untouched.

**B. 4088 + bounded PTE delay**

Same vector as Case A, executed against the **old** B-quiet-gated obligation rule. Expected outcome: the run does **not** reach terminal checks and does **not** print a PASS line. It is expected to terminate on one of the existing bounded failure surfaces — `watchdog: no handshake progress while waiting DONE`, `scenario budget exhausted while waiting DONE`, or `not quiet: TL in_flight!=0 or DMA job_quiet!=3` — each preceded by `dump_stall()` (3077‑3216), followed by the failure record at 4593‑4596 with `completed:false, verified:false` and `rc = 1`. ## Unresolved / flagged for Codex (do not treat as applied)

1. **Virtual-W pairing with a split A write.** 4088 introduces a second A write burst, one of them single-beat (`VLEN=0`). If the design ever offers that burst's first W beat on the translation-request port *before* its own AW, the existing observer (2222‑2243) mispairs and trips `n_nat_vw_unattr`, `n_nat_vw_mismatch` or `n_nat_vaw_q.empty()` (1470‑1478). Those CHECKs already carry the “observer cannot pair legal W-before-AW; not a DUT verdict” caveat, so a legitimate 4088 PASS could be reported as a failure. Deciding whether to tolerate/repair that observer is an RTL/root call, not a bounded fixture change — not patched here.
2. **`first_a_page_beats` scope.** On the ordinary (non-shared) path it returns the literal `256` per the requested rule, which is only coincidentally correct for the 2048-byte geometry; the 32768-byte ordinary run is not represented. If the field must be meaningful there, it would need a different formula — requires an explicit decision.
3. **Second-page derived count.** `a_second_raw_parent_bytes_expected` (= 2048 − first page bytes; 1024 for 3072, 2040 for 4088) is *not* emitted — not requested. Available on request.
4. **Observed split is deliberately absent.** No field claims an observed raw-AW split. The only per-flow split counters available are the global q-child W counters (`dbg_pause_a_*`, q-writer) and the post-translation DDR-side `paw`/`pw` events; neither is raw *parent* AW telemetry, so per the constraint none was surfaced as “actual”. If root adds real A raw-parent telemetry, `a_first_raw_parent_bytes_expected` should be **supplemented**, not silently renamed.
5. **`a_next_pte_ar_matches == 1`** is structurally guaranteed (increment shares the `a_next_pte_delay_applied == 0` guard at 2712‑2721), so no new CHECK was added for it; if a stricter assertion is wanted, it is `CHECK(a_next_pte_ar_matches == 1)` inside the existing 5b block.

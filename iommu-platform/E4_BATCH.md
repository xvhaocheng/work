## 执行方式

使用 `idma_experiment --batch` 选择独立的硬件批量操作；原命令继续走软件逐项补交。每路保持一个未完成的DMA任务，完成后由前端硬件接续下一项，不等待CPU逐项轮询或改写地址。数据路径仍为DEFAULT读写拷贝，每项4096字节。地址按 `base + (任务序号 % 页数) * 4096` 推进，源/目标独立，同一DID内循环。

V任务数1～1048576，页数1～4096；A使用2^32项安全上限。两路配置完成后先启动A再启动V，A持续执行；CPU轮询V的整批DONE，随后请求A停止。STOP不取消在途AXI，也不撤回已提出但未受理的任务；停止时允许当前已提出任务安全完成，然后排空。若排空超时则保留缓冲、标记quarantine并拒绝后续实验。

这不是同时起跑：A比V先开始，硬件测量窗口从V的首个任务开始。观测器检查A在整个V窗口保持批量运行，A提前耗尽会使试次无效。两路最大一项未完成，仍可在设备之间并发；不引入深描述符队列。

预热沿用已验证的软件逐项模式，之后排空、从页号0进入批量测量。warmup=0时不额外发预热任务。V/A的映射、缓存同步和正确性检查保持；新模式的供给/边界变化已明确，因此不把新旧E4样本混为同一协议。

## 接口及输出

新增独立ioctl `IDMA_IOC_RUN_BATCH`（0x08），复用ABI1的输入结构布局、flags/reserved仍要求0；旧0x07含义不变。新增软件能力位bit2，运行时还精确验证batch硬件及observer v2标识；旧BIT不能运行批量模式。每次批量实验强制采集硬件观测，不受旧 `observe` 参数影响。

CLI的批量JSON schema为 `idma.batch.v1`。submitted/completed是安全排空后读取的硬件任务数；软件refill_gap字段为null。A任务数包含A启动及末尾排空，不能除以V窗口称为窗口内A吞吐。`victim_elapsed_ns`仍是软件窗口，包含A/V启动和最终轮询；真正硬件窗口见同seq的三条 `idma_batch_obs` 日志：

- `part=time`：cycles、h、gap、hmax、gapmax、issued、done、batch_polled、done_to_read及valid/status、V/A身份。
- `part=axi_v` / `part=axi_a`：沿用AXI请求/返回/等待、在途期初/期末和四种占用状态。

硬件窗口从V首个任务被frontend后级FIFO接受，到第N项实际完成。H累计各项“FIFO接受→完成”，gap累计完成到下一项FIFO接受；严格满足 `cycles = h + gap`。该H的开始比旧E4“CPU触发任务ID分配”边界更靠后，不能假装完全相同。窗口在硬件完成时冻结；done_to_read另计末项完成到对应整批DONE读取，batch_polled应为1。没有逐项软件P/R统计。所有硬件时间为50MHz周期（20ns），不等于纯IOMMU时间。

HPM仍是软件窗口前后非原子的快照，覆盖A启动/停止尾部；硬件AXI计数另有精确V窗口。观察到重叠只证明并发压力存在，不单独证明共享队列竞争或HOL。

## 寄存器（驱动管理）

在每路DMA已有映射内显式新增高128字节bank，旧低128字节寄存器不变。硬件锁住活动批次的源/目标/长度等写入；STOP可用。

| 偏移 | 说明 |
|---|---|
| 0x80 | batch v1标识 `0x49444d4142544301` |
| 0x88 | 写0清除/关闭（仅空闲，包括清零旧任务计数）；写1启用（仅空闲）；写2请求安全停止。读bit0启用、bit1运行、bit2已停止、bit3正常完成、高32位配置错误 |
| 0x90 | 有限任务数，1～2^32 |
| 0x98 | 源/目标各自的循环页数，1～4096 |
| 0xa0 / 0xa8 | 已完成 / 已发出任务数，按4KiB任务计 |
| 0x28 / 0x30 | 沿用NEXT_ID触发整批及DONE确认整批；功能ID每批增加一次 |

仅FPGA实例启用新bank，地址低8位显式解码，不能套用原7位镜像访问规则。批量开始时校验DEFAULT、4KiB长度和页对齐；配置错误不能静默当作正确批次。

observer v2标识 `0x49444d414f425302`，原0x58～0x78窗口保持。ARM增加bit25选择批量；结果0～33保留索引，批量时2/P固定0、3表示硬件gap、9表示整批读取次数，34新增done_to_read。错误bit5表示A未覆盖V窗口。旧软件模式仍可使用observer v1/v2，日志格式保持。

## 上板顺序

新BIT和00082软件均就位后，保存完整串口及每次JSON、退出码、三条同seq观测。初次可运行：

```sh
platform-timeout 120 idma_experiment --batch --device /dev/idma0 \
  --aggressor none --victim-pages 1 --chunk 4096 \
  --transfers 8 --warmup 0 --timeout-ms 10000
rc=$?
echo "batch exit=$rc"
dmesg | tail -80
```

先连续两次上述相同配置，核对清除/重用；换DMA1重复。再用8页、8项、无预热的Solo覆盖页序列，再做双角色A1/A8的8/64项短批次，保存原始记录。warmup=0试次需确认未触及页保持初始化值；不要先用预热把漏访问掩盖。

有效观测应valid=1/status=4，V issued=done=N、batch_polled=1，H+gap=cycles，占用四项和=cycles，AXI“期初+受理=返回+期末”；V请求/返回应非零且期末排空。核对A供给覆盖、实际请求重叠及CPU读完成延迟。无数据错误、quarantine和内核taint后，才做4096项、预热256的Solo/A1/A8双角色对照。主样本轮转条件并交换角色，不因没有慢化而补采挑选结果。

以上为原定上板顺序；Mac现已完成短校准及主矩阵，另按用户要求完成固定角色A16/A32/A64扩展。结果和边界见文首链接。下一步再设计IOMMU内部定位对照；当前不自动扩展E2/E3或改中断。

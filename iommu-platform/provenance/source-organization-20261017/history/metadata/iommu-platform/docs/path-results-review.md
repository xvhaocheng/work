## 能说明什么

1. **Solo→A1：** 内部经过时间不变，读写后段均增加约618周期，存在即使双方无miss也会发生的数据路径慢化。不能把“共跑导致的全部下降”归因于翻译。
2. **A1→A8：** 内部读写时间显著增加，而V的HPM miss均为0，支持优先核查共享翻译服务/队列等待；已经得到比总吞吐和miss相关性更具体的位置证据。stage1仍含排队、翻译服务、出队等过程，尚不知道增量在哪个内部子段。
3. **入口/出口：** 这批请求的入口恒1周期、COMP首次VALID至握手恒0；未观察到额外入口经过时间或COMP地址反压。它不排除IOMMU内部出队等待，也不排除数据/返回通路竞争。
4. **写后段：** A8比A1增加约325周期，必须保留解释。写stage3包含W数据供给及B返回；V读翻译变晚可能使写数据更晚到达，也可能有数据通路竞争。当前不能把它全算成DDR变慢，或假定已全部由内部等待解释。

读写和同通道多笔事务重叠，**不能把各段sum相加，也不能据此计算47.76ms中有多少百分比“由翻译造成”**。正式V miss全0只是该HPM窗口的计数，尚未直接观测每个V请求的首次IOTLB查询。

A8的软件窗口中位174.046ms，硬件154.920ms，末项完成至DONE读取中位18.673ms。这是另一个计时层面，不能混入内部经过时间。A1第29条软件130.766ms、硬件107.205ms、done_to_read仅2.233ms，说明软件额外时间也不能一律归到最后轮询。

## 1. 三条路线的取舍

| 路线 | 一句话问题 | 潜在贡献，尚未验证 | 主要工作与风险 | 决定 |
|---|---|---|---|---|
| A：页面工作集感知的 DMA 提交控制 | 同样的字节流量，翻译压力不同，普通带宽限速会不会选错控制力度？ | 一个低成本的翻译压力代理与提交规则，在相同后台有效吞吐下改善敏感任务耗时，并明确失效条件。 | 描述符/提交原型、性能测量为主；须先查现成接口，不能承诺纯软件。主要风险是大页、复用、简单限流已解决问题。 | **首选做立题验证** |
| B：共享 IOMMU 配置的适用边界与选择规则 | 什么情况下缓存保护、命中先服务及其组合有用，何时付出更多代价？ | 可验证的原因区分和简洁配置选择规则，在未参与调参的条件上优于固定选择或已有简单规则。 | 复用四模式与计数器；缺关键观测才补。实现较集中，新意风险较高：不能只报告“参数不同结果不同”。 | **A 的备选，也可共用测量基础** |
| C：容量隔离与替换状态耦合 | 分开分配缓存条目后，共享替换历史还会怎样影响对方？ | 只有发现可推广的设计约束/代价，并经强普通基线后仍成立，才可能形成贡献。 | 已有局部线索；涉及 RTL、替换策略和闭环归因，容易只剩本实现问题。 | **工程诊断线索，不单独押作首篇题目** |

“增加日志/事件账本”归入研究工具；“最少观测”若没有独立方法与用途，不另外拆一篇。这里不同时开启三套实现。

## 2. 路线 A：把题目说清楚

**暂定题目：面向共享 IOMMU 的页面工作集感知 DMA 提交控制。** 题目用于限定范围，还不能称新机制已经成立。

用大白话说：后台设备既可能反复搬运几个页，也可能不断访问新页。两者即使每秒搬运相近字节，对地址翻译缓存和页表遍历的压力也可能不同。尝试让提交控制同时看字节量和近期页访问特征，减少对敏感任务的干扰。

可以从简单版本起步：在提交端维护一个有界的近期页集合/近似计数，对引入大量新页的后台批次调整提交节奏。第一版保持任务的合法顺序，不必引入跨设备 DAG、预测网络或全新页表。是否需要调整真实在途请求数，取决于接口，不能把“完成后等待一段时间”称作在途预算控制。

**潜在新意应落在三件事的连接上：** 可得到的页信息究竟预测什么翻译压力；它怎样改变一个具体提交决定；改变后能否在强基线之外改善双方性能与成本的权衡。仅提出“按页限速”或“使用两个预算”还不够。

### 必须跨过的前作

| 前作 | 已有内容 | 对本候选的直接限制 |
|---|---|---|
| [Overcoming the IOTLB wall，2023](https://doi.org/10.7717/peerj-cs.1385)；[本地全文](../out/shared-translation-literature-20261006/papers/iotlb_wall2023.pdf) | 已分析每 MiB 的 IOTLB miss、缓冲区局部性/回收，并实现大页感知分配器。 | 页局部性和翻译压力的联系不是新发现。须比较大页、复用、缩小活跃集合及简单反馈。 |
| [Bermuda，2025 作者稿](https://arxiv.org/abs/2508.19670)；[本地全文](../out/shared-translation-literature-20261006/papers/bermuda2025.pdf)，§V-C | 已测多 DMA 下的 IOMMU 干扰，并提出 per-stream QoS 缓解方向；该稿未完成缓解机制的实验评价。 | 不能宣称首次发现干扰或首次提出限速。可继续核一个具体、低成本控制方法的有效范围。 |
| [rIOMMU，ASPLOS 2015](../out/shared-translation-literature-20261006/papers/riommu2015.pdf)，设计/适用范围 | 利用 ring 映射顺序，采用专用平表与失效组织；N≥L 是容量/活跃 IOVA 约束。 | “利用描述符顺序/批量”有前史；其专用结构不是现成的软件提交限速器，也不能因此忽略它。 |
| [MASK，ASPLOS 2018](../out/shared-translation-literature-20261006/papers/mask2018.pdf) | GPU 中已有翻译准入、争用保护和调度。 | 翻译感知准入也不是空白；应区分源端提交、内部 TLB 准入及各自信息/成本，并补查等价机制。 |

[SP-IMPact](../out/shared-translation-literature-20261006/papers/spimpact2025.pdf)支持 cache coloring 和内存带宽预算的研究框架，但所核评价明确未展开 MBR 配置；不能拿它证明 IOMMU 翻译控制已验证。[RISC-V QoS ID 扩展](https://docs.riscv.org/reference/iommu/iommu_extensions.html)提供资源控制/监测标识的关联规则，不等于当前 FPGA 已具备页数预算控制器。

这些对照尚不足以排除全部等价前作。继续检索只围绕提交限流、翻译感知准入和页工作集代理，不再默认扩大到整套 GPU/CXL 架构。

### 最小论文证据链

1. **一个有用的现象。** 在可比较的任务、提交需求与字节流量下，不同页复用行为造成普通限速的效果差异。需要剥离 DDR/互连、CPU 提交和缓存前态影响；只有“工作集变大更慢”不够。
2. **一个简单机制。** 近期页信息帮助调整提交，普通字节限速、固定 gap、固定批量/队列深度经过合理调参后仍留下收益空间。新规则的参数和资源不得享有不公平优势。
3. **一个完整验证。** 用敏感任务耗时—后台有效吞吐曲线、控制开销、不同局部性与阶段变化、阴性负载，说明什么条件有用、什么条件无效。

首张关键图的横轴是后台实际完成的有效字节/秒，纵轴是敏感任务端到端耗时；分别画普通字节限速、固定 gap/批量以及候选方法的参数扫描曲线。比较可达到的权衡边界，避免只挑一个很差的限速参数。没有逐作业时间戳时只报告现有完成窗口；取得足够样本和边界定义后才能报告尾部延迟。

固定逻辑任务、输入、权限语义和合理资源预算。miss 数、完成吞吐和排队变化是结果，不强行固定它们。后台总完成量相同也不意味着竞争时序相同，所以同步记录任务可提交时刻、实际提交、排队/积压、完成和测量窗口边界。敏感任务耗时从事先定义的释放点开始，不能把控制器造成的等待隐藏在计时之外。

不使用“敏感延迟除以后台字节”代替双方性能曲线；不同量纲相除会掩盖取舍。固定总工作量的作业完成图可作为补充，不能单靠它声称同等吞吐。

### 简单不等于可以忽略的细节

- “近期新页”只是代理，不是精确 IOTLB miss 预测；PWC、预取、缓存容量、页大小与其它设备都可能让它失准。
- 源与目的地址都可能需要翻译；键须按实际地址空间/翻译上下文和页粒度定义、合理去重，不能认定 DID 总是 IOTLB 的 tag。
- 大页、缓冲区复用/重排、缩小 ring/活跃集合是强基线。若实际接口不支持某个方案，明确限制，并在合适模型或扩展中评价；不通过人为禁用来保护候选。
- 控制开销包括页集合维护、CPU 周期、元数据、提交延迟、批处理摊销、阶段切换和后台积压。先求清楚的小规则，不引入复杂学习算法。
- 如果普通方法已经给出同样或更好的权衡，停止该机制。阴性结果是否另有论文价值，取决于是否形成可复用的新解释，不能自动转成“负结果论文”。

## 3. 路线 B：用现有四模式做有预测力的测量研究

**暂定题目：共享 IOMMU 中容量保护与并发服务的适用边界。** 目标是帮助工程师决定什么时候开保护、开命中先服务、两者一起开或保持基线。

现有 S/N/P/PN、同 BIT 对照、正常 lookup/hit/miss、fast accept、实际 GAP 周期和缓存快照可提供起点。已有条件差异尚未完成因果归因；172/172 是功能验收，原数据已看过且是单 boot 三 block，不能当新的留出验证。

它要形成论文，至少需要：找出一个对配置选择有用且已有研究没有充分解释的具体条件；用真实源码/受控干预区分容量、排队、替换历史和软件供给；形成简洁选择规则；在新工作集、释放节奏或实现配置上预先预测，再验证其准确性与实际用途。

第一张目标图可画“局部性/提交节奏 → 最佳配置与选择代价”，但不能只给彩色热图。应给出相对固定选择、简单 miss 阈值及强普通基线的错误选择损失、测量成本和不适用范围。若 N 在所有有效条件下已最好，或普通规则已足够，不能为了保住题目制造特殊输入。

最强对照包括 [IOTLB Bottleneck 2010](../out/shared-translation-literature-20261006/papers/iotlb_bottleneck2010.pdf)、Bermuda、MASK，以及[已有审议中核过的 KPart](performance-council-decision-20261005.md)。容量分配与带宽竞争的相互作用已有前史。更换 RISC-V 平台、复现通用现象，不足以单独确立新意。

路线 B 不必一开始就做在线控制器或证明全局最小观测集。对未见条件有用的测量方法、预测和设计指导可以成为贡献候选；仍须比现有微基准多回答一个具体问题。一个校准过的开放实现加参数化模型可以支持限定范围的主张，第二块商业板不是自动必需条件；也不能据单一实现外推所有 IOMMU。

## 4. 现有平台能帮到哪里

2026-10-06 已完成[实际源码/构建/数据可行性审查](platform-feasibility-20261006.md)：当前composition可用软件扩展后台gap/静态页数，其BIT禁用旧准入控制；历史method88已在另一profile上完成反馈实验。当前Slice99.60%、WNS0.031ns；先复用旧基线明确新缺口，再决定是否扩展当前版本和控制器。

[现行规格](composition-v1-spec-20261004.md)规定 16 条 IOTLB、四 DMA、四模式及受限的页数/gap/4 KiB chunk 接口。它适合做小范围机制和因果验证，不代表已经有任意描述符调度器、可配置在途上限、完整事件 trace 或真实多设备应用。

当前 gap 是完成后再等待后续提交的闭环节奏，512 拍缓冲也不能直接叫作 descriptor 队列深度。规格文件开头的旧“未称上板通过”是历史状态；当前功能验收以 CURRENT_STATUS 和后续验收记录为准。

选择一个可核实的数据搬运工作流即可起步，例如流式分块搬运与计算交替，或基于 ring 的缓冲区处理。前作中的模式是应用动机；移植到本平台的参数化 workload 应明确称工作流模型，应用级主张还需实际程序或可信轨迹。无需先搭起 NIC–GPU–CXL 整条系统，也不把微基准当实际部署。

## 6. 用户追问：这两点能否突破已有研究边界？

**当前只能说存在实质贡献的路径，不能说已突破。** A、B是可执行的立题入口。A若只是给DMA增加页计数和限速，B若只是扫描S/N/P/PN后总结配置优劣，均不足以据此宣称研究边界扩大。用户不要求顶刊，并不改变这个区分。

全图中的位置是：A连接“软件提交/缓冲区管理”与“共享翻译服务”，B连接“性能观测”与“配置决策”。跨越两个研究主题本身不构成创新。[IOTLB Wall](https://doi.org/10.7717/peerj-cs.1385)已有局部性、misses/MiB与软件缓冲反馈；Bermuda已有干扰测量与QoS方向；MASK已有翻译准入/调度。一般资源管理中，[KPart](https://people.csail.mit.edu/sanchez/papers/2018.kpart.hpca.pdf)也已用性能曲线并考虑缓存和带宽竞争，不能称首次联合管理。HELM、CounterPoint和Coz继续约束B的观测/决策主张。

| 候选 | 宽泛表述的不足 | 值得验证的具体推进 |
|---|---|---|
| A：提交控制 | “相同带宽不同翻译压力”“增加页预算”有充分近邻。 | 在明确的共享翻译条件下，证明普通字节/页计数/局部性规则遗漏了决定动作的因素；用实际可获得的信息和有界状态改进提交，超过调参后的强基线，计入等待、维护与双方性能。 |
| B：配置选择 | “组合可能反噬”“miss少未必快”“统计后选配置”不是新发现。 | 给出可证伪的解释或判别方法，预测未见工作集/释放模式/实现参数下何种配置有效；说明误差和适用范围，并证明比已有简单模型更有用。 |

可以合成一篇：**发现现有控制依据在某类正常条件下失效 → 找到遗漏信息或特有约束 → 以小机制纠正 → 在新条件验证。** B负责证据与解释，A负责可行动作；不要求为了合并而强行证明“同指标不同动作”必然存在。

最小突破证据需回答三个问题：①失败发生在合理工作流中，且不是源码错误/差基线/额外资源造成；②修正依赖的信息、约束或方法相对最强适用前作有可说明的增量；③在未参与选择的条件下仍有净用途。若只有在本板16条缓存和某固定参数下出现，结论应限制范围，不自动外推。

下一判别应寻找一个普通控制判断错误的正例，以及一个相近但普通控制有效的阴性对照。比较包括字节限速、页/局部性启发式、固定队列/批量与适用大页/复用方案；保持逻辑工作与语义公平，不固定miss结果。没有这种缺口就缩小或更换主张。尚无新证据证明上述实例存在；不写“首次”、发表概率或最坏情况保证。

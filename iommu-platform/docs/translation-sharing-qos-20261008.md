# 登记任务的剩余翻译用途：候选机制与下一判别

2026-10-08，§47。主线仍是多 DMA 共享 IOMMU 的整体性能。本轮完成源码、前作和纸面规则审查，没有新增仿真、数学运行、编译或上板；最新完整 copy 结果仍是 §43。

## 保留的具体候选

**把已登记 DMA 拷贝任务的范围与可靠译址进度结合，判断一个共享翻译条目是否还会被已登记任务使用，再辅助保留、准入与替换。**

例如 A 已读过输入页 X，但进度较慢的 V 稍后还会读 X，就保留其翻译价值；如果两者都已越过 X，优先把它交给新页。这里讨论的是缓存价值，不是页表映射失效，也不能取消权限检查。未知的下一份任务仍用普通策略处理。

这比“谁最近访问过”多了一类可用信息，但**提前传任务、预取、锁定、引用计数和 dead-first 替换本身已有前作，不能仅改名字就称独立创新**。如果具体的新反馈与状态组织能以较低成本，或取得较好的完整 copy 性能，超过获得相同信息的强对照，就可以论证独立微架构贡献。

## 机制需要什么真实信息

iDMA frontend 已有 src、dst、len；批处理还会改变 offset。它们可以描述已登记任务，但 IOMMU 目前没有免费获得完整任务、epoch 和可靠剩余用途反馈。

legalizer 的地址推进表示下游接受了请求，**不表示译址结果已经成功保存**。因此拟议规则使用“译址已成功写入请求私有元数据”的事件，而不是把地址最大值当成完成前缀。

第一版只考虑固定映射、合法 4KiB 页、有限已登记的递增拷贝。每任务分别管理读源、写目的的剩余范围与尚未完成译址的请求；多个任务的用途取并集。正常命中照常服务，未被登记任务继续使用的条目优先回收，其余使用普通替换。不能把全部仍有用途的页硬锁住，使缓存满时无法继续。

原生 TC 的每方向 FIFO、每 bank 单笔请求和响应流程支持一条较窄的简化：在单任务、固定 bank、递增且成功译址按序返回的条件下，可用保守页游标表示已越过的页。当前页仍保留到下一页或可靠的结束事件；大页必须比较完整覆盖范围。bank 来自原 AXI ID 位，并不是 DID 或读写方向，不能用 bank 代替任务身份。

**最新 §43 prepared-parent helper 不能直接套这条简化。** 它可以保留多份 parent，慢准备期间又有快复用返回；prepared 表示已提交，valid 才表示准备成功。必须核 producer 的连续完成边界，或者计入乱序空洞窗口。相关关键源码与条件见[根级设计](../out/translation-sharing-qos-20261008/codex-candidate-design.md)和[独立规则审查](../out/translation-sharing-qos-20261008/rules-critical-agent.md)。

## 更合适的最小场景

若各 DMA 只读自己的源、写自己的目的，单调前进且后面无人复用旧页，普通每方向 last-page cache 或共享条目指针就可能消除全部容量重读。知道“已经用完”不能进一步省掉首次必须进行的翻译。

下一场景采用**两个 DMA 读取同一份只读输入，写入不同输出，进度错开**。一方越过的源页，另一方稍后仍需要。研究席已给两份 32KiB copy 的合法页表与请求字典，但没有执行；完整内容见[规则审查 §2](../out/translation-sharing-qos-20261008/rules-critical-agent.md)。

先确认确有额外的非首次页表遍历，再比较完整 copy 完成时间和 V/A 各自处理速度。允许普通对照使用同样任务信息、总容量和进度信息，包括：

- 全局替换、任务感知的范围比较与用途并集；
- 少量 last-page microTLB，或共享条目指针与引用保护；
- 预取、有限锁定与释放、动态容量分配。

若这些对照已消掉重复翻译，或页表遍历减少却被数据搬运瓶颈完全抵消，就停止把纯替换规则作为性能贡献。

## 成本与现有证据

保守游标不自动更便宜。例如 D=4、E=16、VPN 宽度 W=29 时，两方向游标仅载荷就有 232 bit；另存两端页再需 232 bit。普通每条目、每 DMA、每方向用途位图载荷为 128 bit。两者还需上下文、epoch、有效位、初始化/更新、窗口、接口和比较逻辑。这些是局部手算，**不是完整等成本比较或面积结果**。

纸面两槽见证说明：登记任务的后续用途能够改变合理 victim；但同信息的普通任务感知保留也能取得相同 miss 数。因此它只证明信息可能有用，不证明新算法或平台收益。

合并 miss 的物理工作只发生一次，而多个逻辑受益者均可独立记账；这是两个账本，不能把普通扣费合同包装成新机制。Li 2015 已给后加入 merger 更新排队请求及累计年龄；UCP、SHiP、Hawkeye 分别已有容量效用、插入来源反馈和使用区间等明确机制，不能把它们混称同一种 requester 历史，但须纳入强对照。[前作逐字段审查](../out/translation-sharing-qos-20261008/prior-critical-agent.md)

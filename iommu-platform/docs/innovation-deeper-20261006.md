# 再深入一层：实际早发写路径与比成对预翻译更弱的完成条件

日期：2026-10-06。接续[上一轮审查](innovation-followup-20261006.md)。本轮核源码、规范与条件推演；未修改生产代码、构建、仿真、重跑限速或上板。

## 1. 本轮新增结论

**研究问题还能进一步收窄，但创新仍未过关。** 源码允许目的物理写地址先于源地址翻译完成；当前却没有构成所讨论完整环的撤销锁与排空等待。更重要的是：不仅“全 job 缓冲”过于昂贵，“必须先拿齐两端翻译”也不一定是必要的完成条件。

| 问题 | 本轮裁定 |
|---|---|
| 真实 iDMA 会不会提前发 AW | 当前实际配置允许。读写请求同拍生成也不能排除后续翻译先后不同 |
| banked 路径是否排除这种顺序 | 不排除；每 bank 仍使用 AW 优先的控制器，读准入守卫不保证源翻译先行 |
| 当前失效是否产生上一轮完整等待环 | 没有这项证据。CQ 的 PR/PW 排空为 TODO，IOTLB 失效不是全局暂停翻译锁 |
| 普通成对预翻译是否必须锁住两个 TLB way | 不必须。可用结果暂存表，但必须处理其有效性；不能人为抬高基线成本 |
| 还能否比成对预翻译更宽松 | 在限定的物理请求排空模型内，可以用返回空间预留与写数据依赖准入排除两类环；这是普通控制规则的组合，不是新机制验收 |
| 是否立即以 C2 为论文主线 | 不建议。当前只有更精确的研究规格；新颖性、应用场景、相对强基线的增量均未确立 |

## 2. 实际源码闭合了哪一半

源码位置均相对于 `cva6/corev_apu/`；[本轮记录](../out/innovation-deeper-20261006/README.md)保留模型输入、完整答复和根审查纠正。

- `fpga/src/ariane_peripherals_xilinx.sv:1265–1290`：实际实例 `RAW_COUPLING_AVAIL=0`、`NUM_AX_IN_FLIGHT=8`；研究模式 DMA0/1 的 buffer 为512拍。`1418–1421` 将研究模式连接至 banked controller。
- `iDMA/src/frontends/register_64bit/idma_reg64_frontend.sv:366–367`：`decouple_aw=0`、`decouple_rw` 来自软件配置。前一个 bit 在本配置中不能启用一个没有实例化的 coupler。
- `iDMA/src/idma_backend.sv:811–858`：耦合器关闭时 AW 走 fall-through register，无等待 R 到达的门控。
- `iDMA/src/idma_legalizer.sv:452–466`：`decouple_rw=0` 使两个虚拟请求共同推进，不保证下游两个翻译同时完成。不能把 `decouple_rw=1` 列为早发物理 AW 的必要条件。
- `riscv-iommu/rtl/transaction_controller/rv_iommu_trans_ctl_wrap.sv:623–647,716–727`：同一 bank 优先选 AW，目的翻译完成后可发物理 AW，再处理 AR。`329–360` 的 AW 发出没有等待 W 数据到齐的条件。
- `iDMA/src/idma_axi_transport_layer.sv:232,289–291,343–360,388`：普通 copy 的 W 数据来自读返回缓冲，AW 与 W 数据条件分离。
- `riscv-iommu/rtl/transaction_controller/rv_iommu_banked_ctl.sv:243–278,314–357`：bank 根据原始 AXI ID 位选择，每 bank 内仍是前述控制器；跨 bank 读准入守卫避免特定数据路径依赖，不保证源翻译先于 AW。

由这些门控可以构造源码允许的前缀：虚拟 AR/AW 均待处理 → 目的翻译先完成 → 目的物理 AW 被接纳 → 源翻译／读返回仍未完成。这里假定合法地址、互连正常响应，讨论的是可允许的顺序；**没有运行仿真取得周期轨迹，也没有证明完整系统死锁。** 正常继续完成源翻译时，这个顺序本身不是错误。

已有 `iDMA/src/idma_channel_coupler.sv:105–181` 可以将 AW 延迟到首个对应 R 到来之后。它是必须考虑的普通基线。首个 R 不等于整个 W burst 所需数据都已可得；是否已涵盖所有源翻译取决于读写 burst 的对应关系。对于等长、正确配对的单读／单写 burst，首个 R 已证明该读的翻译完成；不能泛称 coupler 对本题永远无效。不同页边界／读写独立分块需另核，不能假定一律一对一。

## 3. 不能补一个假想的更新锁，再宣称现有平台有缺陷

`riscv-iommu/rtl/software_interface/rv_iommu_cq_handler.sv:310–341` 产生失效控制；`348–395` 中明确保留 `TODO: Add IOFENCE support with PR and PW using R/W counters`。该路径没有实现本题需要的物理读写排空等待。现有可选 ATS fence 等待、完成通知写与设备数据排空是不同的事。

`riscv-iommu/rtl/translation_logic/rv_iommu_iotlb.sv:83–137,166–331,433` 的查找与失效更新分开；失效并非“锁住所有后续翻译直到全部物理写完成”。本轮不据此对整个失效正确性作全面签核。

[RISC-V IOMMU 20260222 的命令规范](https://docs.riscv.org/reference/iommu/v20260222/iommu_in_memory_queues.html)也不要求实现全局暂停后续翻译：IOTINVAL 同步页表更新与后续隐式访问；IOFENCE 的 PR/PW 对已被 IOMMU 处理的先前请求提供全局有序保证，未被处理的请求还涉及互连特定的 fence。

因此，“增加全局停翻译 → 再等 W 完成 → 遇到循环”目前首先是对一种设计选择的反例。除非找到真实系统中合理且必要的这类暂停语义，不能把自己额外施加的限制当成领域公认难题。

## 4. 更进一步的推演：不必每次等齐两端翻译

以下由 Codex 提出并审查，是一个限定模型的充分条件，**不是已发表的新方法，也不是完整 AXI／撤销协议证明**。

假定更新 U 停止新的翻译／物理请求准入，只等已经物理发出的请求排空；已发请求保有合法的完成权限。内存公平响应，接收缓冲及完成通道能被服务，没有另一个未建模的网络／队列环，普通内存 copy 无额外外部数据生产依赖。

两条普通规则：

1. 对每个接收域维持 `O + R ≤ B`。O 为已存读数据，R 为已物理发出未返回的读字节，B 为可用接收容量；预留必须在实际接收缓冲中可用，不能只算全芯片总和。
2. 发出一个物理 AW 前，它所需的全部源读已物理发出，或对应数据已存在；完成这笔 W 不再需要 U 所禁止的新翻译／新准入。部分数据已到、只收到首拍或只翻译了第一段，不能无条件代替这个判断。

于是停止新准入后：已发 R 可以使用预留空间返回；已发 W 的数据来自这些能返回的 R 或既有数据；二者都不需要通过暂停的新翻译才能完成。原先两类 `U → 数据排空 → 新翻译 → U` 环在这些假定下被切断。

这允许一个普通次序：**先完成源翻译并带空间预留发读，目的翻译随后进行；只有满足写数据依赖条件才发 AW。** 不要求发读之前目的翻译已经完成。这也不意味着任意情况下源优先都好，或只加一个读优先 bit 就正确。

一个只用于说明的单分块时序：源／目的翻译耗时分别为 `Ts/Td`，读返回延迟为 `Lr`，写阶段为 `Lw`；单 PTW、缓冲足够、无故障／干扰、忽略接口气泡。严格拿齐两端再发读的完成时间为 `Ts+Td+Lr+Lw`；上述次序允许 `Ts+max(Td,Lr)+Lw`。差额来自普通的翻译／数据访问重叠，**不是实测提升，更不是相对最强流水化预翻译方案的优势**。多槽预翻译流水也可能隐藏这段代价，必须纳入比较。

若 U 等整个 descriptor/job 完成，上述证明不适用；若存在缺页、错误回收、设备永不响应或额外反压环，也需补充机制／假设。当前 RTL 并未实现并验收这套规则。本轮不建议为了它立即重编。

## 5. 重新列公平的资源账本

| 独立资源／语义 | 应如何比较 | 不应如何比较 |
|---|---|---|
| B：读返回／数据缓冲 | 相同字节容量与可用接收位置，计入预留但未返回字节 | 只记录当前 FIFO 占用，忽略未来必到数据 |
| K：持有的配对翻译记录 | 明确新增表每项的地址、权限／上下文、有效性和取消状态；允许有界流水 | 把当前一／两个控制器请求槽直接称为一／两个配对槽 |
| W：PTW 服务能力 | 与 K、控制器在途数分别固定／扫描 | K 增加就当作 walker 增加 |
| C：IOTLB 缓存 | 同等容量与缓存策略；记录额外命中／污染 | 假定每对必锁两个 TLB way |
| 配对信息 | 可来自已有 descriptor、可证明的顺序或显式 tag | 必须修改 AXI 才能配对，或同 AXI ID 就天然唯一配对 |
| 更新／错误语义 | 同样的有效性、更新完成边界与可重复副作用限制 | 用无限推迟更新、复用旧权限、任意重放已生效写换性能 |

当前控制器只保存各自正在处理的单请求翻译结果；没有因此就获得“完整配对结果槽 K”。普通基线可以用独立 holding 表，未发出且仍有效的结果可按规则保留，失效结果必须作废。`NO_ERROR_HANDLING` 也不是已经具备失败重放。

最低限度的普通比较组包括：返回空间信用＋匹配 burst 的既有 R→AW 耦合；上述按实际依赖准入；小 K 的成对预翻译并允许跨块流水；适用场景下的部分完成／重试。全量 job 缓冲只是一项参考。

补核了 [Intel DSA Rev3（2025-06）](https://cdrdv2-public.intel.com/857060/341204-006-intel-data-streaming-accelerator-spec.pdf)：§3.13 已有描述符地址 ATS 和故障阻塞／部分完成，§4.3–4.4 提供读缓冲保留／限额与在途描述符限制，§8.2.4 定义故障时已完成字节。这限制了“第一次联合 DMA 翻译、缓冲和完成进度”的宽泛主张；它不等于证明本文特定 AXI 更新循环已有完整对应解法。规范不同于具体处理器每项能力都已启用。

## 6. 还剩什么可能成为论文

进一步可问：**已有信用控制、R→AW 耦合、小表成对预翻译分别会在哪种合法搬运关系下变得过于保守？能否仅增加少量真实依赖信息，使更多请求安全重叠，同时不增加缓冲或拖延更新？**

这比“少预留几个翻译”更具体，因为新增信息及其能改变的准入决定可以明确。但尚未找到一个经前作核验、能使这些强普通办法都留下有意义缺口的真实场景。普通源优先、动态切换两个模式、画等待图或给已知信用规则换名，都不自动构成创新。

进入最小概念验证需要：真实场景与地址路径；普通规则必须保守的具体状态；新规则在同等可用信息／资源下可合法放行的状态；强基线也能解决时的停止条件。更高性能和跨条件稳定性在概念验证后检验，不要求开始前就有完整结果。

**本轮决定：不把 C2 升为首篇主线，不启动 RTL／板测；继续只值得做这个明确的信息差异与资源边界判别。** 若差异只能靠添加当前应用不需要的全局更新锁、移除普通基线能用的信息，或人为不给对照流水能力，便停止这条主张。当前还没找到可诚实宣布“已达到创新点”的结果；也没有据此断言整个共享翻译领域已无空间。

DeepSeek 完成源码证据整理与定向修订；Codex 直接核关键数据路径、官方规范并完成条件推演和最终裁定。详细纠正见[审计记录](../out/innovation-deeper-20261006/audit.json)，不是模型共识或实验结论。

## 7. 用户追问：这些是否早已有过，能否算创新

**明确裁定：基础办法大部分已有，当前描述不通过创新立项。** 前述“还可深入”指尚未排除的研究可能，不是确认有足够差异值得投入RTL。没有一篇已核论文被证明与全部假设逐项等价，也不等于因此获得新颖性。

| 当前表述 | 直接前史 | 裁定 |
|---|---|---|
| 预装／锁定翻译；按burst记录失败并重发以节省缓冲 | [ICCD2018 MMU-aware DMA §IV-C](https://arxiv.org/pdf/1808.09751) | 这些构件已有；单外存端与双外存端不同不足以自动构成增量 |
| 等对应读返回再放行写地址 | 本地 `idma_channel_coupler.sv:11–12,105,140–162` | 已有实现，不是新接口原则 |
| 缓冲配额、在途限制、吞吐与延迟取舍 | [Intel DSA规范§4.3–4.4](https://cdrdv2-public.intel.com/857060/341204-006-intel-data-streaming-accelerator-spec.pdf) | 宽泛资源控制主张已有明确前史 |
| 失效完成等待后续翻译的进度问题 | [Arm DTI IHI0088G §4.3.6](https://documentation-service.arm.com/static/668660ca69e89f01e39c40fb) | 同类依赖早已在规范中被处理；不等价于普通miss=fault或相同AXI实现 |
| 少量依赖信息使准入更准确 | 目前仍是问题描述；普通信用／coupler／结果暂存流水均是强对照 | 尚未给出具体新增机制和超过前作的有效差异 |

合理的增量论文不要求全部构件原创，也不要求在所有场景打败所有方案。可接受的研究目标包括：有意义新约束下的明确机制改进；或此前未建立、经因果验证且有适用边界的新结论。并非只有全新机制才可能发表。但简单组合、换到RISC-V/FPGA、实现已有功能、单例修bug或增加实验数量，本身不足以承担这里的论文创新主张。

当前欠缺的是具体差异：哪个真实场景、哪个旧办法在什么约束下付出什么代价、新增的机制或结论究竟改变什么。因而停止将目前这组表述当作已具备立项价值的机制候选；保留资料，不为维持这个想法持续改名或追加大实验。将来若有新的具体差异证据可重新评价，不等于整个领域没有空间。

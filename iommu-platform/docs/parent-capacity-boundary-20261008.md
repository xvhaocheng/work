# 请求槽必要性与下一项创新判别（2026-10-08，§34）

**结论：当前场景下，强固定方法每流一个译址后请求槽就够，不能拿八槽的原型成本为动态机制制造优势。** 1／2／4槽的六次新运行全部通过，输出CSV与对应启动顺序的旧8槽基准逐字节相同。动态最长前缀仍未确立独立主贡献；下一项应比较译址与分片的先后顺序，而不是继续增加动态规则。

Codex亲自设计容量判别、修改out实验副本、审查关键源并执行；DeepSeek整理接口证据，起草和修订汇总脚本，未执行实验。此次3个SV+C++模型构建成功、6次新仿真；2份8槽记录明确复用§33，不算新增实验。

## 这次改变了什么

沿用§33固定最多128拍的后译址分片及两侧真实W序匹配。两真实iDMA、同bank、普通S、每路32KiB、CONF1、源页偏移0／目的偏移3072、行为DDR读等待参数31；无CPU、预热、batch、强制反序或AW交错。两路iDMA数据FIFO合计48B，仍不是整个系统的缓存成本。

只独立缩小**已译址但原逻辑读尚未全部返回**的父请求保存槽：`parent_q / offset_q / returned_q`每流深度改成1／2／4；虚拟源关联数组、两侧AW序队列仍为8，iDMA在途额度8、TC队列也没有随之缩小。数组索引用`seq % ParentDepth`，准入用`pa-done < ParentDepth`，并保留容量／属性／连续偏移／原RLAST检查。

因此，本次不能写成“整个IOMMU只剩一个在途请求”或“所有队列都不需要8项”。[实际RTL](../out/parent-capacity-20261008/posttl_owner_fragment.sv)／[机械派生脚本](../out/parent-capacity-20261008/prepare.py)。

## 对原因和创新边界的判断

物理父槽保存与真正发数据读是分开的。当前控制器只选择两侧W队头owner和段序相符的流，只服务该流最老父；有一个物理子片在途。额外父槽能保存更多已译址请求，却不自动增加数据读并行度。这个源结构解释了为什么“更多保存槽”未必改变当前输出，但尚不足以证明所有映射、快路径和四DMA情形都无收益。

另一个关键限制是当前natural驱动明确`reset(false)`，拒绝S以外模式，也关闭分区。此次不是P／N／PN对比，不能用于解释历史PN退化；没有通过换一项命令就测到快路径。[驱动关键流程](../out/posttl-independent-20261008/natural_fragment_test.cpp:854)。

前作又补到更早的IOMMU直接证据：AMD于2009年公开的[US7480784B2，Fig.10](https://patents.google.com/patent/US7480784B2/en)描述了P2P设备流量、写译址miss及页表读取构成依赖环，并使用独立IOMMU虚拟通道。它并不是本平台的双W序匹配算法，却足以否定“首次发现IOMMU引入这种等待环”与“翻译开独立通道本身是新贡献”的宽泛表述。这是技术前史核对，不是专利法律判断。

所以，当前动态路线的独立立项否决保持；固定方法可继续作工程基线。单纯缩队列、固定／动态切burst、增加PTW优先或专用VC，都不能仅凭名字当新创新。

## 下一步主线：严格比较先分片与先译址

Codex提出下一项受控判别：保持真实iDMA的CONF1、原父256拍、两侧AW序、48B数据FIFO、每流1个父槽以及固定最多128拍服务规则相同，只改变分片在IOMMU之前还是之后。前置分片也必须恢复原ID／RLAST，不能再拿CONF0读写共同切分的结果直接比较。

拟比较三种方案：

1. **前置固定分片＋同owner准入**：两个128拍源请求分别进入IOMMU，按同样的真实W可消费条件服务；目的AW几何保持不变。
2. **后置固定分片**：保留一个256拍逻辑源译址，再按实际W顺序发两个物理子片；沿用本次1槽强基线。
3. **前置分片＋提前翻译准备**：若前两者有差异，再加入已有预翻译／准备队列能力作为更强普通对照，按总元数据和接口成本对齐，避免把它排除后虚构独占收益。

关键问题是：在源译址可以提前、数据暂时不能送出时，后置方法能否减少重复控制工作、隐藏等待，并在同总资源下改善两路完成时间及进度。**译址请求次数减少不等于IOTLB miss或PTW次数减少**：前置两片可能都命中同一缓存映射。必须分别记录TL请求／hit／miss／walk、两路NEXT→DONE与物理末W、队列占用和blocked原因；不能只用AR计数证明新机制。

这三项尚未实现／执行，当前不是新方案成功结果。先做最小合法对照，若更强普通准备也做到同样行为和成本，就停止把“放在译址之后”作为独立算法主贡献。只有剩余差异具有明确适用条件、真实收益或可证明约束，才值得扩展四DMA／MIG／实板与论文；仍不承诺二区。

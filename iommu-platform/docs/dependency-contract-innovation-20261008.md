# 继续创新探索：依赖信息、翻译寿命与写承诺（2026-10-08）

**目前仍未确认独立创新，但把下一问题收窄了：提前取得的翻译，何时值得保留、何时应释放、何时允许拷贝取得共享写顺序？** “只预约读尾部”“增加copy元数据”“先翻译再提交”各自都有强普通对照，不能直接作为新机制。它们是否能组合出更好的成本—吞吐点，需要明确接口与资源寿命，不能靠改名。

本报告继续多DMA共享IOMMU性能/成本主线。Codex亲自设计和裁决；DeepSeek整理证据、独立质疑及修订。完整任务、答案、纠正和来源见[资料导航](../out/dependency-contract-innovation-20261008/README.md)。

## 2. 一个原先被测试掩盖的接口代价

现测试把iDMA内部的job接受/完成、copy类型、源/目的地址和长度直接接给控制模块：`tests/nonblock_actual_dma_top.sv:638–646`。引擎当然知道自己在拷贝，但普通AXI-IOMMU消息没有定义这个copy关联合同；`include/axi-iommu/typedef.svh:37–81`的通用USER可以扩展，不能据此称接口不可表达。

因此，“同一DMA发出的R就是当前W的数据来源”不能从DID相同推出；有效字节区间也不能只用AXI len代替，iDMA内部还有offset/tailer。若使用这些信息，必须把连线、标记、校验和生存期计入实现成本。单纯把层次信号搬成wire是接口工程，尚非论文机制。

这是本轮源码核查得到的边界，没有证明任意AXI设备的普遍信息下界，也没有新RTL见证。

## 3. 为什么不直接做朴素成对准备

假设K个准备槽，每个copy要两份独立译址结果。如果K个copy各拿一份、不释放而等另一份，剩余槽为零，可能互相等待。**这是拟议结构的条件反例，不是现生产RTL新bug；这里槽是结果/在途合同容量，不是IOTLB ways或返回数据字节。**

普通方法已能处理：

| 普通方法 | 对这个槽反例的作用 | 须支付或确认的代价 |
|---|---|---|
| 原子预约一对 | 不产生持一份等另一份的状态 | 每在准备copy占两槽；冷端可能使预约长期闲置 |
| 给已有半对保留一个补齐槽 | 公平、有限服务和正确用途限制下可前进 | 新半对不能占逃生槽；仍需处理其它共享资源 |
| 仅让两端就绪copy进入ready队列 | 减少冷端提前取得写顺序 | 翻译就绪信息的可靠性、队列与重排约束 |
| 取消未提交准备、重做 | 可打破槽占用 | 重做walk的带宽、活锁/公平性和取消合同 |
| W数据齐备才提交AW | 提交后已有源数据 | 整写片段缓冲；必须比较AXI-REALM，不故意弱化 |

目的先行本身并不消除同质槽池中的互占；把“源先拿满”换成“目的先拿满”仍有同样反例。

Arm LTI还有两个更具体的约束：§6.2.1不允许已返回翻译的LC完成依赖另一笔Stall翻译的返回；§6.2.2要求使用该翻译的事务在发LC前已全球可观察。NoStall流另有合理时间/故障返回要求。因此不能将“物理AR/AW被接收”当作通用LTI或失效安全的结束点。现平台TC的COMPLETE在地址ready后回IDLE，名字相同不表示同一语义。

## 4. 下一候选：将“可丢弃的准备”和“真实在途承诺”分开

研究问题：**能否在有限准备状态和小返回缓冲下，保留非阻塞翻译的重叠机会，又不让一端冷翻译或长写等待占住另一端的映射合同？**

Codex提出以下可检查规格；未实现、未证明优于普通预取＋ready队列：

1. 从合法描述符取得首片段的src/dst、copy序号和有效区间。首判只处理对齐、静态映射、普通copy，不引入整job锁定。
2. 准备期仅预热缓存、保存可丢弃提示。提示不授权访存、不长期锁住可用物理译址或共享W所有权；缓存替换/失效后允许提示作废。
3. 真正发AW的第一拍VALID之前，选择一个符合顺序的copy，重新核src READ和dst WRITE的当前译址/权限，并确认其具体进度资源。复核miss则返回准备阶段；不能撤销已持有的AXI VALID或重试已接受的burst。
4. 只有两端检查和所需资源绑定完成，才交给正常数据路径。映射合同按实际体系结构保留至合法结束点；不能靠地址握手过早释放。
5. 下一片段可继续可丢弃准备；不会为了整job未来所有页长期占槽。公平性、反复替换后的重做、故障/失效/取消是必须明确的扩展，当前不声称解决。

需要找到的差异是**准备结果寿命、cache重做与W承诺之间的具体联合决策**。如果实现只等于普通预取＋双地址复核＋ready队列，就作为强工程基线，不为它新起算法名字。

允许每个原语已有前作，也不要求所有负载都胜。增量架构论文可以靠新的明确约束、机制组合和可信成本性能结果成立；但“普通机制可以表达”本身既不是首创证据，也不是已发表同款的证明。

## 5. 对现有平台和论文产出的判断

**可改性有，收益和创新仍待证。** iDMA描述符和legalizer已知两端地址，RTL可在AW首次VALID前调整准入；但生产IOMMU没有现成纯翻译准备接口，需要明确接口/取消/失效合同，不能称只改一个开关。Linux首判可沿用现有copy供给与静态映射；无须先做BIT或把故障恢复扩成另一条论文主线。

真实动机仍是§26：PN的62次FAST早于源读捕获1051/1052cycles，捕获后到DDR仅5cycles；首例被A的跨bank写所有权与目的写准备挡住。这说明有值得检查的后续约束。**它没有证明改变W准入就能消除PN的265cycle差，更不能把62次等待相加成可节省总时间。**

若路线成立，可交付三项贡献：

- 明确copy依赖、结果寿命、共享写顺序的进度边界，给合法可达见证及适用条件。
- 提出至少一个与强普通方法作出不同决定、且有代表性成本/吞吐优势的规则；不能只复现弱原型错误。
- 两真实DMA起步、再四DMA的RTL与实际资源结果，最终板端验证；包含负结果、退化条件与V/A综合指标。

这些是**待达到的贡献条件**，不是已完成论文成果。当前没有依据认定二区水平，主线也没有转向安全。

## 6. 下一次只做能判别的最小工作

先复用真实iDMA入口和已有模型，保持CONF0与当前PN任务形状；不先大矩阵或全量BIT：

- 普通当前W-head门：保留现基线。
- 强普通联合准备＋ready队列：不因冷端先取得W顺序；计全部新增结果槽、队列和payload。
- 可丢弃预取＋提交前复核：采用第4节规格，计重做walk、结果持有寿命、同容量并行深度。
- 写数据齐备后AW的普通方法：同分段、同工作量、计完整片段buffer成本。

先选择两种必要形状：一端热/另一端冷且争用写顺序；提前准备后被其它DMA替换，测试重做代价。代表性场景与真实轨迹还需核实，不能仅造不合法资源循环来赢。

**停止条件**：联合准备＋ready队列在同信息、资源和合同下同效同成本，则不推荐更复杂机制；可丢弃准备被重做成本完全吃掉则停止该实现；若当前PN提前翻译后的等待已能由简单安全门消除，就先固化它为基线，再找剩余缺口。并不要求证明一切普通算法都不可能做到。

上一D的独立R/W分段小判别仍未执行；本轮优先处理更贴近现CONF0动机的接口/寿命问题，不拿D解释PN。

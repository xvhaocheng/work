# 译址后分段候选 I：真实几何实验与创新门槛（2026-10-08，§30）

**本轮排除了一个预期收益场景，没有建立新的独立创新。** 真 iDMA 确实能产生“源一次读 2 KiB、目的两次各写 1 KiB”，但在本次普通路径中，两段目的写地址均早于源读就准备好了。因此候选 I 在这里会退化为现有独立长读，与普通方法没有优势。该负结果限制的是这个场景，不能外推为所有多 DMA 调度都没有空间。

## 1. Codex 本轮独立提出的机制位置

原 G 在源虚拟 AR 首次 VALID 前选长度。实际 idma_backend 已把 legalizer 的 AR 装入保持寄存器，此后不能依据晚到的目的进度修改长度。Codex 提出 I：保留已接收的原逻辑 AR，在**源翻译完成后、下游物理 AR 首次 VALID 前**选择片边界。

候选控制使用与这段源数据对应的、已经完成合法目的译址且具有实际写入顺序保证的范围。若整段目的都可推进，发长读；若只有前段有保证，先发前段，释放物理读服务后再处理后段。恢复上游原 ID、拍数及原 RLAST，不重复翻译同一原源请求。目的有效译址、虚拟 W 顺序和物理 W 顺序必须一起满足；不能把“PTE 命中”或瞬时 WREADY 当保证。

这只是机制规格，**I 未实现**。元数据取得与配对、故障及映射失效、原逻辑 R 未结束时的后续选择、进度证明与资源费用尚待解决。[Codex 先于本轮补丁任务保存的独立规格](../out/adaptive-fragment-witness-20261008/codex-rule-i.md)。

直接核的关键源码：

- [legalizer](../cva6/corev_apu/iDMA/src/idma_legalizer.sv:201)：共同边界与独立边界；读 AR 长度在此生成。
- [backend](../cva6/corev_apu/iDMA/src/idma_backend.sv:613)：AR 保持寄存器；AW 与写数据描述符另有队列。
- [frontend](../cva6/corev_apu/iDMA/src/frontends/register_64bit/idma_reg64_frontend.sv:367)：CONF 的 decouple 接至 decouple_rw。
- [TC](../cva6/corev_apu/riscv-iommu/rtl/transaction_controller/rv_iommu_trans_ctl_wrap.sv:628)：AW 优先，物理 AW 握手后可回 IDLE，不须等 WLAST 才处理下一地址。
- [banked ctl](../cva6/corev_apu/riscv-iommu/rtl/transaction_controller/rv_iommu_banked_ctl.sv:245)：虚拟写顺序与读准入的依赖。

## 2. 本轮实际执行

复用 §23 的生成模型及 archive，只编译、链接一个新的 C++ 实验驱动。生产源码与当前 tests 文件未改。新文件全部在 [本轮实验目录](../out/adaptive-fragment-witness-20261008/README.md)。

复用参数为 PolicyEnable=1、DmaBufferDepth=512、SharedPoolMode=0、SameBankDmasEnable=1、ReverseReadOrderEnable=1。**后两项来自旧诊断模型，不能把该模型说成未经诊断改造的完整生产配置。** 本轮只启动 V 一个 DMA，A 和另外 DMA 均静默，无待重排的另一 DMA 读，因此测量单 DMA 几何与本次时序；不能据此证明自然多 DMA 写序或生产等价。512 拍是普通大缓冲，不是资源节省实验。

两个独立冷启动调用：源 IOVA 0x10000000，目的 IOVA 0x10001c00，长度 2048 B。现有页表映射覆盖两个目的页。CONF=0 使用读写共同边界；CONF=1 使用独立边界。DDR 模型延迟 31，CPU/batch/预热均关闭。数据计数只取 comp 发起端口前缀 2 及目标地址，剔除 DS/PTW 和 CPU 读。

| 实际观测 | CONF=0：共同边界 | CONF=1：独立边界 |
|---|---:|---:|
| 源数据物理读 | 1024 B + 1024 B | 2048 B |
| 目的物理写 | 1024 B + 1024 B | 1024 B + 1024 B |
| 第一段目的 AW 握手周期 | 1013 | 1013 |
| 第二段目的 AW 握手周期 | 1456 | 1456 |
| 第一条源 AR 握手周期 | 1899 | 1899 |
| 第一拍源 R 周期 | 1931 | 1931 |
| 全局第 129 拍 R 周期 | 2090 | 2059 |
| 最后一拍源 R 周期 | 2217 | 2186 |
| 源 R / 目的 W 拍数 | 256 / 256 | 256 / 256 |
| 字节、未写区域、响应与排空检查 | PASS / exit 0 | PASS / exit 0 |

第二段目的 AW 比第一条源 AR 提前 **443 周期**，比第一拍源 R 提前 **475 周期**。本次并不存在“读已启动而后一段目的仍未译好”的冷场景。

独立长读的源最后一拍比共同分段早 31 周期。这是**已有 CONF 模式与简单 DDR 模型下的源返回终点差**，不是候选 I 的加速、完整拷贝延迟、系统吞吐或实板结果。该单 DMA 运行也没有观察多 DMA 的全局 W 顺序竞争。

两次运行均检查完整 2048 B 拷贝、源内容、目的页未写头尾及正常队列排空。Codex 另按原始 JSON 核每段 AR/AW 的地址、长度、总拍数与时序。完整命令、日志、模型哈希和模型使用限制保留在 [stage-evidence.json](../out/adaptive-fragment-witness-20261008/stage-evidence.json)。

## 3. 与最强前作的界线

| 前作或强对照 | 已覆盖的机制 | 候选必须证明的剩余差别 |
|---|---|---|
| [AXI-REALM，2025，III-A](https://arxiv.org/html/2501.10161v1) | 可配置粒度的透明拆分，恢复原 RLAST；写片完整缓冲后提交 AW | 同一复制的目的译址与具体写序是否能驱动片边界，并在计入元数据后降低成本 |
| [Preemptive VCs，2026，I/III](https://arxiv.org/html/2607.01430v1) | DMA 读写依赖死锁；分流、信用及可抢占 VC 的面积/时序比较 | IOMMU 具体依赖能否提供更小的局部合同，且不重复泛用 VC 贡献 |
| [CN114780466B，2022](https://patents.google.com/patent/CN114780466B/en) | 配合复制源/目的，提前排列多页首地址以触发 MMU 翻译 | 译址之后的物理读分段与目的写序合同，而不是“提前翻译目的页” |
| 固定译址后 AXI 分片 | 不重复原源翻译，也能透明恢复读事务 | 同等状态成本下，冷热依赖不同能否自动选择，并超过固定粒度的最佳配置 |
| 普通长读 + 精确尾部缓冲预约；共同边界分段；普通动态选片 | 安全缓冲或缩短读请求，动态选片可表达同一长度公式 | 不能只比弱整包预约；需要验证控制信息、接口位置与成本的实际差别 |

“普通逻辑也能写出同一公式”本身不是文献已经发表该方案的证明；普通器件可以实现新控制规则。反过来，给已有分片器增加一个输入、重新命名也不足以确立论文贡献。需要已有工作覆盖核查、真实区别场景及同资源结果共同支持。本轮尚未达到这三项。

## 4. 下一步主线与淘汰条件

主线保持**多 DMA 共享 IOMMU 的翻译干扰、进度约束和资源成本**。

下一步先核实际可达的多 DMA 写序依赖：同一 bank 的两个 DMA 持续供给、长拷贝和源/目的边界不同；记录虚拟 AW 顺序、物理 AW 顺序、原源读与目的可消费范围。必须使用与生产对应的 DMA ID/bank 关系，关闭旧 ReverseReadOrder/InterleaveAw 等诊断强制排序，不能把人为调度作为自然可达证据。不能拿本轮单 DMA 大缓冲结果代替这个检查。

进入 I 的 RTL 实现前必须找到两种实际状态：一类只有源读的前段可以安全推进，另一类整段都可推进。再与共同边界、精确尾部预约、固定译址后分片和普通动态选片进行相同总资源比较，计入标签、队列、缓冲及控制逻辑。

若原控制器已保证目的整段先准备好，或普通强方法以相同状态成本达到相同结果，就淘汰相应收益论证。若停滞发生在源翻译/AR 提交前，单独的译址后分片也不能被当成该停滞的修复。尚无新机制性能、面积或论文等级结论。

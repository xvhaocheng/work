# 从2026年7月开始的研究进度与目的

截至2026年10月14日，项目已从多DMA平台扩展、测量校准和干扰诊断，推进到首篇方法论文的立题与机制筛选。已经保留的成果包括可运行的FPGA平台、两类局部干扰的实板证据、普通基线和明确的负结果；当前还需要一个有实际用途、相对强普通方法有独立增量、完整收益与成本能够闭合的方法主张。

整体脉络是：**远端页表遍历的自身代价 → 多DMA共享翻译的跨设备代价 → 可信因果测量 → 改善方法与强基线比较 → 从具体失效中筛选论文贡献。**

## 最初目标与后续目的

原学位论文研究加速器侧IOMMU的Remote Page Walk：页表在远端时，一次翻译未命中会怎样拖慢DMA。FPGA环境用可控延迟分离页表读取和数据传输的影响，比较Pinned直接DMA与Bounce Buffer加CPU copy的端到端代价。这里的FPGA是评估环境，不能直接当成真实多Chiplet系统。

多DMA扩展增加了另一个问题：一个设备的翻译未命中，是否会替换另一个设备的翻译条目，或让另一个本来命中的设备等待共享服务。后续目标逐渐明确为：找到一个能改善有用任务完成、同时保留后台进度且成本合理的新方法，形成首篇论文。Chiplet是原背景，当前选题可以围绕共享翻译问题独立成立。

依据：[9月研究总览](../../研究总览_2026-09-08.md)、[原问题与当前问题](research-panorama-audit-20261011.md)。

## 九月的测量修复与局部因果证据

9月8日建立当前`iommu-platform/`，保留组件历史和个人补丁，加入锁定版本、隔离构建、交付哈希及定向验证。E0至E4从一开始就分别承担校准、慢化测量、缓存状态、共享等待和软件/数据路径核查。这样后续解释能够对应实际事件，而不只依赖吞吐或miss计数。

9月15至16日的上板过程先解决数据和执行正确性问题，包括CVA6的SC.W高半字节偏移、CPU缓存同步和Linux的IOVA转物理地址偏移。这些是实验基础修复，不能记为干扰改善收益。历史修复和验证入口见[交接记录](../../HANDOFF.md)及[验证记录](validation.md)。

## 十月初的缓解方法与强对照

10月3日的E2新版64项把“V预热驻留 → A替换V条目 → 探测前条目消失 → V首次再用miss”串起来。16项IOTLB中，V占2项，W7的A共占14项时保留V，W8共占16项时发生替换。W7/W8正向探测中位为696/1483周期。有限布局下的替换和首次再用代价因此有直接证据；这不自动等于稳态性能的全部归因。依据：[E2正式结果](../out/e2-results-review-20261003/RESULTS.md)。

实际占用计费方向先经过完整分组观测和462项方法实验，再用冻结的method88核强基线。两个启动、两个方向的四格中，固定A8、target170的p5对保护匹配强基线的相对增益均为负，约−4.44%至−8.24%。该版p5的独有收益主张被关闭，已经完成的控制器和负结果继续保留。依据：[method88](../out/method88-execution-20261004/RESULTS.md)。

P是容量分区，N是命中旁路，PN是两者组合。10月4至7日的原型和实板实验发现：组合不必比单独P更快。隔离替换历史后，P/PN的A miss差消失，PN仍慢约12.67%至12.79%。数据提前放行占用共享内存、反过来推迟页表服务，是行为模型中已验证的一条竞争链；它没有完整解释实板约12.7%的差额。同期修复DS写数据归属和PTW合法叶判断错误，属于必要功能维护。依据：[PN历史隔离及模型边界](composition-history-isolation-20261007.md)、[阶段交接](../../HANDOFF.md)。

10月7至9日进一步探索了分段、小缓冲、共享源读、在途加入、晚选目的和部分页表遍历。有些取得真实RTL功能验证，但部分收益被更强的普通提前准备或起点共享追平；一些新场景的需求没有与原COPY工作流建立连接。因此，10月10日前后的路线审查要求先明确真实问题、简单方法的具体失效和新增能力，再投入大实现。单个正例被追平只关闭该例的独有收益，不能证明整个方向无价值。依据：[路线审查](research-route-audit-20261009.md)。

## 十月十日以后的完整任务评价与需求筛选

stage97的M0改为共同就绪、双方各64次自然完成，并核对实际字节、B响应和排空。此前“V结束即停A”的窗口适合特定取舍评价，不能直接当成双方固定工作量的完整完成比较。

在该模型中，P/PN原FIFO服务的V完成为86594/90283周期；普通DS优先后均为76738周期，A也同为76164。3689周期差额被普通服务规则消除，因此关闭“必须新增逐copy门控来收回这项差额”的理由。DS优先仅在行为DDR模型中执行，尚无相应综合或实板收益。依据：[完整任务与历史裁决](research-panorama-audit-20261011.md)。

10月11至13日把候选放回有来源的工作任务：行预取、双缓冲流处理、AI/KV恢复及逐包交付。目的在于查清谁搬什么、何时需要、何时可以释放缓冲，以及合法大页、提前准备、驻留、批量、CPU和单DMA等方法为何不足。

- 行预取和固定双缓冲分支的主要收益被普通控制覆盖，相关有限分支结束。
- AI来源的有限R107恢复已经实板完成：恢复阶段1728次lookup全部hit、0walk；准备、换出、供给、校验和回收成本同时记录。这份all-ready有限卡归档，不据它否定所有AI或共享翻译场景。
- stage117在受控模型中完成真实CVA6缓存端口、CPU/DMA共享backing、包级所有权、metadata及consumer路径，并比较CPU/单DMA/双DMA的即时与整批交付六案。不同控制存在早期包与最后包的取舍，但未证明普通控制外具体可避免的共享翻译损失，未进入新方法阶段。

依据：[总计划](../../研究计划.md)、[R107实板普通恢复](r107-ordinary-pilot-20261012.md)、[逐包交付六案](stage117-delivery-g0-20261013.md)。GPU/AI是优先应用来源，实验平台继续沿用Genesys2、CVA6、四iDMA、RISC-V IOMMU及Linux；有限投影不当成原生GPU系统。

## 现在在分析什么

当前研究处于首篇方法论文的立题与贡献准入。10月13日的新授权允许先探索机制，再用有界合成微benchmark筛选，实际GPU/AI工作流验证后置。最初两项规则中，R1当前动作被普通方法覆盖，R2提前准备许可的成功动作可由普通控制表达；其完整成本问题随后被继续核查。依据：[机制续推](mechanism-continuation-20261013.md)。

10月14日进一步聚焦到：在共享服务的合法控制点，先发载荷数据读，或先让页表请求推进，会怎样经过写地址准备、真实读写及各自B响应，影响双方完整完成。需要同时核查控制点是否尚可改变、观察信息属于哪个存活任务、后续供给是否公平、普通规则是否已有同样动作，以及完整实现费用。

最新AW因果裁决纠正了一个关键跨端点推断：DMA源侧的写地址握手不等于后一级input接受；原有两槽AW spill能产生前瞻。因而旧“第二AR必等input AW接受与另一任务WLAST”的推断已撤回。新的完整收益仍缺原始配置/任务快照、有序供给、完整历史、共享R/W/B反馈、完整费用和相对冻结普通规则的完成差异，按准确缺项收束，未准入microbenchmark。未来AW包络及完整准入家族保留，原已关闭收益主张保持关闭。依据：[最新AW准备裁决](aw-barrier-causal-20261014.md)。

本回顾采用的当前状态原件保存在[读取时快照](../out/research-progress-from-july-20261014/current-status-at-review.md)。运行状态继续以[当前状态](../../CURRENT_STATUS.md)为准；本轮技术裁决或某个goal完成，都不表示论文完成。

## 未来推进取决于什么

当前source-only后继入口需要新的同源原始证据包，或明确增加合法能力的机制修订。它应解决当前缺项，不能只把相同纸面条件继续扩写。

如果一个合法新动作能够改变完整任务完成，或在同预算下给出完整成本优势，并且强普通控制不能覆盖这一点，就可以进入有限模型：冻结一个正例、相邻反例及两条留出，最多四条序列；随后核GPU/AI工作流中的真实共享翻译路径，实施一个最小原型，再做FPGA关键验证。

如果成功动作相同，但普通方法与候选的完整存储、端口、控制延迟和资源成本不同，可能形成成本或能力边界上的贡献；局部字段少几bit不能代替这种完整比较。如果普通方法覆盖实际需求，或新增成本吞没收益，就归档该具体候选，保留平台与证据，转向有新需求依据的邻近问题。

原约两周立题投入窗口继续累计。通过后的路线是最小原型、现有FPGA关键验证、论文证据与初稿；这些阶段各约1至2周是计划估计，不是已经完成或保证发表。依据：[研究方法](../../研究方法.md)、[总计划](../../研究计划.md)和[当前下一门](../out/aw-barrier-causal-20261014/next-goal-contract.json)。

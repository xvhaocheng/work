# stage117-r3：虚拟机间包交付来源裁决

C117R3 **准入一次有限 FPGA 普通基线，附明确的软件适配条件**。真实需求是把完整数据包交给接收方已经发布的缓冲区。允许 CPU 或一个 DMA 直接 A→B，原程序 A→host→B 的两次复制不能当作必须工作。现有 DEFAULT 非 batch 路径能表达精确地址和字节数，缺失的是有限实验的软件接口与接收消费逻辑。本轮没有实施、运行或性能结果；未进入 G0/G1，也没有提出新机制。root 的关键来源核查见[原文复核](../out/stage117-r3-astra-20261013/root-critical-source-review.json)。

## 唯一来源与必要搬运

冻结 DPDK v25.11，commit `ed957165eadbe60a47d5ec223578cdd1c13d0bd9`。唯一任务是 `examples/vhost/main.c` 的 `vm2vm=1` 本地单播分支：客体 A 的 TX 包按目的 MAC 送到客体 B 的 RX 队列。不是上一轮 dmafwd，不把文档的 PVP 回环测试或规定复制次数作为有用输出。[源码 main.c](https://github.com/DPDK/dpdk/blob/ed957165eadbe60a47d5ec223578cdd1c13d0bd9/examples/vhost/main.c#L1118)。

决定事实：接收方先把自有 mbuf 的地址、长度、WRITE 标志和 cookie 写入 descriptor；完成时按 used ID 找回**同一个原始 mbuf**。因此在两个既有缓冲区具有独立存储的情形，只换一个 host 指针或直接返回 A 的指针，不能使 B 在已发布地址读到包。完整包必须在 B 的缓冲区中可用。这不是声称 DMA 不可替代：CPU 直接复制完全满足需求。原文 S04/S05/S06 对应 `virtio_rxtx.c:285–321 / 173–204 / 991–1090`；[原始文件与逐字节来源](../out/stage117-r3-astra-20261013/source/file-manifest.json)。

原生 NIC 入站已按 VMDQ 对应目的客体，普通直接 RX 到 guest buffer 可能省掉后端中转。因此本轮没有用这条入站分支主张必要复制，最终冻结同一 vhost 来源中 A 客体内存→B 客体内存的真实本地分支。两客体及多 DMA channel 配置有源支持，但实际同时到达、backlog 与共同物理 IOMMU 未观察。GPU/AI仍优先；本轮未为标签新建运行时或恢复已关闭 AI 卡。

## 完整普通对照

- **直接 CPU A→B**：读源描述符/包头并选路，完整复制一次，构造 header，按顺序发布 used；不再读取 A 后才返回其完成，B 实际消费后再回收。只付 CPU 路径实际成本，不强加 DMA 的 cache/quiet 费用。
- **同 owner 单 DMA 直接 A→B**：后端合法映射 A/B 两个区间，逐真实 span 复制；全部完成、quiet及缓存所有权交接后，发布 used。一个 DMA 可服务双向队列。它是允许的普通改造对照，未声称 DPDK 源码已实现；A 的持有时间可能比原 staging 路径更长，须计成本。
- **原地、共享页、页借用/重映射、producer直接写入**：若实际合同允许则采用。页重映射必须保存 B 已发布地址/cookie、A 完成后的合法行为，以及同页邻接对象；需核真实页粒度、对齐、独占性和生命周期。不能只凭“不同 owner”排除它们，也不能为候选强加隔离。满足这些条件时，必要复制主张退出。
- **大页、预映射、驻留、批量、合并、布局、稳定池/暂存**：全部开放。源码本就要求异步客体内存预分配并锁页，支持多 virtqueue 共用 DMA。不能把旧映射屏障中的 S1 flush 每批照搬来制造冷翻译。

正确性相邻反例是：A→B 包尚未写入 B 原始 buffer 就发布 used，guest 会返回原来的 B cookie并读到旧字节。性能相邻反条件是：CPU/单DMA或合法大页、常驻、直接放置已满足任务，或剩余损失只是软件供给/全局交接。此时不能靠加小页、压力、期限或禁用普通方案制造新方法机会。[普通对照与具体成本](../out/stage117-r3-astra-20261013/ordinary-control-decision.json)。

## 现平台能保留什么

`idma_reg64_frontend.sv:325–327` 从寄存器取 length/src/dst，`:490–561` 的非 batch DEFAULT 接受非零长度并按真实完成退休。4096B batch和64B受控launcher限制不应套到这条普通路径。tracked `idma.c:939–956` 的 chunk整除4096与缺通用payload API是软件接口边界；原封不动的现有实验 ioctl 还不能接这张包任务卡。读写仍使用同一设备/PID并通过翻译，不能造一个读侧绕过开关。

后续只允许有界软件适配：有限包/descriptor输入、非 batch精确span执行、used/cookie生命周期与完整包consumer、checked drain/release。复用已接受的全局有限所有权规则：DMA阶段CPU不访问所持载荷；全部相关DMA静止后再做本平台cache交接、CPU消费与释放。**不声称已有逐槽CPU/DMA并发缓存协议。** 因而不需要新stream硬件、QEMU、完整virtio网络栈或图像/数值runtime。若实现发现这些成为必要，停止该投影并提交范围决定。

有限投影保留完整字节、源/目的生命周期、真实目的地址与容量、完成→used→consume依赖，以及真实4 iDMA→共同IOMMU路径；删去原生虚拟化隔离、NIC、eventfd/中断、真实guest并发运行和原生时序。软件两个owner只代表生命周期，不冒称安全域。全局DMA阶段也删去原生流式重叠，可能消除性能机会，必须让普通基线真实裁决。[适配边界](../out/stage117-r3-astra-20261013/finite-adaptation-contract.json)／[需求接口卡](../out/stage117-r3-astra-20261013/demand-interface-card.json)。

## 字节、资源与判定门槛

对接受包集 P，`L_i` 为完整 Ethernet frame长度，`H` 为协商 virtio header长度。有效包字节是 `ΣL_i`，接收记录占 `L_i+H`。原 staging 路径载荷读写各 `2ΣL_i`；直接普通路径各 `ΣL_i`。header/descriptor/used、输入准备、consumer读、cache、页表、供给和释放另计，不能从DMA总线字节推出应用收益。

source burst上限32、descriptor vector上限256、async vector上限2048、DMA descriptor请求`min(4096,设备上限)`；这些是容量边界，不是实际包数/到达。源默认147456个host mbuf可配置，不是有限FPGA任务必须分配的数量。未来有限输入与实际资源须先冻结；不得为压力把包补齐到64/4096B或强凑旧64笔。实际N、L、RAM、leaf、时序与收益均保留null。完整成本含prepare、供给、consumer、校验、排空、转换、释放及软件适配。逐字节比较、guard检查与trace属于观测开销，单列时间与访问量；不能冒充源应用本身必须执行的计算，也不从实际总成本中隐藏。[全部成本](../out/stage117-r3-astra-20261013/bytes-resources-costs.json)。

安全合同可表达不等于本轮已验证安全；来源任务成立不等于翻译瓶颈成立；直接copy合并本身属于普通方法，不能作为独立创新。如果后续公平普通基线中出现具体可达、可避免翻译残余，才进入G0；G0支持后才设计G1方法。原生requester、启用共同IOMMU、原生速度和FPGA收益均未知。

# 共有 IOMMU の干渉実験：計画と v1 設計

## 目的

複数の DMA が一つの IOMMU を共有する際に、背景負荷のアドレス変換が測定対象の処理時間や変換状態に与える影響を調べる。

## 実験計画

| 段階 | 検証内容 |
| --- | --- |
| E0：計測の校正 | 計時、デバイス別カウンタ、負荷の強さを確認 |
| E1：性能評価 | 単独実行と同時実行で Victim の完了時間を比較 |
| E2：変換状態 | Aggressor の処理終了後に Victim のキャッシュ状態への影響を確認 |
| E3：リクエスト阻塞 | Aggressor の変換ミスが Victim の進行を妨げるか検証 |
| E4：対照実験 | データ転送経路の競合や CPU の処理負荷の影響を切り分け |

性能低下だけで、キャッシュ容量不足や HOL ブロッキングが原因だとは判断しない。

## v1 の設計

測定対象を **Victim（V）**、背景負荷を **Aggressor（A）** とする二つの DMA によるメモリコピー実験。

| 項目 | Victim | Aggressor |
| --- | --- | --- |
| 使用領域 | コピー元・先の各 1 ページ | コピー元・先の各 W ページ |
| アクセス | 固定したページ対を反復 | ページ 0〜W−1 を順番に巡回 |
| ページ／コピー単位 | 4 KiB／4 KiB | 4 KiB／4 KiB |
| 終了条件 | 固定回数のコピー完了 | V の測定終了後に追加投入を停止 |

初期試行では単独実行と W＝1、8、32 の同時実行を比較する。V は 4,096 回、計 16 MiB のコピーを候補とするが、使用領域は計 2 ページ。正式な条件は校正後に決定する。

### 実行・測定方法

- 一つの CPU が両 DMA を管理し、各 DMA の完了確認後に次のコピーを投入する。
- ウォームアップ後、V の最初の投入直前から最後の完了確認までを計測する。A はウォームアップ中と測定中に継続して投入する。
- 測定時間には CPU の投入・確認処理を含み、A の残りの処理の完了待ちは含めない。
- V の完了時間、デバイス別の変換ミス／ページテーブルウォークのカウンタ、A の処理量・投入間隔を記録する。

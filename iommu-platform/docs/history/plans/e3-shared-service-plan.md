## 问题与竞争解释

主问题：V的请求已经被TR接收，但A的页表遍历占用当前翻译服务时，V是否必须等A释放后才能获得服务？区分三种情况：

- V主要在控制器选中前排队，等待另一个A请求。
- V已经被选中，自己的翻译/上下文处理耗时增加。
- 前项已译完，却占着内部出队位置或其他资源，造成后项等待。

静态RTL提供观察落点，不是实测结论：`rv_iommu_trans_ctl_wrap.sv:579`为AW优先的请求选择，`:627`提出翻译请求，`:646`等待响应，`:669`在内部译后地址被接收后才弹出队头。观察到外部stage2=0并不替代这些内部事件。

## 第一项实施：一次构建同时带观测和可关闭干预

保留DS50/50、V0/A1、硬件批量及整批轮询、4KiB拷贝；主要条件A8。扩展现有observer/MMIO和Linux读出，不增加全量trace平台，不改DMA仲裁或转中断。

1. 对同一请求记录TR接收、控制器选中、翻译请求握手、翻译响应握手、COMP首次VALID，分出排队/请求提交/翻译服务/出队。这里“翻译服务”是请求握手至响应握手的接口内经过时间，仍含上下文处理和内部缓冲，不是纯PTW时间。以源AXI ID、读写和同ID序号匹配，附DID/IOVA；仅DID/IOVA不够，因为地址重复。保留原v3四段及错误/窗口守恒检查。
2. 锁存每请求**首次**IOTLB查询结果、当前PTW归属和控制器状态。`rv_iommu_tl_wrap.sv:1088`的PT状态会持续查询，miss后PTW填入也会hit，不能记录最终hit来冒充初始命中。
3. 保存一组有界事件记录：选中的A请求、已排队的目标V（优先V读请求）、干预触发/释放、A结束和V获服务/返回时刻，以及是否有其他请求插入。聚合计数不足以证明它们是同一对请求。
4. 在PTW专属R返回分支增加单项响应缓冲，运行时`D=0/128周期`（128周期=2.56µs），每个V窗口最多触发一次。触发要求：当前正常翻译属于A、首次查询miss、目标V已经排队、接收到目标A的一笔PTE响应。两种D使用同一硬件和触发规则，记录PTE级次、请求序号、实际额外保持周期及释放握手；D=0也保存事件，不能只记录干预组。

PTW支路在`rv_iommu_tl_wrap.sv:567`独立，DDTW/PDTW在`rv_iommu_ds_if.sv:77`附近才汇合；应在专属分支选择A，保持既有全局DS延迟不变。PTW AXI ID固定0（`rv_iommu_ptw.sv:274`），不能用它判断源DMA，必须锁存当前翻译请求归属。排除隐式目录遍历/S2/MSI等非本实验路径。

响应缓冲必须遵守AXI：先正确捕获完整R载荷，计时后稳定提供给PTW直到消费，不能撤销已提出的VALID、丢失/重放响应，不能无意阻塞其他DS分支。D=0/128均走相同缓冲结构，公共固定延迟单独记录；“配置128”不能代替实测保持128周期。

写后段同步保留一个必要边界：对应V AW握手、WLAST握手、B握手，全部取同一COMP接口，以该接口AW顺序归属写数据（W本身无ID），不混拼TR侧事件。借此区分W供给较晚与WLAST后等待；WLAST前也可能包含下游W反压，不能直接称CPU/DMA供给瓶颈。若W在AW前已传送，以有界暂存记录先到事件，显式记录先后，不用无符号负时差拼阶段；暂存溢出须报无效。这只为解释既有写stage3增量，不另加参数矩阵。

涉及事务控制器、translation wrapper、PTW分支、IOMMU顶层/FPGA连线、observer和Linux配置/读出。新硬件版本及对应软件必须精确匹配，需新BIT和启动软件。上述字段已实现于v4及新配对命令，旧BIT/旧命令不具备本轮控制。

## 同一映射内做对照

当前每次ioctl重新准备/释放映射，不能宣称两次命令保持同一物理布局。新增最小成对会话：一次分配/映射，两个子轮分别预热、运行、冻结观测、完整排空/校验；仅切换D，子轮间重新初始化必要软件数据并执行既有缓存同步。HPM窗口和事件记录分别保存；错误停止并遵守原quarantine规则。

相同映射不保证相同IOTLB内容、替换状态或排队顺序。必须记录实际首次hit/miss、A PTW及PTE级次、触发时V队列位置和中间插入的请求。无触发、V首次miss、不同顺序、超时或错误样本全部保留并分层，不能丢掉后补采，不能为了得到预期结果无限重试。

## 验证和最小采样量

先做定向RTL/驱动验证：多笔同ID、首次查询只记录一次、归属和同拍边界、D=0/128精确延迟、只触发一次、未触发、R反压/稳定性、复位/超时、安全排空、成对映射生命周期。一次完整构建后，在FPGA做重复短Solo、A1控制和A8触发短验收；成功日志仍仅保存，有报错才查。

正式只做**10对A8**，每对D=0与128各一次，交替对子顺序（共20个子轮）；沿用4096项/warmup256作为触发机会窗口，不以整批吞吐变化作本试验主要指标。另做2对A1开关对照，预热后无目标PTW时预期触发数0。Solo只作新增接口/事件基本验收。无需重新采完整Solo/A1/A8性能矩阵或DS回切。

主比较单位是被关联的目标V请求。配对必须报告实际映射一致性、触发/顺序是否相符和可比较对子数；10对不保证10个有效因果对子。若触发稀少或请求顺序无法匹配，先报告具体缺口，再设计有限请求/硬件相位控制，不静默扩样。

## 判据与后续分支

| 观测 | 可支持的结论/动作 |
|---|---|
| A的PTW响应确实额外保持128周期；V已排队、不能获服务；释放后A完成，V才继续；匹配对子中主要增加V服务前等待，V首次hit且自身服务近似不变 | 支持该A PTW响应对该V获服务时刻的因果依赖，可寻找服务解耦或任务准入的控制点 |
| 增量主要在V自己的翻译服务，或V首次miss | 优先解释自身上下文/翻译处理；只有证据要求检查持久翻译状态时才进入E2 |
| 增量出现在前项COMPLETE/内部出队 | 转向对应内部出口或资源持有的对照，不能称纯PTW等待 |
| WLAST显著后移而WLAST后等待基本不变 | 与写数据更晚可用/传输相符；结合W反压及关联读请求继续区分 |
| 没有触发、序列不匹配、只有整批时间变化或只有相关性 | 不作机制确认，明确还缺的请求/相位证据 |

不要求每个V等待差精确等于128：其他请求插入、自然背压及触发前历史都可能改变差值；应报告事件顺序、实际保持和对应分段差，不能将不匹配对子硬作相减。也不能用一次128周期干预解释原47.76ms的全部损失。

若依赖成立，可说“延长具体A的PTW响应使已排队V更晚获得服务”。要进一步称HOL，还需证明阻塞当时V的条目/权限有效以及本可服务却不能绕过的约束；V后来首次查询hit不单独证明这一反事实。先完成较小的因果问题，随后选一项方法及直接基线，不为HOL标签扩充本轮。

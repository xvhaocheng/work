# E4 首轮：DMA 供给与完成观察实验卡

实施更新：用户确认保留轮询后，观测模块/驱动已实现，定向回归及独立软件/FPGA构建通过，交付后已完成105次上板试次及服务器复核，见 [E4结果复核](e4-results-review.md)。实际接口和交付状态以 [E4被动观测](../E4_OBSERVER.md) 为准；下文保留实施前实验设计。

日期：2026-09-16。承接 [E1 复核](e1-results-review.md)。下文是实施前确定的实验方案；当前实现与交付状态以上面的入口为准。当前 E1 的约73%～79%共跑慢化成立于软件计时口径；本实验先解释它出现在哪段时间，不预设原因。

## 1. 首先回答一个问题

V 变慢时，是一个已经提交的 DMA 任务在硬件里停留更久，还是硬件早已完成、软件过一段时间才读取完成状态并提交下一次？同时确认两路 AXI 请求实际重叠到什么程度。

固定现有缓存同步、正确性校验、单路未确认完成描述符上限、HPM及DS50/50。当前不增加队列深度，不改变请求供给方式；先观察现状，避免同时改变测量对象。

## 2. 用同一硬件时钟划分三段

| 段 | 起点 → 终点 | 能解释什么 |
|---|---|---|
| H：已发出任务的硬件经过时间 | DMA前端为该任务分配ID → 该ID实际完成退休 | 包括前端、内部排队、翻译和数据搬运，不能单称IOMMU时间 |
| P：完成后等待读取 | 该ID完成退休 → 第一次被接受且返回该完成ID的DONE读取 | 硬件完成到完成状态读取之间的间隔，是软件晚观察的直接线索 |
| R：读取完成后等待下一次提交 | 上述DONE读取 → 下一个V任务分配ID | 软件继续执行及配置/提交通路的间隔 |

前端分配ID与CPU进入提交函数不是同一个边界。DONE读取事件取外设寄存器响应被接受的时刻，并核对返回ID；它也不等于CPU已执行完比较、统计的时刻。因此P称为“完成到寄存器读取”，不冒称精确的CPU发现延迟。

对N个被测V任务，记录N段H、N段P、N−1段R及各自总和/最大值。窗口从首个被测任务分配ID到末个任务对应的DONE读取；三段总和应严格等于该硬件窗口。原软件 `victim_elapsed_ns` 继续保存，其首尾还包含不同的提交/返回路径，不直接相减后给残差贴CPU标签。已有 `active_cycles` 继续作为backend非idle累加，与H不是同一指标。

阶段边界全部被动观察已有信号和寄存器访问，热循环中不添加逐描述符读计时寄存器或打印。新测量窗口在预热完成后由驱动一次性ARM，下一次V任务分配ID才开始计数；硬件按设定N及ID序列自动结束，末次DONE读取完成后冻结。安全排空后读取固定结果。这样排除ARM、读取结果、校验与串口输出的时间，且不会把最后一次任务之后的等待计入R。

## 3. AXI 重叠观测

在DMA0/1到外部mux之前分别观察AR/AW提出和握手、RLAST/B返回握手；同时观察mux到IOMMU公共入口的地址握手及等待。读、写在途数量分开维护，R只在RLAST握手时退休，B只在B握手时退休。单个软件描述符可拆出多个AXI请求，不能用一个busy位或一个布尔在途位代替。

四种状态的周期数为：仅V存在地址请求/在途事务、仅A存在、两者同时存在、两者都不存在。额外保存每路AR/AW等待受理周期和请求/完成数。统计口径包含尚未握手的地址VALID；如果只数已握手事务，会漏掉被挡在入口的请求。

在途跟踪从运行前持续维护，ARM时仅重置窗口累计，不清除真实在途状态；A可能跨越预热边界。冻结窗口后不再累计，实际请求仍照常排空。越界/下溢、ID归属异常、未完成目标数量、异常终止都将结果标为无效，不能显示成零等待。两路同时在途说明存在重叠机会，仍不独自证明在某个共享队列竞争，更不证明HOL。

## 4. 适合现有 Mac 工作流的读取方式

本轮优先用Linux可读的少量汇总寄存器。现有Mac流程能下载BIT和保存串口，但没有已经验证的ILA读取流程；因此不把安装新的本地Vivado/虚拟机作为前置。

实现范围限定为一个被动观测模块、必要信号连接和窄的寄存器读出入口。拟使用“标识/版本、控制、结果索引、结果数据、状态”接口；寄存器偏移在实施时与现有解码核对。当前前端仅按低7位解码，已有0x50 active寄存器，不能随意使用0x100之类地址导致旧控制寄存器别名。读出模块不得给正常DMA/AXI流量新增背压。

驱动只在测量边界做ARM，在安全排空后读取结果；不改既有RUN ioctl布局，不占用要求为零的reserved字段。第一版可将冻结汇总按单次调用输出一条带序号、V/A身份、有效标志的内核诊断记录，由现有串口运行器与该次JSON一起保存。输出在计时窗外。若日志配对或长度实际不可用，再选专用只读查询，不能先把静默ABI变更混入旧结构。

只接受精确的硬件观测标识和版本；旧BIT上的普通E1仍可运行，但本实验缺观测时必须报“不可用”，不返回伪零值。停止/错误时保留原排空和quarantine规则，观测控制不能取消DMA。

## 5. 代码落点与一个已发现的供给限制

- `cva6/corev_apu/iDMA/src/frontends/register_64bit/idma_reg64_frontend.sv`：`issue`、`trans_complete`、`done_id`和DONE响应边界，是H/P/R事件来源；保留功能状态机不变。
- `cva6/corev_apu/iDMA/src/systems/cva6_reg/dma_core_wrap.sv`：1D frontend与backend/FIFO连接；需将只读观测信号接出。
- `cva6/corev_apu/fpga/src/ariane_peripherals_xilinx.sv`：`axi_dma_tr_req/resp[0:1]`及`axi_iommu_tr_req/resp`为外部mux两侧观测点，四DMA拓扑保持。
- `linux/drivers/misc/idma.c`：预热结束后的测量入口及最终安全排空点接ARM/读取，正常热循环保持原次序。

前端实际为IDLE→COUNT→WAIT，WAIT等待`trans_complete_i`后才回IDLE；配置的8项job FIFO不能直接当作8个独立任务的可用提交队列。若后续证明供给不足，应另行评估最小自主循环/提交改动，并验证完成ID、读写顺序、停止与排空；本轮不先改它。旧benchmark中的特殊模式也不是本轮可直接复用的已验证接口。

## 6. 构建和上板顺序

1. 先完成被动观测模块的定向RTL回归，覆盖背压、读写同周期、多AXI事务、返回ID、计数溢出/下溢、预热时A已在途、末个DONE冻结、失败中止和角色交换。用可控的硬件完成/寄存器读取间隔验证H/P/R精确分解，并断言开启观测不改变功能请求/响应。补驱动边界回归，不要求新建完整IOMMU仿真系统。
2. 单独建立观测构建profile，保留DS50/50、SC.W修复和缓存同步软件；保留旧BIT/软件/E1样本。构建新BIT及软件，审查新增时序影响、产物标识和原有约束警告，构建成功不作板上通过。
3. Mac沿用BIT下载、SD软件更新、串口保存流程。新版本先做针对性的短试次/新观测校准和数据正确性验收；这是新产物验收，不重新宣称旧E1尚未完成。
4. 同一新BIT/软件下比较观测关闭与开启，先行3条件×2角色×2开关×3重复，共36个观测开销样本。固定V工作、预热和配对顺序，检查是否改变原有现象。建议以配对中位数变化1%作为分析门槛（小于本轮A8/A1约3.5%～3.9%的差异），超过则先分析；这不是显著性检验或板上逻辑正确性的替代。静态加入逻辑的布局变化另与旧E1交代，不能由开关对照消除。
5. 校准通过后，主矩阵固定Solo/A1/A8 × DMA0/1角色 ×10次，共60条；参数沿用V4096、预热256、4KiB chunk。轮转条件顺序、交替角色，保存每次原JSON、硬件汇总、版本与退出状态。故障即停；不追加样本寻找期待结论。计时/HPM仍使用各自定义的窗口，不把A跨界完成量当作精确字节流量。

## 7. 结果如何决定后续工作

| 新观测 | 支持的解释 | 后续动作 |
|---|---|---|
| H基本不变，增加主要出现在P/R；请求重叠少 | 当前供给/完成读取方式限制了观察到的系统性能 | 先改最小供给方式并重新校准压力，再测IOMMU机制 |
| H增加，且V请求到达后等待增加 | 存在硬件路径中的额外等待 | 用E3/E4内部边界进一步定位；不直接称HOL |
| H与P/R都增加 | 软件供给与硬件路径混合影响 | 分别报告，设计匹配对照，不简单归为一种机制 |
| 数据/计数/窗口恒等式不成立 | 观测尚未校准 | 修观测并保留失败，暂不解释性能 |

E2仍按同映射生命周期的“V预热→A有限访问→排空→首次探测”检验持续翻译状态影响；当前V主样本miss为零使它不是解释这组大幅慢化的首要证据。E3需进一步识别请求、命中状态、PTW与出口等待，以上边界汇总不能单独满足它。DS0/0正式基线、S2/IRQ校准及时钟/CDC/IO待办继续按各自用途推进。

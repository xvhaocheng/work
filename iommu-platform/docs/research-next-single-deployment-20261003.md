# 下一轮：减少SD镜像更换，分阶段收集成套论文证据

2026-10-03。DeepSeek起草同包阶段与对照，Codex审定研究路线、控制边界和实验取舍。当前为研究计划，方法原型及下列新模式尚未实现、编译或上板；精确运行矩阵须在交付前冻结。

**2026-10-03 最新部署约束（优先于下文早先的同包要求）：** 用户明确真正麻烦的是Linux镜像更新后，需要把SD卡从FPGA取出、插到Mac拷贝，再插回FPGA。BIT可以经JTAG更新，不需要动SD卡。因此优先减少Linux/payload重新制作与SD拷贝次数；不强求E2和方法M同时完成或塞进同一个BIT。软件接口尽量一次准备充分，硬件可分版本推进。

软件共用的前提是寄存器/UAPI、设备树、驱动与实验工具兼容；已有00092不能未经核查就承诺支持未来控制器。先冻结必要接口、版本/能力识别及软件支持，再构建所需镜像；之后兼容的BIT迭代可只走JTAG并按流程重新启动、重新准备实验初态。不将BIT更新描述为保留运行中Linux状态的热切换。确需不兼容软件改动时才另交付镜像，不承诺永不重编Linux。

E2扩展保留为独立工作包：准备顺利可同期推进，若需要额外计时/布局接口或拖慢M，则分开交付BIT，不勉强捆绑。方法与其直接性能基线仍优先在同一个方法BIT内切换，保持公平；E2可以使用另一兼容BIT，记录各自版本/启动，不跨BIT伪配对。

**最新接受的交付形式：一份共用Linux＋两份兼容BIT＋Mac端顺序执行流程。** 用户明确可以在一次上板工作中准备两个BIT轮流执行，交给Mac端AI完成，不需要为切换实验人工制作SD卡。优先兼容现有SD镜像；若必要软件支持缺失，交付前集中解决并明确是否仍需一次镜像更新，不能未经验证承诺现有00092直接可用。两份BIT分别承载E2扩展与M/公平基线，不以“两份”推断两个实现已完成。

Mac流程应为：核对文件及软件兼容性→加载第一份BIT→启动并核对Linux/硬件身份→短验收与对应实验→保存并确认结果已收集到Mac→停止实验并按板卡流程准备重新配置→经JTAG加载第二份BIT→重新启动/核对身份→短验收与另一组实验→归档两段结果。两段各有BIT哈希、Linux版本、启动标识、用例清单和独立目录。JTAG/启动/版本或正确性错误停止，不自动重跑或切到下一组；方法无优势按预定规则继续收集。脚本/交接须让Mac端AI执行，不假定Dell连接FPGA，不执行格式化/擦写SD。跨BIT自动切换是待实现和验收的交付要求，不是当前已有能力或保持Linux运行态的热切换。

## 2. 真正待回答的创新问题

**在给V相近保护效果时，按A实际占用翻译控制器的时间限流，能否让A比简单方法完成更多有效工作？**

“实际占用”仅指A归属的REQ_TRANS/AWAIT_RESP周期，不等于所有IOMMU压力或V因果损失。A1的主占用仅20周期，V仍约149.55 MiB/s，而Solo约283.05；这提醒我们保留不能由窄计费解释的条件。

[SafeSU §III](https://people.ac.upc.es/jabella/ETS21.pdf)已有请求时长观测及按参考事件成本消耗时间额度；[AXI-REALM](https://arxiv.org/html/2501.10161v1)已有按周期补给、按传输量消耗的硬件预算。因此不能把时间计费、令牌桶或硬件限流本身作为创新。

候选贡献是：明确计数控制不足的条件，给出具体可执行的实占计费准入方法，并证明其在公平保护条件下的额外收益及适用边界。三个部分缺一不能宣布方法创新成立。当前H-M0仅获得简单计数层面的支持，H-M1（控制收益）仍未测试；训练内类型拟合好坏都不能独自裁决H-M1。

## 3. 同一次上板准备的六组有用实验

方法M及其直接性能对照目标是在一个方法BIT内通过运行时参数切换；E2无需放入同一BIT。校准与正式采集分目录。工作集为A循环使用的源/目的页数量；V保护强度表示要求V至少保持多少搬运速度。下表是方法评价需要准备的内容，尚不是可执行清单。

|实验组|具体比较或变化|为论文回答的问题|
|---|---|---|
|① 主方法比较|同版Solo、无节流、固定gap、计数计费、实占计费M、只根据V速度调节的简单反馈；A8作为核心条件|M是否比简单办法更有用？|
|② 保护强度取舍|在板前限定的候选目标中，按冻结规则校准宽松/中等/较强三个可行保护档；同时记录V与同窗口A|收益是否只存在于一个恰好有利的目标？保护V要牺牲多少A？|
|③ 工作集与反例|A1/A8/A16，V保持规定负载；保留A1低翻译占用但明显共跑减速、A16偶发V miss的条件|方法适用于哪种竞争，在哪些条件下收益有限或失效？|
|④ 计费依据对照|保持外层控制规则和合法放行边界，只替换字节/请求/miss/实际周期；可观测类型审查通过才加入固定类型权重；核心条件加滞后占用对照|收益来自实际占用信息，还是仅仅“加了反馈/限流”？及时性是否有用？|
|⑤ 未参与调参的验证|板前预声明另一组合法地址布局/访问顺序/启动相位；校准后冻结参数，不看验证结果回调|结果能否离开调参条件仍成立？当前A1/A8/A16已观察过，不能伪称全新发现集|
|⑥ 开销与稳定性|同BIT关闭策略/只观测/启用策略的执行代价；保留预算、限流周期、V短窗进度、最长观测停顿、A尾部和错误；资源/时序来自构建报告|是否靠过大开销、A几乎停工或偶然相位换取结果？|

这些不是六个完整笛卡尔积。核心A8覆盖主方法与三个保护档；A1/A16覆盖预定代表目标；计费/滞后对照集中在核心条件；独立验证覆盖冻结的M与各基线校准赢家；稳定性选代表点。具体每个“点”与重复数必须板前形成总表和预计耗时，不能靠现场随意追加。

字节和请求在固定4KiB、每copy四次请求下可能成比例：若确认控制行为等价，记录为等价设置，不用重复试验冒充两项独立优势。单纯miss为零时的行为须定义，不能静默变成失控或隐含常数计费。类型权重基线不得凭当前req/miss相同而被排除。

布局/顺序/相位的接口须先核查和测试；当前不声称具备batch中动态改变工作集的生成器。必要变体随本包实现，避免把未知接口留到上板后。先不把真实应用、多租户扩展、非阻塞新架构等所有方向同时塞入这一包。

## 4. 同包自动执行的阶段与停止规则

1. **主机准备完成再交付：**冻结模式、寄存器、计账/排空契约、测试总表、候选参数、校准算法、验证集、比较容差与工程意义门限；逐模式做主机/RTL检查，完整构建。正常构建日志保存，不反复查看。
2. **板上短验收：**每模式最小用例检查正确性、计数、状态切换和关窗；成功才进入下一阶段。
3. **有限校准：**只运行预先列出的候选参数，给各方法相同调参机会；各计费单位分别定标，不强制同数值额度。确定性规则选择参数，保存配置及哈希，无需一次次手工回传调参。
4. **正式比较与六组证据：**用冻结参数和交错顺序运行预定实验。先完成核心比较，再执行扩展/反例；不是看到好结果才决定是否做反例。
5. **独立验证与归档：**验证条件在上板前已确定且未参与校准；完整保存原始JSON、UART、版本、参数、失败、未运行项和阶段标识。每阶段落盘，避免末尾失败丢掉前面结果。

硬件/数据/计数协议错误：停止整套后续动作，保留现场，不自动重跑或剔除。**科学阴性（M不如基线、某个目标达不到）不是程序错误**：记录失败目标或不满足匹配，继续完成事前规定且安全的独立用例。不能因方法输了而停止收集反例。

若校准未找到匹配参数，按预设规则标记不可比/目标不可达；不现场放大搜索、不用验证集反调参数。允许其余不依赖该失败校准的预定实验继续；不能将缺失结果当通过。

## 5. 公平比较与不可改坏的边界

- 同BIT、时钟、仪器、负载和下一完整copy放行边界。比较重点是在V固定工作完成时间及短时保护满足冻结容差时，A在同一V硬件窗口内完成的有效字节率；不以A整轮吞吐替代。
- 计费消融共享外层控制器。V-only简单反馈是独立强基线，共享作动边界但不强迫其采用M同一算法。固定gap也有自己的校准机会。
- M沿用[已审控制合同](paper-logic.md)：A归属REQ_TRANS/AWAIT_RESP逐周期扣费、欠账保留、窗末按旧预算补给、下窗反馈更新；仅在上一完整搬运排空且下一请求尚未提出时作准入决定。不能误改为“完成后才一次性扣实际周期”。首份也准入，V起止不免债。
- 反馈采用V成功数据完成字节及可信活动生命周期；全活动窗零完成仍参与，部分活动窗规则固定。参数位宽、溢出、CDC、owner归属和排空证明属于新实现验收，不能用旧观察器通过代替。
- 关闭策略的同BIT对照可测运行代价，但不能单独证明新增硬件的面积/频率代价；后者须提供与固定来源基准的资源/时序比较，不为此默认要求额外上板。
- 各run或配对轮次是重复单位；同一run内窗口不是独立重复。保留重启/采集段标识。已有旧60或旧21不混入新方法正式重复。

## 6. 下一步执行准备与完成判据

先完成软件与两份候选BIT的兼容接口核查，冻结各工作包小范围实现规格及“用例—模式—参数—重复—目的—预计耗时”总表，再实现、验证和必要构建。软件需要更新时集中制作镜像；兼容的硬件后续单独构建BIT。最终交付两份BIT、共用软件版本说明、各实验入口及Mac端AI顺序换BIT/启动/收集结果的执行流程；在各自实验前设置身份与兼容性检查。不能现在虚构精确试次数或承诺未测模式已经可运行。

核心判断：若M在多个冻结保护目标和独立条件上，以可接受开销保留更多A工作，才推进方法贡献；若强基线同样好或更好，保留所有结果并收缩/撤回该方法主张。证据不足保持未决，置信区间跨零不是等价证明。旧E2/E3机制事实不因此消失。

目标是这次上板尽量同时回答“有没有用、为什么有用、在哪里有用、代价是什么”，而不是仅增加重复次数。一次部署能否完成全部仍取决于实施验收与板上正确性，但不将本可预先准备的对照留到下一次。

## 7. 2026-10-03 补充：E2 与改善方法同次上板推进

本节原按用户询问规划E2同期推进。用户随后澄清可接受JTAG单独更新BIT，故改为**可并行准备、独立交付，不强求同步完成或同BIT**。以下实验内容保留为E2工作包，软件共用取决于接口兼容。E2阶段的V预热→A有限访问→完全排空→V首次探测，与方法阶段的A/V共跑分别运行；不把两个实验同时叠加，也不是已有新板测在运行。

已有W0/1/4/7命中、W8/16出现A覆盖后首miss的局部证据保留；旧60不整套重跑。新版本仍需要少量兼容锚点，旧数据不能代替新版本性能配对。下面三项E2扩展及一项关联分析纳入本包准备：

|项目|具体实验与对照|新增证据及边界|
|---|---|---|

|E2-X2：有限访问前缀|固定W8/W16，只执行事前选定的少数A搬运次数（候选1/8/16，正式值板前冻结）；每个用例重新准备V，A排空后探测|确定目标覆盖在所选访问前缀间如何出现；保留实际已访问页数，短前缀不冒充遍历整个W。若要定位到第几次搬运，须有事件与搬运序号关联，不能只靠前缀推出精确位置|

E2阳性继续要求完整证据链：V目标初始驻留→归属A的填入覆盖目标→探测前驻留变化→对应目标首次lookup结果；排除主动失效/上下文改变，区分探测自身造成的替换。没有替换或首次仍命中是正常科学结果，不能作为技术失败停止。

**实施前需核查的接口。** 已有计划生成器的`--a-transfers`来自统一112常量，前缀首先需要扩展逐用例计划字段；这不等于已证明底层CLI不能接受其他次数，须核查实际校验链。布局/顺序变体和首访计时的完整可用性尚未确认，须板前补齐并验证。现有E2阶段计时和更新事件不能自动视作完整翻译/数据完成计时。X3优先随X1/X2采集，减少额外用例；正式运行前缺计时接口必须解决或明确降级，不能上板后才发现无法测量。保持旧冻结计划不变，新增独立扩展入口/清单。

**控制边界。** 已直接核对观察器：ARM_A要求V目标已驻留且quiet，PROBE要求READY且quiet；固定5,000,000周期仅为A阶段截止/排空裕量，不能当作替换代价。E2中A运行时V不活跃，不能直接切换M开关就宣称测了完整V反馈方法。本包优先用E2补充机制、自然共跑验证完整方法；不另加锁项/静态分区等新硬件路线。

**执行与冻结。** 各BIT按自身能力执行短验收及对应实验，E2不作为M校准/正式比较的必需前置。切换BIT后按流程重新启动并重建初态；能复用SD镜像不表示可混用启动状态。E2探索用的布局/顺序不得再冒充M未观察的独立验证条件；两者名单在板前分别冻结，保留真正未用于调参的验证集。具体重复数、运行顺序、合法参数和总耗时进入各自交付前总表。数据/协议错误停止，科学阴性继续；保留所有样本，不自动重跑。

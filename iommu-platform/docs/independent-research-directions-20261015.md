## 2. 第一建议：从解释局部变慢，推进到可检验的控制选择

### 2.1 真实问题与为什么值得先做

共享IOMMU的容量保护或命中旁路可能减少某类等待，却改变后续载荷进入内存的时机，使其他walk、消费者或最终排空更慢。决定问题是：**在付费测量之后，能否事前判断这个实际控制会改善哪项完整任务目标？** 这比“存在干扰”“统计更多”“设计一个新分数”更具体，也能直接决定后续应该开发哪个机制。

已有资产给出动机但没有证明答案：E2支持特定容量替换效应；E3 v6只支持一次启动中的局部A-miss→V-hit等待传播；旧PN实板组合比P约慢12.7%；另一M0行为DDR合同中普通服务规则消掉差额。**这些不是同一任务/配置，不能拼成一对完整正反状态，更不能宣布板端根因已查清。** [历史边界](research-panorama-audit-20261011.md)、[M0](workflow-g0-m0-results-20261010.md)。

我优先选它的理由，是它同时回答一个直接影响研究行动的问题，并允许用很小的证据单元推翻；无需先承诺一个通用程序分析器、新prepare协议或新硬件平台。若新增信息只能靠昂贵全历史collector取得，这个优势就会消失，排序应随证据调整。

### 2.3 我建议具体发展的方法

1. **冻结合法动作与目标。** 先限定P、PN和一个普通限流配置；N只有实际支持且有区分作用才加入。以V完整完成及后台完整工作/进度约束为目标，保留consumer、最终排空和归还。若只能idle配置，就研究下一个同类任务的选择，不假设免费在线切换。
2. **冻结已有观测O0。** 按真实可读接口登记per-DID命中/缺失、walk、字节、pending、周期及噪声，也给基线同样可取得的复用、请求合并/扇出和占用突发信息。不能删除有辨别力的现成计数器来制造缺口；GPU已有事件也不能假定本平台免费具备，新增费用对双方同等计入。
3. **寻找动作相关的信息缺口。** 两个有来源的合法状态在O0测量分辨率内相似，而P→PN对完整目标的净效果相反。首版只考察两类额外联合时间关系：一个owner的请求等待是否与另一owner的walk同处真实阻塞链；PTE pending是否与另一owner的已放行payload服务相遇。hit标签若事后才知道，只能用于随后决策。
4. **以完整动作验证信息的用途。** 共同出现不等于因果，两个等待周期不能相加成“可回收时间”。用合法动作的完整结果检验判断，信息不够时才请求有预算的校准。训练后冻结规则，在未见任务/阶段上测试。

可能形成的三项贡献是：一个限制明确的**动作不可辨识边界**；一个及时、可部署的**联合时序观测方法**；以及它改善**完整控制选择**的机制解释和证据。求解器/阈值不必全新；如果同信息简单阈值已足够，就诚实把贡献放在新信息与验证认识，不能再宣称新选择算法。

可核查novelty论证：前作已经把计数器、采样、干预和策略选择连接起来，最新TLB工作也已展示相似miss统计对应不同保护收益及组合退化。因此本候选不认领这些宽思想。**如果**具名多DMA任务中，现有统计加可得复用/扇出/突发信息及同预算普通估计，仍无法区分会改变P/N净效果的状态，且少量可及时取得的跨owner时序信息能以较低总成本纠正未见任务上的完整决策，**那么**新增贡献是这项具体的信息边界、获取办法及可复用控制依据。当前已核的是前作范围、已有局部资产与研究合同；状态对、观测物理成本和净选择收益仍待验证。

### 2.4 最关键的四份证据，按顺序取得

| 次序 | 所需证据 | 能判定什么 / 何时收窄 |
|---|---|---|
| **D1：先判值不值得立题** | 一对同合同的状态：真实任务来源、同目标/资源、O0及噪声、实际可行动作、相反完整后果；可先以有来源小模型验证原理，但须标模型 | 如果现有统计足以分开，或只有局部而无完整差别，本版信息缺口不成立；不先做大collector |
| **D2：信息确实可用** | 新关系在哪个真实接口产生、何时知道、身份如何对应；普通现有计数/短轨迹能否取到；面积/时序或软件费用 | 不偷用未来hit、理想内存内部状态；若信息到得太晚或取不到，改假设而非填0成本 |
| **D3：固定规则的留出效果** | 同信息阈值/DOA式结构判别、训练集选出的最佳固定配置、付费完整任务试选/反馈选择、可适配的MISE/ASM式估计；同一个候选规则覆盖未见任务/阶段 | 主指标为完整决策损失和约束违约，辅以观察/试选成本；不是原因分类准确率。离线逐例最佳只作oracle |
| **D4：可信完整闭环** | 所有DMA实际字节/完成、consumer、背景进度、排空/归还，观测与校准/切换费用；关键机制由正确时序下原生实现核验 | 动作改变后续到达时必须闭环。旧板负结果与模型正例不能互相冒充；当前MIG暂停不因此解除 |

D1是下一项最值得花时间取得的证据，D2同步只做定向接口核。D1/D2不成立，D立即降为支撑工具，I或其他有真实正例的候选前移；不通过扩大pressure/人工延迟不停寻找赢家。

## 3. 第二建议：把失效优化从“命令更少”推进到“系统共同成本”

这个方向有新补到的真实需求：2026年7月SMMUv3 RIL补丁讨论，作者倾向每gather一个范围命令以减少提交时延，reviewer担心扩大失效范围影响摄像/显示的live DMA。作者同时指出等时设备应容忍偶发full walk，且RIL相对原full失效更温和。**这是待量化的实际权衡，不是已证明deadline失守，也未核该补丁最终合入状态。** [原讨论](https://lists.infradead.org/pipermail/linux-arm-kernel/2026-July/1146330.html)、[回应](https://lists.infradead.org/pipermail/linux-arm-kernel/2026-July/1146543.html)。

最强发展版本：给定真实待撤销范围和合法命令集合，联合考虑命令取回/执行/同步、额外清除live翻译造成的重walk、延迟回收所占IOVA/页表/pin/buffer；按真实服务与回收预算选择粒度和有界批次。保持正式撤销语义，不能允许旧授权多活一段时间却仍称同合同更快。

最近前作的实质边界：

- [IDYLL，MICRO2023](https://yananguo.com/files/micro23_2.pdf)§5.2/§6.2–6.3已有失效与demand walk争资源、保守目录及合并/延后PTE维护；不能把这些现象重新认领。
- [Utilizing the IOMMU Scalably，ATC2015](https://www.cs.tau.ac.il/~mad/publications/atc2015-iommu.pdf)§3.2/§5已有per-core flush队列、锁外等待及同步前保留资源。新问题须增加对live任务和回收的共同可预测结果。
- [rIOMMU，ASPLOS2015](https://www.mulix.org/pubs/iommu/riommu-asplos-2015.pdf)§4用ring顺序与flat结构减少显式失效，适用时是强对照；不能无价移植到通用页表，也不能忽略它。

最小条件见证：同domain内页10与14需要撤销，页12仍有合法live DMA；两个精确命令和覆盖10–14的一个范围命令都可正确撤销，后者可能多清页12。**精确基线本来就会赢某些情况，所以这不是新算法正例。** 方法贡献要由一个事前固定的规则在混合未见输入上兼顾live预算和回收/命令费用，而非逐例事后挑最优。区间覆盖/DP、固定阈值、普通合批、持久映射、可行分domain必须公平比较。

当前平台还存在更简单解释：Linux host VMA失效没有设置PSCID，range循环被注释；硬件本身却支持匹配。root已亲核[驱动](../linux/drivers/iommu/riscv/iommu.c:1799)和[IOTLB](../cva6/corev_apu/riscv-iommu/rtl/translation_logic/rv_iommu_iotlb.sv:217)。先把正确范围作为基线，不能把修复这处扩大失效包装成新机制。CQ前缀完成依赖也不能直接解释一个从不等CQ的静态设备为何数据变慢。

**第一证据**是一条真实正常I/O的map/unmap→gather→命令→完成/回收轨迹，以及同时live任务的实际domain、翻译余量和预算。若正确精确失效、普通RIL或持久映射已经足够，本应用不需要新控制。若目标是SMMUv3 RIL，必须取得相应平台/可信原始轨迹；当前RISC-V无ATS配置不能冒充它。该线机制上限值得保留，但取证成本和现实余量未知，因此本轮排第二。[完整审查](../out/independent-directions-20261015/lifecycle/assessment.md)。

## 4. 为什么A、B和联合QoS没有排第一

### A：有实际发现，论文增量尚未落在可复用方法上

A3发现真实AXPY丢弃已有transaction ID而wait-all，最后tile可提出只等两个输入ID的普通方案，中间tile必须处理旧Y输出仍在读取的复用约束；同信息标准参考在四个抽象前缀上给同答案。[A3稳定接受](../out/a3-consumer-position-rules-20261015/root-result-acceptance.json)。

**最新A4已补齐一个关键源级缺口，不能仍说ID语义完全未核。** 固定FIFO→最后写分段B→累计完成前缀在同ID合法有序响应条件下成立，普通O-T1因此只需等后发RY的一个32位ID；一般循环另有双ID/Y复用guard。root读取A4稳定接受、源回执并直接抽核累计计数与last-B退休。其完成计数不检查错误，也不等于cache/失效/free；实际窗口、成功合同、完整净收益和真实第二publisher仍缺。A4还登记runtime cfg/serialize错配而未修。现成接口能表达动作，停止的仅是“该动作必须新增早接口”版本，不关闭A族；这项新事实不改变本轮排序。[A4报告](a4-axpy-control-decision-20261015.md)、[稳定接受](../out/a4-axpy-control-decision-20261015/root-result-acceptance.json)。方法席报告以A3为读取时点，本段为root对A4的后续整合，不改写席位原报告。

[RTAS2026](https://retis.santannapisa.it/~giorgio/paps/2026/Aromolo-RTAS26.pdf)§V–VI已具体包含FIFO外调度、合法分块、预算与完整任务分析；TC/ICRT/REALM也限制宽泛主张。A仍可能形成**特定接口的可靠抽取/部署方法**，无需发明新图算法，但需展示同一规则在未见真实任务中给出有用判断及完整验证。当前仅为了保留主线而先建通用分析器，问题与实现风险大于D的首关。

### B1：合法准备窗口真实，前作与当前普通入口也真实

HERO双缓冲提供“未来host地址已知、SPM槽尚不能覆盖”的合法窗口；这不是跨保护域授权，因为host映射与SPM payload owner是不同对象。[ICCD2018](https://arxiv.org/abs/1808.09751v1)§IV-A/IV-C已允许纯翻译预取进入该窗口；[RISC-V ATS规范](https://docs.riscv.org/reference/iommu/v20260222/iommu_data_structures.html)已给翻译结果、后续translated请求和失效语义。

新增核查是当前平台`InclDbg=1`，debug控制器能按IOVA/DID/PID/RW发纯翻译，并直接返回PPN/fault，不提交payload。root亲读[控制器](../cva6/corev_apu/riscv-iommu/rtl/software_interface/rv_iommu_dbg_if_ctl.sv:58)和[返回路径](../cva6/corev_apu/riscv-iommu/rtl/translation_logic/rv_iommu_tl_wrap.sv:1544)。因此受信软件debug预热是必须计MMIO/CPU/争用的具体强对照，尚未编程/实测。它没有pin和安全PA采纳，不等于完整B1协议。

B1可以争取一种比现有可执行方案更好的片上接口/部署成本点，不必把PA队列换名成新算法；但先要有普通预热/PTE缓存后仍阻挡完整任务的真实残余。当前只证明窗口，没有该性能事实。[完整审查](../out/independent-directions-20261015/ownership/assessment.md)。

### Q：问题重要，但不能靠P+N+限流的组合本身立新

[Taming Non-blocking Caches，RTAS2016](https://ittc.ku.edu/~heechul/papers/taming-rtas2016-camera.pdf)§II/§V已说明容量分区仍会被共享MSHR耗尽阻塞，并用OS控制在途额度；[MASK，ASPLOS2018](https://research.ece.cmu.edu/safari/pubs/MASK-address-space-aware-gpu-memory-hierarchy_asplos18.pdf)§5.2–5.4已有TLB准入、PTE缓存旁路和页表/数据内存调度。root重核这两处关键设计，故“容量与并发共同保护”“页表优先”不能再宽称新。

[DWS，HPCA2021](https://www.csa.iisc.ac.in/~arkapravab/papers/hpca21_DWS.pdf)§V–VI已有walker保留/借用；[mNPUsim，IISWC2023](https://myshlee417.github.io/files/mnpusim_iiswc_2023.pdf)§3.1/§4.1/§4.4已建模DMA突发、依赖、TLB/PTW/DRAM共享及性能/公平性。它们不证明本平台所有控制已最优；它们要求新控制必须指出更具体的失效条件。

现有R2、CO1、RCS1、BR1、SDH1、LR1负结果只关闭冻结动作/成本/模型主张。普通在同新增接口上复现动作，不等于接口已发表或整个架构无价值。未知未来路径、动态victim反馈、共享结果与private历史的成本仍可发展，但需要明确新动作及完整证据，不能只把固定图改叫动态。D若先发现一项普通控制解释不了的、可稳定识别的反馈失效，可自然导出Q的新机制，而非先造机制再找压力配置。

## 5. 更远的方向保留什么

不规则gather/完整消费者分组的旧思想仍有潜力，但“同组翻译齐备才有用”“短组先做”已受Scheduling Page Table Walks及普通SJF/依赖调度限制。当前RCS1特定版本被SJF完整结果压住，不排除真正动态依赖；先取一个正常程序中影响后继生成的真实分组实例，比较页排序、普通预取及消费者调度。

多GPU访问—更新冲突、翻译共享范围和不同设备布局也不应因FPGA不方便而关闭。但旧候选缺少“同对象在相关窗口既高复用又高更新”的事实，IDYLL、ShareMMU、Hydra及布局/混合表示已有深厚前史；ShadowUpdate/SPMC等关键未核方法不能凭题名猜覆盖。若能取得真实访问—更新—再访问轨迹，这一族可以重新升位；本轮未补齐该独立证据，因此不对它作终局新意否定。详细历史条件见[六族候选](innovation-council18-20261006.md)、[四项方法比较](translation-comparison-20261006.md)。

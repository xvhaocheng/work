# 普通翻译复用与提前准备：剩余差距指向请求可见范围

2026-10-08，接 §35。Codex 设计并实现关键路径、核查原源码与前作，执行构建与仿真；DeepSeek 整理接口证据，起草并修订汇总脚本。

## 结果先说清楚

普通父内翻译复用已实现并通过。它确实把真实 TL 调用从 98 降到 66，但两流平均完成耗时只降低 **0.337%**。普通提前准备也已实现：32 个原父全部提前译址、64 个子请求复用成功，平均只降低 **0.329%**。

所以，在当前前置实现中，少做 32 次重复翻译处理，不能解释 §35 后置方案的约 27% 优势。提前准备当前已经可见的父请求，也没有消除差距。

进一步读旧后置 CSV，发现它在第一拍源 R 返回前已接收 **6 个原始源读请求**。本轮前置入口每流只保存 1 个原父。这是实际可见范围不同的证据，不能把剩余差距直接归为一个独立新调度规则。

如果把请求可见范围和总保存成本配平后，普通准备／队列方法达到相同效果，就不能把当前位置规则作为独立创新。如果新的联合规则在同样约束下提供普通方法做不到的进度或成本优势，并且强前作没有覆盖这个约束，才可以建立独立机制贡献。

## 两种普通方法如何实现

复用器接在真实 TC 和 TL 的请求／响应接口之间，分片和写序服务仍由 §35 的原前置模块执行。没有新增 payload 缓冲，没有改变物理读长度、内存延迟、AW/W 调度或原父 RLAST。

TL 请求不含 AXI ID，也不含原父编号。Codex 从前置模块已经保存的真实父头、active/accepted/done 状态提供上下文和父序号，而不是用 DID 猜物理地址。缓存检查完整的 TL 请求上下文；仅地址可变为同一父内的另一 1 KiB。只缓存成功、非 ignore、非 MRIF 且页内偏移一致的正常响应；保存完整响应，PA 来自真实 TL 的 spaddr，再加页内差额。

普通父内复用：第一个子请求照常进入真实 TL，成功响应缓存给同一父的第二个子请求。每父缓存只供一次后续使用，父结束或序号改变清除。实际填入 32 次、复用 32 次，真实 TL 前向 66 次。

普通提前准备：真实原父已被接受后，在 TC 没有提出新请求、没有 TL 在途和缓存响应时发一次背景源译址。已经发出的准备请求通过寄存的 offer 保持到握手，不能被随后出现的 TC 请求撤回。准备响应由准备器自身接收，不塞给没有提出请求的 TC。成功结果供两片使用。实际背景准备 32 次、填入 32 次、缓存响应 64 次，真实 TL 总调用仍 66 次；结束时 slow/hit/valid/offer 全为 0。

正常 TC 请求在背景 offer 形成之前优先。不是独立翻译通路，不是多 walker，不是在假模型里直接生成物理地址。

模块接了现有 invalidation 清除／禁止再填入条件，但 harness 的 invalidation 输入硬接 0。背景错误不缓存并允许正式 TC 请求走原翻译；当前没有运行错误／失效／取消／epoch 场景，准备阶段可能产生的 fault 可见性未完成生产处理。不能把正常静态映射的成功实验当作通用安全回退验收。

## 可见范围不同的实际见证

§35 post/V先 CSV 中，第一拍物理源 R 在 cycle 2404；其前已有源原请求：

| cycle | 原始源地址 | 长度 |
|---:|---|---:|
| 68 | 0x10000000 | 2048 B |
| 69 | 0x10000800 | 2048 B |
| 70 | 0x10001000 | 2048 B |
| 71 | 0x10001800 | 2048 B |
| 2367 | 0x10002000 | 2048 B |
| 2374 | 0x10002800 | 2048 B |

此时没有 payload R 返回，六个原父都不可能已经完成。A 先为对应 A 源镜像。原始见证保存在 [lookahead-witness.json](../out/parent-translation-reuse-20261008/lookahead-witness.json)。

这不是“某个内部队列高水位等于 6”的推断，而是整条路径在读数据返回前至少已接收六个原父的下界。post 每流一个 physical parent 槽，不等于整条路径只允许一个原请求；原 TC、输入 FIFO 和 virtual 关联仍能保存未来请求。

本轮前置的每流一个 raw 父必须等当前父的 256 拍都返回后，才能接受下一个 raw 父。普通提前准备只看这个已经接受的当前父，不能提前翻译尚不可见的后续父。它并不是与 post 同提前范围的最强普通基线。

该见证说明一个必须配平的因素，没有证明全部 6904 周期都由队列容量造成。TC 占用、正常 AW 反馈和源／目的译址相互顺序仍可能影响结果，不能仅凭首次入队时刻做完整因果分摊。

## 前作对创新判断的具体限制

本轮直接重核 Arm 官方 [AMBA LTI IHI0089A](https://developer.arm.com/-/media/Arm%20Developer%20Community/PDF/IHI0089A_amba_lti.pdf?hash=091C20253C83E0BB218FD393595E051F343E8A52&la=en&revision=ec4c2359-5838-4f79-86ab-e1354236830a)。§6.2.2（文档6-51、PDF51页）已有同一4KiB区域、相同请求上下文的翻译共享，并约束完成时间；§1.1已有在事务排序条件满足前请求翻译的接口思想。§4.2的SPEC不能直接作为普通数据事务的使用许可。

因此，父内一次翻译多次使用、提前翻译以及简单扩大队列，不能直接作为独立新规则。规范同时提醒结果持有与失效完成的关系；若后续研究寿命／容量，也要与这个已有约束比较。当前 RISC-V 原型不是实现了 Arm 的 LC 协议，不能照搬其完成语义。

这没有证明当前完整双 W 序规则已被某论文逐项覆盖，也没有把技术前作核查当作专利法律结论。§35 的其他前作继续适用，不重新包装透明分片、owner 选择或独立 VC。

## 成本与实际执行清点

声明非统计状态：前置原模块 2502 bit；普通复用器 1012 bit，总 3514；提前准备器 1016 bit，总 3518；后置模块 3568 bit。辅助观测分别 128／160 bit 另计，前置共有的观测也另计。

两个前置普通方案与后置的模块声明量已经接近，但比较器、mux、时序、公共 TC/FIFO 及真实可用入队范围不同。没有综合、没有总面积配平，不能把约 50 bit 的声明差当作面积优势或“已等成本”。两路原 iDMA 数据 FIFO 都是 48 B。

本阶段实际 3 次新 SV+C++ 构建成功：首次接入 5.943s、显式输入修正 5.944s、提前准备 6.247s。总共 10 次新运行均 exit0/PASS：首批四次开关未生效，排除出受控对照；后六次是有效新对照。四份 §35 pre/post 只引用，没有重跑。

首次使用 SV plusargs 时，生成模型直接将 enable 设置为 1，两类参数都实际开启。该接入问题属于 Codex 的实验控制错误，不是 DUT 数据错误。Codex 起初把原因归到独立仿真 context，随后读实际 C++ 构造和生成代码，撤回此解释；确切工具消除原因未继续调查。改为 C++ 明确驱动顶层输入后，disabled 两轨迹恢复与旧基线逐字节相同。旧记录和首次源码／生成模型仍保留。

DeepSeek 汇总初稿有绝对 offset／父内 offset 和字段名错误，修正后只重解析 raw；Codex 最终核查还发现把不同启动顺序的第一发起者混成“双流平均”，直接修正为固定 V 先启动的 V/A 平均。最终脚本 exit0、778 条件通过；关键数学结果另直接由原日志重算，并核启动镜像。

76 份生产 SV 哈希与 §35 一致。原 tests、生产 RTL、Linux、BIT、SD 和板卡未改。本例仍是两真 DMA 同 bank、CONF1、各 32 KiB、src0/dst3072、全部行为 DDR 读延迟31、无 CPU／预热／诊断逆序／AW强制交错／DS优先。无综合、四DMA、MIG、失效、通用公平性和旧PN根因结论。

## 下一步主线

先构造具有相同原请求提前可见范围的普通对照，分开衡量“看到了多少未来父请求”和“实际允许读入多少数据”。可以复用已有 TC/header 队列，或对尚未接受但保持 VALID 的下一原父作普通无副作用翻译准备；两者的 metadata、映射保存、权限／失效寿命与退路必须计入总预算。当前尚未实现此下一版本。

先检查普通方法在给足相同可见范围后能否追平，不能只把 pre 的保存槽写成 1、post 的 physical 槽也写成 1，就宣称公平。如果普通方法追平，停止把位置或预取本身作为主创新。若仍有缺口，再寻找在相同预算下，利用真实读写完成依赖作出不同保留／释放／准入决定的规则，并给可达差异与必要进度条件。

这一轮交付的是两个已完成普通反事实和一个真实容量／可见范围见证。独立创新不能由“普通当前父准备无效”自动推出；下一份关键证据必须排除普通方法能看见更多未来请求的效果。§33 动态最长前缀的负结论保持，不先生产 BIT 或旧172重测。

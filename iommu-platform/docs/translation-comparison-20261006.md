日期：2026-10-06。接续[候选说明](translation-opportunities-20261006.md)、[文献地图](shared-translation-deepening-20261006.md)和[缺口审计](shared-translation-gaps-20261006.md)。本文是立题比较与验证设计，尚无候选通过新颖性或性能验证。“最强前作”指当前检索中最直接限制该主张的工作，不表示已穷尽领域。

## 2. 候选①：跨设备依赖指导翻译服务

### 前作与真正需要超出的边界

| 必须对照的工作 | 已有能力及评价范围 | 不能再当新意的说法／仍待检验的问题 |
|---|---|---|
| [Scheduling Page Table Walks，ISCA 2018](../out/shared-translation-literature-20261006/papers/walk_scheduling2018.pdf)，调度设计与评价章节 | 执行驱动 GPU/IOMMU 仿真；关联同一 SIMD 指令的遍历，估计完成工作量、批处理并考虑老化。 | “一组翻译齐备才有用”“短组先服务”已有前史。新问题需说明跨设备依赖为何改变翻译服务决策，以及普通任务优先级为何不足。 |
| [MASK，ISCA 2018](../out/shared-translation-literature-20261006/papers/mask2018.pdf)，设计章节 | 多应用 GPU 的 TLB 准入、翻译/数据干扰与公平性。 | 不能只增加 per-device 优先级或重命名争用保护；需与相同资源、公平约束下的策略比较。 |
| [MMU-aware DMA，ICCD 2018](../out/shared-translation-literature-20261006/papers/socdma2018.pdf)，§IV–V | DMA 缺失重试、软件并行处理 miss、编译器预取；缺失 DMA 不必长期占住共享资源。 | 降低队头阻塞、预备翻译和修改提交方式必须是强基线。不能将软件供给改善归功于新 PTW 调度。 |
| [BIS](../out/shared-translation-literature-20261006/gap-audit-02/papers/bis2012.pdf)、[Criticality Stacks](../out/shared-translation-literature-20261006/gap-audit-02/papers/criticality2013.pdf)；CATS 正式全文待取 | 已有根据同步等待、关键性或任务图安排资源的通用方法。 | 依赖信息可以由运行时廉价提供，这本身并不否定研究；要否定的是“已有普通调度使用该信息就能取得同样收益”。 |

### 场景证据与未解决约束

**已知场景 A：非规则 GPU 计算。** 2018 PTW 论文的 GPU 指令经 TLB/IOMMU 进入遍历队列，多个翻译共同影响一条指令前进；这是仿真中的组完成依赖，不能当作跨设备依赖证据。

**已知场景 B：SoC 指针追踪与流处理。** MMU-aware DMA 的 §V 在 Zynq-7045 上实现 PMCA、SPM、DMA 和混合 IOMMU；作者把 FPGA 用作硬件仿真平台。两类可调微负载由应用关键阶段提取，路径是 host 分配共享内存 → worker 发起 DMA → IOMMU/软件 miss 处理 → 数据到 SPM → 计算。它提供可复用的机制验证入口，尚不能替代完整多设备应用。

**目标场景仍是研究假设：** 一个生产者的数据搬运与另一个消费者的开工同时受到共享翻译资源影响，设备局部队列信息不足以判断哪组翻译最值得先完成。NIC–GPU、GPU–存储或多个加速器只是待筛选入口，不默认成立。尤其 [GPUDirect RDMA 官方文档 §3.4](https://docs.nvidia.com/cuda/gpudirect-rdma/index.html#supported-systems)对所述路径要求 1:1 映射/直通；NIC 能访问 GPU 内存不能证明两者争用共享 IOMMU 翻译。

**关键缺口：** 一条实际地址路径、生产—消费同步关系、翻译等待与消费者开工的对应，以及依赖标签的获取/更新成本。已有 [BaM](../out/shared-translation-literature-20261006/gap-audit-03/papers/bam2023.pdf)可提供 GPU 发起 I/O 的应用入口；[VIO §3](../out/shared-translation-literature-20261006/gap-audit-03/papers/vio2025.pdf)提供提交前准备页的软件替代方案。二者都不能自动证明目标瓶颈。

### 最小判别实验规格（未执行）

1. **路径门槛。** 对一条有应用依据的流水线画出 VA、IOVA、PA、GPU MMU、NIC 注册映射、IOMMU 和设备缓存；标明生产完成、数据可见、消费者可启动分别由什么事件保证。若目标流量绕过所研究的共享翻译资源，换场景。
2. **收益空间。** 在同一程序、输入及资源预算下，比较 FIFO、公平调度、预计短组优先/同组批处理、运行时已有关键路径优先，以及获知完整依赖的理想策略。所有对照允许适用的软件预取/准备机制，不以“不改 OS”人为削弱基线。
3. **归因与终点。** 主终点为端到端完成时间；消费者解锁时间、各设备等待和公平性为解释量。单独消除翻译排队的理想实验用于估计收益空间，不把增加 PTW 或带宽的收益冒充调度收益。
4. **成本与反证。** 加入标签传输、状态维护、陈旧标签、调度延迟和防饥饿成本。若最强普通基线在测量不确定性内达到同效果，或可实现策略的成本吃掉收益，则停止当前机制主张。

**重要方法修正：** 固定程序和输入，不能强行固定每条请求的原始发出时刻。服务顺序改变会反过来改变后续请求、合并、同步和工作重叠。无反馈的轨迹回放只能回答局部排队问题，端到端主张需要闭环/执行驱动验证。完整依赖启发式也不自动等于数学最优；只有最优求解或严格界才能称上界/下界。

## 3. 候选②：映射生命周期与共享范围

### 前作分层比较

| 前作 | 它管理的对象与已有机制 | 对候选的约束 |
|---|---|---|
| [Hydra，ATC 2024](../out/shared-translation-literature-20261006/papers/hydra2024.pdf)，§3.2、§3.5 | CPU NUMA 页表的惰性部分复制；页表 sharer 信息缩小 TLB shootdown 范围。 | “只复制有用部分、只通知相关节点”已有实现；页表级 sharer 不等于每个设备 TLB 的精确驻留目录。 |
| [IDYLL，MICRO 2023](../out/shared-translation-literature-20261006/papers/idyll2023.pdf)，设计中的 IRMB/Correctness | 多 GPU 的 PTE 失效目录、合并与延迟处理；**收到失效时 TLB 仍立即失效**。 | 延后 PTE 更新不等于允许旧翻译继续访问。新策略必须保持相同正确性语义。 |
| [ShadowUpdate，ISCA 2026，机构摘要](https://yonsei.elsevierpure.com/en/publications/reducing-page-faults-via-invalidation-based-mapping-propagation-i/) | 利用已有失效广播传播新映射；跟踪在途迁移，页拷贝完成后再释放请求。 | “迁移时顺带传播映射、避免随后重新缺页”已经被提出。本轮仍未取得全文，不能确定其完整传播范围或开销模型。 |
| [ShareMMU，MICRO 2026 已接收](../out/shared-translation-literature-20261006/papers/sharemmu2026.pdf)，§V-C | Permission Tracker 包含私有 TLB；定向反向失效；权限变更仍等待写回、flush/在途访问完成与确认。 | 复用与撤销确认并非新问题。不能删除这些等待来制造性能收益。 |
| [Trans-FW](../out/shared-translation-literature-20261006/papers/transfw2023.pdf)、[CLAP](../out/shared-translation-literature-20261006/papers/clap2025.pdf) | 前者已有远端转发及共享；后者已探索页大小/locality 与选择性迁移结合。 | “加入迁移”不是新贡献。CLAP 的跨 kernel 访问变化扩展示例是作者构造的场景，不证明该变化普遍频繁。 |

通用对照包括 [TinyLFU 的准入](../out/shared-translation-literature-20261006/gap-audit-02/papers/tinylfu2015.pdf)、[Leases](../out/shared-translation-literature-20261006/gap-audit-02/papers/leases1989.pdf)与共享内存副本管理。它们提供比较思路；数据缓存有效期不能直接当成安全的翻译撤权协议。

### 场景与尚缺事实

**优先应用入口：多 GPU UVM 共享页的迁移。** IDYLL 有双 GPU A100 的问题剖析，机制评价主要为模拟；论文区分随机、邻接、scatter-gather 共享模式。可查 PageRank/矩阵工作负载中哪些页反复被多个 GPU 使用、何时迁移、哪些 GPU 又访问。这里应先研究 GMMU/PTE 路径，不能默认就是 PCIe IOMMU/ATS 路径。

**部署对照入口：VIO 的 VirtIO 设备直通。** 它通过描述符探查，在设备消费前准备页，并在 snooping/passthrough 等模式间选择。该路径用于检验软件供给是否已经解决问题；尚无证据说明它存在我们需要的多设备翻译共享冲突。论文中的 Linux/PRI 支持描述属于作者当时环境，不作为今天所有设备的普遍结论。

**待证假设：** 访问总量、共享程度相近时，映射更新的时机及下一次复用间隔会改变最佳副本范围；可在线取得的生命周期信号能预测这种变化。只提高更新频率制造极端负载不能充当真实应用证据。

### 最小判别实验规格（未执行）

| 项目 | 具体要求 |
|---|---|
| 选定对象 | 先选择 GPU PTE 副本或 IOMMU/设备 TLB 条目。登记实际准入、逐出、驻留查询、失效及完成接口；若提出新接口，其面积、消息、延迟都计入。接口缺失本身不是论文贡献。 |
| 基线 | 本地/最大可行共享、按需复制、热度/频率准入、按 sharer 定向失效；再选择该层适用的最新论文机制。Hydra、IDYLL、ShareMMU 不直接拼成一个不存在的系统，移植的部分注明改造与成本。 |
| 输入 | 真实访问与映射事件作为主体；保持访问量/重叠接近的更新时序扰动只作为敏感性分析。关联页、设备、版本、迁移、权限变更、失效及确认。 |
| 公平条件 | 相同物理工作量、权限/迁移完成语义、总资源预算；元数据与维护流量是待测结果，**不预先强行设为相同**。 |
| 终点与成本 | 端到端完成时间及最慢消费者进度；记录复制收益、更新、确认和重填时间线。失效等待可与计算重叠，不能把所有组件延迟直接相加。 |
| 反证 | 真实窗口不同时具备共享和更新；简单准入/惰性复制已达同效果；获知未来生命周期仍无额外收益；或维护与新接口开销抵消收益。 |

**决定：条件保留，实施暂缓。** 下一证据应是“同对象访问—更新—再次复用”的时间线和适用前作边界，不先发明另一套生命周期评分。ShadowUpdate、SPMC 全文优先级高于继续扩宽泛题录。

## 4. 候选③：指导动作所必需的观测

| 强前作 | 证据与已做内容 | 对候选的要求 |
|---|---|---|
| [CounterPoint，ASPLOS 2026](../out/shared-translation-literature-20261006/gap-audit-02/papers/counterpoint2026.pdf) | 用真实 Haswell MMU 的带噪计数器检查/修正微架构模型，考虑计数器相关性。 | “通过计数器推断隐藏行为”不是新意；它不是在线控制器，其特定计数器数量/阈值不能搬成通用门槛。 |
| [HELM，SC 2025，出版社页面及索引](https://doi.org/10.1145/3712285.3759812) | 从 UM 驱动遥测提取可解释指标，并用于策略选择；页面还给出 MIM 与[作者公开 artifact](https://doi.org/10.5281/zenodo.15294080)。 | “增加指标后指导策略”也有直接近邻。正文/实验细节尚未取得，不能把其在线性或预测边界说死。 |
| [ObservUVM，ISCA 2026](../out/shared-translation-literature-20261006/papers/observuvm2026.pdf)，§VII | 复用访问计数器提供采样观测，以反馈指导驱逐/预取；真实 RTX 3090、14 个应用评价。 | 不只是观察工具，已连到策略收益；但目标为显存超额订阅，不能直接等同 IOMMU/PTW 服务。 |
| [Coz](../out/shared-translation-literature-20261006/gap-audit-02/papers/coz2015.pdf)、[MISE](../out/shared-translation-literature-20261006/gap-audit-02/papers/mise2013.pdf)、[ASM](../out/shared-translation-literature-20261006/gap-audit-02/papers/asm2015.pdf) | 因果剖析、带干预的 slowdown 估计、缓存/内存干扰管理。 | 有界扰动和性能归因均有强前史；需要翻译场景中的具体信息不足及净决策价值。 |

**窄问题：** 限定已有观测集合、采样窗口和噪声后，能否找到两种真实状态，已有观测近似相同，但同一可行动作集合中的最佳选择不同？例如都出现高 miss 率，一种翻译排队卡住消费者，另一种翻译延迟被计算隐藏。这个例子仍是假设。

**验证办法：** 与①或②共用一个真实负载；先只选一种实际控制，例如固定总 PTW 预算下调整服务份额，或改变所选翻译层的准入。用完整事件和受控干预建立参考结果，逐步屏蔽依赖、排队归因、更新阶段等信息，对比已有统计+阈值、已有统计+简单模型、额外采样/标签及有界扰动。离线真值单独记账；在线策略拿不到的未来信息不得混入输入。

主终点是**选择该动作后完成时间距同条件最佳可行动作的差距**，并加入观测、校准、扰动和切换成本。若动作影响后续状态，必须比较闭环策略轨迹，不能把每个决策点的局部最优简单相加。跨工作负载/阶段留出验证，避免从同批真值挑选特征后又在同批数据宣称泛化。

**停止条件：** 现有观测足够；补充观测获得太晚；开销吃掉收益；只能提高分类准确率；或无法可靠区分测量噪声与真正的状态混淆。通过消融只能说“在已检验集合中更少”，不能据此证明全局最小观测集。

**决定：先作为①/②的支撑。** 独立立题需要同时证明信息缺口、低成本取得信息的方法，以及跨负载的净决策收益。

## 5. 候选④：同对象的不同翻译表示

| 强前作 | 已有设计与层级 | 还需证明的边界 |
|---|---|---|
| [PFM / Dual-View Memory，MICRO 2026 已接收](../out/shared-translation-literature-20261006/gap-audit-02/papers/pfm2026.pdf)，§IV-C、§VIII | 同一物理数据提供 NPU/PIM 不同视图；ARU 做 PA→硬件地址重映射，基本 VA→PA 保留；使用离线映射、MDT、重排缓冲。 | 不能再用“双视图”本身立题。候选即使处于 IOMMU 层，也须说明额外解决了什么应用约束。 |
| [EMT，OSDI 2025](../out/shared-translation-literature-20261006/papers/emt2025.pdf)，框架/Limitations | OS 抽象支持 radix、ECPT、FPT 等翻译方案。当前范围不含 IOMMU DMA，并明确方法可能扩展到该处。 | “把 EMT 用于设备”不自动产生新意；它是框架与实现基线，不能充当目标多设备应用。 |
| [RMM，ISCA 2015](../out/shared-translation-literature-20261006/gap-audit-02/papers/rmm2015.pdf)、[Utopia，MICRO 2023](../out/shared-translation-literature-20261006/papers/utopia2023.pdf) | 范围与分页、受限与灵活映射已有共存方案。 | 同时支持多粒度、多表示已有前史；需具体的更新/访问冲突，而非结构组合。 |

**有证据的应用动机：** PFM 的 NPU/PIM 推理展示不同计算单元希望以不同方式访问同一数据，主要依据为模型/模拟。这证明布局需求值得研究，尚未证明换 IOMMU 翻译表示比现有布局、范围或混合方案更必要。

**最小判别：** 从实际算子链提取一个共享对象，写明每个设备访问模式、更新粒度、权限与同步事件。先比较标准分页/大页/合并、范围或混合表示、软件布局/数据复制，以及理想每设备表示。按相同物理内存、翻译 SRAM、带宽等总预算比较；不同条目覆盖范围是设计变量，不能固定相同条目数与页大小而提前抹掉候选差异。

若应用确实禁止复制，给出应用理由；否则复制作为可行基线并计入容量、搬运和同步成本。页级翻译无法免费完成任意页内张量转置。元数据、查找、切换、权限更新、失效和重填一起计入端到端结果。

**决定：暂缓。** 当前没有一个已核实的冲突实例，能说明现有表示/布局方案在相同约束下仍不能解决。VBI、DIPTA、DeACT、Barre Chord 的全文已在原库，不属于“还没收集”；如重启该候选，应按具体冲突定向重读，而不是继续堆结构名词。

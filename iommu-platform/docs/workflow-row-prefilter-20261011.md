# 行预取工作流需求卡与 G0 判别

日期：2026-10-11发起，2026-10-12收束。状态：登记G0两项模型运行及独立验收完成；归档本期限失效假设，不进入新机制。

## 需求与真实约束

来源为 DASH §2.2 的 Sobel 行缓冲例：640×480、30fps、1B像素、四行槽，每次使用三行并预取下一行。输入帧开始前已存在且不变；477个稳态copy为row3..479，640B/次。前3行必须真实初始化，初始化时间单列，最后消费也单列；不把行预取期限通过说成完整Sobel/FPS验收。

50MHz下，周期是精确31250/9：任务j=row−3的release=ceil(j×31250/9)，deadline=floor((j+1)×31250/9)。任务地址和期限均提前可知，限制仅是不能提前写入尚在消费的目的槽；合法提前翻译、预读及大页各方均可用并计真实成本。晚选择、共享数据或未来oracle均不是合同条件。

后台为本研究追加的DID11独立4KiB COPY，与DASH原例不同；源/目的各16个4KiB页环，完成驱动gap0。首个有界判别固定2048个后台copy（8MiB），双方自然完成，终态quiet；公共稳态窗口内后台进度与后台全部完成时间分开报告，不在V结束时STOP A。2048是本研究工作量参数，不冒称原文应用值。

## 可执行布局与普通对照

V源IOVA 0x10000000，307200B帧；目的IOVA 0x20000000，四槽共2560B。V源PA 0x80000000，目的PA 0x80200000，避免旧微基准0x80001000目的落在源帧内。A源IOVA/PA为0x20000000/0x90000000，目的为0x20100000/0x90100000；DID区分页表，A/V相同数值IOVA不是共享数据。

4KiB映射需要V源75页、目的1页，A源16页、目的16页。强简单大页对照可用V两个2MiB叶、A一个2MiB叶，物理地址/数据工作量相同；映射的未用空间只属于该测试上下文的已保留分配，不跨域授权他人内存。实际Linux驱动当前按PAGE_SIZE映射，大页测试是模型能力对照，不称已有Linux部署。大页占用/暴露的额外空间须列成本。

首个普通策略为P固定分区、全速后台供给，无新保护/逐copy门控、无行为DDR内部DS优先，CPU关闭；不按结果调阈值。先检验它是否已经满足477个行期限。低翻译压力映射是相邻因果参照，并不自动是同内存预算的免费部署方案。只有实际失败后才按合同补强相关普通控制，不先实现完整DASH或大矩阵。

## 可被推翻的失效假设

G0题：在上述真实行释放、固定分离目的与自然后台copy竞争下，普通固定P是否仍有行copy超期；若有，额外等待是否由共享翻译服务传播，且在现有合法控制点能及时避免。

H0：普通固定P已经满足该需求，或合法简单映射/准备/控制已覆盖损失。H1：普通策略留下可归因、可达且可避免的损失。不能把旧P/PN差额迁移成这里的收益，不能从只是V慢于solo推导有新方法空间。

判定：P全速供给已使所有477行按期，结束“需要新增保护以满足本期限”的立题理由；这不证明A吞吐全局最优、不否定其他工作流或内存预算下的方法。若P失败，检查技术守恒与普通强对照，再决定是否进入新规则。未有运行记录时状态为待判，不记零迟到或关闭。

## 接口、成本与验收

普通MMIO的长度寄存器支持640B；BatchPort的固定4KiB限制不能套到single-copy NEXT_ID。新测量保持旧SYSTEM RTL，在私有C++驱动中逐行普通提交，复用已编译RTL前先核source/binary provenance。MMIO提交等待计入释放至实际done的时间；不能把软件启动当逻辑ready。

独立逐任务观察硬件issue/done、第一次真实W、有效字节、AW/W/B及quiet。单次迟到仍完成全部任务，但源数据/槽消费正确性失败则该运行不能作性能证据。每行目的数据须在实际done后立即核对，最终槽内容不能证明此前477copy全正确。初始化、准备、最终消费与协议收尾单列；不拿旧full64结果校验器直接验证本合同。

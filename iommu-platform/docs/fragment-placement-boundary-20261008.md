# 分片位置的性能判别：后置分片有效，下一步排除普通翻译复用

2026-10-08，接组成研究记录 §34。设计、关键源码核查和研究判断由 Codex 完成；DeepSeek 提供 C++ 观测与结果汇总脚本草案，Codex 实际应用、编译、运行和审定。

## 当前结论

本轮得到一个可以继续追查的正结果：同一工作集下，先翻译原请求、再拆成物理子请求，比先拆请求、再分别翻译的两路平均硬件完成耗时低 **27.09%**。V、A 都改善，没有靠牺牲其中一路换取平均数。

两种方法的 miss 都是 34，实际 PTW 读取都是 102，物理源读都是 64。因此这里减少的是重复的翻译控制请求，不能解释成减少页表访问或搬运字节。

因为翻译结果复用和提前翻译已有前作，仅凭这个位置变化及其加速，不能认定一个独立的新算法。如果普通的父请求翻译复用与提前准备，在相同总资源约束下达到同样效果，就不能把当前规则作为独立创新。下一步先做这个直接对照。

## 两种方法究竟有什么不同

每个真实 DMA 发出一个 2 KiB 源读原请求。为了适配当前已经准备好的写序，两种方法都最终向内存发出两个 1 KiB 源读子请求；都保持原 DMA 看到的 ID、256 拍和唯一的最后 RLAST。

前置方法（preTL）：先把原请求拆成两个 1 KiB，等对应写序可服务时，分别送入 IOMMU 翻译。两个子请求即使在同一页，也各经过一次翻译请求控制。

后置方法（postTL）：把 2 KiB 原请求送入 IOMMU，取得翻译结果并保存父请求，等对应写序可服务时，再产生两个物理 1 KiB 源读。后半段不用再提交一次同页翻译请求。

两种方法都使用 §33 的同一固定上限和双侧写序核对：virtual AW 与已接收 physical AW 的 owner、每流段序及连续字节范围匹配，才服务相应源读。不是一方有 owner 调度而另一方没有，也没有新增 R 数据缓存。当前比较的是固定分片位置；§33 的动态最长前缀规则没有参与本轮。

前置模块接在两个真实 DMA 的源 AR 与 IOMMU 之间，在共享 AR 仲裁之前按流保存原请求，避免一个已经满的流挡住另一个空槽。AW/W/B 仍走原共享 mux；源 R 由前置模块恢复原父结束标记后交回原 demux。

## 实际结果

主表为 V 先启动的 S 条件。A 先启动是对应镜像，不是独立随机重复。

| 实际观测 | 前置分片 | 后置分片 |
|---|---:|---:|
| 原始 iDMA 源读父请求，合计 | 32 | 32 |
| IOMMU 入口源 AR，合计 | 64 | 32 |
| IOMMU 入口目的 AW，合计 | 34 | 34 |
| TL 接收／返回 | 98／98 | 66／66 |
| IOTLB 命中／未命中 | 64／34 | 32／34 |
| 实际 DDTW／PTW AR 握手 | 2／102 | 2／102 |
| 物理源读子请求，合计 | 64 | 64 |
| 每流实际源 R／目的 W 拍数 | 4096／4096 | 4096／4096 |
| V：硬件 issue→done 周期 | 24162 | 17471 |
| A：硬件 issue→done 周期 | 27436 | 20149 |
| 两流 issue→done 平均周期 | 25799 | 18810 |

平均缩短 `(25799−18810)/25799 = 27.0902%`；V 缩短 27.6922%，A 缩短 26.5600%。这是完成延迟降低，不等同于“吞吐提升 27%”。

V、A 的 issue_cycle 分别为 64、69；前置 done_cycle 为 24226、27505，后置为 17535、20218。观测来自真实 `dbg_dma_issue` / `dbg_dma_done` 脉冲，每流各恰好一次，按同一时钟采样点计算，没有用软件轮询的先后顺序代替 DONE。

对应最后 DDR W，前置为 24221／27500，后置为 17530／20213；它们各比真实 DONE 早 5 周期。这两个指标分别保存，不混作同一完成时刻。

完整原始日志、argv、实际退出码、CSV 和汇总位于 [本轮证据目录](../out/fragment-placement-20261008/README.md)。

## 收益的解释与尚待分解的因素

入口源 AR 少 32，TL 请求也少 32，命中少 32，miss/walk 不变：直接支持“分片前后会改变重复命中处理的数量”。

它还改变了源翻译能提前到什么位置、翻译和数据服务的交织，以及通过实际 DMA 背压反馈形成的正常 AW 顺序。因此不能把 V 的 6691 周期和 A 的 7287 周期差，全部分摊给这 32 次重复命中。当前没有逐请求等待分解足以支持这种因果分摊。

两个方法的原始请求几何、目的 AW 数、物理 AR 数和字节量相同，排除了靠改变总任务量获得优势；但它们的逻辑入口保存容量不完全相同。postTL 仍保留每流 8 项 virtual 源关联和原 TC 队列，preTL 在真实 DMA 入口每流只保存 1 个原父请求。这是下一轮总资源比较必须纳入的限制。

## N 对照：没有触发，不能判定快路径价值

本轮另有四次 N 运行，分别覆盖前置／后置与 V／A 先启动。模式开关正确传入，但四次 FAST 都是 0；各自 CSV 与对应 S 逐字节相同。

直接核查生产 `rv_iommu_tl_wrap.sv:303–306`：现成 N 的窗口要求正在 PT 状态、有 PTW 活动，且新请求的 bank 与当前请求 bank 不同。本轮两流被放在同一 bank，条件不满足。

因此四次 N 是零触发控制，不能支持“有效命中快路径也替代不了后置分片”。Codex 在运行之前没有先核对其跨 bank 触发条件，已纠正原先把 N 当作本场景强快路径对照的说法。这里不需要为取得非零 FAST 而改变当前主工作集，下一步使用直接针对重复同页请求的普通复用对照。

## 成本与验证范围

独立模块的声明非统计状态，前置 2502 bit，后置 3568 bit，后置多 1066 bit。观测状态各 160 bit 另计，两路 iDMA 数据 FIFO 合计均为 48 B。

此差额来自后置保留的 virtual 源 offset/len 和序号，与前置保存的扩展 AR 类型宽度之差。它不是综合后的 FF/LUT 数，未计公共 TC、DMA、AXI cut，也没有证明总资源相等。不能因为没有新增 R payload，就忽略翻译结果、原请求与写义务的保存成本。

本轮仅一个新 SV+C++ 构建；另三次仅 C++ 重链接。八次仿真均 exit 0 / PASS；最终汇总 902 项条件通过，新增观测后两份 postTL/S CSV 与 §34 对应单父槽基准逐字节相同。数据、源保持、未写区域、NEXT→DONE 和静默排空检查来自实际 C++ 驱动；汇总脚本解析这些记录，不声称自己重新检查了内存。

新构建保留了 Verilator 的已有多项警告，并新增 `pre_parent_ar` 的 UNOPTFLAT 报告。局部就绪表达式只依赖已寄存的 active/父计数，owner 选择只读取这些每流就绪；例示路径包含把不同信号放在同一个 always_comb 的依赖。本轮四次前置运行正常收敛、完成，但不能据此声称完整组合路径已通过 lint、综合或时序。进入生产实现前仍须拆清组合依赖并完成相关检查。

有效范围为两真实 DMA、同 bank、CONF1、每流 32 KiB、源页偏移 0／目的页偏移 3072、正常静态有效映射、64-bit INCR、页内原父请求。没有 CPU 供给、预热、诊断逆序、强制 AW 交错、页表优先或批量提交。`ptw-latency=31` 实际影响全部行为 DDR 读，不是只改变 PTW 或真实 MIG。

当前没有故障／取消／失效／epoch 生命周期保证、通用公平性或四 DMA 进度证明。原 extended AR 字段在前置模块保存；公共 flat harness 本来只支持其中的子集，不能宣称所有扩展属性都已端到端覆盖。

76 份生产 SV 哈希与 §34 一致。原 tests、生产 RTL、Linux、BIT、SD 和板卡均未改；沿用 §31 的 out 写额度修正。不是旧 PN 退化已修复或实板加速结论。

## 下一步主线与停止条件

先实现普通的**原父请求翻译复用**：第一个子请求获得有效翻译后，在原父的剩余页内子请求中复用该结果；保留同样的双 W owner/段序服务、固定 128 拍、原 ID/RLAST。记录真实 TL 接收、PTW 读取和硬件 DONE。当前静态页内正常任务可以作为有界实验，不能据此省略生产失效与权限寿命处理。

这个对照若仍因“等第一个子请求能服务才翻译”而慢，再补**普通提前翻译准备＋相同物理 child 调度**。它应按同一可用元数据总量计入父请求、映射、关联与 TC 队列，不能只把每流父槽数写成 1 就说等成本，也不应故意省去普通方法可获得的 owner 信息。

判定条件：

- 如果普通复用与提前准备在相同总成本下消除当前差距，因为它们已解释主要收益，当前位置规则不能称为独立创新；保留它作工程强基线，停止包装新机制。
- 如果公平的普通基线仍受明确的翻译寿命、写提交顺序或总保存容量约束，而新的联合规则能在实际可达状态中提供不同的决定、可证明的进度或成本收益，并且最强前作没有覆盖该约束，就可以据此建立独立机制贡献。
- 如果只剩少数场景的速度差，却没有新规则所需信息、必要条件与成本解释，就不能用本轮 27% 直接支持独立创新或论文分区。

§33 动态最长前缀在固定对照下没有稳定净收益的结论保持；本轮固定分片位置的正结果不能自动恢复动态算法的主贡献资格。下一轮从上述普通复用对照开始，不重跑已完成的八项、不先编译 BIT。
